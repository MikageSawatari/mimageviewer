状態: **設計 (2026-11-21)。実装は未着手、収録版未定 (v5.6.0 には入れない)**。
基点は master `28f9c5a11`。行番号はこの基点のもの。実行時の挙動は誰も観測していない
(この文書の根拠はコードと文書の参照だけ。実機で確かめる点は §14)。

親文書は [mcp-integration-plan.md](mcp-integration-plan.md)。安全性 (§5)・IPC の版 (§4.2)・

## 0. 要約

AI アプリ (MCP クライアント) が mIV の使い方を説明し、利用者が許可していれば、今開いている場所を見て
案内し、環境設定とお気に入りの登録・索引を変える。tool を 6 本足す。

| tool | 内容 | 要る許可 | 本体との通信 |
| --- | --- | --- | --- |
| `search_help` | 同梱のマニュアルを語で探す | なし | なし (MCP exe だけ) |
| `get_help` | マニュアルの節・目次を返す | なし | なし |
| `get_view_state` | 今開いている場所・表示中の項目・そこが検索の対象か | 読み取り以上 + 「今開いている場所を AI に見せる」 | UI スレッド |
| `get_settings` | 環境設定の項目・今の値・選択肢 | 読み取り以上 + 「設定の確認と変更を AI に任せる」 | UI スレッド |
| `set_settings` | 環境設定の値を変える (確認なし) | 同上 | UI スレッド |
| `set_favorite` | お気に入りへの登録、アイテム索引・コンテナ索引の切り替え (確認なし) | 同上 | UI スレッド |

中心の決定は 3 つ。

1. **設定の変更は、環境設定の OK と同じ確定処理をそのまま通す**。下書きを作り、値を入れ、
   `apply_preferences_dialog` を呼ぶ。確定処理は切り出さず、AI 専用の反映の経路も作らない (§6.3)。
2. **変えてよい項目は、設定の書き出し・取り込みの表 (`preferences_policy!`) の 164 項目から、
   AI に変えさせない 8 項目を引いたもの** (§6.4)。通信・AI 連携の許可・外部ツール・スクリプト・
   PC 固有のパスは、この表の外なので最初から対象にならない。
3. **許可は独立のチェック欄 2 つ (既定オフ)**。許可の範囲 (4 段) には段を足さない (§3)。

mIV Sound の処理の並びを組む機能は第 2 段で、この文書の範囲外 (§12)。キー割り当ての変更は
今回は外すことを提案する (§11)。

## 1. 利用者の決定 (2026-11-21)

利用者の言葉 (統括経由):

> 設定変更もAIにまかせることを決めたのであれば、他の処理と同じように都度の確認はしない形としたいと
> 思います。いずれも設定でユーザが許可した場合だけ権限を渡し（デフォルトはオフ）、権限を渡したら、
> その後は個別の確認はしない、という方針で揃えたいです。mIV Soundは規模が大きいと思うので、そちらは
> 第2段とし、まずｍIVヘルプ・設定関連まで一式でリリースしたいです。

ここから決まること:

- 呼び出しごとの確認ダイアログは出さない。タグ・★・コレクションと同じ扱い (親文書 §5.5 の U9)。
- 設定を見せる・変えさせる、今開いている場所を渡す、はどちらも利用者が設定で許可したときだけ。既定はオフ。
- 今回出すのは、案内 (ヘルプ)・今の状態・設定の確認と変更・お気に入りの登録と索引。mIV Sound は第 2 段。

利用者の例 3 つがどこまで届くか:

| 例 | 今回 | 届かない部分 |
| --- | --- | --- |
| 1. ホイールでズームにしたい | 設定を変えるところまで | なし |
| 2. プロンプトで検索するには | Ctrl+F と Ctrl+G の違いの説明、今の場所が索引の対象かの判定、お気に入りの登録とアイテム索引 ON | 索引の作成の進み具合は返さない (§8.4) |
| 3. レコードのノイズを消したい | mIV Sound の説明書から手順を案内するところまで | 並びを組んで入れること (第 2 段) |

## 2. 範囲

含む:

- マニュアル (`htdocs/mimageviewer/manual/`、mIV Sound の説明書 `manual/sound/` を含む) を MCP exe に同梱して引かせる。
- 今開いている場所と、そこが検索の対象かを返す。
- 環境設定の項目を読む・変える。
- お気に入りへの登録、アイテム索引 (Ctrl+G) とコンテナ索引 (Ctrl+S) の ON / OFF。
- 許可の設定 2 つ、設定画面、公開文書の書き換え。

含まない:

- mIV Sound の処理の並びを組む (第 2 段、§12)。
- キー割り当て・リング・マウスボタン・ゲームパッドの変更 (§11)。
- お気に入りの削除・名前の変更・並べ替え、別バージョン索引・サムネイルの事前作成の切り替え。
- 環境設定やお気に入り編集の画面を AI から開くこと。
- 呼び出しごとの確認、変更の取り消し専用の tool (§9)。

## 3. 許可の持ち方

### 3.1 案の比較

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A | 許可の範囲 (無効 < 読み取り < 開く < 整理) の上に「設定の変更まで」を足す | 順序 1 本を保てるが、設定の変更とライブラリの整理は別の能力で、順序が付かない。例 1 だけ使いたい人にタグの変更まで許させることになる。親文書 §5.2 が予定する「移動・名前変更」「ごみ箱」の段との上下も決まらない |
| **B (推奨)** | 独立のチェック欄 2 つ。「今開いている場所を AI に見せる」「設定の確認と変更を AI に任せる」 | 既にある「見せる」チェック 4 つ (縮小画像・撮影位置・AI 説明文・文字起こし) と同じ形。許可の範囲の意味を変えない |
| C | B の「設定」を「見せる」「変えさせる」の 2 つに分ける (チェック欄 3 つ) | 「設定は見せるが変えさせない」が選べる。ただし設定の値は機微な情報ではなく (§6.2)、見せるだけの需要は薄い。状態が 1 つ増える |

B を採る。利用者の方針は「許可したら個別の確認はしない」で、読むだけと変えるを分ける理由が無い。
C が要るかは利用者の確認事項として残す (§13 U2)。

### 3.2 設定項目

`Settings` に 2 項目を足す (既定 false)。

| 項目 | 画面の表記 | 効くもの |
| --- | --- | --- |
| `agent_show_current_view` | 今開いている場所を AI に見せる | `get_view_state` |
| `agent_allow_settings` | 設定の確認と変更を AI に任せる | `get_settings`・`set_settings`・`set_favorite` |

- どちらも許可の範囲が「読み取りのみ」以上のときだけ効く。無効のときはチェックがあっても拒む
  (既存の 4 つのチェックと同じ規則。`check_tool_permission`、`src/agent_ipc/mod.rs:308-328`)。
- `PermissionSnapshot` (`crates/agent-ipc/src/lib.rs:406-414`) に 2 つの flag を足す。`miv_status` が返すので、
  AI は「設定の変更は許可されていません。mIV の『設定 → AI 連携…』で『設定の確認と変更を AI に任せる』を
  オンにしてください」と案内できる。拒否のエラー文も、足りない許可を名指しする (既存の方針、親文書 §5.2)。
- 保存の鍵は `agent_show_current_view`・`agent_allow_settings`。既存の `agent_*` と同じく、変わったら
  許可の epoch を進める (`src/settings_db.rs:1070,1201`)。
- `preferences_policy!` では既存の `agent_*` と同じ理由で exclude に入れる (「AI 連携の許可は移行先を維持」)。
  164 項目の外なので、AI は自分の許可を変えられない。
- これは未リリースの新しい項目で、旧データが無い。追加の列・既定値だけで足り、移行は要らない
  (既存の利用者は 2 項目とも false から始まる)。

### 3.3 許可の検査

既存の書き込みと同じ 2 段にする。

1. 要求を受けた thread で、設定 DB の snapshot から検査する (`Connection::request`)。
2. UI スレッドで実行の直前にもう一度 `self.settings` を見る (`admit_agent_metadata_write` と同じ、
   `src/app/agent_metadata_write.rs:74`)。

## 4. ヘルプ (`search_help`・`get_help`)

### 4.1 渡し方の比較

| 案 | 評価 |
| --- | --- |
| instructions に要約を持つ | 上限 4,096 字 (UTF-16、`crates/mcp-server/src/tests.rs:83-91`)、今 852 字。マニュアルは HTML で約 2.4MB + mIV Sound 約 2.1MB で、要約でも載らない。誘導の 1〜2 文だけ足す |
| MCP の resources | AI が自分から引けるかがクライアント次第 (今回は各クライアントの扱いを調べていない)。今は `tools` だけを公開しており (`crates/mcp-server/src/lib.rs:395,467`)、capability を増やすと互換の確認が広がる |
| **tool で検索と取得 (採用)** | AI が自分で引ける。既存の tool の作り (予算・テスト) にそのまま乗る |

### 4.2 同梱の仕方

- `crates/mcp-server` の build script が `htdocs/mimageviewer/manual/` を読み、節単位のテキストへ変換して
  exe に埋め込む。MCP exe は launcher に内包され版ごとに配られる (`crates/launcher/build.rs:52-73`) ので、
  **マニュアルは必ずその版のもの**になる。生成物はコミットしない (ずれる経路を作らない)。
- 対象: `manual/*.html` と `manual/sound/*.html`。`changelog.html` は除く (更新履歴は大きく、使い方ではない)。
  画像は除く。
- 節の単位は `<h2>`。最初の `<h2>` より前は「概要」の節にする。節の id は `ページ名#h2 の id`
  (id が無い h2 は `ページ名#n`、n はそのページ内の順番)。id はビルド時に一意であることを検査する。
- テキストへの変換: タグを落とす。表は行ごとに `セル | セル`。`<kbd>` の中身は残す。`<img>` は alt だけ残す。
  リンクは文字だけ残す。
- HTML の解析は、workspace に既にある crate があればそれを build-dependencies に使う。無ければ軽いものを 1 つ足す。
  マニュアルは自作で形が揃っているが、手書きのタグ除去にはしない。
- 圧縮はしない (MCP exe の依存を増やさない)。増える大きさは実装で測って報告する (見込み 1〜2MB、未実測)。
- `cargo:rerun-if-changed` はマニュアルのフォルダに付ける。マニュアルが無い checkout ではビルドを失敗させる
  (空のヘルプを黙って配らない)。

### 4.3 tool

`search_help { query, limit? }`

- 空白で区切った語の AND。ASCII は大文字小文字を区別しない部分一致。日本語はそのままの部分一致
  (形態素解析はしない。AI が言い換えて引き直せる)。
- 並びは、節の見出しに当たったもの → ページの題に当たったもの → 本文の出現数の順。
- 返すもの: `id`・ページの題・節の見出し・当たった付近の抜粋 (各 200 字まで)。`limit` は既定 10、最大 30。
- 応答に `app_version` を入れる (どの版のマニュアルかを AI が言えるように)。

`get_help { id? }`

- `id` が節 → 節の本文。データ応答の予算 (`MAX_PAGE_CHARS` 38,000 字、`crates/agent-ipc/src/lib.rs:108-111`)
  を超える節は、既存の cursor で続きを返す。
- `id` がページ名 → そのページの節の一覧 (id と見出し)。
- `id` なし → ページの一覧 (ページ名と題)。

どちらも本体へつながない。**mIV が起動していなくても、連携が無効でも答える**。中身は公開のマニュアルと同じで、
利用者の情報を含まない。検索語はどこにも記録しない (親文書 §5.4 の「検索語を残さない」と同じ)。

### 4.4 instructions

既存の文に 1〜2 文を足す (4,096 字の上限内、足す分は 300 字まで)。内容:

- mIV の機能・操作・設定の質問には、答える前に `search_help` / `get_help` を引く (同梱のマニュアルはこの版のもの)。
- 許可があれば `get_view_state`・`get_settings` で今の状態を確かめてから案内する。
- 設定を変える前に、何をどう変えるかを利用者に伝える (mIV は確認を出さないので、AI の側で伝える。保護ではなく案内)。

### 4.5 古い MCP exe

AI アプリが起動したままだと、MCP exe は本体より古い版のことがある (§1.789)。そのときヘルプは古い版の
マニュアルを返す。応答の `app_version` で分かる。追加の仕組みは作らない (AI アプリを再起動すれば新しくなる)。

## 5. 今の状態 (`get_view_state`)

### 5.1 返すもの

```json
{
  "view": "folder",
  "folder": "D:\\pics\\ai",
  "fullscreen": true,
  "item": { "path": "D:\\pics\\ai\\0012.png", "name": "0012.png", "kind": "image" },
  "search": {
    "item_index": false,
    "favorite": null,
    "favorite_root": false
  }
}
```

- `view`: 一覧の種類。`folder` / `search_results` / `tag` / `reading_history` / `bookmark` / `rating` /
  `smart_folder` / `subfolder_expansion` / `drive_list` / `other`。App の `items_are_*` の flag (`src/app.rs:16637-16661`)
  から決める。当てはまらないものは `other` (種類を増やすときに追加だけで済む)。
- `folder`: `App.current_folder` (`src/app.rs:16132`)。アイテム検索の結果を表示中は、検索の前の場所のまま
  (`src/app.rs:44633`)。無いときは null。
- `fullscreen`: 閲覧表示 (全画面) を開いているか (`fullscreen_idx`)。
- `item`: 閲覧表示で表示中の項目。閲覧表示でなければ選択中の項目。無ければ null。場所の表記は
  `list_folder` が受け取り・返すものと同じ投影を使う (ZIP・PDF の中も同じ。AI がそのまま `list_folder` や
  `get_item_info` に渡せる)。
- `search`: `folder` が検索の対象か。`metadata_ownership(...).owner(path)` (`src/metadata_ownership.rs:112,165`)
  で決める。`item_index` はアイテム索引 (Ctrl+G) の対象か。`favorite` はその場所を持つお気に入りの名前と場所
  (無ければ null)。`favorite_root` は `folder` 自体がお気に入りとして登録済みか (`Settings::is_favorite`、
  `src/settings.rs:11521`)。

### 5.2 どの表示を読むか

- UI スレッドの `poll_agent_open_requests` (`src/app/startup_ops.rs:180-225`) の時点で App の field が指している
  表示を読む。既存の「mIV で開く」が要求を受ける時点と同じ。
- **parked の viewer context は読まない。別ウィンドウ (F12 の別ウィンドウ・複数ウィンドウ) の中身は返さない**。
  返すのはメインの一覧と、メインの閲覧表示だけ。
- 読むだけで、どの field も書かない。detached の述語・viewport の経路には触れない
  (CLAUDE.md の「Detached viewer リワーク中のルール」の対象外であることを、設計レビューで確かめる)。
- 実装の最初に、`poll_agent_open_requests` の時点で mount されているのが常にメインの context であることを
  コードで確かめる。違っていたら実装せずに設計担当へ返す。

### 5.3 受付

- 起動処理中 (`!initialized` または索引の準備の overlay) は `NotReady`。
- リモート操作中は `Busy`「リモート操作中は表示の状態を返しません」。リモートが表示を持っている間の
  「今見ているもの」は PC の前の利用者のものではない。既存の書き込みがリモート操作中を拒むのと同じ判定
  (`with_local_composition_admission`、`src/app/agent_metadata_write.rs:95-100`) を使う。
- モーダルのダイアログを開いていても返す (読むだけなので拒まない)。

### 5.4 お気に入りの索引の有無

`list_library(kind=favorites)` の行に `item_index`・`container_index` (bool) を足す。追加だけの変更。
アイテム索引が ON の場所は `miv_status.search_scope` が既に返しているので、新しく渡る情報は
コンテナ索引の有無と、索引 OFF のお気に入りがどれか、だけ。これは「読み取りのみ」で返す (チェック欄は要らない)。

## 6. 設定 (`get_settings`・`set_settings`)

### 6.1 項目の表

設定の書き出し・取り込みの表 `preferences_policy!` (`src/settings_transfer.rs:181-777`) をそのまま使う。

- export 側 164 項目: 項目名・型・日本語の表記・検証・読み書き。
- exclude 側 339 項目: 除外の理由つき。表示やツールバーの状態、利用データ (お気に入り・タグ・履歴)、
  PC 固有のパス、外部ツール・フォント・LUT・Susie・VST、キー割り当て・リング、通信 (`update_check_enabled`・
  `remote_*`)、AI 連携の許可 (`agent_*`)、スクリプト (`stack_script_enabled`)。
- 新しい項目をどちらかに入れないとビルドが通らない (`exhaustive_policy`、`:185-187`)。

**AI が扱う鍵と値の形は、書き出しファイルの `preferences` の中身と同じ**にする (鍵は項目名、値は書き出しと同じ JSON)。
書き出しファイルは既に外へ出している形式 (format_version 1) なので、鍵を新しく決めない。

この表を使う理由 (設計の根拠として書く。後付けではなく、この表が作られた目的に合うため):
書き出し・取り込みは「別の PC へ持っていってよい環境設定」を選んだ表で、PC 固有のもの・通信の opt-in・
AI 連携の許可・任意のファイルを指すものを意図して外している (`docs/settings-export-import-plan.md`)。
AI に触らせてよい範囲とほぼ同じ線で、足りない分だけを §6.4 で引く。

### 6.2 `get_settings { query?, keys? }`

- `keys` も `query` も無い → 全項目の `key`・`label`・`value` だけ (選択肢は付けない。約 164 行で予算に収める)。
- `keys` (最大 32) または `query` (表記と項目名への部分一致、空白区切りの AND) → 当たった項目に
  `choices` と `writable` も付ける。
- `choices`: 列挙型の項目の選択肢。保存値と画面の表示名の組。数値・真偽・複合の項目は null。
- `writable`: AI から変えられるか (§6.4 の 8 項目は false)。
- 実行は UI スレッド。`capture_export(&self.settings)` をそのまま使う (メモリの中の値を読むだけで I/O は無い)。
  環境設定を開いて編集中でも、返すのは確定済みの値。

選択肢の出し方: 型ごとに trait (`SettingChoices`) を実装し、`preferences_policy!` の export 側の型すべてに要求する
(未実装の型があるとビルドが通らない)。真偽・数値・複合の型は「選択肢なし」を返す。列挙型は全部の値と表示名を返す。
保存値は書き出しと同じ serde の表記。`#[serde(other)]` の `Unknown` のような「読めなかった値」は選択肢に出さない。

渡る情報: 164 項目の値。表示・操作・既定の動作の好みで、ファイルの場所・名前・履歴は含まない
(それらは exclude 側)。例外として `image_ext_priority` (拡張子の並び) や `details_name_colors` (色) のような
複合の値も、個人を指す情報ではない。実装で 164 項目の型を見て、場所や任意の文字列を持つ項目が無いことを確かめる
(あれば §6.4 と同じ表で「返さない」に入れ、設計担当へ報告する)。

### 6.3 `set_settings { changes: { key: value, … } }` — 確定処理

**環境設定の OK と同じ経路・同じタイミングで反映する**。UI スレッドで次を順に行う。

1. 許可を見る (§3.3)。
2. 受付 (§6.5)。
3. `changes` を検査する (§6.6)。1 つでも通らなければ全体を拒み、何も変えない。
4. 対象の鍵の今の値を控える (`before`)。
5. 下書きを作る: `ensure_preferences_state()` (`src/ui_dialogs/preferences.rs:2828`)。
6. 下書きへ値を入れる: 取り込みと同じ `ParsedPreferences::apply_to(&mut draft.settings)`
   (`src/ui_dialogs/preferences/transfer.rs:190`)。
7. 確定する: `apply_preferences_dialog(ctx)` (`src/ui_dialogs/preferences.rs:2897`)。`show_preferences` は立てない
   (画面は開かない)。
8. 対象の鍵の値を読み直す (`after`)。`before`・`after` を応答に入れ、変更の通知と記録を出す (§9)。

5〜7 は、設定の取り込み → OK と同じ処理 (取り込みは 5・6 のあと環境設定を開き、利用者が OK を押すと 7 が走る)。

**切り出しをしない理由**: 確定処理は、項目ごとの後処理 (一覧の読み直し、閲覧表示の位置の取り直し、
別ウィンドウを閉じる、キャッシュの無効化、保存など) を約 450 行の中に直に書いている。AI 用に「この設定を
適用する」入口を別に作ると、後処理の並びを 2 か所で保つことになり、片方だけ直す事故の元になる。
下書きを作って同じ関数を呼べば、**後処理の持ち主は 1 つのまま**で、新しい項目の後処理を足したときも
AI 側は何も変えなくてよい。「環境設定を開いて、その項目だけ変えて、OK を押した」と同じ結果になる。

**同じにならない点と扱い**:

- 確定処理は 2 つの場合に、設定を入れ替えずに戻る (`install_preferences_settings`、`:2619-2631`。
  本の順序を保存中の本棚フォルダの変更、本への追加の途中)。本棚フォルダは exclude 側 (PC 固有のパス) で
  AI からは変えられないので前者は起きない。後者は受付 (§6.5) で先に拒む。それでも値が入らなかった場合に備え、
  8 の読み直しで **実際に入った値を応答に返す** (入らなかった項目は `before` と同じ値になり、AI に見える)。
  入らなかった理由を型で返す仕組みは足さない。
- RAW の同時現像数のように、確定処理が値を丸めたり元へ戻したりする項目も、8 の読み直しで実際の値が返る。
- `ensure_preferences_state()` は下書きを作るときに件数を数える DB の読み取りを同期で行う
  (`:2846-2855`、音量の正規化 DB・閲覧履歴 DB の `count()`)。環境設定を開くときに今も UI スレッドで
  走っている処理で、新しく増えるものではない。`perf::event` をこの区間に入れ、実装で時間を測って報告する。
  長ければ、件数を使わない下書きの作り方を設計担当と決める (先回りして分岐を作らない)。
- 7 のあと `pref_state` が残っていないことを検査する (debug_assert とテスト)。§6.5 の受付が通れば、
  確定処理の冒頭の早期 return (`:2898-2917`) には入らない。

**確定のタイミング**: 1 回の `set_settings` が 1 回の確定。複数の項目を 1 回で渡せば、OK を 1 回押したのと同じ。

### 6.4 AI に変えさせない項目

export 側 164 項目のうち、次の 8 項目は **読めるが変えられない** (`writable: false`、`set_settings` は拒む)。

| 項目 | 画面の表記 | 理由 |
| --- | --- | --- |
| `skip_recycle_bin_delete_confirmation` | ごみ箱への削除確認を省略 | 削除の確認を外す |
| `write_rating_to_xmp` | 評価を XMP に保存 | ファイルへの書き込みを始める |
| `clipboard_capture_image_enabled` | コピーした画像を自動保存 | クリップボードの監視と保存を始める |
| `clipboard_capture_html_enabled` | コピーしたページの画像を選んで保存 | 画像をサイトから取得する (通信) |
| `reading_history_enabled` | 閲覧履歴を記録 | 記録の開始・停止 |
| `save_search_input_history` | 検索欄の入力履歴を保存する | オフで確定すると今の入力履歴を消す (`privacy.html:152`) |
| `sidecar_backup_enabled` | 編集データのサイドカーバックアップ | バックアップを止める |
| `tag_sidecar_backup_enabled` | タグのサイドカーバックアップ | 同上 |

基準: (1) 削除・上書きの確認を外す、(2) ファイルへ書き込む、(3) 通信や監視を始める、(4) 記録やバックアップを
止めて利用者のデータが失われ得る。**この 4 つに当たるものは、利用者が mIV の画面で自分で変える**。

- 表の持ち方: `preferences_policy!` の export 側の行に印を足さず、agent 側に項目名の定数表を 1 つ置く。
  テストで「表の項目名がすべて export 側にある」ことを検査する (項目名を変えたときに黙って外れない)。
- 実装で 164 項目を上の基準で 1 つずつ見直し、当たる項目がほかにあれば表へ足して設計担当へ報告する
  (設計では表記から選んだ。`edit_restore_prompt_enabled` 「編集の復元確認」は、オフにしたとき失われるものが
  あるかをコードで確かめてから決める)。
- 164 項目の外 (exclude 側) は、鍵として受け付けない。**AI 連携の許可・通信 (更新確認・リモート)・外部ツール・
  スクリプト・保存先などのパス・お気に入り・キー割り当ては、`set_settings` では変えられない**。

この線引きは利用者の確認事項 (§13 U1)。

### 6.5 受付

UI スレッドで、次のどれかなら拒む (何も変えない)。

| 条件 | 応答 |
| --- | --- |
| 起動処理中 (`!initialized`、索引の準備の overlay) | `NotReady` |
| モーダルのダイアログ・処理が出ている (`modal_dialog_block_reason().is_some()`、`src/app.rs:23962`) | `Busy`「mIV でダイアログを開いている間は設定を変更できません。閉じてからやり直してください」 |
| 環境設定の下書きが残っている (`pref_state.is_some()`) | 同上 |
| リモート操作中 | `Busy`「リモート操作中は設定を変更できません」 |

- モーダルの表には、環境設定・操作カスタマイズ・お気に入りの追加と編集・AI アプリの登録・本への追加の取り消し
  などが入っている (`:24026-24082`)。**表を 1 つ見るだけにして、設定用の条件を並べ直さない**。
  利用者が環境設定を開いて編集している間は AI からは変えられない (取り込みが「環境設定が開かれたため中止」
  とするのと同じ考え、`transfer.rs:175-181`)。下書きが 2 つ同時に在る状態を作らない。
- UI スレッドへの受け渡しは、既存の `OpenController` の dispatch に要求の種類を足す
  (`UiRequestKind`、`src/agent_ipc/open.rs:54-58`)。UI が 5 秒以内に受け取らなければ未実行のまま `Busy` を返す
  (既存の claim の規則)。受け取ったあとは同じ frame の中で確定まで終わる。
- 閲覧表示 (全画面) を開いたままでも受け付ける。確定処理は閲覧表示中の反映を持っている
  (`fullscreen_idx` を見る後処理が複数ある、`:3061` ほか)。別ウィンドウを開いているときに
  「複数ウィンドウモード」「動画・音声は別ウィンドウで再生」を変えると、確定処理が別ウィンドウを閉じる
  (`:3187-3198`)。環境設定の OK と同じ結果で、AI 用の扱いは足さない。

### 6.6 検査

- `changes` は 1〜32 項目。鍵は export 側の項目名。知らない鍵・exclude 側の鍵・§6.4 の鍵が 1 つでもあれば全体を拒む
  (エラー文に鍵の名前を入れる。AI が直せるように)。
- 値は取り込みと同じ検査 (`parse_items` → 項目ごとの validator) を通す。型・選択肢・範囲が合わなければ全体を拒む。
- **一部だけ入れることはしない**。取り込みは通らなかった項目を飛ばして残りを入れるが、AI からの変更は
  「言われたとおりに全部入った」か「何も変わっていない」のどちらかにする (応答を読む AI が、どこまで入ったかを
  推測しなくて済む)。
- 3 項目まとめて扱う group (`fullscreen_seek_bar_locked` ほか、`:434`) は、書き出しと同じ 1 つの鍵として扱う。

## 8. お気に入り (`set_favorite`)

### 8.1 tool

`set_favorite { path, name?, item_index?, container_index? }`

- `path` が未登録 → お気に入りへ登録し、渡された索引の flag を入れる (渡されなかった flag は false)。
  `name` が無ければフォルダ名。
- `path` が登録済み → 渡された flag だけを変える。`name` は無視する (名前の変更はしない)。
- 応答: `added` (新しく登録したか)、`before`・`after` (`item_index`・`container_index`、未登録だった場合の
  `before` は null)。
- 削除・名前の変更・並べ替え・別バージョン索引・サムネイルの事前作成は扱わない。お気に入りの削除は、
  補正のお気に入り標準と表示の記憶も消す (`src/ui_dialogs/favorites_editor.rs:1272-1277`) ので、AI には渡さない。

tool を 1 本にする理由: 「登録する」と「索引を切り替える」を分けると、未登録の場所に索引だけ頼まれた場合の
扱いが増える。1 本なら「この場所をこの状態にする」で済む。

### 8.2 実行

既存の画面と同じ関数を通す。

- 登録: 追加ダイアログの確定の中身 (`src/ui_dialogs/fav_add.rs:134-175`。`try_add_favorite` → flag → 保存 →
  indexer の同期 → コンテナ索引の起動 → `cc.checked` の長さ合わせ) を **App の関数 1 つに切り出し、
  ダイアログと AI の両方から呼ぶ**。挙動は変えない切り出し。
- 索引の切り替え: お気に入り編集と同じ `apply_favorite_meta_index_change` (アイテム索引)、
  `apply_favorite_name_index_change` (コンテナ索引、`src/app.rs:33022`) を呼び、`settings.save()`。
  編集画面が変更をためて最後にまとめて行う並び (`favorites_editor.rs:1280-1304`) と同じ順にする。
- 場所の検査は worker で行う (既存の「mIV で開く」と同じく、存在の確認は UI スレッドでしない、
  `src/agent_ipc/open.rs` の `dispatch_request`)。絶対パスで、実在するフォルダであること。追加ダイアログが
  受け付ける種類 (フォルダだけか、ZIP 等も可か) を実装の最初にコードで確かめ、同じ範囲にする。
- 上限 100 件 (`MAX_FAVORITES`)・重複は、`try_add_favorite` のエラーをそのまま返す。

### 8.3 受付

§6.5 と同じ表 (起動処理中・モーダル・リモート操作中)。お気に入り編集は `self.settings.favorites` を位置で直接
書き換える画面なので、開いている間は AI からは変えない (モーダルの表に `favorites_editor`・`fav_add` が入っている)。

### 8.4 索引の作成

アイテム索引を ON にすると、背景で場所の中を走査して索引を作る。大きい場所では時間がかかる。

- tool の説明に「索引の作成は背景で始まり、終わるまで検索に出ない項目がある」と書く。
- **作成の進み具合は今回返さない**。AI は「進み具合は mIV の『お気に入り → 編集』で見られます」と案内する
  (マニュアルに書いてある内容)。進み具合を返す tool は後続の候補 (§12)。
- OFF にすると索引を消す (作り直せるデータ)。ON と OFF の両方を許す (OFF は ON の取り消しとして要る)。

## 9. 変更の通知・記録・取り消し

- **通知**: 変更のたびにトースト (「AI アプリが設定を変更しました: 閲覧表示の通常ホイール操作」など)。
  既存の `ChangeController::publish` (`src/agent_ipc/changes.rs:166-172`) を使う。
- **記録**: 「AI 連携」の窓の「AI による変更」に、項目の表記・変更前・変更後を出す (既存の `ChangeRow` の形)。
  メモリの中だけで、mIV を閉じると消える (今と同じ)。
- **ログ**: 通常のログに、tool 名・変えた項目名・変更前後の値を残す (「AI が勝手に変えた」の調査のため)。
  設定の値は機微な情報ではない。お気に入りは場所も残る (利用者が画面から登録したときと同じ扱い)。
- **取り消し**: 専用の tool は作らない。`set_settings`・`set_favorite` の応答に変更前の値が入っているので、
  AI は同じ tool に変更前の値を渡せば戻せる。利用者は「AI による変更」を見て、環境設定で戻すこともできる。
  「変更の履歴」を別に持つと、履歴と実際の値がずれる場合 (あとから利用者が画面で変えた等) の扱いが増えるので持たない。

## 10. IPC と tool 一覧の予算

- `AGENT_PROTOCOL_VERSION` を 5 → 6 にする。足すのは `Command` の 4 種 (`GetViewState`・`GetSettings`・
  `SetSettings`・`SetFavorite`)、`PermissionSnapshot` の flag 2 つ、お気に入りの行の field 2 つ。
  **追加だけ**で、版 3〜5 の adapter はそのまま動く (`crates/agent-ipc/src/lib.rs:3-18` の契約、§1.789 A-2)。
  版 5 までの凍結互換テストに、版 5 の adapter が新しい field を無視して動くことを足す。
- 新しい adapter が古い本体につないだ場合は、既存の版の取り決めに従って「mIV を更新してください」を返す。
  ヘルプの 2 本は本体を使わないので動く。
- ヘルプの 2 本は pipe を開かない。ほかの tool は今と同じく呼び出しごとに接続する (`crates/mcp-server/src/pipe.rs:265-310`)。
- **tool 一覧 (tools/list) の予算**: 上限 48,000 字、検査の余裕 512 (`crates/mcp-server/src/lib.rs:22`)。
  親文書の記録では最大 41,824 字 (余裕込み 42,336、`mcp-integration-plan.md:6450`) で、残りは約 5,600 字。
  6 本で 4,500 字以内を目標にする (説明は短くし、細かい使い方はマニュアルの「AI アプリとの連携」の節に書いて
  `get_help` で引かせる)。**実装の最初に今の実測を取り、6 本が入らなければ実装を進めずに設計担当へ返す**
  (上限を上げるか、既存の説明を削るかは設計で決める)。
- annotation: `search_help`・`get_help`・`get_view_state`・`get_settings` は `readOnlyHint=true`。
  `set_settings`・`set_favorite` は `readOnlyHint=false`、`destructiveHint=false`
  (変更前の値へ戻せる。索引 OFF は作り直せる)。

## 11. キー割り当てを今回は外す提案

統括の読みは「段 1〜3 (案内、状態と設定、お気に入り・索引・キー割り当て) を 1 回で」。このうち
キー割り当てだけを後続に回すことを提案する。

- 利用者の例 3 つは、キー割り当てを使わない。案内は今回のヘルプで届く (操作カスタマイズの画面の使い方は
  マニュアルにある)。
- 要るものが設定とは別系統で、一式が増える: 操作の一覧 (画面の種類ごと) を返す tool、同じキーの重複の規則、
  既定へ戻す操作、リング・マウスボタン・ゲームパッドとの関係。適用の入口も環境設定の確定処理とは別
  (`apply_operation_customize_bundle`、`src/ui_dialogs/preferences.rs:4050`) で、受付・テストがもう 1 組要る。
- tool 一覧の予算が残り約 5,600 字で、今回の 6 本でほぼ使う。
- 「動画・音声の通常ホイール」(`ring_shortcuts.video_normal_wheel_action`) も操作カスタマイズ側の項目なので、
  今回は変えられない (案内はできる)。キー割り当てと一緒に後続で扱う。

## 14. 確かめていない点

実行時の挙動は誰も観測していない。実装と実機で確かめる。

- 閲覧表示を開いたまま確定処理を通したとき、表示が崩れないこと。次のホイールから新しい値で動くこと (例 1)。
- 別ウィンドウ・複数ウィンドウを開いているときに設定を変えたときの挙動 (環境設定の OK と同じになるはず)。
- `ensure_preferences_state()` の時間 (§6.3)。
- `poll_agent_open_requests` の時点で mount されている context (§5.2)。
- tool 一覧の実測の字数 (§10)。
- 同梱で増える exe の大きさ (§4.2)。
- 各 AI アプリが、6 本を足した tool 一覧と instructions を受けて、質問に対してヘルプを引くか
  (AI アプリの側の動きで、mIV からは保証できない)。
- 追加ダイアログが受け付けるお気に入りの種類 (§8.2)。

## 15. 状態を減らす検討の記録

| 検討 | 結果 |
| --- | --- |
| 設定の反映を AI 用に作るか、環境設定の OK と同じ経路に揃えるか | 揃える (§6.3)。後処理の持ち主を 1 つに保つ |
| 環境設定を開いている間の AI からの変更 | 拒む (§6.5)。下書きが 2 つ在る状態を作らない |
| ほかのダイアログ・処理の途中の変更 | 既存のモーダルの表 1 つで拒む。設定用の条件を並べない |
| 一部の項目だけ入る場合 | 作らない。全部入るか何も変わらないか (§6.6) |
| 変更の履歴・取り消しの tool | 持たない。応答の変更前の値で戻す (§9) |
| 登録と索引の切り替えを別の tool にするか | 1 本にする (§8.1) |
| 読むだけ / 変える の許可を分けるか | 分けない (§3.1) |
| 許可の範囲に段を足すか | 足さない。独立のチェック欄 (§3.1) |
| 別ウィンドウの中身を返すか | 返さない。メインの表示だけ (§5.2) |
| リモート操作中の扱い | 読む・変えるとも拒む。既存の書き込みと同じ判定 |
| マニュアルの生成物をコミットするか | しない。ビルドで作る (§4.2) |

**まれな失敗は割り切り (ログ + 通知)**。設定の保存に失敗したときは、確定処理が今も出している警告
(「設定を保存できませんでした。…」、`preferences.rs:3213-3215`) のまま。応答はメモリの中の値を返す。
UI が 5 秒応答しないときは未実行で `Busy`。回復の仕組みは足さない。

## 17. 実装の区切りとテスト

実装は Codex、検収は設計担当。区切りごとにコミットする。

| 区切り | 内容 | 主なテスト |
| --- | --- | --- |
| A | ヘルプ (MCP exe だけ)。build script、`search_help`・`get_help`、instructions | 生成が決定的、節の id が一意、全ページの節が引ける、AND 検索、長い節の続き、tool 一覧の予算、マニュアルが無いとビルド失敗 |
| B | 許可 2 項目、IPC 版 6、`get_view_state`、お気に入りの行の索引の有無 | 許可オフで拒否・epoch、一覧の種類ごとの `view`、リモート操作中の拒否、版 5 の adapter の互換 |
| C | `get_settings`・`set_settings` | 下記 |
| D | `set_favorite` (追加の確定の切り出しを含む) | ダイアログと同じ関数を通る、上限・重複、索引 ON で indexer が同期、OFF で戻る、モーダル中の拒否 |
| E | 設定画面、公開文書、マニュアル、ui_snapshot | 3 区画がチェックに応じて変わる、検索の語、`check_site_cards.py`・`check_ui_glyphs.py` |

区切り C のテスト (設定は、編集 → 確定 → 効果までを通しで確かめる):

- 変更なしの確定 (`changes` が今の値と同じ) で、`Settings` が変わらず、後処理も走らない。
- `fullscreen_wheel_action` を変えると、`self.settings` と設定 DB の両方が変わり、閲覧表示のホイールの判定
  (`fs_wheel_segment_in_page_scroll`) が新しい値を読む。
- 164 項目すべてについて、`get_settings` の値を `set_settings` に渡すと通る (往復)。
- §6.4 の 8 項目・exclude 側の鍵・知らない鍵は拒まれ、何も変わらない。
- 型・選択肢・範囲が合わない値は拒まれ、同じ呼び出しの正しい項目も入らない。
- 環境設定を開いている・モーダルが出ている間は `Busy` で、下書きに触れない。
- 確定のあと `pref_state` が残らない。
- 応答の `before`・`after` が実際の値と一致する。
- 列挙型の項目すべてに選択肢があり、選択肢の値はすべて検査を通る。

テストの範囲: 環境設定の確定処理は変えない (呼ぶだけ)。変えるのは agent の受付と、お気に入りの追加の切り出し。
ブランチでは関連の filter (agent・preferences・settings_transfer・fav_add・mcp-server・agent-ipc) を流し、
本体 lib の全件は master への取り込みの後に統括が 1 回流す (CLAUDE.md「テストの段階分け」)。

実機の確認 (利用者、インストーラ版または build-dev): §14 の上 2 つと、例 1〜2 を AI アプリから通しで。
