## 0. 背景

状態によって出たり消えたりする行を縦に積んでいる。そのため**状態が変わるたびに上部の高さが変わり、

これを「状態が変わってもレイアウトが動かない」構成に整理する。**機能は削らない。置き場所を変える。**

## 1. 新しい配置

## 2. モーダル化について（判断の根拠も記録すること）

CLAUDE.md「状態の組み合わせを減らす」に従い、読込衝突の確認は表示中に他の編集を受け付けないモーダルにする。
既存の H1 / H2 の状態遷移（`ProjectLoadState::Ready`、`LrcLoadState::Ready`、`apply_ready_*` / `discard_ready_*`、
`defer_loaded_project`）の**判定ロジックは変えない**。変えるのは提示の仕方だけ。
モーダル表示中に非同期完了（別の読込・素材・LRC）が届いた場合の扱いが既存と同じであることを、既存テストの
維持と追加テストで示す。モーダルにすることで既存の状態遷移の前提（「Ready の間も編集が続く」など）と
矛盾が出る場合は、実装を止めて根拠を添えて報告する。

## 3. 絶対に守ること

1. 上部ツールバーとステータスバーの高さが、プロジェクト・素材・書き出し・再生・未解決の状態で**変わらない**。
2. 既存の操作・確認・警告を**1 つも失わない**（置き場所の移動のみ）。§0 の各項目の移動先を報告に表で示す。
3. L1 の編集フレーム API（`begin_frame` … `finish`、`process_editor_frame`）の順序、L2 の枠、
   非同期完了は全パネルの入力の後、を維持する。モーダルのボタン入力も完了の採否より前に反映する。
4. `musicvideo-ui` は egui と core 系だけに依存（eframe / cpal / ffmpeg を入れない）。共有 UI に移すもの
   （例: 未解決素材の一覧描画、プロジェクトタブの素材パス表示）は `musicvideo-ui`、ファイルダイアログや
   ホストの状態はラボに置く。
5. `src/`（本体）・`comic-core`・`music-core`・`musicvideo-core` を触らない。アプリを起動しない。コミットしない。
   `cargo fmt` を通す。

## 4. テスト

1. **高さが変わらない**: 次の状態それぞれで、上部ツールバーとステータスバーの矩形の高さが基準と同じ
   （egui の headless テストで実際に描いて測る）: 通常、未保存、素材読込中、素材未解決、書き出し中、
   書き出し完了後、再生中（計測あり）、プロジェクト読込衝突中、LRC 読込衝突中、復元失敗。
2. 読込衝突のモーダル: 「切り替える」「続ける」の結果が従来と同じ。表示中は Properties / Timeline の編集入力が
   Project を変えない。既存の同フレーム完了テストが維持される。
3. 未解決素材ウィンドウから「画像を差し替える」が従来と同じ要求を出す。
4. 診断ウィンドウは既定で閉。開いても上部の高さが変わらない。
5. 変異検証: 例えば計測行を上部に戻す、確認をインラインに戻すと §4-1 が落ちることを確かめる。
