# ブリーフ: Phase 3 Step 3i — 右パネルのタップでパネルがスクロールする

対象: v2.13.0 タッチ対応 Phase 3。実装 = Codex Sol / レビュー・検収 = ClaudeCode /
実機確認 = 利用者。

正本: [docs/touch-support-plan.md](touch-support-plan.md) §5.7-2 / §5.15。

前提 (コミット済み、`b7ca719f` まで): Phase 3 Step 3h まで。

---

## 1. 症状 (実機、2026-08-09)

> 右パネルで、#★ などのタグを**タップで操作すると、右パネルが下の方にスクロール**します。
> **マウスクリックではこの問題は起きません。**

あわせて、同じ面で次も報告されている (原因が同じかは未確認):

> 右パネルで #★ をマウスクリックし、右上にトーストが出ている間にもう 1 回クリックすると、
> トースト消去になり #★ のクリックがキャンセルされるようです。

**⚠ 後者はコードと矛盾している。** トーストが `Sense::click()` で interact するのは
`fs_feedback_toast_reveal_path` が `Some` のときだけで
([ui_fullscreen.rs:25064](../src/ui_fullscreen.rs))、これはキャプチャ保存など
「保存ファイルを表示」を提供するトースト専用である。タグのトーストは reveal path を
持たないので、**クリックを奪わないはず**。

トーストの矩形は**画面右上**、右パネルも**画面右端**なので、**両者が重なる帯**がある。
まずそこを疑うこと。

---

## 2. ⚠ 先に原因を確定すること。推測で直さないこと

このセッションでは、推測に基づく修正が 2 回外れている
(plan §5.10 と Step 3f/3g の記録を参照)。**症状を消すガードを入れないこと。**

### 2.1 ClaudeCode の仮説 (検証対象であって、前提ではない)

**タップとタップの間でポインタが瞬間移動している**のではないか。

- マウスは連続的に動くので `pointer.delta()` は常に小さい
- タッチは前のタップ位置から次のタップ位置へ**いきなり飛ぶ** (間の移動が存在しない)。
  `PointerGone` を挟んでも、次の `PointerMoved` で egui は大きな delta を得る
- `ScrollArea` は既定 `ScrollSource::ALL` (`drag: true`) で、コンテンツより先に
  **低優先度の背景 drag 応答**を置いている (plan §5.7-2、`scroll_area.rs:786-830`)。
  押下フレームの差分をスクロールとして解釈し得る

これなら「マウスでは起きない」「下方向に大きく飛ぶ」の両方が説明できる。
**ただし確認すること。** 別の原因 (フォーカス取得時の scroll-into-view、
タグ増減によるレイアウト変化、トースト矩形との重なり) も同じ症状を出し得る。

### 2.2 確定のしかた

原因が絞れないなら、**分岐や値を 1 行に出す一時ログを入れて実機ログを取る**
(Step 3f / 3g はこれで 2 往復で確定した)。ClaudeCode が実機依頼とログ確認を行う。
**原因が分かったら一時ログは撤去し、回帰テストに置き換えること。**

---

## 3. 直し方の方針

原因が確定してから決める。ただし次を守ること。

- **パネルの指スクロール自体は殺さないこと。** 静止画・動画とも指ドラッグでの
  スクロールは実機確認済みで、利用者が使っている機能である
- **タップとドラッグの区別は既存の認識器に持たせる。** 新しいしきい値や
  「タップ直後は N ms スクロールしない」のような時間ガードを足さない
  (plan §5.10: 見えない時間状態で意味を変えない)
- **見た目・レイアウトを変えないこと。** スナップショットに差分が出たら報告する
- **マウス経路を変えないこと** (§5.15)

## 4. トーストの件 (§1 後半)

- **仕様として不統一は意図的**である: 行動を提供するトースト (保存ファイルを表示) だけが
  押せて、情報通知は押せない。**この区別は変えないこと**
- 調べるのは「**タグのトーストが押せないはずなのにクリックが消える**」ほうだけ。
  トーストの painted rect と右パネルの当たり判定の重なりを確認する
- 重なりが原因なら、**トーストが情報通知のときはポインタを通す**のが素直
  (押せないものが下の操作を塞がない)。修正するならその形にする
- 原因がこれでなければ、**直さずに報告すること**
