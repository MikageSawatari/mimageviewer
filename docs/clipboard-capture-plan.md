# クリップボード取り込み 設計書

ステータス: **初版 (2026-10-02)・独立レビュー前・未実装**。
担当: 設計・検収 = ClaudeCode Opus 5.5 / high、実装 = Codex GPT-6.1 Sol / high、
独立レビュー = 実装者とは別の GPT-6.1 Sol / xhigh (AGENTS.md の既定)。
作業ブランチ: `clipboard-capture` (worktree `C:\home\mimageviewer-clipcapture`)。

## 1. 目的

普段の作業中に見つけた画像を、手間なく mIV に取り込めるようにする。

- 画像そのものをコピーした (スクリーンショット、ブラウザの「画像をコピー」など) ときは、自動で保存する。
- ブラウザでページの HTML をコピーした (Ctrl+A → Ctrl+C など) ときは、ページ内の画像を一覧から選んで保存できる。

ブラウザ拡張・ストア公開・mIV 内ブラウザを使わず、**クリップボードだけ**で完結させる。

## 2. 利用者向け仕様 (2026-10-02 利用者と合意)

### 2.1 設定

環境設定に「クリップボード取り込み」ページを新設し、次の 2 つのチェックを置く。どちらも既定 OFF。

- □ 画像がコピーされたら自動で保存する
- □ ページ (HTML) がコピーされたら、含まれる画像を選んで保存できるようにする

加えて、保存先フォルダ (既定 `ピクチャ\mimageviewer\clipboard`、変更可・既定に戻す・フォルダを開く) を置く。
どちらの監視も **mIV の起動中だけ**動く。トレイ常駐と組み合わせれば常時になる旨をページに書く。

### 2.2 画像のコピー

クリップボードに画像データが入ったら、保存先へ PNG などで保存し、右下の小窓 (§2.4) で
「クリップボードの画像を保存しました [開く]」と知らせる。

### 2.3 ページ (HTML) のコピー

1. ブラウザでページを選択してコピーすると、mIV が HTML から画像 URL を数える。
2. 右下に小窓「このページの画像 N 件 [画像を選んで保存] [×]」を出す。
3. ボタンを押すと mIV が前面に出て、メインウィンドウ内に選択ダイアログが開く。**画像の取得はこの時点から**始める。
4. 縮小表示を見ながら選び、[保存] で保存先へ書き出す。

### 2.4 右下の小窓

- mIV 専用の小さなネイティブウィンドウ。**前面ウィンドウ (= 多くの場合ブラウザ) のある画面**の作業領域の右下に出す。
- **フォーカスを奪わない**。ブラウザでの作業を止めない。
- 8 秒で消える。マウスを乗せている間は消えない。
- 内容は常に最新 1 件だけ。続けてコピーしたら中身を置き換える。
- Windows の通知機能は使わない (§3.3)。OS の通知設定に関係なく出る。

### 2.5 Ctrl+V

mIV の一覧で Ctrl+V を押したとき、クリップボードの中身で動作を分ける。監視のチェックが OFF でも動く (手動の入口)。

| クリップボードの中身 | 動作 |
| --- | --- |
| ファイル (Explorer のコピー / 切り取り) | 従来どおり今のフォルダへ貼り付け |
| 画像データ | 保存する (保存先は §10 Q1) |
| HTML (画像 URL あり) | 選択ダイアログを開く (保存先は §10 Q1) |

小窓を見逃した場合の救済も Ctrl+V が担う。

### 2.6 ファイル名

```
<日時>-<ドメイン>_<連番>.<拡張子>
例: 20261002-153012-345-www.example.com_01.jpg
    20261002-153012-345-www.example.com_02.jpg   ← 同じコピーなので 1 スタック
    20261002-154500-012_01.png                    ← 画像データのコピー (出どころ不明)
```

- 既定のスタック規則 (最後の `_` より前が同じものを畳む、[filename-stack-plan.md](filename-stack-plan.md)) で、
  **1 回のコピーが 1 スタック**になる。
- 日時が先頭なので名前順 = 取り込み順。ミリ秒まで入れる。
- `_` より前に `_` を含めない。日時の区切りは `-`。ドメイン中の `_` と Windows で使えない文字は `-` に置換する。
- 連番の桁は、そのコピーの枚数に応じて 2 桁以上でそろえる (100 枚以上なら 3 桁)。
- 拡張子は、取得した**中身から判定した形式**で付ける (URL の拡張子は信用しない)。
- 元のファイル名はファイル名に入れない。出どころは §7.5 で記録する。
- スタック表示の ON/OFF は既存のトグルのまま。このフォルダで自動 ON にはしない (状態を増やさないため)。
- 区切り文字の設定を `_` 以外に変えている利用者の場合はまとまらない。マニュアルに「既定の区切り文字でまとまります」と書く。

### 2.7 保存先フォルダ

- 既定は `capture::default_output_dir().join("clipboard")` (= `ピクチャ\mimageviewer\clipboard`)。
- その下に月ごとのサブフォルダ (`2026-10`) を作る。
- フォルダは**最初に保存するとき**に作る。チェックを入れた時点では作らない。
- 場所▼メニューに「クリップボード取り込み」を出す。表示条件は「2 つのチェックのどちらかが ON」とし、専用の表示設定は増やさない。
- 本棚と違い、検索索引の除外対象にはしない。お気に入り配下にあれば通常どおり Ctrl+G / Ctrl+S の対象になる。

## 3. 検討した代替案と採否

### 3.1 取り込みの入口

| 案 | 採否 | 理由 |
| --- | --- | --- |
| ブラウザ拡張 (Native Messaging + 中継 exe) | 不採用 | ストア公開 (Chrome / Edge / Firefox) と審査、拡張のインストール手順、中継 exe のレジストリ登録が要る。単体 exe 版は本体の場所が版ごとに変わるので登録先の管理も要る |
| mIV 内の WebView2 で URL を開く | 不採用 (将来の候補) | ログインが必要なサイトで、埋め込みブラウザからのログイン自体が拒否される可能性がある (Google は方針として制限)。サイトごとに試さないと成否が分からない。取りこぼしが問題になったら再検討する |
| **コピーした HTML / 画像をクリップボードから読む** | **採用** | 追加インストール・公開作業・ログインが不要。実装も既存部品 (クリップボード監視・HTTP 取得) の延長で済む |

HTML から得た URL を mIV が取得する方式の制約 (取れない画像) は §7.3 に整理した。

### 3.2 保存先

| 案 | 採否 | 理由 |
| --- | --- | --- |
| 本棚の本「クリップボード画像」 | 不採用 | 本はページ順を持つ冊子 (`0001_元名` の連番、1 冊 9999 ページ上限) で、本棚は検索索引の対象外。溜め続ける場所に合わない |
| **専用の通常フォルダ (月ごと)** | **採用** | 上限なし、検索対象、取り込み順に並ぶ。冊子にしたい分は既存の「本に追加」で送れる |

### 3.3 HTML 検出の知らせ方

| 案 | 採否 | 理由 |
| --- | --- | --- |
| トレイのバルーン通知 (mXD と同じ) | 不採用 | Windows の通知を OFF にしている利用者には何も出ず、しかも出なかったことを mIV が知る手段が無い (`Shell_NotifyIconW` は抑止時も成功を返す)。「mIV が動いていない」と誤解される。ボタンも付けられない。トレイアイコンの常時表示も要る |
| Windows の通知 API (AppUserModelID 登録) | 不採用 | 同じく OS の通知設定で消える。3 つの配布形態すべてでレジストリ登録が要る |
| **mIV 専用の小窓** | **採用** | OS の設定に左右されない。ブラウザのある画面に出せる。ボタンと 8 秒表示を自由に作れる。代わりに位置・DPI・フォーカス非奪取を mIV が持つ (§6) |

## 4. 状態の組み合わせを減らすための決定

CLAUDE.md「設計の簡素化」に従い、割り込みを扱う仕組みを作る前に、組み合わせ自体を減らした。

1. **HTML の待ちは最新 1 件だけ**。待ち行列は持たない。小窓は内容を置き換える。
2. **小窓の時点では何も取得しない**。取得は選択ダイアログを開いてから始める。普段のコピーで通信は発生しない。
3. **選択ダイアログはモーダル**。開いている間、フォルダ移動・フルスクリーン・別ダイアログなどの操作は受け付けない
   (`App::common_modal_dialog_open` へ登録)。閉じたら取得中の処理を取り消し、一時ファイルを消す。途中から再開する仕組みは持たない。
4. **選択ダイアログを開いている間の HTML 検出は無視する** (小窓を出さず、待ちも更新しない)。閉じた後に必要なら Ctrl+V で開き直す。
5. **画像データと HTML が両方あるコピーは、画像データだけで判断する**。ブラウザの「画像をコピー」は両方入るため。
   画像の自動保存が OFF なら何もしない (HTML 側へ回さない)。HTML はこのとき出どころの記録にだけ使う。
6. **チェックの切り替えは即時に効く**。監視の仕組み自体は常に動かしておき、読み取り時に現在の設定を見る (§5.2)。
   チェックを入れる前からクリップボードにあった内容は取り込まない。
7. **保存先フォルダは保存時に作る**。利用者が途中で消しても次の保存で作り直す。
8. **Ctrl+V と小窓は同じ処理に合流する**。違いは保存先の引数だけ (§10 Q1)。
9. **まれな失敗は割り切る** (CLAUDE.md「まれな失敗への対処」)。保存の書き込み失敗・ディスク不足は小窓で「保存できませんでした」と出してログに残すだけで、再試行しない。
   強制終了で残った一時ファイルは次回起動時にまとめて消す。

## 5. クリップボードの監視

### 5.1 通知の受け取り: 既存の listener を共有する

既存の `cut_clipboard` には、`AddClipboardFormatListener` を登録した message-only window を持つ listener thread がある
([cut_clipboard.rs:1120](../src/cut_clipboard.rs) `run_listener`、[section220-cut-item-appearance.md](section220-cut-item-appearance.md))。
これは process 単一の `LISTENER_STATE` で、2 つ目の listener を拒否する。

**案**: listener を「クリップボード変更通知」の単一所有者として一般化し、`ClipboardReadRequest { request_serial, os_sequence }` を
切り取り表示の reader と、新しい取り込み reader の 2 つへ配る。

- 理由: 同じ OS 通知を 2 か所で受けると、起動・終了・失敗の扱いが 2 系統に分かれる。listener の起動待ち、終了、
  `Disabled` への移行は既存の実装とレビュー結果をそのまま使える。
- 取り込み reader は切り取り表示 reader とは別 thread にする。読む形式も処理時間も違うため。
- 既存の起動時 initial read は切り取り表示だけのもの。取り込み reader へは配らない (§4-6)。
- 代替案: 取り込み専用に listener window をもう 1 つ持つ。`AddClipboardFormatListener` は複数 window を許すので技術的には可能。
  既存コードへの影響は小さいが、通知の所有者が 2 つになる。**どちらを採るかは独立レビューの論点にする**。

### 5.2 取り込み reader

- 専用 thread `clipboard-capture-reader`。latest-request slot から最新の要求だけを取り出す (既存と同じ合流方式)。
- 取り込みのチェックが両方 OFF なら、要求を読み捨てる。設定は UI thread から atomic snapshot で渡す。
- チェックが OFF→ON になった時点の `GetClipboardSequenceNumber` を基準値として記録し、それと等しい sequence の要求は無視する (§4-6)。
- クリップボードを開けない間は、既存の 25/50/100/250 ms の上限付き再試行を使う。新しい通知が来たら打ち切って新しい要求を読む。
- 読み取りの前後で sequence が変わったら、途中の結果を捨てて読み直す (既存と同じ)。
- 読む形式と判定は §5.3。重い処理 (DIB→PNG 変換、HTML 解析) もこの thread で行い、UI thread へは結果だけを渡す。
- UI への通知は既存と同じく `mpsc` + `request_repaint`。App は `update` の先頭 (fullscreen 等の early return より前) で受け取る。
  ただし自動保存と小窓の表示は UI thread を経由しなくてよい (§6.3)。

### 5.3 読む形式と判定

判定は次の順に行う。最初に当てはまったもので決める。

1. **取り込まないコピー**:
   - `ExcludeClipboardContentFromMonitorProcessing` 形式がある
   - `CanIncludeInClipboardHistory` が 0
   - `Clipboard Viewer Ignore` 形式がある
   - (パスワード管理ソフトなどが付ける。Windows のクリップボード履歴と同じ扱い)
2. **mIV 自身のコピー**: §5.4 の印がある。
3. **ファイルのコピー**: `CF_HDROP` がある。切り取り表示と Ctrl+V の既存処理の対象で、取り込みはしない。
4. **画像データ**: 登録形式 `PNG`、`CF_DIBV5`、`CF_DIB` のいずれかがある。
   - Office の表やグラフのコピーにも画像データが付く。これを除外する規則が要る (§5.5、S0 で決める)。
5. **HTML**: `HTML Format` があり、そのヘッダの `SourceURL` が `http` / `https`。
   - Word / Outlook などのコピーは `SourceURL` を持たないので、ここで外れる見込み (S0 で確認)。
6. それ以外 (テキストのみなど) は何もしない。

画像データの取り出しは `PNG` (透過と元のバイト列を保つ) → `CF_DIBV5` (透過あり) → `CF_DIB` の順に試す。
`PNG` はデコードできることを確かめたうえで、そのバイト列をそのまま保存する。DIB は PNG にエンコードする。
DIB の読み取りは既存の `books::decode_cf_dib_rgba` ([books.rs:1946](../src/books.rs)) を共通化して使う。

同じ内容の連続保存を防ぐため、直前に保存した画像の内容ハッシュと同じなら保存しない。
アプリによっては 1 回のコピーで更新通知が複数回届くため。

### 5.4 mIV 自身のコピーの印

mIV は「画像をコピー」(右クリック、ZIP 内画像、動画フレーム、キャプチャ) で `CF_DIB` を書く
([context_menu.rs:2503](../src/ui_dialogs/context_menu.rs) `set_rgba_to_clipboard`)。今は印が無い。

同じ `OpenClipboard` / `CloseClipboard` の中で、private 登録形式 `mImageViewer Clipboard Origin v1` に
process nonce を書く。取り込み reader はこの形式があれば取り込まない。

- 書き込み直後の sequence を記録する方式は、`CloseClipboard` との前後関係で取りこぼすので採らない。
- 既存の切り取り用の印 (`mImageViewer Cut Owner v1`) はファイルの Cut 専用で、意味が違うので流用しない。
- 書き込みの入口は `set_rgba_to_clipboard` の 1 か所なので、そこだけ直せば全経路に効く。

### 5.5 S0 で決めること: 形式の実態調査

アプリごとにクリップボードへ何を入れるかは、実測して決める。開発用の小さな dump 手段
(PowerShell スクリプト、ASCII のみ) で、コピー直後の形式一覧と `HTML Format` の中身を保存する。
**利用者がコピー操作を行い、エージェントは dump の解析だけを行う** (エージェントは製品バイナリを起動しない)。

調べる対象:

- Chrome / Edge / Firefox:
  - 「画像をコピー」
  - ページ全体のコピー
  - 一部範囲のコピー
- Windows の切り取りツール (Win+Shift+S)、PrintScreen
- Excel のセル範囲・グラフ、Word の文章・図、PowerPoint の図形
- Explorer のファイルコピー
- mIV の「画像をコピー」(印の追加後)

決めること:

- 画像データの取り込みから外す規則。候補は、Office 系の形式 (`Embed Source` / `Object Descriptor` / `XML Spreadsheet` / `Rich Text Format` など)、
  または空でない `CF_UNICODETEXT` が同時にあるもの。誤って外すと、ブラウザの「画像をコピー」まで取れなくなる。
- `HTML Format` 内の URL が絶対 URL になっているか (相対なら `SourceURL` と `<base>` で解決する)。
- 各ブラウザがページ全体のコピーで、遅延読み込みの属性 (`data-src` など) や `srcset` を残すか。

## 6. 右下の小窓

### 6.1 ウィンドウ

- 専用 thread `clipboard-capture-popup` が、Win32 の小さな top-level window を 1 つ持つ。初回表示時に作り、以後は再利用する。
- egui の viewport にはしない。複数ウィンドウの仕組みはリワーク中 ([detached-rework-plan.md](detached-rework-plan.md)) で、
  そこに新しい viewport を増やさないため。小窓は App の描画ループから独立する。
- 拡張スタイル: `WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`。owner は持たない。
  owner を持つと、表示時にメインウィンドウが前に出るため ([native_context_menu.rs:1497](../src/native_context_menu.rs) の tooltip と同じ判断)。
- `WM_MOUSEACTIVATE` には `MA_NOACTIVATE` を返す。表示は `SW_SHOWNOACTIVATE` で行う
  (動画 HUD の [hud_window.rs:672](../src/video/native_window_host/hud_window.rs) と同じ)。
- タスクバーにボタンを出さない (`WS_EX_TOOLWINDOW`)。

### 6.2 位置・描画・寿命

- **位置**: `GetForegroundWindow` → `MonitorFromWindow` → `GetMonitorInfoW` の `rcWork` の右下に、余白を取って置く。
  サイズは `GetDpiForMonitor` で物理 px に換算する。前面ウィンドウが取れなければプライマリモニターを使う。
  既存の `native_name_dialog::owner_work_area` は DPI を返さないので、DPI 付きの共通 helper を `monitor.rs` に追加する。
- **描画**: GDI で自前描画する (`DrawTextW`、DPI に合わせた `CreateFontW`)。mIV では GDI の文字描画は初めて使う。
  - 子コントロールの BUTTON は、押したときにフォーカス移動が絡むので使わない。ボタン領域は自前で描き、`WM_LBUTTONUP` で当たり判定する。
  - 配色は mIV の Light / Dark 解決結果に合わせる。
  - 文字は Yu Gothic UI (なければ既定の UI フォント) を使い、絵文字や環境依存記号は使わない (CLAUDE.md のグリフ規則)。
- **寿命**: `SetTimer` で 8 秒。`TrackMouseEvent` でマウスが乗っている間は止め、離れたら残り時間を戻す。
  [×] またはタイムアウトで隠す (破棄はしない)。
- **内容の種類**:
  - HTML 検出「このページの画像 N 件 [画像を選んで保存] [×]」
  - 画像の保存完了「クリップボードの画像を保存しました [開く] [×]」
  - 保存失敗「保存できませんでした: <理由> [×]」

  どれも最新 1 件で置き換える。
- **出さない場面**:
  - mIV 自身が前面のとき。メインウィンドウ内のトーストで足りるので、既存の `show_feedback_toast` を使う。
  - 選択ダイアログを開いている間 (§4-4)。

### 6.3 クリックの受け渡し

- [画像を選んで保存] が押されたら、小窓の thread がメインウィンドウを前面に出し、App へ typed event を送る。
  - 前面に出す処理は、トレイ復帰の `do_show_window` ([tray.rs:453](../src/tray.rs)) と 2 重起動時の処理
    ([single_instance.rs:751](../src/single_instance.rs)) と同じ手順。これを共通 helper に切り出して 3 か所で使う。
  - 小窓は利用者がクリックした直後なので、`SetForegroundWindow` が許される条件 (直前の入力イベントを受けた process) を満たす。
- event は `mpsc` + `request_repaint`。メインウィンドウがトレイに隠れていた場合は、トレイと同じく `WM_PAINT` を post して
  `update` を確実に起こす ([tray.rs:8](../src/tray.rs) の注意)。
- App は event に入っている検出結果 (HTML の解析結果のスナップショット) で選択ダイアログを開く。クリップボードは読み直さない
  (その間に別の内容をコピーしている可能性があるため)。
- [開く] (保存完了) は、メインウィンドウを前面に出して保存先フォルダを開き、保存したファイルを選択する。

## 7. HTML の解析と画像の取得

### 7.1 HTML の解析

- `HTML Format` (CF_HTML) のヘッダ `StartFragment` / `EndFragment` / `SourceURL` を読む。
  オフセットは UTF-8 のバイト数。壊れていたら全体を HTML として扱う。
- **HTML パーサ crate を追加する**。現在の依存には無く、`quick-xml` は実際の HTML に耐えない。
  候補は `scraper` (html5ever) か `tl`。html5ever は堅牢で保守も活発なので、こちらを第一候補にする (ライセンス MIT / Apache-2.0)。
- 集める候補:
  - `<img src>`、`<img srcset>` (最大の w / x 記述子)
  - `<picture><source srcset>`
  - 画像拡張子への `<a href>`
  - 遅延読み込み属性 (`data-src` など。S0 の結果で対象を決める)
- URL の解決: `<base href>` → `SourceURL` の順で相対 URL を解決し、fragment を取り除く。
  - 受け付けるスキームは `http` / `https` / `data:image/*` だけ。
  - `blob:` / `file:` / `cid:` / `javascript:` は捨てる。
- 同じ URL は 1 件にまとめる。
- `width` / `height` 属性が両方あって、どちらかが 32 px 未満のものは数えない (アイコン・計測用画像の除外)。最終的な絞り込みは取得後の実寸で行う (§8)。
- 候補は最大 500 件まで。HTML 自体が 32 MiB を超えたら解析しない (まれ。小窓で「大きすぎるため扱えません」)。

### 7.2 取得

選択ダイアログが開いたら、背景の取得 worker が候補を順に取る。

- **HTTP**: 既存の `ureq` 2 を使う (更新確認と同じ。rustls、OS のプロキシ設定は使わない)。
  - 接続 10 秒、読み取り 30 秒でタイムアウト。
  - User-Agent は `mImageViewer/<版>`。ブラウザを装わない。
  - 同時取得は全体 4 本。
  - 1 枚の上限は 64 MiB。超えたら失敗扱い。
- **参照元 (Referer)**: ブラウザの既定 (`strict-origin-when-cross-origin`) と同じ規則で付ける。
  - 同じ origin なら、ページ URL (fragment を除く)
  - 別 origin なら、origin だけ (`https://www.example.com/`)
  - https のページから http の画像なら付けない

  2026-10-02 に、参照元をチェックする画像サーバーで次を確認した (確認者: ClaudeCode、`curl`、Cookie なし)。
  - 参照元なし: 403
  - origin のみ: 200
  - ページ URL: 200
- **リダイレクト**: `ureq` の既定に従う。リダイレクト先が `http` / `https` 以外なら失敗にする。
  リダイレクト後も参照元が送られるかは、実装時にテスト用ローカル HTTP サーバーで確かめる。
- **宛先の制限**: ページ自体がローカル / プライベートアドレスでない限り、候補の解決先がループバック・プライベート・リンクローカルの
  アドレスなら取得しない。悪意あるページが、ブラウザの表示では読み込まれない `<img>` を仕込み、利用者の LAN 機器へ要求させるのを防ぐ。
- **中身の確認**: 先頭バイトで画像形式を判定し、mIV が扱える画像形式でなければ失敗にする (HTML のエラーページなど)。
  拡張子はここで決める。
- **一時保存**: 取得したバイト列は `data_dir/tmp/clipboard-capture/<dialog id>/` に書き、メモリには持たない。
  縮小表示は worker がそこからデコードして作る。
- **取り消し**: ダイアログを閉じたら cancel token を立て、一時フォルダを消す。
  起動時には `data_dir/tmp/clipboard-capture/` を丸ごと消す (§4-9)。
- `data:` URL はその場でデコードし、同じ一時保存に乗せる。

### 7.3 取れない画像

| 状況 | 結果 |
| --- | --- |
| 公開されている画像 | 取れる |
| 参照元をチェックしている画像 | §7.2 の参照元で取れる見込み |
| 期限付き署名 URL | 期限内なら取れる |
| ログインが必要な画像 | 取れない。一覧に「取得できませんでした (403)」と出す |
| ボット対策のあるサイト | 拒否されることがある。同上 |
| `blob:` / canvas / CSS の背景画像 | HTML に無い、または取れない。数えない |
| 画面外で未読み込みの画像 | 遅延読み込み属性が残っていれば拾える (S0 で確認) |
| SNS のタイムライン | 画面付近に描かれている投稿だけ |

## 8. 選択ダイアログ

- メインウィンドウ内の `egui::Window`。`ui_dialogs/` に 1 ファイルで置く。モーダル扱い (§4-3)。
- 上部: 出どころ (ドメイン)、取得の進み具合 (N / M)、最小サイズの絞り込み (短辺 px、既定 100)、全選択 / 全解除。
- 本体: 縮小表示の格子。チェック付き。
  - 取得中は枠だけ、失敗は理由付きで選べない状態にする。
  - 既定ではチェック済み (§10 Q4)。最小サイズ未満は既定で未チェック。
- 縮小表示のテクスチャ化は 1 フレームに 1〜2 枚までに抑える (`ctx.load_texture` のペーシング、[ui-responsiveness.md](ui-responsiveness.md) §3)。
- 同じ内容 (ハッシュ一致) の画像は 1 件にまとめる。
- [保存]: 選んだものを §2.6 の名前で保存先へ書き、ダイアログを閉じる。完了はメインウィンドウのトースト
  (`show_capture_saved_toast` 系) で「N 枚保存しました」と出す。
- [閉じる] / Esc: 取り消し (§7.2)。Esc は `dialog_escape_pressed` を使う (IME 規則)。

## 9. 保存と記録

### 9.1 保存

- 保存先: §2.7。Ctrl+V から来たときは §10 Q1。
- 書き込み: 保存先と同じフォルダに `.part` で書き、rename で確定する。一時保存 (§7.2) からは copy → rename。
- 名前の衝突 (同じミリ秒に 2 回など): 日時部分に `-2`, `-3` … を付けて避ける (`_` より前を変える)。
- 保存したら、そのフォルダを表示中なら通常のフォルダ監視で一覧に出る。専用の更新処理は足さない。

### 9.2 出どころの記録 (§10 Q3)

**案 A (推奨): Mark of the Web (`Zone.Identifier` 代替データストリーム)**

ブラウザがダウンロードしたファイルに付けるのと同じ形式で、`ZoneId=3`、`ReferrerUrl=<ページ URL>`、
`HostUrl=<画像 URL>` を書く。

- 新しい DB が要らない。
- ファイルと一緒に移動する (NTFS 内)。
- Explorer のプロパティでも見える。
- FAT / exFAT へコピーすると消えるのは、ブラウザのダウンロードと同じ。
- 画像ファイルの表示を Windows が妨げることはない。ただしプロパティに「ブロックの解除」が出る。

**案 B: mIV の新しい SQLite (`clipboard_capture.db`)**

保存パス → 画像 URL / ページ URL / 取り込み日時を持つ。メタデータパネルに「元ページを開く」を出しやすい。
一方で、ファイルの移動・改名で対応が切れる。

どちらでも、**v1 ではメタデータパネルへの表示は作らない** (記録だけ)。表示は後の段階で、
既存のツイート情報パネル ([ui_metadata_panel.rs:5967](../src/ui_metadata_panel.rs) `draw_tweet_panel`) と同じ形で検討する。
いずれも未リリースの新規データなのでマイグレーションは不要。

## 10. 利用者の判断を仰ぐ点

| # | 論点 | 推奨 |
| --- | --- | --- |
| Q1 | Ctrl+V で画像・HTML を取り込むときの保存先 | **今のフォルダ**。既存の Ctrl+V (ファイル貼り付け) と同じく「貼り付けた場所に入る」。ファイル貼り付けが無効な一覧 (検索結果・ZIP 内など) では取り込みも無効。小窓と自動保存は取り込みフォルダ |
| Q2 | 画像の自動保存のたびに小窓で知らせるか | **知らせる**。監視が動いていることの確認になる (「動いていないと誤解される」を避ける) |
| Q3 | 出どころの記録方式 | **案 A (Mark of the Web)** |
| Q4 | 選択ダイアログの既定のチェック | **最小サイズ以上は全部チェック済み** |
| Q5 | 場所▼の「クリップボード取り込み」の表示条件 | **どちらかのチェックが ON のときだけ** |

## 13. テスト

- **純ロジックの単体テスト**:
  - CF_HTML ヘッダの解析 (正常・壊れたオフセット・`SourceURL` なし)
  - `srcset` の最大選択
  - `<base>` と相対 URL の解決
  - 受け付けスキーム
  - 32 px 未満の除外
  - 候補上限
- **参照元の規則**: 同 origin / 別 origin / https→http の 3 通り。
- **宛先の制限**: ループバック・プライベート・リンクローカル、およびページ自体がプライベートの場合。
- **ファイル名**: 生成した全ての名前について、既存の `filename_stack` の prefix 関数がコピー単位で同じ値を返すこと
  (ドメインに `_` を含む場合、100 枚以上の場合、衝突回避の `-2` を含む)。
- **判定順 (§5.3)**:
  - 除外形式
  - 自身の印
  - `CF_HDROP`
  - 画像と HTML が両方ある場合
  - S0 で決めた Office 除外

  形式集合を入力にした純関数として持つ。
- **reader の状態**: OFF→ON の基準値より前の内容を取り込まないこと、連続する同一内容を 1 回だけ保存すること。
- **取得**: テスト用ローカル HTTP サーバーで確かめる。
  - 送られた参照元
  - 403
  - リダイレクト (参照元の扱い・スキーム制限)
  - 画像でない応答
  - 64 MiB 超
  - 取り消し後に一時フォルダが消えること
- **選択ダイアログの状態遷移**: 開く → 取得中に閉じる → 一時ファイル削除、ダイアログ中の HTML 検出を無視、モーダル登録。
- **Ctrl+V の分岐 (handler-level)**: ファイル / 画像 / HTML / どれでもない、と無効な一覧での無反応。
- **idle health**: 監視 ON・小窓非表示の静止状態で repaint が増えないこと ([idle-health-check.md](idle-health-check.md))。
- **実機 (利用者)**: 複数ディスプレイの位置、DPI の異なる画面、ブラウザでの作業中にフォーカスが移らないこと、トレイ常駐中・最小化中のクリック。
