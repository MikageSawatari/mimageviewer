独立レビュー = 実装者とは別の GPT-6.1 Sol / xhigh (AGENTS.md の既定)。

## 1. 目的

普段の作業中に見つけた画像を、手間なく mIV に取り込めるようにする。

- 画像そのものをコピーしたとき (スクリーンショット、ブラウザの「画像をコピー」など) は、自動で保存する。
- ブラウザでページの HTML をコピーしたとき (Ctrl+A → Ctrl+C など) は、ページ内の画像を一覧から選んで保存できる。

ブラウザ拡張・ストア公開・mIV 内ブラウザは使わず、**クリップボードだけ**で完結させる。

## 2. 利用者向け仕様 (2026-10-02 利用者と合意)

### 2.1 設定

環境設定に「クリップボード取り込み」ページを新設し、次の 2 つのチェックを置く。どちらも既定は OFF。

- □ 画像がコピーされたら自動で保存する
- □ ページ (HTML) がコピーされたら、含まれる画像を選んで保存できるようにする

保存先フォルダも同じページに置く。既定は `ピクチャ\mimageviewer\clipboard` で、変更・既定に戻す・フォルダを開くができる。

どちらの監視も **mIV の起動中だけ**動く。トレイ常駐と組み合わせれば常時動かせる旨をページに書く。

### 2.2 画像のコピー

クリップボードに画像データが入ったら、保存先へ保存し、右下の小窓 (§2.4) で知らせる。
知らせる文面は「クリップボードの画像を保存しました [開く] [×]」。

### 2.3 ページ (HTML) のコピー

1. ブラウザでページを選択してコピーすると、mIV が HTML から画像 URL を数える。
2. 右下に小窓「このページの画像 N 件 [画像を選んで保存] [×]」を出す。
3. ボタンを押すと mIV が前面に出て、メインウィンドウの一覧画面に選択ダイアログが開く。**画像の取得はこの時点から**始める。
4. 縮小表示を見ながら選び、[保存] で保存先へ書き出す。

### 2.4 右下の小窓

- mIV 専用の小さなネイティブウィンドウ。**前面ウィンドウ (多くの場合ブラウザ) のある画面**の、作業領域の右下に出す。
- **フォーカスを奪わない**。ブラウザでの作業を止めない。
- 8 秒で消える。マウスを乗せている間は消えない。
- 内容は常に最新 1 件だけ。続けてコピーしたら中身を置き換える。
- Windows の通知機能は使わない (§3.3)。OS の通知設定に関係なく出る。

### 2.5 Ctrl+V

mIV の一覧で Ctrl+V を押したとき、クリップボードの中身で動作を分ける (詳細は §5.5)。
監視のチェックが OFF でも動く。手動の入口であり、小窓を見逃したときの救済も兼ねる。

| クリップボードの中身 | 動作 |
| --- | --- |
| ファイル類 (Explorer のコピー / 切り取り、Shell の仮想ファイルなど) | 従来どおり Shell の貼り付け |
| 画像データ | 保存する (保存先は §11 Q1) |
| HTML (画像 URL あり) | 選択ダイアログを開く (保存先は §11 Q1) |
| どれでもない | 従来どおり Shell の貼り付けへ渡す (現状と同じ) |

### 2.6 ファイル名

```
<日時>-<ドメイン>_<連番>.<拡張子>
例: 20261002-153012-345-www.example.com_01.jpg
    20261002-153012-345-www.example.com_02.jpg   ← 同じコピーなので 1 スタック
    20261002-154500-012_01.png                    ← 画像データのコピー (出どころ不明)
```

- **1 回のコピーが 1 スタックになる**。既定のスタック規則 (最後の `_` より前が同じものを畳む、[filename-stack-plan.md](filename-stack-plan.md)) に合わせている。
- 日時が先頭なので、名前順がそのまま取り込み順になる。日時はミリ秒まで入れる。
- `_` より前には `_` を含めない。
  - 日時の区切りは `-` にする。
  - ドメイン中の `_` と、Windows で使えない文字は `-` に置き換える。
- 連番の桁は 2 桁以上で、そのコピーの枚数に合わせてそろえる (100 枚以上なら 3 桁)。
- 拡張子は、取得した**中身から判定した形式**で付ける。URL の拡張子は信用しない。
- 元のファイル名はファイル名に入れない。出どころは §10.2 で記録する。
- スタック表示の ON/OFF は既存のトグルのまま。このフォルダで自動的に ON にはしない (状態を増やさないため)。
- 区切り文字の設定を `_` 以外に変えている利用者の場合は、コピー単位にまとまらない。マニュアルに「既定の区切り文字でまとまります」と書く。

### 2.7 保存先フォルダ

- 既定は `capture::default_output_dir().join("clipboard")` (= `ピクチャ\mimageviewer\clipboard`)。
- その下に月ごとのサブフォルダ (`2026-10`) を作る。
- フォルダは**最初に保存するとき**に作る。チェックを入れた時点では作らない。
- 場所▼メニューに「クリップボード取り込み」を出す。
  - 表示条件は「2 つのチェックのどちらかが ON」。専用の表示設定は増やさない。
  - **メインウィンドウの場所▼だけ**に出す。`known_folders::location_menu_entries` は mIV Remote のホームとも共有しているので、Remote 側の列挙から除外し、Remote の既存の場所一覧が変わらないことをテストで固定する。
- 本棚と違い、検索索引の除外対象にはしない。お気に入りの配下にあれば、通常どおり Ctrl+G / Ctrl+S の対象になる。

## 3. 検討した代替案と採否

### 3.1 取り込みの入口

| 案 | 採否 | 理由 |
| --- | --- | --- |
| ブラウザ拡張 (Native Messaging + 中継 exe) | 不採用 | 次の作業がすべて要る:<br>・ストア公開 (Chrome / Edge / Firefox) と審査<br>・拡張のインストール手順<br>・中継 exe のレジストリ登録<br>さらに単体 exe 版は本体の場所が版ごとに変わるので、登録先の管理も要る |
| mIV 内の WebView2 で URL を開く | 不採用 (将来の候補) | ログインが必要なサイトでは、埋め込みブラウザからのログイン自体が拒否される可能性がある (Google は方針として制限している)。成否はサイトごとに試さないと分からない。取りこぼしが問題になったら再検討する |
| **コピーした HTML / 画像をクリップボードから読む** | **採用** | 追加インストール・公開作業・ログインが要らない |

### 3.2 保存先

| 案 | 採否 | 理由 |
| --- | --- | --- |
| 本棚の本「クリップボード画像」 | 不採用 | 本はページ順を持つ冊子として作られている (`0001_元名` の連番、1 冊 9999 ページまで)。本棚は検索索引の対象外。取り込んだ画像を溜め続ける場所には合わない |
| **専用の通常フォルダ (月ごと)** | **採用** | 上限がなく、検索の対象にもなる。冊子にしたい画像は既存の「本に追加」で送れる |

### 3.3 HTML 検出の知らせ方

| 案 | 採否 | 理由 |
| --- | --- | --- |
| トレイのバルーン通知 (mXD と同じ) | 不採用 | Windows の通知を OFF にしている利用者には何も出ない。しかも出なかったことを mIV は知る手段がない (`Shell_NotifyIconW` は抑止されても成功を返す)。利用者には「mIV が動いていない」ように見える。ボタンも付けられない |
| Windows の通知 API (AppUserModelID 登録) | 不採用 | 同じく OS の通知設定で消える。3 つの配布形態すべてでレジストリ登録が要る |

### 3.4 クリップボード変更通知の受け方 (レビュー第 1 回で決定)

| 案 | 採否 | 理由 |
| --- | --- | --- |
| 既存の切り取り表示用の listener を共有する | 不採用 | 既存の起動・終了・停止の約束 (startup / `Disabled` / shutdown) は、切り取り表示全体についてのもので、通知だけを配る仕組みではない。共有すると次の問題が出る:<br>・新機能が起動に失敗すると、既存の切り取り表示まで止まり得る<br>・既存 reader の初回読み取りや読み直しの要求を、取り込み側が「新しいコピー」と誤認する ([cut_clipboard.rs:1026](../src/cut_clipboard.rs) / [:1051](../src/cut_clipboard.rs) / [:1466](../src/cut_clipboard.rs)) |
| **取り込み専用の listener を持つ** | **採用** | `AddClipboardFormatListener` は 1 プロセスで複数の window を登録できる。既存コードは触らずに済み、独立した部品として起動・停止・失敗できる。既存の補助部品 (`OleStaGuard` 相当、上限付き再試行、読み取り前後の sequence 確認) は共通化して使う |

## 4. 状態の組み合わせを減らすための決定

CLAUDE.md「設計の簡素化」に従い、割り込みを扱う仕組みを作る前に、組み合わせそのものを減らした。

1. **HTML の待ちは最新 1 件だけ**。待ち行列は持たず、小窓の内容を置き換える。
2. **小窓の段階では何も取得しない**。取得は選択ダイアログを開いてから始める。普段のコピーで通信は発生しない。
3. **選択ダイアログは一覧画面でだけ開く**。開ける条件は次のすべて:
   - メインウィンドウが一覧表示中 (フルスクリーン・動画・detached でない)
   - 他のモーダルが開いていない
   - Remote が操作を握っていない

   条件を満たさないときは開かずに、メインのトーストで「一覧画面で Ctrl+V を押すと開けます」と出す。
   これでフルスクリーン・detached の経路には触れない (リワーク中の凍結ルールの対象外にとどまる)。
4. **選択ダイアログはモーダル**。
   - 開いている間は、フォルダ移動・フルスクリーン・他のダイアログ・2 重起動からのパス受け渡し・D&D を受け付けない。
     `App::common_modal_dialog_open` (`modal_dialog_block_reason`) と、2 重起動の受付判定
     `document_open_modal_admission_blocked` ([app.rs:33418](../src/app.rs)) の両方に登録する。
   - 保存中も、保存が終わるまでモーダルを保つ。
   - 閉じたら取得を取り消す。途中から再開する仕組みは持たない。
5. **選択ダイアログを開いている間の HTML 検出は無視する**。小窓も出さず、待ちも更新しない。閉じた後に必要なら Ctrl+V で開き直す。
6. **画像データと HTML が両方あるコピーは、画像データだけで判断する**。ブラウザの「画像をコピー」は両方を入れるため。
   - 自動保存では、画像の自動保存が OFF なら何もしない (HTML 側へは回さない)。
   - このときの HTML は、出どころの記録にだけ使う。
7. **設定は世代番号付きの不変スナップショットで渡す** (§5.3)。設定を変えると世代が進み、次のものはすべて捨てる:
   - 旧世代の読み取り結果
   - 表示中の小窓
   - HTML の待ち

   ただし、すでに始まった保存は最後まで行う (割り切り)。
8. **保存先フォルダは保存時に作る**。利用者が途中で消しても、次の保存で作り直す。
9. **自動と手動 (Ctrl+V) は、解析と保存の部品を共有し、入口の意図を型で分ける** (§5.5)。
10. **小窓は mIV が前面でも同じように出す**。表示経路を 1 つにするため。コピーは通常ほかのアプリで行うので、mIV が前面のまま監視が反応する場面はほぼない。
11. **まれな失敗は割り切る** (CLAUDE.md「まれな失敗への対処」)。
    - 保存の書き込み失敗・ディスク不足・出どころ記録の失敗は、すでに保存できた画像はそのまま残す。
    - 件数と理由を小窓またはトーストで伝え、ログに残す。
    - 再試行・巻き戻し・回復のための状態は持たない。
    - 強制終了で残った一時ファイルは、次回起動時にまとめて消す。

## 5. クリップボードの監視

### 5.1 構成

新しいモジュール `clipboard_capture` が、process に 1 つの `ClipboardCaptureService` を持つ。App が所有し、viewer bundle には入れない。

- **listener thread** `clipboard-capture-listener`
  - message-only window を持ち、`AddClipboardFormatListener` を登録する。
  - `WM_CLIPBOARDUPDATE` ごとに、単調増加の request serial と `GetClipboardSequenceNumber` を latest-request slot に置いて reader を起こす。
  - 起動時の初回読み取りはしない。起動前からクリップボードにあった内容は取り込まない。
- **reader thread** `clipboard-capture-reader`
  - slot から最新の要求だけを取り出し、§5.2 の手順で読む。
- 起動・停止・失敗は既存の切り取り表示と独立させる。
  - 起動に失敗した場合: 設定ページに「この環境ではクリップボードの監視を開始できませんでした」と出し、ログに残す。Ctrl+V の手動入口は監視と無関係に動く。
  - 終了時: 既存と同じく、message 投入に成功した thread だけを join する。外部のクリップボード呼び出し中の thread は待たない。
- 監視のチェックが両方 OFF のときは、listener も reader も起動しない。
  - チェックを入れたら起動し、両方外したら停止する。
  - 起動と停止の切り替えは設定の世代 (§5.3) と同じ境界で行う。

### 5.2 読み取りの手順

1. **重複の排除**: 要求の OS sequence が「最後に受理した sequence」と等しければ読まない。同じコピーで通知が複数回届く場合のため。
2. **形式の確認**: クリップボードを開き、形式の一覧だけを見て §5.4 の判定をする。
3. **生データの取り出し**: 必要な形式の生データを、上限付きでコピーしてすぐ閉じる。
   - 上限: 画像 256 MiB、HTML 32 MiB。超えたら取り込まない。
   - **クリップボードを開いている間は、デコード・解析・保存をしない。** 既存の製本の読み取り ([books.rs:1928](../src/books.rs)) は開いたままデコードしているが、常時動く監視では他アプリの邪魔になるので、同じやり方は採らない。
4. **読み直し**: 読み取りの前後で sequence が変わったら、途中の結果を捨てて読み直す。
5. **受理**: 前後で同じなら、その sequence を「受理済み」として記録する。
   - 遅延 rendering で sequence が後から変わる場合の扱いは、S0 で実態を確かめる。sequence で保証できない範囲は、この受理済み記録と §5.6 の内容の一致で抑える。
6. **解析**: クリップボードを閉じた後で、デコード・HTML 解析を reader 上で行う。
7. **結果の扱い**:
   - 画像なら、保存 worker へ渡す。
   - HTML なら、小窓へ渡す。
   - 結果には設定の世代番号を付ける。
8. **再試行**: クリップボードを開けない間は、上限付きで再試行する (既存と同じ 25 / 50 / 100 / 250 ms)。新しい要求が来たら打ち切る。

### 5.3 設定のスナップショット

UI thread は、次の項目を 1 つの不変スナップショットにまとめて `Arc` で reader へ渡す。

- 2 つのチェック
- 保存先
- 世代番号

設定が変わるたびに世代が進む。reader・保存 worker・小窓は、自分が受けた世代と現在の世代が違えば結果を捨てる (§4-7)。
チェックを入れた時点のクリップボードの内容は取り込まない。listener は起動直後に初回読み取りをしないので、これは自然に成り立つ。

### 5.4 形式の判定

上から順に判定し、最初に当てはまったもので決める。この判定は**形式の集合を入力にした純関数**として持つ。

1. **取り込まないコピー**: 次のいずれかに当てはまる。パスワード管理ソフトなどが付ける形式で、Windows のクリップボード履歴と同じ扱いにする。
   - `ExcludeClipboardContentFromMonitorProcessing` 形式がある
   - `CanIncludeInClipboardHistory` が 0
   - `Clipboard Viewer Ignore` 形式がある
2. **mIV 自身のコピー**: §5.7 の印がある。
3. **ファイル類**: `CF_HDROP`、`FileGroupDescriptorW`、`Shell IDList Array` のいずれかがある。
4. **画像データ**: 登録形式 `PNG`、`CF_DIBV5`、`CF_DIB` のいずれかがある。
   - ただし S0 で決める除外規則 (Office の表・グラフなど) に当てはまるものは除く。
5. **HTML**: `HTML Format` があり、ヘッダの `SourceURL` が `http` / `https`。
   - Word / Outlook などのコピーは `SourceURL` を持たないので、ここで外れる見込み。S0 で確認する。
6. それ以外: 何もしない。

画像データは `PNG` → `CF_DIBV5` → `CF_DIB` の順に取り出す。

- `PNG` は、デコードできることを確かめたうえで、そのバイト列をそのまま保存する。
- DIB は PNG にエンコードする。DIB の解釈は既存の `books::decode_cf_dib_rgba` ([books.rs:1946](../src/books.rs)) を共通化して使い、製本とクリップボード取り込みで同じ規則にする。
- **alpha がすべて 0 の 32bit DIB は不透明として扱う** ([books.rs:2081](../src/books.rs) の既存規則)。alpha を書かないアプリがあるためで、完全に透明な画像のコピーは実用上ないとみなす割り切り。透過を保つ主な経路は `PNG` 形式で、ブラウザや切り取りツールは `PNG` も入れる見込み (S0 で確認)。
- デコード後の大きさにも上限を設ける。既存のデコードの上限に合わせ、超えたら取り込まない。

### 5.5 Ctrl+V の分岐

入口の意図を型で分ける。

```
enum CaptureIntent {
    Automatic { generation },        // 監視から
    Manual { destination },          // Ctrl+V から
}
```

- 解析・保存の部品は共有する。
- **監視専用の抑止は手動へ適用しない**。対象は、チェックの OFF、世代、受理済み sequence、§5.6 の内容の一致、§5.7 の自身の印。
  - mIV で「画像をコピー」した画像を Ctrl+V で貼れば、それも保存される (利用者の明示操作なので)。
- 既存の `App::handle_clipboard_shortcuts` ([app.rs:50795](../src/app.rs)) に合流させる。
  - 判定 (§5.4 の 1・3〜5) が「画像データ」か「HTML」のときだけ新しい処理へ回す。
  - **それ以外はすべて従来の Shell の貼り付け** (`invoke_shell_folder_background_verb(..., Paste)`) へ渡す。現状の Ctrl+V の動作 (`CF_HDROP` 以外の Shell 対応形式を含む) は狭めない。
  - 形式の確認は UI thread で行うので、形式一覧を見るだけにする。生データの取り出しは worker で行う。
- 無効な一覧 (検索結果・タグ結果など、既存の Ctrl+V が無反応な一覧) では、新しい処理も無反応にする。
- Ctrl+V は今も `GetAsyncKeyState` による固定扱いで、キー割り当ての対象外。今回もそれを変えない。

### 5.6 同じ内容の重複

自動保存では、**直前に保存した 1 件と内容のハッシュが一致する画像は保存しない**。これは利用者向けの仕様で、同じ画像を続けて 2 回コピーしても 1 枚になる。
通知の重複は、別に §5.2-1 の受理済み sequence で抑える。

### 5.7 mIV 自身のコピーの印

mIV の「画像をコピー」は、右クリック・ZIP 内画像・動画フレーム・キャプチャのいずれも、
[context_menu.rs:2503](../src/ui_dialogs/context_menu.rs) の `set_rgba_to_clipboard` を通る。
今はここに印がなく、さらに `OpenClipboard(None)` → `EmptyClipboard` を使い、API の失敗を捨てている ([context_menu.rs:2557](../src/ui_dialogs/context_menu.rs))。

Microsoft の文書には「NULL の window で開いて `EmptyClipboard` すると所有者が NULL になり、`SetClipboardData` が失敗する」とある。
**現状の画像コピーが実際に失敗しているかは未確認**。

印を足すときに、次のように整える。

- 所有者として有効な HWND で開く。専用の message-only window を 1 つ持つ。監視 OFF でも画像コピーは使うので、監視用の listener window とは別にする。
- `EmptyClipboard` と各 `SetClipboardData` の成否を確かめる。
  - 成功時は、HGLOBAL の所有権をシステムへ移す。
  - 失敗時は、自分で解放する。
- `CF_DIB` と同じ開閉の中で、private 登録形式 `mImageViewer Clipboard Origin v1` (process nonce) を書く。
- 印の登録や書き込みに失敗しても、画像コピー自体は続ける。ログに残すだけにする (割り切り)。
- 書き込み直後の sequence を記録する方式は、`CloseClipboard` との前後関係で取りこぼすので採らない。
- 既存の切り取り用の印 (`mImageViewer Cut Owner v1`) はファイルの Cut 専用で意味が違うので、流用しない。

### 5.8 S0 で決めること: 形式の実態調査

アプリごとにクリップボードへ何が入るかを、実測して決める。開発用の dump スクリプトを用意し、コピー直後の形式一覧・`HTML Format` の中身・sequence の推移を保存する。スクリプトは PowerShell で、ASCII のみで書く。

**コピー操作は利用者が行い、エージェントは dump の解析だけを行う** (エージェントは製品バイナリを起動しない)。

調べる対象:

- Chrome / Edge / Firefox:
  - 「画像をコピー」
  - ページ全体のコピー
  - 一部範囲のコピー
- Windows の切り取りツール (Win+Shift+S)、PrintScreen
- Excel のセル範囲・グラフ、Word の文章・図、PowerPoint の図形
- Explorer のファイルコピー、Outlook の添付ファイルのコピー (仮想ファイル)
- mIV の「画像をコピー」(印を付ける前の現状。§5.7 の失敗有無も見る)

決めること:

- 画像データの取り込みから外す規則。
  - 候補は「Office 系の形式 (`Embed Source` / `Object Descriptor` / `XML Spreadsheet` / `Rich Text Format` など) が同時にある」か、「空でない `CF_UNICODETEXT` が同時にある」。
  - 誤って外すと、ブラウザの「画像をコピー」まで取れなくなる。
- `PNG` と DIB が同時に入るか、`PNG` の alpha が保たれるか。
- 1 回のコピーで更新通知が何回届くか。遅延 rendering で sequence が後から変わるか。
- `HTML Format` の中の URL が絶対 URL か。
- ページ全体のコピーで、遅延読み込みの属性 (`data-src` など) や `srcset` が残るか。

## 6. 右下の小窓

### 6.1 ウィンドウ

- 専用 thread `clipboard-capture-popup` が、Win32 の小さな top-level window を 1 つ持つ。初回表示時に作り、以後は再利用する。
- **egui の viewport にはしない**。複数ウィンドウの仕組みはリワーク中 ([detached-rework-plan.md](detached-rework-plan.md)) なので、そこに新しい viewport を増やさない。小窓は App の描画ループから独立させる。
- 拡張スタイルは `WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`。owner は持たない。
  - owner を持つと、表示時にメインウィンドウが前に出る ([native_context_menu.rs:1497](../src/native_context_menu.rs) の tooltip と同じ判断)。
- `WM_MOUSEACTIVATE` には `MA_NOACTIVATE` を返す ([hud_window.rs:672](../src/video/native_window_host/hud_window.rs) と同じ)。
- 表示は `SW_SHOWNOACTIVATE` で行う。位置とサイズの変更は、すべて `SetWindowPos(..., SWP_NOACTIVATE)` で行う。

### 6.2 位置と DPI

- popup thread は per-monitor DPI aware v2 で動かす。プロセスの既定に従い、違う場合は thread の DPI 文脈を明示する。
- 位置の決め方:
  1. `GetForegroundWindow` → `MonitorFromWindow` → `GetMonitorInfoW` で、`rcWork` (物理座標) を得る。
     前面ウィンドウが取れなければプライマリモニターを使う。
  2. 仮の位置へ `SetWindowPos` で移す。
  3. `GetDpiForWindow` で DPI を得て、フォント・大きさ・ボタン領域を作り直す。
  4. 右下へ置き直す。

  Microsoft の案内に従い、per-monitor aware の thread では `GetDpiForMonitor` ではなく `GetDpiForWindow` を使う。
- `WM_DPICHANGED` を受けたら、提案された矩形へ移し、フォントと当たり判定を作り直して再描画する。
- この手順は popup 専用に持つ。`monitor.rs` に「HWND / 前面ウィンドウの作業領域」を返す helper を足し、DPI は window から取る。

### 6.3 描画と寿命

- **描画**: GDI で自前描画する (`DrawTextW`、DPI に合わせた `CreateFontW`)。mIV で GDI の文字描画を使うのは初めて。
  - 子コントロールの BUTTON は使わない。押したときのフォーカス移動が絡むため。ボタン領域は自前で描き、`WM_LBUTTONUP` で当たり判定する。
  - 配色は、mIV の Light / Dark の解決結果をスナップショットで受け取る。
  - フォントは Yu Gothic UI (無ければ既定の UI フォント)。絵文字や環境依存の記号は使わない (CLAUDE.md のグリフ規則)。
- **寿命**:
  - `SetTimer` で 8 秒後に隠す。
  - `TrackMouseEvent` を使い、マウスが乗っている間はタイマーを止め、離れたら 8 秒を数え直す。
  - [×] またはタイムアウトで隠す。window は破棄しない。
- **内容の種類**: どれも最新 1 件で置き換える。
  - HTML 検出:「このページの画像 N 件 [画像を選んで保存] [×]」。検出結果のスナップショットを持つ。
  - 保存完了:「クリップボードの画像を保存しました [開く] [×]」
  - 保存失敗:「保存できませんでした: <理由> [×]」
- **出さない場面**: 選択ダイアログを開いている間だけ (§4-5)。

### 6.4 クリックの受け渡しと前面化

- ボタンが押されたら、popup thread がメインウィンドウを前面に出し、App へ typed event を送る。
  - HTML 検出の場合は `OpenCaptureSelection(snapshot)`。
  - 保存完了の場合は `RevealSaved(path)`。
- **前面化の helper**: トレイ復帰の `do_show_window` ([tray.rs:453](../src/tray.rs)) と、2 重起動時の処理 ([single_instance.rs:751](../src/single_instance.rs)) を共通 helper に切り出し、3 か所で使う。
  - helper は 3 つの状態を分ける:
    - **トレイに隠れている**: 保存済みの配置で表示する (既存どおり)。
    - **通常の最小化**: `IsIconic` なら明示的に `SW_RESTORE` する。
    - **表示中**: 前面化だけ行う。
  - 既存の約束は保つ。配置スロットの lock は外してから Win32 を呼び、App 側の復帰同期 (`sync_after_restore`) も維持する。
  - `SetForegroundWindow` は、利用者がクリックした直後なので許可される条件を満たす見込み。ただし成功は保証されない。失敗したらログに残すだけにし、再試行や強制的なフォーカス操作は足さない。
- event の受け渡しは `mpsc` と `request_repaint` で行う。メインウィンドウがトレイに隠れていた場合は、トレイと同じく `WM_PAINT` を post して `update` を確実に起こす ([tray.rs:8](../src/tray.rs) の注意)。
- App は `update` の先頭で event を受け取り、§4-3 の条件で選択ダイアログを開く。
  - 開けない場合は、メインのトーストで理由を出す。
  - クリップボードは読み直さない。その間に別の内容をコピーしている可能性があるため。

## 7. HTML の解析

- `HTML Format` (CF_HTML) のヘッダから `StartHTML` / `EndHTML` / `StartFragment` / `EndFragment` / `SourceURL` を読む。オフセットは UTF-8 のバイト数。
  - **`<base href>` は context (StartHTML〜EndHTML) から**、**候補は fragment (StartFragment〜EndFragment) から**集める。
  - 範囲の検証:
    - オフセットは、範囲内にあり大小関係が正しいか、UTF-8 として切れていないかを確かめる。
    - fragment のオフセットが壊れていたら、本文中の `<!--StartFragment-->` / `<!--EndFragment-->` 印を探す。
    - それも無ければ、検証済みの context 全体を fragment とみなす。
    - context も壊れていたら解析しない。
- **HTML パーサの crate を追加する**。今の依存には無く、`quick-xml` は実際の HTML に耐えない。
  - 第一候補は `scraper` (html5ever)。堅牢で保守も活発 (ライセンス MIT / Apache-2.0)。
- 集める候補:
  - `<img src>`
  - `<img srcset>` (最大の w / x 記述子のもの)
  - `<picture><source srcset>`
  - 画像拡張子への `<a href>`
  - 遅延読み込み属性 (`data-src` など。対象は S0 の結果で決める)
- URL の解決: `<base href>` → `SourceURL` の順で相対 URL を解決し、fragment を取り除く。
  - 受け付けるスキームは `http` / `https` / `data:image/*` だけ。`blob:` / `file:` / `cid:` / `javascript:` は捨てる。
- 同じ URL は 1 件にまとめる。
- 小さい画像を除く: `width` / `height` 属性が両方あって、どちらかが 32 px 未満のものは数えない (アイコンや計測用画像)。最終的な絞り込みは、取得後の実寸で行う (§9)。
- 候補は最大 500 件まで。それを超えた分は「上限のため省略」として件数だけ示す。

## 8. 画像の取得

### 8.1 取得サービス

- App が所有する `CaptureFetchService` が、固定 4 本の worker を持つ。
  - ダイアログをまたいで共有するので、閉じて開き直しても同時取得は全体で 4 本を超えない。
- 取得はダイアログごとの session ID 付きで投入する。
  - ダイアログを閉じると、その session の未着手の取得を取り消し、取得中の結果も捨てる。
  - blocking read の途中で中断はできないので、取得中の worker は §8.2 の期限まで走り切る。
- `data:` URL は通信せず、同じ流れでデコードする。

### 8.2 HTTP

- 既存の `ureq` 2.12 を使う (更新確認と同じ構成。rustls を使い、OS のプロキシ設定は使わない)。
  - 社内プロキシが必須の環境では取得できない。更新確認と同じ制約として割り切る。
- タイムアウト: 接続 10 秒、読み取り 1 回 30 秒、**1 枚の取得全体で 60 秒**。全体の期限は、読み取りのたびに確かめる。
- User-Agent は `mImageViewer/<版>`。ブラウザを装わない。
- 1 枚の上限は 64 MiB。`Content-Length` だけでなく、**実際に読んだ量**で判定する。
- **リダイレクトは自前で処理する**。`redirects(0)` にして、最大 5 回まで追う。各段の送信前に、次をすべて評価し直す:
  - スキーム (`http` / `https` のみ)
  - 宛先の制限 (§8.3)
  - 参照元 (Referer)

  ureq の既定のリダイレクトは、設定した Referer をそのまま次の宛先へ送る (ureq 2.12.1 の `src/unit.rs:216`、レビュー第 1 回で確認)。そのため既定には任せない。
- **参照元 (Referer)**: ブラウザの既定 (`strict-origin-when-cross-origin`) と同じ規則で、**送る段ごとに**決める。
  - 同じ origin なら、ページ URL (userinfo と fragment を除く)
  - 別 origin なら、origin だけ (`https://www.example.com/`)
  - https から http へなら、送らない

  2026-10-02 に、参照元を確認する画像サーバーで次の結果を得た (確認者: ClaudeCode、`curl`、Cookie なし)。origin だけでも取得できることを確認済み。

  | 送った参照元 | 結果 |
  | --- | --- |
  | なし | 403 |
  | origin のみ | 200 |
  | ページ URL | 200 |

### 8.3 宛先の制限

悪意あるページの HTML をコピーさせて、利用者の LAN 機器やローカルのサービスへ要求させるのを防ぐ。

- ureq の接続用 resolver (`AgentBuilder::resolver`) で、**実際に接続するアドレス**を検査する。許可されたアドレスだけを接続へ渡す。
  - 事前に別途 DNS を引いて検査する方式は、DNS rebinding で破られるので採らない。
- 拒否するアドレス:
  - ループバック
  - プライベート (10/8、172.16/12、192.168/16、fc00::/7)
  - リンクローカル
  - 未指定 (0.0.0.0、::)
  - IPv4-mapped IPv6 で上記に当たるもの
- リダイレクトの各段にも同じ resolver が効く。
- プロキシは使わないので、名前解決は常にこの resolver を通る。
- **ページ自体が社内サイトや NAS の場合の例外は設けない** (§11 Q6)。

### 8.4 一時保存と予算

- 取得したバイト列は `data_dir/tmp/clipboard-capture/<session id>/` に書き、メモリには持たない。
- 予算: ダイアログ 1 つあたり一時保存の合計 2 GiB。超えた分は「上限のため省略」とする。
- 一時フォルダの削除:
  - session の worker と保存処理がすべて終わってから、背景で 1 回だけ削除する。
  - 削除に失敗したら、ログに残す。次回起動時に `data_dir/tmp/clipboard-capture/` を丸ごと消すので、回復処理は持たない。
- 縮小表示は worker が一時ファイルからデコードして作る。
  - デコード後の大きさの上限は、既存のサムネイル生成と同じにする。
  - UI へ渡す縮小画像は件数上限付きの backlog に積み、テクスチャ化は 1 フレームに 1〜2 枚までにする ([ui-responsiveness.md](ui-responsiveness.md) §3)。
- **中身の確認**: 先頭バイトで画像形式を判定する。mIV が扱える画像形式でなければ失敗にする (HTML のエラーページなど)。拡張子もここで決める。

### 8.5 取れない画像

| 状況 | 結果 |
| --- | --- |
| 公開されている画像 | 取れる |
| 参照元を確認する画像 | §8.2 の参照元で取れる見込み |
| 期限付きの署名 URL | 期限内なら取れる |
| ログインが必要な画像 | 取れない。一覧に「取得できませんでした (403)」と出す |
| ボット対策のあるサイト | 拒否されることがある。同上 |
| `blob:` / canvas / CSS の背景画像 | HTML に無い、または取れない。数えない |
| 画面外でまだ読み込まれていない画像 | 遅延読み込み属性が残っていれば拾える (S0 で確認) |
| SNS のタイムライン | 画面付近に描かれている投稿だけ |
| 社内サイト・NAS 上の画像 | 取れない (§8.3) |

## 9. 選択ダイアログ

- メインウィンドウ内の `egui::Window`。`ui_dialogs/` に 1 ファイルで置く。モーダル扱い (§4-3, §4-4)。
- 上部には次を置く:
  - 出どころ (ドメイン)
  - 取得の進み具合 (N / M)
  - 最小サイズの絞り込み (短辺 px、既定 100)
  - 全選択 / 全解除
- 本体は、チェック付きの縮小表示の格子。
  - 取得中のものは枠だけを出す。
  - 失敗したものは理由を付け、選べない状態にする。
  - 既定のチェックは §11 Q4 に従う。
- 同じ内容 (ハッシュ一致) の画像は 1 件にまとめる。
- [保存] を押すと:
  - 背景の保存 worker が、選んだものを §2.6 の名前で保存先へ書く。
  - 保存が終わるまでダイアログはモーダルのまま、進み具合を出す。
  - 終わったら閉じ、メインのトーストで「N 枚保存しました」(失敗があれば件数も) と出す。
- [閉じる] / Esc で取り消す (§8.1)。
  - 保存中は [閉じる] を無効にする。
  - Esc は `dialog_escape_pressed` を使う (IME 規則)。

## 10. 保存と記録

### 10.1 保存

- 保存先は §2.7。Ctrl+V から来たときは §11 Q1 に従う。
- 書き込みは、保存先と同じフォルダに `.part` で書いてから rename で確定する。一時保存からは copy → rename。
- 名前が衝突した場合 (同じミリ秒に 2 回など) は、日時部分に `-2`, `-3` … を付けて避ける (`_` より前を変える)。
- 保存したフォルダを表示中なら、通常のフォルダ監視で一覧に出る。専用の更新処理は足さない。
- 複数枚の保存が途中で失敗したら、保存済みの画像は残す。件数と理由を伝え、巻き戻さない (§4-11)。

### 10.2 出どころの記録 (§11 Q3)

**案 A (推奨): Mark of the Web (`Zone.Identifier` 代替データストリーム)**

ブラウザがダウンロードしたファイルに付けるのと同じ形式で、次を書く。

- `ZoneId=3`
- `ReferrerUrl=<ページ URL>`
- `HostUrl=<画像 URL>`

いずれも userinfo と fragment は除く。

利点:
- 新しい DB が要らない。
- ファイルと一緒に移動する (NTFS の中で)。
- Explorer のプロパティでも見える。

注意点:
- FAT / exFAT へコピーすると消える。これはブラウザのダウンロードと同じ。
- 書けない保存先や書き込み失敗は、ログに残して画像の保存は続ける (§4-11)。
- Windows が画像の表示を妨げることはない。ただしプロパティに「ブロックの解除」が出る。

**案 B: mIV の新しい SQLite (`clipboard_capture.db`)**

保存パスから画像 URL / ページ URL / 取り込み日時を引ける。メタデータパネルに「元ページを開く」を出しやすい。
一方で、ファイルを移動・改名すると対応が切れる。

どちらの案でも、**v1 ではメタデータパネルへの表示は作らない** (記録だけ)。表示は後の段階で、既存のツイート情報パネル
([ui_metadata_panel.rs:5967](../src/ui_metadata_panel.rs) `draw_tweet_panel`) と同じ形で検討する。
どちらも未リリースの新しいデータなので、マイグレーションは要らない。

## 11. 利用者の判断を仰ぐ点

| # | 論点 | 推奨 |
| --- | --- | --- |
| Q1 | Ctrl+V で取り込むときの保存先 | **今のフォルダ**。既存の Ctrl+V (ファイルの貼り付け) と同じく、「貼り付けた場所に入る」。小窓と自動保存は取り込みフォルダに保存する |

| Q4 | 選択ダイアログで最初からチェックを付けておくか | **最小サイズ以上は全部チェック済み** |
| Q5 | 場所▼の「クリップボード取り込み」の表示条件 | **どちらかのチェックが ON のときだけ** |
| Q6 | 社内サイト・NAS の Web 画面など、ローカル / プライベートアドレス上の画像を取り込めるようにするか | **取り込めないままにする** (§8.3)。例外を作ると、許可する範囲の定義と検査が増える。困る利用者が出たら再検討する |
| Q7 | 同じ画像を続けてコピーしたとき 2 枚目を保存するか | **保存しない** (直前の 1 件と一致する場合だけ)。間を空けて同じ画像をコピーした場合は保存する |

## 12. 範囲外 (v1)

- mIV Remote・ゲームパッド・キー割り当てからの、取り込みフォルダへの移動 (場所▼のメイン表示のみ対応)
- detached viewer・フルスクリーンからの Ctrl+V や選択ダイアログ (§4-3)
- サイトごとの原寸 URL への書き換え
- 失敗した画像を別の手段 (WebView など) で取り直すこと
- メタデータパネルでの出どころ表示 (§10.2)
- Ctrl+V のキー割り当て化

## 14. テスト

- **形式の判定 (§5.4)** は、形式の集合を入力にした純関数のテストにする。
  - 除外形式
  - 自身の印
  - ファイル類 (`CF_HDROP` / 仮想ファイル)
  - 画像と HTML の両方があるもの
  - S0 で決めた Office の除外
- **reader の状態**:
  - 同じ sequence の重複通知で 1 回だけ処理されること
  - 読み取り前後の sequence 変化で読み直すこと
  - 旧世代の結果が捨てられること
  - 起動前からの内容を取り込まないこと
  - 直前と同じ内容を保存しないこと
- **DIB**: 完全透明・部分透明・alpha 未定義を、製本の入口とクリップボード取り込みの入口の両方で確かめる (§5.4 の規則のとおりになること)。
- **CF_HTML**:
  - 正常なもの
  - fragment のオフセットが壊れたもの (印による fallback)
  - context の `<base>`
  - `SourceURL` が無いもの
  - UTF-8 境界
- **候補抽出**:
  - `srcset` から最大のものを選ぶ
  - 受け付けるスキーム
  - 32 px 未満の除外
  - 候補の上限
- **参照元の規則**: 同じ origin / 別 origin / https→http と、リダイレクトの各段での再評価。userinfo と fragment が除かれること。
- **宛先の制限**: resolver で、IPv4 / IPv6 / IPv4-mapped と、リダイレクト先が private のもの。
- **ファイル名**: 生成した名前すべてについて、既存の `filename_stack` の prefix 関数がコピー単位で同じ値を返すこと。
  - ドメインに `_` を含む場合
  - 100 枚以上の場合
  - 衝突回避の `-2` を含む場合
- **取得** (テスト用ローカル HTTP サーバー):
  - 送られた参照元
  - 403
  - リダイレクト
  - 画像でない応答
  - `Content-Length` の無い 64 MiB 超
  - 少しずつ届いて全体の期限を超える応答
  - 取り消し後に worker が終わってから一時フォルダが消えること
  - 同時取得が全体で 4 本を超えないこと
- **選択ダイアログ**:
  - 開ける条件 (§4-3) の判定
  - 両方のモーダル述語への登録
  - 保存中の閉じる操作の無効化
  - ダイアログ中の HTML 検出の無視
- **Ctrl+V (handler-level)**:
  - ファイル類 / 画像 / HTML / どれでもない
  - 無効な一覧での無反応
  - 自動保存の直後の Ctrl+V (手動では保存されること)
  - mIV 自身がコピーした画像の Ctrl+V
  - 仮想ファイル形式が従来の Shell の貼り付けへ渡ること
- **場所▼**: Remote の場所一覧が変わらないこと。
- **idle health**: 監視 ON で小窓が出ていない静止状態で、repaint が増えないこと ([idle-health-check.md](idle-health-check.md))。
- **実機 (利用者)**:
  - 複数ディスプレイでの位置
  - DPI の違う画面への移動
  - ブラウザでの作業中にフォーカスが移らないこと
  - トレイ常駐中・通常の最小化中のクリック
