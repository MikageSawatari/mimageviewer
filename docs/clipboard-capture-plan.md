## 1. 目的

普段の作業中に見つけた画像を、手間なく mIV に取り込めるようにする。

- 画像そのものをコピーしたとき (スクリーンショット、ブラウザの「画像をコピー」など) は、自動で保存する。
- ブラウザでページの HTML をコピーしたとき (Ctrl+A → Ctrl+C など) は、ページ内の画像を一覧から選んで保存できる。

ブラウザ拡張・ストア公開・mIV 内ブラウザは使わず、**クリップボードだけ**で完結させる。

## 2. 利用者向け仕様 (2026-10-02 利用者と合意)

### 2.1 設定

環境設定に「クリップボード取り込み」ページを新設し、次の 2 つのチェックを置く。どちらも既定は OFF。

- □ 画像がコピーされたら自動で保存する
- □ ページ (HTML) がコピーされたら、含まれる画像を選んで保存できるようにする

保存先フォルダも同じページに置く。既定は `ピクチャ\mimageviewer\clipboard` で、変更・既定に戻す・フォルダを開くができる。

どちらの監視も **mIV の起動中だけ**動く。トレイ常駐と組み合わせれば常時動かせる旨をページに書く。

### 2.2 画像のコピー

クリップボードに画像データが入ったら、保存先へ保存し、右下の小窓 (§2.4) で知らせる。
知らせる文面は「クリップボードの画像を保存しました [開く] [×]」。

### 2.3 ページ (HTML) のコピー

1. ブラウザでページを選択してコピーすると、mIV が HTML から画像 URL を数える。
2. 右下に小窓「このページの画像 N 件 [画像を選んで保存] [×]」を出す。
3. ボタンを押すと mIV が前面に出て、メインウィンドウの一覧画面に選択ダイアログが開く。**画像の取得はこの時点から**始める。
4. 縮小表示を見ながら選び、[保存] で保存先へ書き出す。

### 2.4 右下の小窓

- mIV 専用の小さなネイティブウィンドウ。**前面ウィンドウ (多くの場合ブラウザ) のある画面**の、作業領域の右下に出す。
- **フォーカスを奪わない**。ブラウザでの作業を止めない。
- 8 秒で消える。マウスを乗せている間は消えない。
- 内容は常に最新 1 件だけ。続けてコピーしたら中身を置き換える。
- Windows の通知機能は使わない (§3.3)。OS の通知設定に関係なく出る。

### 2.5 Ctrl+V

mIV の一覧で Ctrl+V を押したとき、クリップボードの中身で動作を分ける (詳細は §5.5)。
監視のチェックが OFF でも動く。手動の入口であり、小窓を見逃したときの救済も兼ねる。

| クリップボードの中身 | 動作 |
| --- | --- |
| ファイル類 (Explorer のコピー / 切り取り、Shell の仮想ファイルなど) | 従来どおり Shell の貼り付け |
| 画像データ | 保存する (保存先は §11 Q1) |
| HTML (画像 URL あり) | 選択ダイアログを開く (保存先は §11 Q1) |
| どれでもない | 従来どおり Shell の貼り付けへ渡す (現状と同じ) |

### 2.6 ファイル名

```
<日時>-<ドメイン>_<連番>.<拡張子>
例: 20261002-153012-345-www.example.com_01.jpg
    20261002-153012-345-www.example.com_02.jpg   ← 同じコピーなので 1 スタック
    20261002-154500-012_01.png                    ← 画像データのコピー (出どころ不明)
```

- **1 回のコピーが 1 スタックになる**。既定のスタック規則 (最後の `_` より前が同じものを畳む、[filename-stack-plan.md](filename-stack-plan.md)) に合わせている。
- 日時が先頭なので、名前順がそのまま取り込み順になる。日時はミリ秒まで入れる。
- `_` より前には `_` を含めない。
  - 日時の区切りは `-` にする。
  - ドメイン中の `_` と、Windows で使えない文字は `-` に置き換える。
- 連番の桁は 2 桁以上で、そのコピーの枚数に合わせてそろえる (100 枚以上なら 3 桁)。
- 拡張子は、取得した**中身から判定した形式**で付ける。URL の拡張子は信用しない。
- 元のファイル名はファイル名に入れない。出どころは §10.2 で記録する。
- ドメインには、ページ URL が分かればページのドメインを使い、分からなければ画像 URL のドメインを使う。どちらも無ければ (切り取りツールなど) ドメインの部分を付けない。
- スタック表示の ON/OFF は既存のトグルのまま。このフォルダで自動的に ON にはしない (状態を増やさないため)。
- 区切り文字の設定を `_` 以外に変えている利用者の場合は、コピー単位にまとまらない。マニュアルに「既定の区切り文字でまとまります」と書く。

### 2.7 保存先フォルダ

- 既定は `capture::default_output_dir().join("clipboard")` (= `ピクチャ\mimageviewer\clipboard`)。
- その下に月ごとのサブフォルダ (`2026-10`) を作る。
- フォルダは**最初に保存するとき**に作る。チェックを入れた時点では作らない。
- 場所▼メニューに「クリップボード取り込み」を出す。
  - 表示条件は「2 つのチェックのどちらかが ON」。専用の表示設定は増やさない。
  - **メインウィンドウの場所▼だけ**に出す。`known_folders::location_menu_entries` は mIV Remote のホームとも共有しているので、Remote 側の列挙から除外し、Remote の既存の場所一覧が変わらないことをテストで固定する。
- 本棚と違い、検索索引の除外対象にはしない。お気に入りの配下にあれば、通常どおり Ctrl+G / Ctrl+S の対象になる。

## 3. 検討した代替案と採否

### 3.1 取り込みの入口

| 案 | 採否 | 理由 |
| --- | --- | --- |
| ブラウザ拡張 (Native Messaging + 中継 exe) | 不採用 | 次の作業がすべて要る:<br>・ストア公開 (Chrome / Edge / Firefox) と審査<br>・拡張のインストール手順<br>・中継 exe のレジストリ登録<br>さらに単体 exe 版は本体の場所が版ごとに変わるので、登録先の管理も要る |

| **コピーした HTML / 画像をクリップボードから読む** | **採用** | 追加インストール・公開作業・ログインが要らない |

## 4. 状態の組み合わせを減らすための決定

CLAUDE.md「設計の簡素化」に従い、割り込みを扱う仕組みを作る前に、組み合わせそのものを減らした。

1. **HTML の待ちは最新 1 件だけ**。待ち行列は持たず、小窓の内容を置き換える。
2. **小窓の段階では何も取得しない**。取得は選択ダイアログを開いてから始める。普段のコピーで通信は発生しない。
3. **選択ダイアログは一覧画面でだけ開く**。開ける条件は次のすべて:
   - メインウィンドウが一覧表示中 (フルスクリーン・動画・detached でない)
   - 他のモーダルが開いていない
   - Remote が操作を握っていない
   - フォルダを開く・移動するための準備が進行中でない (`folder_open_preparation_pending` など、[app.rs:33425](../src/app.rs))。後から完了する移動との組み合わせを、開く前に除外する

   条件を満たさないときは開かずに、メインのトーストで「一覧画面で Ctrl+V を押すと開けます」と出す。
   この設計では、フルスクリーン・detached の述語や経路を変更しない。実装で detached の述語・viewport 経路・前面化の経路に変更が及ぶ場合は、CLAUDE.md の凍結ルールの手順 (構造的修正であることの双方合意と [detached-rework-plan.md](detached-rework-plan.md) への記録) に従う。
4. **選択ダイアログはモーダル**。
   - 開いている間は、フォルダ移動・フルスクリーン・他のダイアログ・2 重起動からのパス受け渡し・D&D を受け付けない。
     `App::common_modal_dialog_open` (`modal_dialog_block_reason`) と、2 重起動の受付判定
     `document_open_modal_admission_blocked` ([app.rs:33418](../src/app.rs)) の両方に登録する。
   - 保存中も、保存が終わるまでモーダルを保つ。
   - 閉じたら取得を取り消す。途中から再開する仕組みは持たない。
5. **選択ダイアログを開いている間の HTML 検出は無視する**。小窓も出さず、待ちも更新しない。閉じた後に必要なら Ctrl+V で開き直す。
6. **画像データと HTML が両方あるコピーは、画像データだけで判断する**。ブラウザの「画像をコピー」は両方を入れるため。
   - 自動保存では、画像の自動保存が OFF なら何もしない (HTML 側へは回さない)。
   - このときの HTML は、出どころの記録にだけ使う。
7. **設定は世代番号付きの不変スナップショットで渡す** (§5.3)。設定を変えると世代が進み、次のものはすべて捨てる:
   - 旧世代の読み取り結果
   - 表示中の小窓
   - HTML の待ち

   ただし、すでに始まった保存は最後まで行う (割り切り)。
8. **保存先フォルダは保存時に作る**。利用者が途中で消しても、次の保存で作り直す。
9. **自動と手動 (Ctrl+V) は、解析と保存の部品を共有し、入口の意図を型で分ける** (§5.5)。
10. **小窓は mIV が前面でも同じように出す**。表示経路を 1 つにするため。コピーは通常ほかのアプリで行うので、mIV が前面のまま監視が反応する場面はほぼない。
11. **まれな失敗は割り切る** (CLAUDE.md「まれな失敗への対処」)。
    - 保存の書き込み失敗・ディスク不足・出どころ記録の失敗は、すでに保存できた画像はそのまま残す。
    - 件数と理由を小窓またはトーストで伝え、ログに残す。
    - 再試行・巻き戻し・回復のための状態は持たない。
    - 強制終了で残った一時ファイルは、次回起動時にまとめて消す。

## 5. クリップボードの監視

### 5.1 構成

新しいモジュール `clipboard_capture` が、process に 1 つの `ClipboardCaptureService` を持つ。App が所有し、viewer bundle には入れない。

- **listener thread** `clipboard-capture-listener`
  - message-only window を持ち、`AddClipboardFormatListener` を登録して `GetMessageW` のループを回す。
  - `WM_CLIPBOARDUPDATE` ごとに、次の 3 つを latest-request slot に置いて reader を起こす。
    - 単調増加の request serial
    - `GetClipboardSequenceNumber`
    - **その時点の設定スナップショット** (§5.3)
  - 起動時の初回読み取りはしない。
- **reader thread** `clipboard-capture-reader`
  - slot から最新の要求だけを取り出し、§5.2 の手順で読む。
- **寿命**: 一度起動したら、App の終了まで保持する。
  - 起動時に両方のチェックが OFF なら、起動しない。最初にどちらかを ON にした時点で起動する。
  - その後両方を OFF にしても、thread は止めない。reader が要求を読み捨てるだけにする。
  - これで、設定操作のたびの停止待ち・再起動を扱わずに済む。既存の切り取り表示の detach は、プロセス終了のためだけの約束なので、設定の OFF に流用しない。
- 起動・終了・失敗は、既存の切り取り表示と独立させる。
  - **起動に失敗した場合**: 設定ページに「この環境ではクリップボードの監視を開始できませんでした」と出し、ログに残す。Ctrl+V の手動入口は監視と関係なく動く。
  - **App 終了時**: 既存と同じく、message の投入に成功した thread だけを join する。外部のクリップボード呼び出し中の thread は待たない。

### 5.2 読み取りの手順 (自動)

1. **設定の確認**: 要求に付いた設定スナップショットで、対象の種類が OFF なら読まない (§5.3)。
2. **重複の排除**: 要求の OS sequence が、最後に受理した sequence と等しければ読まない。同じコピーで通知が複数回届く場合のため。
3. **形式の確認**: クリップボードを開き、形式の一覧だけを見る。
4. **生データの取り出し**: 判定に必要な形式の生データを上限付きでコピーし、すぐ閉じる。必要な形式は §5.4 を参照。
   - 上限は画像 256 MiB、HTML 32 MiB。超えたら取り込まない。
   - **クリップボードを開いている間は、デコード・解析・保存をしない。** 既存の製本の読み取り ([books.rs:1928](../src/books.rs)) は開いたままデコードしているが、常時動く監視では他のアプリの邪魔になるので採らない。
5. **読み直し**: 次の 3 つが一致しなければ、途中の結果を捨てる。
   - 3 つの sequence:
     - 要求の sequence
     - 読み取り直前の sequence
     - 読み取り直後の sequence
   - 読み直しの順序 (既存の [cut_clipboard.rs:1413](../src/cut_clipboard.rs) / [:1466](../src/cut_clipboard.rs) と同じ考え方で、次の通知を待つだけにはしない):
     1. latest-request slot に新しい要求があれば、それを優先する。
     2. 無ければ、観測した sequence を要求として、**同じ設定スナップショットのまま 1 回だけ**読み直す。読み直しの要求も、有効化の基準 sequence (§5.3) による除外と、受理済みの sequence による重複の排除 (step 2) を通す。
     3. それでも一致しなければ、そのコピーは見送る (割り切り)。専用の timer や回復用の状態は持たない。
        - ログに残す。
        - そのコピーがまだ最新の要求だった場合だけ、既存の小窓で「取り込めませんでした。もう一度コピーしてください」と知らせる。
        - 新しい通知に置き換えられた場合や、世代が古くて捨てた場合は、知らせない。
6. **受理**: 3 つが一致し、かつ要求の設定の世代が現在の世代と同じなら、その sequence を受理済みとして記録する。
   - 世代が古い読み取りは捨てる。受理済みの sequence も、§5.6 の内容ハッシュも更新しない。
   - 正しさの根拠は、この 3 つの sequence の一致と §5.6 の内容の一致に置く。待ち時間 (debounce) には頼らない。
7. **判定と解析**: クリップボードを閉じた後、取り出した生データに §5.4 の判定を行い、デコードや HTML 解析を reader の上で行う。
8. **結果の扱い**:
   - 画像なら保存 worker へ、HTML なら小窓へ渡す。
   - 結果には設定の世代番号を付ける。
9. **開けないとき**: クリップボードを開けない間は、上限付きで再試行する (既存と同じ 25 / 50 / 100 / 250 ms)。新しい要求が来たら打ち切る。

### 5.3 設定のスナップショット

UI thread は次の項目を 1 つの不変スナップショットにまとめ、`Arc` で listener へ渡す。

- 2 つのチェック
- 保存先
- 世代番号
- **チェックごとの有効化時の基準 sequence**

設定が変わるたびに世代が進む。

- **有効化の基準**: チェックを OFF から ON にした時点で、UI thread が `GetClipboardSequenceNumber` を読み、そのチェックの基準 sequence として記録する (軽い syscall)。
  - reader は、要求の sequence が対象チェックの基準と等しければ、その種類として扱わない。
  - チェックを入れた時点でクリップボードにあった内容は、片方がすでに ON で listener が動いていても取り込まない。
  - sequence は wrap するので、大小比較はせず、等しいかどうかだけを見る (既存と同じ)。
- **世代の扱い**: スナップショットは通知の時点で要求に付く。後から別の世代を付け直すことはない。
  - reader・保存 worker・小窓は、受けた世代と現在の世代が違えば結果を捨てる (§4-7)。
  - 現在の世代は atomic で読む。

### 5.4 形式の判定 (自動)

判定は、**取り出した生データの要約を入力にした純関数**として持つ。入力は次の構造体にする。

- 形式の集合
- `CanIncludeInClipboardHistory` の値
- `HTML Format` の `SourceURL`
- S0 で決める除外判定に要る値

上から順に判定し、最初に当てはまったもので決める。

1. **取り込まないコピー**: パスワード管理ソフトなどが付ける形式。Windows のクリップボード履歴と同じ扱いにする。
   - `ExcludeClipboardContentFromMonitorProcessing` 形式がある
   - `CanIncludeInClipboardHistory` が 0
   - `Clipboard Viewer Ignore` 形式がある
2. **mIV 自身のコピー**: §5.7 の印がある。
3. **ファイル類**: `CF_HDROP`、`FileGroupDescriptorW`、`Shell IDList Array` のいずれかがある。
4. **画像データ**: 登録形式 `PNG`、`CF_DIBV5`、`CF_DIB` のいずれかがある。
   - ただし、**Office 固有の形式**があるものは除く (S0 と利用者の決定 Q8、§5.8)。Office (Excel / Word / PowerPoint) からのコピーはここで外れ、ブラウザと切り取りツールの画像は外れない。
     - `Embed Source`、`Object Descriptor`、`XML Spreadsheet` のいずれか
     - `Art::GVML ClipFormat`、または名前が `PowerPoint ` で始まる形式 (Office の図形・グラフ)
   - テキストが同時にあることは、除外の理由にしない。画像に説明文や URL を添えてコピーするアプリもあるため。
5. **HTML**: `HTML Format` があり、ヘッダの `SourceURL` が `http` / `https`。
   - Word / Outlook などのコピーは `SourceURL` を持たないので、ここで外れる見込み。S0 で確認する。
6. **それ以外**: 何もしない。

**画像データの取り出し**は `PNG` → `CF_DIBV5` → `CF_DIB` の順で行う。

- `PNG` は、デコードできることを確かめてから、そのバイト列をそのまま保存する。
- DIB は PNG にエンコードする。DIB の解釈は既存の `books::decode_cf_dib_rgba` ([books.rs:1946](../src/books.rs)) を共通化し、製本と取り込みで同じ規則を使う。
- **alpha がすべて 0 の 32bit DIB は不透明として扱う** ([books.rs:2081](../src/books.rs) の既存規則)。
  - alpha を書かないアプリがあるため。完全に透明な画像のコピーは実用上ないとみなす割り切り。
  - 透過を保つ主な経路は `PNG` 形式。ブラウザや切り取りツールは `PNG` も入れる見込みで、S0 で確認する。
- **デコード前の寸法の上限**: メモリを確保する前に、`PNG` の IHDR と DIB のヘッダから幅・高さを読む。次のどちらかに当たれば取り込まない。
  - 幅または高さが 32768 を超える
  - RGBA に展開すると 1 GiB を超える

  既存の 256 MiB の上限 ([thumb_loader.rs:911](../src/thumb_loader.rs)) は JPEG 経路のもので、全形式に効くわけではない。
  - **この上限は取り込みの入口でだけ適用する**。共通化する DIB の解釈 ([books.rs:1929](../src/books.rs)。確保は [:2017](../src/books.rs)) には入れない。
  - 製本の「クリップボードの画像を本に追加」は、今の受付範囲のまま残す (例: 40000×1 の DIB も受け付ける)。
  - 取り込みの入口では、共通の解釈を呼ぶ前に、ヘッダの寸法を検査する。

### 5.5 Ctrl+V の分岐 (手動)

入口の意図を型で分ける。

```
enum CaptureIntent {
    Automatic { snapshot },          // 監視から
    Manual { destination },          // Ctrl+V から
}
```

- 解析・保存の部品は共有する。
- **監視専用の抑止は手動へ適用しない**。手動の Ctrl+V は利用者の明示操作なので、次のいずれも見ない。
  - チェックの OFF
  - 世代・基準 sequence・受理済み sequence
  - §5.6 の内容の一致
  - §5.7 の自身の印
  - §5.4-1 の除外形式
  - Office の除外規則

  たとえば mIV で「画像をコピー」した画像や Excel の表を Ctrl+V すれば、それも保存される。
- **分岐は UI thread で、形式の一覧だけを見て決める**。
  1. 形式にファイル類 (§5.4-3) が 1 つでもあれば、**従来の Shell の貼り付け**。
  2. 画像データの形式があれば、画像の取り込み。
  3. `HTML Format` があれば、HTML の取り込み。
  4. どれでもなければ、**従来の Shell の貼り付け**。
  - 生データの取り出し・解析は worker で行う。
  - HTML に `SourceURL` が無い、または画像の候補が 0 件なら、メインのトーストで「取り込める画像がありません」と出して終わる。Shell の貼り付けへ戻すことはしない。分岐の後でクリップボードが変わる可能性があるので、戻す仕組みを作らない。
- **既存の動作との関係**: 画像データや HTML だけが入ったクリップボードで Shell の貼り付けを呼んでも、今は何も起きない見込み。Explorer のフォルダは、画像や HTML の貼り付けからファイルを作らない。
  - この見込みは S0 で確かめる。今の mIV に画像をコピーした状態で、Ctrl+V を押したときの動作を利用者に見てもらう。
  - 何か起きている場合は、既存の動作を変えることになる。その場合は着手前に利用者へ相談する。
- 既存の `App::handle_clipboard_shortcuts` ([app.rs:50795](../src/app.rs)) に合流させる。
  - 無効な一覧 (検索結果・タグ結果など、既存の Ctrl+V が無反応な一覧) では、新しい処理も無反応にする。
  - 保存先は今のフォルダ (`current_favorite_target()`、Q1)。
- Ctrl+V は今も `GetAsyncKeyState` による固定扱いで、キー割り当ての対象外。今回もそれを変えない。

### 5.6 同じ内容の重複 (自動、Q7)

**保証の範囲 (Q7 の補足、利用者の決定 §11 Q9)**: この判定は、**reader が読めたコピーの並び**に対して行う。listener は最新の要求だけを残すので、reader が処理中の間に続けてコピーされたものは、途中のものが読まれずに合流する。
- 例: 画像 A の処理中に「テキスト → A」と続けてコピーすると、テキストは読まれず、2 回目の A は重複として保存されない。
- 起きるのは、1 秒に満たない間に続けてコピーした場合だけ。
- 合流で消えたコピーを、通知の回数などから推測する仕組みは作らない。

自動保存では、**直前に受理した内容が同じ画像なら保存しない**。

- reader は、最後に受理したコピーの内容ハッシュを 1 つだけ持つ。
  - ハッシュは、**画像の監視が有効な期間の中だけ**で使う。
    - 設定スナップショットに「画像の監視の有効化回数」を入れる。
    - reader は、ハッシュを記録したときの回数と要求の回数が違えば、ハッシュを捨ててから判定する。
  - 例: 画像 A を保存 → 監視 OFF → テキストをコピー → 監視 ON → 画像 A をコピー、の順でも A を保存する。OFF の間の通知が合流して届かなくても、有効化の境界で必ずハッシュが捨てられる。
  - 受理したコピーが画像でなかった場合 (テキストなど) は、そのハッシュを消す。
  - 同じ画像を続けて 2 回コピーすると、2 枚目は保存しない。
  - 間に別の内容のコピー (テキストを含む) を挟めば、同じ画像でも保存する。
  - 経過時間は見ない。
- 通知の重複は、これとは別に §5.2-2 の受理済み sequence で抑える。

### 5.7 mIV 自身のコピーの印

mIV の「画像をコピー」は、次のすべてが [context_menu.rs:2503](../src/ui_dialogs/context_menu.rs) の `set_rgba_to_clipboard` を通る。

- 右クリック
- ZIP 内画像
- 動画フレーム
- キャプチャ

**今の状態**:

- 印を付けていない。
- `OpenClipboard(None)` → `EmptyClipboard` で開き、API の失敗を捨てている ([context_menu.rs:2557](../src/ui_dialogs/context_menu.rs))。
  - Microsoft の文書には「NULL の window で開いて `EmptyClipboard` すると所有者が NULL になり、`SetClipboardData` が失敗する」とある。
  - ただし **S0 の記録では、mIV の「画像をコピー」の直後に、所有者なしの `CF_DIB` (3858×2775) がクリップボードに入っていた** (利用者の記録 `173922`)。今の書き込みは実際に成功している。

**整え方**: **今の書き込みの経路と開き方は変えず**、次の 2 点だけを足す。

- `CF_DIB` と同じ開閉の中で、private 登録形式 `mImageViewer Clipboard Origin v1` (process nonce) を書く。
- `EmptyClipboard` と各 `SetClipboardData` の成否を確かめる。
  - 失敗したらログに残し、失敗した HGLOBAL は自分で解放する。
  - 成功したものは、所有権をシステムへ移す。

印の登録や書き込みに失敗しても、画像コピー自体は続ける (割り切り)。既存の書き込み世代 (`reserve_clipboard_write_sequence` / `clipboard_seq_is_latest`) の約束はそのまま残す。

**採らなかった方式**:

- **書き込み専用 thread** (第 4 版の案): 有効な所有者の window を持つために、message ループを回し続ける専用 thread を新設する案。S0 で今の書き込みが成功していると分かったので取りやめた。thread とその寿命の管理を増やさずに済む。
- **書き込み直後の sequence を記録する方式**: `CloseClipboard` との前後関係で取りこぼす。
- **既存の切り取り用の印の流用**: `mImageViewer Cut Owner v1` はファイルの Cut 専用で、意味が違う。

**ページ全体のコピーの HTML** (173736):

- `SourceURL` は `https://…/artworks/…#1` (fragment 付き)。
- URL はすべて絶対 URL。`srcset` と `<picture>` は無い。
- `<img>` は 15 件。内訳は次のとおり。`width` / `height` 付きは 7 件で、うち 2 件が 32 px 未満。
  - SVG のロゴ・アイコン 3 件
  - プロフィールアイコン
  - 一覧用の縮小画像
  - 本文の表示用画像 (長辺 1200)
- `data-src` は 3 件。いずれも `style` の背景画像と重複していた。
- `style="background-image: url(...)"` は 10 件 (アイコン、スタンプ、関連商品の縮小画像)。
- **画像へのリンク `<a href>` の 1 件が、原寸画像 (`img-original/…_p0.png`) を指していた。**
  - 参照元を origin だけにして取得すると、200 (PNG、2,815,533 バイト) が返った (確認者: ClaudeCode、`curl`、Cookie なし)。
  - 汎用の候補規則 (§7) のままで、このページでは原寸が取れる。

**決めたこと**:

- **画像データの除外規則** (§5.4): Office 固有の形式がある場合は除外する。利用者の決定 (Q8) で、Office は Excel / Word / PowerPoint をそろえて除外する。
  - 対象の形式は `Embed Source` / `Object Descriptor` / `XML Spreadsheet` / `Art::GVML ClipFormat` / 名前が `PowerPoint ` で始まる形式。
  - Chrome / Edge / Firefox の「画像をコピー」と切り取りツールは、どれにも当たらないので取り込まれる。
- **待ち時間は設けない** (§5.2): 上の「記録の読み方の注意」のとおり、記録は待ち時間の根拠にならない。
- **`PNG` を最優先する**: 3 つのブラウザ・切り取りツール・PowerPoint のすべてが `PNG` を入れていた。`PNG` があれば、DIB の alpha の扱い (§5.4) で透過が失われる場面は起きない。
- **「画像をコピー」の出どころ** (§10.2): HTML に `SourceURL` が無いので、別の形式から取る。
  - 画像 URL は `UniformResourceLocatorW` から取る (Chrome / Edge)。
    - Firefox の `HTML Format` にある `<img src>` は使わない。Firefox は画像データと HTML を別々に作るので、`srcset` や `<picture>` で実際に表示されていた画像と、`src` 属性が違うことがある (レビュー第 5 回)。
  - ページ URL は Chromium の `Chromium internal source URL` から取る (Chrome / Edge)。Chromium 独自の形式なので、取れたときだけ使う。中身の書式は実装時に確かめる。
  - Firefox では、ページ URL も画像 URL も取らない (`text/_moz_htmlcontext` は空だった)。出どころは記録せず、ファイル名にドメインも付けない。
- **HTML の候補** (§7): インライン `style` の `background-image: url()` を候補に加える。SVG は mIV で扱えないので候補から外す。
- **今の画像コピーの経路** (§5.7): 変えない。
- **Firefox**: 出どころを確実に取る手段が無いので、出どころの記録とファイル名のドメインを省く (§2.6、§10.2)。

**今の Ctrl+V の動作** (§5.5): 今の mIV で、Chrome で「画像をコピー」した後に一覧で Ctrl+V を押すと、**何も起きなかった** (2026-10-02、利用者が確認)。画像データだけのクリップボードでは、今の Shell の貼り付けは何もしない。§5.5 の分岐で失われる既存の動作は無い。

## 6. 右下の小窓

### 6.1 ウィンドウ

- 専用 thread `clipboard-capture-popup` が、Win32 の小さな top-level window を 1 つ持つ。初回表示時に作り、以後は再利用する。
- **egui の viewport にはしない**。複数ウィンドウの仕組みはリワーク中 ([detached-rework-plan.md](detached-rework-plan.md)) なので、そこに新しい viewport を増やさない。小窓は App の描画ループから独立させる。
- 拡張スタイルは `WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`。owner は持たない。
  - owner を持つと、表示時にメインウィンドウが前に出る ([native_context_menu.rs:1497](../src/native_context_menu.rs) の tooltip と同じ判断)。
- `WM_MOUSEACTIVATE` には `MA_NOACTIVATE` を返す ([hud_window.rs:672](../src/video/native_window_host/hud_window.rs) と同じ)。
- 表示は `SW_SHOWNOACTIVATE` で行う。位置とサイズの変更は、すべて `SetWindowPos(..., SWP_NOACTIVATE)` で行う。

### 6.2 位置と DPI

- popup thread は per-monitor DPI aware v2 で動かす。プロセスの既定に従い、違う場合は thread の DPI 文脈を明示する。
- 位置の決め方:
  1. `GetForegroundWindow` → `MonitorFromWindow` → `GetMonitorInfoW` で、`rcWork` (物理座標) を得る。
     前面ウィンドウが取れなければプライマリモニターを使う。
  2. 仮の位置へ `SetWindowPos` で移す。
  3. `GetDpiForWindow` で DPI を得て、フォント・大きさ・ボタン領域を作り直す。
  4. 右下へ置き直す。

  Microsoft の案内に従い、per-monitor aware の thread では `GetDpiForMonitor` ではなく `GetDpiForWindow` を使う。
- `WM_DPICHANGED` を受けたら、提案された矩形へ移し、フォントと当たり判定を作り直して再描画する。
- この手順は popup 専用に持つ。`monitor.rs` に「HWND / 前面ウィンドウの作業領域」を返す helper を足し、DPI は window から取る。

### 6.3 描画と寿命

- **描画**: GDI で自前描画する (`DrawTextW`、DPI に合わせた `CreateFontW`)。mIV で GDI の文字描画を使うのは初めて。
  - 子コントロールの BUTTON は使わない。押したときのフォーカス移動が絡むため。ボタン領域は自前で描き、`WM_LBUTTONUP` で当たり判定する。
  - 配色は、mIV の Light / Dark の解決結果をスナップショットで受け取る。
  - フォントは Yu Gothic UI (無ければ既定の UI フォント)。絵文字や環境依存の記号は使わない (CLAUDE.md のグリフ規則)。
- **寿命**:
  - `SetTimer` で 8 秒後に隠す。
  - `TrackMouseEvent` を使い、マウスが乗っている間はタイマーを止め、離れたら 8 秒を数え直す。
  - [×] またはタイムアウトで隠す。window は破棄しない。
- **内容の種類**: どれも最新 1 件で置き換える。
  - HTML 検出:「このページの画像 N 件 [画像を選んで保存] [×]」。検出結果のスナップショットを持つ。
  - 保存完了:「クリップボードの画像を保存しました [開く] [×]」
  - 保存失敗:「保存できませんでした: <理由> [×]」
- **出さない場面**: 選択ダイアログを開いている間だけ (§4-5)。

### 6.4 クリックの受け渡しと前面化

- ボタンが押されたら、popup thread がメインウィンドウを前面に出し、App へ typed event を送る。
  - HTML 検出の場合は `OpenCaptureSelection(snapshot)`。
  - 保存完了の場合は `RevealSaved(path)`。
- **前面化の helper**: トレイ復帰の `do_show_window` ([tray.rs:453](../src/tray.rs)) と、2 重起動時の処理 ([single_instance.rs:751](../src/single_instance.rs)) を共通 helper に切り出し、3 か所で使う。
  - helper は 3 つの状態を分ける:
    - **トレイに隠れている**: 保存済みの配置で表示する (既存どおり)。
    - **通常の最小化**: `IsIconic` なら明示的に `SW_RESTORE` する。
    - **表示中**: 前面化だけ行う。
  - 既存の約束は保つ。配置スロットの lock は外してから Win32 を呼び、App 側の復帰同期 (`sync_after_restore`) も維持する。
  - `SetForegroundWindow` は、利用者がクリックした直後なので許可される条件を満たす見込み。ただし成功は保証されない。失敗したらログに残すだけにし、再試行や強制的なフォーカス操作は足さない。
- event の受け渡しは `mpsc` と `request_repaint` で行う。メインウィンドウがトレイに隠れていた場合は、トレイと同じく `WM_PAINT` を post して `update` を確実に起こす ([tray.rs:8](../src/tray.rs) の注意)。
- App は `update` の先頭で event を受け取り、§4-3 の条件で選択ダイアログを開く。
  - 開けない場合は、メインのトーストで理由を出す。
  - クリップボードは読み直さない。その間に別の内容をコピーしている可能性があるため。

## 7. HTML の解析

- `HTML Format` (CF_HTML) のヘッダから `StartHTML` / `EndHTML` / `StartFragment` / `EndFragment` / `SourceURL` を読む。オフセットは UTF-8 のバイト数。
  - **`<base href>` は context (StartHTML〜EndHTML) から**、**候補は fragment (StartFragment〜EndFragment) から**集める。
  - 範囲の検証:
    - オフセットは、範囲内にあり大小関係が正しいか、UTF-8 として切れていないかを確かめる。
    - fragment のオフセットが壊れていたら、本文中の `<!--StartFragment-->` / `<!--EndFragment-->` 印を探す。
    - それも無ければ、検証済みの context 全体を fragment とみなす。
    - context も壊れていたら解析しない。
- **HTML パーサの crate を追加する**。今の依存には無く、`quick-xml` は実際の HTML に耐えない。
  - 第一候補は `scraper` (html5ever)。堅牢で保守も活発 (ライセンス MIT / Apache-2.0)。
- 集める候補:
  - `<img src>`
  - `<img srcset>` (最大の w / x 記述子のもの)
  - `<picture><source srcset>`
  - 画像拡張子への `<a href>`
  - 遅延読み込み属性 `data-src`
  - インライン `style` の `background-image: url(...)`。HTML の実体参照 (`&quot;` など) を解いてから読む。S0 では 10 件あった
- 拡張子が `.svg` の URL は候補にしない。mIV で扱えない形式なので。最終的な判定は §8.4 の中身の確認で行う。
- URL の解決: `<base href>` → `SourceURL` の順で相対 URL を解決し、fragment を取り除く。
  - 受け付けるスキームは `http` / `https` / `data:image/*` だけ。`blob:` / `file:` / `cid:` / `javascript:` は捨てる。
- 同じ URL は 1 件にまとめる。
- 小さい画像を除く: `width` / `height` 属性が両方あって、どちらかが 32 px 未満のものは数えない (アイコンや計測用画像)。最終的な絞り込みは、取得後の実寸で行う (§9)。
- 候補は最大 500 件まで。それを超えた分は「上限のため省略」として件数だけ示す。

## 8. 画像の取得

### 8.1 取得サービス

App が所有する `CaptureFetchService` が、固定 4 本の worker を持つ。

- **同時取得の上限**: ダイアログをまたいで共有するので、閉じて開き直しても同時取得は全体で 4 本を超えない。
- **session の単位**: 取得はダイアログごとの session として投入する。session は次のものを**自分で所有**する。
  - ureq の `Agent`、接続用 resolver、接続プール
  - session 開始時に決めたページの区分 (§8.3、不変値)
  - 一時保存フォルダ
- **session ごとに分ける理由**: ureq は、使える接続がプールにあれば resolver を呼ばずに再利用する (ureq 2.12.1 `src/unit.rs:355`)。プールのキーにはページの区分が含まれない (`src/pool.rs:190`)。Agent を共有すると、社内ページの session で開いた private への接続を、公開ページの session が再利用できてしまう。
  - サービス共通の可変なページ区分を、resolver から参照しない。
- **閉じたとき**: その session の未着手の取得を取り消し、取得中の結果も捨てる。
  - blocking read の途中では中断できないので、取得中の worker は §8.2 の期限まで走り切る。
- **`data:` URL**: 通信せず、同じ流れでデコードする。

### 8.2 HTTP

**ライブラリ**: 既存の `ureq` 2.12 を使う。更新確認と同じ構成で、rustls を使い、OS のプロキシ設定は使わない。社内プロキシが必須の環境では取得できない (更新確認と同じ制約として割り切る)。

**期限**:
- 1 枚の取得全体で 60 秒。リダイレクトの各段の送信時に、残り時間を ureq の全体 timeout として渡す。ureq では全体 timeout が読み取りごとの timeout より優先される (`src/stream.rs:85`, `:433`)。
- 接続は 10 秒。ureq では接続の timeout が全体の timeout より優先される (`src/agent.rs:405`, `src/stream.rs:352`)。そのため残り時間が少ない段では、接続だけで最大 10 秒超過し得る。これは許容する (割り切り)。
- 名前解決には ureq の期限が効かない (`src/stream.rs:364`)。OS の名前解決の期限に任せる (割り切り)。

**User-Agent**: `mImageViewer/<版>`。ブラウザを装わない。

**サイズ**: 1 枚の上限は 64 MiB。`Content-Length` だけでなく、**実際に読んだ量**で判定する。

**URL の検査**: 最初の URL と、各リダイレクトの `Location` を解決した URL に、毎回次を行う。
- `http` / `https` 以外のスキームは拒否する。
- **userinfo (`user:pass@`) を含む URL は拒否する**。ureq は URL の userinfo から Basic 認証のヘッダを自動で作るため (`src/unit.rs:87`)。相対 URL が userinfo 付きの base を引き継ぐ場合も同じ。
- **ブラウザの禁止ポート**を拒否する。Fetch 仕様の bad port の一覧を使う (例: 25、110、6000 など)。80 / 443 だけに絞ることはしないので、3000・8000・8080 などの開発用ポートは使える。

**リダイレクトは自前で処理する**。
- `redirects(0)` にして、最大 5 回まで追う。
- 各段の送信前に、上の URL の検査、宛先の制限 (§8.3)、参照元を評価し直す。
- 自前で処理する理由: ureq の既定のリダイレクトは、設定した Referer をそのまま次の宛先へ送る (`src/unit.rs:216`)。

**参照元 (Referer)**: ブラウザの既定 (`strict-origin-when-cross-origin`) と同じ規則で、**送る段ごとに**決める。
- 同じ origin なら、ページ URL を送る。
- **送る前に、`SourceURL` から username・password・fragment を必ず取り除く**。これは画像 URL の userinfo を拒否する処理とは別のもの。`SourceURL` 自体に userinfo があると、認証情報が Referer に残ってしまうため。
- 別 origin なら、origin だけを送る (`https://www.example.com/`)。
- https から http へなら、送らない。

2026-10-02 に、参照元を確認する画像サーバーで次を確かめた (確認者: ClaudeCode、`curl`、Cookie なし)。origin だけでも取得できる。

| 送った参照元 | 結果 |
| --- | --- |
| なし | 403 |
| origin のみ | 200 |
| ページ URL | 200 |

※ この節のファイル位置 (`src/...`) は、ローカルの依存ソース ureq 2.12.1 のもの。

### 8.3 宛先の制限 (ブラウザに倣った規則、§11 Q6)

**目的**: 悪意ある外部ページに社内向けの URL を仕込み、その HTML をコピーさせて、利用者の LAN 機器やローカルのサービスへ要求させるのを防ぐ。一方で、社内の開発中サービスなど、**社内のページからは社内の画像を取り込める**ようにする。

規則は、ブラウザの Private Network Access のアドレス区分と順序に倣う。「コピー元のページより内側のネットワークへは行かない」。

これはブラウザと完全に同じではない。ブラウザは実際にページを取得した接続先で判定するが、mIV は `SourceURL` を後から解決し直して判定する。

**アドレスの区分** (外側から順に):

| 区分 | 該当するアドレス |
| --- | --- |
| 公開 | 下記以外 |
| プライベート | 10/8、172.16/12、192.168/16、100.64/10、fc00::/7、リンクローカル (169.254/16、fe80::/10) |
| ローカル | 127/8、::1、198.18/15 (PNA の `local` と同じ) |
| 常に拒否 | 未指定 (0.0.0.0、::)、マルチキャスト、ブロードキャスト |

- IPv4-mapped IPv6 は、中の IPv4 アドレスで判定する (常に拒否の区分も含む)。
- **`localhost` / `*.localhost`** は、末尾のドットを正規化したうえで、名前解決せずにローカルとして扱う。接続先はループバック (127.0.0.1 / ::1) に固定する。`localhost.example.com` のような名前は対象外にする。

**ページの区分**:
- 選択ダイアログを開いたとき、session の開始処理 (worker 上。UI thread では行わない) で `SourceURL` のホストを 1 回だけ解決して決める。
- この名前解決は、宛先の検査を掛けない**素の resolver** で行う。
- 結果は session の不変値として、その session の resolver に閉じ込める (§8.1)。
- 解決したアドレスが複数あるときは、**いちばん外側の区分**を採る。公開とプライベートが混ざっていれば公開。
- 解決に失敗した場合も、公開とみなす。

**取得してよい宛先**:

| ページの区分 | 取得してよい画像のアドレス |
| --- | --- |
| 公開 | 公開のみ |
| プライベート | 公開・プライベート |
| ローカル | 公開・プライベート・ローカル |

**検査のしかた**:
- session の ureq 接続用 resolver (`AgentBuilder::resolver`) で、**実際に接続するアドレス**を上の表で検査する。許可されたアドレスだけを接続へ渡す。
- 事前に別途 DNS を引いて検査する方式は、DNS rebinding で破られるので採らない。
- リダイレクトの各段にも、同じ session の resolver が効く。
- プロキシは使わないので、名前解決は常にこの resolver を通る。
- `data:` URL はアドレスを持たないので、対象外。

**残る抜け道と限界** (許容する):
- **名前解決の操作**: 攻撃者が自分のドメインの名前解決を操作し、ページの区分を決める瞬間だけプライベートやローカルのアドレスを返すと、ページがその区分と判定される。
  - その場合でも、mIV が送るのは Cookie も認証情報も付かない GET だけで、取得結果を外へ送ることもない。
  - 被害は「URL を開くだけで状態が変わる作りの甘い機器・サービス」に限られる。しかも、利用者が選択ダイアログを開いた場合だけ。
  - このため許容する (2026-10-02 利用者と合意)。追加の再検査や再試行の仕組みは足さない。
- **グローバル IPv6 アドレスの社内網**: この区分では公開として扱う。LAN 内のサービスをすべて見分けて守れるわけではない。

### 8.4 一時保存と予算

- 取得したバイト列は `data_dir/tmp/clipboard-capture/<session id>/` に書き、メモリには持たない。
- 予算: ダイアログ 1 つあたり一時保存の合計 2 GiB。超えた分は「上限のため省略」とする。
- 一時フォルダの削除:
  - session の worker と保存処理がすべて終わってから、背景で 1 回だけ削除する。
  - 削除に失敗したら、ログに残す。次回起動時に `data_dir/tmp/clipboard-capture/` を丸ごと消すので、回復処理は持たない。
- 縮小表示は worker が一時ファイルからデコードして作る。
  - **デコードの前に**ヘッダから寸法を読み、§5.4 と同じ上限 (幅・高さ 32768、RGBA 展開 1 GiB) を検査する。
    - 既存のサムネイル生成の上限は形式ごとに違い、WIC は寸法だけで最大 4 GiB の確保を許す ([wic_decoder.rs:219](../src/wic_decoder.rs))。そのため既存の上限には任せない。
  - 上限で拒否したものは、別のデコーダへの fallback で迂回しない。失敗 (「大きすぎます」) として一覧に出す。
  - UI へ渡す縮小画像は件数上限付きの backlog に積み、テクスチャ化は 1 フレームに 1〜2 枚までにする ([ui-responsiveness.md](ui-responsiveness.md) §3)。
- **中身の確認**: 先頭バイトで画像形式を判定する。mIV が扱える画像形式でなければ失敗にする (HTML のエラーページなど)。拡張子もここで決める。

### 8.5 取れない画像

| 状況 | 結果 |
| --- | --- |
| 公開されている画像 | 取れる |
| 参照元を確認する画像 | §8.2 の参照元で取れる見込み |
| 期限付きの署名 URL | 期限内なら取れる |
| ログインが必要な画像 | 取れない。一覧に「取得できませんでした (403)」と出す |
| ボット対策のあるサイト | 拒否されることがある。同上 |
| `blob:` / canvas / CSS の背景画像 | HTML に無い、または取れない。数えない |
| 画面外でまだ読み込まれていない画像 | 遅延読み込み属性が残っていれば拾える (S0 で確認) |
| SNS のタイムライン | 画面付近に描かれている投稿だけ |
| 社内サイト・NAS 上の画像 | 社内のページからなら取れる。外部のページに仕込まれた社内向けの URL は取らない (§8.3) |

## 9. 選択ダイアログ

- メインウィンドウ内の `egui::Window`。`ui_dialogs/` に 1 ファイルで置く。モーダル扱い (§4-3, §4-4)。
- 状態は `Fetching` (取得中・選択中) → `Saving` (保存中) → 閉じる、の一方通行。
- 上部:
  - 出どころ (ドメイン)
  - 取得の進み具合 (N / M)
  - 最小サイズの絞り込み (短辺 px、既定 100)
  - 全選択 / 全解除
- 本体:
  - チェック付きの縮小表示を格子状に並べる。
  - 取得中のものは枠だけを出す。
  - 失敗したものは理由を付けて、選べない状態にする。
  - 最小サイズ以上は、最初からチェック済み (Q4)。
- 同じ内容 (ハッシュ一致) の画像は 1 件にまとめる。
- [保存] を押すと `Saving` に移る。
  - 背景の保存 worker が、選んだものを §2.6 の名前で保存先へ書く。
  - 保存中は進み具合を出す。
  - 終わったら閉じ、メインのトーストで「N 枚保存しました」と出す。失敗があれば、その件数も出す。
- **`Fetching` での [閉じる] / Esc / タイトルバーの ×**: いずれも取り消しになる (§8.1)。
  - Esc は `dialog_escape_pressed` を使う (IME 規則)。
- **`Saving` 中の閉じる操作**: [閉じる] ボタン・Esc・タイトルバーの × を**まとめて拒否**する。
  - `dialog_escape_pressed` は IME の判定しかしないので、Esc も状態を見て無視する。
  - × は `.open(&mut open)` を `Saving` 中に渡さず、表示しない。
  - 保存が終わるまで同じモーダルを保つ。保存を途中で取り消して続きを扱う処理は作らない。

## 10. 保存と記録

### 10.1 保存

- 保存先は §2.7。Ctrl+V から来たときは §11 Q1 に従う。
- 書き込みは、保存先と同じフォルダに `.part` で書いてから rename で確定する。一時保存からは copy → rename。
- 名前が衝突した場合 (同じミリ秒に 2 回など) は、日時部分に `-2`, `-3` … を付けて避ける (`_` より前を変える)。
- 保存したフォルダを表示中なら、通常のフォルダ監視で一覧に出る。専用の更新処理は足さない。
- 複数枚の保存が途中で失敗したら、保存済みの画像は残す。件数と理由を伝え、巻き戻さない (§4-11)。

### 10.2 出どころの記録 (§11 Q3)

**案 A (推奨): Mark of the Web (`Zone.Identifier` 代替データストリーム)**

ブラウザがダウンロードしたファイルに付けるのと同じ形式で、次を書く。

- `ZoneId=3`
- `ReferrerUrl=<ページ URL>`
- `HostUrl=<画像 URL>`

いずれも userinfo と fragment は除く。

「画像をコピー」(画像データ) の場合は、§5.8 の取り方で `HostUrl` と `ReferrerUrl` を決める。取れないものは書かない。

利点:
- 新しい DB が要らない。
- ファイルと一緒に移動する (NTFS の中で)。
- Explorer のプロパティでも見える。

注意点:
- FAT / exFAT へコピーすると消える。これはブラウザのダウンロードと同じ。
- 書けない保存先や書き込み失敗は、ログに残して画像の保存は続ける (§4-11)。
- Windows が画像の表示を妨げることはない。ただしプロパティに「ブロックの解除」が出る。

**案 B: mIV の新しい SQLite (`clipboard_capture.db`)**

保存パスから画像 URL / ページ URL / 取り込み日時を引ける。メタデータパネルに「元ページを開く」を出しやすい。
一方で、ファイルを移動・改名すると対応が切れる。

どちらの案でも、**v1 ではメタデータパネルへの表示は作らない** (記録だけ)。表示は後の段階で、既存のツイート情報パネル
([ui_metadata_panel.rs:5967](../src/ui_metadata_panel.rs) `draw_tweet_panel`) と同じ形で検討する。
どちらも未リリースの新しいデータなので、マイグレーションは要らない。

## 12. 範囲外 (v1)

## 14. テスト

- **形式の判定 (§5.4)** は、形式の集合を入力にした純関数のテストにする。
  - 除外形式
  - 自身の印
  - ファイル類 (`CF_HDROP` / 仮想ファイル)
  - 画像と HTML の両方があるもの
  - S0 で決めた Office の除外
- **reader の状態** (自動):
  - 同じ sequence の重複通知で 1 回だけ処理されること
  - 読み取り前後の sequence 変化で読み直すこと
  - 旧世代の結果が捨てられること
  - 起動前からの内容を取り込まないこと
  - 片方のチェックが ON で動作中に、もう片方を ON にした時点の内容を取り込まないこと (チェックごとの基準 sequence)
  - 両方 OFF の間は要求を読み捨て、thread は残ること
  - 直前と同じ内容を保存しないこと。間にテキストを挟めば保存すること
  - 画像 A を保存 → 監視 OFF → 監視 ON → 画像 A、の順で保存されること (有効化の境界でハッシュが捨てられる)
  - 3 つの sequence が一致しない場合と、世代が古い読み取りで、受理済みの sequence とハッシュが更新されないこと
  - 3 つの sequence が一致しないとき: 新しい要求があればそれを優先すること。無ければ同じスナップショットで 1 回だけ読み直し、なお不一致なら見送ること
  - reader が読めたコピーの並びで「画像 A を保存 → テキスト → A」なら、A が再び保存されること (Q7)。合流でテキストが読まれなかった場合に保存されないのは仕様 (§5.6)
- **寸法の上限**:
  - 巨大な寸法の `PNG` / DIB が、取り込みの入口でメモリ確保の前に拒否されること。
  - **製本の「クリップボードの画像を本に追加」は今の受付範囲のまま**であること (40000×1 の DIB を受け付ける)。
- **取得画像のデコード予算**: 上限を超える寸法の画像が、別デコーダへの fallback なしで拒否されること。
- **自身の印** (§5.7):
  - 印が書かれること。
  - 印の失敗で画像コピーが止まらないこと。
  - 世代が古い書き込みを捨てる既存の約束が保たれること。
- **S0 の記録を fixture にする**: 記録した形式の集合 (Chrome / Edge / Firefox の「画像をコピー」、切り取りツール、Excel / Word / PowerPoint、Explorer、mIV) を判定関数に通し、§5.8 の決定どおりになること。
- **DIB**: 完全透明・部分透明・alpha 未定義を、製本の入口とクリップボード取り込みの入口の両方で確かめる (§5.4 の規則のとおりになること)。
- **CF_HTML**:
  - 正常なもの
  - fragment のオフセットが壊れたもの (印による fallback)
  - context の `<base>`
  - `SourceURL` が無いもの
  - UTF-8 境界
- **候補抽出**:
  - `srcset` から最大のものを選ぶ
  - 受け付けるスキーム
  - 32 px 未満の除外
  - 候補の上限
- **参照元の規則**:
  - 同じ origin / 別 origin / https→http のそれぞれで、規則どおりに送られること。
  - リダイレクトの各段で評価し直されること。
  - `SourceURL` に userinfo がある場合も含め、userinfo と fragment が除かれること。
- **宛先の制限**:
  - ページの区分 3 種 × 宛先の区分 4 種のすべての組み合わせ
  - IPv4 / IPv6 / IPv4-mapped (常に拒否の区分を含む)
  - 198.18/15
  - 複数アドレスの混在 (いちばん外側を採ること)
  - ページの名前解決の失敗
  - リダイレクト先が内側へ向かうもの
  - `localhost` / `*.localhost` / 末尾ドット付き / `localhost.example.com`
  - **session をまたいだ接続の再利用が起きないこと** (社内ページの session の後に、公開ページの session から private へ行けないこと)
- **URL の検査**: userinfo 付きの URL・相対 URL が userinfo を引き継ぐ場合・リダイレクト先の userinfo を拒否すること。禁止ポートの拒否と、開発用ポート (3000 / 8080) の許可。
- **ファイル名**: 生成した名前すべてについて、既存の `filename_stack` の prefix 関数がコピー単位で同じ値を返すこと。
  - ドメインに `_` を含む場合
  - 100 枚以上の場合
  - 衝突回避の `-2` を含む場合
- **取得** (テスト用ローカル HTTP サーバー):
  - 送られた参照元
  - 403
  - リダイレクト
  - 画像でない応答
  - `Content-Length` の無い 64 MiB 超
  - 少しずつ届いて全体の期限を超える応答、ヘッダが遅い応答 (各段に残り時間が渡ること)
  - 取り消し後に worker が終わってから一時フォルダが消えること
  - 同時取得が全体で 4 本を超えないこと
- **選択ダイアログ**:
  - 開ける条件 (§4-3) の判定
  - 両方のモーダル述語への登録
  - `Saving` 中の [閉じる] / Esc / × がすべて拒否されること
  - 移動の準備中は開かないこと
  - ダイアログ中の HTML 検出の無視
- **Ctrl+V (handler-level)**:
  - ファイル類 / 画像 / HTML / どれでもない
  - 無効な一覧での無反応
  - 自動保存の直後の Ctrl+V (手動では保存されること)
  - mIV 自身がコピーした画像の Ctrl+V
  - 仮想ファイル形式が従来の Shell の貼り付けへ渡ること
  - `SourceURL` の無い HTML・候補 0 件でトーストだけ出て、Shell の貼り付けへ戻らないこと
  - 手動では除外形式・Office の除外・自身の印を見ないこと
- **場所▼**: Remote の場所一覧が変わらないこと。
- **idle health**: 監視 ON で小窓が出ていない静止状態で、repaint が増えないこと ([idle-health-check.md](idle-health-check.md))。
- **実機 (利用者)**:
  - 複数ディスプレイでの位置
  - DPI の違う画面への移動
  - ブラウザでの作業中にフォーカスが移らないこと
  - トレイ常駐中・通常の最小化中のクリック
