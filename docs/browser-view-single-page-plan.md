# §1.870 ブラウザから開いた画像が保存先の別の画像と見開きになる件の設計

2026-11-23。設計担当 ClaudeCode。ブランチ `browser-870-single-page` (master `30c5a0e32` から)。独立設計レビュー 5 回目で ACCEPT (`74a76e17a`)。**その後の利用者の判断 (§6) で、保存先のフォルダのページ構成は「覚えない」に変わった。6・7 回目のレビュー (REVISE) の指摘を直し、mIV Remote は利用者の判断で R2 (見開きを選べない) にした。**8 回目のレビューで ACCEPT (`ba4e5025d`)。実装は Codex へ。**
独立設計レビューは 1 回目 (`8d8d6c841`)・2 回目 (`a0dccfd18`) とも REVISE。指摘をこの版で直した (§8)。2 回目の指摘を受けて、範囲を「保存先の根の下」だけに狭め、本扱いの種類を分ける関数は作らない形にした。

## 1. 観測と、コードで確かめた原因

- **観測** (利用者、2026-11-23): メイン PC の v5.6.0 と拡張 0.2.0 で、手引きの 1-4「mIV が起動しているときに続けて開く」を行ったときのこと。ブラウザから開いた画像と、保存先のそれ以外の画像の 2 枚が見開きになることがあった。<kbd>1</kbd> で単ページにすれば問題ない。
  - 観測したときの設定 (統括が利用者の `settings.db`・`spread.db` を読み取りだけで確認、2026-11-23):
    - `auto_fullscreen_zip_pdf = true`、`auto_fullscreen_image_folders = false` なので、(1c) は無効。
    - `apply_default_spread_to_plain_folders = true` (「通常フォルダにも既定のページ構成を使う」が ON)、`default_spread_mode = RtlCover`。
    - `browser_view_output_dir = C:\miv-test-v5\818\images`。
    - `spread.db` には `/miv-test-v5/818/images/2026-11` の行が 1 つある (mode 0 = 単ページ、`SpreadMode::from_int`。flow 0、direction 1)。利用者が <kbd>1</kbd> で単ページにした後の行とみられる。単ページが全体の既定 (RtlCover) と違うので、行が残った。
    - よって、この観測の原因は、下の判定の順番の 2 (「通常フォルダにも既定」が ON) の経路。
- **原因** (コード):
  - ブラウザから開く窓 (`DetachedWindowPurpose::BrowserView`) は、保存先の月のフォルダ (例 `…\mimageviewer\browser\2026-11`) をふつうの物理フォルダとして読み込み、その中の受け取った画像を開く。
  - 単ページ / 見開きの形は、ほかのフォルダと同じ決まりで決まる。BrowserView 用の扱いは無い。
  - 読み込みの既定値は `SpreadRestoreDefaults::for_physical_folder` (`src/app.rs:13752`) が決める。入力の `book_locked` は `physical_page_order_locked` (`src/app.rs:13712`) で、次のどれかなら真になる。
    - (1a) 本棚の製本フォルダ (`is_direct_book_folder`)
    - (1b) コンテナとして開く指定のフォルダ (`is_open_as_container`)
    - (1c) **画像だけのフォルダを本として扱う設定** (`auto_fullscreen_image_folders_enabled()`) が有効で、一覧がすべて画像
      - この設定 (`settings.rs:9799`) は、環境設定の「本の表示モード」が「開いたとき、ページを表示」(`auto_fullscreen_zip_pdf`、または複数ウィンドウのモード) で、かつ「画像のみのフォルダは、PDF/ZIP のように本として扱う」(`auto_fullscreen_image_folders`、既定 OFF) が ON のときに有効になる。
      - ブラウザの保存先の月のフォルダは画像だけなので、この設定が有効なら必ず本扱いになる。
  - 判定の順番:
    1. `book_locked` が真: 全体の既定 `default_spread_mode`。
    2. 「通常フォルダにも既定のページ構成を使う」(`apply_default_spread_to_plain_folders`、既定 OFF) が ON の実フォルダ: `default_spread_mode`。
    3. それ以外: 単ページ (`NON_BOOK`)。
  - そのフォルダに保存行 (`spread.db` の `spreads`、キーはフォルダのパス) があれば、それが既定値に勝つ (`src/app.rs:29365`、`src/spread_db.rs:94`)。
  - したがって、受け取った画像が別の画像と組になるのは次のどれかのときで、ここで尽きる。
    - その月のフォルダに見開きの保存行がある (以前にそこで見開きを選んだ)。全体の既定には関係しない。
    - 保存行が無く、全体の既定が見開きで、次のどれかに当たる。
      - (1c) の設定が有効。
      - 「通常フォルダにも既定のページ構成を使う」が ON。
      - 利用者がその月のフォルダを製本 (1a)、またはコンテナ指定 (1b) にした。
  - 月のフォルダには、前に受け取った関係のない画像が並ぶ。そのため隣の画像と組になる。
- **<kbd>1</kbd> の意味** (`src/ui_fullscreen.rs:47409` `apply_fullscreen_spread_mode`):
  - 表示中のフォルダの保存行を Single に書き換える (`persist_spread_presentation`) 操作で、一時的な切り替えではない。
  - 利用者の回避は、その月のフォルダについては残る。次の月の新しいフォルダでは、また既定に戻る。

## 2. 守ること

- 受け取った 1 枚は、単ページで見えること。関係のない保存済みの画像と組にならないこと。
- 利用者が保存した見開きの設定 (全体の既定、ほかのフォルダの保存行) を変えない。勝手に書き込まない。
- 保存先の根の下の実フォルダでは、ページ構成を覚えない (利用者の判断、§6)。開き直すと、いつも単ページ。
  - その場で見開きを選べば、開いている間は見開きで見られる (デスクトップ。Remote は §4)。
  - 既にある保存行は消さないが、根の下にある間は読まない。
- 決まりは設定とデータから決まり、開いた順番・窓の状態・起動直後の準備の進み具合で変わらない (決定性)。
- UI スレッドで同期 I/O をしない。
- 別ウィンドウ (detached) の述語・viewport・窓の寿命には触れない (凍結の決まり)。

## 3. 案

### 案 A (採用): ブラウザ閲覧の保存先のフォルダは、いつも単ページで開き、ページ構成を覚えない

- **決まり:** 「ブラウザ閲覧の保存先」の根とその下の実フォルダの一覧 (ZIP / PDF などのコンテナは除く) は、ページ構成 (見開き・読む方向・連結) をいつも単ページ (`NON_BOOK`) で開き、**覚えない** (§6 の利用者の判断)。
  - 読み込み: 単ページにする。そのキーの保存行のページ構成 (mode・flow・direction) は読まない。
  - 保存: ページ構成を `spread.db` に書かない (行を足すことも、消すことも、書き換えることもしない)。
  - メタデータの再計算: ページ構成を計算し直さない (読み込みの値、またはその場の選択を保つ)。
  - Remote: 既定の計算は単ページ。保存は書かずに `Unsupported` で知らせる。Remote ではその場の見開きも選べない (R2、§4・§6 の 4)。
- **優先順位:** 保存先の根の下かどうかを、**ほかのどの判定よりも先に**見る。
  1. 保存先の根の下の実フォルダ: 単ページ。本扱い (1a・1b・1c)、「通常フォルダにも既定」の ON、保存行のどれにも関係なく、そうする。
  2. それ以外 (根の外、根の下の ZIP / PDF など): 今までどおり (本扱いなら全体の既定、「通常フォルダにも既定」が ON の実フォルダなら全体の既定、それ以外は単ページ。保存行があれば保存行が勝つ)。
  - 根の下で本扱いの種類を見ない理由 (2 回目のレビューの P2 を受けた単純化):
    - 本扱いの判定 (`physical_page_order_locked`) は、本棚の根を求めるときに既知フォルダの照会 (`SHGetKnownFolderPath`) に届く。保存の側から呼ぶと、UI スレッドの同期の照会になる。
    - 根の下の判定はパスの比較だけで済む。
    - 保存先の月のフォルダを利用者が製本・コンテナ指定にすることは、ふつうは無い。そうした場合も、そのフォルダは単ページで開く。
- **範囲:**
  - 変えるのは、根の下の実フォルダの**ページ構成 (mode・flow・direction) の読み込み・保存・再計算だけ**。本扱い (1c) のほかの効果 (ページ順の固定、画像フォルダを全画面で開く、など) は変えない。`physical_page_order_locked` も変えない。
  - 根の外のフォルダの既定・保存・再計算は、1 か所も変えない。
- **触れる場所:**
  - (a) 読み込み: 保存先の根の下かを判定する関数 (パスの比較だけ) を 1 つ置く。
    - 本体の読み込み (`install_loading_items_inner`、`src/app.rs:44826`。保存行の合成は `apply_spread_for_key_with_document_direction`、`src/app.rs:29365`): 根の下の実フォルダなら、ページ構成を `NON_BOOK` にし、保存行の mode・flow・direction を合成しない (行が無いのと同じ扱い)。
    - Remote の既定の計算 (`src/remote_ipc/container.rs:6884`): 同じく、根の下の実フォルダなら `NON_BOOK` にし、保存行の mode・direction を使わない。
  - (b) 保存: 「その一覧のページ構成を覚えるか」を 1 つの述語にまとめ、ページ構成を覚える操作の入口はすべてこれを通す (6 回目のレビューの P2 2 件)。
    - 述語: 抽出結果の一覧、または根の下の実フォルダの一覧なら「覚えない」。それ以外は「覚える」。
      - 抽出結果の一覧は、今もキーが無いので保存せず (`spread_container_key`)、お気に入りの既定も更新しない (`extracted_result_surface().is_none()` の判定、下の 3 か所)。同じ「覚えない」なので、述語に含めて判定を 1 か所にする。抽出結果の表示の変換 (`extracted_view_mode` など) は、今までどおり `extracted_result_surface()` で決める。
      - 判定はキーのパス、読み込みで運んだ「実フォルダの一覧である事実」、今の設定だけで決まる。本扱いの判定を使わない。
    - デスクトップ: `persist_spread_presentation` (`src/ui_fullscreen.rs:46953`) は、述語が「覚えない」なら `spread.db` に触れず、そのことを型で返す (たとえば `Saved` / `NotRemembered`)。表示中の値はそのまま変える (その場の選択は、開いている間は効く)。
      - 呼び出し元は、「覚えない」のとき、お気に入りの既定 (`update_active_favorite_spread_mode` / `update_active_favorite_reading_flow`) を更新しない。保存先がお気に入りの表示設定の効く場所にあっても、その場の選択が、同じお気に入りの下の別のフォルダの既定に広がらないようにするため。
      - 対象の呼び出し元: 見開きの切り替え (`src/ui_fullscreen.rs:47458`)、連結方式 (`47844`)、読む方向からの見開きの同期 (`sync_spread_mode_from_reading_direction`、`47872`。読む方向の切り替え `47897` と、ページ構成のポップアップ `30778` から呼ばれる)。今の `extracted_result_surface().is_none()` の判定を、この述語に置き換える。
    - Remote: ページ構成を `spread.db` に書く Remote の書き込みは 3 経路ある。どれも、UI の書き込みの振り分け (`src/remote_ipc/ui.rs:2620` 付近) の手前で、同じ述語 (運んだ `is_directory` + 今の設定) で止める。
      - `SetSpread` の通常の経路 (`persist_remote_spread`、`ui.rs:3118`)。
      - `SetSpread` の、表示の分類だけを変える旧経路 (`legacy_view_mode` → `service.set_view_mode`、`ui.rs:2631`)。
      - `SetViewMode` (`ui.rs:2621` → `book_composition/service.rs:944` の `set_mode_only`)。実フォルダにも受理される。
      - 止めたときは、書かずに `Unsupported` と決めた文で返す (§4 の Remote、R2)。
    - **本の構成が表示設定を持つ本** (`composition_owns_view_settings`、`src/ui_fullscreen.rs:47524`。構成が採用済み、または読めない状態) は、述語の対象外にして今までどおり覚える。本の構成は利用者が作ったデータなので (`book_composition_runtime.rs:606`・`625` の書き込みは変えない)。
      - `ProjectionRecipe::Book` 全体を除外しない (7 回目のレビューの P2)。`Book` には、自動の本扱いの `ImageFolder` と製本フォルダの `CompiledFolder` も入る (`src/app/book_materialization.rs:814`)。これらは本の構成の対象外 (`book_materialization.rs:48`) で、根の下では「覚えない」のまま。
      - 読み込みで運ぶ「実フォルダの走査による一覧」という事実は、表示の分類 (`Book` かどうか) では変えない。除外は、述語の側で `composition_owns_view_settings` を見て行う。
      - Remote: 既存の構成の受理の検証 (`composition_admission`、`src/remote_ipc/ui.rs:2603`) は今のまま保つ。止める対象は、振り分けの手前 (`ui.rs:2620`) で、運んだ `is_directory` と今の根だけで決める。追加の状態は持たない。
        - `composition_admission` は、表示設定を構成が持つかの判定とは同じではない (`SetViewMode` は構成付きの本でも空になり得る、`container.rs:3420`。空の受理の検証の成功は、構成が表示設定を持つことを意味しない、`book_composition/permission.rs:291`)。そのため、除外の判定には使わない (8 回目のレビューの P3)。
        - 今のコードでは、実フォルダは本の構成の採用の対象外なので、`is_directory` と根だけで決めても、デスクトップの除外と食い違わない。
    - メタデータの取り込み (`metadata_transfer.rs:6401`) は、利用者が明示した移送で、表示の操作ではない。変えない。根の下のフォルダへ取り込んだ行は消えずに残り、根の下にある間は読まない (下の「保存行の扱い」)。
  - (c) メタデータの再計算 (`src/app.rs:51073`): 根の下の実フォルダでは、ページ構成 (mode・flow・direction) の再計算をしない。読み込みで決まった値、またはその後にその場で選んだ値を保つ。
    - 再計算すると、保存しないその場の選択を、取り込みの完了で単ページへ戻してしまうため。
    - 同じ再計算の中の、ほかの値 (末尾の表紙・端の単独ページ・単独ページの指定・表示の切り抜き) は今までどおり取り込む。
    - 根の外は、今の計算をそのまま保つ。
- **窓の経路への影響:** 無い。
  - フル機能のモード (linked 窓) では、メインの App が月のフォルダを読み込む。そのときの値が単ページになるだけ。
  - 複数ウィンドウのモードでも、fork はその値を写すだけ (`viewer_context_registry.rs:5186`)。
  - 窓を閉じたときの復元、次の画像が届いたときの掛け直し、保存の漏れ止め、どれも要らない。BrowserView の述語を新しく読まない。
  - 保存しないのは、窓の種類ではなく、保存するキー (根の下の実フォルダ) で決める。メインウィンドウから同じフォルダを開いても同じ。
- **メインウィンドウとの一貫性:** 場所▼の「ブラウザ閲覧」から月のフォルダを開いて全画面にしても、同じく単ページ。窓とメインの一覧で形が食い違わない。
- **前後の画像への移動:** 今までどおり移れる。移っても単ページのまま。新しい制限は足さない。

### 案 B: BrowserView の窓だけ、表示を常に単ページにする (保存行も無視)

- 窓の用途 (`BrowserView`) を見て、表示の形だけ単ページにする。設定値と表示値を分ける。
- **退けた理由** (状態の組み合わせが大きく増える。CLAUDE.md「設計の簡素化」):
  - フル機能のモードでは、BrowserView の窓がメインの App と `spread_mode` を共有している。一時的に Single を入れると、次の処理がすべて要る。
    - 窓を閉じた・置き換えた・F11 / park したときに戻す。
    - フォルダの読み直し (`src/app.rs:45065`、`51073`) の後に掛け直す。
  - 保存の漏れが 4 経路ある (`ui_fullscreen.rs:47834`・`47892`・`30778`、お気に入り表示中の既定の書き換え `settings.rs:9718`)。
  - 「設定値と表示値を分ける」形にすると、`spread_mode` を読む全画面の処理すべてに、窓の用途の判定が入る。detached の述語を表示の主経路へ持ち込むことになる。
  - 利用者が保存先で選んだ見開きを、その場でも効かなくする (案 A では、開いている間は効く)。

### 案 C: 受け取った 1 枚だけを見せ、前後へ移れなくする

- 退けた。窓に新しい制限を足すことになり、今できる「保存済みの画像を見返す」がなくなる (リリース済みの挙動の退行)。

## 4. 案 A の細部

- **保存先の根:**
  - 環境設定の「ブラウザ閲覧の保存先」(`settings.browser_view_output_dir`) が指定されていればそれ。無ければ既定 (ピクチャ\mimageviewer\browser)。
  - 根自身とその下を対象にする。比べ方は既存のパス比較 (`folder_tree::path_eq` と同じ、大小無視の component 比較)。
- **既定の根の求め方 (P2、初期化の境界):**
  - 既定の根は、ピクチャの既知フォルダに `mimageviewer\browser` を足して作る。`SHGetKnownFolderPath(FOLDERID_Pictures, KF_FLAG_DONT_VERIFY)` を使う。`KF_FLAG_DONT_VERIFY` は存在の確認をしない旗で、今の `KF_FLAG_DEFAULT` は存在の確認が残る。
  - **UI が動き出す前に 1 回だけ求めて保持し、判定は保持した値だけを読む。** 置き場所は `run()` の中 (`src/lib.rs`)。worker・二重起動などで抜ける分岐を通った後で、Remote reader の起動 (`src/lib.rs:1959` 付近) より前に置く。portable・`--data-dir`・test-script の GUI の起動でも行う。登録できるかどうかの条件では外さない。
    - 判定の側からは照会しない。照会の完了を待つ経路も作らない。
    - 照会に失敗したとき (ピクチャを解決できない) は、既定の根なしとして保持する。そのときは、明示の保存先だけが対象。
  - 登録の側 (`browser_integration::backend::Environment::capture`) の既定の保存先も、同じ関数から作る (綴りを 1 か所にする)。登録の側は今までどおり worker で呼ぶ。
    - 登録の側の `pictures_dir()` は、ピクチャのフォルダが無いと `USERPROFILE\Pictures` に代える。この代替とだけは食い違い得る。
    - まれな環境なので割り切る。そのときはふつうのフォルダの決まりに従うだけで、データは変わらない。
- **連携が OFF のとき:** 判定は連携の ON / OFF に関係なく、保存先の根で行う。OFF にした後も、以前に受け取った画像のフォルダは同じ形で見える。
- **保存先を変えたとき:**
  - 読み込みの単ページは、次の通常の読み込みから新しい根で決まる。
  - 保存しない判定は、変えた直後 (読み込み直す前) から新しい根で決まる。
  - 前の根は対象から外れ、前の保存先に残った画像のフォルダは、ふつうのフォルダの決まりに戻る。
  - 新しい根の下に、利用者が前に保存した行のあるフォルダがあれば、根の下にある間は読まない。根から外せば、また効く。行は消さないので、何も失われない。
- **保存行の扱い (「覚えない」、§6 の 3):**
  - 読み込みの既定値は `spread.db` に書かない。既存のテスト `plain_folder_spread_install_uses_scan_and_does_not_persist_defaults` と同じ契約。
  - 根の下の実フォルダでは、ページ構成を保存しない (§3 (b))。

    - 行は消さない (利用者のデータを、決まりを理由に消さない)。根を変えて外れたフォルダでは、また効く。
    - 一括の書き換え・移行は無い。
  - 同じ行に入る、ページ構成以外の値 (末尾の表紙・端の単独ページ・単独ページの指定) の保存と読み込みは変えない。
    - どれも見開きのときだけ効く値で、根の下では開き直すといつも単ページなので、表示には出ない。
    - 保存を止める入口をこれ以上増やさないため、触れない。
  - BrowserView の窓で開いている間に次の画像が届き、一覧を読み直したときも、単ページに戻る (読み込みの決まりどおり)。
  - ページ構成を覚える表示の操作の入口は、本番のコードでは `persist_spread_presentation` と Remote の 3 経路 (§3 (b))。本の構成の書き込みと、メタデータの取り込みは対象外 (§3 (b))。`set_presentation_state` を呼ぶほかの箇所は、テストのデータの準備。本・ZIP・抽出結果の一覧は、`persist_spread_presentation` の中の `spread_container_key` (`src/app.rs:29236`) でキーが決まる。抽出結果の一覧はキーが無いので保存しない。ZIP / PDF などのコンテナは、根の下に置かれていても対象にしない (今までどおり本の既定)。対象は根の下の実フォルダの一覧だけ。
  - **実フォルダかどうかは、読み込みのときに確定した事実を保存まで運んで決める** (3 回目のレビューの P2)。保存の側で、キーの形や拡張子から推定しない。stat もしない。
    - `spread_container_key` の分岐 (抽出結果 / `zip_nav` あり / それ以外) は区別に使えない。「それ以外」には PDF なども入る。
    - Remote の `RemoteSubresource::File` も、実フォルダ・ZIP のルート・PDF のどれにも使われる (`container.rs:3536`・`6584`)。
  - 本体: 読み込み (`install_loading_items_inner`) で、「保存キー + そのキーが実フォルダの一覧であるという事実」を、その context の状態として持つ。**根の下かどうかは持たない** (4 回目のレビューの P2)。

      - 保存先を変えた直後に、読み込み直す前の一覧で保存すると、両者が違い得る。
      - 新しく根の下になったフォルダ: 書かない。次の読み込みで単ページになるので、次の読み込みの結果と合う。
      - 根から外れたフォルダ: 今までどおり書く。次の読み込みでは、ふつうのフォルダの決まりと保存行で開くので、保存した結果が保たれる。
    - 既に受理した走査 (`folder_signature`) と読み込み元の種類から決める。今の既定の計算と同じ入力。
    - 保存 (`persist_spread_presentation`) は、保存するキーがその状態のキーと同じで、かつ今の設定で根の下のときだけ、ページ構成を書かない。メタデータの再計算 (§3 (c)) も、同じ状態と同じ判定で、ページ構成の再計算を止める。

    - 既存の `folder_observation` (受理した走査の元と世代) は、メインの context だけが持つ (`folder_observation_allowed`、`src/app.rs:27693`)。複数ウィンドウのモードの fork した context では使えないので、使わない。
    - 新しい状態は context の bundle の入れ替えの対象 (`viewer_context_registry.rs` の `swap_field!`) に足す。fork (`split_materialized_physical_context_payload`) では、`spread_mode` と同じく写す。viewer context 監査 (A4 など) の許可が要るかは、実装のときに監査を流して確かめる。
  - Remote: 既存の worker の書き込みの検証で、すでに `is_directory` を得ている (`container.rs:3536`)。その値を `RemoteWritePayload` に保持し、既存の queue → `ClaimedRemoteWrite` → UI の保存 (`session.rs:1155`) へ運ぶ。根の下かどうかは、保存のときの設定とパスで決める。追加の stat は要らない。
    - Remote の読み込みの側 (既定の計算) は、走査の元 (`SpreadDefaultSource::Directory`) から実フォルダかが分かる。
