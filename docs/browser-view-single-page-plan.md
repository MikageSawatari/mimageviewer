# §1.870 ブラウザから開いた画像が保存先の別の画像と見開きになる件の設計

2026-11-23。設計担当 ClaudeCode。ブランチ `browser-870-single-page` (master `30c5a0e32` から)。実装は未着手。

## 1. 観測と、コードで確かめた原因

- **観測** (利用者、2026-11-23): メイン PC の v5.6.0 と拡張 0.2.0 で、手引きの 1-4「mIV が起動しているときに続けて開く」を行ったときのこと。ブラウザから開いた画像と、保存先のそれ以外の画像の 2 枚が見開きになることがあった。<kbd>1</kbd> で単ページにすれば問題ない。
  - 利用者の設定の値と、保存先の月のフォルダの保存行は未確認。どちらが当てはまったかは §6 の質問 0 で確かめる。
- **原因** (コード):
  - ブラウザから開く窓 (`DetachedWindowPurpose::BrowserView`) は、保存先の月のフォルダ (例 `…\mimageviewer\browser\2026-11`) をふつうのフォルダとして読み込む。その中の受け取った画像を開く。
  - 単ページ / 見開きの形は、ほかのフォルダと同じ決まりで決まる。BrowserView 用の扱いは無い。
  - 読み込みの既定値は `SpreadRestoreDefaults::for_physical_folder` (`src/app.rs:13752`) が決める。上から順に判定する。
    1. 本として固定されたフォルダ: 全体の既定 `default_spread_mode`。
    2. 「通常フォルダにも既定のページ構成を使う」(`apply_default_spread_to_plain_folders`、既定は OFF) が ON の実フォルダ: `default_spread_mode`。
    3. それ以外: 単ページ (`NON_BOOK`)。
  - そのフォルダに保存した行 (`spread.db` の `spreads`、キーはフォルダのパス) があれば、それが既定値に勝つ (`src/app.rs:29365`、`src/spread_db.rs:94`)。
  - 受け取った画像が別の画像と組になるのは、次のどれかのときに限られる。
    - 「通常フォルダにも既定のページ構成を使う」が ON で、全体の既定が見開き。
    - その月のフォルダで、以前に見開きを選んで保存した。
    - そのフォルダが本として固定されている。
  - 月のフォルダには、前に受け取った関係のない画像が並ぶ。そのため隣の画像と組になる。
- **<kbd>1</kbd> の意味** (`src/ui_fullscreen.rs:47409` `apply_fullscreen_spread_mode`):
  - 表示中のフォルダの保存行を Single に書き換える (`persist_spread_presentation`) 操作で、一時的な切り替えではない。
  - 利用者の回避は、その月のフォルダについては残る。次の月の新しいフォルダでは、また既定に戻る。

## 2. 守ること

- 受け取った 1 枚は、単ページで見えること。関係のない保存済みの画像と組にならないこと。
- 利用者が保存した見開きの設定 (全体の既定、ほかのフォルダの保存行) を変えない。勝手に書き込まない。
- 決まりは設定とデータから決まり、開いた順番や窓の状態で変わらない (決定性)。
- 別ウィンドウ (detached) の述語・viewport・窓の寿命には触れない (凍結の決まり)。触れずに済む案を優先する。

## 3. 案

### 案 A (推奨): ブラウザ閲覧の保存先のフォルダは、ページ構成の既定を単ページにする

- **決まり:** 「ブラウザ閲覧の保存先」とその下の月のフォルダを読み込むとき、既定値を判定 3 (`NON_BOOK`、単ページ) にする。「通常フォルダにも既定のページ構成を使う」が ON でもそうする。
- **変わらないもの:**
  - そのフォルダに保存行があれば、今までどおり保存行が勝つ。利用者がそこで <kbd>2</kbd> などを選んだら、それを覚えて従う。明示の選択なので尊重する。
  - 本として固定したフォルダ (判定 1) も、今までどおり全体の既定。保存先を本として固定するのは利用者の明示の操作なので、変えない。
- **触れる場所:** `SpreadRestoreDefaults::for_physical_folder` に「ブラウザ閲覧の保存先の下か」の入力を 1 つ足し、判定 2 の前で単ページにする。
  - 呼び出し元は 3 か所。すべてに同じ入力を渡す。
    - `install_loading_items_inner` (`src/app.rs:44826`)
    - メタデータの取り込み完了の再計算 (`src/app.rs:51088`)
    - Remote の既定の計算 (`src/remote_ipc/container.rs:6888`、`reading_settings` から)
- **窓の経路への影響:** 無い。
  - フル機能のモード (linked 窓) では、メインの App が月のフォルダを読み込む。そのときの値が単ページになるだけ。
  - 複数ウィンドウのモードでも、fork はその値を写すだけ (`viewer_context_registry.rs:5186`)。
  - 窓を閉じたときの復元処理、次の画像が届いたときの掛け直し、保存の漏れ止め、どれも要らない。BrowserView の述語を新しく読まない。
- **メインウィンドウとの一貫性:** 場所▼の「ブラウザ閲覧」から月のフォルダを開いて全画面にしても、同じく単ページになる。BrowserView の窓とメインの一覧で形が食い違わない。
- **前後の画像への移動:** 今までどおり移れる。移っても単ページのまま (フォルダの形が単ページなので)。新しい制限は足さない。

### 案 B: BrowserView の窓だけ、表示を常に単ページにする (保存行も無視)

- 窓の用途 (`BrowserView`) を見て、表示の形だけ単ページにする。設定値と表示値を分ける。
- **退けた理由** (状態の組み合わせが大きく増える。CLAUDE.md「設計の簡素化」):
  - フル機能のモードでは、BrowserView の窓がメインの App と `spread_mode` を共有している。一時的に Single を入れると、次がすべて要る。
    - 窓を閉じた・置き換えた・F11 / park したときに戻す処理。
    - フォルダの読み直し (`src/app.rs:45065`、メタデータの取り込み完了 `51073`) の後に掛け直す処理。
  - 保存の漏れが 4 経路ある。窓の中で 6 / 7 キーや見開きのポップアップを使うと、一時的な Single が月のフォルダの保存行に書かれる (`ui_fullscreen.rs:47834`・`47892`・`30778`、お気に入り表示中の既定の書き換え `settings.rs:9718`)。
  - 「設定値と表示値を分ける」形にすると、`spread_mode` を読む全画面の処理 (ペアの解決・ページ送りの歩幅・先読み・ジャンプなど) すべてに、窓の用途の判定が入る。detached の述語を表示の主経路へ持ち込むことになり、凍結の決まりの点でも重い。
  - 利用者が保存先で明示的に見開きを選んだ場合も上書きしてしまう。

### 案 C: 受け取った 1 枚だけを見せ、前後へ移れなくする

- 退けた。窓に新しい制限 (ページ送りの禁止) を足すことになり、今できる「保存済みの画像を見返す」がなくなる (リリース済みの挙動の退行)。単ページの問題は案 A で消える。

## 4. 案 A の細部

- **保存先の根 (どこより下を対象にするか):**
  - 環境設定の「ブラウザ閲覧の保存先」(`settings.browser_view_output_dir`) が指定されていればそれ。無ければ既定 (ピクチャ\mimageviewer\browser)。
  - その根自身と、その下のフォルダを対象にする。比べ方は既存のパス比較 (`folder_tree::path_eq` と同じ大小無視の component 比較) で行う。
- **既定の根の求め方 (UI スレッドの I/O と決定性):**
  - 既定の根は、ピクチャの既知フォルダから作る。今の `known_folders::pictures_dir()` は `is_dir()` で存在を確かめるので、UI スレッドからは呼ばない。
  - 対象の判定には存在の確認は要らない。`SHGetKnownFolderPath` で得たパス (存在を確かめない版) を、プロセスで 1 回だけ求めて保持する。登録の側 (`browser_integration::backend::Environment::capture`) が使う既定と同じ関数から作り、綴りを 1 か所にする。
  - 起動直後の順番に左右されない。登録の準備 (worker) の完了を待たない。
  - ピクチャのフォルダが無く、登録の側が `USERPROFILE\Pictures` への代替を使った場合は、根が食い違う。まれな環境なので割り切る (その場合はふつうのフォルダの決まりに従うだけで、壊れない)。
- **連携が OFF のとき:** 判定は連携の ON / OFF に関係なく、保存先の根で行う。OFF にした後も、以前に受け取った画像のフォルダは同じ形で見える。ON / OFF で形が変わらない。
- **保存先を変えたとき:** 新しい根が対象になり、前の根は対象から外れる。
  - 前の保存先に残った画像のフォルダは、ふつうのフォルダの決まりに戻る。
  - 保存行は書かないので、戻しても何も失われない。
- **保存:** 既定値を変えるだけで、`spread.db` には書かない。既存のテスト `plain_folder_spread_install_uses_scan_and_does_not_persist_defaults` と同じ契約。
- **Remote:**
  - Remote も同じ `for_physical_folder` で既定を計算している (`src/remote_ipc/container.rs:6884`)。保存先の根を `reading_settings` に足して、同じ判定を渡す。
  - 揃えないと、Remote で月のフォルダを開いたときだけ見開きになる。
  - 設定の受け渡しの版 (IPC) が変わるかは、実装の前に確かめる。
- **公開文書:** マニュアルの「ブラウザ連携」の「保存先と『ブラウザ閲覧』」に 1 文足す。「保存先のフォルダは、『通常フォルダにも既定のページ構成を使う』が ON でも単ページで開きます。見開きにしたい場合は、そのフォルダで見開きを選ぶと覚えます。」の形。設定リファレンスの「通常フォルダにも既定のページ構成を使う」にも、例外として 1 文。

## 5. テスト (実装時)

- `for_physical_folder` の表の単体テスト:
  - 保存先の根の下 × 「通常フォルダにも既定」ON / OFF × 本の固定の有無。
  - 根の外のフォルダは、今までどおりの結果になること。
- インストールの状態遷移テスト:
  - 「通常フォルダにも既定」ON・全体の既定が見開きのとき、保存先の月のフォルダを読み込むと `spread_mode == Single` になる。
  - `spread.db` に行が書かれないこと。
  - 保存行 (見開き) があるときは見開きになること。
- 既存の browser818 のテスト (フル機能 / 複数ウィンドウの両経路) で、受け取った画像が単ページで開くこと:
  - フル機能では、メインの App の `spread_mode` が Single。
  - 複数ウィンドウでは、fork した context の `spread_mode` が Single。
  - 窓の経路のコードは変えない。
- 環境設定の保存先を変えたときに、新しい根で判定されること。
- Remote の既定を揃える場合は、その計算のテストも足す。
- 実機確認 (利用者): 「通常フォルダにも既定」ON・全体の既定が見開きの状態で、手引きの 1-3〜1-4 と同じ操作をして、毎回単ページで開くこと。

## 6. 利用者に決めてもらうこと (推奨を先頭に)

0. (確認) 観測した時点の設定の値。
   - 確かめたいこと: 「通常フォルダにも既定のページ構成を使う」が ON で、全体の既定が見開きだったか。月のフォルダで以前に見開きを選んだ (保存行がある) か。
   - 案 A が直すのは前者で、後者は利用者の明示の選択として残る。
   - 統括が、利用者の `settings.db` と `spread.db` を読み取りだけで確かめられるなら、質問は不要。
1. 直し方:
   - **(推奨) 案 A**: 保存先のフォルダは既定を単ページにする。そこで見開きを選んだら、それを覚えて従う。
   - 案 B: ブラウザから開いた窓だけ、常に単ページ (そのフォルダで選んだ見開きも無視する)。窓を閉じたときの戻し方や保存の漏れ止めが要り、手間と不具合の余地が大きい。
2. 前後の画像への移動:
   - **(推奨) 今までどおり移れる**。移っても単ページ。
   - 受け取った 1 枚だけを見せ、移れなくする。今できる「見返す」が無くなる。
3. 保存先のフォルダで見開きを選んだ場合:
   - **(推奨) 覚えて従う** (案 A のまま)。
   - 保存先のフォルダでは見開きを選んでも覚えない。

## 7. 凍結の決まりとの照合

- 案 A は、別ウィンドウの述語 (`DetachedWindowPurpose`・linked / independent)・viewport・窓の寿命・placement に触れない。変えるのはフォルダの読み込み時の既定値の計算だけ。
- 窓の種類で分岐する処理を足さない。症状を消す guard / delay / retry / 一括 reset / silent fallback ではない。
- 原因 (関係のない画像が並ぶフォルダに、本と同じ見開きの既定を当てていた) に対応する。
- それでも §1.818 の窓で見える問題なので、独立レビューで「症状パッチではなく構造的な修正 (または detached の経路に触れない修正)」であることへの合意を取り、[detached-rework-plan.md](detached-rework-plan.md) §11 に記録する。
