# §1.250 「常に最前面」Stage A 設計 / Stage B 実装

## 2026-09-27 VST editor 前面からの HUD 操作

ON 時に VST editor 内をクリックしてから HUD の VST ボタンを押すと、editor だけが消え、
動画の右上 1/4 表示と VST パネルが残る報告を受けた。source 調査では bridge-process editor を
presenter 復旧が外部 foreground と誤分類し、HUD down も presenter focus を無条件要求していた。
登録済み可視 editor HWND と bridge PID を共有分類に使い、editor から HUD への down では
focus 要求と presenter raise を起こさない。bridge の別 popup と本当の外部アプリは区別し、
外部アプリからの復旧を維持する。presenter touch は editor 前面でも focus claim を維持し、
editor の HWND/PID 登録と bridge PID 集合は不変 snapshot を一回で公開し、公開準備中も直前の完全な
snapshot で HUD focus を分類する。登録済み editor からの HUD 操作では claim を抑え、
presenter が owner の可視 popup でも未登録なら抑止しない。
OS 上の実際の hide/occlusion と mouse-up 到達は未測定なので、
VST ボタン操作に限定した通常ログで HWND owner/可視/topmost/iconic と down/up/toggle を観測する。
headless の pump/App テストは window level ごとの実際の順序を再現しない。smoke copy には
VST bridge がない。この事象の ON/OFF での editor 可視性・パネル・compact layout の同期は、
ユーザーが通常 profile の確認 build で実機確認済み。ON 固有の z-order はこの実機確認に基づく。

作成・改訂: 2026-09-27 / Codex。Stage A の設計は独立レビューの指摘を反映済みで、Stage B の製品コードと smoke シナリオを実装した。実アプリ smoke は設計 owner による実行待ち。対象は mIV の main と閲覧用 top-level host。設定既定 OFF、明示 ON の間だけ host を topmost にする。切替自体は activation を要求しない。仕様は [backlog §1.250](next-release-backlog.md#L438)。

## 2. 状態と適用境界

1. 唯一の希望状態は `Settings.always_on_top: bool`。`#[serde(default)]` / `Default=false` とし、`App`、window runtime、context bundle に同義 flag を追加しない。`Settings` は serde object として `settings_kv` に書かれ、欠けた key は serde default で復元できる。[`src/settings.rs:3996`](../src/settings.rs#L3996), [`src/settings.rs:4194`](../src/settings.rs#L4194), [`src/settings_db.rs:927`](../src/settings_db.rs#L927), [`src/settings_db.rs:1971`](../src/settings_db.rs#L1971), [`src/settings_db.rs:2893`](../src/settings_db.rs#L2893)。新機能の key 自体は未出荷なので DB schema migration は不要。既存 `SCHEMA_VERSION=1` も変更しない。[`src/settings_db.rs:48`](../src/settings_db.rs#L48)。旧 `settings.json` からの移行でも欠損時は OFF。保存/読込 roundtrip と欠損 key のテストを用意する。
2. `bool -> WindowLevel::{AlwaysOnTop, Normal}` を共通 helper で決める。root の起動 builder、fullscreen builder（inactive 分岐も）、active detached builder、passive/parked builder の**すべて**に明示的に `.with_window_level(level)` を渡す。`None` に戻しても既存窓は解除されないため OFF は `Normal` を送る。egui の builder diff は値が変わると `ViewportCommand::WindowLevel` を発行する。[`vendor/egui/src/viewport.rs:632`](../vendor/egui/src/viewport.rs#L632), [`vendor/egui/src/viewport.rs:804`](../vendor/egui/src/viewport.rs#L804), [`vendor/egui/src/viewport.rs:908`](../vendor/egui/src/viewport.rs#L908)。root 起動前は `saved` を使い、App 開始後は `self.settings` を使う。
3. 切替入口はメニューと `KeyAction` から一つの `App::set/toggle_always_on_top(ctx, ...)` に集める。ここで `self.settings` を変更し、**root のみに**明示 `ViewportCommand::WindowLevel(level)` を送る。root は起動時 builder の後、通常 frame で再登録する builder がない。一方、既存の fullscreen / detached egui host には toggle fanout を送らず、次の host builder diff を唯一の command 発行者にする。メニュー描画は子 host 登録より後なので、menu toggle は root repaint を要求して次 pass の child builder diff へ届ける。[`src/app.rs:77462`](../src/app.rs#L77462), [`src/app.rs:77468`](../src/app.rs#L77468), [`src/app.rs:77730`](../src/app.rs#L77730)。子 host からのキー切替も同じ希望状態を更新し、次の root pass で各 builder が追従する。`AtRest` context など HWND が無い相手には command を送らず、生成時 builder で設定を得る。active detached ID が `detached_image_windows` にもある期間は **active session が登録を所有し、同 ID の passive/parked 登録は行わない**。active が host を譲る handoff 後は passive/parked builder が所有する。一つの ViewportId に一つの builder を登録する ownership とし、現行経路で両方が同 frame に登録され得るならその境界を修正する。二重送信を最後で消す guard は置かない。[`src/ui_fullscreen.rs:17230`](../src/ui_fullscreen.rs#L17230), [`src/ui_fullscreen.rs:19427`](../src/ui_fullscreen.rs#L19427), [`src/ui_fullscreen.rs:21921`](../src/ui_fullscreen.rs#L21921)。root のみ、F12 active、複数 parked、fullscreen 別 viewport を同時に扱う。永続化は既存の通常終了 / tray 格納時の `persist_window_state_and_flush` に載せ、toggle のたびに新しい同期 DB 書込を UI thread へ足さない。[`src/app.rs:63287`](../src/app.rs#L63287), [`src/app.rs:63353`](../src/app.rs#L63353), [`src/tray_integration.rs:342`](../src/tray_integration.rs#L342)。
4. 再生成・placement switch は生成時 builder が level を継承する。active/loading/holdover/cleanup と passive/`ParkedLive` の全 builder 入口をテストで列挙し、直接作る例外を残さない。[`src/ui_fullscreen.rs:21615`](../src/ui_fullscreen.rs#L21615), [`src/ui_fullscreen.rs:22542`](../src/ui_fullscreen.rs#L22542), [`src/ui_fullscreen.rs:26778`](../src/ui_fullscreen.rs#L26778), [`src/ui_fullscreen.rs:27000`](../src/ui_fullscreen.rs#L27000)。通常最小化→復元、tray hide/restore、fullscreen 再表示と detached 復帰の各経路で **まず実アプリ style probe を測る**。`Minimized(false)` / `Visible(true)`、root `ShowWindow`、`sync_after_restore` は既存経路だが、現時点で再 assert は仕様化しない。[`src/app.rs:51743`](../src/app.rs#L51743), [`src/tray_integration.rs:355`](../src/tray_integration.rs#L355)。希望 level と `WS_EX_TOPMOST` が食い違った復帰 edge だけで、担当 host へ `WindowLevel(level)` を再送する。その edge で builder diff も送る場合は発行 ownership を一本化し、同じ ViewportId に 1 command とする。常時 Win32 `SetWindowPos` 連射や新しい detached lifecycle flag は作らない。
5. 既存 window activation 用 `Focus`、tray Open の `SetForegroundWindow`、native presenter の表示/raise は今回の設定変更入口から呼ばない。[`src/tray.rs:478`](../src/tray.rs#L478), [`src/app.rs:51751`](../src/app.rs#L51751), [`src/video/native_window.rs:1085`](../src/video/native_window.rs#L1085)。winit 0.30.13 の Windows `set_window_level` は `HWND_TOPMOST/HWND_NOTOPMOST` と `SWP_NOACTIVATE` で実装される（Cargo registry `winit-0.30.13/src/platform_impl/windows/window_state.rs:339-357`）。ただし同時期の placement/restore が別途 activation する可能性を分けて実測する。topmost 切替そのものは `WindowLevel` だけを発行し、前面アプリ/foreground HWND を変えない。
6. 環境設定ダイアログは `Settings` snapshot を OK 時に全体差し替えする。非環境設定 field は `overwrite_non_preferences_from(live)` で最新値へ移す設計なので、新 field をここへ追加して、ダイアログを開いたままメニュー/キーで切替後に OK しても巻き戻さない。[`src/ui_dialogs/preferences.rs:1861`](../src/ui_dialogs/preferences.rs#L1861), [`src/ui_dialogs/preferences.rs:2388`](../src/ui_dialogs/preferences.rs#L2388), [`src/settings.rs:9650`](../src/settings.rs#L9650)。

## 5. Stage B の実測で決める問い

1. **fullscreen native の実機 z-order**: root topmost 化は owner rule で borderless presenter へ伝播する見込みだが、既存の fullscreen egui host、native presenter、HUD/VST が同時にある実機配置で順序を確認する。root の WindowLevel 切替が presenter を覆う場合は、native window pump の所有境界で最小の順序調整を再設計し、Focus/foreground や UI thread からの presenter `SetWindowPos` は使わない。
2. **restore の reassert 境界**: 通常 minimize/restore、tray restore、fullscreen / detached 復帰の各 probe で topmost style が保持されるなら追加 command は不要。失われる機種/遷移があれば native/egui の具体的な復帰イベントを測定して、同一 desired level をその境界だけで再送する。別の runtime bool は作らない。

   2026-09-26 の disposable smoke では root の最小化中・復元後とも `WS_EX_TOPMOST=true` を確認した。この経路の再送は不要。
   **2026-09-27 06:32 の run (`target/ui-smoke-runs/20260926T213201504Z-172208-AlwaysOnTop-c4f9fe8e`、PASS) で決着**:
   root と独立 detached 2 窓は tray 格納・復帰後も topmost を保持し、同一 profile での再起動後も ON が復元された。
   **測定した restore 経路 (root 最小化/復元、tray 復帰) では再送を追加しない。**
3. **旧 `DetachedWindow` fallback（Stage B 静的確認済み）**: 現行 App の `viewer_presentation_to_native_video_placement` は `MainWindowChild` / `FullscreenBorderless` / `DetachedViewerChild` だけを生成し、`native_video_target_for_presentation` と host-claim 経路もこの変換を使う。[`src/app.rs:50645`](../src/app.rs#L50645), [`src/app.rs:50994`](../src/app.rs#L50994)。`NativeVideoPlacement::DetachedWindow` の残存参照は video 層の受け側とテスト、および `#[cfg(test)]` の逆変換であり、現行製品 App からは到達しない。新規 production producer が見つかった場合だけ ownerless presenter policy を再審査する。
