# 編集用追加パック ダウンロード仕様

Status: Draft / miV 本体マージ後に実装予定
Date: 2026-06-05

この文書は、吹き出し・テキスト・オノマトペ機能と、補正レイヤーの被写体分離モデルを
本体 exe へ常時同梱せず、初回利用時にまとめて追加ダウンロードするための仕様メモ。

## 1. 結論

編集系の大きな追加ファイルは、TensorRT pack とは分けて **編集用追加パック** として扱う。

- 本体には、オノマトペ用 OFL フォントや被写体分離 ONNX モデルを原則入れない。
- 初めて「補正レイヤー」または「吹き出し / テキスト / オノマトペ」へ入った時点で、
  追加パックのダウンロード確認モーダルを出す。
- ダウンロードは 1 回で済ませる。フォントだけ、AI モデルだけ、と細かく分割しすぎない。
- TensorRT は利用者が一部で、サイズも大きいので別 pack のままにする。
- ユーザーがキャンセルした場合も基本 UI は開けるが、追加ファイルが必要な機能は無効表示にする。

想定する確認文言:

```text
追加の編集用AIモデル・フォントをダウンロードしますか？

被写体分離機能、オノマトペ向けフォント、テキスト編集用のサンプルが追加されます。
ダウンロードサイズ: 約 XXX MB

[ダウンロード] [今はしない]
```

## 2. 分ける理由

### 本体に入れない理由

本体 exe はすでに約 200 MB 規模で、mIV の主用途は画像ビューワーである。
編集機能を使わないユーザーに、フォント・編集用 AI モデルの容量を常時負担させない。

特にオノマトペ用フォントは、1 つずつは数百 KB から数 MBでも、使いやすさを重視して多めに入れると
数十 MB 以上になる。被写体分離モデルも通常版へ差し替える場合は 100 MB 級になり得る。

### TensorRT と分ける理由

TensorRT pack は NVIDIA / 高速 AI 処理を必要とする一部ユーザー向けで、サイズも約 2 GB 級。
編集用追加パックは、TensorRT を使わないユーザーにも有用なフォント・被写体分離を含むため、
TensorRT とは別の導線にする。

## 3. パック構成

初期候補:

| 種別 | 内容 | 必須度 | サイズ目安 | 備考 |
| --- | --- | --- | --- | --- |
| オノマトペ向け OFL フォント | Google Fonts 等の OFL 日本語フォント | 高 | lab 現状 18 書体で約 61 MiB | ライセンス文面も同梱 |
| 被写体分離モデル | BiRefNet fp16 ONNX (foreground matte) | 高 | ~490 MB | onnx-community/BiRefNet-ONNX (重み ZhengPeng7/BiRefNet 由来、MIT)。RTX 4090/DirectML で warm 104ms (1024²) を実測 |
| フォントプリセット | フォントごとのサンプル語、色、袋文字、初期角度 | 高 | 小 | アプリ側コード/JSON でもよい |
| 画像オノマトペ素材 | PNG/WebP スタンプ素材 | 低 | 未定 | ライセンス整理が必要。初期 pack には含めなくてよい |

被写体分離モデルについて (2026-06 確定):

- 当初は U²-Net 系を候補としていたが、検証の結果 **BiRefNet fp16** を採用した。
  イラスト (髪の細毛まで) / 実写 (salient 被写体) いずれも U²-Netp と別次元の品質。
- 入手元: onnx-community/BiRefNet-ONNX (`onnx/model_fp16.onnx`, 490 MB)。
  重みは ZhengPeng7/BiRefNet 由来、**MIT** ライセンス。
- I/O: 入力 `input_image` [1,3,1024,1024] **fp32** (fp16 は内部のみ)、ImageNet 正規化。
  出力 `output_image` [1,1,1024,1024] は **sigmoid 適用前のロジット** (後処理で sigmoid)。
- 実行は **DirectML (GPU)**。RTX 4090 で warm 104ms / cold 297ms、初回ロード ~4.9s。
  CPU では 1024² が実用にならないため、`load_model` (DirectML EP) を使う。
- v1.1.0 開発中に本体埋め込みの U²-Netp は廃止。被写体マスク生成は追加パック導入時のみ有効。
- モデル差し替えは pack manifest のバージョン更新で扱う。保存済み被写体マスクはモデル無しでも使える。
- 検証 probe: `cargo run --release --bin probe_birefnet -- <model.onnx> <image>`。

## 4. ダウンロード導線

### 4.1 起動時には出さない

初回起動時や通常閲覧時には案内しない。
編集機能へ入るユーザーだけに出す。

トリガー:

- 補正レイヤーパネルを初めて開く
- 吹き出し / テキスト編集ツールを初めて開く
- オノマトペ追加を初めて選ぶ

上記のどれかで追加パックが未導入なら、同じ確認モーダルを出す。
同一セッションで何度も出さないように、`declined_this_session` を持つ。

### 4.2 モーダル中の挙動

ダウンロード確認モーダル:

- 「ダウンロード」を押すと進捗モーダルへ遷移する。
- 「今はしない」を押すと、必要機能を disabled にして編集画面へ入る。
- ネットワーク無し / 失敗時は、再試行と手動インストール案内を出す。

進捗モーダル:

- ダウンロード完了までは編集用追加ファイルを必要とする操作をブロックしてよい。
- UI スレッド自体は止めない。ダウンロードと展開は worker thread で行い、UI は進捗を poll する。
- キャンセル可能にする。キャンセル時は `.part` を削除し、未導入状態へ戻す。

表示例:

```text
編集用追加ファイルをダウンロードしています

  128 MB / 240 MB
  フォントと被写体分離モデルを展開中...

[キャンセル]
```

## 5. 配置先

インストール先 (`Program Files`) には書き込まない。
既存のモデル展開方針に合わせ、ユーザー領域へ置く。

推奨配置:

```text
%APPDATA%/mimageviewer/addons/editing/
  manifest.json
  packs/
    editing-2026-06-xx/
      manifest.json
      fonts/
        *.ttf
        *-OFL.txt
      models/
        birefnet_fp16.onnx
        birefnet_fp16-LICENSE.txt
```

`manifest.json` は現在有効な pack へのポインタを持つ。
pack 更新時は新しいディレクトリへ展開してから、検証完了後に active を切り替える。

## 6. マニフェスト

配布ファイルには、アプリ側で検証できる manifest を含める。

例:

```json
{
  "schema": 1,
  "pack_id": "editing-base",
  "version": "2026.06.0",
  "app_min_version": "1.1.0",
  "files": [
    {
      "path": "fonts/OtomanopeeOne-Regular.ttf",
      "kind": "font",
      "license": "OFL-1.1",
      "sha256": "..."
    },
    {
      "path": "models/birefnet_fp16.onnx",
      "kind": "subject_matte_model",
      "model_id": "birefnet_fp16",
      "license": "MIT",
      "sha256": "..."
    }
  ]
}
```

アプリ側は次を確認する:

- pack schema が対応範囲内
- 必須ファイルが揃っている
- sha256 が一致する
- ライセンス表示に必要なファイルが揃っている

## 7. ダウンロード処理

推奨フロー:

1. アプリが `editing-pack-index.json` を取得する。
2. アプリバージョンに合う最新 pack URL、サイズ、sha256、表示文言を読む。
3. ユーザー確認後、worker thread で `*.zip.part` へダウンロードする。
4. ダウンロード完了後、zip 全体の sha256 を検証する。
5. 一時ディレクトリへ展開する。
6. 展開後に各ファイルの sha256 を検証する。
7. `packs/<version>` へ atomic rename し、active manifest を更新する。
8. UI に完了を通知し、フォント一覧 / モデル一覧を再読み込みする。

中断・失敗時:

- `.part` と一時展開ディレクトリは削除してよい。
- 既存の active pack は消さない。
- 次回同じ入口で再試行できる。

## 8. フォントの扱い

フォントは 2 系統に分ける。

| 系統 | 内容 | UI 上の扱い |
| --- | --- | --- |
| アプリ追加フォント | editing pack の `fonts/` 配下 | 「オノマトペ向け」「同梱」などで絞り込める |
| システムフォント | Windows Fonts / ユーザー追加フォント | 通常フォント一覧。別フィルタで表示 |

オノマトペ追加ダイアログでは、まずアプリ追加フォント + プリセットを表示する。
通常のフォント変更ダイアログでは、カテゴリとして以下を用意するのがよい。

- すべて
- オノマトペ向け
- 同梱 / 追加パック
- システム
- 日本語対応

ユーザーが自分で追加したフォントは `%APPDATA%/mimageviewer/user_fonts/` などへ置き、
pack 更新で消えないようにする。アプリ追加フォントとは別管理にする。

## 9. 被写体分離モデルの扱い

補正レイヤーの「被写体」マスク生成は、追加パックのモデルがある時だけ有効化する。

未導入時:

- 既存の保存済みマスクは表示・編集できる。
- 新規生成 / 再生成ボタンは disabled。
- ボタン付近に「編集用追加ファイルが必要です」表示と「ダウンロード」ボタンを出す。

導入後:

- 生成は既存の AI / 補正 worker 方針に従い、UI スレッドでは session 作成や推論をしない。
- モデルロードは遅延。アプリ起動時には ONNX session を作らない。
- 生成結果は通常の補正レイヤーマスクとして保存し、モデル pack を削除しても再表示できる。

通常版 U²-Net へ差し替える場合の方針:

- 軽量版 / 通常版の分岐を UI に出さない。
- 初期は通常版 1 本にする。ターゲット PC は比較的新しい性能を想定する。
- 重すぎる実測が出た場合だけ、後続で軽量 pack または低品質モードを検討する。

## 10. ライセンス表示

追加パックに含むファイルは、本体とは別にライセンス一覧へ表示する。

最低限:

- pack manifest の `files[].license`
- 配布元 URL
- 原ライセンス文面へのリンクまたは同梱テキスト
- pack バージョン

OFL フォント:

- フォントファイルと同じ pack に OFL 1.1 文面を入れる。
- フォント名の予約名 (Reserved Font Name) がある場合、改変再配布時に注意する。
- mIV 側でフォントを改変せず同梱するだけなら、通常は OFL と MIT 本体コードの併用は可能。

AI モデル:

- ONNX ファイルごとに元リポジトリ、モデルライセンス、学習済み重みの再配布可否を確認する。
- コードライセンスとモデル重みライセンスが異なる場合があるため、実装前に再確認する。

## 11. 更新と削除

環境設定に「編集用追加ファイル」ページを追加する。

表示項目:

- 導入状態
- pack バージョン
- ダウンロードサイズ / 展開後サイズ
- 含まれるフォント数
- 被写体分離モデル名
- 更新確認
- 削除
- 手動インストール先を開く

削除時:

- active pack を外し、pack ディレクトリを削除する。
- ユーザー追加フォントや保存済み編集データは削除しない。
- 削除後は未導入状態と同じ disabled 表示へ戻る。

## 12. 実装メモ

新規モジュール候補:

| モジュール | 役割 |
| --- | --- |
| `src/editing_addon.rs` | manifest 読み込み、導入状態、pack path 解決 |
| `src/editing_addon_download.rs` | ダウンロード worker、sha256、展開、キャンセル |
| `src/ui_dialogs/editing_addon.rs` | 確認 / 進捗 / 失敗 / 設定ページ UI |
| `src/font_assets.rs` | app pack fonts + user fonts + system fonts の統合列挙 |

注意:

- UI スレッドで `std::fs::read`、zip 展開、sha256 計算、ONNX session 作成をしない。
- ダウンロードは mpsc で進捗イベントを返す。
- フォルダ切替や編集モード終了でキャンセルできるようにする。
- 設定 DB には巨大 BLOB を入れず、active pack の ID / version / path だけ保存する。
- `Program Files` 配下には書き込まない。
