## 実装サマリ (v2.0.0 で実装された最終形)

- **モジュール**: 純ロジック [src/filename_stack.rs](../src/filename_stack.rs) (lib+bin、`StackMember` /
  `StackGroup` / `StackView` + `prefix_of` / `group_media` / `materialize_aggregated` /
  `materialize_flat` / flat-index 写像 / `stack_jump_target`)、App グルー
  [src/filename_stack_ui.rs](../src/filename_stack_ui.rs) (bin-only、トグル / 開く intercept /
  ビュー切替)。
- **新 GridItem**: `GridItem::Stack { key, representative, count }` (集約グリッドの畳んだセル。
  ZipDir と同じ仮想コンテナ扱い = pin / snapshot / file-op / checkable / rating すべて対象外)。
- **2 段ビュー (メンバーグリッドは無し)**:
  - **集約グリッド** = 1 グループ 1 セル。複数枚画像はスタックセル + 右上「N 枚」バッジ、単独は
    通常 Image/Video セル。コンテナ (フォルダ/ZIP/PDF) は先頭に素通し表示。
  - **フラット読書フルスクリーン** = セルを開くと `self.items` を全画像展開 (`materialize_flat`) に
    差し替えてフルスクリーンへ。閉じると集約へ戻る (`stack_reconcile_after_fullscreen_close`)。
- **トグル**: アドレスバー右端、サムネ枚数「12/345」の左の selectable「スタック」。ON/OFF は
  transient (`stack_mode_requested`、永続化しない)。別フォルダ/検索/ドライブ一覧へ移ると自動解除。
  通常フォルダに加えて、サブ展開スナップショット表示中にも利用できる。
- **サブ展開ビュー連携**: 複数フォルダの画像が混ざるため、サブ展開中は親フォルダ単位で分類する。
  ユーザー定義スクリプトも同じ AST を使い回しながら親フォルダごとに `group(files)` を呼び、
  返されたキーに親フォルダスコープを付ける。これにより同名 prefix / 先頭連番が別フォルダ間で
  誤結合しない。OFF 時は保持済み `SubfolderExpansionSnapshot` を再インストールして元の
  フラットなサブ展開一覧へ戻す。
- **サムネ**: 代表は実画像ファイルなので**専用 cache key 不要** — その実ファイルの通常 per-file
  サムネをそのまま要求・再利用する (toggle 跨ぎでキャッシュ命中)。当初案の `stackthumb:` は不採用。
- **ナビ (フルスクリーン)**: `↓↑`=全画像フラット順送り (境界越え) / `Shift+↓↑`=次/前スタック先頭へ
  ジャンプ / `Ctrl+↓↑`=フォルダ移動 (据え置き)。Shift+↓↑ は raw consume_key (動画音量と同流儀、
  `stack_showing_flat` 中のみ stack jump)。
- **区切り文字**: `settings.stack_separator: char` (既定 `_`、`#[serde(default)]`、永続)。
- **②製本との連携 (§5)**: 集約グリッドでスタックセルを選択 → ピン本/アクティブ本へ追加すると、
  `add_grid_selection_to_named_book` が `stack_member_paths` でメンバー実パスを取り出し、
  各メンバーを `book_page_source_for_stack_member` で**通常の Grid 追加と同じ規則**に合流させる
  (= スタック解除 → メンバー全選択 → 追加 と同結果)。具体的には `book_page_source_for_idx` の
  Image+Grid 分岐をパスベースで再現し、①同一本ページは拒否、②色補正/非破壊回転があれば
  `AdjustedFile` に焼き込む。メンバーは集約 items に出ず idx を持たないため、params/rotation は
  `adjustment_db.get_page_params` / `rotation_db.get_key` を `page_path_key` 同形のキーで直接引く
  (`set_page_params` が DB へ書き戻すので集約ビューでも正しく拾える)。エラー時は部分コピーせず全体中止。
  (Codex P2 第1ラウンド: メンバー展開を追加 / 第2ラウンド: 旧 `stack_member_book_sources` の
  生 `File` 展開が同一本拒否・補正/回転焼き込みを迂回していたのを上記パスベース経路へ是正)。
- **トグルの有効条件**: `stack_mode_available` は実ディレクトリ表示、または
  `items_are_subfolder_expansion_view && subfolder_expansion_snapshot.is_some()` のときだけ true。
  PDF ページ一覧 / ZIP / 検索合成を除外し、Ctrl+F 現在地検索中 (`show_search_bar` /
  `search_filter` / `search_pending`) も不可 (トグルで検索フィルタが消えるため)。
- **MVP 制限**: スタックモード中の Ctrl+F / facet は集約セル単位で照合し、隠れたメンバー名/メタは
  未評価。内訳: **種別 / 拡張子の facet は代表画像で評価** (集約セルは image-like)、**メンバー単位の
  メタデータ facet (タグ / AI モデル / AI ツール) は集約セルを一律で素通し** (= `facet_tag_filter_applies`
  / `facet_ai_filter_applies` がスタックを対象外にする。集約セル単体ではメンバーのタグ/AI メタを
  評価できないため、全落ちさせず残す。タグ facet と AI facet で挙動が食い違わないように揃えた)。
  Ctrl+F も prefix キーで照合。Shift+↓↑ は端で no-op (次フォルダは Ctrl+↓)。breadcrumb は集約=
  フォルダパスのまま。
- **新機能なのでマイグレーション不要** (CLAUDE.md「永続データ・スキーマ変更時の判断」)。

## 当初設計 (履歴。最終実装は上記サマリが正本)

## 0. 背景と目的

2026-06 の機能拡張検討で確定した整理系機能のひとつ。pixiv / danbooru 等のダウンローダは
**1 つの投稿に複数画像があると、ファイル名の前半 (prefix) が共通で後半 (suffix) だけ変わる**
(例: `12345678_p0.jpg` / `12345678_p1.jpg` …)。これをフラットな一覧で見ると、1 投稿の
複数ページがバラけて見通しが悪い。

- **目的**: フォルダ内の画像を「投稿 = スタック」に畳んで一覧の見通しを上げ、スタック単位で
  読む / 整理する。
- **seed-stack 案 (メタデータ署名でまとめる) は不採用**: ユーザーが seed 違いを作らなく
  なった (毎回ランダムプロンプトを混ぜる運用) ため需要が消えた。ファイル名 prefix 方式は
  ダウンローダ由来の整理に汎用で、実装も軽い (本計画で置換)。

### 想定ユースケース
- **pixiv/danbooru 等の多画像投稿**: 1 投稿を 1 サムネイルに畳んで一覧。
- **AI 生成の連番出力**: 同一プロンプトのバリエーションが共通 prefix を持つ場合の集約。
- **②製本との連携**: スタックを丸ごと「本」へコピーして仕分け ([compile-book-plan.md](compile-book-plan.md) §11.5)。

## 1. 中核モデル: スタック = フォルダ内の一時的な仮想本

- **グループ化キー = ファイル名の「末尾の区切り文字の前」**。既定の区切り文字は `_`、設定可能。
  例: `12345678_p0.jpg` → 末尾 `_` の前 = `12345678` でグループ化。danbooru 系は命名が
  まちまちなので区切り文字を設定で変えられるようにする。
- **全グループを仮想スタックにする (単独ファイルも "1 ページのスタック")**。これはナビゲーション
  の一貫性のため (§3.4)。グリッド表示上は単独スタックを通常サムネイルとして描く (§3.3) が、
  内部のグループ構造は単独でもスタックとして持つ。
- **スタックは「フォルダ内の一時的な仮想本」**として扱う。mIV のフルスクリーンは既に
  「コンテナまたぎ Ctrl+↑↓ / コンテナ内ページ送り」の二段ナビを持つ
  ([fullscreen-navigation-consistency.md](fullscreen-navigation-consistency.md))。スタックを
  この "コンテナ" に見立てれば、既存のナビ実装にそのまま乗る。

## 2. 既存資産との接続 (実装は薄く済む見込み)

v1.3.0 のネスト ZIP ツリー ([nested-zip-tree-plan.md](nested-zip-tree-plan.md)) が構造的にほぼ
同型 (区切りを `/`→`_`、対象を ZIP エントリ→フォルダ内の実ファイルに替えた版)。実ファイルなので
ZIP エントリの間接層も DB も無いぶん、ZIP ツリーよりむしろ簡単。

| 必要な処理 | 流用元 |
| --- | --- |
| 仮想コンテナのグリッドアイテム (実パスを持たない・代表サムネ + 件数バッジ) | `GridItem::ZipDir` / `GridItem::SearchContainer` ([src/grid_item.rs](../src/grid_item.rs)) |
| 表示リストの差し替え | `start_loading_items()` の単一チョークポイント ([src/app.rs](../src/app.rs)) |
| 集約ビューへ入る / Backspace で戻る (in-memory にリスト再構築) | Ctrl+G ドリルダウン ([src/global_search_ui.rs](../src/global_search_ui.rs)) |
| 「現在の本だけ」で見開きペアをリセット | ZIP ツリーの `materialize_current` 系 |
| 仮想グループの代表サムネのキャッシュ ID | `stackthumb:<prefix>` を追加 (既存 `zipdir:` / `searchrep:` / `#pin:` と同じ prefix 方式、[src/thumb_loader.rs](../src/thumb_loader.rs)) |
| 重い I/O を UI スレッドから外す | 既存 worker + mpsc + cancel ([ui-responsiveness.md](ui-responsiveness.md)) |

**DB 変更なし・非破壊** (ファイルを動かさない)。

## 3. 機能設計

### 3.1 トグル
- **ツールバーのフォルダ欄右端にスタックトグル** (Ctrl+G の集約と同系の文言 / ボタン)。
- ON で現在フォルダの画像をグループ化して表示、OFF で通常一覧に戻す。

### 3.2 グループ化ロジック (純関数)
- 入力 = 現在フォルダの**画像ファイルのみ**の一覧。フォルダ / ZIP / PDF / 動画 / 変換アーカイブは
  対象外 (グループ化に混ぜない。スタックモード中の表示可否は §3.6)。
- prefix = ファイル名 (拡張子を除いた basename) の**末尾区切り文字の前**。区切り文字が無い
  ファイルは prefix = basename 全体 (= 単独スタック)。
- **2 個以上同一 prefix が揃ったグループだけを「畳んだスタック」**として扱い、グリッドで
  代表 + 枚数バッジを描く。単独 (1 個) は通常サムネイルとして描く (バッジなし)。
- グループ内の並びは現在のソート設定に従う。

### 3.3 グリッド表示
- 1 スタック = 1 サムネイル。代表画像 = グループ先頭 (ソート順の最初)。
- **2 枚以上のスタックには枚数バッジ**、単独スタックはバッジなし (見た目は通常一覧と同じ)。
- 代表サムネのキャッシュキーは `stackthumb:<prefix>` (グループの先頭が変わればキーも変わる)。
- グリッドの矢印キーはスタック間でカーソル移動 (スタック = 1 セル)。

### 3.4 ナビゲーション (二段)
- **グリッドでスタックをクリック / 開く = そのスタックの先頭からフルスクリーン読書に入る**。
  単独スタックはその 1 枚を直接開く (中間のメンバー一覧は挟まない)。
- **フルスクリーン中**:
  - **通常ページ送り (↑↓ / クリック / ホイール等) = スタック内のページ移動**。
  - **Ctrl+↑↓ = 次 / 前のスタックへ移動** (既存のコンテナまたぎ Ctrl+↑↓ を流用)。
  - **見開きペアはスタックごとにリセット** (`materialize` 相当)。スタック末尾での送り / 境界
    ヒントは既存のフォルダまたぎ挙動に合わせる。

### 3.5 containment と自動解除
- **containment は "ビューモード" として実装** (ハードロックしない)。Ctrl+G 集約と同じ流儀で、
  スタックへドリルイン / Backspace で集約ビューへ戻る。
- **その仮想ツリーの外へ移動しようとしたら自動でスタックモードを解除**する (別フォルダへ移動 /
  検索 / ドライブ一覧等への遷移でトグル OFF)。固定ロックはしない。

### 3.6 横断系との整合
- **選択 / チェック / シェル操作 / ドラッグアウト / ★ / タグ**: スタックを展開した後の
  メンバーは実 `GridItem::Image(PathBuf)` なので、これらは展開後そのまま動く。
- **ソート**: グループ内 / スタック間の並びにソート設定を反映する。
- **facet フィルタ / Ctrl+F**: スタックモード中の絞り込み挙動 (グループ単位で残すか、メンバー
  単位で評価してから再グループ化するか) は実装時に詰める (§7 のテスト対象)。
- **MVP では「スタックを丸ごと操作」を基本**とし、メンバーをグリッドに展開して個別選択する
  経路は将来拡張 (②製本との連携 §5 で多くの用途はカバーできる)。

## 4. 非対象 / 制約
- 画像以外 (フォルダ / ZIP / PDF / 動画) はグループ化対象外。スタックモード中の一覧での
  扱い (非表示にするか素通し表示するか) は実装時に決める。
- スタックの内容を実ファイルとして書き換えない (純粋な表示集約)。

## 5. ②製本との連携
- スタックモードで**スタックを選択 → ピン留めした本のボタンを右クリック = そのスタックの
  メンバー全部をその本へコピー追加** ([compile-book-plan.md](compile-book-plan.md) §11.5)。
  重複は skip + トースト (§11.2)。
- 左右クリックの規約 (左=開く / 右=追加) はツールバー統一モデル
  [toolbar-customization-plan.md](toolbar-customization-plan.md) §1.1 に従う。スタックトグル
  自体もこの refactor 後のツールバー上のモードトグルとして置く。

## 6. 永続データへの影響 (未リリース新機能)
| 対象 | 状況 | 対応 |
| --- | --- | --- |
| スタックトグルの ON/OFF | **永続化しない** (transient) | フォルダを出ると自動解除 (§3.5) するので、セッションをまたいで保持しない |
| 区切り文字設定 | 新規 settings フィールド | `#[serde(default)]` で既定 `_`。後方互換 |
| サムネキャッシュ | `stackthumb:<prefix>` を追加 | 既存 prefix 方式に追従、スキーマ非依存 |

新機能のため**マイグレーション不要** (CLAUDE.md「永続データ・スキーマ変更時の判断」)。

## 7. テスト
- prefix 分割の純ロジック unit test: 末尾区切り文字の前で正しく切れる / 区切り文字なしは
  basename 全体 / 2 個以上だけ畳む / 単独はバッジなし。
- ナビ: グリッドクリック→フルスクリーン先頭、フルスクリーンで ↑↓=スタック内・Ctrl+↑↓=
  スタック間、見開きがスタックごとにリセットされる。
- 自動解除: 別フォルダ / 検索 / ドライブ一覧へ移動するとトグル OFF になる。
- 横断系: 展開後メンバーへの ★ / タグ / シェル操作 / ドラッグアウトが効く。facet / Ctrl+F の
  スタックモード時挙動。
