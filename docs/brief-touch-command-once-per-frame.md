# ブリーフ: タッチコマンドが 1 アプリフレームに 2 回実行される

対象: v2.13.0。実装 = Codex Sol / レビュー・検収 = ClaudeCode。
正本: [docs/touch-support-plan.md](touch-support-plan.md) §5.2 / §5.10。

前提 (完了・コミット済み): Step 0 `bb9574b2` / Step 1 `66cb2910` / Step 2 `6be3afd3` /
Step 3 `42aa037a` / Step 3c `cae9ffd6` / ピンチ昇格 `21ef4643`。

---

## 1. 症状

実機報告 (2026-08-07):

> ウィンドウ中央をタップしても、**2 回タップして HUD が出て、もう 2 回タップすると
> HUD が閉じる**ように見える。

## 2. 原因 (特定済み)

`process_in_temp_data` ([src/touch_correlation.rs:479](../src/touch_correlation.rs)) は、
同じアプリフレームで 2 回目以降に呼ばれると `repeated_drive_result` を返す。
これは `state.last_frame` をそのまま返しており、**コマンドが入ったまま**である
([:504](../src/touch_correlation.rs))。

呼び出し側 ([src/ui_fullscreen.rs](../src/ui_fullscreen.rs) の
`for command in touch_frame.clone().into_commands()`) は、返ってきたコマンドを**毎回実行する**。

egui は **1 つのアプリフレームに対して複数パスを走らせる**ことがある
(レイアウトが確定しないときの再パス、`request_discard` など)。
クロームの表示 / 非表示はレイアウトを変えるので、まさに再パスを誘発する。

→ **`ToggleChrome` が 1 タップで 2 回実行され、差し引きゼロになる。**
パス数が 1 回のフレームと 2 回のフレームが交ざるため、「2 回タップでやっと反応する」ように見える。

### 同じ穴を通る他のコマンド (重要)

**`ToggleChrome` だけの問題ではない。** トグルでないコマンドは、二重実行が
「効かない」ではなく「**2 倍効く**」形で出る:

| コマンド | 二重実行したときの症状 |
| --- | --- |
| `ToggleChrome` | 差し引きゼロで反応しない (報告された症状) |
| `PageSide` | **1 タップで 2 ページ進む** |
| `Zoom` | 倍率が 2 回分かかる |
| `Pan` | 移動量が 2 倍になる |
| `PinchEnd` | PDF 再レンダリングが 2 回走る |

**すべて同じ原因なので、まとめて直すこと。**

## 3. 直し方 — コマンドは 1 アプリフレームに 1 回だけ届ける

`TouchFrame` が持っている 2 種類の情報は、**寿命がまったく違う**:

| 情報 | 必要な寿命 | 理由 |
| --- | --- | --- |
| **コマンド** (`commands`) | **そのアプリフレームで 1 回だけ** | 実行すると状態が変わる。冪等でない |
| **抑止判定** (`primary_events`) | **同じフレームの全パスで何度でも** | 問い合わせるだけで副作用がない。後続パスの widget も参照する |

現在はこの 2 つを同じ経路で返しているため、後者に必要な「何度でも返す」が
前者にも適用されてしまっている。**この 2 つを分けるのが構造的な修正**である。

指示:

- **同一アプリフレーム内の 2 回目以降の drive では、コマンドを空で返す**
- **抑止判定は 2 回目以降も従来どおり返す** (ここは変えない。変えると Step 3c の
  バーボタン解決や click 抑止が後続パスで壊れる)
- 「実行済みかどうか」を呼び出し側に持たせて分岐する形にはしないこと。
  **`TouchFrame` を返す側で寿命の違いを表現する** (呼び出し側が忘れたら再発するため)

> ⚠ **パス番号でごまかす guard を足さないこと。** 「2 回目のパスなら実行しない」を
> 呼び出し側に書くのは症状パッチで、surface が増えるたびに同じ間違いを繰り返す。
> 直すのは `touch_correlation` 側の戻り値の意味づけ。

## 4. テスト

- **同一フレームで `drive` 相当を 2 回呼ぶと、2 回目のコマンドが空になること**
- **2 回目でも抑止判定は従来どおり返ること** (これが壊れると Step 3c が退行する)
- 次のフレームでは新しいコマンドが正常に返ること
- 上記を `ToggleChrome` 以外のコマンド (`PageSide` 等) でも確認すること
- 既存のタッチ関連テストがすべて通ること

**可能なら「1 タップ = トグル 1 回」を状態として検証するテスト**を入れること
(コマンド列レベルで固定できれば十分)。
