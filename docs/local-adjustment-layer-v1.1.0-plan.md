# v1.1.0 画像補正・補正レイヤー計画

Status: Codex 案 / Draft
Date: 2026-05-31

## 1. 背景

v1.0.0 後の拡張候補として、自動検出によるマスク生成を検証したが、局部検出はイラストで
見逃しが多く、検出範囲も実際の隠蔽用途には広すぎる傾向があった。検出が外れると事故に
直結するため、v1.1.0 の主軸としては慎重に扱う。

一方で、実際の利用フィードバックでは画像補正、背景ぼかし、キャラクター強調、液タブでの
細かな編集支援が好意的に受け止められている。画像補正は検出と違い、効果が合わなければ
戻せる非破壊処理なので、投資対効果を読みやすい。

v1.1.0 では次の 3 本をまとめて進める。

- 全体画像補正の強化
- マスク作成・調整機能の強化
- マスクを使った補正レイヤーの導入

## 2. 目標

### 2.1 ユーザー価値

- AI イラストや写真を、mIV 内で閲覧から軽い仕上げまで進められるようにする。
- 背景だけぼかす、背景だけ彩度やコントラストを落とす、キャラクターだけ明るくする、のような
  実用的な編集を、外部ペイントソフトなしで行えるようにする。
- 既存の消しゴム / 隠蔽加工マスク UI を、選択範囲作成の基盤として再利用する。
- 自動検出に頼りすぎず、ユーザーが意図した狭い範囲を安全に調整できるようにする。

### 2.2 v1.1.0 の範囲

- 全体補正に、明瞭度 / 柔らかさ系の補正を追加する。
- 必要ならトーンカーブの最小構成を追加する。
- 消しゴム / 隠蔽加工と共通で使えるマスク調整機能を強化する。
- 新しい「補正レイヤー」を追加し、1 レイヤーにつき 1 つの加工を適用できるようにする。
- 補正レイヤーごとに、マスク反転、フェザー、拡張 / 縮小、透明度を持てるようにする。
- マスクの生成元を増やし、手描き / ポリゴンだけでなく、グラデーション、輝度・カラー範囲、
  被写体選択、色差 / 境界ベースの領域分割を扱える設計にする。

### 2.3 v1.1.0 ではやらないこと

- Luminar Neo 相当の総合 AI 写真編集ソフトを目指さない。
- 自動局部検出や顔検出を、v1.1.0 の中心機能にしない。
- ポストフィルタの順序を大きく変更しない。
- フィルタスタックを 1 レイヤー内に複数持たせる高度なノード構造は作らない。
- 画像ファイルを直接上書きする破壊的編集は行わない。書き出しは既存の export 経路に寄せる。
- パイプライン途中で画像サイズを変える crop / 水平補正は、座標系への影響が大きいため
  v1.1.0 の中核には含めない。crop はまず最後段の preview / export crop として扱う案を検討する。

## 3. 処理順序

v1.1.0 では、既存挙動を大きく崩さず、消しゴム後・隠蔽加工前に補正レイヤーを差し込む。

```
元画像
  -> AI denoise / upscale
  -> 全体画像補正
  -> ポストフィルタ
  -> 消しゴム / 補完
  -> 補正レイヤー x N
  -> 隠蔽加工
  -> crop (任意、最後段)
  -> 表示 / 書き出し
```

本体 UI では左側のツール列を処理順に合わせ、`消しゴム -> 補正レイヤー -> 隠蔽加工 -> 切り取り -> 保存`
の順に並べる。`local_adjust_lab` でも同じ流れを確認できるように、消しゴムと隠蔽加工は
軽量なダミーパネル、補正レイヤー、切り取り、保存は実操作パネルとして用意する。

現状のポストフィルタは鑑賞時のおまけ的な機能として追加されたもので、調整項目も少ない。
そのため v1.1.0 では全体画像補正の中に置いたままにする。

将来、ポストフィルタをアップロード前の最終ルックとして使う要望が強くなった場合は、
「隠蔽加工後に再適用できる最終フィルタ」として別段に分ける。ただし、その場合は各フィルタの
強度調整や書き出し UI も合わせて再設計する。

## 4. 補正レイヤー

補正レイヤーは、マスクと加工内容を 1 セットにした非破壊レイヤーである。
UI 上の呼称は「補正レイヤー」とする。
プロトタイプ UI では、左パネルに処理順の切替、レイヤー一覧、選択レイヤーの加工内容を置き、
右パネルをマスク生成 / 調整 / 手動マスクツールに分ける。筆サイズなど頻繁に触る
ツールパラメータが、レイヤー一覧の下に沈まない配置を優先する。切り取りは補正レイヤーには
混ぜず、最後段の専用パネルとして扱う。

効果側に「中心」「光源位置」「効果中心」のような画像空間の位置パラメータを持つ場合は、
スライダーだけでなくキャンバス上のドラッグハンドルを標準で用意する。ハンドル表示は
`画像ハンドルを表示` で切り替え、スライダーは精密調整・数値確認用として残す。
この表示切替は、効果パネル冒頭ではなく、対象になる中心 X/Y・光源 X/Y などの
画像空間パラメータの直前に置く。ハンドルで動かすものと数値スライダーを同じ視線の
まとまりに入れ、効果ごとの差を作らない。線形 / 円形グラデーションやチルトシフト範囲の
ように専用ハンドル系があるものは、効果中心ハンドルには混ぜず、その専用操作を維持する。

### 4.1 基本モデル

```rust
struct LocalAdjustmentLayer {
    id: Uuid,
    name: String,
    enabled: bool,
    opacity: f32,
    mask: LocalMask,
    manual_override: ManualMaskOverride,
    mask_inverted: bool,
    mask_expand_px: f32,
    mask_feather_px: f32,
    mask_before_effect: bool, // true=マスク範囲だけを効果の入力にする
    mask_after_effect: bool,  // true=効果結果をマスクで切り取る
    effect: LocalEffect,
}
```

```rust
enum LocalEffect {
    None,
    Tone(LocalToneParams),
    Curve(LocalCurveParams),
    Blur(LocalBlurParams),
    SoftFocus(LocalSoftFocusParams),
    Mosaic(LocalMosaicParams),
    Sharpen(LocalSharpenParams),
    Look(LocalLookParams),
    Bloom(LocalBloomParams),
    Vignette(LocalVignetteParams),
    FilmGrain(LocalFilmGrainParams),
    ChromaticAberration(LocalChromaticAberrationParams),
    Defringe(LocalDefringeParams),
    ScanlineGlitch(LocalScanlineGlitchParams),
    Vhs(LocalVhsParams),
    PixelSort(LocalPixelSortParams),
    OldFilm(LocalOldFilmParams),
    WaterCaustics(LocalWaterCausticsParams),
    ParticleOverlay(LocalParticleOverlayParams),
    Aurora(LocalAuroraParams),
    Halftone(LocalHalftoneParams),
    ScreenTone(LocalScreenToneParams),
    ColorHalftone(LocalColorHalftoneParams),
    CmykPlateShift(LocalCmykPlateShiftParams),
    Textureizer(LocalTextureizerParams),
    EdgePreservingSmooth(LocalEdgeSmoothParams),
}
```

v1.1.0 の初期実装では、1 レイヤーにつき 1 つの `LocalEffect` のみを持つ。
複数効果を重ねたい場合は、同じマスクを複製して複数レイヤーとして重ねる。

`LocalMask` は「最終的に 0.0..1.0 のマスク alpha を返すもの」として抽象化する。
合成処理は生成元を知らず、反転 / 拡張縮小 / フェザー / 透明度を共通に適用する。

```rust
enum LocalMask {
    RasterVector(RasterVectorMask), // 手動マスク: bitmap strokes + editable objects
    LinearGradient(GradientMask),
    RadialGradient(GradientMask),
    Range(RangeMask),
    Subject(RasterMask),       // 被写体 / 背景の1枚マット
    Segmentation(RegionMask),  // 色分け領域候補 + 個別ON/OFF
}

struct ManualMaskOverride {
    add: Option<RasterVectorMask>,      // 2値。該当ピクセルを alpha=1.0 に上書き
    subtract: Option<RasterVectorMask>, // 2値。該当ピクセルを alpha=0.0 に上書き
}
```

初期実装では、合成器を単純に保つため、各マスク生成元から一時的な raster alpha mask を作って
既存のマスク合成に流す。グラデーションや範囲マスクの編集パラメータは保持するが、ぼかしや
補正そのものは raster alpha mask だけを見て動く。

自動生成、範囲、グラデーション系マスクは「初期選択」として使い、そのソフトな情報を破壊しない。
手修正は、各レイヤーに共通の `manual_override.add` / `manual_override.subtract` として持つ。
合成時は base mask を評価した後、追加マスクで alpha=1.0、削除マスクで alpha=0.0 に上書きし、
その後に反転、拡張 / 縮小、フェザー、不透明度を適用する。これにより、円形グラデーションや
被写体マットの滑らかな alpha を維持しつつ、ピクセル単位の追加 / 削除を2値マスクで軽く保存できる。
レイヤーは効果計算前 / 効果計算後のどちらでマスクを使うかを個別に切り替えられる。
既存互換の基本形は `mask_before_effect=false` / `mask_after_effect=true`。風、ブルーム、
ネオングロー、光芒、クロス光など、マスク内の素材から外側へ広がる効果は
`mask_before_effect=true` / `mask_after_effect=false` をデフォルトにする。波形ゆがみなど
対象内に収めたい変形は、必要に応じて両方 ON にできる。
プレビューでは、追加マスク / 削除マスクの両パネルを閉じているときは最終マスクを選択中の
ベース色で表示する。追加マスク編集中は削除マスクを無視した base mask をベース色、
操作中の追加マスクを編集色で表示する。削除マスク編集中は base mask + 追加マスクをベース色、
操作中の削除マスクを編集色で表示する。
これにより、最終 alpha が 0 になる削除マスクも編集対象として視認できるようにする。
マスク生成 / 編集が行われた場合は、ユーザーが見落とさないよう `選択マスク表示` を自動で ON にする。
UI では非手動マスクの追加 / 削除マスクパネルを初期非表示にし、ユーザーが `追加マスク` または
`削除マスク` を押した時だけ、その下に手描きツール群と編集説明を展開する。同じボタンをもう一度
押すと閉じる。閉じている間は補正用の空マスクを生成せず、ベースマスクの設定 UI と効果設定だけを
見せる。

複数のレイヤー効果へ同じマスクを適用したい場合は、レイヤー複製後に加工内容だけを変更する。
追加 / 削除マスクで部分的な手修正ができるため、別レイヤーからマスクだけをコピーする専用 UI は
初期実装から外す。

### 4.2 マスク反転

各レイヤーに `mask_inverted` を持たせる。

用途:

- キャラクターを囲んで、反転して背景だけぼかす。
- 背景を選んで、反転してキャラクターだけ明るくする。
- 既存マスクを複製し、片方は内側、片方は外側の補正に使う。

反転は保存マスク自体を書き換えず、合成時の評価だけを反転する。これにより、反転 ON/OFF を
切り替えてもマスク編集履歴や形状データが壊れない。

### 4.3 マスク調整

レイヤーごとに以下を持たせる。

| 項目 | 目的 |
| --- | --- |
| `mask_expand_px` | マスクを外側へ広げる / 内側へ縮める。負値で縮小 |
| `mask_feather_px` | 境界をぼかして補正の段差を減らす |
| `opacity` | 効果全体の強さを下げる |

マスク調整は元マスクを破壊せず、合成時に一時マスクとして計算する。

### 4.4 マスク生成元

補正レイヤーの価値を上げるため、マスクは複数の生成元を持てるようにする。

| 生成元 | 優先度 | 用途 | 実装メモ |
| --- | --- | --- | --- |
| 手動マスク | 高 | 狭い範囲を意図通りに選ぶ | 既存の消しゴム / 隠蔽加工と同等のブラシ、囲み、直線、縦線、横線、矩形、楕円、選択ハンドル、Undo を持つ |
| 線形グラデーション | 高 | 上下・左右だけ暗くする、背景をなだらかに落とす | パラメータ評価だけで軽い |
| 円形 / 楕円グラデーション | 高 | 主役のスポット強調、周辺だけぼかす | 中心 / 横半径 / 縦半径 / feather を編集 |
| 輝度範囲 | 中 | ハイライトだけ、暗部だけを補正 | flood fill しないので暴走しにくい |
| カラー範囲 | 中 | 特定色だけ彩度や色相を調整 | スポイト + 許容幅 + feather |
| 被写体選択 | 中-高 | 背景ぼかし、キャラクター強調 | 任意モデルを追加 DL。被写体 / 背景の1枚マットとして扱う |
| 領域分割 | 中-高 | 髪、服、小物などを候補領域から個別選択 | 色差 / 境界 / 連結領域のクラシック分割。SAM / SAM2 系の AI 領域分割は検証の結果 v1.1.0 では見送り |

輝度 / カラー範囲マスクは Photoshop の Magic Wand のように連結領域を広げるのではなく、
画像全体に対して条件を評価する。ユーザーが嫌う「意図せず遠くまで広がる」挙動を避け、
閾値と feather で結果を予測しやすくする。

### 4.5 被写体選択と領域分割

被写体選択と領域分割は、UI と内部データの両方で分ける。

被写体選択は、U²-Netp / BiRefNet / IS-Net-Anime のような foreground/background matte
モデルを使い、被写体 / 背景の 1 枚マスクを生成する。背景を加工したい場合はマスク反転で扱う。

領域分割は、細かい候補領域を境界表示し、ユーザーがクリック / ドラッグで個別に ON/OFF する
ためのマスクである。生成直後は未選択にし、未選択候補はアニメーションする境界線だけを表示する。
選択した領域だけを選択中のマスクカラー + 明るい境界として表示する。初期実装ではモデル追加なしで、色差、境界線、連結領域から候補を作る。
被写体選択マスクがある場合は、その内側または背景だけを分割できる。被写体選択 / 領域分割
レイヤーを追加した直後は、右パネルの生成ボタン待ちに見えないよう、デフォルト設定で 1 回だけ
自動生成を開始する。領域分割の初回自動生成は画像全体を対象にする。

導入方針:

- モデルは本体に同梱しない。TensorRT 追加パックと同じ感覚で、必要なユーザーだけが追加で
  ダウンロードする。
- 被写体選択の採用候補はライセンス、モデルサイズ、ONNX / DirectML での実行可否、AI イラストでの精度を
  個別に確認してから決める。
- 生成結果は通常のマスクとして保存し、ユーザーが候補領域の ON/OFF、ブラシ、境界吸着、
  拡張 / 縮小、スムーズで手修正できるようにする。
- モデルが foreground matte だけを返す場合でも、「前景」「背景」の 2 値として使い、背景ぼかし
  プリセットに接続できる。

SAM / SAM2 系の AI 領域分割は `local_adjust_lab` で検証したが、promptable object mask
generator の出力をユーザーが期待する髪 / 服 / 小物などの意味単位へ安定して変換できず、
過分割や細かい破片が目立った。v1.1.0 では領域分割への AI 導入を見送り、クラシック分割と
手動補正をチューニングする。詳細は [ai-region-segmentation-retrospective.md](ai-region-segmentation-retrospective.md) を参照。

## 5. v1.1.0 の効果候補

### 5.1 全体画像補正に追加する候補

| 機能 | 優先度 | メモ |
| --- | --- | --- |
| 明瞭度 / 柔らかさ | 高 | 正負 1 スライダーにする。正で局所コントラスト増、負で柔らかくする |
| ソフトフォーカス | 高 | AI イラストでは明瞭度を上げるより、背景や全体を柔らかくする需要がありそう |
| ハイライト / シャドウ | 高 | トーンカーブより触りやすい定番補正。白飛び抑制、暗部持ち上げに使う |
| トーンカーブ | 中-高 | 最大の空白。まずは RGB 共通カーブから始め、チャンネル別は後続でもよい |
| 自然な彩度 | 中 | 彩度を上げても肌色や強い色が破綻しにくい補正 |
| かすみ除去 | 中 | 写真向け。AI イラストでは使いどころを見て優先度を調整する |
| HSL / 色相別補正 | 中 | 強力だが UI が増えるため、補正レイヤー安定後でもよい |
| tint / スポイト WB | 低-中 | 写真向け。AI イラスト中心なら優先度は少し下げる |

### 5.2 補正レイヤーに入れる候補

v1.1.0 の最小構成:

- 効果なし: レイヤー作成直後の初期値。まずマスクを作り、後から効果を選ぶ
- 色調補正: 明るさ / コントラスト / ガンマ / 彩度 / 色温度
- ぼかし: Gaussian blur
- ソフトフォーカス: 明部にじみ + blend
- モザイク: 既存隠蔽加工の処理を再利用

追加候補:

- トーンカーブ
- 明瞭度 / 柔らかさ
- ハイライト / シャドウ
- シャープ
- HSL
- Look / LUT
- Glow / Bloom
- ビネット
- フィルム粒子 / ノイズ追加
- 色収差
- ハーフトーン / 漫画調 / 印刷風 / スクリーントーン
- エッジ保持ぼかし / 滑らか化

モザイクは隠蔽加工にも存在するが、補正レイヤーにも置けるようにすると「最終隠蔽」と
「作品づくりのための加工」を同じレイヤー UI で扱える。ただし、公開用の確実な隠蔽処理は
引き続き最後段の隠蔽加工を推奨する。

背景ぼかしでは、マスク境界付近で前景色が背景側の blur に混ざる halo / edge bleed が出る
可能性がある。MVP では feather とマスク縮小で緩和する。必要になれば、前景側を簡易 inpaint
または edge-aware sampling で埋めてから背景をぼかす方式を検討する。

### 5.3 サムネイル非反映の仕上げ系レイヤー

全体画像補正はサムネイルにも反映されるため、重い処理や見た目が大きく変わる演出は入れにくい。
一方で、補正レイヤーはサムネイルへ反映しない前提にできるため、書き出し前の仕上げとして
重めの効果も扱える。全体にかけたい場合は、マスク種類を「全体」にする。

| 効果 | 優先度 | 用途 | 実装メモ |
| --- | --- | --- | --- |
| Look / LUT | 高 | 夕焼け風、夜景風、明るい日光、フィルム風などのルック適用 | まず内蔵プリセット + 強度。将来 `.cube` 読み込み |
| Glow / Bloom | 高 | 光源、髪、瞳、背景の明部を柔らかくにじませる | 明度閾値 + blur + screen/add blend |
| ビネット | 高 | 周辺を暗く / 明るくして視線誘導 | 専用効果にすると円形マスクより手早い |
| フィルム粒子 / ノイズ追加 | 中-高 | AI 絵のつるっとした質感を軽く崩す | seed 固定で再現性を持たせる |
| Orton / Soft Glow | 中 | 写真・イラストの柔らかい仕上げ | SoftFocus と近いがルック寄り |
| 色収差 | 中 | 演出系。軽く使うと画面効果になる | 強度上限を控えめにする |
| ハーフトーン / 漫画調 / 印刷風 / スクリーントーン | 中 | ポストフィルタ的な見た目を範囲・強度付きで使う | `Halftone` は簡易網点、`ScreenTone` は網点 / 線 / カケアミ、`ColorHalftone` は CMYK 4版ドット、`CmykPlateShift` は版ズレ、`Textureizer` は紙目 / キャンバス / リネン質感を持つ印刷・紙質系フィルタ |
| エッジ保持ぼかし / 滑らか化 | 中 | 背景なじませ、美肌、ノイズ感の低減 | bilateral / guided filter 系。重いので worker 前提 |

Look / LUT は「プリセット名 + 強度 + 適用色空間」を持つ。内蔵プリセットは、最初は少数に絞る。

- 夕焼け風
- 夜景風
- 明るい日光
- 淡色
- 寒色
- 暖色
- レトロ / フィルム風

外部 LUT 読み込みは、v1.1.0 の後半または次フェーズで `.cube` を候補にする。ライセンス上、
同梱 LUT は自作または配布許諾が明確なものに限定する。

## 6. UI 案

### 6.1 全体補正パネル

既存の画像補正パネルはそのまま維持し、次を追加する。

- 明瞭度 / 柔らかさスライダー
- ソフトフォーカススライダー、またはポストフィルタではない実用補正としてのソフトフォーカス
- トーンカーブを追加する場合は、折りたたみセクションか別ダイアログにする

ポストフィルタは現状の位置に残す。v1.1.0 では、ポストフィルタを最終書き出し用の本格的な
カラーグレーディング機能として扱わない。

### 6.2 補正レイヤーパネル

フルスクリーンの補正パネルから「補正」へ入れるようにする。

UI の基本構成:

- レイヤー一覧
- 新規レイヤー作成
- 表示 ON/OFF
- マスク編集ボタン
- マスク生成元の選択
- マスク反転チェック
- フェザー / 拡張縮小 / 透明度
- 効果種別の選択
- 効果ごとのパラメータ
- レイヤー複製 / 削除 / 上下移動

最初の体験は次の流れにする。

1. 「補正レイヤーを追加」
2. 空レイヤー (`手動マスク + 効果なし`) が作成される
3. マスクを作成または編集
4. 効果を選ぶ: ぼかし / ソフトフォーカス / 色調補正 / モザイク / Look / Bloom など
5. 必要なら「マスク反転」を ON
6. 強さやフェザーを調整

マスク生成元の UI は、最初は次の選択肢にする。

- 手描き / ポリゴン
- 線形グラデーション
- 円形グラデーション
- 輝度範囲
- カラー範囲
- 被写体選択
- 領域分割

被写体選択は、モデル未導入時は「モデルを追加」導線を表示する。モデルが入っている場合は
被写体 / 背景の 1 枚マットを生成し、反転や追加 / 削除マスクで調整する。

領域分割は、色差 / 境界 / 連結領域から候補領域を生成する。生成直後は未選択にし、
境界だけを表示して、クリック / ドラッグで複数領域を統合する。

背景ぼかしプリセットは、導入バリアを下げるためのショートカットとして用意する。

```
背景ぼかし:
  セグメンテーションまたは手動マスク
  -> マスク反転
  -> Blur レイヤー
  -> feather / shrink の初期値を設定
```

### 6.3 マスク編集ツール

`mask_lab` と `local_adjust_lab` で試している方向を、本体のマスク編集に戻す。

補正レイヤーでは、マスク生成元の 1 つとして「手動マスク」を持つ。この手動マスクは
試作専用の別物にせず、既存の消しゴム / 隠蔽加工のマスクツールと同等の操作体系に揃える。
後で本体へ統合するときは、消しゴム / 隠蔽加工側をこの共通手動マスク部品へ差し替えられる
構成を前提にする。

優先度高:

- クリックで点を置くポリゴン選択
  - ビットマップ系の範囲選択として扱い、クリックで頂点追加、始点付近クリック、右クリック、
    または Enter で確定、Esc でキャンセル、Ctrl+Z で頂点を 1 つ戻す
  - 消しゴム / 隠蔽加工 / `local_adjust_lab` で同じ操作感に揃える
- マスクの拡張 / 縮小 / スムーズ
  - `local_adjust_lab` では手動マスクのビットマップ本体に対する `拡張 +1`、
    `縮小 -1`、`スムーズ` ボタンとして試す。レイヤー側の非破壊 `mask_expand_px` /
    `mask_feather_px` とは別に、手修正用の破壊的な編集操作として扱う
- 境界で止まりやすいブラシ
  - 初期実装は `local_adjust_lab` の `境界筆 [A]` として、ストローク開始点の色に近い
    ピクセルだけをブラシ円内で塗る方式にする。全画面 flood fill は行わず、影響範囲を
    ブラシ周辺に閉じる
  - ブラシ円内で開始点から連結している近似色だけを塗り、画像エッジを通行止めとして扱う。
    近似色が境界の向こう側にあっても、連結していなければ塗らない
  - 内部描線などが境界判定されて塗り漏れる場合に備え、`Ctrl` 押下中は境界判定なしの
    通常筆として動かす。`Ctrl` 押下中でも境界の強調表示は維持し、抜けた箇所を確認しながら
    通常筆で補えるようにする
  - `境界線を含む` オプションを持たせる。オンのときは、境界筆で塗れた領域に接している
    検出境界だけを少し追加 / 除外する。ブラシ円内の境界を一括処理する独立ツールより、
    操作対象を予測しやすくする
- ラフに置いた線や点の境界吸着
  - 多角形ツールではクリック候補点を常時表示する。`Ctrl` 押下中は候補点自体を
    近傍の強い境界へ吸着し、クリック前に追加位置を確認できるようにする
  - 吸着半径は画像ピクセルではなく画面 px として扱う。ズーム時に探索範囲が画面上で
    不自然に膨らまないよう、内部で画像座標へ換算してから探索する
  - 吸着候補は境界強度だけでなくカーソルからの距離も強く評価する。遠い強境界へ
    飛ぶより、カーソル近傍の十分な境界を優先する
  - mIV 本体の画像フルスクリーンでは `Shift` 押しっぱなしがルーペなので、
    境界吸着 / 境界強調のモディファイヤは `Ctrl` を基本にする
- 境界候補の表示と補完
  - エッジ勾配だけでなく、周囲より暗い線 / 周囲より明るい線の内部も境界候補に含める。
    黒髪に白線、明るい髪に濃い線など、線色の方向が逆でも拾えるようにする
  - `Ctrl` 押下中は同じエッジ判定を画像上に強調表示し、どの境界が対象になるか
    事前に確認できるようにする
  - 強調表示は水色固定にせず、画像色に埋もれにくいマゼンタ〜黄色系のアニメーション色と
    暗色下地で表示する
  - 検出境界に 1〜2px 程度の小さい途切れがある場合は、`境界ギャップ補完` で穴埋めして
    連続した境界として扱う
  - `境界追加` / `境界除外` の独立ツールは試作上の検証用に留め、通常 UI からは外す。
    追加 / 除外の使い分けは、境界筆の描画 / 消去と `境界線を含む` オプションに寄せる
- 隙間補完ブラシ
  - `隙間補完 [G]` として、左右または上下を既存マスクに挟まれた細い未塗り部分を
    指定幅内で補完する。境界筆で残る数 px の空白を手早く埋めるための補助ツール

ビットマップマスクの破壊的な調整は、別見出しにせずビットマップツール直下へ置く。
`1px 拡張` / `1px 縮小` は、粗く塗った後に少し太らせて手で削る用途があるため残す。
`スムーズ` は 2 値マスクの方針と重なるので削除し、境界を柔らかくする用途は
レイヤー側の非破壊 `ぼかし境界` に統一する。
AI イラストでは、線にグラデーションが入る、線色が均一でない、塗りと線の明度差が小さい、
内部描写が境界に見える、といった条件が重なりやすい。このため、決定的アルゴリズムだけで
常に「意図した線」だけを精密に拾うのは難しい。境界筆は精度を上げ続けるより、境界表示、
通常筆への一時切り替え、隙間補完、`境界線を含む` のような予測しやすい手修正導線を重視する。
境界筆側は境界近傍の余白を取りすぎないよう、エッジ判定そのものの画素だけを通行止めにして、
境界ぎりぎりまで塗れる方向に調整する。

レイヤー追加時にマスク種類を選び、追加後はマスク種類を直接切り替えない。
既存マスクが予告なく消える事故を避けるため、種類変更ではなく「新規レイヤー追加」または
「レイヤー複製後に加工内容を変更」で対応する。
追加ダイアログは画面中央付近に表示し、主パネルや右パネルの裏に潜らないようにする。

`元画像表示` と `選択マスク表示` は確認頻度が高いため、補正パネルでは処理順の下に置き、
試作では `Q` / `W` をショートカットにする。切り取りパネルではマスク表示切替は出さず、
crop 外の暗転を常時表示する。3 種類程度のマスクカラープリセットは `表示:` 行の右側に
小さいボタンとして置き、ピンク系の画像でも見分けやすい色へ切り替えられるようにする。
レイヤーは一覧上で一時的に有効 / 無効を切り替えられるようにする。
Undo / Redo は `Ctrl+Z` / `Ctrl+Y` / `Ctrl+Shift+Z` をサポートする。
大きい画像ではビットマップマスクのスナップショットが重くなるため、Undo / Redo の保持数は
画像サイズに応じて制限する。境界検出は合成画像の単体テストで、黒線 / 白線 / 小さい検出穴の
補完を検証し、境界筆の `境界線を含む` が線幅の数倍に太る退行を防ぐ。
試作 UI は、左パネルを「選択と一覧」、右パネルを「選んだもののパラメータ」に分ける。
左パネルには処理順、補正パネル用の表示切替、レイヤー一覧、
加工内容の種類、手動マスクのツール選択を置く。レイヤー名編集や選択中レイヤーの個別ブロックは置かず、
有効 / 無効はレイヤーカード左上のチェックボックスで扱う。右パネルには筆サイズ、境界しきい値、
マスク反転 / 不透明度 / 拡張 / フェザー、
グラデーション / 範囲マスクの数値、加工内容のスライダーを置く。
レイヤー一覧は有効チェック、マスクサムネイル、マスク種類、加工内容を表示し、
スクロールせずに対象レイヤーを選び直せるようにする。

補正レイヤーのモザイクは、既存の隠蔽加工と文言・考え方を揃える。タイルサイズは
長辺比率 / 固定 px の 2 モードを持ち、プリセットは長辺比率 0.5 倍 / 1 倍 / 2 倍を
起点にする。境界処理は隠蔽加工と同じく、`マスクを含むタイルを不透明で描画` /
`マスクを含むタイルをマスクの割合に応じた不透明度で描画` / `マスクの形に沿って描画`
を選べるようにする。`マスクを含むタイルを不透明で描画` では、タイル境界を維持するため
補正レイヤー側でもマスク外へモザイクが広がる専用合成を使う。

1792x2304 程度の画像でも操作追従を優先するため、ドラッグ中は補正の最終結果レンダーを
開始しない。マスクプレビューのフル解像度テクスチャ更新も一定間隔で間引き、ポインタ操作が
止まってから高精度表示へ追いつかせる。
最終結果レンダーの再チェックは 90ms 程度でよいが、筆のマスクプレビュー更新は 60fps を狙える
16ms 程度の間隔に分ける。両者を同じ throttle 値にしない。
通常筆、境界筆、隙間補完は、前回ポインタ位置から現在位置までをブラシサイズに応じた間隔で
補間してスタンプする。高速ドラッグ時に円形スタンプが飛び飛びになるのを避けつつ、
境界筆では 1 フレームあたりの補間数に上限を設けて応答なしを防ぐ。
素早い円描画では入力点同士が遠く、直線補間だけだと多角形状になりやすいため、
直近 3 点を使った Catmull-Rom 補間でストロークを滑らかにする。
通常筆は円内判定を全ピクセルで行わず、行ごとの塗り範囲に変換して処理する。複数スタンプを
1 入力イベント内で処理した場合も、`dirty` 通知とプレビュー更新要求は最後にまとめる。
ライブストローク表示は、実際に確定したマスクと見分けにくくなるため採用しない。
境界筆は、ツール選択時または `Ctrl` 境界表示時に、現在のしきい値に対応したフル解像度の
境界マップを準備して使い回す。しきい値やギャップ補完を変更した場合は再生成する。
性能調査は大量ログではなく、準備時間やマスク更新時間のような小さい計測値をステータス表示や
開発用表示へ出す方針にする。原因を絞るまではログを常時吐かない。
筆のカクつき調査では、`target/local_adjust_lab_perf.log` に 1 秒ごとの統計を出す。
ログはフレームごとの全イベントではなく、`input/frame`、`stamps/frame`、
`input_gap_px_max`、ブラシ処理時間、マスク評価 / テクスチャ更新時間、再合成時間の集計にする。
また、同一フレーム内に届いた `PointerMoved` を処理し、1 フレーム 1 点だけでストロークを
作らないようにする。
マスクプレビューは 1 枚のフル解像度テクスチャを毎回更新せず、256px 程度のタイルに分ける。
筆ストロークでは変更範囲にかかるタイルだけを更新し、全画面の `texture.set` による 20〜50ms
級の停滞を避ける。
高速ストローク時は、外接矩形に含まれる全タイルではなく、実際にブラシが触れたタイル集合だけを
更新する。ログには `mask_tiles/update` を出し、タイル更新数と `mask_texture_ms` の相関を見る。
さらに、手動マスクで `拡張/縮小` と `ぼかし境界` が 0 の場合は、フル解像度の
`evaluate_layer_mask` を通さず、変更タイルだけをレイヤーの `RasterVectorMask` から直接評価する。
これにより筆ドラッグ中の固定 10ms 程度のマスク評価コストを避ける。

AI 自動検出よりも、ユーザーの意図した範囲を狭く安全に作れることを優先する。
セグメンテーションは「自動で完璧に確定する」機能ではなく、マスク作成の出発点として扱う。

## 7. 永続化案

補正レイヤーは容量が大きくなりやすく、ユーザーが時間をかけて調整するデータでもある。
そのため、まずは画像ファイルと一緒に移動しやすいサイドカー保存を第一候補にする。

サイドカー案:

- 通常画像 `foo.png` に対して `foo.png.miv` を同じフォルダに作る。
- ファイル名全体に `.miv` を付けることで、`foo.png` / `foo.jpg` が同じフォルダにあっても衝突しない。
- JSON 形式にし、数値パラメータや効果は読みやすく保存する。
- 手動マスク、追加マスク、削除マスクは 2値として 1bit/pixel に packed し、deflate + base64 で保存する。
- 被写体マットのようなソフトマスクは 8bit alpha に量子化し、deflate + base64 で保存する。
- 領域分割ラベルは u32 little-endian 配列を deflate + base64 で保存し、選択状態は別配列で持つ。

DB 案は、将来本体に統合するときの高速検索 / 一括管理 / 仮想フォルダ対応用として残す。

候補:

- `local_adjust_db.rs`
- `%APPDATA%/mimageviewer/local_adjust.db`

テーブル案:

```sql
CREATE TABLE local_adjust_layers (
    page_path TEXT NOT NULL,
    layer_id TEXT NOT NULL,
    z_index INTEGER NOT NULL,
    enabled INTEGER NOT NULL,
    name TEXT NOT NULL,
    opacity REAL NOT NULL,
    mask_inverted INTEGER NOT NULL,
    mask_expand_px REAL NOT NULL,
    mask_feather_px REAL NOT NULL,
    mask_width INTEGER NOT NULL,
    mask_height INTEGER NOT NULL,
    mask_blob BLOB NOT NULL,
    vectors_json TEXT NOT NULL,
    mask_source_json TEXT NOT NULL,
    effect_json TEXT NOT NULL,
    PRIMARY KEY (page_path, layer_id)
);
```

`page_path` の正規化は `adjustment_db::normalize_path` と同じ規則に揃える。
ZIP / PDF ページのキーも既存のページキー生成に合わせる。

`mask_blob` は最終的な raster alpha mask の保存またはキャッシュとして使う。
`vectors_json` は手描き / ポリゴン系の編集情報、`mask_source_json` はグラデーション、
輝度 / カラー範囲、被写体選択、領域分割などのパラメータを保存する。
合成時は `mask_source_json` から必要なら raster alpha mask を再生成し、既存の mask pipeline に流す。

サイドカーバックアップ `mimageviewer.dat` には、将来的に `local_adjust_layers` 相当の
配列を追加するか、画像単位の `.miv` サイドカーを正式採用するかを本体統合時に判断する。
`local_adjust_lab` では先に `foo.png.miv` 形式を実装して、容量と復元性を検証する。

## 8. キャッシュ案

新しい表示優先順位:

```
conceal_cache
  > local_adjust_cache
  > erase_result_cache
  > adjustment_cache
  > ai_upscale_cache
  > fs_cache
```

ただし、隠蔽加工の合成入力は `local_adjust_cache` を優先する。

```
local adjust source:
  erase_result_cache > adjustment_cache > ai_upscale_cache > fs_cache

conceal source:
  local_adjust_cache > erase_result_cache > adjustment_cache > ai_upscale_cache > fs_cache
```

### 8.1 無効化

| 変更 | local_adjust_cache | conceal_cache |
| --- | --- | --- |
| 全体補正変更 | クリア | クリア |
| AI denoise / upscale 結果変更 | クリア | クリア |
| 消しゴムマスク変更 / 補完結果変更 | クリア | クリア |
| 補正レイヤー変更 | クリア | クリア |
| 隠蔽加工変更 | 残す | クリア |
| 最後段 crop 変更 | 残す | 残す |
| 回転変更 | 残す | 残す |

補正レイヤーは隠蔽加工より前段なので、補正の変更は隠蔽加工の表示結果にも影響する。
そのため `local_adjust_cache` と `conceal_cache` の両方を stale にする。

最後段 crop は `local_adjust_cache` / `conceal_cache` の内部画像を変えず、表示または書き出し時に
切り出すだけにする。この場合、crop 変更は crop preview / export のみを更新し、上流 cache は
残せる。

## 9. パフォーマンス方針

色調補正は LUT で軽いが、複数レイヤー・フェザー・ぼかし・ソフトフォーカスはフル解像度では
重くなる。UI 応答性を守るため、次を基本にする。

- レイヤー効果はマスクの bbox と効果半径ぶんだけ処理する。
- ぼかしやソフトフォーカスは separable blur を使う。
- Look / LUT、Bloom、粒子、ハーフトーン、スクリーントーン、エッジ保持ぼかしなどの仕上げ系は、全体画像補正ではなく
  補正レイヤー側へ置く。サムネイルには反映せず、表示 / 書き出し用の worker で処理する。
- UI 操作自体を妨げないことを優先する。表示への反映が数百ミリ秒遅れることは許容し、
  操作中の入力、ドラッグ、パネル描画を止めない。
- 高速化のためにパイプラインを過度に複雑化しない。まずは「シンプルな再計算 + 非同期化 +
  古い結果の破棄」で成立させる。
- 全体補正のドラッグ中は、重い補正レイヤーと隠蔽加工の再合成を debounce し、release または
  短い idle 後に最新パラメータだけを再合成する。必要なら暫定表示は上流補正のみでよい。
- 重いレイヤー合成は worker 化する。UI スレッドで同期実行する場合は、軽い効果に限定する。
- worker の結果には generation を持たせ、古い合成結果が遅れて返ってきても採用しない。
- パラメータ変更で新しい generation が発生した場合、実行中 worker にはキャンセルフラグを立てる。
  generation 破棄は古い結果の採用防止、キャンセルはメディアンなど重い効果の待ち時間削減として
  別に扱う。行単位やタイル単位で進められる重い効果は、処理ループ内でキャンセル確認と進捗通知を
  行い、左パネルのステータスに `メディアンフィルタ 30%` のような効果名 + 進捗率を表示する。
- 再合成や反映待ちは、ステータス文字列だけでなく左パネル上部の常時見えるインジケータで示す。
  `再合成中`、`反映待ち`、`マスク更新`、`最新` を色付きの `●` で表示し、処理遅延が仕様通りで
  あることをユーザーがすぐ判断できるようにする。
- 右側のレイヤーパネルに `選択レイヤーまでプレビュー` を用意する。オンの間は表示用再合成を
  選択レイヤーまでで止め、後続の重いレイヤーを一時的に省略して調整できるようにする。
  保存時はこのプレビュー制限を使わず、全レイヤーで再合成して書き出す。
- PDF ズーム再レンダリングや AI アップスケールでソース解像度が変わる場合、マスクを一度だけ
  ソース解像度へリスケールする。

## 10. 実装フェーズ

### Phase 1: 全体補正の拡張

- `AdjustParams` に明瞭度 / 柔らかさ、必要ならソフトフォーカスを追加。
- ハイライト / シャドウ補正を追加する。
- `apply_adjustments_fast` に実装。
- 補正パネルにスライダーを追加。
- サムネイル補正にも乗るよう `is_color_identity()` を更新。

### Phase 2: マスク機能強化

- `mask_lab` のクリックポリゴン、境界吸着、境界停止ブラシ、境界追加 / 除去ブラシを評価。
  最終 UI では追加 / 除去の独立ツールを境界筆オプションへ統合する。
- 本体の消しゴム / 隠蔽加工の共通マスク UI へ移植する。
- 拡張 / 縮小 / スムーズを本体 UI に追加する。
- 線形 / 円形グラデーションマスクを追加する。
- 輝度 / カラー範囲マスクを追加する。

### Phase 3: 補正レイヤーの最小実装

- `local_adjust_db.rs` を追加。
- `LocalAdjustmentLayer` / `LocalEffect` を定義。
- `local_adjust_cache` を追加。
- 効果なし、色調補正、ぼかし、ソフトフォーカスの 4 効果を実装。
- マスク反転、フェザー、拡張 / 縮小、透明度を実装。
- フルスクリーン UI にレイヤー一覧と編集 UI を追加。

### Phase 3b: 仕上げ系レイヤー効果

サムネイルに反映しない補正レイヤー側へ、重めの仕上げ効果を追加する。

- Look / LUT: 内蔵プリセット + 強度。外部 `.cube` は後続候補
- Glow / Bloom
- ビネット
- フィルム粒子 / ノイズ追加
- Orton / Soft Glow
- 色収差
- ハーフトーン / 漫画調 / 印刷風 / スクリーントーン
- エッジ保持ぼかし / 滑らか化

実装順は、見た目の価値が分かりやすく実装リスクが低いものから始める。
推奨順は Look / LUT、Bloom、ビネット、フィルム粒子、色収差、ハーフトーン、
エッジ保持ぼかし。

プロトタイプでは `local-adjust-core` と `local_adjust_lab` に、内蔵 Look、Bloom、
ビネット、フィルム粒子、色収差、ハーフトーン、スクリーントーン、カラーハーフトーン、テクスチャライザ、エッジ保持ぼかし、Orton / Soft Glow を追加済み。
Orton / Soft Glow は Soft Focus と Bloom とは別に、ボケコピーの明るさ、コントラスト、彩度を調整できるルック寄りの専用効果として扱う。

### Phase 4: 被写体選択 / 領域分割マスクの検証

- 被写体選択は foreground matte 型モデルを追加ダウンロード方式で検証する。
- 候補モデルのライセンス、サイズ、ONNX / DirectML 実行可否を確認する。
- 領域分割は色差 / 境界 / 連結領域のクラシック方式を AI イラストでチューニングする。
- AI / SAM 系の複数候補型領域分割は、実験結果が弱かったため v1.1.0 では採用しない。
- 生成結果は通常マスクへ変換し、追加 / 削除マスクで手修正できるようにする。

### Phase 5: 書き出し連携と polish

- Ctrl+E 書き出しが補正レイヤーを含むようにする。
- Undo / Redo に補正レイヤー操作を乗せる。
- レイヤー複製、上下移動、名前変更、ON/OFF を整える。
- 必要ならスロットやプリセットを追加する。

### Phase 5b: 最後段 crop preview / export crop

- crop rect を source image coordinate で保存する。
- 切り取りパネル表示中は crop 外を常に暗くする overlay を表示する。
- 書き出し時は、隠蔽加工まで反映した最終画像に crop を適用する。
- `local_adjust_cache` / `conceal_cache` は crop 変更で破棄しない。
- 途中 crop や水平補正は、この段階では実装しない。
- UI は補正レイヤーとは別の「切り取り」パネルにする。有効 / 編集のトグルではなく、
  リセット、比率 (維持 / 自由 / 16:9 / 3:2 / 4:3 / 1:1 / 3:4 / 2:3 / 9:16)、
  X / Y / W / H の数値入力を置く。全体サイズと同じ crop rect は切り取りなしとして扱う。
  切り取りパネル表示中は crop 外を常に暗くし、全体状態からは画像内ドラッグで新しい
  crop rect を作れるようにする。

### Future: crop / ジオメトリ系の非破壊編集

crop は投稿前の軽い仕上げとして価値が高い。特に Look / Bloom / 粒子などの仕上げ系レイヤーを
整備すると、「最後に構図を詰めたい」需要が強くなる。

ただし、crop は画像サイズと座標系を変えるため、補正レイヤーより影響範囲が大きい。

#### 案 A: パイプライン途中に crop を入れる

例:

```text
元画像
  -> AI denoise / upscale
  -> 全体画像補正
  -> ポストフィルタ
  -> 消しゴム / 補完
  -> crop
  -> 補正レイヤー x N
  -> 隠蔽加工
  -> 表示 / 書き出し
```

利点:

- crop 後の画面だけを見ながら、補正や隠蔽加工を作れる。
- crop 後解像度で重い補正を走らせられる。

問題:

- crop 変更時に、補正マスク、グラデーション、セグメンテーション結果、隠蔽マスクを再投影する
  必要がある。
- crop 前に作った消しゴムマスクと、crop 後に作る補正 / 隠蔽マスクで座標系が分かれる。
- DB 保存、サイドカー、Undo、キャッシュキーに crop transform を含める必要がある。
- crop を後から広げた場合、crop 外に存在しなかった downstream マスクをどう扱うか判断が必要。
- ZIP / PDF ページ、見開き、比較表示、右 Ctrl 元画像プレビューの扱いが複雑になる。

途中 crop は柔軟だが、v1.1.0 の実装量としては重い。やるなら、全マスクと表示座標を
「source image coordinate + transform」で扱う共通座標変換層を先に作る必要がある。

#### 案 B: 最後段の非破壊 crop にする

例:

```text
元画像
  -> AI denoise / upscale
  -> 全体画像補正
  -> ポストフィルタ
  -> 消しゴム / 補完
  -> 補正レイヤー x N
  -> 隠蔽加工
  -> crop
  -> 表示 / 書き出し
```

利点:

- crop 直前まで内部画像サイズを変えないため、既存パイプライン、マスク DB、隠蔽加工、cache の影響が
  最小になる。
- crop rect は source image coordinate の矩形として保存すればよい。
- crop 変更時も upstream の補正やマスクを再計算・再投影しなくてよい。
- 表示時は crop overlay / crop preview、書き出し時は最後に切り出し、という単純な実装にできる。

問題:

- crop 後の構図だけを見ながらマスク編集したい場合、UI 上は crop 外を隠す preview 表示が必要。
- crop 後解像度で重い補正を軽くするメリットは得られない。
- crop 外にある隠蔽加工や補正も内部的には計算されるため、処理効率だけ見れば無駄がある。

#### 案 C: 破壊的 crop ツールとして別画像保存

利点:

- 実装が最も単純。
- crop 後の画像を新しい入力として扱えるため、既存 pipeline への影響はほぼない。

問題:

- 作業が分断される。
- crop 前に行った補正やマスクを再利用しづらい。
- ユーザー体験としては、軽い仕上げ用途には不便。

#### Codex 推奨

v1.1.0 では、まず案 B の「最後段の非破壊 crop」を推奨する。

- 内部パイプラインの解像度は最後まで変えない。
- crop rect は source image coordinate で保存する。
- 切り取りパネル表示中は crop 外を常に暗くし、crop 範囲を確認しながら調整できるようにする。
- 書き出し時は隠蔽加工まで反映した最終画像に crop を適用する。
- crop 外を暗くする overlay と、crop 内だけへズームする preview mode を用意する。

この形なら、パイプライン途中で解像度が変わらないため、v1.1.0 の補正レイヤー実装を
大きく複雑化せずに crop 需要へ応えられる。将来、crop 後解像度での編集や水平補正まで
扱いたくなった段階で、案 A の transform layer 方式を検討する。

## 11. 検証項目

- 全体補正のみの既存画像が v1.0.0 と同じ順序で表示される。
- 消しゴム結果の上に補正が乗る。
- 補正の上に隠蔽加工が乗る。
- マスク反転 ON/OFF で保存マスク自体は変化しない。
- 補正を変更すると `conceal_cache` も更新される。
- 大きい画像でスライダー操作中に UI が固まらない。
- ZIP / PDF ページでもキー生成と保存が既存補正と同じ規則になる。
- 右 Ctrl の元画像プレビューで、補正レイヤーも一時的に外れる。
- 書き出し結果が表示結果と一致する。
- 最後段 crop を変更しても `local_adjust_cache` / `conceal_cache` は破棄されず、
  crop preview と書き出し範囲だけが変わる。
- crop preview ON の状態でも、内部マスク座標は source image coordinate のまま扱える。

## 13. プロトタイプ実装

本体統合前の検証用として、以下を追加した。

| パス | 役割 |
| --- | --- |
| `crates/local-adjust-core/` | mIV 本体と試作ツールの両方から呼べる補正レイヤー合成 core |
| `tools/local_adjust_lab/` | JPEG / PNG 1 枚を D&D または CLI 指定で読み込み、補正レイヤーを試す軽量アプリ |

`local-adjust-core` の境界は次の形に固定する。

```text
RGBA image + ordered LocalAdjustmentLayer list -> same-size RGBA image
```

初期実装済み:

- 複数補正レイヤー
- マスク反転 / 拡張縮小 / フェザー / 透明度
- マスク生成元: Full / Raster / Linear Gradient / Radial Gradient / Luma Range / Color Range / Subject / Segmentation
- `local_adjust_lab` の被写体選択は、任意配置の `tools/local_adjust_lab/models/u2netp.onnx`
  を使って U²-Netp の被写体 / 背景マスクを worker thread で生成する初期実装まで接続済み。
  新規生成 / 再生成にはモデルが必要だが、生成済みマスクは `.miv` sidecar に保存されるため、
  モデル未配置環境でも読み込み、編集、適用は継続できる。生成結果は `Subject(SubjectMask)`
  として保持し、背景選択はマスク反転で扱う。
  `SubjectMask` は現在の alpha に加えて生成直後の soft matte も保持し、切り抜き向け整形の
  `マスクを整形` チェックが ON のときだけ、しきい値 / 収縮拡張 / 境界なめらかスライダーで
  その元 matte から現在 alpha を再生成する。OFF に戻すと元 matte へ復帰する
- `local_adjust_lab` の領域分割は、色差 / 境界 / 連結領域による候補生成を worker thread で行う。
  生成結果は `Segmentation(RegionMask)` として保持し、生成直後は未選択にする。未選択候補は
  アニメーションする境界線だけで表示し、クリック / ドラッグで個別に選択 / 解除できる。
  被写体選択マスクがある場合は、被写体内または背景だけを領域分割できる。
  境界線などで未所属になった内部ピクセルは近い領域へ割り当て、隣接領域を複数選んだときに
  マスクの隙間が残りにくいようにする
- `local_adjust_lab` では、外部 SAM 候補マスク読み込みと SAM2 Hiera Tiny 直接実行の
  試験経路をいったん実装したが、AI イラストで期待する意味単位の領域分割にならなかったため
  削除した。失敗内容と再導入条件は [ai-region-segmentation-retrospective.md](ai-region-segmentation-retrospective.md)
  に残す
- 効果: Tone (自然な彩度・tint を含む) / Tone Curve / RGB Curve / Color Balance /
  3-way Color Grading / Selective Color / Part Color / Channel Mixer / Color Mixer / Clarity / Highlights-Shadows /
  Texture / HighPass / Blur / Motion Blur / Wind / SpeedLines / Tilt Shift / Lens Blur / Radial Blur / WaveDistortion / HeatHaze / PinchSpherize / Twirl / PolarCoordinates / GlassDisplacement / LensCorrection / LineExtract / ColorTrace / ArtisticMedia / BrushStroke / Cutout / ToonShade / Emboss / PixelStylize / Solarize / GlowingEdges / OilPaint / Soft Focus / Orton / Mosaic / Sharpen(radius/threshold) / SmartSharpen(edge-aware) / HSL / Dehaze / Look / 3D LUT / Posterize / Threshold / Invert / Duotone / Equalize / Gradient Map / ColorFill / OutlineStroke / RimLight / ContactShadow / ColorOverlay / NeonGlow / DiffuseGlow / Bloom / Halation / ColorDodgeGlow / GodRays / LensFlare / Anamorphic Flare / CloudFog / WaterCaustics / ParticleOverlay / Aurora / Spotlight /
  Vignette / Film Grain / Chromatic Aberration / Defringe / Scanline Glitch / VHS / Pixel Sort / Old Film / Halftone / ScreenTone / ColorHalftone / CmykPlateShift / Textureizer / Cross-Star Glow /
  Edge-preserving Smooth / Median
- 3D LUT は `.cube` の `LUT_3D_SIZE` / `DOMAIN_MIN` / `DOMAIN_MAX` / `LUT_3D_INPUT_RANGE` を読み取り、RGB 3D table
  をレイヤー設定に保持する。ファイル読み込みは worker thread で行い、UI スレッドでは重い I/O
  をしない。設定保存時は LUT データも含まれるため、外部 LUT ファイルが移動しても効果は再現できるが、
  大きな LUT では sidecar が大きくなる点に注意する
- `local_adjust_lab` には自作の小さな `.cube` サンプル LUT を `tools/local_adjust_lab/sample_luts/`
  に置き、LUT 読み込みと強度調整をすぐ試せるようにする
- Selective Color は、対象色相スライダーに加えて画像上クリックのスポイトで対象色相を設定できるようにする
- 加工内容はプルダウンではなく、左パネルの現在効果表示 + `効果選択` ボタンで扱う。
  `効果選択` はグループ別のダイアログを開き、効果ボタンのホバーで説明を表示する。
  グループは効果数の増加に合わせ、色調補正 / 色変換・ルック / ぼかし・フォーカス /
  シャープ・ディテール / 変形・歪み / 表現・絵画調 / 光・雰囲気などへ細分化する。
  フィルタ数が増えても選びやすくするため、詳細方針は [local-adjust-filter-candidates.md](local-adjust-filter-candidates.md)
  の UI 方針に合わせる
- 各効果は選択直後になるべく無加工になる default とする。実用値は「プリセット」ボタンで投入し、
  個別のスライダーやプリセットで調整する。加工内容が効果なしの間はリセットを出さず、
  効果選択後だけ「リセット」で default に戻せるようにする
- Look は未選択状態を `選択してください` として持ち、強度の default は 1.0 にする。
  これにより、効果選択直後は見た目を変えず、夕焼けなどのプリセットを選んだ時点で
  すぐ効果が出るようにする
- ColorFill も未選択状態を `選択してください` として持ち、不透明度 default は 1.0 にする。
  これにより、効果選択直後は見た目を変えず、単色 / 線形 / 円形の形状を選んだ時点で
  すぐ塗りつぶし結果を確認できる
- Tone Curve はまず RGB 共通の固定 5 点カーブ + プレビューで実装し、チャンネル別カーブは後続候補。
  Dehaze は Dark Channel Prior の考え方を軽量化し、白っぽさ低減と局所コントラスト寄りの仕上げ効果として扱う。
  Cross-Star Glow は明部抽出 + 方向性の減衰ブラーで、光線本数と回転角を指定できる
  クロス/斜め X 字/6本/8本のレンズフィルター風の光条を生成する。白くなりすぎないよう
  明部しきい値は高めを基本にし、0.990 以上も微調整できるようにする
- `local_adjust_lab` 側で非同期再合成 + generation による古い結果破棄
- 最後段 crop preview / export crop を `local_adjust_lab` に追加。crop rect は source image
  coordinate で保持し、上流の補正レイヤーやマスク座標は変えず、保存時に最終結果だけを
  切り出す。試作 UI では切り取り専用パネル、crop 外を暗くする overlay、編集ハンドル、
  比率選択、数値入力を持つ
- `local_adjust_lab` の左パネルは mIV 本体の処理順検証として、消しゴム / 補正レイヤー /
  隠蔽加工 / 切り取り / 保存を切り替える。消しゴムと隠蔽加工はラボのコンパイル時間と
  検証範囲を抑えるため、実処理なしのダミーパネルに留める
- 読み込み直後は補正レイヤーを作らず、未加工状態から開始する
- レイヤー追加は効果種類を先に選ばせず、追加ダイアログのマスク種類ボタンを押した時点で
  選んだマスク種類 + `効果なし` の空レイヤーを作る。全体にかける仕上げ系フィルタを
  すぐ追加できるよう、`全体` を先頭に置く。ユーザーは範囲を作ってから加工内容を選び、
  試し替えできるようにする
- `全体` マスクは通常表示ではキャンバス上でベースマスクを塗りつぶし表示しない。全体に
  適用されることはレイヤー行とマスク設定で示す。`全体` では追加マスクは意味を持たないため
  追加マスクボタンを出さず、削除マスクだけを利用できるようにする。削除マスク編集中は
  全体ベースを薄く表示した上で編集対象を強調し、削除マスクが入った通常表示では
  最終マスクを表示する
- `local_adjust_lab` は上部メニューバーの `読み込み` から画像を開ける。直近 20 件の読み込み履歴を
  保存し、履歴項目を選ぶだけで再度開けるようにする
- レイヤー削除などの単発 UI 操作後も follow-up repaint を要求し、次入力を待たずに再合成する
- 線形 / 円形グラデーションは手動マスク内のオブジェクトではなく、独立した mask source として扱う。
  選択後の初回ドラッグで生成し、キャンバス上の線・ハンドルで編集できる
- スポイトは手動マスクのツールではなく、カラー範囲 mask source の対象色を画像クリックで取得する操作とする
- 手動マスクは、ブラシ、境界筆、境界線を含むオプション、囲み、多角形、直線、縦線、横線、矩形、楕円、選択、ハンドル編集、Ctrl+Z、
  Delete による選択オブジェクト削除、矢印キー移動、`[` / `]` 回転を `local_adjust_lab` へ移植中
- 多角形は、クリックで頂点を置き、始点付近クリック、右クリック、または Enter で確定する
  ビットマップ範囲選択として、消しゴム / 隠蔽加工 / `local_adjust_lab` に実装する。
  共通化の第一段階として、本体側は
  `manual_mask_tools` の頂点追加 / 確定判定ヘルパーを消しゴム・隠蔽加工の双方から呼ぶ
- パネルは既存の消しゴム / 隠蔽加工に寄せ、描画 / 消去、ビットマップ、オブジェクトの区分で
  操作できるようにする
- `local_adjust_lab` のパネルは本体と同じく画像上の `Area + Frame::popup` として表示する。
  画像のパン / ズームを入れ、大きい画像でも実際の編集感に近い状態で手動マスクを検証する
- 表示補助のモディファイヤは本体操作に寄せる。`Ctrl` 押下中は元画像を一時表示、
  効果パラメータを変更したときは結果確認を優先してマスク preview を自動で OFF にし、
  `Alt` 押下中はマスク preview の表示状態を一時反転する。`Shift` 押下中はカーソル周辺のルーペを出す
- 試作段階では、セグメンテーションなど新しいマスク種類より先に、既存の消しゴム / 隠蔽加工と
  同等の手動マスク操作を完成させる。ここが共通部品化できると、後から直線囲みや境界補助を
  消しゴム / 隠蔽加工にも反映しやすい
- `*_local_adjust.png` 書き出し

起動:

```powershell
cargo run -p local_adjust_lab -- path\to\image.png
```

この段階では、既存の消しゴム / 隠蔽加工マスク DB とは接続しない。
マスクのコピーや既存機能への新マスク種類追加も行わず、補正レイヤー独立のマスクとして
操作感と効果の品質を検証する。

ただし、マスク UI の仕様は本体とずれないようにする。手動マスクは、補正レイヤー専用の
実装として閉じ込めず、消しゴム / 隠蔽加工でも置き換え可能な共通部品として育てる。
具体的には、bitmap alpha、編集可能オブジェクト、Undo snapshot、選択 / ハンドル編集の境界を
本体状態から独立させ、`local_adjust_lab` と mIV 本体の双方から同じ engine を呼べる形にする。
これにより、試作で調整した操作感を本体統合時に作り直す手戻りを避ける。
