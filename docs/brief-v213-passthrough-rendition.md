# ブリーフ: 通過表示の絵を「色まで合ったサムネイル」にする

## 前提 (必ず守ること)

- **アプリを起動しない**。ビルドとテストまでで止める。
- **git 操作をしない**。master の作業ツリーに未コミットのまま残す。統合はこちらで行う。
- **着手前に [docs/display-pipeline.md](display-pipeline.md) §2.5「ページ送り中の表示規則」を
  必ず読むこと。** ここが正本で、R1〜R4 とその出どころが書いてある。
  **この節に書いていない規則を推測で足さない。**
- 作業ツリーには `scripts/analyze_perf.py` / `scripts/test_analyze_perf.py` / `src/colorize.rs` /
  `docs/display-pipeline.md` の未コミット変更が別作業として入っている。**触らないこと。**

## 背景

ページ送りの通過表示は、カタログサムネイルをそのページの代役に使う最適化。しかし
**サムネイルはカラー化・色調補正の前の絵**なので、カラー化して読んでいると白黒のページが
混ざる (R2 違反)。2026-08-11 に実機で発覚し、判定側で辻褄を合わせようとして 3 回退行させた。

**方針を変える。判定を複雑にするのではなく、代役の絵そのものを忠実にする。**

実測 (`cargo test --release -p mimageviewer --lib thumbnail_effect_cost_measurement -- --ignored`):

| 寸法 | 色調補正 | カラー化 | うちぼかし |
| --- | ---: | ---: | ---: |
| 347×506 (実測サムネイル) | 0.24ms | **1.93ms** (最大 4.52) | 1.45ms |
| 800×1200 | 1.27ms | 6.09ms | 4.78ms |

キーリピート間隔は 34ms、現在の通過表示は 1〜2ms/フレーム。**ページごとに 1 回 2ms なら
十分収まる**。

## やること

### 1. 通過表示用の絵 (以下「通過レンディション」) を作る

カタログサムネイルに、**色の最終段だけ**を適用したもの。

- **適用する**: 色調補正 / Creative LUT / カラー化
- **適用しない**: 消しゴム / 隠蔽 / テキスト注釈 (§2.5.3 のとおり、最悪 1 秒以上かかるため
  意図的にスキップ)。AI アップスケールも不要 (サムネイル寸法では意味がない)

**⚠ 最重要: カラー化するかどうかの判断を、最終合成と一致させること。**
`ColorizeMode::MonochromeOnly` は「その絵が実質モノクロか」で決まる。通過レンディションと
最終合成で判断が食い違うと、**キーを離した瞬間に色が変わる** = R2 を別の形で破る。
フルサイズの判定材料 (`colorize_mono_summary_cache` / `edit_result_cache`) がまだ無い場合に
どうするかを設計し、**食い違わないことをテストで固定すること**。
サムネイルから判定する方式を採るなら、フルサイズ判定と同じ結論になることを示すか、
判定が確定するまでは通過表示を使わない (= 待つ) 側へ倒すこと。**推測で片方だけ実装しない。**

### 2. キャッシュする

`(idx, 適用した加工のキー)` で持つ。同じページを何フレーム描いても再計算しない。

- 既存の edit / effect key の仕組みを使う。**新しいキー体系を作らない**
- 上限を設けて LRU で解放する。先読み窓 (back 4 / forward 12) 程度を目安にする
- 加工パラメータが変わったら失効する。既存の失効フックに乗せる
  ([docs/preset-and-adjustment.md](preset-and-adjustment.md) のキャッシュ無効化規則を読むこと)

### 3. UI スレッドで同期計算する

ワーカー化・先読みはしない。ページごと 1 回 2ms のために機構を増やさない。

- **GPU アップロードはしてよい。** サムネイル寸法は実測 `upload_ms=0.003ms` で、
  `defer_ui_uploads` が避けているフルサイズの 21ms とは桁が違う。
  **`defer_ui_uploads` の対象に加えないこと** (加えると通過表示自体が動かなくなる)
- 実行時の空き状況で挙動を変えない。設定 (サムネイル寸法) だけで決まるようにする

### 4. 判定を §1.58 の形へ戻す

`page_turn_decision_for_inputs` から **`final_composite_available` を外す**
(`5a57a67b` で足したもの。代役が忠実になれば不要)。

```rust
let defer_ui_uploads = page_turn_input_pending && passthrough_rendition_ready;
let paint_source = if defer_ui_uploads { Thumbnail } else { Composite };
```

- `catalog_thumbnails_ready` は **`passthrough_rendition_ready`** に置き換わる
  (サムネイルがあり、かつ通過レンディションが用意できている)
- **`00d23a33` の 2 軸分離 (`paint_source` / `defer_ui_uploads`) は維持する。**
  1 つの真偽値へ戻さない
- 見開きは従来どおり表示単位の全ページで判定する

### 5. 後段の `waiting_for_colorize` は残す

通過表示に入らないフレーム (= 完成画像を描く経路) で、完成画像がまだ無いときに白黒
サムネイルへ落ちない仕掛けは引き続き必要。**消さないこと。**

## 完了条件 / 回帰テスト

- 純関数: `page_turn_input_pending` × `passthrough_rendition_ready` の 4 通りで
  `paint_source` / `defer_ui_uploads` を固定
- 通過レンディションに色調補正とカラー化が乗っていること (色が変わっていることを画素で確認)
- **通過レンディションと最終合成のカラー化判断が一致すること** (上の ⚠)
- 消しゴム / 隠蔽 / 注釈が通過レンディションに乗っていないこと
- キャッシュが `(idx, 加工キー)` で効き、パラメータ変更で失効すること
- 見開きで片方のページのレンディションが未用意なら単位全体が通過しないこと
- サムネイルが無いページは従来どおり待つこと
- `cargo fmt --check` / `cargo check -p mimageviewer --bin mimageviewer-core` が warning なしで通る
- `cargo test -p mimageviewer --lib page_turn` / `--lib colorize` が通る

## 検査

この修正の後、実機ログに対して次が exit 0 になること (別途こちらで実施する):

```
python scripts/analyze_perf.py <jsonl> page-turn --check
```

**注意**: 通過レンディションが用意できないページ (サムネイル無し) では `Composite` に
倒れるため、1 バースト内で描画元が混ざりうる。現在の I2 (混在禁止) はこれを違反と見なす。
**`page_turn_decision` の `reason` を見て、混在の理由が「レンディション未用意」の場合は
I2 を免除する**必要がある。`scripts/analyze_perf.py` の該当部分もあわせて更新すること
(このファイルは別作業の未コミット変更が入っているので、**その上に足す**形にする)。
