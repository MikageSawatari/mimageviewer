# 環境設定パネルのレイアウト指針

環境設定ダイアログは左にページツリー、右にページ内容を置く。右ペインは
`src/ui_dialogs/preferences.rs` の共通 `pref_panel` `ScrollArea` が管理し、
solid スクロールバーでバー領域を予約する。egui の既定 floating スクロールバーは
内容の上に重なるため、環境設定右ペインでは使わない。

## 開閉時の表示位置 (§1.365)

- 選択ページと右ペインの縦スクロール位置は App の `preferences_view_position` が
  アプリ実行中だけ保持する。設定 DB や一時編集 `PreferencesState` へ保存しない。
- 同じ所有者の `in_page` snapshot に、外部ツールの選択 ID と関連付け拡張子、
  フォントの絞り込み、メニュー/右クリック項目の展開、右クリックの確認場面、
  EXIF グループの折りたたみ、VST3 の絞り込みと音声入力なし候補の表示、左ツリーの展開を保持する。
  拡張子優先度と VST3 候補の入れ子一覧のスクロール位置も同じ snapshot に保持する。
  初期化は `ensure_preferences_state` の一箇所で行い、描画後・閉じ処理前に表示専用の値だけを捕捉する。
  外部ツールは確定済み一覧に ID が存在する場合だけ復元し、不在なら既存の初期選択
  （先頭、空一覧なら未選択）を使う。編集欄は確定済み設定から読み直し、破棄した値は復元しない。
  初回には snapshot がないため、関連付け拡張子など現在の文脈から決まる既存の既定値を保つ。
  外部ツールの選択/拡張子は、そのページの本文を実際に表示した後だけ記録する。
  未訪問のページや検索結果一覧の表示で、現在のファイル種別から決まる初期値を凍結しない。
- メニュー/右クリック項目の CollapsingHeader は owner の展開値を毎回 `open(Some(...))`
  で投影し、クリックだけで owner を更新する。egui の保存済み展開値を読み戻さない。
  ヘッダー ID は既存の表示世代に属し、閉じた編集セッションの ID を再利用しない。
  ScrollArea の ID 変更だけでは子 widget の ID は変わらず、`default_open` だけでは
  既存の egui 状態を上書きできない。OFF 後の再表示と再 ON は owner の既定値から始める。
  本件は通常の開閉操作を所有境界で修正する。まれな失敗は既定で割り切り（ログ＋通知、必要なら作り直し）、回復機構を加えない。
- 全体設定の「環境設定を開き直したときに前回の位置を復元する」は既定 ON。
  `Settings.preferences_restore_position` の ON/OFF だけを DB と設定転送へ保存する。
  OFF を OK で確定すると記憶位置を消し、OFF 中は記録せず、通常の入口は全体設定の先頭を開く。
  ON へ戻した後は全体設定の先頭から新しく記録する。チェック変更をキャンセルすると確定値を保つ。
  ページ内の表示状態も同じ ON/OFF に従い、OFF 確定時にすべて消す。
  明示的なページ/anchor 要求と検索結果ジャンプは ON/OFF にかかわらず優先する。
- 通常のメニュー・リング操作・キーボードからの入口は表示フラグだけを立て、
  共通の `ensure_preferences_state` / `show_preferences_dialog` が初期ページと位置を決める。
  設定取り込みなどで先に編集 state を作る場合も同じ初期化を通す。
  ツールバーの非表示件数チップなど特定項目への導線は明示的な open request を渡す。
- 新しい編集 state に右 ScrollArea の新しい ID を割り当て、初回描画で記憶した位置を一度渡す。
  明示的な `PreferencesOpenRequest` は、同じページを開く場合も先頭または指定 anchor を優先する。
  検索結果ジャンプは既存の anchor / 強調表示経路を使い、別ページのツリー選択は先頭へ戻す。
- ScrollArea 出力の、現在の本文・表示領域に収まる offset を閉じ処理より前に記録する。
  OK・キャンセル・×・Esc・追加パック導入への遷移のいずれでも、設定の保存・破棄から独立して
  ON 中は最後に表示したページ位置を保つ。検索結果一覧の offset は設定ページの記憶へ混ぜない。
- 復元は右 ScrollArea の共通描画経路で行う。遅延、再試行、DB 永続化は不要。
  入れ子一覧もそれぞれの ScrollArea の描画経路で位置を渡し、出力の補正済み offset を記録する。
  headless の実ダイアログ操作テストで開閉・ON/OFF・ジャンプ・内容/サイズ変化を確認する。
  外部ツールのパス確認 worker は待機中も再描画するため、選択/開閉のテストは固定フレームの
  `Harness::run_steps` で遷移を確認し、worker の完了や UI の静止を成立条件にしない。
- 設定値、未確定の入力、確認ダイアログ、結果メッセージ、検索結果/強調/移動要求は復元しない。
  別ダイアログの「操作カスタマイズ」の選択・録音/キー捕捉状態は対象外。
  既存の閉じる/新しい編集 state を作る経路を使い、編集 state 全体を保持する方式は採らない。
  表示だけを残せば、ワーカーや保存/キャンセルの組み合わせを増やさず復元できるため。

## 右ペインの基本ルール

- ページ実装は `ui.available_width()` の範囲内へ収める。
- 右端にボタン、`ComboBox`、削除 `×`、展開 `▼` などを置く場合も、ページ側で
  スクロールバー分の余白を追加しない。共通 solid スクロールバーに任せる。
- `ui.separator()` はそのまま使う。solid スクロールバーが本文幅を差し引くため、横線は
  スクロールバー手前で止まる。
- 横並びが長くなる行は `ui.horizontal_wrapped` を使い、固定幅の `TextEdit` は
  `ui.available_width()` からボタン幅を引いた値で `desired_width` を決める。
- `right_to_left` レイアウトで右端ボタンを置く場合、親 UI の content width を超える
  `min_width` や固定幅を指定しない。
- ページ内にさらに `ScrollArea` を入れる場合は、高さを限定した局所リストだけにする。
  ページ全体の縦スクロールは外側の `pref_panel` に任せる。

## 新規ページ追加時の確認

- ダイアログ幅を既定値付近と狭めた状態の両方で、右端の文字・ボタン・区切り線が
  スクロールバーに重ならないことを確認する。
- `pref_panel` のスクロールスタイルを floating に戻さない。新しい余白が必要に見える場合は
  ページ側の固定幅指定が `ui.available_width()` を超えていないかを先に確認する。
- ライト / ダークテーマで、弱い説明文とボタンラベルが読めることを確認する。
- 入力欄を追加するときは日本語 IME 中の Enter / Esc 挙動を既存ダイアログ helper に
  揃える。
- フォルダ走査、プラグイン scan、DB の大量削除など時間のかかる処理は UI スレッドで
  直接実行しない。ボタンは worker 起動や one-shot request の設定に留める。
