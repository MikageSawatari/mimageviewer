# v0.9.0 リリース修正タスク一覧 (統合版)

## 進行プロセス (各タスク共通)

1. **再検証**: タスク内容が現 HEAD で有効か Read/Grep で確認 (レビュー後に修正済みの可能性あり)
2. **設計**: 修正方針を本ファイルの該当タスク欄に追記
3. **設計レビュー**: `codex exec --sandbox read-only -o ...` で設計の第二意見
4. **実装**: 変更を入れて `cargo fmt` / `cargo build` / 該当テスト
5. **実装レビュー**: `codex exec --sandbox read-only -o ...` でコミット範囲レビュー、P 指摘対応

各タスクの完了マーク (`[x]`) は **実装レビュー** まで通過した時点で付ける。

## ステータス凡例

- 出典: `[C]` = Claude review, `[X]` = Codex review, `[C+X]` = 両者
- 検証: `[検証済]` = レビュー時に失敗経路確認済 / `[要検証]` = 追加確認必要
- 種別: `[Security]` / `[Data]` / `[Stability]` / `[Compat]` / `[Release]` / `[UX]` / `[Refactor]`

### T14 [P2→v0.10][Compat][C+X][検証済] EOF 状態が EngineActor に伝わらない 🛑 v0.10 延期
- 出典: Claude R1-2 + Codex R-VENG-002
- 場所: `src/video/decoder.rs:2840`, `src/video/engine/actor.rs:497`, `src/video/mod.rs:4135,4270`
- 問題: demux EOF は `clock.notify_eof_reached()` するが `DecoderEvent::EofReached` を送らず。`EngineActor` の `EofReached` ハンドラ + テストが死にコード。`engine_state_atomic` が EOF 後も `Playing` のままで perf/HUD 診断に影響
- **v0.10 延期理由** (Codex 設計レビュー 2026-05-16):
  - EngineActor::transition_to_eof は engine.state を Eof に遷移させると同時に `engine_state_atomic` を EOF に published する。EOF は `engine_state_parks_decode` で audio decode も park 対象 (`decoder.rs:151-152, 5031`) なので、demux EOF 直後に EofReached を発火すると audio decode thread が drain frames の送信を abort (`decoder.rs:5031`) → 末尾 50ms の audio が欠落
  - 正しい修正には「Eof state は audio drain 完了後にのみ遷移」する drain latch を engine に組む必要があり、AudioEvent::DrainComplete などの新シグナル + audio pump/RT callback の改修が要る (= state machine 拡張)
  - 一方、`OpenOptions.loop_enabled` は現状ハードコード `false` (`mod.rs:2981`) + `SetLoopEnabled` no-op (`actor.rs:342`) で、loop seek は VideoPlayer::tick / loop_target_secs が担当している。EofReached を発火してもループ動作は変わらない (= ユーザー影響なし)
  - HUD 診断の「Playing のまま」は単独 atomic を追加すれば回避できるが、v0.9.0 のリリースブロッカではない
  - 上記から v0.10 で「engine と clock/tick の EOF 主導権を一本化 + drain latch + AudioEvent::DrainComplete」をまとめて整理する方が安全
- [x] 再検証 (v0.9 範囲外と判定) / [ ] 設計 / [ ] 設計レビュー / [ ] 実装 / [ ] 実装レビュー
