# ブリーフ: 比較の準備中に 4×4 のプレースホルダが描かれる

対象: v2.13.0 出荷ブロッカー。実装 = Codex Sol / レビュー・検収 = ClaudeCode /
実機確認 = 利用者。

前提: master。着手前に `git log --oneline -3` で HEAD を確認すること。

---

## 1. 症状と原因 (実機ログで確定済み。再調査不要)

`Shift+C` の直後、および比較中にホイールでページを移した直後、**1 瞬だけ合成が画面いっぱいの
正方形に広がり、縦長ページの左右にはみ出す**。

`[compare-geometry]` ログ (利用者実機):

```
main Wipe target=3584x4608  draw=(747.5,0)-(1812.5,1369.3)   幅 1065   ← 正常
main Wipe target=3328x4864  draw=(811.5,0)-(1748.5,1369.3)   幅  937   ← 正常
main Wipe target=4x4        draw=(595.3,0)-(1964.7,1369.3)   幅 1369   ← 異常
```

**`target=4x4`** のペアが描画へ回っている。4×4 は 1:1 なので `compare_image_draw_rect` が
正方形いっぱいの矩形を返し、縦長ページより横に大きくなる。これが利用者の言う
「揃える前の状態が見えている」の正体。

**追加の切り分け (利用者、2026-08-10)**:

- `Shift+C` を押した**直後にも起きる**
- 画像を変えた後、`Shift+C` を**複数回押して切り替えると 2 回目以降は起きない**

→ **準備済みのペアがある場合は起きない = 新規に準備するときだけ縮退したペアが現れる。**

なお `ComparePreparedPair` を組む所 ([src/app.rs:26796](../src/app.rs) 付近) のサイズ検査は
**バイト長 = w×h×4 の整合しか見ていない**ので、4×4 でも通過する。

## 2. やること

1. **4×4 (縮退した / プレースホルダの) ペアがどこで作られているかを特定する。**
   `compare_prepared_pair` へ入る経路と、比較準備 worker が早期に返す結果の両方を見る。
   「初回だけ」「キャッシュがあると出ない」ことから、**新規準備の開始時に置かれる仮の値**の
   可能性が高い
2. **そのペアを描画に回さない。** 準備が完了していないことを型で表す
   (`Option` の有無や 4×4 という値を sentinel にしない。CLAUDE.md の「相互排他的な状態を
   field の有無を sentinel として表現しない」)。準備中は既存の「比較表示を準備中」表示と、
   通常のページ表示のままにする
3. **サイズの妥当性検査を足す**なら、バイト長だけでなく**元画像の寸法と整合するか**を見る。
   ただし検査で弾くのは二次的な保険であって、**本筋は縮退したペアを publish しないこと**

## 3. やらないこと

- `compare_image_draw_rect` や uv 窓の計算を変えること (ログで正しいと確認済み)
- 4×4 を特別扱いする分岐 (`if target == [4,4]`) を足すこと。**値ではなく状態で表す**
- 準備中に前のペアを描き続けること (それは前回直した「古い合成が出る」に戻る)
- 比較の union サイズ合わせ自体を変えること (仕様。利用者も理解している)

## 4. テスト

- 準備完了前の状態では合成を描かないことを、状態遷移テストで固定する
- 準備完了後に `target_size` が両画像の union になることを固定する (既存があれば流用)
