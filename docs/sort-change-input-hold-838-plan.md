- 第一候補は案 a (統括の指定)。案 a・b・c の比較は共有メモ `duration-762-ng-fix-material-20261121.md` §3-2。

## 1. 起きていること (コードから)

1. 並べ替えの変更は `apply_sort_control_change` (`src/ui_main.rs:8804`) から `apply_sort_change_reload*` (`src/app.rs:29073`) へ進む。
2. 物理フォルダでは、並べ替えの種類で経路が分かれる。
   - 長さ順: `PhysicalFolderSortReload::WorkerScan` (`src/app.rs:29187`)。worker で走査し、`folder_pane_open_pending` に `FolderOpenScanPurpose::CurrentViewOrderRefresh` の待ちを置く。
   - その他: `Immediate`。UI スレッドで同期の走査と採用をする (`src/app.rs:32333`)。
   - これは通常の並べ替えの入口 (`apply_sort_control_change`) の分け方。お気に入りの表示状態の反映・一括変換などは、長さ順以外でも WorkerScan を使う (`src/app.rs:95869`、`src/ui_dialogs/epub_batch_convert.rs:230`)。どの入口でも、物理フォルダの WorkerScan は同じ `CurrentViewOrderRefresh` の待ちになる。
3. WorkerScan の走査中も、一覧は前の順のまま操作できる。
   - キー: `handle_keyboard` (`src/app.rs:102325`) が前の `items` に効く。
   - クリック: `grid_item_input_allowed()` (`src/ui_main.rs:21195`) を通る。
   - その結果、「1 回目は前の順で効く」が起きる。
4. 走査結果の採用 (`apply_current_view_order_refresh`、`src/app.rs:62258`) は、items の差し替えと同じ呼び出しの中で sidecar restore を始める (`src/app.rs:32454` → `:26052`)。
   - sidecar restore の間は、`consume_input_during_sidecar_restore` (`src/app/sidecar_restore.rs:1342`) が入力を捨てる。
   - その結果、「2 回目以降は消える」が起きる。
5. 項目の入力の共有ゲート `grid_item_input_block()` (`src/filename_stack_ui.rs:2342`) は、キー・ポインタ・スクロール・ゲームパッド・メニュー・フルスクリーンを開く操作をまとめて止める。
   - 直接移動の走査 (`DirectNavigation`) は、すでにこのゲートで止めている。
   - 並べ替えの走査 (`CurrentViewOrderRefresh`) は止めていない。

壊れている前提: 「一覧の項目への入力は、利用者が見ている (これから見る) 順に対して効く」。並べ替えの要求から採用までの間だけ、これが成り立たない。

## 2. 修正 (案 a)

**並べ替えの走査を待っている間は、直接移動の走査と同じ共有ゲートで項目の入力を止める。**

- `GridItemInputBlock` に `ViewOrderRefreshScan` を足す。
  - 条件は `folder_pane_open_pending` の purpose が `CurrentViewOrderRefresh` であること。新しい bool・pending・時刻は持たず、既存の待ちから導く。
  - `direct_navigation_scan_pending()` と同じく `main_folder_history_available()` を条件にする。detached の context では成り立たない。
- 止めるのは、一覧の項目に対する入力だけ。
  - キー: `DirectNavigationScan` と同じ許可一覧にする。`handle_stack_refresh_keyboard` (`src/app.rs:59637`) で、Esc のスタック切り替えと `GridToggleStackMode` を通さない。戻る/進む・環境設定・再読み込みなどは通す。これらは、新しい走査・移動で待ちを置き換えるか、待ちに触れない。
  - ポインタ・スクロール・タッチ・右クリックメニュー・フルスクリーンを開く操作: 共有ゲートのまま止める。
- **項目に依らない操作は止めない (r2、レビュー P2-1・P2-2)。** 共有ゲートを使っているゲームパッドの次の 3 か所は、項目に依らない操作も一緒に止めている。並べ替えの待ちでは、これらを通す。
  - 左スティックのフォルダツリー移動 (`src/app/gamepad_input.rs:5032` のゲートが、`:5040` のツリーの分岐より前にある)。
  - グリッドのリングピッカーを開く操作 (`:5259`)。
  - ピッカーのプレビュー (`:6189`)。列数・並べ替え・サムネ比率・コンテナ評価は通し、アイテム評価だけ止める。
    - 並べ替えの行を通さないと、長さ昇順の走査中に降順を選んだとき、ピッカーの表示だけが降順になり、設定と要求は昇順のまま残る。採用時の sidecar restore がピッカーを確定せずに閉じるので、降順の選択が失われる。
  - アイテム評価は、プレビューだけでなく入力の入口で止める (r3、r2 のレビュー P2)。
    - 左右操作 (`src/app/gamepad_input.rs:6096`) と値一覧からの選択 (`:6570`、`:6649`) は、プレビューより前に評価値と dirty を変える。
    - 確定 (`commit_ring_picker_in_owner` → `finalize_live_picker_ratings`、`:7083`、`:7290`) は dirty な評価を再適用する。この書き込みは `apply_ring_picker_state_in_owner` のゲート (`:7475`) より前で、ゲームパッドのセッション終了 (`:4473`、`:4539`) からも届く。
    - そのため、待ちの間は両方の入口でアイテム評価の行の変更を受け付けず、draft と dirty を変えない。確定は待ちの間に新しい評価を書かない。
    - 待ちが始まる前に成功したプレビューの dirty・Undo の記録・終了処理は残す。確定全体を止めることはしない。
  - 判定は `GridItemInputBlock` の 1 つの方法 (例: `item_independent_controls_allowed()`) にまとめる。`ViewOrderRefreshScan` だけが真。
  - 既存の variant (直接移動など) の扱いは変えない。同じ制限が既にあるが、今回の範囲の外。
- 待ちの終わり方。
  - 成功・owner の不一致・エラー・切断・park は、既存の `take` で `None` になる。retire は bundle のキャンセルと drop で終わる (`src/app/viewer_context_registry.rs:3148`、`:3194`)。
  - 置き換えでは、ゲートは解けずに後続の要求へ引き継ぐ (レビュー P2-3)。
    - 旧要求は `src/app.rs:61675` で取り出され、後続の要求が同じ pending に置かれる (`:61793`)。
    - A→B の並べ替えなら遮断が続き、A の結果は採用しない。直接移動への置き換えなら `DirectNavigationScan` が引き継ぐ。
  - 導いた条件なので、張り付かない。
  - 採用と sidecar restore の開始は同じ呼び出しなので、ゲートから sidecar の遮断へ隙間なく移る。
- 待機表示: 直接移動の「移動先を読み込み中…」と同じ 500ms の猶予つきの表示を使う。文言は「並べ替え中…」。
  - 猶予は表示だけのためで、入力は要求したフレームから止める。既存の `direct_navigation_wait_overlay_delay` と同じ規則。
  - §1.911 段 6c: 主一覧はこの猶予の間だけ薄く描かず、入力の遮断は維持する。「並べ替え中…」が出ると従来どおり薄く描く。
    他の遮断理由の見た目と、子部品自身の disabled 表示は変えない。
  - 並べ替えの待ちには、今は表示が無い。ネットワーク共有などで走査が長いと、止まった理由が見えないため足す。
- popup の扱い (レビュー P3):
  - 並べ替えのメニューなどの popup は、ゲートでは閉じない。採用時の sidecar restore が閉じるのは今と同じ。
  - 項目の右クリックメニューは閉じる。持ち主の判定に共有ゲートを含めており (`src/ui_dialogs/context_menu.rs:989`)、不成立なら閉じる (`:1105`)。前の順の項目への操作を止めるという目的に合うので、そのままにする。
- 変えないもの:
  - Immediate の経路。
  - sidecar restore の遮断。
  - detached の述語・viewport の経路。

## 3. 状態の組み合わせを減らす検討

- 新しい状態を持たない。待ちの持ち主は `folder_pane_open_pending` の 1 つで、ゲートの条件はそこから導く。
- 直接移動の走査と、止め方・許可一覧・表示を同じ経路に揃える。
- 「保留したキーを採用後に再生する」(案 c) は採らない。再生は、他の保留や置き換えと組み合わさるため。
- 「手元の一覧をその場で並べ直す」(案 b) は採らない。評価順の DB 読み・長さの snapshot・本の順の固定などの並べ替えの経路を、全部置き換えることになるため。
- モーダル (popup を閉じ、chrome を無効にする) にはしない。
  - 直接移動の走査も、モーダルにはせず共有ゲートで止めている。それと同じ扱いに揃える。
  - 走査の間も、メニュー・ツールバーから次の並べ替えや移動を選べる (新しい要求が待ちを置き換える)。
- まれな失敗は既定の割り切り方針による。

## 4. 使い勝手への影響

- 並べ替えの走査の間は、前の一覧の項目を操作できなくなる。共有のメモ §3-2 の案 a の説明どおりで、統括が第一候補とした。
  - 項目の右クリックメニューは、待ちが始まると閉じる (§2)。
  - フォルダツリー・メニュー・ツールバー・ゲームパッドのピッカー (アイテム評価を除く) は、今までどおり使える。
  - ローカルの通常のフォルダでは、走査は数十〜数百 ms の見込み (コードからの推論、未計測)。
  - 長い場合は「並べ替え中…」が出る。
- 走査の間に前の順で動かした選択は、採用で並びが変わると位置の意味を失う。止めて失うものは小さい。
- **利用者の決定 (2026-11-22、統括経由)**: 案 a で進める。利用者の言葉は「案 a で進める」。
  - 統括が案 a・b・c の違いと、項目の右クリックメニューが待ちの開始で閉じることを説明したうえでの返事。

## 6. テスト (実装の前に赤で足す)

本物のフレームで、長さ順への変更で WorkerScan の待ちを作る。worker の完了を止めた状態で検査する。

操作できる項目を複数置き、入力の所有を一覧にした状態で検査する。

1. 待ちの間の矢印キー・Enter: 選択が動かない、項目が開かない。今のコードでは赤。
2. 待ちの間のグリッドのクリック: 選択が変わらない。今のコードでは赤。
3. 待ちの間の戻る (マウスの戻るボタン or 対応する KeyAction): 今と同じく通る。Esc と `GridToggleStackMode` は通らない。
4. 採用: sidecar restore の間も入力は通らない。sidecar restore の後に遮断が解け、矢印キーが新しい順で効く。
5. 待ちの終わり方。
   - owner の不一致で採用しない・走査エラー・切断・park・retire: どれでもゲートが解ける。
   - A→B の並べ替えの置き換え: 遮断は途切れず、A の結果は採用しない。B の採用で解ける。
   - 直接移動への置き換え: `DirectNavigationScan` の遮断へ引き継ぐ。
6. 500ms 後に「並べ替え中…」が出る。猶予の前は出ないが、入力は止まっている。
7. detached との境界: detached の並べ替えの待ちはメインの一覧の入力を止めない。メインの待ちは独立した detached の操作を止めない。
8. ゲームパッド (P2-1・P2-2):
   - 長さ昇順の走査中に、ピッカーで降順を選ぶ。設定と要求が降順になり、採用後の並びも降順になる。今のコードでは緑の見込みで、退行を防ぐテスト。r1 のまま共有ゲートへ足すと赤になる。
   - 走査中に左スティックでフォルダツリーを動かせる、グリッドのピッカーを開ける。
   - アイテム評価の行は止まる。左右操作・値一覧のどちらで変えても、通常の確定・セッション終了のどちらでも、DB の評価は変わらない。
   - 待ちが始まる前に成功したアイテム評価は、待ちの間に確定しても Undo できる。

### 8.2 段階 2: 製品コードの実装 (2026-11-22、実行検証は設計担当へ引き継ぎ)

- §2 のとおり `ViewOrderRefreshScan` を共有ゲートへ追加。条件と経過時間は、メイン所有の既存 `CurrentViewOrderRefresh` pending から導く。新しい状態・時刻は持たない。
- キーは直接移動の走査と同じ許可一覧へ接続し、Esc のスタック切り替えと `GridToggleStackMode` を止める。
- ゲームパッドの項目非依存操作は `GridItemInputBlock::item_independent_controls_allowed()` へ集約し、新しい variant のときだけ例外を認める。ツリーの左スティック・ピッカーを開く操作・アイテム評価以外のプレビューを維持する。
- アイテム評価の左右操作・値一覧の選択は draft / dirty の変更前に止める。確定時は新しい item 評価の書込みだけを止め、成功済みプレビューの記録・Undo・ピッカー終了処理を維持する。
- 実装レビュー P2 対応: 開いたままの Grid ピッカーのアイテム評価は、直接移動への引き継ぎ後や本の構成操作など他の variant でも共有ゲートに従って入口・確定の両方で止める。非 Grid の判定と項目非依存操作の許可一覧は変更しない。
