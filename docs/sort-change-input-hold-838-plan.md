# §1.838 並べ替えを変えた直後のキー: 一覧の採用まで項目の入力を止める (設計 r1)

- 収録版: v5.6.0 (統括の割り当て、2026-11-21)。ブランチ `range-filter-835` (§1.835 の上)。
- 観測 (サブ PC 担当、duration-762、v5.5.0): 並べ替えを変えた直後 (約 0.1 秒) のキーは、1 回目は前の順で効き、2 回目以降は消える。
- 第一候補は案 a (統括の指定)。案 a・b・c の比較は共有メモ `duration-762-ng-fix-material-20261121.md` §3-2。
- 以下の行番号は、このブランチの `5498fd963` の時点。

## 1. 起きていること (コードから)

1. 並べ替えの変更は `apply_sort_control_change` (`src/ui_main.rs:8804`) から `apply_sort_change_reload*` (`src/app.rs:29073`) へ進む。
2. 物理フォルダでは、並べ替えの種類で経路が分かれる。
   - 長さ順: `PhysicalFolderSortReload::WorkerScan` (`src/app.rs:29187`)。worker で走査し、`folder_pane_open_pending` に `FolderOpenScanPurpose::CurrentViewOrderRefresh` の待ちを置く。
   - その他: `Immediate`。UI スレッドで同期の走査と採用をする (`src/app.rs:32333`)。
3. WorkerScan の走査中も、一覧は前の順のまま操作できる。
   - キー: `handle_keyboard` (`src/app.rs:102325`) が前の `items` に効く。
   - クリック: `grid_item_input_allowed()` (`src/ui_main.rs:21195`) を通る。
   - その結果、「1 回目は前の順で効く」が起きる。
4. 走査結果の採用 (`apply_current_view_order_refresh`、`src/app.rs:62258`) は、items の差し替えと同じ呼び出しの中で sidecar restore を始める (`src/app.rs:32454` → `:26052`)。
   - sidecar restore の間は、`consume_input_during_sidecar_restore` (`src/app/sidecar_restore.rs:1342`) が入力を捨てる。
   - その結果、「2 回目以降は消える」が起きる。
5. 項目の入力の共有ゲート `grid_item_input_block()` (`src/filename_stack_ui.rs:2342`) は、キー・ポインタ・スクロール・ゲームパッド・メニュー・フルスクリーンを開く操作をまとめて止める。
   - 直接移動の走査 (`DirectNavigation`) は、すでにこのゲートで止めている。
   - 並べ替えの走査 (`CurrentViewOrderRefresh`) は止めていない。

壊れている前提: 「一覧の項目への入力は、利用者が見ている (これから見る) 順に対して効く」。並べ替えの要求から採用までの間だけ、これが成り立たない。

## 2. 修正 (案 a)

**並べ替えの走査を待っている間は、直接移動の走査と同じ共有ゲートで項目の入力を止める。**

- `GridItemInputBlock` に `ViewOrderRefreshScan` を足す。
  - 条件は `folder_pane_open_pending` の purpose が `CurrentViewOrderRefresh` であること。新しい bool・pending・時刻は持たず、既存の待ちから導く。
  - `direct_navigation_scan_pending()` と同じく `main_folder_history_available()` を条件にする。detached の context では成り立たない。
- 止める範囲と通すもの: `DirectNavigationScan` と同じにする。
  - `handle_stack_refresh_keyboard` (`src/app.rs:59637`) で、Esc のスタック切り替えと `GridToggleStackMode` を通さない。
  - 戻る/進む・環境設定・再読み込みなどの許可一覧は、そのまま通す。
  - これらの操作は、新しい走査・移動で待ちを置き換えるか、待ちに触れないもの。
- 待ちが終わる経路は、すべて既存の `take` で `None` になる。成功・owner の不一致・エラー・切断・置き換え・context の park / retire が含まれる。
  - 導いた条件なので、張り付かない。
  - 採用と sidecar restore の開始は同じ呼び出しなので、ゲートから sidecar の遮断へ隙間なく移る。
- 待機表示: 直接移動の「移動先を読み込み中…」と同じ 500ms の猶予つきの表示を使う。文言は「並べ替え中…」。
  - 猶予は表示だけのためで、入力は要求したフレームから止める。既存の `direct_navigation_wait_overlay_delay` と同じ規則。
  - 並べ替えの待ちには、今は表示が無い。ネットワーク共有などで走査が長いと、止まった理由が見えないため足す。
- 変えないもの:
  - 開いている popup は閉じない (共有ゲートは閉じない。採用時の sidecar restore が閉じるのは今と同じ)。
  - Immediate の経路。
  - sidecar restore の遮断。
  - detached の述語・viewport の経路。

### 2.1 範囲の外 (同じ形だが今回は触らない)

- 並べ替えを変えたフレームと同じフレームのキー。グリッドのキー処理はツールバーより前に走るため、前の順で効く。
  - そのキーは並べ替えの要求より前に処理されている。順序として正しい扱いなので変えない。
- Immediate の経路が UI スレッドで同期に走査していること (`docs/ui-responsiveness.md` の規約から外れる)。別項目として報告する。
- detached の context での並べ替えの走査 (`src/app.rs:62430`)。リワーク中のため触らない。
- タグ・レーティングの一覧の並べ替え (非同期)。前の一覧に入力が効くかは、レビューで確かめてもらう (下の §5)。
  - スマートフォルダの準備とサブフォルダ展開の待ちは、すでにモーダルの一覧に入っている。

## 3. 状態の組み合わせを減らす検討

- 新しい状態を持たない。待ちの持ち主は `folder_pane_open_pending` の 1 つで、ゲートの条件はそこから導く。
- 直接移動の走査と、止め方・許可一覧・表示を同じ経路に揃える。
- 「保留したキーを採用後に再生する」(案 c) は採らない。再生は、他の保留や置き換えと組み合わさるため。
- 「手元の一覧をその場で並べ直す」(案 b) は採らない。評価順の DB 読み・長さの snapshot・本の順の固定などの並べ替えの経路を、全部置き換えることになるため。
- モーダル (popup を閉じ、chrome を無効にする) にはしない。
  - 直接移動の走査も、モーダルにはせず共有ゲートで止めている。それと同じ扱いに揃える。
  - 走査の間も、メニュー・ツールバーから次の並べ替えや移動を選べる (新しい要求が待ちを置き換える)。
- まれな失敗は既定の割り切り方針による。

## 4. 使い勝手への影響

- 並べ替えの走査の間は、前の一覧を操作できなくなる。共有のメモ §3-2 の案 a の説明どおりで、統括が第一候補とした。
  - ローカルの通常のフォルダでは、走査は数十〜数百 ms の見込み (コードからの推論、未計測)。
  - 長い場合は「並べ替え中…」が出る。
- 走査の間に前の順で動かした選択は、採用で並びが変わると位置の意味を失う。止めて失うものは小さい。

## 5. レビューで見てほしい点

- タグ・レーティングの一覧の並べ替えも、待ちの間に前の一覧へ入力が効く同じ形か。同じなら同時に直すか別項目にするか。
- `main_folder_history_available()` を条件にすることで、detached の context を変えないと言えるか。

## 6. テスト (実装の前に赤で足す)

本物のフレームで、長さ順への変更で WorkerScan の待ちを作る。worker の完了を止めた状態で検査する。

1. 待ちの間の矢印キー・Enter: 選択が動かない、項目が開かない。今のコードでは赤。
2. 待ちの間のグリッドのクリック: 選択が変わらない。今のコードでは赤。
3. 待ちの間の戻る (マウスの戻るボタン or 対応する KeyAction): 今と同じく通る。
4. 採用の後: 矢印キーが新しい順で効く。sidecar restore の後に遮断が解ける。
5. 待ちの終わり方 (owner の不一致で採用しない・走査エラー・置き換え): どれでもゲートが解ける。
6. 500ms 後に「並べ替え中…」が出る。猶予の前は出ないが、入力は止まっている。
7. detached の context の並べ替えの待ちは、メインの一覧の入力を止めない。
