## 1. 実機ログで分かっていること (再測定不要)

利用者の実機 perf log (`%APPDATA%\mimageviewer\logs\perf_events.jsonl`、
5600×3500 JPEG 12 枚) を ClaudeCode が解析した結果。

### 1.1 対策 1 は効いている / 対策 2 はほぼ消えた

- 前進のページ間隔 p50 = **約 25ms** (修正前 84ms)
- `load_begin` は **80 件、うち Critical 2 件**のみ (修正前は 132 件、Normal → Critical の
  二重要求あり)。**再デコードの抑止 (対策 2) は今回やらない**

### 1.2 戻り方向だけ 65〜190ms の引っかかりが残る

189ms かかった区間の中身:

```
   0ms  page 7 表示 (mode=materialized)
  54ms  fs/ready idx=5  upload_ms=22.9
  99ms  fs/ready idx=4  upload_ms=22.5
 146ms  ui/frame_gap gap_ms=115.5      ← 1 フレームが 115ms
 168ms  fs/ready idx=3  upload_ms=21.4
 189ms  page 6 表示 (mode=materialized)
```

- **フル解像度アップロードが 22ms ずつ連発**。全 213 回のうち **140 回が直前から 40ms 以内**
- **区間の両端がどちらも `materialized`**。つまり戻り方向では通過描画が発動していない
- `input/fs_key` の間隔が **71〜115ms**。OS のキーリピートは 34ms 間隔のはずなので、
  **リピートがフレームあたり 1 つしか届いていない**

## 2. 何を直すか

### 2.1 まず「pending が false になる理由」を確定させること (最優先)

対策 1 の通過描画も、後述のアップロード抑制も、**同じ「次のページ送りが保留されている」
という信号**にぶら下がる。戻り方向でこれが false のままなら、どちらも効かない。

**先に計測すること**:

- そのフレームで観測した pending なページ送りエッジの**数**
- `fs_page_turn_materialization_for_frame` が返した判定と、false になった**理由**
  (ordinary context 判定で落ちたのか、pending が 0 だったのか)
- キーリピートが winit / egui / Win32 のどの段で 1 フレーム 1 つに間引かれているか

「前進では発動するのに戻りでは発動しない」なら、**方向で違うのは判定条件のどこか**である。
判定条件は方向に依存しないはずなので、そこが崩れている理由を突き止めること。
**推測で条件を緩めない。** 特に「N ms 以内なら押しっぱなしとみなす」等の時間ガードは禁止
([docs/touch-support-plan.md](touch-support-plan.md) §5.10)。

### 2.2 押しっぱなし中はフル解像度アップロードを進めない

原因が確定したうえで、**ページ送りが保留されている間は `fs_upload_backlog` を drain しない**
(= 先読み結果の 22ms アップロードをフレームに乗せない) ことを検討する。停止したら通常どおり
drain する。対策 1 と同じ信号にぶら下げること。新しい時間ガードを作らない。

- 現在ページの表示に必要なアップロードは止めないこと。止めると停止時の表示が遅れる
- `fs_upload_backlog` の「1 フレーム 1 枚」規則は既にある
  ([src/app.rs:59411](../src/app.rs) 付近の doc comment)。**そこを壊さないこと**
- これで足りないと分かった場合のみ、バックログ §1.58 の対策 3 (表示解像度へ縮めてから
  アップロード) を**別件として提案**する。今回は実装しない

### 2.3 計測は残すこと

再測定で確認するため、追加した perf event は残す。`analyze_perf.py page-turn` で
「発動しなかった理由」が読める形にすること。

## 3. 併せて直す: ワイプの掴みがウィンドウ外まで反応する

利用者報告 (2026-08-09): ワイプの境界をドラッグするとき、**カーソルをウィンドウの外へ
出しても距離に応じて動き続ける**。ウィンドウ端で止まるようにしたい。

原因は `compare_wipe_fraction_from_screen_x` が `draw_rect` 全体 (ズーム時は画面外へ
はみ出す) を 0..1 に写しているため。**ポインタ x を可視範囲
(`draw_rect ∩ ビューポート`、= `compare_shader_visible_region` の `visible`) で
クランプしてから fraction へ変換する**。

- 見えている範囲の端で止まる、が正しい挙動 (見えない位置へ境界を送れない)
- 白線の描画と掴み判定が同じ定義を使い続けること (§1.60 で揃えた不変条件を壊さない)
- テスト: 等倍 / ズーム時に、可視範囲の外側へポインタを置いても fraction が端の値で
  頭打ちになること
