# 実機確認からの追補 2 件 — 再クリック open の対象方式と、A/B クリア後の現在地

対象: 利用者の実機確認 (2026-08-19)。**どちらも v3.1.2 に入れる。**

## A. 再クリック open を選択方式に依らず使えるようにする

### A.1 現状と、なぜ効かなかったか

`grid_reclick_open_allowed` ([ui_main.rs:4232](../../src/ui_main.rs:4232)) は
`mode.normalized() == GridClickSelectionMode::Explorer` を条件に持つ。
利用者はチェック方式で試したため、設定を ON にしても開かなかった。**設定の反転ではない。**

元の仕様 (backlog §2.5) は「エクスプローラー方式を対象とし、チェック方式のクリックは
従来どおり選択操作」としていた。**利用者判断で、方式に依らず使えるようにする。**

### A.2 やること

- `Explorer` 限定の条件を**外す**。両方式で設定が効くようにする。
- **`no_other_cell_checked` は Explorer 方式のときだけ適用する。**
  理由は方式名ではなく機構にある:
  - Explorer 方式の修飾キーなしクリックは `checked.clear()` を通る
    ([ui_main.rs](../../src/ui_main.rs) の `apply_grid_click_selection` の `!ctrl` 分岐)。
    **そのクリックは「複数選択を 1 件へ畳む」操作**なので、開いてはいけない。
  - チェック方式の修飾キーなしクリックは**チェックを触らない**。カーソルが動くだけなので、
    畳む対象が無く、他にチェックがあっても開いてよい。
  - **「チェック方式だから」ではなく「そのクリックがチェックを消すかどうか」で分ける**こと。
    条件名とコメントもそう書く。
- 他の条件 (選択済み / 設定 ON / 修飾キーなし / touch でない) は両方式で共通。

### A.3 UI 文言

現在の説明文がこの変更で嘘になる:

> エクスプローラー方式で、修飾キーなしのマウスクリックにだけ適用します。複数選択中は 1 件へ
> 戻すだけで開きません。タッチ操作は対象外です。

- 「エクスプローラー方式で」を外す。
- 「複数選択中は」は利用者に伝わらなかった表現。**エクスプローラー方式で他の項目が
  選択されているときは畳むだけで開かない**、と条件を明示する。
- マニュアル ([grid.html](../../htdocs/mimageviewer/manual/grid.html)) と
  [spec.md](../spec.md) も揃える。

### A.4 テスト

1. チェック方式で、選択済みセルの再クリックが**開く** (設定 ON)。
2. チェック方式で、他のセルにチェックがあっても**開く** (畳む対象が無いため)。
3. Explorer 方式で、他のセルが選択されているときは**開かない** (従来どおり畳む)。
4. 設定 OFF では両方式とも開かない。
5. 既存の §2.5 テスト群が、方式条件の削除に合わせて更新されて通る。
6. mutation: A.2 の分岐を外すと 2 か 3 が落ちることを確認して報告する。

## B. A/B クリア後、現在地が active スロットに残っていない

### B.1 症状 (利用者報告)

通常は <kbd>B</kbd> → <kbd>A</kbd> と押せば、B を押す前の場所へ戻る。ところが
**クリア直後に一度もフォルダ移動せずに B → A とすると、ドライブ一覧へ飛ぶ**。
1 回でも移動すれば戻れる。**整合性が無い。**

### B.2 原因

`update_active_quick_folder_target` ([app.rs:16677](../../src/app.rs:16677)) が
「現在のフォルダを active スロットへ記録する」役目を持ち、**移動時に呼ばれる**。
クリアは両 workspace を `default()` に戻すので `target: None` になり、
**次に移動するまで「今見ている場所が、どのスロットのものでもない」窓ができる。**

### B.3 やること

クリアの最後に、**現在のフォルダを active スロット (A) の target として記録し直す**。
`update_active_quick_folder_target` をそのまま使う。

- 現在のフォルダが無い / 合成ビュー (`is_synthetic_view_path`) のときは記録しない
  (同関数が既にその判定を持っている)。
- 記録するのは target と drive-current だけ。**`folder_history` / `recent_folders` /
  戻る・進む履歴は消えたままにする** — 消すのがこの操作の目的。
- **現在の一覧を先頭へ戻す既存の挙動 (§1.98) は変えない。** 場所は保つが、位置は忘れる。

不変条件として書き残すこと: **active スロットの target は、常に画面に出ている場所と一致する。**
クリアはこの不変条件を破ってはいけない。

### B.4 テスト

1. クリア直後、`quick_folder_target(A)` が現在のフォルダになっている。
2. クリア直後に移動せず B → A で、**元のフォルダへ戻る**。
3. B 側の target は空のままで、B へ切り替えるとドライブ一覧になる。
4. 現在のフォルダが合成ビューのときは記録しない。
5. `folder_history` / recent / nav history は消えたままである (§1.98 の回帰)。
6. 現在の一覧が先頭へ戻る挙動が維持される (§1.98 の回帰)。
7. mutation: 再記録を外すと 1 と 2 が落ちることを確認して報告する。

## 2. やらないこと

- §1.98 で消す範囲を狭めない (位置は忘れたままにする)。
- クリア操作でフォルダ移動を起こさない (ドライブ一覧へ飛ばさない)。
- 選択方式そのものの挙動を変えない。
- 時間窓を使わない。
