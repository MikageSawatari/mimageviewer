# 「見ようとしているページがまだ出ていない」ことを中央に見せる

着手前に [CLAUDE.md](../../CLAUDE.md) の「バグ修正の一般原則」と
[docs/display-pipeline.md](../display-pipeline.md) を読むこと。

## 1. なぜ要るのか

ページ送りの挙動を「**常に画像を見せる**」(前ページを保持したまま次を準備する) へ変えた結果、
**準備に時間がかかると固まって見える**。実測では PDF ページの描画が最大 7.1 秒待つことがあり、
その間、画面は前のページのまま静止する。利用者は「ホイールが効いていない」と受け取る。

**優先度をどう積み替えても、この待ちは消えない。**in-flight の PDF 描画は PDFium が cancel
できないため、最悪ケースは残る。**待っていることが見えないほうが構造的な欠陥である。**

## 2. 既存の 2 つの表示とは意味が違う (どちらも触らない)

| 表示 | 位置 | 条件 | 意味 |
| --- | --- | --- | --- |
| `高解像度 読込中...` | 画像の左上 | `state.is_loading && has_any_tex && !pdf_rerendering` ([ui_fullscreen.rs:14148](../../src/ui_fullscreen.rs:14148)) | **何かは出ている**。高解像度へ差し替え中 |
| `PDF 再レンダリング中...` / `読込中...` | 画像の左下 | `fs_pending.contains_key(&fs_idx)` ([ui_fullscreen.rs:14164](../../src/ui_fullscreen.rs:14164)) | 読み込みが in-flight。**出ているかどうかは問わない** |
| **(新規)** `読み込み中` | **中央** | 下記 §3 | **今見ようとしているページが、まだ 1 度も出ていない** |

既存 2 つは**変更しない**。低解像度から高解像度への差し替えなど、別の事実を伝えている。

## 3. 表示条件

**現在の表示単位のページが、まだ提示できていない状態が 500ms 続いたとき。**

- 「まだ提示できていない」は**既存の typed state から導出する**。新しい bool を足さない
  (憲法 §2 規則 3)。前ページの holdover を表示している間は「このページはまだ出ていない」に当たる。
  `fs_pending` に居ることだけを条件にしない — **前ページの高解像度化中にも `fs_pending` は立つ**ため、
  それでは左下と同じ意味になってしまう。
- **見開きは、片方でも出ていなければ対象**とする (両ページ揃って初めて提示されるため)。
- 提示できた時点で**即座に消す**。時間で消さない。
- 500ms は「**いつ見せるか**」だけに使う。**競合判定には使わない** (憲法 §2 規則 5)。
  この用法は既存の前例と同じ (`docs/` に「150ms は提示だけの gate で競合判定には使わない」)。
- 経過時間は**その pending 自身の開始時刻から導く**。別のタイマーや `Instant` フィールドを新設しない。

## 4. 見た目

- 画面中央。既存の左下より**少し目立つ**程度 (半透明の背景 + 文字)。派手にしない。
- 既存 2 つと同じく `settings.fullscreen_processing_status_visible` を尊重する
  (処理状態の表示を切っている利用者に、この 1 つだけ出さない)。
- 文言は「読み込み中」。**PDF 固有の語 (再レンダリング) を使わない** — 中央表示は PDF に限らず
  「見ようとしているものがまだ出ていない」を表すため。

## 5. やってはいけないこと

- **repaint を新しく要求しない。**静止時の完全 sleep を要求するリリース必須ゲート
  (`scripts/check-idle-health.ps1`) が落ちる。500ms 後に見せるために `request_repaint_after` を
  足したくなるが、**読み込み中は既に repaint が回っている**はずなので、その frame に相乗りする。
  相乗りできないケースがあると判断したら、**足さずに報告する**。
- 既存の左上 / 左下の表示条件を変えない。
- 表示のために読み込みや提示の**判定を変えない**。これは提示だけの追加である。

## 6. テスト

- 前ページを保持したまま新ページを読み込み中で 500ms 未満 → **出ない**。
- 同じ状態で 500ms 超 → **出る**。
- 提示できた frame で**即座に消える**。
- 見開きで片方だけ出ている状態 → **出る**。
- `fullscreen_processing_status_visible` が false → 出ない。
- 高解像度化中 (既に現ページが出ている) → **出ない** (左上/左下の担当)。
- `request_repaint` / `request_repaint_after` を新たに呼ばないこと。
