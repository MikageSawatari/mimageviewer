# 1. なぜ直すのか

## 事実 (2026-09-01 に実測。詳細は正本 §2.1 / §2.2)

**X は枠の比率を制限しません。** 配信メタデータは `sizes.large` / `medium` / `small` の
すべてが `resize: "fit"` で、切り取るのは 150x150 のサムネイルだけです。

実際の公開投稿を測った値:

| 投稿 | 枚数 | 1 枚の実寸 | 枠の横/縦 | 合計 |
| --- | --- | --- | --- | --- |
| 3 分割 | 3 | 277 / 278 / 277 x 1216 | **0.228** | 832x1216 |
| 4 分割 (2 件) | 4 | 304x832 | **0.365** | 1216x832 |
| 分割なし (同じ作者) | 1 | 832x1216 | 0.684 | — |

3 分割の投稿は iOS アプリで 359x1576 = **0.2278** で表示されており、アップロード実寸
277/1216 = 0.2278 と一致します。切り取られていません。

**そして実際に行われているのは「絵全体を N 等分する」であって、「一定比率の枠を N 個
並べる」ではありません。** 3 枚の合計 832x1216 は、同じ作者が分割せずに投稿した絵と
同じキャンバスです。4 枚も 304x4 = 1216 ちょうど。**継ぎ目の帯を 1px も捨てていません。**

## 今の実装が作れないもの

枠を 3:4 に固定しているので、グループ矩形は 3 枚で 2.28:1 の横長になります。
832x1216 の縦長の絵に当てると、選べるのは **832x366** — 高さの 30% しかない横帯です。
枠の幅は 274px と作者の 277px にほぼ一致するのに、**縦が 366 対 1216 で切り詰められます。**

**つまり、いま最も多く行われている使い方が、この機能ではできません。** これが直す理由です。

## Instagram は X と違う

| | X | Instagram |
| --- | --- | --- |
| 枠の比率 | **自由** | **1.91:1 〜 3:4 (0.75) の外は切り取られる** |
| 複数枚 | 各枚が独立 | **1 枚目の比率に全スライドが固定される** |
| 隙間 | 枠幅の約 1.7% | なし |

**投稿先という概念は残します。** 違いが隙間だけではないからです。X 用に作った細い枠を
そのまま Instagram へ出すと Instagram が切ります。それを防げるのは投稿先だけです。

Instagram の 2 行は**実測ではなく公開解説の一致**です。X の 3:4 という前提が実測で覆った
直後なので、同じ疑いを持って扱ってください (正本 §2.2 に注記済み)。

# 2. 変更後の仕様

## 2.1 幾何 — グループ矩形は比率自由、枠は「グループを N 等分」

**枠の比率は入力ではなく結果になります。**

```
seam_ratio  = seam_permille / 1000            (枠幅に対する比)
frame_width = group_width / (N + (N-1) * seam_ratio)
frame_height = group_height                    <- ここが変更点。比率から導かない
step        = frame_width * (1 + seam_ratio)
```

- `SnsTarget::frame_aspect_parts()` / `frame_aspect()` は**削除**します。比率はもう
  投稿先の持ち物ではありません。
- `SnsSplitLayout::group_aspect()` も**削除**します。呼び出し側 (`ui_sns_split.rs` の
  ポインタ処理と `with_target_and_count`) はグループ矩形をそのまま保ちます。
- `frame_metrics_for_width` は `height` を比率から導いていますが、グループの高さを
  受け取る形へ変えてください。整数丸め・飽和処理の作りはそのまま活かします。
- `clamped()` は横と縦を**独立に**画像へ収めます。今は高さが幅から決まるので片方の
  予算だけ見れば足りていましたが、これからは両方要ります。
- `fits()` の契約 (最小配置さえ収まらないなら false) は変えません。

**不変条件は今と同じです**: 全枠の幅・高さ・間隔が厳密に一致し、描画・プレビュー・
書き出しはすべて `frames()` を正とする。

## 2.2 継ぎ目を選べるようにする

`SnsSplitLayout` に `seam_permille: u16` (0..=100 = 0.0%..10.0%、0.1% 刻み) を持たせます。
`SnsTarget::seam_ratio_parts()` は**投稿先ごとの既定値**を返すものへ役割を変えます
(X = 17, Instagram = 0)。

UI は「なし / 1.7% / 任意」の 3 択 + 任意のときだけ数値入力。

**投稿先を切り替えたら、継ぎ目はその投稿先の既定へ戻します。** 利用者が X 用に 1.7% を
選んだまま Instagram へ切り替え、隙間の無い Instagram で内容が欠けるのを防ぐためです。
「前の選択を覚えておく」ような賢い挙動は入れないでください (どちらが効いているのか
画面から分からなくなります)。

## 2.3 枠の比率プリセット (Instagram のために要る)

比率が完全に自由だと、Instagram の 0.75〜1.91 に収めるのが目分量になります。
`枠の比率` の選択肢を置いてください: **自由 (既定) / 3:4 / 4:5 / 1:1**。

自由以外を選んでいる間は、**グループ矩形の比率を固定**します。これは今の挙動そのもので、
`CropRect::dragged` のアスペクト固定経路 (`dragged_with_aspect` / `anchored_aspect_rect`) を
そのまま使えます。固定する比率は `frame_ratio * (N + (N-1) * seam_ratio)` です。

## 2.4 「画像全体に合わせる」

グループ矩形を画像全体 (回転・トリム後の表示元画像の全域) にするボタンをパネルに置きます。
**上の実測で分かった、いま最も多い使い方への 1 クリックの導線**です。
比率プリセットが自由以外なら、その比率を保ったまま最大まで広げます。

## 2.5 Instagram の比率チェック

`frames()[0]` の横/縦が **0.75 未満または 1.91 超**のとき、Instagram では:

- パネルに理由を表示する
- **「分割して書き出す」を無効にする**

理由の文面は「Instagram はこの比率を切り取ります。枠の比率を 3:4 〜 1.91:1 に収めるか、
投稿先を X にしてください」の意味で、内部用語なしで書いてください。

**逃げ道は X モードです** (比率の制限なし + 継ぎ目「なし」で完全に自由)。文面でそこへ
案内してください。回転ページ・画像が小さすぎる場合の既存の拒否と**同じ仕組み**に載せ、
新しい分岐を別に作らないこと。

## 2.6 パネルの表示

現在の枠を数字で出してください: **`1 枚 277 x 1216 (0.23)`** のように、書き出される実寸と
横/縦。比率が結果になる仕様なので、これが無いと利用者は何を作っているのか分かりません。

# 3. 設定の永続化

既存の `sns_split_target` / `sns_split_count` に加えて:

- `sns_split_seam_permille: u16` — 0..=100 に clamp。既定 17
- `sns_split_frame_ratio: Option<String>` — `"free"` / `"3:4"` / `"4:5"` / `"1:1"`。既定 `"free"`

**どちらも未リリースの設定です** (`sns_split_*` は v3.4.0 で初出、まだ出荷していない)。
マイグレーションは不要です。`sanitize()` と `overwrite_non_preferences_from` の既存の
扱いに揃えてください。

# 5. テストで押さえてほしいこと

**変異させて落ちることを確認してから出してください。** 「通った」だけでは受け取りません。

1. **実測の再現**: 832x1216 の画像 + 3 枚 + 継ぎ目なし + 画像全体 → 枠が 277 / 278 / 277 x 1216
   (丸めの配分は実装依存でよいが、**合計が 832 ちょうど**で高さが 1216)。
   1216x832 + 4 枚 + 継ぎ目なし → 304x832 が 4 枚、合計 1216。
   **これは今の実装では作れなかったケースです。** 比率固定を戻す変異で落ちること。
2. **継ぎ目**: 0 / 17 / 100 permille で、`frames()` の間隔が `frame_width * seam_ratio` に
   一致し、全枠の幅・高さ・間隔が厳密に等しいこと。
3. **投稿先の切り替え**: グループ矩形が保たれること。継ぎ目が投稿先の既定へ戻ること。
   **P7 で直した「切り替えるたびに小さくなる」の回帰テストを壊さないこと。**
4. **比率プリセット**: 固定中はドラッグでグループの比率が保たれること。辺なら反対辺、
   角なら反対角を固定する P6 の契約が生きていること。
5. **Instagram のチェック**: 0.75 未満 / 1.91 超で書き出しが止まり、境界値で止まらないこと。
   X では止まらないこと。
6. **設定**: 既定値、範囲外の clamp、往復。
