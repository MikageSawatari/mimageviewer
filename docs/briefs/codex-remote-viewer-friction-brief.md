
**原寸切り替えでもない** (fit_mode が page のまま)。

### 私の見立て (確定ではない)

ビューアには `fit_mode` とも visual viewport とも別に、

## 2. 件 B: 連打するとページ送りが止まる

> 連続タップしていると、**mIV が混み合っていますメッセージが出る**ことがあります。
> ページ送りが進まなくなるのでこれも改善したいです。

### 測ったこと

`/api/page` が **503 を 205 回**返している。直近の例:

```
19:59:39.936  503  /api/page  257ms
19:59:40.543  503  /api/page  354ms
19:59:41.993  503  /api/page  354ms
```

IPC の admission が埋まって弾いている。**50〜350ms 待たされた末に失敗**している。

### 考え方

**ページ送りは「最新だけが要る」操作**であって、積む操作ではない。
5 回叩いたら要るのは 5 ページ先の 1 枚で、途中の 4 枚は要らない。

今は 1 タップごとに独立した要求が立ち、admission を奪い合って共倒れしている。
**後から来た要求が前の要求を置き換える形**にすれば、混雑そのものが起きにくい。

**どこで実現するかは判断してよい** (端末側で in-flight を捨てる / 束ねる、
サーバ側で同一セッションの前の要求を捨てる、など)。**ただし:**

- **503 を握り潰して「成功したことにする」形にしないこと。**
  混雑が本当に起きたときに見えなくなる
- **リトライを足すだけの回避にしないこと。** 要求の数が減らなければ同じ

**サムネイルの 503 が 1121 回ある**が、これは一覧の並列取得で別の話。
**今回は触らないでよい。** 触るなら理由を報告してほしい。

外れる)。
