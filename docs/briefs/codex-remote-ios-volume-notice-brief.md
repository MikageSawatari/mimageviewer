## 1. 前の増分の指示を撤回する

直前の増分で「**UA 判定は使わない。実際に効くかを見る**」と指示した。**これを撤回する。**
機能検出が成立しないことが実測で確定したため。

### 1.1 何が分かったか

`mediaElementVolumeControlSupported` を `loadedmetadata` へ移した後も、iPad から
`supported: true` が届いた (テレメトリ `media_capability` / `volume_control` で確認)。

つまり**現在の iPadOS は `volume` への代入を受け付け、読み戻しも代入値と一致する。
音に反映されないだけ**である。したがって JS から可否を検出する手段が無い。

Apple のドキュメントは「音量は常に利用者の物理的な操作下に置く。volume は JavaScript から
設定できない」と**意図的な方針**として書いている。ただし同じ箇所の
「Reading the volume property always returns 1」は現在の挙動と食い違っており、この
「常に 1 を返す」が失われたことで検出の手がかりが無くなっている。

Apple がこれをバグとして扱っているかは、WebKit の bug report にも Apple の回答にも
見つからなかった。**不明である。** 方針として書かれている以上、近い将来の変更は見込まない。

### 1.2 なぜ UA 判定でよいのか

検出できない以上どの案も経験則に頼る。**外したときの代償で選ぶ。**

| 案 | 判定を外したとき |
| --- | --- |
| **注記を出す (採用)** | 文が 1 行余計に出る / 出ない。実害はほぼ無い |
| スライダーを隠す | 効くのに操作できなくなる。実害あり |

同じ経験則に頼るなら、外れたときの代償が小さい方を選ぶ。

## 2. やること

### 2.1 効かない検出を撤去する

`mediaElementVolumeControlSupported` は**全端末で true を返す**ので機能していない。
残すと誤った安心感を与える。検出とその呼び出し、テレメトリ送出、判定前にスライダーを
隠す処理をまとめて撤去する。

**スライダーは全端末で表示する。** 隠さない。

### 2.2 注記を出す

音量スライダーの近くに、iOS / iPadOS のときだけ注記を出す。**文面は利用者確定。
そのまま使い、変更しないこと**:

> iOS / iPadOS では、音量はデバイスのボタンで操作します。ここでの変更は反映されません。

- 何をすればよいか (デバイスのボタン) を先に書いている。「効かない」だけでは利用者が
  次に進めない
- 音量スライダーが見えている文脈にだけ出す。動画・音声どちらの再生画面でも同じ
- 文面をテストで固定すること

### 2.3 判定

- **iPadOS は Mac として名乗る**ので、`iPad` の文字列だけでは拾えない。
  タッチ点数と組み合わせる等、iPadOS を確実に含む判定にすること
- 判定は**純関数**に切り出し、テストで固定する。`navigator` を直接読む処理と、
  判定そのものを分ける
- 判定結果でスライダーの有無を変えない。**注記の有無だけ**を変える
