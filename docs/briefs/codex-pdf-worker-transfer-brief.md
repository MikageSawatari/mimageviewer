# PDF ワーカーとの受け渡しで、描画と転送のどちらに時間が要っているかを測る

作業ツリー: `C:\home\mimageviewer-web` (branch `web-remote`)。`883d48ed` の続き。
**まず計測。原因が確定してから直す。** この経路は**本体のローカル PDF 表示も通る**ので、
効けばリモート専用の改善では終わらない。

## 1. 実測で分かっていること (再調査不要)

リモートのページ生成 1 枚 (46.6 MP) の内訳:

| 段 | p50 | 1 MP あたり |
|---|---|---|
| **source (プール往復)** | **1308ms** | 28.1 |
| compose | 302ms | 6.5 |
| jpeg | 153ms | 3.3 |
| resize | 62ms | 1.3 |
| 合計 | 1869ms | 40.1 |

**`source` が 70% を占める。**そのうちプール往復 (`rtt_ms`) は 881ms。

サイズ違いの `rtt_ms` に直線を当てると **固定 121ms + 4.08 ms/MB (= 245 MB/s 相当)**。

| ラスタ | バイト | `rtt_ms` |
|---|---|---|
| 25.5 MP | 102 MB | 537ms |
| 46.6 MP | 186 MB | 880ms |

**バイト数に比例する部分が 760ms ある。**ただし PDFium のラスタライズも画素数に比例するので、
**この当てはめだけでは描画と転送を分離できない。**

**JPEG エンコードと縮小は同時本数が増えても平ら**で、ロック待ちも全段でほぼ 0。
つまり「どこかが直列」ではなく、**この 1 本の経路が単に重い**。

## 2. 決定

**ワーカーの中で「PDFium の描画」と「結果の書き出し」を別々に測る。**
親側の「読み取り」も測る。**この増分では速くする変更を入れない。**

分かれば次が決まる:

- **描画が支配的** → 転送をいじっても無駄。解像度を下げる以外にない
- **書き出し / 読み取りが支配的** → バッファ層か転送方式に手が入る。
  **ローカルの PDF 表示も同じだけ速くなる**

## 3. 変更内容

### 3.1 ワーカー内の内訳

`worker_main` の Render 処理を分けて計測し、応答に載せるかログへ出す (どちらでもよいが、
**親の perf イベントと突き合わせられる形にすること**)。

- PDFium がビットマップを作るまで
- そのビットマップを stdout へ書き終えるまで
- 書いたバイト数

### 3.2 親側の読み取り

`pool_recv` に、`rtt_ms` の内訳として**読み取りに要した時間**を足す。
既存の `rtt_ms` の意味は変えない (過去ログと比較できなくなるため)。

### 3.3 バッファ層の実際

**推測で決めないための情報を出す。**書き出し / 読み取りが何回の呼び出しに分かれたかを
数えて記録する。1 回で済んでいるのか、何万回に分かれているのかで結論が変わる。

> 参考: `std::io::stdout()` は `LineWriter` を挟む。バイナリを流したときにどう分割されるかは
> **実装を読んで確かめること。** 改行ごとに分割されるという理解は確認が取れていない。

### 3.4 他の IPC 経路の棚卸し (調査のみ、変更しない)

大きなバイト列を運ぶ IPC が他にもある。**どこで何バイトをどう運んでいるかを一覧にして
報告する** (直さない)。少なくとも次を見る:

- Susie 32bit ワーカー (`src/susie_loader.rs`)
- VST3 host bridge (`crates/vst3-host/`)
- 本体 ↔ remote-web の名前付きパイプ (`src/remote_ipc/pipe.rs`)
- 動画ストリーミング

**同じ作りを他でもしているなら、直す価値がその分だけ増える。**

## 4. 触らないもの

- **速くする変更はこの増分では入れない。**原因が確定してから別増分で行う
- プロトコルのフレーミング (`[4B len][data]` + `read_exact`)。**既に一括読みで、ここは問題ない**
- アルファチャンネルを送っている件。**転送が支配的だと確定してから**、別増分で判断する
  (同時に変えるとどちらが効いたか分からなくなる)
- `rtt_ms` の既存の意味、プールの優先度・予約・epoch
- remote-web (`crates/`)、protocol、画質プリセット、並列数の上限
