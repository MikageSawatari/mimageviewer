## 1. 件 A: 補正パネルがスクロールできない

> スクロール時にスライダーに触ってしまうとスライダーの値が変わってしまうため、
> **スライダーに触らないようにスクロールする必要があり、使いづらい**です。

### 原因 (確認済み)

```css
.adjustment-slider-row input[type="range"] {
  width: 100%;
  min-height: 28px;
  touch-action: none;   /* ← これ */
}
```

`touch-action: none` は「この要素が全てのタッチ操作を自分で処理する。ブラウザは
スクロールするな」という宣言。スライダーは**幅 100%・高さ 28px 以上**あるので、
**指が乗った時点でスクロールが原理的に不可能**になる。

利用者は「スクロールバーを太く出してほしい」と提案しているが、**それは別の場所を
用意する回避策**であって、スライダーに触れたら値が変わる状況は残る。

### 直し方

`touch-action: pan-y` にすれば、**縦方向はブラウザ (スクロール)、横方向は要素
(スライダー)** と所有権が分かれる。方向の判定はブラウザがやる。
同じスタイルシートの [styles.css:546](../../crates/remote-web/web/styles.css) に
既に前例がある。

**ただし `pointerdown` の `preventDefault()` が残っていると効かない可能性がある。**
touch pointer の pointerdown で preventDefault すると、実装によってはパン自体を止める。
**実際にどうなるか確認して、必要なら pointerdown の扱いも直してほしい。**

ブラウザが縦スクロールと判定した時点で、こちらのポインタ処理には `pointercancel` が来る。
**補正スライダーが `pointercancel` を扱っているか確認すること。** 扱っていないと、
スクロールに移った瞬間の値が残る。

対象は色調・カラー化・AI の全スライダー (同じ `adjustment-slider-row` を使っている)。

**動画と画像のシークバーは `touch-action: none` のままでよい** (スクロール文脈に居ない)。
そこまで変えないこと。

### スクロールバーについて

**根本原因が直れば不要だと私は考えている。** ただし「下にまだ続きがある」ことを
示す手掛かりとしては別の価値がある。**入れるかは判断してよい。**
入れないなら、その判断を報告してほしい。

## 2. 件 B: ダブルタップで画面全体がズームして戻せない

> 画像をページ送りしようとしてダブルタップすると、**少しだけ画面全体がズームされ、
> 前後移動のボタンなどが見切れる状態になり、戻せなくなりました**。一覧に戻れば直ります。

### 分かっていること

- **画像ビューアにダブルタップの処理は無い。** `dblclick` を購読しているのは
  `video-stream.mjs` だけ ([video-stream.mjs:1815](../../crates/remote-web/web/video-stream.mjs))。
  利用者はページ送りの操作だと思っていたが、そういう操作は実装されていない
- viewport meta は `width=device-width, initial-scale=1, viewport-fit=cover`
  ([index.html:5](../../crates/remote-web/web/index.html))。
  **`maximum-scale` も `user-scalable` も指定していない**ので、ブラウザのズームは有効
- `.viewer-stage` は `touch-action: none`
  ([styles.css:789](../../crates/remote-web/web/styles.css))

つまり**ブラウザのダブルタップズームが働いている**と読んだが、
stage が `none` なのになぜ起きるのかは説明できていない。

**どの要素がそのダブルタップを受け取っているか調べて報告してほしい。**
バー、ボタン、余白、stage の子要素など候補がある。**推測で塞がないこと。**

### 方針

これは全画面で使うアプリなので、**ブラウザのダブルタップズームに用途が無い。**
`touch-action: manipulation` はダブルタップズームだけを止め、**ピンチズームは残す。**
同じスタイルシートで既に多数使われている。

**viewport meta で `user-scalable=no` / `maximum-scale=1` を使わないこと。**
拡大の手段を丸ごと奪うのは弱視の利用者に対して有害だし、iOS Safari はこれを無視する。

「戻せなくなった」ことも重要。**起きないようにするのが第一だが、
起きたときに戻せるかも確認してほしい。**
