# 同じ PDF を開き直しても、実行中の列挙に合流する

## 1. 観測 (利用者実機、2026-08-20)

`d:\home\scan\illust21030_001.pdf` (174 ページ) をダブルクリックしても表示されず、
利用者が 3 回クリックした。ログの時系列:

```
38.806 activation accepted            ← 1 回目
38.929 enumerate_send
40.447 activation accepted            ← 2 回目
40.494 old requester cancelled  waited_ms=1563.9
42.737 pool_dispatch            wait_ms=2220.2
44.186 activation accepted            ← 3 回目
44.196 old requester cancelled  waited_ms=3679.1
45.197 requester cancelled       waited_ms=955.2
```

**初発原因はこの PDF 自体**である。同ファイルの background job:

```json
{"kind":"pool_recv","rtt_ms":7540.96,
 "worker_open_ms":7371.8,   ← 文書を開くだけで 7.4 秒
 "worker_page_ms":11.5,
 "worker_render_ms":154.9}
```

**PDFium で開くのに 7.4 秒かかる病的なファイル。**描画は 155ms、ページ取り出しは 11.5ms。
これは我々には縮められない。

**しかし待ち時間が 1.5 → 2.2 → 3.7 秒と積み上がったのは我々の側の問題である:**

- **キャンセルした IPC は pool の worker を解放しない。**PDFium は中断できないので、
  次の要求はその後ろに並ぶ
- 利用者からは無反応に見えるので再クリックし、**同じ PDF の要求が新しく積まれる**
- プールが空いた後の成功例は**クリックから 6ms で open、236ms で表示完了**

## 2. やること — 同じ列挙に合流させる

`enumerate_pages_async` ([pdf_loader.rs:3762](../../src/pdf_loader.rs:3762)) は**呼ばれるたびに
新しい要求を作る**。呼び出し元は 1 箇所 ([app.rs:22223](../../src/app.rs:22223))。

**同じ (path, パスワード) の列挙が実行中なら、新しい要求を作らず、実行中のものに待ち手を
合流させる。** 2 回目・3 回目のクリックは 1 回目の結果を共有して受け取る。

- **既に走っている PDFium の仕事を捨てない。**7.4 秒を 3 回払う理由はない
- 実行中のものが**キャンセルされていない**ことを確認して合流する。キャンセル済みなら新規要求
- 合流した待ち手それぞれが自分の `PdfEnumerateHandle` を持ち、**個別に drop / cancel できる**
  こと。1 人が諦めても他の待ち手の結果は生きる。**全員が諦めたときだけ**元の要求を cancel する
- **完了した結果は全待ち手へ配る**

## 3. 制約

- **時間窓を使わない。**「N ms 以内の再要求をまとめる」ではなく、**実行中かどうか**で決める
- **silent fallback を作らない。**合流できない場合 (キャンセル済み等) は新規要求として明示的に進む
- **`render_page_target` など他の pool 経路は今回触らない。**列挙だけが対象
  (再クリックで積み上がるのは列挙のため)
- detached の viewport / context 経路には触れない

## 4. テスト

- 同じ (path, パスワード) で 2 回呼ぶと、**pool への要求は 1 回**であること
- 両方の待ち手が**同じ結果**を受け取ること
- 片方の `PdfEnumerateHandle` を drop しても、**もう片方は結果を受け取る**こと
- **全員が drop したら**元の要求が cancel されること
- パスワードが違えば**別の要求**になること
- 実行中のものが既に cancel されていたら、新規要求になること

pool を起動するテストは書けないので、**合流の判定と待ち手の管理を純関数 / 小さな型に切り出して
テストする**方針でよい (どこを切り出したか報告すること)。

## 5. やらないこと

- **7.4 秒の open 自体**。PDFium のコストで、我々には縮められない
  (昨日入れた文書キャッシュにより「ページごと 7.4 秒」→「初回だけ」には既になっている)
- **`Opening` 中の detached セッションに可視の loading 表示を出す件**。これは detached リワーク
  (R2) の構造課題として切り分け済み。今回は触らない
