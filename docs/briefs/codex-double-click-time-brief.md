# backlog §2.9 — ダブルクリック間隔を Windows の設定へ合わせる

対象: [next-release-backlog.md](../next-release-backlog.md) §2.9 (専用スレ >>253-254)。
**v3.1.2 に入れる (利用者判断 2026-08-19)。**

## 0. 確認済みの事実

- egui 0.33.3 の既定は **300ms** (`InputOptions::max_double_click_delay: 0.3`、
  `input_state/mod.rs:75, 113`)。mIV は Windows の設定を参照していない。
- **Windows `GetDoubleClickTime()` の既定は 500ms** で、マウスのプロパティから変更できる。
  つまり mIV は **OS 既定より 40% 短い窓**を全利用者に強制している。
- 判定は 1 か所で、トリプルクリックも同じ値の 2 倍で決まる (`input_state/mod.rs:1215-1217`)。
  **1 つ直せば両方が OS に揃う。**

## 1. やること

1. Win32 `GetDoubleClickTime()` を呼び、`ctx.options_mut(|o| o.input_options.max_double_click_delay = ...)`
   へ秒で入れる。
2. **起動時に 1 回だけ** (利用者判断)。`WM_SETTINGCHANGE` の追随は入れない。
   セッション中に OS 設定を変えた場合は再起動で反映される、で足りる。
3. 変換は純関数にする (ms → 秒)。`0` (取得失敗) は 300ms 相当の既定へ落とす。
4. **上限・下限のクランプを入れない。** OS が返した値をそのまま使う。この修正の目的は
   OS への一致であって、OS より良い値を選ぶことではない。極端な値を設定した利用者は
   その設定を意図している。
5. Windows 以外では現状の egui 既定のまま (`cfg` 分岐)。**非 Windows ビルドを壊さないこと**
   (CI の ubuntu `cargo check` が番人)。

### 1.1 適用範囲

**メイン一覧だけの独自判定を足さない。** `InputOptions` は Context 単位なので、
**クリックを受け取る Context すべてに同じ値が行き渡ること**を確認する。どの Context が
存在するか (メイン / フルスクリーン viewport / detached 等) を数えて、報告に書くこと。
一覧だけ直すと、同じアプリの中でダブルクリックの意味が場所ごとに変わる。

## 2. やらないこと

- 独自のクリック判定を書かない。egui の判定に値を渡すだけ。
- 設定項目を作らない (OS の設定に従うのが仕様)。
- §2.6 をこの修正で解決扱いにしない。**§3 参照。**
- 時間窓で競合を吸収する類の変更ではないので憲法 §2 規則 5 には当たらないが、
  **この値を他の判定 (連打抑制など) へ流用しない**こと。

## 3. §2.6 との関係 (重要)

§2.6 (ダブルクリックが時々無反応) の報告条件は >>257 で訂正され、
「最初のダブルクリックで開かず、待っても開かず、しばらくして再度ダブルクリックすると開く」
になった。**これは窓が短いときの見え方と一致する**ので、現時点の最有力仮説は本項である。

ただし**証拠なしで §2.6 を閉じない**。§2.6 で入れた計装が判定できる:
押下が 2 回記録されているのに `double_clicked` が立っていなければ、原因は入力の成立側だと
確定する。本項を入れたうえで報告者に再現してもらい、ログで判断する。

backlog には「§2.9 を入れたが §2.6 は未解決のまま」と書くこと。

## 4. テスト

1. 純関数: `500 → 0.5`、`0 → 0.3` (失敗時の既定)、その他の値がそのまま秒になること。
2. クランプしていないこと (極端な値がそのまま通る)。
3. 適用後、`ctx.options()` の値が期待どおりであること。
4. 非 Windows でビルドが通り、既定 0.3 のままであること。
5. 既存のクリック / ダブルクリック関連テストが無修正で通る。
   **赤くなったら報告して止まる。**

## 5. 回帰確認 (手順を報告に書くこと)

窓が**広がる**方向なので、「別々の 2 回のクリック」がダブルクリックとして成立する場面が増える。
特に次を確認する:

- **チェック方式で、あるセルを素早くチェック → 解除**。2 回目が `double_clicked()` にも
  なって開いてしまわないか (**現行 300ms でも起こり得るが、確率が上がる**)。
- Windows 設定を短い値 / 長い値にしたときの実動作。
- 閾値の直前 / 直後。
- touch-derived pointer。
- §2.5 の「選択済み項目のクリックで開く」(設定 ON のとき)。窓が広がると、従来
  再クリック open だった操作がダブルクリック側へ回る。**どちらも開くので見た目は変わらない**
  はずで、それを確認する。
