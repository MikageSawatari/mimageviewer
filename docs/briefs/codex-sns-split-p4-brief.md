# P4a. 回転したページでは分割に入れない

## 見つかっている不具合

[src/ui_sns_split.rs](../../src/ui_sns_split.rs) は rotation を一切見ていません。一方
`render_export_page_pixels` ([export_dialog.rs](../../src/export_dialog.rs)) は
**crop を適用してから rotation を適用**します。

```rust
if let Some(crop) = entry_crop.or(page.crop) {
    let cropped = crate::export_crop::crop_color_image(rendered.as_ref(), crop)?;
    if page.rotation.is_none() {
        return Ok(Cow::Owned(cropped));
    }
    // ここで回転
```

枠は元画像座標で横一列に並ぶので、

- **90° / 270°**: 書き出した N 枚を横に並べても絵が繋がらない (画面上でも枠が縦に積まれて見える)
- **180°**: 並びは横のままだが**順序が反転**し、1 枚目が右端に来る

**しかも何の警告も出ません。**回転は写真や漫画ページで普通に使う機能なので、実機で踏みます。

## 直し方

**回転しているページでは SNS 分割モードに入れないようにする。**

- 判定は **90 / 180 / 270 の回転と、free rotation (`free_rotation_rad != 0`) の両方**
- ボタンは**無効表示にし、理由をツールチップで出す** (例
  「回転しているページでは使えません。回転をリセットしてから実行してください」)。
  他の編集ツールとは無効条件が違うので、**SNS 分割専用の disabled reason** が要ります
  ([ui_adjustment_panel.rs](../../src/ui_adjustment_panel.rs) の
  `image_edit_tools_disabled_reason` の使われ方に合わせる)
- キー (`FsSnsSplitMode`) から入ろうとした場合も同じ理由でトーストを出して入らない
- **モードに入った後で回転が変わった場合**も考えること。回転を変える操作がモード中に可能なら、
  その時点でモードを抜けるか、書き出し直前に弾く。どちらを採ったか報告してください

**180° だけ順序を反転させて救う、のような部分的な対応はしないでください。**「90 は駄目だが
180 は良い」は利用者に説明できません。一律で止めます。

## P4a のテスト

- 回転 90 / 180 / 270 / free rotation のそれぞれでモードに入れないこと
- 回転なしでは今までどおり入れること
- 無効理由の文字列が返ること
- モード中に回転が変わった場合の挙動 (採った方針どおりであること)

# P4b. 投稿後プレビュー

正本 §4.5。パネル内に、**N 枚を実際の隙間比で横並びに描くミニプレビュー**を置く。

隙間は設定で選ばせないので、これは校正用ではなく**構図の確認用**です。
継ぎ目が顔や重要な線の上に落ちていないかは、並べて見ないと分かりません。

## 要件

- **描く元は `layout.frames()`**。プレビュー用に枠を計算し直さない
- **隙間は実際の比率**で描く。X なら枠幅の 1.7%、**Instagram は隙間ゼロ**なので連続して見える
- 枠の中身は、**フルスクリーンで既に表示に使っているテクスチャの UV 部分矩形**を描く。
  - **新しいデコードもテクスチャアップロードもしない。**UI スレッドで画像を読み直さない
    ([docs/ui-responsiveness.md](../ui-responsiveness.md) §4)
  - パネルからテクスチャに手が届かないなら、**描画呼び出し側 (ui_fullscreen) から渡す**
  - テクスチャがまだ無いときは、枠の形だけのプレースホルダーを描く (何も描かない・panic はしない)
- パネル幅 (`PANEL_W` = 240) に収まる小さいもの。高さは固定でよい
- 上に「投稿後の見え方」相当のラベルを付ける
- `fits()` が false のときも `frames()` が返すものをそのまま描いてよい (警告は既に出ている)

## P4b のテスト

描画そのものはテストしづらいので、**純ロジックを切り出してテストする**こと。

- プレビューの矩形計算 (パネル幅と枠数から、各枠の描画位置と隙間を出す関数) を
  純関数にして、次を押さえる:
  - 枠数ぶんの矩形が返り、幅・高さが等しい
  - 隙間が `seam_ratio` に比例する
  - Instagram では隙間がゼロ
  - 与えられた幅に収まる
- UV 部分矩形の計算 (frames の source 座標 → 0..1 の UV) も純関数にしてテストする
