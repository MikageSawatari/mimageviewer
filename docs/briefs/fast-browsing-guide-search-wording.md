## 1. 現状と判断の根拠

- 対象: `htdocs/mimageviewer/guide-fast-browsing.html`。題は「大量の画像を高速に一覧できるしくみ」。
  Google には登録済みで、canonical は自分自身 (2026-11-20 確認)。
- Search Console (直近 90 日、このページだけ、11/18 まで): **13 クリック / 339 表示 / 平均掲載順位 7.6**。
  中身の見える検索語は「mimageviewer」2/26、「mimageviewer 使い方」1/34、「マンガミーヤ」0/2、「mimageviewer 評判」0/1 の 4 つだけ。
  残りの表示は件数が少なく匿名化された語。「高速」「大量」「軽い」などの一般語で拾われている形跡はない。
- このサイトで効果が出た手は、**人がすでに検索している言葉にページの題を合わせる**ことだけ。
  2026-07 に移行ガイドを「後継・代替」へ改題したら、「マンガミーヤ 代替」が 4 週間で 0 → 10 クリック (今は CTR 44%)。
  MassiGra の移行ガイドも同じ形で伸びている (28 日 58 / 681)。
- 反対に、Windows フォト向けの移行ガイド (`migrate-photos.html`) は 28 日 0〜2 クリック。「遅い」「重い」のような困りごとの検索は
  エクスプローラーやフォトの直し方を探す人が多く、大手のサイトとも競う。**大きく伸びる保証はない**ので、手間の小さい変更に留める。
- FAQ の構造化データで検索結果に Q&A を出す表示は、2023 年から Google が政府・医療系など一部のサイトに限っている。
  構造化データを足しても表示は増えない見込み。

## 2. やってほしいこと

### 2.1 製品ページのカードからリンクする

`htdocs/mimageviewer/index.html` の「高速サムネイルキャッシュ」カード (1032 行付近) の本文の末尾に、ガイドへのリンクを 1 つ足す。

- 文案: `<a href="guide-fast-browsing.html">10万枚のフォルダでの計測</a>`
- 今の本文は 115 字。足すと約 128 字で、カードの上限 150 字に収まる。追加後に `python scripts/check_site_cards.py` で確かめる。
- ほかのカードと同じく、リンクは本文の最後に置く (例: コレクションのカード「<a href="manual/collections.html">使い方を見る</a>」)。

### 2.2 ガイドの題と説明を検索される言葉に寄せる

URL (`guide-fast-browsing.html`) は**変えない** (登録済みで、転送を増やしたくない)。変えるのは題・説明・リンクの文字だけ。

文案 (最終的な言い回しは任せる。迷ったら利用者に見せる):

| 場所 | 今 | 文案 |
|---|---|---|
| `<title>` / `og:title` / `twitter:title` | 大量の画像を高速に一覧できるしくみ｜mImageViewer | 大量の画像を軽く見られる画像ビューア（10万枚のフォルダで計測）｜mImageViewer |
| `<h1>` | 大量の画像を高速に一覧できるしくみ | 大量の画像を軽く見られる画像ビューア |
| `description` / `og:description` / `twitter:description` | 数万枚のフォルダでも mImageViewer が軽く動く理由。… | 数万〜10万枚のフォルダでも、サムネイル一覧をすぐ表示できる Windows 用の画像ビューアです。10万枚超のフォルダを HDD に置いて計測した表示時間 (画面の 20 枚が初回 1.4 秒、2 回目以降 0.02 秒) と、速さを支えるしくみを紹介します。 |

- 題に入れたい語: 「画像ビューア」「大量」「軽い / 高速」。「しくみ」は題から外し、本文の見出し「速さを支える 5 つのしくみ」はそのまま残してよい。
- 数字は本文の表と一致させること。出どころは [docs/archive/performance-refactoring/site-bench-2026-09.md](../archive/performance-refactoring/site-bench-2026-09.md)
  (v4.1.0 のコードで計測。初めて見る画像: 最初の 1 枚 0.23 秒 / 20 枚 1.42 秒、キャッシュあり: 0.010 秒 / 0.020 秒)。
  新しく測り直さない限り、数字や条件を変えない。
- 製品ページの記述方針 ([docs/public-wording-policies.md](../public-wording-policies.md)) に従い、版番号や実装用語は題・説明に入れない。

### 2.3 ほかのページのリンクの文字をそろえる

今の題がリンクの文字として使われている所を、新しい h1 にそろえる (`git grep -n '大量の画像を高速に一覧できるしくみ' -- htdocs` で全件出る):

- `index.html` 1396 行付近: 「ガイド」欄のカードの `<h3>`。説明文 (`<p>数万枚のフォルダでも待たされにくい理由と、計測した表示時間をまとめています。</p>`) は
  「10万枚のフォルダでも待たされにくい理由と、計測した表示時間」など、新しい題と矛盾しない形に。
- 「ほかのガイド」欄: `guide-ai-images.html`、`guide-remote.html`、`migrate-honeyview.html`、`migrate-leeyes.html`、`migrate-mangameeya.html`、
  `migrate-massigra.html`、`migrate-photos.html`、`migrate-vix.html`、`migrate-zippla.html`。
- `manual/faq.html` 249 行付近の本文リンク「しくみと計測した表示時間は 〜 にまとめています」。文としておかしくならないよう前後も直す。
  **FAQ は JSON-LD (75 行付近) を本文と同じ文から作っているので、本文を変えたら JSON-LD の `text` も同じ文にそろえる**
  (2026-09 の FAQ 追加時の約束: 見えている文と構造化データの文をずらさない)。
