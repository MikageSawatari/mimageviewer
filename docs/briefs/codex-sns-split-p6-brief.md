# F1. パネルに書き出しボタンを付け、Ctrl+E とは混ぜない

## 利用者の指摘

> SNS 分割のパネルにエクスポートボタンがないので、Ctrl+E を押すことに気付けないと思います。
> Ctrl+E は通常のエクスポートなので、そちらと混ぜずに、SNS パネルに分割のエクスポートボタンを
> つける形にしたいです。

## やること

1. **`KeyAction::SnsSplitExecute` の既定割り当てから <kbd>Ctrl+E</kbd> を外す。**
   アクション自体は残し、`default_chords()` を空にする (利用者が「操作カスタマイズ」で
   割り当てられる状態は保つ = [docs/keymap-spec.md](../keymap-spec.md) の方針)。
   [docs/keymap.ini.default](../keymap.ini.default) も揃えること。
2. **SNS 分割パネルに「分割して書き出す」ボタンを置く。**押すと今の `SnsSplitExecute` と
   同じ経路 (`execute_sns_split_export`) を通る。
   - パネルの下部、プレビューの下あたり。押しやすい大きさで
   - `fits()` が false のときは**無効表示にし、理由をツールチップで出す**
     (すでにパネルに出している警告と同じ文言でよい)
3. **モード中の <kbd>Ctrl+E</kbd> は通常のエクスポートのガードに任せる。**
   ただし、SNS 分割モード中に出るメッセージは**パネルのボタンを案内する文面**にする
   (例「SNS 分割の書き出しはパネルの『分割して書き出す』から実行してください」)。
   他の編集モードのメッセージは変えないこと。

# F2. アスペクト固定時、辺のハンドルが拡大縮小にならず平行移動になる

## 利用者の指摘

> ドラッグで枠は移動できますが、上下左右のハンドルを動かしたときに、枠の拡大縮小ではなく
> 平行移動になってしまうようです。このハンドルは拡大縮小として動くのが期待する動作だと思います。

## 再現済み

`CropRect::dragged` を直接呼んで確認しました。3:4 (ratio 0.75) の 300x400 矩形に対して:

```
before     min=(100.0,100.0) size=(300.0x400.0) center=(250.0,300.0)
East+60    min=(130.0,100.0) size=(300.0x400.0) center=(280.0,300.0)
West-60    min=( 70.0,100.0) size=(300.0x400.0) center=(220.0,300.0)
North-60   min=(100.0, 70.0) size=(300.0x400.0) center=(250.0,270.0)
South+60   min=(100.0,130.0) size=(300.0x400.0) center=(250.0,330.0)
```

**4 辺すべてサイズが変わらず、中心だけが移動量の半分だけ動いています。**

## 原因

[export_crop.rs](../../src/export_crop.rs) の `CropRect::dragged` は、ハンドルに応じて片側の辺を
動かした後、`aspect_ratio` が `Some` なら `fit_to_aspect_around_center` を通します。

`fit_to_aspect_around_center` は**比率に合わせて内接するように縮め、中心を保つ**関数です。
辺のドラッグでは片方の寸法しか変わらないので、この関数が**もう一方の寸法から元のサイズを
復元**してしまい、結果として中心が動いただけになります。

角のハンドルも、ドラッグ量が比率どおりでない限り同じ理由で縮められ、中心がずれます
(例: SouthEast を横方向にだけ動かすと、幅が元に戻って平行移動になる)。

## これは既存の「切り取り」の不具合でもある

`dragged` は既存の切り取りツールと共有です。切り取りで **1:1 / 4:5 / 16:9 / 9:16 / 3:4 /
4:3 / 1.91:1 / 現在比率** のいずれかを選んでいるときも、まったく同じ症状が出ます
(自由のときは `aspect_ratio` が `None` なので影響しません)。

**したがって直す場所は `dragged` です。**SNS 分割側だけで辻褄を合わせると、同じ不具合が
切り取りに残り、しかも 2 か所に別々のリサイズ規則ができます。

## 直し方

`aspect_ratio` が `Some(ratio)` のとき、**掴んだ辺・角の反対側を固定**し、足りない軸を比率から
求める。標準的な画像編集ソフトと同じ挙動です。

| ハンドル | 固定するもの | 決め方 |
| --- | --- | --- |
| East | 左辺 `min_x` | 幅 = `max_x + dx - min_x`、高さ = 幅 / ratio、**縦中心を保つ** |
| West | 右辺 `max_x` | 幅 = `max_x - (min_x + dx)`、高さ = 幅 / ratio、縦中心を保つ |
| North | 下辺 `max_y` | 高さ = `max_y - (min_y + dy)`、幅 = 高さ * ratio、**横中心を保つ** |
| South | 上辺 `min_y` | 高さ = `max_y + dy - min_y`、幅 = 高さ * ratio、横中心を保つ |
| 角 4 種 | **反対側の角** | 幅と高さの両方の変化から寸法を決め、反対の角を動かさない |

角の決め方は、たとえば「dx から求めた幅」と「dy から求めた高さ」のうち**大きい方を採る**
(= ポインタの動きに素直に追従する) など、一貫した規則を 1 つ選んでください。選んだ規則を
コメントに書くこと。

### 変えてはいけないもの

- **`fit_to_aspect_around_center` 自体は変えない。**比率モードを切り替えたときに
  「今の枠に内接する比率へ縮める」のは正しい挙動で、そこで使われています
- `aspect_ratio` が `None` のとき (自由 / SNS 以外の自由モード) の挙動
- `CropHandle::Body` の平行移動
- 画像外へ出さない clamp。**反対側を固定した結果はみ出す場合は、比率を保ったまま縮める**
  (中心へ寄せて逃がさない。掴んでいない側が動くのは直感に反する)

## テスト

`export_crop.rs` の既存テストの流儀に合わせて追加する。

- 固定比率で 8 ハンドルそれぞれをドラッグしたとき:
  - **反対側の辺 / 角が動かない**
  - サイズが変わる (平行移動になっていない)
  - 結果が比率どおり (誤差 1px 以内)
- 画像の端で clamp されるとき、反対側が動かないまま比率が保たれる
- `aspect_ratio = None` では今までどおり (既存テストが通ること)
- 上の「再現済み」の 4 行が、サイズの変わる値になること
