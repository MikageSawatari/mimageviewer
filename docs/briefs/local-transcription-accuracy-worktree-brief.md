# ローカル文字起こしの精度を別 worktree で検証する

日本語の動画から PC 内で文字起こしし、発言を手掛かりに目的の時刻を探せるかを検証する。成果物は、同じ素材で再実行できる CLI 試作と精度レポート。試作は専用 worktree とそのブランチに置き、製品への統合は結果を見て判断する。

## 作業場所と試作の範囲

- 着手時のローカル `master` を起点に別 worktree を作り、起点コミットとブランチ名を記録する。コードの置き場は `scripts/asr-eval/` を候補とする。モデル・試験素材・出力は worktree 内の Git 管理外に置く。`vendor/`、`target/`、モデルや DLL は junction・symlink 等で共有しない。 [Git と worktree の運用](../git-workflow.md)
- 試作はコマンドラインで完結させる。手元の FFmpeg CLI で指定した動画の音声トラックを抽出し、`whisper.cpp` の `whisper-cli` を日本語の文字起こしモードで動かす。開始・終了時刻と本文を保存し、キーワード検索から該当区間の時刻を確認できるようにする。まずは検索結果の時刻を元動画と照合できればよい。試験素材の音声開始時刻を記録し、抽出後の相対時刻と元動画の再生時刻のずれも確認する。 [whisper.cpp](https://github.com/ggml-org/whisper.cpp)
- まず Whisper large-v3-turbo を動かし、同じ音声・同じ設定で Whisper large-v3 を比較する。モデル形式は両方で入手できる Q5 量子化を初期候補とし、実際の形式・ハッシュを記録する。必要なら結果を見て日本語特化の Kotoba-Whisper を追加候補にする。公開値は参考とし、今回のランタイム・量子化での実測値と分ける。 [whisper.cpp のモデル配布元](https://huggingface.co/ggerganov/whisper.cpp/tree/main)・[Kotoba-Whisper の公開比較](https://github.com/kotoba-tech/kotoba-whisper/blob/main/README.md#ablation-study)
- 本体 UI、再生経路、字幕描画、全体検索インデックス、設定 DB への組み込みは後続の判断事項。試験素材と文字起こし結果は PC 内で扱う。利用可能な公開素材または試験用に収録した素材を使い、実プロファイルに依存しない。

## 素材と測り方

1. 短い素材を3〜5本用意する。聞き取りやすい一人の解説、自然な会話、雑音や BGM・無音を含む音声を揃える。音声トラック選択と再生時刻の照合には、少なくとも1本の動画を使う。各素材の出典・利用条件・対象区間を記録する。
2. 出力を見る前に、手で照合した正解テキストと、探したい語・発言区間を用意する。一般語と、人名・製品名・数字など取りこぼしやすい語を含める。検索の成功は、キーワードが見つかり、候補の時刻から対応する発言を確認できたこととする。照合に許容する時刻差は測定前に決め、モデル間で揃える。
3. 素材別に **CER（文字誤り率）、検索成功件数／試行件数、処理時間**を記録する。CER の正規化は共通にし、句読点・空白などの扱いを明記する。検索も同じ条件で比較する。誤変換で見つからなかった固有名詞、発言時刻のずれ、無音で生成された文は、代表例を分けて残す。
4. 実行したコマンド、ランタイムとモデルの版・量子化、CPU/GPU と推論設定を残す。音声抽出と推論にかかった時間を分け、素材の長さも添える。条件を揃えられなかった測定は理由を記載する。

## 完了条件

動画から音声抽出、ローカル推論、検索と時刻の照合までを、手順書どおりに再実行できること。結果は素材別に示し、「解説動画なら使える」「固有名詞の検索漏れが多い」など、どの用途に進めるかを測定結果から判断できる形でメインセッションへ渡す。素材数が少ない段階では、今回の素材に対する結果として報告する。試作差分と再現手順は検証用ブランチに残す。
