# 製本で追加したページに、復元の確認を出さない

正本: [edit-content-identity-plan.md](../edit-content-identity-plan.md)。
本件は同計画の未着手項目「アプリ内コピー / ページ移動の同じ失効漏れ」の一部。

## 1. 観測された失敗

利用者報告 (2026-08-23)。**編集が無くレーティングだけ付いた画像を製本へ追加すると、
その直後に「編集内容の復元」ダイアログが出る。** mIV の機能を使っただけなのに
「どこかからコピーされてきたファイル」として扱われる。

編集がある場合は出ない。焼き込みでバイトが変わりハッシュが一致しないため。
**バイトコピーになる「編集なし」の場合だけ**起きる
(`grid_book_add_without_burn_keeps_byte_copy` が示すとおり製本は純粋なコピー)。

## 2. 原因

記録は編集の確定点 (`ContentIdentityTrigger::Edit`) だけで、
**mIV 自身が作ったコピー先には何も記録していない。**
そのため mIV のコピーとエクスプローラー由来のコピーを区別できず、
検出が「出所不明のコピー」として再発見する。

## 3. やること

**製本がページを作った時点で、その行き先を「確認済み」として記録する。**
検出側には何も足さない。

- 既存の仕組みをそのまま使う: `restore_declined(full_hash, target_key)` へ 1 行
  ([content_identity/restore.rs:152](../../src/content_identity/restore.rs:152) の
  `INSERT OR IGNORE`)。検出は
  [content_identity.rs:1409](../../src/content_identity.rs:1409) で
  `restore_was_declined` を見て候補を落とすので、**検出経路の変更は不要**。
- **ハッシュを計算し直さない。**バイトコピーなので行き先の full_hash は元と同一。
  元が台帳にあればその値を再利用する。
  - 元の `full_hash` が未算出 (stage2 未到達) のときの扱いを決めて報告する。
    元が台帳に無ければ候補自体が出ないので、**何もしなくてよい**はず。
- **UI スレッドで I/O をしない。**製本は既に非同期 (`book_op_pending`) なので、
  その worker 側で記録する。

## 4. ⚠️ 場所で無効化しない

**「製本フォルダ配下では復元を無効にする」という実装にしないこと** (利用者判断で却下済み)。

- 製本フォルダへ**エクスプローラーから編集済みファイルをコピー**した場合は、
  復元の案内が出るのが正しい。場所で切るとそれも消える。
- 原因はフォルダではなく「自分のコピーを記録していないこと」なので、
  場所での除外は症状パッチになる (CLAUDE.md「バグ修正の一般原則」)。

## 5. 製本の仕様は変えない

**レーティングやタグを製本ページへ引き継がない** (利用者判断)。
現状の製本は純粋なコピー + 編集の焼き込みだけで、それを変える意図はない。
「確認済みとして記録する」= **復元機能が入る前と同じ挙動へ戻す**、という位置づけ。

## 6. 他のアプリ内コピー経路

同じ穴がアプリ内コピー / ページ移動にもある (正本の未着手節)。
**今回それらを直す必要は無いが、製本専用の形にしないこと。**
同じ seam を後から他の経路が呼べる形にして、どこに置いたかを報告に書く。

## 7. テスト

- **編集なし + レーティングあり**の画像を製本へ追加 → その本のフォルダを開いても
  復元候補が出ないこと。
- **同じファイルをエクスプローラー相当でその本のフォルダへコピー**したら
  **復元候補が出ること** (= 場所で無効化していないことの証明)。**この 1 件が要**。
- 編集あり (焼き込み) のページでも候補が出ないこと (ハッシュ差で元々出ない)。
- 製本ページにレーティング / タグが付いていないこと (仕様不変の回帰)。
- 元が台帳に無い場合に落ちないこと。
- UI スレッドで I/O していないこと (既存の非同期経路に乗っている)。

- `cargo check -p mimageviewer --bin mimageviewer-core` が通る

  (製本ぶんが済んだこと、残る経路)
- **報告に、元の full_hash が無い場合の扱いと、seam をどこに置いたか**を書く
