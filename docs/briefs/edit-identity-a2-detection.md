## 2. 段 0 — ここで I/O をしてはいけない

`App::image_metas` ([app.rs:9446](../../src/app.rs:9446)) は `(mtime, file_size)` を
**フォルダ走査時に既に取得済み**なので、size 照合に追加 I/O は要らない。
起動時に台帳を読んでメモリへ載せた索引と突き合わせるだけ。

段 0 を通す条件は次の**すべて**:

1. **size が台帳のどれかと一致する。**
2. **その項目自身が台帳の行ではない。** 同じ `file_key` なら「元」であってコピーではない。
3. **復元先に既に編集が無い。** サイドカーと同じ「既存が authoritative」(§5-4)。
   判定は**メモリ上の presence 集合**で行い、DB へ問い合わせない
   (`adjusted_page_keys` / `mask_page_keys` / `conceal_page_keys` /
   `local_adjust_page_keys` / `comic_page_keys`)。
   **ZIP / PDF はページ単位のキーを持つので、`<容器キー>::` の prefix で見ること**
   (`BTreeSet` の range で O(log n) + ヒット数)。
4. **`restore_declined` に載っていない。** ただしこの表のキーは `full_hash` なので、
   段 0 の時点では引けない。**段 2 の後に落とす** (§5-4)。

### 2.1 検出の対象範囲

`install_new_items` ([app.rs:24263](../../src/app.rs:24263)) は物理フォルダだけでなく
スマートフォルダ・検索結果・ZIP 内ナビゲーションでも呼ばれる。
**検出は物理フォルダの一覧に限る。** §6.1 の文面が「このフォルダに」と言っている以上、
別々の場所の項目が混ざる一覧で出すと意味が通らない。
どの述語で絞ったかを報告に書くこと。

## 3. 検出 worker

- **`GlobalIoSemaphore` の `IoPriority::Low`** ([io_semaphore.rs](../../src/io_semaphore.rs))。
  `acquire_cancellable` があるので、cancel token を持つ長寿命 worker はそちらを使う。
- **フォルダ切替でキャンセルする。** worker 化の定型
  (`XxxPending { cancel, rx }` + `start_xxx` / `poll_xxx` + 3 箇所 cancel) は
  [docs/ui-responsiveness.md §2](../ui-responsiveness.md) にテンプレがある。
- 段 1 (先頭 64KB + size) → 段 2 (全体) の順。**段 1 が外れたら段 2 を読まない。**
  ハッシュ関数は A1 の `stage1_head_hash` / `stage2_full_hash` をそのまま使う。
  **新しいハッシュ実装を書かない。**
- 結果は台帳へキャッシュし、**再訪時に再計算しない** (§5-3)。
  つまり検出先のファイルも `edit_origin` に載る。**ここで A1 の trigger をどう使うかを
  決めて報告すること** — 検出は編集ではないので `last_edit_at` を進めてはならない。
- 候補が複数ある場合 (同一内容が複数箇所で別々に編集されている) は
  **`last_edit_at` が新しいものを既定**にし、他も候補として持つ (§5)。
  `last_edit_at = 0` は「未編集」なので最後に回る。

## 4. 設定

環境設定 → フォルダ (§7):

```
☑ コピー・移動したファイルの編集内容を復元するか確認する
   (OFF にすると照合のためのファイル読み取りを一切行いません)
```

- `Settings::edit_restore_prompt_enabled: bool` = **既定 true**。
- **OFF = 検出を完全停止。段 0 の size 照合もしない** (§7)。
- **A1 の記録側は OFF でも止めない** (§7、§10.1)。文言は「確認する / しない」であって
  「記録しない」ではない。**A1 の記録経路に設定分岐を足さないこと。**
- 設定 UI とマニュアルの記述は
  [CLAUDE.md](../../CLAUDE.md)「マニュアル・製品ページの記述方針」に従う (実装語を出さない)。

## 5. 制約

- **UI スレッドから 1 バイトも読まない。**
- **時間窓・sleep・retry で吸収しない。**
- **一括 backfill をしない。** 検出は開いたフォルダの範囲だけ。
- **フルスクリーン中は提示しない** (§5)。A2 はウィンドウを出さないので、
  「保持して一覧に戻ったときに出す」の**保持側**だけを作る。A3 が出す。
- 段 2 を打ち切らない。

## 6. テスト

- **段 0 で size 不一致なら 1 バイトも読まない** — I/O 呼び出し回数を数える (§9)。
- 設定 OFF で **worker が起動しない**こと。
- 自分自身 (同じ `file_key`) が候補にならないこと。
- 復元先に既に編集がある項目が落ちること。**ZIP / PDF の `::` prefix 版も。**
- 段 1 不一致で段 2 を読まないこと。
- `restore_declined` に載る組み合わせが段 2 の後に落ちること。
- 候補が複数のとき `last_edit_at` の新しい順に並び、`0` が最後に来ること。
- フォルダ切替で worker がキャンセルされ、**古い結果が新しいフォルダへ適用されないこと**。
- 物理フォルダ以外の一覧 (スマートフォルダ / 検索結果 / ZIP 内) で検出が走らないこと。
