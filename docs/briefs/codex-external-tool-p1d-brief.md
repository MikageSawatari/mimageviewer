# ブリーフ: 外部ツール起動 P1d — 関連付けハンドラの引き当てを Store 更新に耐えさせる

正本: [docs/external-tool-launch-plan.md](../external-tool-launch-plan.md) §4.1 の
「`GetName()` は安定した識別子ではない」の節。**正本は更新済み。** P1c の続きの不具合修正。

作業場所: この worktree (`C:\home\mimageviewer-extlaunch`, ブランチ `external-tool-launch`)。

## 0. 症状 (実機で確認済み。推測ではない)

P1c で関連付けアプリの起動は直り、利用者の環境で「フォト」と「TsubameViewer」は起動した。
**「ペイント」だけ「関連付けアプリが見つかりません」になる。**

原因は確定している。保存されている `handler_id` と実機の現況が食い違っている。

| | パッケージ |
| --- | --- |
| mIV に保存 | `Microsoft.Paint_11.2603.251.0_x64__8wekyb3d8bbwe` |
| 実機の現況 (`Get-AppxPackage`) | `Microsoft.Paint_11.2605.81.0_x64__8wekyb3d8bbwe` |

Store が Paint を更新したのでパスのバージョン部分が変わり、`GetName()` の完全一致で
引き当てられなくなった。「フォト」「TsubameViewer」は `GetName()` がバージョンを含まない
名前を返すので影響を受けなかった。

## 1. 直し方

正本 §4.1 のとおり、引き当てを 3 段にし、**最初に一致したものを使う**。

1. `GetName()` の完全一致
2. **パッケージ識別の一致**。`...\WindowsApps\<Name>_<Version>_<Arch>__<PublisherId>\<残り>` の形なら、
   バージョンとアーキテクチャを落とした `<Name>` + `<PublisherId>` + `<残り>` で比較する。
   `<残り>` (例 `PaintApp\mspaint.exe`) も比較に含めること。同じパッケージ内の別 exe を
   誤って掴まないため。
3. `GetUIName()` (表示名) の一致

**2 か 3 で一致したら、保存してある `handler_id` を現在の `GetName()` で書き戻す。**
次回から 1 で当たり、Store 更新のたびに劣化しない。書き戻しは
`Settings.recent_open_with_apps` と `Settings.external_tools` の両方が対象。
起動 worker から UI へ結果を返す既存経路に乗せ、**UI スレッドで DB を触らない**。

どれにも一致しなければ、従来どおりツール名を添えて通知する。

### 純関数にする部分

- パッケージ full name の分解 (`Microsoft.Paint_11.2605.81.0_x64__8wekyb3d8bbwe` →
  `Microsoft.Paint` + `8wekyb3d8bbwe`)。`_` で分割するが、`__` の前後を取り違えないこと。
- WindowsApps パスの正規化 (パッケージ部分 + 残りのパス)。
- 3 段の引き当て (入力 = 保存済み ID + 表示名 + 列挙結果の `(GetName, GetUIName)` 一覧、
  出力 = 一致した index と、書き戻しが要るかどうか)。

**COM 呼び出しの中に判定ロジックを混ぜない。** P1c で `invoke_association_handler_inner` に
閉じてあるので、そこから列挙結果を取り出して純関数へ渡す形にする。

## 2. あわせて入れる計装 (1 行)

ネイティブコンテキストメニューに外部ツールを積んだとき、**積んだ件数とラベル**をログへ出す。
既存の `native_context_menu:` 系と同じ形式でよい。

利用者から「右クリックに外部ツールが出てこない」という報告があり、
`miv_items=10` というログだけでは**積まれた中に外部ツールが含まれていたか判定できなかった**。
次に同じ報告が来たときログだけで切り分けられるようにする。積んだ件数が 0 のときも出すこと
(0 だと分かることに意味がある)。

## 3. テスト

- パッケージ full name の分解 (正常形 / `__` が無い / 区切りが足りない / WindowsApps でないパス)。
- 3 段の引き当て: 完全一致 / パッケージ一致 (バージョン違い) / 表示名一致 / どれも無い。
  **実機の実データ (`Microsoft.Paint_11.2603.251.0_...` → `Microsoft.Paint_11.2605.81.0_...`) を
  そのままテストケースにすること。**
- 同じパッケージ内の別 exe を掴まないこと。
- 書き戻しが必要かどうかのフラグが、完全一致のときは立たないこと。

## 4. 守ること

- コミット前に `cargo fmt` (引数なし)。テストは `cargo test -p mimageviewer --lib`。
- UI 文言を足したら `python scripts/check_ui_glyphs.py`。
- UI スレッドで同期 I/O を足さない。書き戻しも worker → UI の既存経路に乗せる。
- 範囲を広げない。
- 正本と食い違ったら実装を止めて報告すること。
