## 2. 現状 (私が確認した範囲)

動画のシークバーはネイティブの `<input type="range">`
([video-stream.mjs:1650](../../crates/remote-web/web/video-stream.mjs))。
iOS Safari では**つまみを掴まないとドラッグが始まらない**。指がずれると何も起きない。
これが「タップ判定がされない」の正体だと私は読んだ。

**本体側は違う作りだった** ([render_core.rs:7103](../../src/video/native_presenter/render_core.rs))。
`hit_rect` に `Sense::click_and_drag()` を張っており、**掴むべきつまみが無い。**
バーの当たり判定のどこを触っても効く。位置は絶対 (指の x をそのまま位置にする)。

つまり本体で困っていないのは、**相対だからではなく当たり判定が広いから**。

## 3. どうするか

**両方入れる。** 当たり判定だけでは利用者の要望の半分しか満たさない。

### (a) つまみを狙わせない

バー全体 (と上下に十分な余白) のどこを触ってもドラッグが始まること。
**指を置いた瞬間に位置が飛ばないこと** — これが (b)。

### (b) 相対にする

指を置いた場所へ**ジャンプしない**。現在の再生位置を起点に、
**指の移動量ぶんだけ**位置を動かす。

移動量と時間の対応は**バーの縮尺と同じ**にしてほしい (バーの端から端まで動かせば
全体の長さぶん動く)。予測できることが大事で、指の移動と目に見える変化が
一致しないと操作感が壊れる。

**細かい調整のための可変感度 (縦方向に離すと細かくなる等) は今回入れない。**
必要だと判断したら、入れずに提案として報告してほしい。

## 4. 落とさないこと

**ネイティブの `<input type="range">` はキーボード操作と支援技術対応を無料で持っている。**
自前のポインタ処理へ置き換えるなら、それを黙って失わないこと。

- 矢印キーでの操作
- `role` / `aria-valuenow` / `aria-valuetext` 相当 (現状 `aria-label` と
  `aria-valuetext` を設定している)

**要素ごと置き換えるのか、range を残して pointer 処理を被せるのかは判断してよい。**
どちらでも上記が保たれること。

## 5. 既存の動作を壊さないこと

- ドラッグ中のシークプレビュー (サムネイル表示) は現状どおり
- 離した時点でシークが確定する現状の挙動を変えない
- `draggingSeek` 中は poll による位置上書きが抑止されている。この不変条件を壊さない
- **動画の再生中・一時停止中・自動再生待ちのどれでも壊れないこと**
  (自動再生待ちは `0ce75b63` で入れたばかりの状態)

## 6. 同型の入口

**画像ビューアのページ位置スライダーも同じ `<input type="range">`**
([app.js:3555](../../crates/remote-web/web/app.js))。同じ「つまみを外すと無反応」を
抱えているはずだが、ページは離散値なので相対ドラッグが妥当かは別問題。

広げるなら理由が要る。

## 7. 受け入れ条件

- バーのどこを触ってもドラッグが始まる。つまみを狙う必要が無い
- 指を置いた瞬間に位置が飛ばない
- 指の移動量とバー上の見た目の移動が一致する
- キーボード操作と支援技術向けの属性が失われていない
- ドラッグ中のプレビューと確定タイミングが現状どおり
- **回帰テスト**を付ける。移動量から位置への変換は純関数で固定できるはず
- web テストが緑
