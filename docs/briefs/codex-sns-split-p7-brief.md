# F1. 投稿先を切り替えるたびに枠が小さくなる (不具合)

## 実測

`centered_max` で作った状態から `with_target` で往復させた結果です。

```
--- image 4000x3000 ---
  n=4 X         frame 987x1316 ar=0.750 gap=17 group=3999x1316
  n=4 Instagram frame 1000x1250 ar=0.800 gap=0  group=4000x1250
  n=4 back to X frame  938x1251 ar=0.750 gap=16 group=3800x1251   <- 元へ戻らない

--- image 2000x3000 ---
  n=2 X         frame 991x1321 ar=0.750 gap=17 group=1999x1321
  n=2 Instagram frame 1000x1250 ar=0.800 gap=0  group=2000x1250
  n=2 back to X frame  938x1251 ar=0.750 gap=16 group=1892x1251   <- 元へ戻らない
```

**X → Instagram → X と戻すと、元より小さくなります。**切り替えを繰り返すほど単調に縮み、
画像の幅も余らせます (4000 の画像に対して group 3800)。利用者が何度か切り替えて確かめようと
すると、「比率が変わる」より先に「なんとなく小さくなる」が起きます。

## 原因

`SnsSplitLayout::with_target_and_count` ([sns_split.rs](../../src/sns_split.rs)) が
**グループの高さを保って幅を導出**しているためです。

- X → Instagram: 高さ 1316 を保つと幅 = 1316 x 3.2 = 4211 で画像 (4000) をはみ出す
  → `clamped` が縮めて 4000x1250 になる
- Instagram → X: 高さ 1250 を保つと幅 = 1250 x 3.038 = 3798 で画像に収まる
  → **収まるので広げ直さない**。3798x1250 のまま

つまり「高さを保つ」規則は、比率が広がるときは縮むだけ、狭まるときは広がらないので、
**往復すると必ず縮みます。**

## 直し方

**保つのを高さから幅へ変える。**中心はこれまでどおり保つ。

```
新しいグループ幅 = 今のグループ幅
新しいグループ高さ = 新しいグループ幅 / group_aspect(新しい target, 新しい count)
はみ出す場合だけ比率を保って縮める (既存の clamped)
```

上の実測値で確認すると、

- X: group 3999x1316 → Instagram: 幅 3999 のまま、高さ 3999/3.2 = 1250 → **収まる**
- → X: 幅 3999 のまま、高さ 3999/3.038 = 1316 → **元へ戻る**

往復で元に戻ります。枚数の切り替え (2↔4) も同じ規則で往復が安定し、意味としても
「選んだ横方向の範囲はそのままで、分け方だけ変える」になって自然です。

高さ側がはみ出すときだけ `clamped` が縮めます (これは避けられません)。

## 既存テストの扱い

`with_count_and_target_keep_center_height_bounds_and_aspect` が**高さの保存を期待**しています。
この修正で意味が変わるので、**消さずに幅の保存を確かめる形へ書き換え、名前も直して**ください。
書き換えた理由を報告に書くこと。

追加してほしいテスト:

- `X → Instagram → X` が元のグループへ戻る (丸め誤差 1px 以内)。複数の画像サイズと枚数で
- `2 → 4 → 2` の枚数往復でも同じ
- 高さがはみ出す場合は比率を保って縮み、画像内に収まる
- 中心が保たれる

# F2. プレビューでは X と Instagram の隙間が描けていない

`sns_split_preview_rects` ([ui_sns_split.rs](../../src/ui_sns_split.rs)) は

```rust
let step = frame_width * (1.0 + seam_ratio);
```

で隙間を出していますが**下限がありません**。パネル幅 240px、余白を引いて描画領域が約 210px、
4 枚なら 1 枠 50px なので、

**X の隙間 = 50px x 1.7% = 0.85px → サブピクセルで描かれません。**

プレビューは「投稿後の見え方」を示すためのものなのに、**X と Instagram の最も特徴的な違いが
見えません**。

**直し方**: `seam_ratio > 0` のときは隙間の描画幅に **1px の下限**を設ける。模式図なので、
ここは厳密な比率より「見分けられること」を優先する。`seam_ratio == 0` (Instagram) は
0 のままにして、連続して見えることを保つ。

純関数のテストに「X では隙間が 1px 以上」「Instagram では 0」を足すこと。

# F3. パネルが投稿先ごとの違いを説明していない

いまパネルに出るのは出力寸法だけ (例「987 x 1316 x 4 枚」) で、切り替えても数字が変わるだけです。
**何がどう変わるのかが読み取れません。**

投稿先の選択肢のすぐ下に、選択中の投稿先の内容を 1 行で出してください。文面は任せますが、
次の情報が読み取れること。

| 投稿先 | 出したい内容 |
| --- | --- |
| X | 枠は 3:4、継ぎ目で枠幅の 1.7% を捨てる |
| Instagram | 枠は 4:5、継ぎ目は捨てない |

**「必ず繋がる」のような保証をする文面にはしないこと** (正本 §8)。
