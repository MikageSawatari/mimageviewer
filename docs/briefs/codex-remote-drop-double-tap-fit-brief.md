# リモート閲覧: ダブルタップの原寸切替を廃止し、残る拡大を測れるようにする

作業ツリー: `C:\home\mimageviewer-web` (branch `web-remote`)。
実装 = Codex、レビュー・テスト・統合 = ClaudeCode、実機確認 = 利用者。

## 1. 決まったこと (利用者判断)

**ビューアのダブルタップによる「全体表示 ⇔ 100% 原寸」の切替を廃止する。**

- 拡大はピンチだけで足りる、というのが利用者の判断。
- 原寸は今も 操作メニュー → 表示 → 「原寸 (100%)」から出せるので、手段は残る。
- 実機で、ダブルタップで原寸にした後にパンできず、パンしようとするとメニューが出る、
  という不具合も出ている。この経路自体を無くす。

## 2. 一緒に畳むもの

ビューアの中央タップは、**ダブルタップ待ちのためだけに遅延**している。バーの切替が
2 回起きないよう、2 打目が来るかを待つ作りになっている
(`pending_center_tap` / `commitPendingCenterTap` / `schedulePendingCenterTap`)。

ダブルタップが無くなれば、**この遅延の理由が無くなる**。待つ仕組みだけ残すと、すべての
中央タップが理由なく遅れる。

- 中央タップは即時にする。
- ダブルタップ待ちのための状態・タイマー・保留コミット・関連 telemetry
  (`double_tap_candidate_rejection` など) を、使われないまま残さない。
- `viewerTapSequenceTransition` がダブルタップ判定のためだけに存在するなら、
  役目に合わせて整理する。**残す価値のある区別 (中央 / 端 / 非タッチ) は残す。**

## 3. 触らないもの

- **`document-double-tap.mjs` の抑止は残す。** アプリがダブルタップに意味を持たなくなっても、
  ブラウザの double-tap zoom は起きるし、実機で「画面全体が拡大して戻せない」害が出ている。
- ピンチによる拡大・パン。
- 端タップによるページ送り、上下スワイプ。

## 4. 残っている拡大を測れるようにする

要素ごとの `touch-action` を書き足す方針で 2 回、抑止の窓を広げる方針で 1 回外している。
**定数を勘で動かすのをやめて、実際の値を記録する。**

- `document-double-tap.mjs` の判定結果を、任意の callback で外へ出せるようにする
  (モジュール自体は telemetry を知らないまま保つ)。
- app 側で通常段 telemetry に記録する。最低限:
  - 直前のタップからの経過 ms と距離 px
  - 抑止したか
  - 除外対象だったか (だとしたら何に一致したか)
  - `event.cancelable`
- `visualViewport` の倍率変化も記録する。**拡大が起きた瞬間**と、その直前のタップ対を
  突き合わせられるようにするのが目的。
- 記録は既存の telemetry 経路を通す。session ID を生で書かない既存の規約を守る。

## 5. やってはいけないこと

- 抑止の窓 (`BROWSER_DOUBLE_TAP_ZOOM_MAX_DELAY_MS`) を、測定結果なしにまた広げること。
- 要素ごとの `touch-action` をさらに書き足すこと (`*` の base rule で意図は表明済み)。
- viewport meta に `user-scalable=no` / `maximum-scale` を足すこと。ピンチは残す。
- 「パンできない / メニューが出る」を、ダブルタップ廃止で直ったことにすること。
  **同じ不具合がメニュー経由の原寸でも起きる可能性がある。** 廃止はそれを隠すためではない。
  この brief では直さず、廃止後に別途確認する。
