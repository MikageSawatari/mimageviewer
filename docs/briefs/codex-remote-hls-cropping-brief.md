## 1. 症状

1280×720 / 1920×1080 は正常。

## 2. 測ったこと (これが事実)

### 出力解像度と結果 (`mimageviewer.log` の `remote-stream encoder selected`)

| 結果 | 出力 | 高さ ÷ 16 |
| --- | --- | --- |
| 正常 | 1280×720 | 45 |
| 正常 | 1280×960 | 60 |
| **緑** | 640×360 | 22.5 |
| **緑** | 480×360 | 22.5 |
| **緑** | 360×270 | 16.875 |

**encoder は全て `h264_nvenc`**、`input_format=nv12`、`profile_request=high`、`bit_depth=8`、
`color_space=bt709`。ここに差は無い。

幅は 640 も 480 も 16 の倍数なのに壊れている。**判別しているのは高さ。**

### NVENC の出力を直接確かめた

`h264_nvenc` で 640×360 を符号化し、SPS を読んだ:

```
pic_width_in_mbs_minus1        = 39   → 40 × 16 = 640
pic_height_in_map_units_minus1 = 22   → 23 × 16 = 368   ← 368 行で符号化
frame_cropping_flag            = 1
frame_crop_bottom_offset       = 4    → 下 8px を捨てる → 360
```

**高さが 16 の倍数でないとき、NVENC は padding して cropping を SPS に書く。**
1280×720 は 720 = 45×16 なので cropping が出ない。

**壊れているのは「cropping 付きストリームの扱い」だと考えられる。**
緑になるのは輝度と色差でプレーンの高さがずれたときの典型的な症状。

## 3. 調べてほしいこと

**どこで cropping の整合が崩れているか。** 候補を挙げるが、**これは私の推測であり、
実際に確かめて報告してほしい。**

- `src/video/stream/segmenter.rs` が組み立てる fMP4。`tkhd` / `stsd` の幅・高さと
  `avcC` の SPS が食い違っていないか。**符号化された 368 と表示される 360 のどちらを
  書くべきかは仕様で決まっている**ので、そこに合っているか
- master playlist の `RESOLUTION` (`playlist.rs`)。符号化サイズを書いているのか
  表示サイズを書いているのか
- codec 文字列 `avc1.PPCCLL` は SPS 由来なので合っているはず。念のため

**iOS だけで出ることの説明も欲しい。** ソフトウェアデコーダは寛容で、
ハードウェアデコーダは厳格、という一般論は成り立つが、**それを根拠に「iOS の仕様」と
片付けないこと。** 正常な HLS なら iOS でも再生できるはずで、
こちらの出力が仕様に合っていない可能性を先に潰してほしい。

## 4. 直し方の方向 (判断してほしい)

2 つ考えられる。**どちらが正しいか判断して報告してほしい。**

- **(A) 出力を正しく記述する。** cropping 付きのまま、container と playlist が
  仕様どおりの値を持つようにする。**元の解像度を保てる**
- **(B) 出力の高さを 16 の倍数に丸める。** cropping を発生させない。
  ただし**わずかに絵が変わる** (縦横比か、切り落としか)

**(A) が本筋だと私は考えている。** (B) は cropping が扱えない相手に合わせる回避で、
仕様に合っているのに壊れているなら原因を残す。ただし**実際に (A) が可能かは
測ってから決めてほしい。**

**症状を消すために解像度を丸めるだけの変更を、原因が分からないまま入れないこと。**
