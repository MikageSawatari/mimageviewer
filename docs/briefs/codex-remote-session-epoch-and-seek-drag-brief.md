## 2. 依頼 (1) — ページ送りごとの往復を、セッションの切り替わり 1 回に置き換える

利用者からの提案:

> PC で操作している間、スマホで操作している間が細かく切り替わることはないはず。
> 毎回バージョンを確認するのではなく、**一度接続が本体とリモートで切り替わったら、
> リモート側のキャッシュをすべて破棄する**、という方法は取れないか。

私が調べた限り、この合図は**既存のセッション所有権に既にある**:

- `SessionStatus::LocalInUse` / `ReleaseReason::Local` / `last_owner`
  ([session.rs](../../src/remote_ipc/session.rs))
- ただし**本体は「操作したら自動で奪う」のではなく、UI の「切断する」ボタンで
  明示的に奪う**だけ ([ui.rs:2008](../../src/remote_ipc/ui.rs) の `local_disconnect`)

なので合図は「本体が奪った瞬間」ではなく、**「リモートがセッションを取得した瞬間」**を
軸にするのが素直だと思う。セッションには idle / liveness のタイムアウトもあるので、
放置後に再開する経路も拾えるはず。

**この理解が正しいか、より良い合図があるかを判断して報告してほしい。**

### 分けてほしい 2 つ

**お気に入りの照合は今のまま live に保つこと。** ここはセキュリティ境界
(消したお気に入りが開けてはいけない) で、実測 2 µs なので緩める理由がない。

| | 方式 |
| --- | --- |
| お気に入りの allowlist | **現状維持** (毎 request live 参照、`data_version` 2 µs) |
| ページ画像の鮮度 | **セッション取得時に一度だけ破棄**。ページ送りの往復をなくす |

### 残る穴 (利用者は承知のうえ)

端末がセッションを保持したまま、本体側でトリムを変え、端末に戻る場合は合図が来ない。
**利用者は「細かく切り替わることはない」という前提でこれを受け入れている。**
ただし **§4 の不変条件は維持すること**: 見開きの 2 ページが版違いで混ざってはいけない。

**穴が想定より広い (例: 合図が来ない経路が他にもある) と分かったら、実装せずに報告してほしい。**

## 3. 依頼 (2) — シークバーをつまみ外からも操作できるようにする

利用者報告:

> つまみのタップに失敗していると左右にドラッグしても反応しない。
> **スライダーと同じようにドラッグを相対にしたほうが良さそう。**

現状は素の `<input type="range">` で、`input` / `change` を拾っているだけ
([app.js:3258](../../crates/remote-web/web/app.js))。独自のポインタ処理は無い。
**トラックをタップしたときにその位置へ飛ぶかはブラウザ依存**で、そこが「反応しない」の正体。

**利用者の要望は「相対ドラッグ」。** つまみを掴めていなくても、触った場所から左右に
動かした分だけページが進む形。

判断して報告してほしい点:

- 相対ドラッグを入れると native range の既定挙動から外れる。**直前に入れた `dir="rtl"` の
  RTL 対応と噛み合うか** (向きの規則が 2 箇所に分かれないこと)
- キーボード操作・アクセシビリティ (`aria-valuetext` 等) が退行しないか
- 相対の量をどう決めるか (1px あたり何ページか)。ページ数が数百の本と数十の本で
  破綻しないこと

## 4. 受け入れ条件

- **ページ送りで `/api/remote-state` の往復が発生しない** (セッション取得時のみ)
- 本体でトリムを変えて端末を開き直すと反映される (セッション取得を挟む経路で)
- 見開きの 2 ページが版違いで混ざらない
- 消したお気に入りが端末から開けない (退行させないこと)
- **シークバーが、つまみを外した位置からドラッグしても動く**
- RTL / LTR とも、ドラッグの向きとページの進む向きが合う
- 前回通った項目が退行していない
- **回帰テスト**を付ける。ドラッグの量→ページ index の対応は純関数で固定できるはず
- `cargo test -p mimageviewer --lib` / remote / ipc / web が緑
