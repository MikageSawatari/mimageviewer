## 1. 症状 (利用者報告、実機)

**(a) 動画再生中に本体から切断すると、しばらく音が流れ続ける。**
再接続ボタンが一瞬出た後、「動画の状態を確認できませんでした」のトーストに切り替わり、
**しばらく再生が続いてから止まる**。タブレットから音が流れ続けるのが不自然。

**(b) 切断後も他の操作ができてしまう。**
操作してもエラーになるだけなので、**モーダルで塞いで再接続を促す**方が自然。

## 2. 原因 (特定済み。ここは再確認しなくてよい)

**通知は遅れていない。受け取り方が悪い。**

動画の状態は **1 秒ごと**にポーリングしている
([video-stream.mjs:27](../../crates/remote-web/web/video-stream.mjs) の
`VIDEO_STATE_POLL_MS = 1000`)。切断は 409 / 428 として**1 秒以内に届いている**。

しかし `schedulePoll` は `pollState()` の失敗を**全部ひとまとめに**扱う
([video-stream.mjs:2332](../../crates/remote-web/web/video-stream.mjs)):

```js
this.showOperationalError(error, "動画の状態を確認できませんでした");
this.schedulePoll();   // 再試行し続ける
```

セッションエラーと一時的な失敗を区別していない。再生が続くのは、既にバッファ済みの
HLS が流れているため。セグメント取得が尽きた時点で止まる。

## 3. これは構造の問題

**「切断された」という状態の持ち主がいない。** 各サブシステムがそれぞれ勝手に
セッションエラーを自前のトーストに変換している (ビューアは再接続ボタン、動画は
「状態を確認できませんでした」)。

**切断状態を一箇所が持ち、各所はそれに従う形にしてほしい。**
サブシステムごとに「セッションエラーならこうする」を書き足す形にしない。
そうすればモーダル表示も動画の即停止も同じ 1 つの状態から導ける。

`remoteSessionAcquireDecision`
([command-core.mjs:71](../../crates/remote-web/web/command-core.mjs)) が
既に「再取得してよいか」を純関数で持っているので、**表示と操作の可否も同じ場所から
導けるはず**。できないなら理由と一緒に報告してほしい。

## 4. やってほしいこと

### (a) 切断されたら動画を即座に止める

セッションエラー (409 / 428 のうち、再取得が `blocked` になる理由) を、
一時的な失敗と**区別する**。区別できたら再生を止め、切断状態へ遷移する。

**再試行し続けないこと。** 現状は `schedulePoll()` を呼び直すので、塞がれた状態で
1 秒ごとに叩き続ける。

### (b) 切断中はモーダルで操作を塞ぐ

再接続するまで他の操作ができないようにする。エラーになる操作を試させない。

- 何が起きたか (本体が操作を取り戻した / 別端末が接続した) が分かること
- **再接続の手段がその場にあること**
- `Expired` (放置による期限切れ) は従来どおり操作内で自動復帰する。
  **ここをモーダルで塞がないこと** — 塞ぐと放置から戻るたびにダイアログが出る

### (c) SSE は入れない

利用者から「SSE で push する形にできないか」という提案があったが、
**この症状には効かない** (通知は 1 秒以内に届いている)。

効くのは「完全に放置している端末が切断を知るまで最大 30 秒」の部分だけで、
そのとき利用者は画面を見ていない。**まず受け取り方を直して、その後に判断する。**

`tiny_http` の worker は 12 本固定で、SSE は 1 接続が 1 worker を占有する
([main.rs:110](../../crates/remote-web/src/main.rs) /
[http.rs:39](../../crates/remote-web/src/http.rs))。入れるなら worker 数の見直しが
先に要る。今回はやらない。

## 5. 受け入れ条件

- 動画再生中に本体から切断 → **1 秒程度で音が止まる**
- 止まった後、**塞がれた状態でポーリングを続けない**
- 切断中は他の操作ができず、**再接続の手段が画面にある**
- 再接続すると再生位置・表示が復帰する (できない場合はその旨が分かること)
- **`Expired` からの自動復帰が退行していない** (モーダルが出ない)
- 別端末に取られた場合も同じ扱いになること
- 一時的な通信失敗を切断と誤認しないこと (電波が切れただけで塞がない)
- **回帰テスト**を付ける。「どのエラーを切断として扱うか」は純関数で固定できるはず
- web テストが緑。Rust 側に触るなら該当テストも
