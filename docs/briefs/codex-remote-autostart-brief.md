## 4. やること

### 4.1 自動起動

- リモートを有効にしたら core が `mimageviewer-remote.exe` を起動する
- **exe と同じディレクトリ**から探す (dev は `target/dev-runtime/`、
  release は `target/release/`)。見つからなければ理由の分かるエラーを出す
- 本体終了時に確実に終了させる
- 既に外部で起動済みの remote がある場合の扱いを決めて報告してほしい
  (開発時は手動起動したいことがある)

**`--remote-ipc` の扱いも判断してほしい。** 現在は起動引数だが、自動起動にするなら
設定から入切する方が自然に見える。ただし既存の引数を壊さないこと。
**どうするのが既存の形に沿うかを見て、根拠と一緒に提案してほしい。**

### 4.2 データディレクトリの受け渡し

core が `--data-dir` で隔離起動されているとき、**remote にも同じ data-dir を渡す**こと。
今日の検証では手で両方に渡していた。ここがずれると別の library を読む。

### 4.3 メニュー移動

`MenuCommandId::HelpRemoteConnection` を**ヘルプから設定メニューへ移す**。
性質が「一度決めるもの」でヘルプではないため。

位置は環境設定の後ろ、区切り付き:

```
操作カスタマイズ…
環境設定…
────────────
リモート接続…
────────────
ツールバー      ▶
```

区切りは既存と同じく、そのコマンドの分岐で先に `ui.separator()` を呼ぶ形
([src/ui_main.rs:5152](../../src/ui_main.rs) 付近の `SettingsRestoreSettings` が先例)。

- ID 名 `HelpRemoteConnection` を改名するかは判断に任せる。改名するなら
  操作カスタマイズの保存済み設定 (`hidden_commands` / 並び順) との互換を壊さないこと。
  **壊れる恐れがあるなら改名しない方がよい**
- `docs/keymap.ini.default` と `docs/keymap-spec.md` の更新も必要なら合わせて
