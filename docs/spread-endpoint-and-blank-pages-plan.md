## 2. §1.239 — 先頭と末尾を独立させる

1. `EndpointPlacementSettings { first: bool, last: bool }` と `EndpointPlacementPreferences { first, last: SingletonSpreadPlacementPreference }` を一つの値として App/context/Remote に渡す。各端だけ `effective(global_end)` で解決する。1 unit が両端なら**先頭優先**という現行規則を維持する。geometry は §1.218 の `Center/Left/Right` と仮想二枠 canvas をそのまま使う（`src/ui_fullscreen.rs:13717`、`docs/section218-singleton-spread-placement.md`「型と判定の唯一の所有者」）。
2. `settings.db` の新キー `singleton_spread_first_enabled` / `singleton_spread_last_enabled` は旧 `singleton_spread_placement_enabled` から両方へ同じ値を写す。**選択する failure-safe 規則は「committed marker が無い間は旧値を両端へ投影」**。専用 migration marker と新二キーを一 transaction で書き、marker がある場合に限り新二キーを正本として読む。旧キー無しは両方 OFF。marker 無しで新キーが 0/1/2 個ある状態はすべて未完了として扱い、特に**片方だけある状態を不完全と診断**する。旧キーから両端へ投影して次回再試行し、未完了中の `save_full` と個別設定書込を抑止する。marker 有りで片キー欠損・不正なら旧値/既定値へ黙って戻さず読込エラーと保存抑止へ送る。書込失敗でも利用者に旧 ON の見た目を保持でき、既存 loader の「migration error を記録して継続」による quarantine 誘発を避けられるためこの規則を選ぶ（`src/settings_db.rs:625`, `src/settings_db.rs:627`, `src/settings_db.rs:853`）。
   新規 `settings.db` の初回 `save_full` は両キーと完了 marker を同じ transaction で書く。保存抑止は既存 DB の未完了移行にだけ適用する。旧 JSON/backup 読込も旧 bool→両端の互換変換を行い、復元した旧 `settings.db` は marker 無しとして再移行する。Remote `load_remote_reading_settings` も同じ marker-gated helper を使い、未完了なら旧キーの live 値を両端へ投影する。移行失敗・不完全状態を起動時設定の古い clone で覆わない。released settings の移行は必須（`src/settings_db.rs:48`, `src/settings_db.rs:805`, `CLAUDE.md:1654`）。
3. `spread.db` は新 table `singleton_spread_endpoint_placements(path PRIMARY KEY, first_preference, last_preference)`、各 0=FollowGlobal / 1=Place / 2=Center と CHECK。旧 table の**全 row** を `(old, old)` へ copy し、専用 completed marker と共に一 transaction で commit する。table の存在だけを移行完了とみなさない。marker 有りの read は新 table のみを使い、表/列欠損はエラー。marker 無しの read は旧 table を両端へ投影し、書込可能 open は次回 transaction を再試行する。途中で新 table のみ作られていた場合は旧 table から再構成して commit し、未完了中の新 endpoint 書込は拒否する。read-only 旧 DB は旧 table の root/nested row を両端へ投影し、旧 table も無ければ両端 `FollowGlobal`（`src/spread_db.rs:65`, `src/spread_db.rs:84`, `src/spread_db.rs:240`）。
   root の両端 FollowGlobal は row 削除、nested は `(0,0)` を保持して root fallback を遮る。片端だけ FollowGlobal の nested row も保持する。旧 `spreads`/final-cover 行は生成しない。移行失敗時に旧 row は不変で retry 可能。marker 有りなのに新 row/表が壊れた場合は旧値へ silent fallback しない。schema/query error は `Result` として App と Remote まで伝え、`FollowGlobal` に見せかけない。
4. resolver は最終 presentation が実 1 page、complete canonical book、`UnpairedSlot` のときだけ `first` または `last` を選ぶ。横長・非 pairable、末尾表紙補助で二枚になった unit、collection/検索/切詰めは従来どおり Center。片端変更は page count、anchor、seek、source demand を変えず、その context の placement layout だけ invalidate する（`src/ui_fullscreen.rs:13496`, `src/ui_fullscreen.rs:13684`, `src/ui_fullscreen.rs:13717`, `src/ui_fullscreen.rs:15986`）。
5. paged、縦/横連結、holdover の capture-time placement、F12 の active と passive frozen projection を同じ composition 値から通す。parked sibling のうち変更端を継承する context のみ再計算し、旧 snapshot を現在設定から描き直さない（`src/ui_fullscreen.rs:7725`, `src/ui_fullscreen.rs:9818`, `src/ui_fullscreen.rs:17166`, `src/app/viewer_context_registry.rs:3223`）。detached viewport/述語に入る実装は `docs/detached-rework-plan.md` §2 の構造合意を先に得て §11 に記録する。
6. 本別 menu は「先頭」「末尾」それぞれ `全体設定に従う / 片側へ配置 / 中央表示`。環境設定は先頭/末尾二項目。metadata export/import、refresh、rename/purge、content identity 復元、Remote live snapshot/write、IPC/Web menu/refit を両端同時に更新する。metadata transfer の出力版を v8 に上げ、**入力は released v7 と v8 の manifest・shard header の両方を明示受理**する。同じ bundle 内の manifest/header 版一致を要求し、未知版は拒否。v7 の `singleton_spread_placement` は root と nested の明示 `FollowGlobal(0)` 行も含め、各行を `(old, old)` として v8 endpoint state へ移す。row absent は absent のまま。現 importer は両 header を `FORMAT_VERSION=7` に厳密比較するため、定数更新だけでは旧 bundle を失う（`src/metadata_transfer.rs:27`, `src/metadata_transfer.rs:456`, `src/metadata_transfer.rs:3041`, `src/metadata_transfer.rs:3062`, `src/metadata_transfer.rs:4491`）。IPC protocol と Web asset token は既存 strict 手順で更新する（`src/remote_ipc/ui.rs:2267`, `crates/remote-ipc/src/lib.rs:31`, `docs/web-remote-plan.md:2837`）。利用者文書 `docs/spec.md`、`htdocs/mimageviewer/manual/settings.html:1141`、`htdocs/mimageviewer/manual/fullscreen.html:441` と Remote 読書設定説明を実装時に更新する。

## 3. §1.240 — 端近くの実ページを単独表示する（新モデル、2026-09-24）

### 利用者仕様と表示単位

- 切替は「表紙の次のページを単独で表示」と「最終ページを単独で表示」の二つ。前者は実読書列の 2 ページ目を、後者は最終実ページを相方と組まず単独の表示単位にする。各単独ページを本来の左右へ置き、その境界の後／前から残りの実ページを組み直す。白紙のファイル、仮想ページ、GridItem、偽 path、blank-only 表示単位は作らない。
- >>402 の例を回帰 oracle にする。表紙 01、本文 03..34、裏表紙 36 を表紙あり見開きで読み、両切替 ON のとき、01 は表紙、03 は単独、その後 04+05…32+33、34 は単独、36 は単独となる。「01 の後に白紙 1 枚、36 の前に白紙 1 枚」を入れた parity と同じ画面側に置く。LTR は 01=右、03=右、34=左、36=左、RTL は鏡映して 01=左、03=左、34=右、36=右。34 の空き側も概念上の白紙に対応する。ただしその白紙はページではなく表示単位の装飾 slot であり、シーク・ページ送り対象にならない。01/03/34/36 の source は各 1 回のまま。
- 1 ページ本は二切替とも効果なしで、その実ページ 1 単位だけ。2 ページ本で二切替が同じ最終ページを指すときも実ページ 1 件につき 1 単位に畳み、2 ページ目は「表紙の次」規則を優先して側を決める。空単位を作って挿入モデルの退化例を模倣しない。表紙なし見開きでは 1 ページ目も必要なら単独になり、2 ページ目を指定どおり単独にする。「白紙挿入」と一致させる対象は実ページの左右位置であり、単位数は二切替の意味に従う。
- 既存の SpreadDisplayUnit は実 index の pages と形成理由を持つ（src/ui_fullscreen.rs:13513, src/ui_fullscreen.rs:14009）。builder に二つの強制境界を渡し、実ページ列を segment ごとに pairing する。既存 UnpairedSlot / LandscapeBoundary と別の ForcedAfterCover / ForcedLast 形成理由、および segment 境界に残る単独理由を持つ。layout-only の WhiteCompanion { side, reference_real_idx } は composition の presentation geometry に属し、SpreadPageOccurrence や SpreadPair::Double の二つ目の実 index へ入れない（src/ui_fullscreen.rs:13532, src/ui_fullscreen.rs:13648）。cache token は両切替の実効値を含める（src/ui_fullscreen.rs:13772）。
- 全 unit に実 anchor がある。単位数・組み合わせ・ページ送りの着地点は変わり得るが、実ページ数と各実ページの seek 番号、resume/bookmark identity、go-to-page の対象集合は変えない。ページ番号は実 page を示し、seek track/thumbnail strip は実ページ由来の位置のみを使う。表示単位間の prev/next は再構成後の unit 列を進み、実ページ選択はその page を含む unit へ着地する。これを別々の consumer が独自に再計算しない（src/ui_fullscreen.rs:14357, src/ui_fullscreen.rs:19831, src/book_resume_db.rs:43）。

### 白い空き側と既存機能

- 強制単独、および上例の 34 のように強制境界で余った実ページの空き側を WHITE で描く。03/34/36 は各実ページ自身の保存回転・表示トリム後の可視寸法を白 slot の寸法にも使う。表紙なしで 01 が強制境界のため余る場合も同じ規則を使う。表紙ありの 01 は通常の cover singleton であり、強制境界の白 slot を足さない。寸法が未確定なら当該実ページの既存 metadata 到着に追従し、白い texture や decode 要求は作らない。§1.218 の自己複製二 slot 仮想 canvas の fit と gap を再利用し、空き側だけ白い矩形として描く。§1.218 の通常 endpoint UnpairedSlot はこれまでどおり余白背景色のまま。白／背景の両色に設定項目は設けない（docs/section218-singleton-spread-placement.md「仮想キャンバスと fit」、src/ui_fullscreen.rs:13717）。
- 強制単独は §1.239 の端の中央/片側 preference より優先し、必ずその mode の自然な側へ置く。強制されない実 endpoint UnpairedSlot だけに §1.239 の first/last を使う。1 unit が両端なら §1.239 の先頭優先を維持する。表紙ありでは 01 の cover 位相の次に 03 の単独位相を置き、表紙なしでは先頭 segment を同じ規則で閉じる。LTR/RTL は既存 SpreadMode の画面左右変換を一度だけ適用する（src/ui_fullscreen.rs:13717, src/ui_fullscreen.rs:14130）。
- 横長・保存回転後の横長も指定対象なら単独にして自然な側へ置く。強制対象でない横長は既存どおり中央の LandscapeBoundary。Single と横長 Split は二切替を保存するが表示構成へ適用しない。見開きへ戻ったときに再構成する（src/ui_fullscreen.rs:13459, src/ui_fullscreen.rs:16067）。最終ページ強制 ON は「最後を単独で表示」を優先するので、その最終 unit に末尾表紙補助を足さない。OFF のときは既存 assist 条件を維持する（src/ui_fullscreen.rs:13700）。
- paged、縦/横連結、holdover は同じ composition の natural side、白い slot の寸法・色を消費する。capture-time holdover は旧 unit の色と geometry を保持し、新設定で後から再判定しない。F12 active と passive frozen snapshot は白矩形を含む実 paint を同じ viewport geometry へ投影し、parked sibling の設定を変えない（src/ui_fullscreen.rs:7700, src/ui_fullscreen.rs:9710, src/ui_fullscreen.rs:17166）。detached viewport 経路に触れる際は docs/detached-rework-plan.md §2 の構造合意と §11 記録が必要。
- Remote server は同じ builder/composition から実ページ address 1 件と layout-only white-slot { side, reference dimensions } を IPC group に投影する。Web は既存 singleton virtual canvas fit を使い、白 slot の矩形を描く。白 slot の image URL、decode lease、prefetch、edit/export target は作らない。collection/truncated/synthetic では complete-book gate に従い二切替を適用しない。protocol version と Web asset token を既存更新手順で進める（src/remote_ipc/container.rs:4897, crates/remote-ipc/src/lib.rs:987, docs/web-remote-plan.md:2837）。

- 全体は after-cover/last の二 bool（既定 OFF）。本別は各々 FollowGlobal / On / Off の typed preference。spread.db の独立 table に exact book key で保存し、nested exact → root fallback と明示 FollowGlobal の fallback 遮断を §1.239 と同じ意味にする。同じ物理フォルダ内でも ZIP ごとに独立した本 key を使う。settings.db の live Remote 読書 snapshot、context bundle、metadata transfer、rename/purge、content identity 復元にも接続する。新機能の default OFF は旧本の見た目を保持し、自動 sidecar は増やさない（src/spread_db.rs:37, src/settings_db.rs:805, src/app/viewer_context_registry.rs:987）。
