## 2. §1.239 — 先頭と末尾を独立させる

1. `EndpointPlacementSettings { first: bool, last: bool }` と `EndpointPlacementPreferences { first, last: SingletonSpreadPlacementPreference }` を一つの値として App/context/Remote に渡す。各端だけ `effective(global_end)` で解決する。1 unit が両端なら**先頭優先**という現行規則を維持する。geometry は §1.218 の `Center/Left/Right` と仮想二枠 canvas をそのまま使う（`src/ui_fullscreen.rs:13717`、`docs/section218-singleton-spread-placement.md`「型と判定の唯一の所有者」）。
2. `settings.db` の新キー `singleton_spread_first_enabled` / `singleton_spread_last_enabled` は旧 `singleton_spread_placement_enabled` の値から両方へ原子的・冪等に移行する。旧キー無しは両方 OFF。旧 JSON/backup の serde 読込にも旧キーから両方への互換変換を用意する。新キーが存在すれば必ずそれを優先し、片端だけ欠けた状態を旧キーで静かに補わない。Remote の live reader も同じ migration/fallback 契約を使い、失敗時は書込抑止と明示エラーにする。released settings の移行は必須（`src/settings_db.rs:48`, `src/settings_db.rs:625`, `src/settings_db.rs:805`, `CLAUDE.md:1654`）。
3. `spread.db` は新 table `singleton_spread_endpoint_placements(path PRIMARY KEY, first_preference, last_preference)`、各 0=FollowGlobal / 1=Place / 2=Center と CHECK。旧 table の全 row を `(old, old)` へ transaction 内で copy し、移行済み marker/schema を記録する。旧 row 不在は両方 `FollowGlobal`。root の両端 FollowGlobal は row 削除、nested は `(0,0)` を保持して root fallback を遮る。片端だけ FollowGlobal の nested row も他端の明示値と共に保持する。旧 table 不在の read-only handle は両端継承、旧 table だけならその値を両端へ投影する。失敗時に旧 row を消さず retry 可能とし、旧 `spreads`/final-cover 行は生成しない（`src/spread_db.rs:65`, `src/spread_db.rs:240`）。
4. resolver は最終 presentation が実 1 page、complete canonical book、`UnpairedSlot` のときだけ `first` または `last` を選ぶ。横長・非 pairable、末尾表紙補助で二枚になった unit、collection/検索/切詰めは従来どおり Center。片端変更は page count、anchor、seek、source demand を変えず、その context の placement layout だけ invalidate する（`src/ui_fullscreen.rs:13496`, `src/ui_fullscreen.rs:13684`, `src/ui_fullscreen.rs:13717`, `src/ui_fullscreen.rs:15986`）。
5. paged、縦/横連結、holdover の capture-time placement、F12 の active と passive frozen projection を同じ composition 値から通す。parked sibling のうち変更端を継承する context のみ再計算し、旧 snapshot を現在設定から描き直さない（`src/ui_fullscreen.rs:7725`, `src/ui_fullscreen.rs:9818`, `src/ui_fullscreen.rs:17166`, `src/app/viewer_context_registry.rs:3223`）。detached viewport/述語に入る実装は `docs/detached-rework-plan.md` §2 の構造合意を先に得て §11 に記録する。
6. 本別 menu は「先頭」「末尾」それぞれ `全体設定に従う / 片側へ配置 / 中央表示`。環境設定は先頭/末尾二項目。metadata export/import、refresh、rename/purge、content identity 復元、Remote live snapshot/write、IPC/Web menu/refit を両端同時に更新する。metadata transfer は旧 bundle を受理し旧一括値から両端へ移行し、新形式の版を上げる。IPC protocol と Web asset token は既存 strict 手順で更新する（`src/metadata_transfer.rs:27`, `src/metadata_transfer.rs:4491`, `src/remote_ipc/ui.rs:2267`, `crates/remote-ipc/src/lib.rs:31`, `docs/web-remote-plan.md:2837`）。利用者文書 `docs/spec.md`、`htdocs/mimageviewer/manual/settings.html:1141`、`htdocs/mimageviewer/manual/fullscreen.html:441` と Remote 読書設定説明を実装時に更新する。

## 3. §1.240 — 表示専用白紙をページ構成に入れる

### 保存と構成

- **本別のみ、既定 OFF**。`spread.db` の別 table に `after_first` / `before_last` の二 bool を保存する。root 行不在は両方 OFF、nested の明示 `(OFF, OFF)` 行は root fallback を遮る。これは本の左右合わせであり、全体既定を変えて既存の全本へ適用しない。フォルダ/ZIP/PDF、nested exact/fallback、metadata transfer（新 bundle 版）、rename/purge、content identity、context bundle、Remote read/write を spread 設定と同じ経路に載せる。変換書庫は §1.242 の指定どおり元書庫 key を正本とするため、現 `spread.db` の cache ZIP key との adapter を設計・検証する。全体設定と自動 sidecar は追加しない（`src/spread_db.rs:37`, `src/metadata_transfer.rs:27`, `src/metadata_transfer.rs:454`, `docs/backlog-on-hold.md:1100`, `docs/backlog-on-hold.md:1140`, `docs/backlog-on-hold.md:1201`）。
- 先に完全な実ページ読書列を得て、**typed** `BookPageSlot = Real { item_idx, stable_page_identity } | Blank { id: AfterFirst | BeforeLast }` を作る。`after_first` は最初の実ページ直後、`before_last` は最後の実ページ直前に挿入し、同じ境界でも二つの異なる blank を保持する。1 枚本では `BeforeLast, Real, AfterFirst` の順にする。実 item 順、`GridItem`、ファイル path、検索/一覧/サムネイル catalog、補正 DB は変えない。blank ID は本・構成世代内だけで有効。単本 complete proof が無ければ挿入しない（`src/ui_fullscreen.rs:12875`, `src/ui_fullscreen.rs:15986`, `docs/backlog-on-hold.md:1107`）。
- builder の入力・cache token に typed slot 列と二設定値を入れる。unit は **二つの物理 slot** と navigation identity を持ち、`Real+Blank` は「実 1 枚 + 明示空き側」、`Blank+Blank` と余った `Blank` は空の見開き step として表現する。blank は paired slot だが `SpreadPageOccurrence` や `SpreadPair::Double { left, right }` の偽 idx にならない。`SpreadDisplayComposition` と `FsNavigationDisplayDemand` の「実 anchor 必須」constructor は typed unit / optional real projection に改め、空 step を明示的に受理する。source/texture/readiness/AI/keep は Real のみ、空き側は背景。`UnpairedSlot`（相方不在）と `BlankCompanion`（相方が明示白紙）を異なる形成理由にする（`src/ui_fullscreen.rs:13513`, `src/ui_fullscreen.rs:13532`, `src/ui_fullscreen.rs:13566`, `src/ui_fullscreen.rs:13648`, `src/ui_fullscreen.rs:14386`, `docs/backlog-on-hold.md:1184`）。
- 現在位置は `fs_idx` だけでは空 step や同じ実ページの複数 occurrence を識別できない。`BookUnitCursor { composition_generation, unit_ordinal, optional_real_anchor }` を navigation/continuous/slideshow/Remote に通し、real action だけ `item_idx` へ投影する。book reopen、別本、設定 toggle、並べ替え、非同期完了では世代を検査し、現 real identity を含む新 unit、無ければ近傍 real unit へ再束縛する。blank だけの cursor は UI 内の一時位置であり永続 page identity にしない（`src/app.rs:9489`, `src/ui_fullscreen.rs:13532`, `src/ui_fullscreen.rs:14416`, `src/ui_fullscreen.rs:15177`, `src/book_resume_db.rs:61`）。

### 各画面と操作の契約

- 見開きのページ送り・seek track・Home/End・slideshow は typed **unit** を進む。空 step も一拍として表示し、End は最後の unit。ページ番号の分母は実ページ数のまま。`Real+Blank` は実ページ番号、空 step は「白紙（先頭の後／末尾の前）」と表示し、偽の `N+1` 番を付けない。seek track は blank を含む unit 数を使い、thumb strip には blank 専用の無画像セルを作ってクリックでその unit へ移動する。実ページをクリック/ページ番号ジャンプすると、その実ページを含む unit へ行く（`src/ui_fullscreen.rs:14426`, `src/ui_fullscreen.rs:15312`, `src/ui_fullscreen.rs:19879`, `src/ui_fullscreen.rs:20416`）。
- resume は既存 `book_resume.db` の**実 item index** を維持する。blank-only step にいる間は直前の実ページ（無ければ次の実ページ）を記録し、再起動時はその real を含む unit に戻る。history/bookmarks/linked reading は実ページ identity だけを保存・公開し、blank-only step は新規 bookmark 対象外。blank からの rating/tag/edit/crop/export/external tool/copy/delete は disabled、`Real+Blank` では実ページ 1 件だけが操作対象。pointer hit も blank 側に実ページを返さない（`src/book_resume_db.rs:43`, `src/book_bookmarks.rs:144`, `src/ui_fullscreen.rs:13519`, `src/app.rs:9719`, `docs/virtual-folders.md` §5）。
- Single/landscape Split は実ページ列を従来どおり表示し、blank 設定は保存したまま視覚とページ送りには適用しない。見開きの縦/横連結は同じ unit 列で blank 枠・空 step の scroll extent を保つ。横長ページとその隣の blank は同一面に強制 pair しない。横長は既存単独表示を優先し、blank は次の pair/空 step に残る。ずらし anchor は typed slot 境界で再解決し、toggle 後に古い offset を index だけで流用しない（`src/ui_fullscreen.rs:14130`, `src/ui_fullscreen.rs:14376`, `src/ui_fullscreen.rs:16067`, `docs/section218-singleton-spread-placement.md`「縦連結 / 横連結」）。
- 末尾表紙補助は **最後の navigation unit が実 singleton** の場合だけ従来どおり加える。blank と組んだ末尾実ページ、または末尾空 step へ表紙を添えない。cover phase は最初の**実**ページを基準にし、1 枚本で `BeforeLast` が先にあっても blank を表紙扱いしない。§1.239 は blank 挿入**後**の unit 列へ適用し、端の実 singleton かつ `UnpairedSlot` にだけ first/last 規則を使う。`Real+Blank` は明示 blank の左右 slot で表示し、端 preference を重ねない。1 unit が両端なら first 優先（`src/ui_fullscreen.rs:13700`, `src/ui_fullscreen.rs:13717`, `src/ui_fullscreen.rs:14130`）。
- Remote は同じ typed composition から unit ID、real address slot、blank slot を送る。blank に address を作らず image/decode/preload HTTP 要求もしない。Web の navigation/seek と presentation を分けた既存構造を拡張し、空 step の描画と前後操作、reload/refresh での cursor 維持を検証する。collection/truncated/synthetic は対象外（`crates/remote-web/web/app.js:4752`, `crates/remote-web/web/app.js:4786`, `src/remote_ipc/container.rs:4943`, `docs/web-remote-plan.md:2839`）。
- `KeyAction::FsToggleBlankAfterFirst` / `FsToggleBlankBeforeLast` を `FsImage`、既定 chord なしで追加。menu と action は同じ現在本の書込・世代更新・cursor 再束縛経路を呼ぶ。keymap `all` / name / label / context / default / dispatch / help と `docs/keymap-spec.md`、`docs/key-customization-impl-plan.md` を更新する。テキスト入力中、非 book、編集モードでは既存の入力所有に従い実行しない。`docs/spec.md` と `htdocs/mimageviewer/manual/settings.html` / `fullscreen.html`、Remote manual に白紙・ページ番号・single mode の説明を追加する（`src/keymap.rs:1653`, `src/keymap.rs:2198`, `src/keymap.rs:5336`, `src/keymap.rs:6346`, `docs/keymap-spec.md:53`）。
- §1.242 はこの `Real | Blank` と安定 source identity・unit ordinal を拡張して任意配置を表せる。今回、実 items の並べ替え/非表示、構成 editor、任意位置 blank、pair の手編集は実装しない。§1.242 の旧調査にある「白紙は単ページ表示に出ない」は上の Single 契約と整合するが、1–2 枚本で blank-only **見開き step** は発生し得るため reviewer が確認する（`docs/backlog-on-hold.md:1146`, `docs/backlog-on-hold.md:1184`）。

## 5. レビューで決める点 / v4.1.0 の境界

- **利用者判断候補:** blank は本別のみ・既定 OFF、Single/Split では非表示、blank-only 見開き step はページ送りに含む、resume は実ページへ戻る、という提案。1–2 枚本で空 step を見せない仕様を望むなら、二つの独立 toggle の衝突規則を別途決める必要がある。
- **レビュー上の主なリスク:** 現 `SpreadPair`/`SpreadPageOccurrence`/`fs_idx` が実 index 必須なので §1.240 は局所的な builder 変更では済まない。typed cursor と全 consumer 接続・Remote wire・多窓 projection を完成できない場合、§1.240 を v4.1.0 から延期する。空白を偽 `GridItem`/path にする、blank-only step を黙って落とす、既存機能を止める縮小案は採らない。§1.239 は独立して出せる。
