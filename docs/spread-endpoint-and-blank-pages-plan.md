## 2. §1.239 — 先頭と末尾を独立させる

1. `EndpointPlacementSettings { first: bool, last: bool }` と `EndpointPlacementPreferences { first, last: SingletonSpreadPlacementPreference }` を一つの値として App/context/Remote に渡す。各端だけ `effective(global_end)` で解決する。1 unit が両端なら**先頭優先**という現行規則を維持する。geometry は §1.218 の `Center/Left/Right` と仮想二枠 canvas をそのまま使う（`src/ui_fullscreen.rs:13717`、`docs/section218-singleton-spread-placement.md`「型と判定の唯一の所有者」）。
2. `settings.db` の新キー `singleton_spread_first_enabled` / `singleton_spread_last_enabled` は旧 `singleton_spread_placement_enabled` から両方へ同じ値を写す。**選択する failure-safe 規則は「committed marker が無い間は旧値を両端へ投影」**。専用 migration marker と新二キーを一 transaction で書き、marker がある場合に限り新二キーを正本として読む。旧キー無しは両方 OFF。marker 無しで新キーが 0/1/2 個ある状態はすべて未完了として扱い、特に**片方だけある状態を不完全と診断**する。旧キーから両端へ投影して次回再試行し、未完了中の `save_full` と個別設定書込を抑止する。marker 有りで片キー欠損・不正なら旧値/既定値へ黙って戻さず読込エラーと保存抑止へ送る。書込失敗でも利用者に旧 ON の見た目を保持でき、既存 loader の「migration error を記録して継続」による quarantine 誘発を避けられるためこの規則を選ぶ（`src/settings_db.rs:625`, `src/settings_db.rs:627`, `src/settings_db.rs:853`）。
   旧 JSON/backup 読込も旧 bool→両端の互換変換を行い、復元した旧 `settings.db` は marker 無しとして再移行する。Remote `load_remote_reading_settings` も同じ marker-gated helper を使い、未完了なら旧キーの live 値を両端へ投影する。移行失敗・不完全状態を起動時設定の古い clone で覆わない。released settings の移行は必須（`src/settings_db.rs:48`, `src/settings_db.rs:805`, `CLAUDE.md:1654`）。
3. `spread.db` は新 table `singleton_spread_endpoint_placements(path PRIMARY KEY, first_preference, last_preference)`、各 0=FollowGlobal / 1=Place / 2=Center と CHECK。旧 table の**全 row** を `(old, old)` へ copy し、専用 completed marker と共に一 transaction で commit する。table の存在だけを移行完了とみなさない。marker 有りの read は新 table のみを使い、表/列欠損はエラー。marker 無しの read は旧 table を両端へ投影し、書込可能 open は次回 transaction を再試行する。途中で新 table のみ作られていた場合は旧 table から再構成して commit し、未完了中の新 endpoint 書込は拒否する。read-only 旧 DB は旧 table の root/nested row を両端へ投影し、旧 table も無ければ両端 `FollowGlobal`（`src/spread_db.rs:65`, `src/spread_db.rs:84`, `src/spread_db.rs:240`）。
   root の両端 FollowGlobal は row 削除、nested は `(0,0)` を保持して root fallback を遮る。片端だけ FollowGlobal の nested row も保持する。旧 `spreads`/final-cover 行は生成しない。移行失敗時に旧 row は不変で retry 可能。marker 有りなのに新 row/表が壊れた場合は旧値へ silent fallback しない。
4. resolver は最終 presentation が実 1 page、complete canonical book、`UnpairedSlot` のときだけ `first` または `last` を選ぶ。横長・非 pairable、末尾表紙補助で二枚になった unit、collection/検索/切詰めは従来どおり Center。片端変更は page count、anchor、seek、source demand を変えず、その context の placement layout だけ invalidate する（`src/ui_fullscreen.rs:13496`, `src/ui_fullscreen.rs:13684`, `src/ui_fullscreen.rs:13717`, `src/ui_fullscreen.rs:15986`）。
5. paged、縦/横連結、holdover の capture-time placement、F12 の active と passive frozen projection を同じ composition 値から通す。parked sibling のうち変更端を継承する context のみ再計算し、旧 snapshot を現在設定から描き直さない（`src/ui_fullscreen.rs:7725`, `src/ui_fullscreen.rs:9818`, `src/ui_fullscreen.rs:17166`, `src/app/viewer_context_registry.rs:3223`）。detached viewport/述語に入る実装は `docs/detached-rework-plan.md` §2 の構造合意を先に得て §11 に記録する。
6. 本別 menu は「先頭」「末尾」それぞれ `全体設定に従う / 片側へ配置 / 中央表示`。環境設定は先頭/末尾二項目。metadata export/import、refresh、rename/purge、content identity 復元、Remote live snapshot/write、IPC/Web menu/refit を両端同時に更新する。metadata transfer の出力版を v8 に上げ、**入力は released v7 と v8 の manifest・shard header の両方を明示受理**する。同じ bundle 内の manifest/header 版一致を要求し、未知版は拒否。v7 の `singleton_spread_placement` は root と nested の明示 `FollowGlobal(0)` 行も含め、各行を `(old, old)` として v8 endpoint state へ移す。row absent は absent のまま。現 importer は両 header を `FORMAT_VERSION=7` に厳密比較するため、定数更新だけでは旧 bundle を失う（`src/metadata_transfer.rs:27`, `src/metadata_transfer.rs:456`, `src/metadata_transfer.rs:3041`, `src/metadata_transfer.rs:3062`, `src/metadata_transfer.rs:4491`）。IPC protocol と Web asset token は既存 strict 手順で更新する（`src/remote_ipc/ui.rs:2267`, `crates/remote-ipc/src/lib.rs:31`, `docs/web-remote-plan.md:2837`）。利用者文書 `docs/spec.md`、`htdocs/mimageviewer/manual/settings.html:1141`、`htdocs/mimageviewer/manual/fullscreen.html:441` と Remote 読書設定説明を実装時に更新する。

## 3. §1.240 — 表示専用白紙をページ構成に入れる

### 利用者決定と二段階の実装境界（2026-09-24）

- **確定仕様:** 白紙の二設定は全体既定 + 本ごとの override。多数の同一フォルダ内同人誌 ZIP は裏表紙等の欠け方が違うので、ZIP ごとに別値を保存できること。Single と横長 Split では白紙を表示せず、設定を保持して見開きへ戻ると適用する。blank-only 見開き step はページ送りに含む。>>402 の元要望に従い、**白紙の表示サイズは隣の実ページと同じ**（例: 03 と 34 の近傍）。これらは未決定の利用者判断候補ではない（`docs/backlog-on-hold.md:1100`, `docs/backlog-on-hold.md:1184`）。
- **Stage 1 — 挙動不変の typed unit cursor 基盤、Large（単独実装で概ね 1–2 週間）:** `BookUnitCursor { composition_generation, unit_ordinal, optional_real_anchor }` を viewer context bundle が所有し、見開き中の**現在位置の authority** とする。`fullscreen_idx` は実ページ操作用の派生 projection へ降格し、空 step の sentinel にしない。全入口（ページ送り、Home/End、seek、go-to-page、slideshow、履歴・しおり、連結読み、Remote、F12 activation）を cursor へ正規化し、navigation phase/target/demand、holdover capture、ready/failure terminal、paint、passive frozen snapshot へ同じ unit identity を通す。まだ白紙を生成せず、全既存 unit は実 anchor を持ち、従来の表示・保存・Remote wire と全モードの出力を維持する。現在の `anchor_idx()` と `FsNavigationDisplayDemand`、ページ送り target は実 index 必須なので、この段階を builder 変更より先に完了させる（`src/ui_fullscreen.rs:14009`, `src/app.rs:9489`, `src/ui_fullscreen.rs:26723`, `src/app/viewer_context_registry.rs:987`）。
- **Stage 2 — 白紙構成と全 consumer、Large–Very Large（単独実装で概ね 2–4 週間）:** 二設定の永続化、typed `Real | Blank`、blank-only cursor、白紙 geometry・paint、paged/連結/F12/Remote、KeyAction と実ページ専用操作を一つの完成機能として接続する。Stage 1 の cursor に optional real projection が無い unit を入れ、空 step の phase は source request 0 件で即 ready となる typed 状態にする。前の holdover は新 blank paint が提示されるまで残し、blank paint と frozen geometry は capture-time unit/viewport に属する。async 完了は cursor 世代を照合し、別窓や旧構成へ戻さない。ここだけを局所的に bypass する実装は認めない。

### 保存と構成

- 全体設定は `BlankInsertionDefaults { after_first: bool, before_last: bool }`、両方既定 OFF。本別は端ごとの `FollowGlobal / On / Off` を `BlankInsertionPreferences` として一体保持し、各端だけ実効値を解決する。`settings.db` と Remote の live reading snapshot に全体値、`spread.db` の独立 table に本別値を保存する。root 行不在は両方 FollowGlobal、nested の明示 `(FollowGlobal, FollowGlobal)` は root fallback を遮る。**同じ物理フォルダに並ぶ ZIP ごと**に独立した exact book key を解決し、親フォルダの二設定を機械的に同一視しない。全体変更は継承する context の構成だけ更新し、明示 override の sibling は触らない。新機能なので旧 blank 値の移行元は無く、既存本の見た目は全体既定 OFF により維持する（`src/settings_db.rs:805`, `src/spread_db.rs:37`, `src/app/viewer_context_registry.rs:3223`）。
- フォルダ/ZIP/PDF、nested exact/fallback、metadata transfer（新 bundle 版）、rename/purge、content identity、context bundle、Remote read/write を spread 設定と同じ経路に載せる。変換書庫は §1.242 の指定どおり元書庫 key を正本とするため、現 `spread.db` の cache ZIP key との adapter を設計・検証する。自動 sidecar は追加しない（`src/metadata_transfer.rs:27`, `src/metadata_transfer.rs:454`, `docs/backlog-on-hold.md:1140`, `docs/backlog-on-hold.md:1201`）。
- 先に完全な実ページ読書列を得て、**typed** `BookPageSlot = Real { item_idx, stable_page_identity } | Blank { id: AfterFirst | BeforeLast }` を作る。`after_first` は最初の実ページ直後、`before_last` は最後の実ページ直前に挿入し、同じ境界でも二つの異なる blank を保持する。1 枚本では `BeforeLast, Real, AfterFirst` の順にする。実 item 順、`GridItem`、ファイル path、検索/一覧/サムネイル catalog、補正 DB は変えない。blank ID は本・構成世代内だけで有効。単本 complete proof が無ければ挿入しない（`src/ui_fullscreen.rs:12875`, `src/ui_fullscreen.rs:15986`, `docs/backlog-on-hold.md:1107`）。
- builder の入力・cache token に typed slot 列と二設定値を入れる。unit は **二つの物理 slot** と navigation identity を持ち、`Real+Blank` は「実 1 枚 + 明示白紙側」、`Blank+Blank` と余った `Blank` は白い見開き step として表現する。blank は pairable な構成 slot だが `SpreadPageOccurrence` や `SpreadPair::Double { left, right }` の偽 idx にならない。`SpreadDisplayComposition` と `FsNavigationDisplayDemand` の「実 anchor 必須」constructor は typed unit / optional real projection に改め、空 step を明示的に受理する。source/texture/AI/cache keep は Real のみ。`UnpairedSlot`（相方不在・背景のまま）と `BlankCompanion`（明示白紙・白い面を描く）を異なる形成理由にする（`src/ui_fullscreen.rs:13513`, `src/ui_fullscreen.rs:13532`, `src/ui_fullscreen.rs:13566`, `src/ui_fullscreen.rs:13648`, `src/ui_fullscreen.rs:14386`, `docs/backlog-on-hold.md:1184`）。
- blank の紙面サイズは固有 raster でなく参照実ページの **保存回転後・表示トリム後の可視 page canvas** から導く。`AfterFirst` は先頭実ページ、`BeforeLast` は末尾実ページを参照し、pair 相手や設定切替で勝手に寸法を変えない。`Real+Blank` は両 slot 固有の寸法から同じ spread fit を解く。blank が参照元実ページと並ぶときは紙面寸法が一致する。paged、縦/横連結、Remote Web の全 geometry と F12 frozen projection に slot の左右と寸法を渡す。`Blank+Blank` では各 blank が自身の参照実ページの寸法を持つ。寸法が未準備なら参照実ページの metadata completion を待つが blank texture/decode は作らず UI を block しない。白い矩形を実 paint し、§1.218 の「相方不足で背景が見える」見た目と区別する（`src/ui_fullscreen.rs:13431`, `src/ui_fullscreen.rs:7926`, `src/ui_fullscreen.rs:8025`, `docs/section218-singleton-spread-placement.md`「仮想キャンバスと fit」）。
- Stage 1 の cursor を navigation/continuous/slideshow/Remote の唯一の unit 位置として使い、real action だけ `item_idx` へ投影する。book reopen、別本、設定 toggle、並べ替え、非同期完了では世代を検査し、現 real identity を含む新 unit、無ければ近傍 real unit へ再束縛する。blank だけの cursor は UI 内の一時位置であり永続 page identity にしない（`src/ui_fullscreen.rs:14416`, `src/ui_fullscreen.rs:15177`, `src/book_resume_db.rs:61`）。

### 各画面と操作の契約

- **unit navigation**（ページ送り、seek track、Home/End、slideshow、連結 scroll、Remote next/prev）は typed cursor の unit ordinal を進む。blank-only step も一拍として表示し、End は最後の unit。**real page selection**（ページ番号ジャンプ、しおり、検索/一覧クリック、編集・書き出し対象指定）は実 `PageIdentity` を含む unit へ解決する。`Real+Blank` は実対象 1 件、`Blank+Blank` は 0 件であり、後者から実ページ選択を要求する操作は disabled。`FsSeekInfo` と page-number cache、prepared seek label は cursor/unit 列の snapshot と real projection を同じ世代で受け、blank に偽番号を付けない（`src/ui_fullscreen.rs:14426`, `src/ui_fullscreen.rs:19831`, `src/ui_fullscreen.rs:19916`, `src/ui_fullscreen.rs:26723`）。
- ページ番号の分母は実ページ数のまま。`Real+Blank` は実ページ番号、blank-only step は「白紙（先頭の後／末尾の前）」と表示する。seek track は blank を含む unit 数を使い、thumb strip には blank 専用の無画像セルを作ってクリックでその unit へ移動する。strip の既存実 thumbnail は同じ item index に留める。実ページをクリックするとその実ページを含む unit へ行く（`src/ui_fullscreen.rs:15312`, `src/ui_fullscreen.rs:19879`, `src/ui_fullscreen.rs:20416`）。
- resume は既存 `book_resume.db` の**実 item index** を維持する。blank-only step にいる間は直前の実ページ（無ければ次の実ページ）を記録し、再起動時はその real を含む unit に戻る。history/bookmarks/linked reading は実ページ identity だけを保存・公開し、blank-only step は新規 bookmark 対象外。blank からの rating/tag/edit/crop/export/external tool/copy/delete は disabled、`Real+Blank` では実ページ 1 件だけが操作対象。`FullscreenPageLayout` と pointer hit は slot の物理 rect と optional real occurrence を保持し、白紙 hit に実ページを返さない。`FsPageTurnReadySignature` は unit identity と**実 source occurrence のみ**を含め、blank-only は空 demand を明示的に ready とする。spread export composition も実 source slot だけから作り、白紙と組む場合は既存の実 1 枚 export、blank-only なら拒否する（`src/book_resume_db.rs:43`, `src/book_bookmarks.rs:144`, `src/ui_fullscreen.rs:14907`, `src/ui_fullscreen.rs:44539`, `docs/virtual-folders.md` §5）。
- Single/landscape Split は実ページ列を従来どおり表示し、blank 設定は保存したまま視覚とページ送りには適用しない。見開きの縦/横連結は同じ unit 列で blank 枠・空 step の scroll extent を保つ。横長ページとその隣の blank は同一面に強制 pair しない。横長は既存単独表示を優先し、blank は次の pair/空 step に残る。ずらし anchor は typed slot 境界で再解決し、toggle 後に古い offset を index だけで流用しない（`src/ui_fullscreen.rs:14130`, `src/ui_fullscreen.rs:14376`, `src/ui_fullscreen.rs:16067`, `docs/section218-singleton-spread-placement.md`「縦連結 / 横連結」）。
