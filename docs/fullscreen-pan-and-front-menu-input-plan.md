## 1. 共通の土台

通常のページ単位表示 (単ページ・見開き。Z ズーム・連結読み・360・比較は対象外) のパンは、
`clamp_fullscreen_pan_from_layout` (`src/ui_fullscreen.rs`) が「少なくとも 1 ページの 48px (`FS_PAN_MIN_VISIBLE_PX`) を画面内に残す」範囲に収める。
この制限は入力 (`set_fs_pan_from_input`・ホイールズーム・§1.474 のページ内スクロール) のときにだけ、前の frame に描いた layout から計算する。

- §1.806: 倍率が変わる入力で、前の frame の矩形を倍率の比で投影するとき、通常の見開きのページ間隔まで比例させてしまう (実際の描画は間隔が固定)。
- §1.810: 入力を伴わずに描く形が変わる (回転) と、制限を計算し直す機会が無い。
- §1.807: パンとは別。前面メニューが開いているときに、背後の表示を動かすキーを受け付けるかの判定が、入口によって違う。

## 2. §1.806 見開きのページ間隔の投影

### 2.1 現象 (コード)

`layout_spread_page_rects` は、左右のページの見える幅を倍率で伸ばし、間隔 `spread_gap` は倍率に関係なく固定で置き、全体を中心にそろえる。
`clamp_fullscreen_pan_from_layout` は各ページの描いた矩形を「中心 + パン」の基準点から倍率の比 `r` で投影するので、
左ページの右端は `基準点 - (g/2)·r` に投影されるが、実際の描画では `基準点 - g/2` になる。差は `g·(r-1)/2` (間隔 200・倍率 1→2 で 100pt)。
`SingletonSpread` (白ページ付きの単独ページ) には同じ補正 `singleton_spread_projected_gap_correction` があり、通常の 2 ページの見開きにだけ無い。

### 2.2 決定

- 投影で使う「固定の間隔と、間隔に対するページの側」は、描画で間隔を置いた側 (layout の作り手) が記録し、clamp はそれを読むだけにする。
  clamp の時点で設定 (`spread_page_gap_px`) を読み直さない (前の frame の描画と同じ値でなければ投影が合わないため)。
- 補正の式は `SingletonSpread` と同じ 1 つの helper にまとめる (側と間隔を受け取る形)。単独ページと 2 ページの見開きで式を 2 か所に書かない。
- 記録の置き場所は実装担当が決めてよい (例: `ResolvedDisplayPlacement::Normal` に見開きの側と間隔を持たせる、`FullscreenPageLayout` の見開きの組に間隔を持たせる)。
  条件は「描画で使った値そのもの (物理 px への丸め後) を、描いた frame の layout と一緒に持つ」こと。
- 縦方向・回転したページ・トリムのあるページでも、間隔は横方向にだけ入る (`layout_spread_page_rects` のとおり)。

### 2.3 テストで守る不変条件

「前の frame の layout から倍率 `z1` へ投影した各ページの矩形」が、「倍率 `z1` で実際に描いた layout の矩形」と一致する (物理 px の丸めの範囲で)。
見開き (間隔 0 / 200、左右の幅が違うページ、トリムあり) で、倍率 1→2・2→1 の両方。端に当てたときに止まる位置が、次の frame で描いた layout から計算し直した位置と同じになること。

## 3. §1.810 回転したあとのパンの制限

### 3.1 現象 (サブ PC 担当の観測とコード)

観測 (サブ PC 担当、§1.474 の確認 4-7): 縦長の画像を横幅フィットで全画面にし、R → 横の端までスクロール → L で戻すと真っ黒になり、↓↑・Shift+ホイールでも戻らない。
コード: 回転 (`apply_rotation`) は `fs_pan` / `fs_zoom` に触れず、描く形が変わっても制限を計算し直す経路が無い。

### 3.2 案の比較と決定

- 案 A (回転したら初期配置に戻す) は、今の「回転しても倍率と位置を保つ」挙動が変わるので採らない (利用者への相談が要る案)。
- **案 B を採る**: 回転が変わったページを描く最初の frame で、その frame に描く形に対してパンを制限し直し、**同じ frame をその制限後のパンで描く**。
  倍率は保ち、範囲内のパンは 1 px も動かさない (制限が動かすのは範囲外のときだけ)。
- 「次の frame で直して再描画」にはしない。1 frame だけ画面外の絵が出るうえ、再描画の要求を足すことになる。
  同じ frame で直す前例として、§1.726 の初期配置 (`resolve_fs_initial_placement`) が、描画中に解決した矩形からパンを決めてその frame をそのパンで描き、`fs_pan` に書き戻している。同じ位置・同じ形にそろえる。

### 3.3 きっかけの判定 (状態を増やさない)

- 新しい要求・印のフィールドは作らない。きっかけは、この context が前の frame に描いた layout (`fullscreen_page_layout`、viewer context ごとに swap される) と、今の frame で描く形の比較から導く。
  「前の frame に描いた同じページ (idx) の 90° 単位の回転が、今の frame で描く回転と違う」ときだけ制限し直す。
- 回転の書き手 (R / L・回転メニュー・別ウィンドウからの回転・一括回転など) を列挙して要求を配る形にしない。書き手が増えても、描く側の比較 1 か所で拾える。
- 別の context (F12 の別ウィンドウなど) で同じページが表示されていれば、その context は自分の次の描画で自分の layout と比べて自分の `fs_pan` だけを直す。ほかの context の状態には触れない。
- 偽のきっかけ (フォルダを替えて同じ idx の別の画像になった、など) は害が無い: 制限し直しは範囲内のパンを動かさないので、範囲外でなければ何も変わらない。
  ページを替えたときはパンの初期化・初期配置の既存経路がそのまま先に効く。
- 初期配置 (§1.726) がその frame で適用されるときは、そちらのパンを使い、制限し直しはしない (初期配置のパンは端に合わせた範囲内の値)。

### 3.4 制限の計算

- 入力のときと同じ規則 (少なくとも 1 ページの 48px を画面内に残す、見開きは補正量が最小のページを採る) を、今の frame に描く矩形にそのまま当てる。
  `clamp_fullscreen_pan_from_layout` の「倍率の比が 1 の場合」と同じ結果になるよう、計算は共有の純関数に寄せ、規則を 2 か所に書かない。
- 制限で動いた分だけ、その frame の矩形を平行移動して描く (または制限後のパンで transform を解決し直す)。どちらでも、`fullscreen_page_layout` に記録する矩形・パン (`zoom_pan`)・§1.474 の描いた表示単位の印 (`FsDrawnUnitStamp`) が、実際に描いたものと一致すること。
- `fs_pan` に書き戻すのは、制限で値が変わったときだけ。書き戻しは「利用者入力」ではないので、`set_fs_pan_from_input` は通さない (初期配置の要求を消す副作用を持ち込まない)。
  自動の初期配置との一致判定 (`fs_automatic_initial_view`) は、範囲外から戻した結果なので「動かした」扱いのままでよい (回転前に利用者が動かしていたため)。
- 対象は通常の配置 (`Normal` と `SingletonSpread`、倍率の持ち主が画像) だけ。Z ズーム・連結読み・360・比較・編集モードの各モードは、それぞれの制約を持つので触らない。

### 3.5 対象外 (今回は直さない、記録だけ)

回転以外にも、入力を伴わずに描く形が変わり得るもの (ウィンドウの寸法の変化、自動トリムの結果の到着、フィットの切り替えでパンを保つ経路があれば) は、同じ「入力のときだけの制限」の土台に乗る。
実装担当は、パンを保ったまま描く形を変える経路を列挙して報告する。症状が確かめられていないものは今回の範囲に入れず、バックログ §1.810 に候補として記録する
(きっかけを「描く形の比較」にしたので、後で比較する項目を足せば同じ所で扱える)。

## 4. §1.807 前面メニューが開いているときの背後のキー入力

### 4.1 現象 (コード、およびサブ PC 担当の観測)

- ROOT 経由: `handle_fullscreen_root_key_input` は ROOT の `ctx` を共通の全画面キー handler に渡す。egui の Popup の記憶は viewport ごとなので、
  handler の `fs_still_seek_strip_popup_open(ctx)` の早期 return と固定の矢印 (`consume_arrow`) は、全画面ウィンドウ側で開いているポップアップを見ない。
- 同じウィンドウ: 固定の矢印は、同じ viewport の回転メニュー (マウスで開くとフォーカスが無い) も見ない。
  サブ PC 担当の観測 (§1.474 の確認 8-4): 上下キーを「ページ内スクロール」にして回転メニューを開いたまま ↓ を押すと、背後の画像がスクロールし、メニューは開いたまま。
- §1.474 の新しい操作 (J / K・4 方向) は、配送元と配送先の両方の viewport を照会する `fs_page_scroll_front_menu_presented` で止まる (サブ PC 担当の観測 8-2)。

### 4.2 決定

- 「前面メニューが開いているか」の問いは 1 つの helper に寄せる。配送元 (`ctx` の viewport) と、全画面の配送先 viewport の両方を照会する。
  §1.474 の `fs_page_scroll_front_menu_presented` をこの helper にし (名前は用途に合わせて変えてよい)、新しい操作もこれまでどおりそれを使う。
- この helper が真のとき、全画面のキー handler は**背後の表示を動かすキー入力を受け付けず、消費もしない** (イベントはメニュー側に残す。シークのポップアップの既存の扱いと同じ)。
  対象は、固定の矢印 (↑↓←→ と Shift 付き)、keymap のページ送り (`FsPageNext` / `FsPagePrev`・固定ジャンプなど)、§1.474 のページ内スクロール。
  実装担当は handler の中で背後の表示 (ページ・パン・スクロール) を動かす消費者を列挙し、同じ判定に通す。列挙した一覧を設計書 §6 に残す。
- シークのポップアップの既存の早期 return は、配送先の viewport も見る同じ helper に置き換える。早期 return の前に行っている native のマウス戻る/進むの回数の取り出しは、今の順序のまま保つ。
- 前面メニューが開いていても受け付けたままにするもの: Esc (メニューを閉じる経路は egui 側にあり、イベントを残せば閉じる)、ダイアログ・IME・テキスト入力 (既存の判定のまま)。
  回転 (R / L) など背後の表示を「動かさない」ショートカットの扱いは変えない (今回の範囲は背後の表示を動かすナビゲーションだけ)。
- 既定の設定での挙動の変化: 回転メニューなどをマウスで開いたまま ↓ / PageDown などを押すと、今は背後でページが送られる見込み (コード読み、未確認) だが、修正後は送られない。
  J / K とシークのポップアップは既にそう動くので、それにそろえる修正として扱う (統括からの指示で、ROOT 経由と同じウィンドウの回転メニューの両方を対象にする、2026-11-18)。

### 4.3 テスト

- §1.474 の回帰テスト (`root_dispatched_scroll_keys_leave_the_destination_rotation_popup_unconsumed`) と同じ形の handler テストで:
  - ROOT に ↓ / PageDown を配送し、配送先の全画面 viewport でフォーカスの無い回転ポップアップ・シークのポップアップが開いているとき、ページが送られず、イベントが消費されないこと。閉じた後は送られること。
  - 同じ viewport で回転ポップアップが開いているとき、↓ (既定のページ送り・ページ内スクロールの両設定) が背後を動かさないこと。
  - メニューが無いときの既定の挙動 (↑↓←→・PageDown・Shift+↑↓・スタックジャンプ) が変わらないこと。
- テストで、キーの状態を実機から読む形 (偽の入力を消した後の判定) を新しく書かない (§1.814 (a) と同じ落とし穴)。

## 5. 守ること (3 件共通)

- 症状パッチ (guard・delay・retry・追加 repaint・一括 reset・silent fallback) を入れない。§1.810 の制限し直しは「入力のときだけ」という制限の欠けを、描く形が変わった描画で補う構造の修正で、遅延や再描画を使わない。
- detached viewer: 触れるのは context ごとに swap される `fs_pan` と `fullscreen_page_layout` の読み書き、および配送先 viewport の Popup の照会だけ。detached の述語・viewport の経路は変えない。
  変えた場合は CLAUDE.md の「Detached viewer リワーク中のルール」に従い、双方のレビューで「症状パッチではなく構造的修正」と合意し、[detached-rework-plan.md](detached-rework-plan.md) に記録する。
- UI スレッドに新しい同期 I/O を足さない。描画中の追加計算は、解決済みの矩形の比較と平行移動だけにする。
- 既定設定で変わるのは §4.2 の「前面メニュー中のナビゲーション」だけ。パンの制限は範囲内のパンを動かさない。
