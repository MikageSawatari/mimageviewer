# 3D 写真 (AI 深度推定による視差表示) — 実装方法の調査

状態: **調査のみ (2026-11-06)**。設計・実装は未着手。採否と範囲は利用者の判断待ち。
バックログ番号は未採番。

## 1. 目的と参考

1 枚の写真・イラストから AI で深度 (奥行き) を推定し、見る角度を少しずらす動きを付けて
立体的に見せる。フルスクリーンで見るだけでなく、**GIF / APNG / MP4 のアニメーションとして
書き出す**ことも目標に含める (2026-11-06 利用者要望)。

利用者が示した参考は
[ふかふかの立体GIFの記事](https://fukafuka295.jp/gif_rittai/) で紹介されている Windows フリーソフト
『ちくわ』。利用者がペンで深度を塗り分け (手前=赤 / 奥=青)、左右に揺れる GIF を出力する。
今回の案は、この「深度を塗る」工程を AI の深度推定に置き換え、必要なら手で直せるようにするもの。

## 2. 既存製品の手法 (Web 調査)

| 製品 / 研究 | 手法 | 要点 |
| --- | --- | --- |
| Facebook 3D Photos ([Kopf 2020](https://arxiv.org/abs/2008.12298)) | 単眼深度 → 層状深度画像 (LDI) → 段差でメッシュを裂き、隠れた背景を AI で補完 | 段差の引き伸ばしを根本的に減らす |
| Google Photos [Cinematic photos](https://research.google/blog/the-technology-behind-cinematic-photos/) | 単眼深度 + 人物セグメンテーション → 深度で押し出したメッシュ | 補完はせず、カメラ軌道を写真ごとに選んで引き伸ばしを目立たない場所へ逃がす。少し拡大して画像外を見せない |
| Apple Spatial Scenes (iOS 26) | 非公開。Apple の [SHARP](https://github.com/apple/ml-sharp) (1 枚 → 3D Gaussian) が基盤との報道あり (未確認) | SHARP の重みは研究用途限定で使えない |
| Wallpaper Engine [Depth Parallax](https://docs.wallpaperengine.io/en/scene/effects/effect/depthparallax.html) | ピクセル単位の視差 (Parallax Occlusion Mapping 系、1〜50 サンプル) | マウス追従。焦点・X/Y 別の強さ・効果マスク。深度は ML 生成 + 手塗り修正 |
| [DepthFlow](https://github.com/BrokenSource/DepthFlow) | GLSL の ray march (粗い前進 + 細かい後退) | **AGPL-3.0 なので組み込み不可**。パラメータ設計の参考 (`height` 既定 0.2、`steady` = 動かない深度面、`isometric`、`dolly`) |
| Immersity AI (旧 LeiaPix) | 独自深度 + 手修正 | MP4・左右並び (SBS)・深度マップを書き出し |
| depthy (MIT、2014) | WebGL の視差 + GIF 書き出し | 古いが「ビューア + GIF」の先例 |

デスクトップの画像ビューア (XnView、Honeyview、Windows フォト) に同種の機能は見つからなかった
(調べた範囲での不在)。ビューアに内蔵すれば差別化になり得る。

## 3. 深度推定モデルとライセンス

配布には「コードと重みの両方が商用利用・再配布可」であることが必要。
以下は 2026-11-06 時点で各リポジトリの LICENSE と Hugging Face のタグから調べた結果で、
**採用時に一次情報を再確認する** (法的判断ではない)。

### 使える候補

| モデル | ライセンス (重み) | 規模 | ONNX | 位置づけ |
| --- | --- | --- | --- | --- |
| Depth Anything V2 **Small** | Apache-2.0 | 25M | onnx-community / fabio-sim に実績あり。DirectML で 518px 約 7ms の報告 | 互換性が最も安全。既定候補 |
| Depth Anything 3 **Small / Base** | Apache-2.0 | 80M / 120M | onnx-community にあり | 新しく品質が上の見込み。DirectML 動作は未確認。既定候補 |
| Depth Anything 3 **Mono-Large** | Apache-2.0 | 350M | SpatialHub にあり | 高品質オプションの最有力 |
| MoGe-2 (vits / vitb / vitl) | MIT | 35M / 104M / 331M | 公式 ONNX あり (vits・vitb の ONNX はライセンス表記なし → 元の重みから自前変換が安全) | 境界が鋭いと謳う。画角も推定する |

### 使わないもの

| モデル | 理由 |
| --- | --- |
| Depth Anything V2 Base / Large、Video Depth Anything B/L | CC BY-NC (非商用) |
| Depth Anything 3 Large(-1.1) / Giant | CC BY-NC。-1.1 は GitHub と HF で表記が食い違うので使わない側に分類 |
| Apple Depth Pro / SHARP | 重みが Apple の研究用ライセンス (Depth Pro は表記が食い違い、不明確) |
| UniDepth v2 | CC BY-NC |
| Metric3D v2 | 重みのライセンス記載なし |
| Distill-Any-Depth B/L | 初期重みが DAv2 B/L (NC) 由来 |
| Marigold / Lotus | 拡散モデルで重い。Marigold は OpenRAIL の利用制限条項を利用者へ引き継ぐ必要 |

### アニメ・イラスト

- **商用で使えるアニメ専用の深度モデルは見つからなかった**。
- waifu2x 作者の [nunif/iw3](https://github.com/nagadomi/nunif/blob/master/iw3/README.md) の所感では、
  アート・アニメでは Depth Anything 系が良く、前景と背景の分離は正確だが前景がやや平らになる。
- 陰影の少ないベタ塗り、線画、吹き出し・文字、髪の境界で外れやすいと考えられるが、ベンチマークは無い。
- `docs/local-adjust-filter-candidates.md` の被写界深度フィルタは「イラスト主体なので AI 深度は不要」
  としてグラデーション深度を採った。今回は用途が違う (立体表示そのものが目的) ので、
  AI 深度を前提にする。ただしイラストで外れる前提で、**手で直す手段と弱めの既定値**を用意する。
- **判断材料は実物比較しかない**。採用前に、利用者の写真とイラストで DAv2-S / DA3-S / DA3-Mono-L /
  MoGe-2 を並べて比べるスパイクを行う (§7)。

### 隠れた背景の補完

同梱済みの `migan.onnx` (MI-GAN) は重みも MIT で、そのまま使える。小さな視差なら、
補完せず背景側の画素を引き伸ばすだけでも足りることが多い。

## 4. 描画方式

| 方式 | 長所 | 短所 |
| --- | --- | --- |
| (a) 深度で変位させた格子メッシュ | 画素あたり安い。三角形単位で段差を裂きやすい | 段差の三角形が伸びる。格子解像度で輪郭が粗くなる |
| (b) ピクセル単位の ray march (POM 系) | 全画面 1 パスで済み、既存の表示変換に載せやすい。輪郭は深度テクスチャの解像度で決まる | 画素数 × ステップ数の費用。段差で「カーテン」状の引き伸ばし |
| (c) 2 層 (前景 + 補完済み背景) | 段差の引き伸ばしを根本的に減らす | 背景層の生成 (段差マスク → MI-GAN 補完) が要る |
| (d) 3D Gaussian | 品質最高、大きく動かせる | 配布できる生成モデルが無い (SHARP は研究用途限定)。将来枠 |

**推奨: v1 は (b)**。フラグメントシェーダで、粗い前進 + 二分探索での精緻化、ステップ数は変位量に
比例 (上限 32〜64)。v2 で (c) へ拡張する。

深度の前処理 (CPU の worker で行う):

- 推論は長辺 518〜1024 px。表示解像度への拡大は joint bilateral upsampling で RGB の輪郭に合わせる。
- 1% / 99% パーセンタイルで 0〜1 に正規化し、深度ガンマを付ける (遠景がつぶれて平らに見えるのを防ぐ)。
- 段差では前景側を数 px 膨張させる (髪の周りで背景色が前景と一緒に動くハローを減らす)。軽いぼかし。
- Depth Anything 系の出力は相対的な逆深度 (視差相当)。視点移動による変位は視差に比例するので、
  `変位 = 強さ × (d − 焦点深度)` の線形でよい。メートル単位の深度は不要。

既定値の目安 (調査担当の工学的判断、要実物確認):

- 最も手前の変位は画像幅の 1.5〜3% (マウス追従)、1〜2% (自動)。5% を超えると破綻が目立つ。
- 焦点面 (動かない深度) は被写体付近 (正規化深度 0.3〜0.5)。
- 自動の動きは左右の振り子 (『ちくわ』と同じ) と円 / 楕円軌道 (周期 6〜10 秒、継ぎ目なくループ)。
  画像の外が見えないよう 3〜8% 拡大する。

## 5. mIV への組み込み (コード調査)

### 使える既存の部品

| 必要なもの | 手本 | 場所 |
| --- | --- | --- |
| 画像 1 枚につき 1 回の推論 | BiRefNet 被写体マスク (固定サイズ入力、正規化、元サイズへ戻す) | `ui_adjustment_panel.rs` の `run_local_adjust_subject_segmentation` と worker |
| モデルの配布 | 編集アドオンパック (sha256・ライセンスを manifest に記録、ダウンロード・取り消し付き) | `editing_addon.rs`、`editing_addon_download.rs`、`docs/editing-add-on-download-spec.md` |
| フルスクリーンの独自 wgpu 描画 | 360° パノラマ (`egui_wgpu::CallbackTrait`、stale guard、モード切り替え、VRAM 解放) | `panorama_wgpu.rs`、`docs/panorama-360-view-plan.md` |
| 表示中テクスチャの再利用 | `renderer.texture(&id)` で egui の既存テクスチャを読む | `gpu_lanczos.rs` |
| 表示元の画素の選択 | `resolve_pano_source` (最終合成 → 補正 → AI → 元画像) | `app.rs` |
| 隠れた背景の補完 (v2) | 消しゴムの MI-GAN | `ui_erase.rs` の `inpaint_migan` |
| GIF 書き出し | `image` crate の `GifEncoder` | `ui_dialogs/clipboard_capture.rs` |
| MP4 (H.264) 書き出し | NVENC / QSV / AMF / Media Foundation / OpenH264 の選択 (Remote 用) | `video/stream/encoder.rs`。ファイル出力の方針は `docs/music-video-export-plan.md` |

APNG は `png` crate のアニメーション書き出しで対応できる見込み (未確認)。

### 守る制約

1. **推論とモデルの読み込みを UI スレッドで行わない**。ORT のセッションは mutex で直列化されるので、
   表示中の AI アップスケールを待たせない優先度にする (`docs/async-architecture.md` §3.2.1)。
2. AI ランタイムの初期化は `AiRuntimeInitOwner` 経由で、取り消し付きで待つ (`docs/ui-responsiveness.md` §2.1.2)。
3. 新しい要求・フルスクリーン終了・フォルダ切り替えで取り消し、結果は要求のキーが一致するときだけ受け取る。
4. **パノラマのような UI スレッドでの再アップロード (40〜110 ms) を繰り返さない**。色は表示中の
   テクスチャを使い、新たに上げるのは小さな深度テクスチャだけにする。
5. 深度は「表示している画素」に対応させる。切り抜き・回転・補正後の画像を表示しているなら、
   その画素から推定する (キャッシュのキーもそれに合わせる)。
6. ZIP / PDF のページ、サムネイルとフルスクリーンの一貫性、`perf::event` の計装、文書の同時更新
   (`docs/architecture-overview.md` §7)。

### 状態の組み合わせを減らす案 (CLAUDE.md「設計の簡素化」)

- **パノラマと同じく排他的な表示モードにする**。オンの間は補正・消しゴム・比較・見開き・
  スライドショーを止め、単ページだけを扱う。補正途中の画像に深度を追従させる仕組みが要らなくなる。
- **深度はメモリ上の小さな LRU だけに持ち、v1 ではディスクに保存しない**。小型モデルなら推論は
  数十 ms 程度の見込み (要実測) なので、作り直しで足りる。新しい永続ストアと移行・掃除の対応が要らない。
  手で直した深度を保存する段階 (v1.x) で、保存先を改めて設計する。
- **書き出しはモーダルの進行ダイアログにする**。書き出し中に画像の切り替えなどを受け付けない。
- **書き出しは画面と同じシェーダでオフスクリーン描画し、フレームを読み戻す**。画面用と書き出し用で
  描き方を 2 つ持たない。動きの軌道は時刻だけで決まる関数にし、ループの継ぎ目が出ないようにする。

## 6. 段階案

| 段階 | 内容 |
| --- | --- |
| スパイク | 候補 4 モデルを ONNX + DirectML で動かし、利用者の写真・イラストで深度と所要時間を比べる。シェーダの試作で既定値の当たりを付ける |
| v1 | フルスクリーンの「3D 写真」モード (キー割り当て + メニュー)。マウス追従 + 無操作時の自動の動き。設定は強さ・焦点・動き方 (左右 / 円) の 3 つ。GIF / APNG / MP4 書き出し |
| v1.x | 段差の検出とフェード、深度の手修正ブラシ (『ちくわ』の塗りに相当)、左右並び (SBS) / アナグリフの書き出し |
| v2 | 2 層化 (段差マスク → MI-GAN で背景補完)。高品質モデル (DA3 Mono-Large) をアドオンで追加 |
| 対象外 | 360° パノラマ、動画、アニメ GIF (深度がフレームごとにちらつく)。mIV Remote (v1 では非対応) |
