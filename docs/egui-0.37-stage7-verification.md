# egui 0.37 更新 — 段7 実機確認の記録

2026-10-17 夜、利用者の承認を得て、設計担当 (ClaudeCode) が確認用ビルド (`target\dev-runtime\mimageviewer-core.exe`) を
使い捨ての data-dir で起動し、画面操作で代表操作を確かめた。普段の `%APPDATA%\mimageviewer` は使っていない。
画面は 3 台 (2560×1440 主、1440×2560 縦、1280×800)。開いたのはリポジトリ内の `testdata/` だけ。

## 見つかった不具合と修正

- **起動直後の panic (P1)**: 空の data-dir (新規インストール相当) で起動すると 1.4 秒で
  `wgpu create_texture 'egui_texid_Managed(0)' Dimension X is zero` で終了した。最初の Full より前の WindowEvent で、
  退役 delta の回収が egui の初期予約 (0×0 の font atlas) を renderer へ渡していた。`6d0d8cd5b` で修正
  (台帳 `docs/egui-0.37-stage7-startup-atlas-verification.md`、独立レビュー ACCEPT)。修正後は同じ条件で起動できた。

## 旧版との比較で、以前からの挙動と分かったもの

比較用に v4.7.1 release (egui 0.33) をコピーして別の使い捨て data-dir で起動し、同じ操作をした。

- popup / メニューを開いたまま Escape を押すと、popup だけでなくフルスクリーン (または動画ウィンドウ) ごと閉じる。旧版も同じ。
- DPI を考慮しないプロセスから `SetWindowPos` で別 DPI のモニターへ窓を移すと、`Surface::configure` の寸法超過
  (要求 1778×98246、旧版は 1778×32710) で panic する。**旧版でも同じく panic する既存の問題**で、egui 0.37 の退行ではない。
  Win+Shift+矢印での通常の移動では起きなかった。利用者の通常操作で起きるかは未確認。

## Remote (利用者が PIN を設定・入力し、設計担当が操作)

使い捨ての data-dir で、利用者が本体のリモート接続ダイアログで PIN を設定し、Chrome の PIN 画面で入力した。以降の操作は設計担当。
Tailscale serve は既に設定済みで、今回の操作で変えていない。確認後にリモート接続を無効に戻し、アプリを終了した (panic なし)。

| 項目 | 結果 |
| --- | --- |
| ログイン後のホーム・ドライブ一覧・フォルダ一覧 (試験用フォルダ) | 表示された |
| PC でローカルの閲覧窓を 1 つ開き、本体を最小化した状態で Remote から画像を開く (操作権の取得) | PC を戻さずに取得でき、ローカルの閲覧窓は閉じた。本体は最小化のまま |
| 最小化のまま Remote でページ送り・レーティング保存 (★3) | 応答した。`rating.db` に ★3 が書かれた |
| Remote の閲覧を閉じて一覧へ戻り、PC の本体を元に戻す | 閉じた閲覧窓は復元されず、一覧に ★3 が反映された |
| 本体のリモート状態表示 | 2 回目の接続は 要求 41 / 完了 41 / 失敗 0。1 回目の「失敗 6」はホームの場所一覧のサムネイル `/api/thumb` の 404 で、新旧どちらでも出るものかは未確認 |

補足: Chrome のタブが裏に回っている間は、ページの処理が止まって操作が届かなかった (Chrome 側の挙動。利用者に前面へ出してもらって再開した)。
「3」キーは Remote の閲覧画面では見開き切替 (レーティングではない) で、仕様どおり。
