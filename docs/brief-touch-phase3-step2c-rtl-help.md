## 1. 症状

利用者報告 (2026-08-08、Step 2b の実機確認):

> 静止画で、**RTL の場合にヘルプが適切ではない**ように思いました。

現在の静止画の初回ヘルプ ([ui_fullscreen.rs:6124-6134](../src/ui_fullscreen.rs)) は、
左右どちらにも外向き矢印 + **「ページ送り」という方向に中立な文字**を出している。

RTL (右→左の読み) では**左タップが「次のページ」**になるが、ヘルプはそれを言わない。
初めて触る利用者は、左の ◀ を見て「戻る」と受け取る。

---

## 2. 直し方 — いま実際に起きることを書く

**左右のラベルを、現在の読み方向で解決した「前のページ」/「次のページ」にする。**

| 読み方向 | 左のラベル | 右のラベル |
| --- | --- | --- |
| LTR | 前のページ | 次のページ |
| RTL | 次のページ | 前のページ |

外向き矢印 (◀ / ▶) は**そのまま残す**。テキストで前 / 次が確定すれば矛盾しない。
むしろ RTL では「次は左」なので、◀ + 「次のページ」で整合する。

### 2.1 ⚠ 読み方向の述語を取り違えないこと

**`self.spread_mode.is_rtl()` を使うこと。**
タップのページ送りが使っているのと**同じ述語**である
([ui_fullscreen.rs:17074-17077](../src/ui_fullscreen.rs))。

`self.settings.fullscreen_seek_direction.is_rtl(self.reading_direction)` は
**シークバー用の別の方向**なので使わない。取り違えるとヘルプだけ逆になる。

ヘルプの描画関数は現在 `full_rect` と `show_scaling_hint` しか受け取っていないので、
呼び出し元 2 か所 ([6158](../src/ui_fullscreen.rs) / [6247](../src/ui_fullscreen.rs)) から
解決済みの値を渡す。**描画関数の中で App を触らないこと** (スナップショット fixture が
呼べなくなる)。

### 2.2 「通常はこう / RTL はこう」の併記は採らない

利用者から併記案も出たが、**採らない**。理由:

- オーバーレイの役割は plan §5 のとおり「**どこを叩けば何が起きるか**」を伝えること。
  いま有効でない対応表を出すと、読み手に「自分はどっちか」を考えさせることになる
- 一度しか出ない画面で、**一目で読めること**が最優先。行数を倍にする価値がない
- mIV は読み方向を知っている。利用者に対応付けをさせる理由がない
- 後で読み方向を変えた人には `?` のコンテキストヘルプがある (§3 でそちらも方向対応にする)

## 3. コンテキストヘルプも同じにする

`FS_IMAGE_TOUCH_SHORTCUT_ROWS`
([ui_dialogs/context_shortcuts.rs:69 付近](../src/ui_dialogs/context_shortcuts.rs)) の
左右タップの行も、同じ読み方向で「前のページ」/「次のページ」に解決する。

Step 2b で動画の行を `touch_rows(video_touch_available)` の条件で切り替えたのと同じ形で、
**LTR 用 / RTL 用の 2 つの静的配列**を持たせて選べばよい (所有文字列を作らない)。

## 4. ついでに直す — 左右ラベルが半分の中心に置かれている

静止画ヘルプの左右ラベルも `side.center().x` (= 画面の 25% / 75%) に置いている。
中央矩形は 34% から始まるので、**文字が長くなると矩形に潜り込む**。
動画側は同じ問題を `5ddf1726` で直したところ (19pt の「左をタップ」が実際に重なっていた)。

静止画は現在 14pt の「ページ送り」で辛うじて収まっているだけで、
**§2 で「次のページ」に変えると文字数が増える**。同じ直し方を適用すること:

- ラベルは**自分が説明する帯の中心**に置く
  (左 = `full_rect.min.x` 〜 `center_tap_rect.min.x` の中点、右はその対称)
- 幅を変えても矩形に潜り込まないことを純関数テストで固定する
  (動画側の `native_video_touch_help_side_labels_stay_clear_of_the_centre_rectangle` と同じ形)

## 5. ⚠ 記録だけしてほしいこと — 音声モードは native overlay ではない

利用者報告 (2026-08-08):

> 10 は普通にシークできました。常に HUD が出ている画面なのでトグルも無いはずです。
> 音声モードの画面を正しく認識できてないのではないでしょうか。

**調査結果: 取り違えていない。コード変更は不要。**

- `audio_only: true` を渡しているのは
  [native_video.rs:7270](../src/app/native_video.rs) の**音楽 VST シェル 1 か所だけ**
- 通常の音声モードでは `fs_music_view_active` が true の面を **egui が描いており**、
  native presenter は隠れている。**タッチは native アダプタに一切届かない**
- 波形タップのシークは egui 音楽ビュー自身の既存動作。HUD は常時表示なのでトグルも無い

**[docs/touch-support-plan.md](touch-support-plan.md) にこれを記録すること。**
「音楽ビューは egui surface であり native touch アダプタの対象外。動画の native 挙動を
音楽ビューで検証しない」と書いておく。次に同じ確認を出さないため。
