## 2. ジェスチャの仕様

### 2.1 単発タップ = HUD トグル (現状維持)

動画には守るべきページ送り領域が無いので、**画面全体の単発タップが HUD トグル**である。
現在 `native_touch_command_toggles_chrome` が `ToggleChrome` と `PageSide` の両方を
chrome latch の toggle へ写像している。**この結果は変えない。**
左右の区別は、これから足すシークのためだけに使う。

### 2.2 ダブルタップ = 相対シーク

| 条件 | 動作 |
| --- | --- |
| 1 回目のタップ | **常に即座に HUD トグル**。ダブルタップ判定を待たない |
| 2 回目が同じ側・時間窓内・近い位置 | **シークを実行し、HUD トグルはしない** |
| 3 回目以降も同じ側・窓内 | **都度シークする** (累積) |
| 反対側にタップ | run を切って、そのタップは 1 回目として扱う |
| 中央領域 | シーク無し。単発タップが 2 回 = toggle が 2 回 |
| HUD 由来の stream | シーク無し (Step 1 で widget passthrough 固定済み) |
| 時間窓を過ぎたタップ | 1 回目として扱う |

**⚠ 1 回目を待たせないこと**は plan の明示要求である。待つと単発タップの反応が鈍く感じる。

**累積を入れる理由**: タッチには「キーを押しっぱなし」が無い。累積が無いと 30 秒進めるのに
「タップ・タップ・待つ・タップ・タップ・待つ…」になる。3 回目以降を無視する実装にしない。

### 2.3 左右の意味は読み方向に依存しない

**物理的な画面の左 = 巻き戻し、右 = 早送り**で固定する。

静止画の `PageSide` は読み方向 (RTL / LTR) で previous / next の意味が変わるが、
**時間軸は常に「左が過去」**である。`TapZone::PageSide { left }` の `left` は
物理的な画面の側なので (`touch_input.rs:98-99` の doc comment)、そのまま使えばよい。
読み方向の解決関数を経由させないこと。

### 2.4 シーク量は ±5 秒

plan §5.14-9 で確定済み (mIV のキーボードと同じ刻み。アプリ内の一貫性を優先)。

**既存の `App::native_video_seek_relative_with_hint(fs_idx, ±5.0)`
(`src/app/native_video.rs:8098`) を通すこと。** overlay 側で現在位置に足した絶対値を作って
`NativeOverlayCommand::Seek { target_secs }` に流さない。相対シークの clamp と
`RelativeSeekOutcome` に応じた hint 処理がその関数に入っており、キーボードの ← → と
挙動が分かれてしまう。必要なら相対シーク用の command variant を足す。

## 3. 初回オーバーレイヘルプ (動画)

### 3.1 学習フラグは静止画と共有する

**`Settings.touch_center_chrome_learned` を共有し、動画専用のフラグを新設しないこと。**

plan §5 の判断がそのまま効く: **「安全上必要なのは中央タップだけ」**。
「タップするとクロームが出る」を一度でも覚えた人に、面ごとに同じことを教え直さない。

- 静止画で学習済みの人には**動画のヘルプは出ない**
- そのぶんシークの発見可能性は §3.3 のコンテキストヘルプが担う

### 3.2 内容と挙動

| 項目 | 内容 |
| --- | --- |
| 図示 | **タップ = HUD 表示** / **左右ダブルタップ = 相対シーク** |
| 隅の 1 行 | 「UI が小さい場合はメニューの『スケーリング』から変更できます」(従属的に小さく) |
| 表示中のタップ | **どこを叩いても「学習 + HUD 表示」に畳む**。シークもページ送りも実行しない |
| 表示の起点 | フルスクリーン中の**最初のタッチ接点**。マウス / キーだけでは出さない |
| 閉じ方 | 閉じる操作を要求しない。モーダルにしない |

Step 3d (静止画) の規約と揃えること。ただし**描画は native overlay 側**なので、
`ui_fullscreen.rs` の egui 実装をそのまま呼べない。
**規約 (表示条件・畳み方・学習保存) を揃え、描画だけ overlay に書く。**

### 3.3 コンテキストヘルプ

`HelpShowContextShortcuts` の**動画**の表示に「タッチ操作」欄を足す
(Step 3d が画像フルスクリーンに足したのと同じ形)。載せるのは
**タップ = HUD 表示** と **左右ダブルタップ = ±5 秒シーク** の 2 行。

## 4. ⚠ 先に読むこと — plan §5.10「実機で 3 回踏んだ同型バグ」

ダブルタップは**この対応で初めて入る cross-frame state** である。着手前に §5.10 を読むこと。

native overlay は egui の multi-pass replay とは駆動が違うが、規則は同じように効く:

- **タイマーや `request_repaint` ループを新設しないこと。** 「2 回目が来なかった」は
  **次のイベントが来たときに `now_ms` を比較して判定**する。時間で消えるのであって、
  誰かが消しに行くのではない
- したがって state は**自分で無効になれる**。「未来のエッジで解除する」設計にしない
- 相互排他を bool で持たない。「どちら側で run 中か」は
  `Option<側 + 最終タップ時刻>` のような **1 つの typed 値**にする。
  `left_pending: bool` + `right_pending: bool` のような持ち方をしない

## 5. 実装の seam

**ダブルタップの判定は `src/video/native_touch.rs` (動画のアダプタ) に置き、
`src/touch_input.rs` (共有の認識器) には置かないこと。**

認識器は既に「左 / 右 / 中央のどこでタップが起きたか」を `TouchCommand::PageSide { left }` /
`ToggleChrome` として教えてくれる。**2 回目に何の意味を与えるかは動画固有の話**なので、
共有の認識器に動画専用の概念 (`accepts_double_tap_seek` のような behavior フラグや
`Seek` command) を足すと、静止画と一覧が持たない概念を背負うことになる。

この seam が合わないと分かったら、**症状パッチを当てずに報告すること**。

## 6. マウス無影響 (§5.15)

- **マウスのダブルクリックにシークを割り当てない。** presenter 上のマウス左クリック
  (再生 / 一時停止)、ダブルクリック、右クリック (リング) の現行挙動を一切変えない
- キーボードの ← → (±5 秒) も不変。**同じ helper を共有するだけ**で、経路は分ける
- ペンは `PT_TOUCH` ではないので対象外
- `MIV_DISABLE_TOUCH_GESTURES=1` で現行挙動へ戻ること

## 7. テスト

タップ列 → コマンド列を純関数で固定する。

- 1 回目のタップで **即座に** chrome toggle が出ること (2 回目を待たないこと)
- 2 回目が同じ側・窓内・近距離 → **シーク 1 回、chrome toggle は出ない**
- 3・4 回目も同じ側・窓内 → **そのつどシーク** (累積)
- 反対側 → run が切れ、そのタップは toggle として扱われる
- 時間窓超過 → toggle として扱われる
- 位置が離れすぎ → toggle として扱われる
- 中央領域の連打 → シークが 1 回も出ない
- HUD source の連打 → シークが 1 回も出ない
- **初回ヘルプ表示中はシークが出ない**こと。最初のタップは学習 + HUD 表示に畳まれる
- 学習済みフラグが立っていればヘルプが出ないこと (静止画で学習した場合を含む)
- シーク量が ±5 秒であること
- 左が負、右が正であること (読み方向を変えても不変)
