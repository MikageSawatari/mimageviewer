# 焼き込み段階の統一 — 製本 / Ctrl+E / 外部ツール

**状態**: 設計。未着手 (2026-09-02)。
**発端**: 外部ツール連携の実機確認で「カラー化が反映されていない画像が渡る」と報告され、
調べたところ製本・Ctrl+E・外部ツールで焼き込む段が食い違っていた。

## 1. なぜやるのか

### 同じ Ctrl+E が、1 枚と複数で違う出力を出す

| 機能 | 経路 | 出る段 |
| --- | --- | --- |
| 製本 | ワーカー合成 (`compose_book_page`) | 編集まで |
| **画像 Ctrl+E** | **表示画素** (`ensure_final_composite_pixels`) | **表示用補正まで** |
| **バッチ Ctrl+E** | ワーカー合成 (`write_composited_page`) | **編集まで** |
| 外部ツール | ワーカー合成 (materializer) | 編集まで |

カラー化やポストフィルタを掛けている利用者が、**1 枚書き出すと乗り、まとめて書き出すと
乗らない**。同じショートカットキーで入口も同じなのに結果が変わる。

バッチ Ctrl+E は用途が製本寄りだったため製本へ揃えたが、**同じ Ctrl+E である以上、既定は
画像 Ctrl+E へ揃えるべき** (利用者判断 2026-09-02)。表示用補正が不要な人は設定で外せる。

**バッチ Ctrl+E はまだ出荷していない** (2026-09-02 に master へ入ったばかり)。
既定を変えるコストが今なら無い。

### 「AI まで」を出す手段が無い

「AI 拡大は焼けた状態で手直ししたいが、カラー化は入れたくない」(利用者 2026-09-02) は
今どの機能でも出せない。段が 2 択 (編集まで / 表示用補正まで) しか存在しないため。

### 画像 Ctrl+E は表示用の制約を出力に持ち込んでいる

表示パイプラインはデコード直後に GPU テクスチャ上限 (`MAX_TEXTURE_DIM` = 8192) へ縮小する
([app.rs:51238](../src/app.rs:51238))。画像 Ctrl+E はその画素を書き出すので、
**8K を超える画像は縮んで保存される**。ワーカー合成経路にこの制約は無い。

## 2. 段の定義

適用順は表示パイプラインの正本 ([preset-and-adjustment.md](preset-and-adjustment.md)) に従う。
**順序は変えない。** 段はその順序上の「どこまで」を指す。

| 段 | 含むもの | 実装 |
| --- | --- | --- |
| **編集** | 消しゴム / ローカル調整 / 隠蔽 / 回転 / 注釈 / 切り取り / 色調補正 | `books::compose_book_page` (現行) |
| **AI 処理** | AI アップスケール、AI デノイズ | [`ai::upscale::upscale`](../src/ai/upscale.rs:260) / [`ai::denoise::denoise`](../src/ai/denoise.rs:16) |
| **表示用補正** | スマートシャープ → カラー化 → Creative LUT → ポストフィルタ | [`apply_final_smart_sharpen`](../src/adjustment.rs:793) / [`colorize::apply`](../src/colorize.rs:367) / [`creative_lut::apply_to_color_image`](../src/creative_lut.rs:836) / [`post_filter::apply`](../src/post_filter.rs:24) |

**すべて CPU の純粋関数**で、ワーカー上で呼べる (AI もモデルを読めば同じ)。カラー化は
AI 推論ではなく階調パレットによる着色。CPU 側でこの鎖を組む前例は
[`apply_erase_adjustments_to_source`](../src/app.rs:52533) に既にある。

### 段どうしの条件結合は 1 つだけ

`effective_smart_sharpen(output_is_ai_upscaled)` — **AI 拡大した出力にはシャープを掛けない**
([adjustment.rs:666](../src/adjustment.rs:666))。「AI 処理」を含まない段では
`output_is_ai_upscaled = false` になり、シャープが掛かる。これは定義として一貫している。

### 個別 ON/OFF にしない (2026-09-02 決定)

任意の組み合わせを許すと、上の条件結合を組み合わせの数だけ定義する必要が出る。
**3 値なら定義すべきものが 3 つ**で、テストもそこに閉じる。内部表現も 3 値にする
(「個別フラグの集合として持ち、UI だけ 3 値」も検討したが、同じ理由で取り下げた)。

## 3. 機能ごとの設定と既定

```
              編集   AI 処理   表示用補正
製本           ◯      ―        ―          ← 現状維持
画像 Ctrl+E    ◯      ◯        ◯          ← 現状維持
バッチ Ctrl+E  ◯      ◯        ◯          ← 変更 (未出荷)
外部ツール     ◯      ―        ―          ← 現状維持
```

- 設定は**機能ごとに 1 つ**。既定が機能ごとに違う以上、単一設定では表せない。
- **出荷済みの 2 機能 (製本 / 画像 Ctrl+E) の既定は変えない。** 移行で黙って見た目を変えない。
- 外部ツールは「編集まで」のまま。ここを変えると、先日マニュアルへ明記した
  「表示専用効果は含まれない」と食い違う。設定で選べるようにはする。

### UI

行 = 機能、列 = 段の表にする。**行ごとに 1 つだけ選べる** (radio)。
段は積み上げなので、**選んだ列までが塗られる**見せ方にして「どこまで」が読めるようにする。
チェックボックスの表にすると「AI だけ ◯、編集は ×」を作ろうとさせてしまう。

置き場所は環境設定。製本 / エクスポート / 外部ツールの各ページに散らすのではなく、
**1 つの表として 1 か所に置く** — 機能どうしの関係が見えることがこの設定の価値なので。

## 4. 実装

### 4.1 ワーカー合成経路に段を足す

`compose_book_page(image, edits)` の後段に、段に応じて AI と表示用補正を足す。
`BakedEditSnapshot` に段の指定と、AI / 表示用補正に必要な値 (`upscale_model`,
`denoise_model`, `smart_sharpen`, `colorize`, `creative_lut`, `post_filter`) を持たせる。
これらは既に `AdjustParams` にあるので、**運ぶだけで新しい状態は作らない**。

AI ランタイムはワーカーが自前で初期化する経路が既にある
([materializer.rs:708](../src/materializer.rs:708) — 消しゴムの MI-GAN 補完用)。
そこへアップスケール / デノイズを足す。

### 4.2 画像 Ctrl+E をワーカー経路へ移す

`prepare_single_export_dialog_target` / `prepare_spread_export_dialog_target` が
表示画素 (`ensure_final_composite_pixels`) を渡している。ここを
`CompositeSource` + `BakedEditSnapshot` へ変える。

**変わるもの (利用者に説明が要る)**:

- **8K 超の画像が縮まなくなる** (GPU 上限が外れる)。改善だが出力が変わる。
- **AI が再計算になる。** 表示側のキャッシュを使わないので書き出しに時間が乗る。
  利用者判断で許容 (2026-09-02)。
- **「画面と同一」ではなくなる。** 段を全部適用したものであって、画面のコピーではない。
  DirectML でビット単位の一致は保証されない。**マニュアルの Ctrl+E の記述を直す。**

見開きの合成 (`combine_spread_color_images`) はこの経路の外なので、そのまま使う。

### 4.3 キャッシュ鍵に段を含める

外部ツールの一時ファイルは materializer の指紋 (`CacheKey` = source + policy +
pdf_render_long_edge + edit_fingerprint) で再利用される。**段を指紋に含めないと、
「AI まで」で作った一時ファイルが「編集まで」の要求で再利用される。**

### 4.4 テスト

- 段ごとの出力が期待どおり違うこと (3 値 × 代表的な params)
- `effective_smart_sharpen` の条件結合が段によって正しく変わること
- 指紋が段で変わること
- 既定値が現状を保つこと (製本 = 編集まで / 画像 Ctrl+E = 表示用補正まで)

## 5. 段取り

1. ワーカー合成経路に AI と表示用補正の段を足す (既定は現状維持なので**まだ誰の挙動も変わらない**)
2. 設定と UI を足す
3. バッチ Ctrl+E の既定を「表示用補正まで」へ
4. 画像 Ctrl+E をワーカー経路へ移す ← **出荷済み機能の挙動が変わるのはここだけ**
5. マニュアル / 製品ページの更新 (Ctrl+E の説明、外部ツールの「含まれないもの」)

4 は独立して実機確認する。8K 超の画像、AI 拡大あり、カラー化あり、見開き、PDF ページで
出力を比べる。

## 6. 決定済み

1. **段は 3 値** (`編集 / AI 処理 / 表示用補正`)。個別 ON/OFF は作らない。
2. **名称**: 「表示どおり」は使わない。共通経路化で画面と一致しなくなるため、
   約束ではなく**段の中身**を名前にする。「画像補正」ではなく「編集」なのは、
   この段が回転・消しゴム・注釈等を含み補正だけではないため。
   「AI アップスケール」ではなく「AI 処理」なのは、デノイズも含むため。
3. **バッチ Ctrl+E の既定は画像 Ctrl+E へ揃える。** 用途は製本寄りだが、
   同じショートカットキーで入口も同じなので、既定は統一感を優先する。
4. **画像 Ctrl+E は共通経路へ移す。** 専用経路を残すより処理が 1 本になるほうがよく、
   AI 再計算の時間は許容できる。8192 クランプが外れるのは副産物。
5. **出荷済み機能の既定は変えない** (製本 / 画像 Ctrl+E)。
