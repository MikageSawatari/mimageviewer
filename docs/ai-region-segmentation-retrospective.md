# AI 領域分割 検証メモ

2026-06 に `local_adjust_lab` で、補正レイヤーの「領域分割」マスクへ AI / SAM 系モデルを使えるか検証した。
結論として、v1.1.0 では AI 領域分割を採用しない。領域分割は色差 / 境界 / 連結領域の
クラシック方式をチューニングし、AI は被写体 / 背景の 1 枚マット生成に限定して扱う。

## 目的

当初の期待は、髪、服、小物、背景などを候補領域として自動で分割し、ユーザーがクリックやドラッグで
複数領域を選んでマスク化できることだった。

この UI では、領域候補が次の性質を持つ必要がある。

- 各ピクセルが 1 つの領域だけに属する
- 領域同士が重ならない
- 未所属の隙間が実用上残らない
- AI イラストで、ユーザーが選びたい意味単位に近い
- 破片が少なく、クリック対象として理解しやすい

## 試したこと

`local_adjust_lab` に以下の試験経路を入れて評価した。

- 外部ツールで生成した白黒 / alpha 候補マスクを `<image-stem>.sam_masks` から読み込み、
  候補マスクの重なりや隙間を排他的な `RegionMask` に変換する経路
- SAM2 Hiera Tiny ONNX の encoder / decoder を直接実行し、画像上のグリッド点を
  foreground prompt として候補マスクを生成する経路
- SAM2 decoder 出力名の明示、stability score、mask IoU NMS、候補数制限、
  高スコア候補優先の greedy 割り当てなどの後処理

SAM2 ONNX については、入力正規化の二重適用も疑った。実際に確認した encoder グラフでは
先頭が Conv で、グラフ冒頭に明確な Sub / Div 正規化ノードは見えなかったため、少なくとも
今回の主因は入力正規化ではないと判断した。

## 観測された問題

最も目立った問題は過分割だった。AI イラストの実画像では、領域数が数百に膨らみ、服、背景、
髪のハイライト、線画周辺が細かい破片として分かれた。例として、503 領域程度まで細分化され、
色差ベースの分割よりもクリック対象として理解しづらい結果になった。

外部候補マスクを「どの候補に含まれるか」の署名で分割すると、重なりの交差ごとに別領域が
生まれる。SAM / SAM2 の候補マスクは重複しやすく、境界もファジーなので、この方法では
構造的に破片が増える。

greedy 割り当てや NMS に変更すると領域数は減るが、髪、服、小物といったユーザー期待の単位に
まとまるわけではなかった。SAM / SAM2 は promptable object mask generator としては有用だが、
画像全体を編集しやすい意味単位へ自動分割する用途とはズレがある。

AI イラスト特有の線画、グラデーション、ハイライト、装飾、塗りの揺れも難しさを増やした。
写真向けの物体マスクや汎用 SAM 系出力を後処理するだけでは、mIV の補正レイヤーで期待する
「選びやすい候補領域」にはなりにくい。

## 結論

v1.1.0 では、SAM / SAM2 系の AI 領域分割は採用しない。試験コードも `local_adjust_lab` から
削除し、UI には残さない。

一方、被写体 / 背景の 1 枚マット生成は用途が異なる。背景ぼかしや主役強調には引き続き有用なので、
U²-Netp などの foreground matte 型モデルによる被写体選択は別機能として残す。

領域分割は、当面は色差 / 境界 / 連結領域のクラシック方式を改善する。AI イラストでは、
フラットな塗りや線画境界を直接見るクラシック方式の方が、少なくとも現時点では予測しやすい。

## 再導入条件

将来 AI 領域分割を再検討する場合は、実装を始める前に次を満たすこと。

- AI イラストの実例で、髪、服、小物、背景などがユーザーに理解しやすい領域へ分かれることを
  UI 実装前に確認する
- 重複なし / 隙間なしの `RegionMask` へ変換しても、破片が少ないこと
- 色差ベース分割より明確に良いケースが複数あること
- モデルのライセンス、サイズ、追加ダウンロード手順が一般ユーザー向けに説明できること
- 「モデルを変えれば直る」という見込みだけで UI や保存形式へ組み込まないこと

候補としては SAM 系の単純な差し替えではなく、AI イラスト特化の semantic / part segmentation
モデル、または色差 / 境界分割を AI の粗い領域で補助する hybrid 方式が必要になる可能性が高い。
