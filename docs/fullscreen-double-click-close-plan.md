# 閲覧中の左クリック: 「単クリックで送らず、ダブルクリックで閉じる」モード (§1.471)

- 状態: **設計第 3 版 r3 ACCEPT、利用者判断済み (§10)。実装済み (f866e3cfb〜508d4f527)、独立実装レビュー ACCEPT (§11)。利用者の実機確認待ち・master 未統合**。対象 v5.7.0 (間に合わなければ次)。
- 要望: 5ch >>639・>>882。ViX のように「サムネイルをダブルクリックで開き、画像をダブルクリックで一覧へ戻る」。
- 利用者決定 (2026-11-23、統括経由): 「単クリックでページ送り (従来、既定)」と「単クリックでは送らず、ダブルクリックで閉じる」を選択式にする。後者では、先に送って巻き戻す処理や、従来モードへのクリック遅延を入れない。任意のコマンドを割り当てる汎用機能にはしない。
- 関連: [キー仕様](keymap-spec.md) の「マウス左クリック」行、[ナビゲーション仕様](fullscreen-navigation-consistency.md)、[リング / マウス操作計画](ring-shortcut-plan.md)、[detached リワーク計画](detached-rework-plan.md) (凍結の決まり)。

## 1. 現状 (コード参照)

- 閲覧中のキャンバスの左クリックは `src/ui_fullscreen.rs::plan_fs_canvas_click` が 1 つの `FsCanvasClickAction` に分類する。
  - 動かしていない通常の静止画: 単クリック → `PageSide` (左右半分でページ送り)。
  - 動かした表示 (ズーム・パン・回転、`fs_view_has_moved`): 単クリックは何もしない、ダブルクリック → `ResetTransform`。
  - 動かしていない表示のダブルクリック: 2 回の単クリックとしてページを 2 回送る (マニュアルどおり)。
  - 動画: 単クリック → `ToggleVideo` (egui 経路のときだけ。native presenter は自前で処理)。
  - その他: overflow (HUD「…」) が開いていれば `DismissOverflow`、各種 popup・連結読み・サイドパネルのクリック領域・シークパネル上は何もしない。編集モード・分析モード・360 度 (panorama) は最初に除外 (`None`)。3D (Depth) は Ctrl+クリックで `DepthFocusAt`、それ以外はページ送り。
- ダブルクリックの判定は `FsFrontPointerOwnership::backing_double_clicked`。egui のクリック回数を、**キャンバスが受け付けたクリックの数** (`FsBackingClickBoundary::current_accepted`) で頭打ちにする。これにより、一覧のダブルクリックで開いた直後の 2 回目のクリックや、HUD・メニューが持っていったクリックは、キャンバスのダブルクリックに数えない。フォーカス復帰直後のクリックは `primary_suppression` が止めるが、閉じるモードでは復帰だけを理由に止めた離しも数える (§12)。
- 閉じる経路: 右クリック短押しの「フルスクリーンを閉じる」は `FsWheelFrameResult.close` → `close_fs` → 既存の閉じる処理 (`handle_fullscreen_close_request` 系) を通る。F12 別ウィンドウ・複数窓・ブラウザから開いた窓・ZIP / PDF の一覧への戻り先は、すべてこの処理が決める。

## 2. 方針

1. 設定を 1 つ足す: `fullscreen_primary_click: FullscreenPrimaryClickMode { PageTurn (既定), DoubleClickClose }`。全体で 1 つ。本ごと・窓ごとにはしない。
2. `FsCanvasClickAction` に `CloseViewer` を 1 つ足す。`DoubleClickClose` のときだけ `plan_fs_canvas_click` が返す。
3. `CloseViewer` は右クリック短押しの閉じると同じく `close = true` に合流させる。閉じた後の行き先・別ウィンドウの畳み方は既存の閉じる処理に任せ、新しい経路を作らない。
4. `DoubleClickClose` では単クリックは何もしない (`PageSide` を作らない)。従来モードのコードは一切変えない (遅延なし)。
5. 状態を増やさない。例外は §4.3 の「直前に受け付けたクリックが閉じる候補だったか」の 1 ビットで、これは既存の `FsBackingClickBoundary` (クリック回数の頭打ち) と同じ寿命・同じ持ち主に置く。新しい App のフラグにはしない。
6. 対象はマウスの左クリックだけ。タッチのタップは専用の認識器 (`touch_input::TouchCommand`) が左右・中央のタップゾーンを処理しており、今回は変えない (§4.5)。

## 3. 設定と選ぶ場所

- 型: `FullscreenPrimaryClickMode`、保存値 `"page_turn"` / `"double_click_close"`、既定 `PageTurn`。§1.772 の `page_turn_animation_style` と同じ形で、settings_kv の 1 キー、未知の値は既存の非互換の扱い (旧版は未知のキーを読まない)。**未リリースの新規キーなので移行は不要**。設定の書き出し・取り込み (`settings_transfer`、stage1 の分類) と環境設定のスナップショットにも同じ形で登録する。
- 選ぶ場所 (推奨): 環境設定 → 操作カスタマイズ → 設定 → **「マウスボタン」タブの先頭**に「閲覧中の左クリック」の 2 択ラジオを置く。
  - 「クリックでページを送る (既定)」
  - 「クリックでは送らず、ダブルクリックで閉じる」
  - 説明 (1 行): 「画像の閲覧中のマウスの左クリックに適用します。動画・編集中・360 度表示のクリックと、タッチのタップは変わりません。」
  - 理由: >>640 で代替として案内した「マウスボタンに『画像フルスクリーンを閉じる』を割り当てる」と同じ画面で、マウスで閉じる方法がまとまる。
- 代案: 「右ドラッグ・右クリック」タブを「マウスのクリック・ドラッグ」に改め、右クリック短押しの隣に左クリックの行を足す / 表示 → 閲覧表示に置く。
- HUD・キーには出さない (常時切り替える性質の設定ではない)。`KeyAction` も足さない (固定入力の扱いを keymap-spec に書く)。

## 4. 新モードの挙動

### 4.1 単クリック

- キャンバスの単クリックは何もしない。ページ送り・巻き戻し・遅延は無い。
- ほかのクリック用途は今のまま: HUD「…」を閉じるクリック (`DismissOverflow`)、popup を閉じるクリック、サイドパネルの細いバー、シークパネル、ナビゲーター、3D の Ctrl+クリック (`DepthFocusAt`)。

### 4.2 ダブルクリックと ResetTransform の優先 (利用者判断 Q2)

- 推奨 (案 A): **動かした表示ではダブルクリックは今までどおり「表示を戻す」、動かしていない表示では「閉じる」**。判定は今の `can_reset` (通常の静止画は `fs_view_has_moved`、それ以外は変形の有無) をそのまま使い、`can_reset` が真なら `ResetTransform`、偽なら `CloseViewer`。
  - 拡大して見ていたページは、ダブルクリック 1 回目で元に戻り、もう 1 回で閉じる。今の「ダブルクリックで表示を戻す」を新モードでも失わない。
  - 帰結: 縦に長いページを幅合わせで表示してスクロールした後 (パンが自動配置と違う) も「動かした表示」なので、1 回目は表示を戻す。「読み始め」の自動配置だけのページは動かしていない扱い (今のクリック送りと同じ)。
- 案 B: ダブルクリックは常に閉じる。表示を戻すのはキー・メニューだけになり、新モードではマウスで表示を戻せなくなる。
- 連結読み: 今は単クリックで送らず、変形があればダブルクリックでリセット。新モードでは変形が無ければダブルクリックで閉じる (案 A と同じ規則)。連結のスクロール位置は変形に数えない (今のリセット判定と同じ)。
  - 構造: 今の `plan_fs_canvas_click` は popup と `continuous_active` を同じ早期 return に入れている。新モードではこれを分け、popup は今どおり除外、連結読みは「ページを送らない」だけにして、位置・サイドパネルのバー・シークパネルの除外 (後段の chrome 判定) を通してから閉じる候補を決める。従来モードの連結読みは今のまま早期 return。

### 4.3 閉じる候補の判定とクリックの数え方 (新しく足す唯一の状態)

今のダブルクリック判定には、新モードで次の 2 つの穴がある。

1. **用途のあるクリックの直後**: キャンバスが受け付けたクリックは用途を問わず数える (`accept_backing_click`)。HUD「…」が開いているときの 1 回目は `DismissOverflow` でパネルを閉じ、2 回目は overflow が閉じているのでそのままだと `CloseViewer` になる。popup・サイドパネルのバー・シークパネル・3D の Ctrl+クリック・ナビゲーターのクリックの直後も同じ。
2. **同じフレームに 2 回のクリック**: 重い読み込みなどでフレームが詰まると、押す・離す 2 組が 1 つの入力 pass に入る。`accept_backing_click` は 1 pass に 1 回しか数えないので、egui の回数 2 が 1 に頭打ちされ、ダブルクリックにならない。これは通常の使い方でも起こり得る (CLAUDE.md の「まれな失敗」ではない)。

対策 (新モードだけ):

- **閉じる候補**: 新モードで、そのクリックの位置が「何もしないキャンバスのクリック」になること。すなわち、除外モード (編集・分析・360・動画) でなく、overflow・popup・右クリックメニューが開いておらず、ドラッグでなく、サイドパネルのバー・シークパネル・Depth パネルの外で、Ctrl+クリックの 3D 焦点でもない。位置ごとに判定する純粋な関数にする (今の後段の chrome 判定と同じ材料)。
- **数え方**: 新モードでは、その pass の受け付けた左ボタンの離しを、イベント順に 1 つずつ畳み込む (既存の `accept_navigator_click` と同じ形)。
  - 入力: 離しごとに、egui のクリック認定 (位置と回数、`released_buttons_with_click_counts`) と、対応する raw の離しイベントの修飾キー (Depth の既存の Ctrl+クリック判定と同じ対応付け) と前面 UI の所有 (`FsFrontPointerEventOwnership`) を結び付けた 1 件の事実にする。pass 終端の修飾キー・所有状態で全部の離しを分類し直さない。フォーカス喪失などの初期化も元のイベント順で、その位置で適用する。
  - 回数: 離しごとの実効回数は既存と同じ `raw_count.min(受け付け数)`。時間・距離によるダブルクリック判定は egui に任せ、新しいタイマーは作らない。egui が新しい列 (raw の回数 1) を始めたとき、候補のビットも新しい列として扱う (直前のビットを引き継がない)。
  - 判定: **実効回数が 2 の離しで、その離しが閉じる候補、かつ同じ列の直前の離しも閉じる候補**のとき `CloseViewer`。
- **ResetTransform は候補のビットと無関係**: 実効回数が 2 の受け付けたダブルクリックで `can_reset` が真なら、今と同じく overflow・popup・chrome の判定より先に `ResetTransform` を返す (今の順と同じ)。候補のビットは `CloseViewer` だけに使う。拡大中に HUD「…」を開いたまま外側をダブルクリックしても、今どおり表示が戻る。
- 状態: `FsBackingClickBoundary` に「直前に受け付けた離しが閉じる候補だったか」の 1 ビットを足す。受け付け数と同じ離し単位で更新し、新しいクリック列・前面 UI が持っていったクリック・フォーカス喪失・viewport の違いで一緒に消える。ナビゲーターのクリック (`accept_navigator_click`) は候補でない離しとして数え、ビットを落とす。
- 従来モード: `accept_backing_click` と `backing_double_clicked` を今のまま使い、このビットも見ない (挙動不変)。設定を途中で切り替えた直後の 1 組は、どちらの規則で数えても閉じすぎない (候補のビットは新モードでしか立たない)。
- フォーカス復帰だけを理由に止めた離しは、閉じるモードでは普通の離しと同じに数え、候補のビットも更新する。ただし単クリックの用途は起こさない。ほかの理由の止めや前面 UI の所有は今どおり列を初期化する (§12)。
- 代案 (状態を足さない): 用途のあるクリックで `FsBackingClickBoundary` を初期化し、次のクリックを 1 回目に数え直す。同じフレームの 2 クリックは解けないうえ、従来モードと共有するなら ResetTransform の成立条件が変わるため採らない。

### 4.4 開いたダブルクリックの持ち越し

- 一覧のダブルクリックで開いたとき、その 2 回目のクリックはキャンバスが受け付けていないので、受け付け数は 1 で頭打ちになり閉じない (既存の仕組み)。テストで固定する。
- 閉じた後: 閉じた 2 回目の離しは閉じたフレームで消費される。続けて 3 回目を押した場合の一覧側の扱いは今の一覧のクリック処理のまま (今回は変えない)。「選択済み項目をもう一度クリックすると開く」(既定 OFF) を ON にしていて、3 回目のクリックがその項目の上に落ちると開き直すことはあり得る。三連打の稀な操作なので割り切る。

### 4.5 対象外 (今のまま) — 利用者判断 Q3

| 場面 | 新モードでの扱い (推奨) | 理由 |
| --- | --- | --- |
| 動画 (native presenter / egui の動画) | 変えない。単クリック = 再生・一時停止 | 要望は画像。動画のクリックはページ送りではない |
| 動画→音声モード・音楽表示 | 変えない | 同上 |
| 編集モード (補正・消しゴム等の overlay 編集)・分析モード | 変えない (クリックは編集に使う) | 既存の除外 (`None`) のまま |
| 360 度 (panorama) | 変えない (ドラッグで視点、クリックは何もしない) | 既存の除外のまま |
| 3D (Depth) | Ctrl+クリックは変換の有無によらず `DepthFocusAt`。Ctrl なしの単クリックは送らず、変換があればダブルクリックで戻し、なければ閉じる | 静止画と同じ規則。§1.874 で 2D の表示変換を共有する ([表示変換設計](depth-view-transform-plan.md) §3.3) |
| HUD・上部バー・メニュー・ナビゲーター・サイドパネル・シークパネル | 変えない。そこでのダブルクリックで閉じない | §4.3 |
| ページ一覧 (overview)・類似プレビュー | 変えない | 別の面の入力 |
| タッチのタップ | 変えない (タップゾーンの左右で送る・中央で HUD) | タップは専用の認識器 `TouchCommand::PageSide` / `ToggleChrome` が処理し、対応するポインタ入力はクリック経路から抑制される (`src/ui_fullscreen.rs` の touch 処理)。対象に入れると認識器・初回ガイド・ピンチとの関係まで設計し直しになる。要望はマウスの操作 |
| キー・ホイール・マウスの戻る/進む/ホイールクリック・ゲームパッド・右クリック | 変えない | 要望の範囲外 |
| mIV Remote (Web UI) | 変えない | 自前のタップ処理。本体の設定は渡らない |

### 4.6 F12・複数窓・戻り先 — 利用者判断 Q4

- 推奨: **右クリック短押しの「閉じる」・Esc と同じ戻り先**。既存の閉じる処理にそのまま合流させる。
  - 通常の閲覧: 一覧へ戻る (ZIP / PDF の中なら今の規則どおりページ一覧または親フォルダ)。
  - F12 の別ウィンドウ・複数窓: その窓の閲覧を閉じる (別ウィンドウは閉じる)。ほかの窓は変わらない。
  - ブラウザから開いた窓: 右クリック短押しの閉じると同じ。
- detached の述語・viewport 経路・窓ごとの描画には触れない。クリックの分類 (`plan_fs_canvas_click`) と、その結果を既存の `close` に合流させるだけなので、凍結の決まりの「detached 周りへの症状パッチ」には当たらない。変更範囲を [detached-rework-plan.md](detached-rework-plan.md) に 1 行で記録する。

### 4.7 閉じるフレームの順序

- クリックの判定位置は今のまま (キーの処理・演出の継続の確定の後、ホイールとクリックの処理の中)。閉じる結果は右クリック短押しの閉じると同じく `close = true` に合流し、同じ順序で扱う。
- 同じフレームで先に確定したキーのナビゲーション・演出の継続は、今の右クリックの閉じると同じく、そのまま閉じる処理に引き継がれる (閉じた後に残らないことはテストで確かめる)。まだ適用していないホイールのページ送りは、合成経路の `suppress_intermediate_navigation` に `CloseViewer` を入れて採用しない。
- perf: 閉じるクリックの記録は `fs_close_click` を優先する (同じフレームのホイールで `fs_wheel` が先に記録されないよう、`CloseViewer` のときは記録の順を入れ替える)。

2. `src/ui_fullscreen.rs`:

   - `plan_fs_canvas_click`: `DoubleClickClose` のとき、単クリックは `PageSide` を作らず `None`。ダブルクリックは §4.2・§4.3 の規則で `ResetTransform` / `CloseViewer` / `None`。連結読みは §4.2 の構造で popup の早期 return から分ける。動画・除外モード・popup・overflow の分岐は今のまま。
   - 閉じる候補を位置ごとに判定する純粋な関数と、受け付けた離しをイベント順に畳む処理 (新モードだけ)。`FsBackingClickBoundary` に候補の 1 ビット。従来モードの `accept_backing_click` / `backing_double_clicked` は変えない。

3. 環境設定 (`src/ui_dialogs/preferences/pages.rs` の `page_mouse_buttons`): §3 のラジオ。
4. テスト (§7)。UI スナップショット (マウスボタンのタブ) を更新・追加。

## 6. 状態の組み合わせを減らした点 (CLAUDE.md の簡素化の方針)

- 新しい状態機械・待ち時間・巻き戻しを作らない。単クリックは何もしないだけ。
- 閉じた後の行き先を作らない。既存の閉じる処理 1 つに合流させる (F12・複数窓・ZIP / PDF の分岐を新モード専用に持たない)。
- タッチは今の認識器のまま触らない (対象をマウスに絞り、タップゾーン・初回ガイド・ピンチとの組み合わせを持ち込まない)。動画・編集・360 は今の除外の分岐を使う。
- 足す状態は §4.3 の 1 ビットだけで、既存のクリック回数の持ち主に同居させる。従来モードの数え方は変えない。代案 (状態を足さない) は同じフレームの 2 クリックを解けず、従来モードの挙動も変わるので採らなかった。
- まれな失敗は割り切り (この機能に保存の失敗の特別な扱いは無い。設定の保存は既存の経路)。

## 7. テスト

- `plan_fs_canvas_click` の handler テスト (新モード):

## 12. §1.899 修正: フォーカスを戻したクリックを、閉じるダブルクリックの 1 回目に数える

- 状態: 実装済み (207f247b6、ブランチ dblclick-899)。設計第 2 版 (2026-11-25)、独立設計レビュー r1 REVISE → r2 **ACCEPT**、独立実装レビュー **ACCEPT** (§12.8)。利用者の実機確認待ち・master 未統合。
- 報告: 5ch >>906「フルスクリーンを終了できないことがある。3 回クリックだと確実に成功する」([backlog §1.899](next-release-backlog.md))。報告者の状況 (いつ起きたか) は未確認。以下はコード読みと headless の小さな試験 (`target/investigation/forum-906-click-close/`、git 管理外) による。
- 利用者の方針: `DoubleClickClose` では、キャンバスへ戻る最初のマウスクリックも閉じるダブルクリックの 1 回目として数える。単クリックだけでは閉じず、ページ送りもしない。既存の復帰保護は一律に消さない。

### 12.1 原因 (コード)

左ボタンの流れ (押してから離すまで) を止める `fs_primary_suppression = PointerStream` の作り手は 2 種類ある。

- **フォーカス復帰 (F)**
  - F1: `fs_focus_regained_at` (viewport のフォーカスが偽→真 `ui_fullscreen.rs` の `focused_now && !fs_prev_focused`、`App::restore_viewer_window`)。`viewer_chrome.rs::advance_viewer_primary_pointer_frame` が、その後 300ms 以内のフレームで左ボタンが押されたままなら流れを止める (離しまで)。押す・離すが同じフレームに入ると `primary_down` が偽なので止めない。
  - F2: クリック時の前面窓の検出 (`handle_fs_wheel_and_click_frame` の `focus_restore_click` = 前フレームの前面窓が別の窓 / VST の編集画面を表示中)。押したフレームで流れを止め、**ハンドラ全体を早期 return** する。
- **ほかの理由 (O)**: 右ドラッグ中の左押し (`cancel_mouse_right_drag_on_primary_press`)、編集プレビュー (`edit_preview_owns_canvas`)、拡大ドラッグの和音 (`retire_changed_drag_zoom` / `handle_drag_zoom` / scrub)、一覧から動画を開いた 2 回目のクリック (`ui_main.rs` / `filename_stack_ui.rs`)。フレーム限りの Suppress: タッチの置き換え・相関、前面 UI が持つ左ボタン。

修正前の閉じるモードの数え方 (`accept_close_mode_clicks`) は、どの理由でも「止められた離し」を受け付けず、候補の列を初期化していた (修正前の §4.3・§7 の扱い)。そのため:

- F1 で押す・離すが別フレーム: 物理 1 / 2 / 3 回目が 0 / 1 / 2 回目になり、3 回目で閉じる (試験で確認)。
- F2 で押す・離すが別フレーム: 同じ。
- F2 で押す・離すが同じフレーム: 早期 return のため離しを数えない。さらに、そのフレームの離しは `advance_viewer_primary_pointer_frame` で先に処理済みなので、後から張った止めが次のクリックの離しまで残り、次のクリックも止められる (従来モードでも、復帰クリックの次の 1 回はページを送らない)。

### 12.2 方針

1. **止める理由を状態に持たせる**: `FullscreenPrimarySuppression::PointerStream` に理由 `FocusRestore` / `Other` を持たせる。`Other` が優先 (止めている途中で `Other` が張られたら `Other` にする。`FocusRestore` で張っても `Other` を下げない)。F1・F2 は `FocusRestore`、ほかの `arm_pointer_stream` (右ドラッグの取り消し・編集プレビュー・scrub / 拡大ドラッグの和音・一覧から動画を開くクリック、`ui_main.rs` は復帰時刻も書くが直接張る理由は持ち越し防止なので `Other`) はすべて `Other`。`TouchStream` 由来の止めも `Other`。
   - **フレームの判定にも同じ優先を適用する**: `FullscreenPrimarySuppressionDecision::Suppress` は「このフレームで止めた理由がフォーカス復帰だけか」を運び、1 フレームの中で判定を合成するとき (`overridden_by`、フレーム限りの上書き、同じフレームで後から張る F2) は `Other` を `FocusRestore` で上書きしない。とくに `advance_viewer_primary_pointer_frame` が離しで状態を `Idle` に戻した後の終端フレームの判定は、戻す前の理由を保つ (例: 右ドラッグを取り消す左クリックの押す・離すが同じフレームで、同時に F2 が成り立つとき、そのクリックは `Other` のまま)。フレーム限りの上書き (`retire_changed_drag_zoom`、タッチの置き換え・相関、前面 UI が持つ左ボタン) は `Other`。タッチの判定が `Allow` / 解除を返す既存の規則は変えない。
2. **閉じるモードの数え方だけを変える**: `fs_double_click_close_active` のとき、`FocusRestore` だけで止められた左ボタンの離しは、ほかの条件 (前面 UI の所有・前面レイヤー・フォーカス・キャンバスの矩形・egui のクリック認定) を今と同じに確かめたうえで、**普通の受け付けた離しと同じに数える** (受け付け数・候補のビット・`double_clicked`・`close_double_clicked`)。ただし `last_click` は立てない (単クリックの用途 `DismissOverflow`・`DepthFocusAt` を復帰クリックで起こさない)。
   - 単クリック 1 回では閉じない: 閉じるには同じ egui の列の直前に受け付けた候補の離しが要る。フォーカス喪失 (`WindowFocused(false)` / pass 終端の非フォーカス) では今どおり列を初期化する。
   - 動かした表示: 復帰クリック + 次のクリックが受け付けたダブルクリックになり、今の優先順位どおり `ResetTransform` (閉じない)。
   - 止めたことによるほかの効果 (ページ送り・パン・ドラッグ開始・拡大の和音・編集の描画を始めない) は、両方の理由で今のまま。`suppresses_current_frame()` の意味は変えない。
3. **F2 の同じフレームの穴**: F2 の分岐 (早期 return) の中でも、閉じるモードのときは、このフレームの左ボタンの離しを 2 の規則で数える。**候補面の構築・離しの受け付け・`CloseViewer` / `ResetTransform` の適用は通常経路と 1 つの処理を共有し**、F2 は既存のタッチの処理を終えた後にその共有処理だけを呼んで return する (F2 専用の数え方・戻す処理の複写を作らない。戻す処理は通常経路の初期配置の解除や再描画と同じものを通す)。候補面に要る `side_panel_chrome_enabled` は純粋な計算なので F2 より前へ出してよい (hover latch の更新などの副作用は動かさない)。止めは今どおり張る (残った止めは次のクリックの離しで解け、その離しは 2 により普通に数えられる)。
   - **モーダル表示中は数えも適用もしない**: 通常経路はモーダル (`modal_input_blocked`、F2 より前に取得済み) で背面のクリックを拒否する。F2 の中の共有処理も、`modal_input_blocked` のときは離しの受け付け・作用の適用を行わない (候補を偽にするだけでは、`ResetTransform` が候補と無関係に先に判定されるので足りない)。
   - 通常経路の捕捉の順序 (閉じるモード用の判定の取得 → 前面 UI が持つ左ボタンでの上書き) は変えない。前面所有は離しごとの所有判定で除外する今の形を保つ。
4. **変えないもの**: 従来モード (`accept_backing_click` / `backing_double_clicked` に渡す値は今と同じ「止めた」)、ページ一覧 (`page_overview.rs` は `suppresses_current_frame()` だけを使う)、タッチ、動画、一覧から開いた 2 回目のクリックの頭打ち (§4.4、受け付け数による。理由 `Other` の止めは今どおり列を初期化)、F1 の 300ms・F2 の検出条件・早期 return そのもの。

### 12.3 採らなかった案

- 閉じるモードでは復帰時の止めを張らない: 単クリック送りは無いが、パン・ドラッグ開始・拡大の和音・編集の描画の保護まで消える。利用者の方針 (一律に消さない) に反する。
- F2 を F1 と同じ扱いにして早期 return をやめる (このフレームを Suppress で通常経路へ流す): 同じフレームのホイール・中ボタン・タッチの再取得の扱いが従来モードでも変わり、タッチの認識器を 2 回駆動しないための組み替えも要る。今回の範囲を超える。
- 復帰クリックを「新しい列の 1 回目」に固定する (2 回目にはさせない): F2 の同じフレームで残った止めが次のクリックを止めるので、その次のクリックが 1 回目に戻ってしまい、F2 では直らない。

### 12.4 状態の組み合わせ (CLAUDE.md の簡素化の方針)

- 新しい状態機械・タイマーは作らない。既存の止めの状態に理由を 1 つ (2 値) 足すだけで、寿命・解除は今の止めと同じ。
- 数え方の規則は 1 つ (普通の離しと同じ) で、例外は「単クリックの用途を起こさない」だけ。F2 の同じフレームも同じ関数を通す。
- まれな失敗の割り切りは関係しない (保存を伴わない)。

### 12.5 テスト (製品の入力 handler を通す。旧コードで落ちるものを必ず含める)

- F1・別フレーム: `fs_focus_regained_at = 直前` で、押す・離すを別フレームにした 1 回目では閉じず (ページも送らない)、2 回目で閉じる。**旧コードでは 2 回目で閉じず落ちる**。300ms 経過後の対照 (2 回で閉じる)。押す・離すが同じフレームの対照 (止めない・2 回で閉じる)。
- F2 (テストでは `vst3_enabled` + `vst3_gui_visible` で `focus_restore_click` を立てる、または前フレームの前面窓を外部にする試験用の入口): 別フレーム・同じフレームの両方で 2 回で閉じる。1 回では閉じない。**旧コードで落ちる**。
- 理由 `Other` の止め (既存の `arm_pointer_stream` 経路、右ドラッグ中の左押し) の離しは今どおり列を初期化し、閉じる候補にならない。`FocusRestore` で止めている途中に `Other` が張られた流れも同じ。
- 終端フレームの優先: 右ドラッグを取り消す左クリックの押す・離すが同じフレームで、同時に F2 が成り立つとき、そのクリックを数えない (状態が `Idle` に戻った後の判定でも `Other` が残る)。
- モーダル: ショートカットヘルプ等のモーダルを開いたまま、F2 が成り立つ状態でモーダルの外をダブルクリック (押す・離すが同じフレーム) → 閉じない・表示を戻さない。
- F2 の後の通常経路: 1 回目だけ F2 (同じフレーム)、2 回目は通常経路で受け付け → 閉じる。同じ pass に 2 クリック (1 回目が復帰クリック) → 閉じる。
- 復帰クリックで単クリックの用途を起こさない: HUD「…」が開いている (候補でない)、3D の Ctrl+クリック (`DepthFocusAt` にならない)。
- 動かした表示: 復帰クリック + 次のクリック → `ResetTransform`、閉じない。続くダブルクリックで閉じる。
- HUD・上部バー・メニュー・ナビゲーター上の復帰クリックは数えない (前面レイヤー / 所有)。
- 一覧から開いた 2 回目のクリックの持ち越し (§4.4 の既存テスト) に、開いた直後のフォーカス復帰を重ねても頭打ちのまま。
- 従来モード: 復帰クリックはページを送らない (今どおり)。動画・タッチのタップ・ページ一覧は今のまま。
- 窓: F12 の別ウィンドウの viewer context で、復帰クリック + 1 回で、その窓だけが既存の閉じる経路で閉じ、ほかの context を変えない。止め・候補を持ったまま A→B→A と窓を切り替えても、単クリックで閉じず、兄弟の表示状態も変わらない。
- フォーカス喪失: `WindowFocused(false)` のイベントと、イベントなしの非フォーカス終端の両方で、復帰クリックの候補が次の列へ持ち越されない。
- 表示を戻した後の閉じるダブルクリックは、§12.7 の既知の件と区別できるだけ間隔を空ける (egui の列を切る)。
- 状態の単体: 理由の優先 (`Other` が勝つ)、離しで `Idle` に戻る。

### 12.6 detached の決まり

viewer の入力ハンドラ (`handle_fs_wheel_and_click_frame`・`advance_viewer_primary_pointer_frame`) は F12 の別ウィンドウと共有している。detached の述語・viewport の経路・窓ごとの所有は変えず、既存の止めの状態に理由を足し、閉じるモードの数え方を変えるだけ。症状パッチ (guard・遅延・再試行) ではなく、「止めた理由を区別せずに数え方から外していた」という前提の誤りを直す構造的修正と考える。ClaudeCode と Codex の双方の合意を取り、[detached-rework-plan.md](detached-rework-plan.md) §11 に記録する。

## 13. §1.906 修正: 押す・離すが同じフレームのクリックで、止めが次のクリックまで残らないようにする

- 状態: 実装済み (d3c2c7bbe・be712caf9、ブランチ dblclick-906)。設計第 2 版 (2026-11-26)。独立設計レビュー r1 REVISE → r2 **ACCEPT**、独立実装レビュー r1 REVISE → r2 **ACCEPT** (§13.8)。利用者の実機確認待ち・master 未統合。

- 方針: 利用者決定 (2026-11-26)「v5.8.0 で直す」。

### 13.1 原因 (コード)

- 1 フレームの順序: 先に `viewer_chrome.rs::advance_viewer_primary_pointer_frame` が、止めの状態 (`fs_primary_suppression`) へ「このフレームで離されたか」を渡す (`PointerFrame { released }`)。`PointerStream` ならこのフレームを止め、離されていれば `Idle` に戻す。
- その後で、押したことを見て止めを立てる箇所がある (`PointerStreamStarted`)。押す・離すが同じフレームに入ったクリックでは、離しはもう渡し終えている。立てた `PointerStream` には終わりの合図が来ず、**次の流れの離しまで残る**。次のクリック (やドラッグ) は、物理的には別の流れなのに丸ごと止められる。
- 観測との対応: 上の欠陥はコードで確かめた。観測 (2 回目も送らない) はこれで説明できる。同じ結果を作れる別の経路として「VST の編集画面の表示中は毎回 F2」(§12.7) があるが、1 回目のクリックのログが `vst_gui_visible=false` なので当たらない (2 回目は F2 の条件が立たずログが出ない)。実機での再現はしていない。
- 守るべき不変条件: **持続する止め (`PointerStream`) は「左ボタンが今も押されていて、その離しをまだ渡していない流れ」だけを表す**。離し済みの流れを、次の流れまで残る止めにしない。一方で、**止めたクリックはその pass の後段 (消しゴム・隠蔽・ローカル補正のキャンバス) にも止まって見える**必要がある。これらは決定値を受け取らず、`fs_primary_suppression.is_active()` を直接見ている (`ui_erase.rs`・`ui_conceal.rs`・`ui_adjustment_panel.rs`)。今は残った `PointerStream` がこの役も果たしている。

止めを立てる箇所 (src 全体で 11 か所。レビューで漏れなしを確認):

| 箇所 | 離しを渡す前/後 | 立てる条件 | 同じフレームの離しで残るか |
| --- | --- | --- | --- |
| 右ドラッグ中の左押し (`advance_viewer_primary_pointer_frame` 内) | 前 | 押した | 残らない。ただし同じフレームの離し→押しでは、新しい流れの止めを古い離しが消す |
| F1 (同上) | 前 | 最終の `primary_down` | 同上 |
| F2 (`handle_fs_wheel_and_click_frame` の `focus_restore_click`) | 後 | 押した | **残る** (今回の報告) |
| 左ボタンのドラッグ拡大の開始 (viewer、`if used \|\| (scrub_held && can_start && pressed)`) | 後 | 押した (開始条件を満たすとき) | 同じ pass の離しで `press_origin` が消えるので開始条件が成り立たず、止めを立てない (**残らない**)。押したままなら離しまで止める |
| 同じ和音 (overlay、`if !used && primary_pressed`、既存の中ボタンドラッグが scrub の開始を拒むとき) | 後 | 押した | **残る** |

| `edit_preview_owns_canvas` | 後 | 呼び出し側で `ctx` の最終の押下と AND | 残らない |
| 一覧から動画を開く 2 回目のクリック (`ui_main.rs`) | 一覧の viewport | 無条件 (ダブルクリックは離しで判定) | 通常は直後の `open_fullscreen` の初期化で消える。初期化しない早期 return では**残る** |
| 同 (`filename_stack_ui.rs`、worker を経て後で開く) | 一覧の viewport | 同上 | 開くまでの間と、開く処理が初期化しないときに**残る** |

### 13.2 直し方

止めの状態に「離し済みの流れを、この pass の残りだけ止める」状態を足し、止めを立てる入口を 1 つにして、その時点の最終の押下を必ず読むようにする。

1. **状態**: `FullscreenPrimarySuppression` に `ReleasedThisPass(理由)` を足す。
   - 意味: この pass で止めた流れはもう離されている。この pass の残り (後段の編集キャンバス) では止まって見え (`is_active()` が真)、次の pass の `PointerFrame` で終わる。
   - `PointerFrame` (次の pass の先頭): `ReleasedThisPass` は `Idle` と同じく `Allow` を返し、`Idle` に戻す。次の pass の押す・離すは新しい流れなので止めない。
   - production では `PointerFrame` は 1 pass に 1 回 (`advance_viewer_primary_pointer_frame` の呼び出しは viewer の描画の 1 か所と、テスト用・ページ一覧の単独入口だけ)。
2. **立てる入口**: `App::arm_fs_primary_suppression(ctx, 理由) -> FullscreenPrimarySuppressionDecision` (`#[must_use]`) を 1 つ置き、全 11 か所をこれに替える。生の `arm_pointer_stream()` / `arm_focus_restore_pointer_stream()` は外から呼べなくする。
   - 中で `ctx.input(|i| i.pointer.primary_down())` (この pass のイベントを処理した後の最終状態) を読む。呼び出し側の途中の入力サンプル (overlay の `CanvasPointerInput::down()` など) は使わない。
   - 押されている: `PointerStream(理由)` (今と同じ)。
   - 押されていない: `ReleasedThisPass(理由)`。
   - 理由の合成は今と同じ (`Other` が勝つ、`TouchStream` に重ねたら `Other`)。押されていないときに今の状態が `TouchStream` なら `TouchStream` のまま (タッチの持ち主が終える) で `Suppress(Other)` を返す。`ReleasedThisPass(r)` に重ねたら理由は `r` と合成する (離し→押しが 1 フレームに入るまれな場合も、`Other` 側に倒れるだけ)。
   - 返り値: どの場合も、このフレームは `Suppress(合成した理由)`。
3. **順序 (`advance_viewer_primary_pointer_frame`)**: 先に今ある流れへ `PointerFrame` を渡し、その決定を取っておく。その後で右ドラッグ中の左押し・F1 を入口 2 で立て、決定を合わせて返す (`pointer_frame.overridden_by(arm)`、`Suppress` が勝つ)。これで 11 か所すべてが「離しを渡した後に立てる」にそろう。同じフレームの離し→押しで、新しい流れの止めを古い離しが消すこともなくなる。F1 の「止めが無ければ」の判定も、古い流れの離しを渡した後に行う。
4. 離しを渡した後に立てる箇所 (F2・ドラッグ拡大) は、返った決定をこのフレームの判定に合わせる (F2 は今も合わせている。ドラッグ拡大は早期 return するので、このフレームは今どおり止まる)。後段の編集キャンバスは `is_active()` のまま (`ReleasedThisPass` で真) なので、変えない。
5. 一覧から開く 2 か所: 最終の押下が偽なら `ReleasedThisPass` になり、閲覧側の次の pass の `PointerFrame` で消える。一覧と閲覧は別の viewport で、一覧の離しが閲覧側へ届くことはない。通常の開く処理の初期化は今のまま。開く処理が初期化しない経路で、閲覧側の最初のクリックを止めていたのが直る。`filename_stack_ui.rs` は worker を経て後で開くので、開くまでの間に別の閲覧の pass があれば、そこで消える。保護 (2 回目のクリックで再生を切り替えない) が壊れないことは、2 つの実際の開く入口でテストする。

閉じるモード (§12) への影響: 同じフレームの復帰クリックの後、次のクリックは止めずに受け付ける (今は残った `FocusRestore` の止めのまま数えていた)。止めていない離しは普通に数えるので、ダブルクリックで閉じる結果は変わらない。次の単クリックで「…」を閉じる等も、今度は起きる (正しい動き)。

### 13.3 採らなかった案

- F2 の判定を `PointerFrame` より前へ移す: F2 は前面窓の検出やタッチの相関など、`handle_fs_wheel_and_click_frame` の中の材料を使う。別ウィンドウと共有する処理の順序を大きく変えるので採らない。代わりに `advance_viewer_primary_pointer_frame` の中の 2 か所を `PointerFrame` の後へ動かし、全部を「後」にそろえる。
- 第 1 版の案 (押されていなければ持続状態を作らず、このフレームの決定だけ返す): 後段の編集キャンバスが決定値を受け取らず `is_active()` を見ているため、復帰クリックが消しゴム等へ漏れる (r1 P1)。決定値を編集キャンバスまで配る案は、配る先が多く、今後の編集ツールでも漏れやすいので採らない。
- 状態にフレーム番号を持たせる: `PointerFrame` が 1 pass に 1 回なので、`ReleasedThisPass` が次の `PointerFrame` で終わるだけで足りる。
- 残った止めを時間で切る (猶予): 症状パッチ (CLAUDE.md のバグ修正の原則)。

### 13.4 状態の組み合わせ

状態は 1 つ増える (`ReleasedThisPass`) が、「離し済みなのに次の流れまで止めている」組み合わせは無くなる。止めを立てる入口は 1 つで、押下はその入口が `ctx` から読むので、呼び出し側ごとに押下の意味が食い違う組み合わせも無くなる。

### 13.5 テスト (handler-level、旧コードで落ちるもの)

テストの道具は `double_click_close_tests.rs` の `Canvas` (`merge` / `split_click` 等) と F2 の入口 (§12.5 と同じ、`vst3_enabled` + `vst3_gui_visible` か前フレームの前面窓)。F1 の 300ms は実時間の `Instant` なので、`fs_focus_regained_at` を明示して切る (`Canvas.time` とは別)。

- 従来モード、F2: 同じフレームの復帰クリック → ページを送らない。F2 が立たない次の同じフレームのクリック → **送る** (旧コードで落ちる)。別フレームの復帰クリック → 次のクリックで送る (対照)。
- 従来モード、F2 の同じフレームの復帰クリックの後のドラッグ (拡大中の移動): 移動できる (旧コードで落ちる)。
- 編集キャンバス: 消しゴム (ブラシ) の編集中、同じフレームの復帰クリック → 塗らない・Undo を積まない (同じ pass で実際の編集ハンドラまで通す)。その次のクリックは塗る (旧コードで落ちる)。
- 離し→押しが同じフレーム (F1 の猶予中、または右ドラッグ中): 新しい流れは離しまで止まる (旧コードで落ちる)。
- ドラッグ拡大の和音 (viewer、対照): 押す・離すが同じ pass では `press_origin` が消えるため scrub は開始せず、止めも立たず `Idle` のまま。そのクリックのページ送りの結果はこのテストでは固定しない (別件、§13.9)。押したまま → 離しまで止める。両方とも、その後の普通のクリックで送る。
- overlay: 既存の中ボタンドラッグが scrub の開始を拒む状態で、左の押す・離すが同じフレーム → その後のクリックが止められない (旧コードで落ちる)。Space 移動中に Ctrl を足し、同じフレームで左を離す → 次のクリックが止められない (旧コードで落ちる)。
- 右ドラッグ中の左押し: 同じフレーム・別フレームとも、そのクリックは止め、その後は止めない (回帰の検査)。
- 閉じるモード: §12 のテストは通す。ただし `close_mode_focus_restore_899_context_focus_roundtrip_does_not_reuse_pair` の「F2 の同じフレームのクリックの後も止めが残る」という確認は、この修正で正しくなくなるので、「その pass では止まり、次の pass で消える」に改める (フォーカスの往復で候補を外す本来の確認は残す)。加えて、同じフレームの復帰クリックの後の単クリックで「…」を閉じる。
- 一覧から動画をダブルクリックで開く (`ui_main.rs` と `filename_stack_ui.rs` の 2 入口、それぞれ実際の開く処理と初期化を通す): 2 回目のクリックで再生が切り替わらない。開いた後の最初のクリックは再生を切り替える。Windows の通常の動画は native presenter 経路で egui の viewer ハンドラを通らないことがあるので、その場合はどの入力経路で確かめたかを書く。
- 状態の単体: 押されていなければ `ReleasedThisPass`・その pass は止める・次の `PointerFrame` で `Allow` と `Idle`・`TouchStream` を壊さない・理由の合成。
- 別ウィンドウ: F12 の別ウィンドウの viewer context で、同じフレームの復帰クリック → 次のクリックで送る。兄弟の context の内容・表示を変えない。止めの判定を別の viewport で使い回さない (入力の viewport を実際に替えて確かめる。今の `merge_window` は context を替えても入力の viewport が ROOT のままなので、それだけでは証拠にならない)。

### 13.6 detached の決まり

F2 と `advance_viewer_primary_pointer_frame` は F12 の別ウィンドウと共有している。`fs_primary_suppression` は context ごとの bundle ではなく前面の viewer に 1 つの App の状態で、open・close・park・新しい窓・passive の採用で初期化される ([detached-rework-plan.md](detached-rework-plan.md) の該当の記録)。今回 bundle へは移さない。detached の述語・viewport の経路・窓ごとの所有は変えない。止めの作り手の寿命と生成の境界 (「離し済みの流れから持続する止めを作らない」「止めを立てるのは離しを渡した後」) を直す構造的修正と考える (guard・遅延・再試行・時間切れを足さない)。ClaudeCode と Codex の双方の合意を取り、§11 に記録する。

### 13.7 まれな失敗

対象外 (入力の状態だけで、保存や外部の失敗は関わらない)。

## 14. §1.900 修正: 表示を戻したダブルクリックの直後のダブルクリックで閉じる

- 状態: 実装済み (2026-11-26、ブランチ small-fixes-590、6ce191c4e)。設計 r3・実装 r2 とも ACCEPT (§15.7)。本体 lib 全件は統括の
  master 取り込みの後、実機は未確認。v5.9.0 の小さな修正としてまとめて扱う。
- 報告: [backlog §1.900](next-release-backlog.md) (§12.7 で見つけた件、コード読み・headless の試験。実機での観測はない)。

### 14.1 原因 (コード)

- egui のクリック回数 (`PointerState::click_count`、`vendor/egui/src/input_state/mod.rs`) は 1・2・3 で、3 で頭打ちになる。
  前のクリックから `max_double_click_delay` 以内なら、4 回目以降も 3 のまま続く。
- 閉じるモードの数え方 (`FsFrontPointerOwnership::accept_close_mode_clicks`) は、離しごとの実効回数を
  `raw_count.min(受け付け数)` とし、受け付け数は `raw_count == 1` のときだけ 1 に戻る。
- 動かした表示でダブルクリック (1・2) → `ResetTransform`。間を置かずにもう一度ダブルクリックすると、
  egui の回数は 3・3 で、実効回数も 3・3 になり、2 にならない。表示はもう動いていないので閉じる条件
  (§4.2) を満たすのに、`CloseViewer` が出ない。間を置けば egui が 1 から数え直すので閉じる。
- 守るべき性質 (§4.2): 「拡大して見ていたページは、ダブルクリック 1 回目で元に戻り、もう 1 回で閉じる」。
  2 回のダブルクリックを素早く続けても成り立つ必要がある。

### 14.2 直し方

- 閉じるモードの数え方で、**受け付け数を 1・2 の繰り返しにする**。離しごとの受け付け数を
  `raw_count == 1` か、直前の受け付け数が 2 以上なら 1、そうでなければ直前 + 1 とする (今は直前 + 1 を 3 で頭打ち)。
  実効回数は今と同じ `raw_count.min(受け付け数)`。直前の候補のビットは、受け付け数が 2 のときだけ使う
  (今の `raw_count != 1` の条件を置き換える)。実効回数 2 の離しの次は、egui の回数によらず 1 回目に数える。
  - 直前の受け付け数は、キャンバスの離しのほか、ナビゲーターのクリック (`accept_navigator_click`、3 で頭打ち) や
    pass の初めの値 (`backing_clicks_at_start`) からも来る。区切りを「キャンバスで 2 を数えた後」だけにすると、
    ナビゲーターが 2・3 を残した後のキャンバスのクリックが 3 のまま続き、同じ頭打ちが残る (独立設計レビュー r1 P2)。
    受け付け数そのものを 1・2 の繰り返しにすれば、どこから来た値でも 2 以上なら 1 から数え直す。
- `ResetTransform` になったかどうかで分けない。閉じるモードでは 2 回目の離しが列の用途 (戻す・閉じる・
  何もしない) を決めるので、3 回目以降を同じ列の続きとして数える意味がない。条件を 1 つにして、
  動かした表示の判定 (`can_reset`) を数え方へ持ち込まない。
- 帰結: 3 回の速いクリックは 1・2・1 (今は 1・2・3)。動かした表示で 4 回なら 1・2 (戻す)・1・2 (閉じる)。
  動かしていない表示では 2 回目で閉じるので、3 回目以降は起きない。今の 3 回目は何もしないので、
  3 回の速いクリックの見える結果は変わらない。
- 同じ pass に複数の離しが入っても、離しごとにイベント順で畳むので同じ規則になる (今の畳み込みのまま)。
- 従来モード (`accept_backing_click` / `backing_double_clicked`) とナビゲーターの数え方 (`accept_navigator_click`) は
  変えない。従来モードでは、動かしていない表示のダブルクリックに用途がなく、この件は起きない。
- 変えないもの: F2 の中も同じ畳み込みの関数を通る (§12.2 の 3) ので、別の処理は足さない。フォーカス復帰の
  離しの扱い (§12)、候補の判定、`ResetTransform` の優先順位。

### 14.3 採らなかった案

- `ResetTransform` を適用したときだけ区切る: 数え方 (`accept_close_mode_clicks`) が、後で決まる作用
  (`plan_fs_canvas_click`) を知る必要があり、順序の依存が増える。帰結も 14.2 と変わらない。
- 独自のタイマーで数える: egui に時間・距離の判定を任せる今の方針 (§4.3) に反する。

### 14.4 テスト (handler-level、旧コードで落ちるもの)

- 閉じるモード、動かした表示 (拡大): ダブルクリック → 戻る・閉じない。`max_double_click_delay` 以内に続けて
  ダブルクリック → 閉じる (**旧コードで落ちる**)。
- 動かした表示で 3 回の速いクリック → 戻るだけで閉じない。
- 動かしていない表示でダブルクリック → 閉じる (回帰の確認)。
- 同じ pass に 4 回の離し (動かした表示、重いフレームで詰まったとき): 畳み込みで 2 回目と 4 回目が実効回数 2 になるが、
  作用の判定は今の優先順位 (`can_reset` なら `ResetTransform` が先) のままで、そのフレームは戻すだけ。この結果を固定する。
- 従来モード: 3 回の速いクリックの結果が今と同じ。
- ナビゲーターで 2〜3 回の速いクリックの直後、近くのキャンバスで (egui の列が続いたまま) 動かした表示をダブルクリック →
  戻る。続けてダブルクリック → 閉じる (**旧コードで落ちる**、独立設計レビュー r1 P2)。
- F12 の別ウィンドウの viewer context で、上の 1 つ目と同じ操作 → その窓だけが閉じ、兄弟の context を変えない。

## 15. §1.907 修正: ドラッグ拡大の和音での速いクリックでページを送らない (この pass の押下位置)

- 状態: 実装済み (2026-11-26、ブランチ small-fixes-590、6ce191c4e)。設計 r3・実装 r2 とも ACCEPT (§15.7)。本体 lib 全件は統括の

### 15.1 原因 (コード)

- egui の `PointerState::press_origin` は、押したときに位置を持ち、離したとき (`PointerButton { pressed: false }` と
  位置なしの `PointerButtonReleased`) に消える。押す・離すが同じ pass に入ると、pass の終わりには `None` になる。
- viewer のドラッグ拡大の和音 (`KeyAction::FsScrubZoomHold`、既定 Ctrl+Space) の開始条件 `can_start` は
  `press_origin` が全体の矩形の中にあることを求める (`ui_fullscreen.rs` の `if scrub_active || (scrub_canvas && scrub_held)`)。
  同じ pass の押す・離すでは成り立たず、拡大を始めず、止めも立てずに、後段のクリックの処理へ進んで
  ページを送る。押す・離すが別の pass なら、押した pass で拡大を始めて止めを立て、クリックにならない。
  同じ操作 (和音を押したまま、動かさずにクリック) の結果が、押す・離すの間隔で変わる。
- 同じ値の Depth パネルの除外: `press_in_depth_panel` (同じ関数、和音と中ボタンの外側の振り分けで共有) と
  `FsWheelFrameSemanticInput::primary_press_origin` (左ドラッグの開始の `can_start_drag`) も `press_origin` を読む。
  §1.906 の実装中に和音の開始位置だけを「この pass の押下イベント」に変え、Depth の除外が `press_origin` のまま
  食い違った (§13.9・§13.10 の r1 P2)。開始と除外は同じ値で決める必要がある。
- 同じ形の箇所 (押した pass の判定に `press_origin` を使う、`src` 全体を確認):
  - `src/video/native_presenter/overlay_draw.rs` の 2 か所と `render_core.rs` の 2 か所: popup の外側の押下で閉じる
    (`press_origin` + `any_pressed`)。同じ pass の押す・離すでは閉じない。
  - 編集面 (`ui_crop.rs`、`ui_sns_split.rs`): 押した pass にドラッグを始める。同じ pass の押す・離すでは何も始めない。
    別の pass でも動かさずに離せば変化なしで終わる見込みなので、今回は変えない (実装担当が見える結果の違いがないかを
    確かめ、違えば報告する)。
  - 分析面 (`ui_analysis_panel.rs` の 2 か所): 修飾キー付きの押下は、押した時点で既存のガイドを長さ 0 のものに置き換え、
    モザイクの格子の表示を外す。同じ pass の押す・離すではこれが起きず、別の pass のときと結果が違う (独立設計レビュー r1 P3)。
    分析モードの中だけの差で、ページ送り・閉じるとは関わらないので、今回は変えず別件として統括へ報告する。
  - `ui_main.rs` の 2 か所は `drag_started` の後に読むだけ (押下中) で、`unwrap_or` もあるので対象外。

### 15.2 直し方

- **押下位置はボタンごとに、この pass の順序付きの押下から取る**: egui の入力から「この pass の、指定したボタンの押下位置」を
  返す関数を 1 か所に置く (例 `button_press_origin(&egui::InputState, egui::PointerButton) -> Option<egui::Pos2>`)。
  - この pass の `pointer.button_events()` (vendor の egui の順序付きの押下・離し、位置付き) にそのボタンの押下があれば、
    **その最後の押下の位置**。その流れがこの pass で離されていても返す。
  - 無ければ、そのボタンがまだ押されているときだけ `pointer.press_origin()` (前の pass で押してまだ離していない流れ)。
    `press_origin` はボタンを問わない値なので、ほかのボタンの押下中は使わない (押されていないボタンには `None`)。
  - popup の外側の押下 (ボタンを問わない) には、同じ場所に「この pass の最後の押下 (どのボタンでも)、無ければ
    `press_origin()`」の版を置く。
- **Depth パネルの除外をボタンごとにする**: `press_in_depth_panel` を 1 つの値で和音 (左) と中ボタンの外側の振り分けに共有
  せず、左は左の押下位置、中は中の押下位置で判定する (中ボタンの開始は `handle_middle_drag_zoom` が既に「この pass の最後の
  中の押下」を使っており、外側の振り分けもそれにそろえる)。今の「Depth パネル内を左クリック → 同じ pass でパネル外で中を押す」
  で中のドラッグを始められる結果を保つ (独立設計レビュー r1 P2)。`FsWheelFrameSemanticInput::primary_press_origin`
  (左ドラッグの開始の `can_start_drag`) は左の版にする。
- **和音はこの pass の左の流れを順に処理する** (中ボタンの短押しの `update_mouse_middle_click_state` が押下ごとに
  開始の可否を付けているのと同じ考え方): この pass の左の押下・離し (`button_events()`、位置なしの離しも含む) を順に見て、
  1. 最初の押下より前の離しは、前の pass から続く流れの終わり。和音のドラッグがあれば、その離しで終える。
  2. 押下ごとに 1 つの流れとし、開始の可否 (`can_start`) はその押下の位置で決める。その後に離しがあればその流れは
     この pass で終わる。
  - この pass に左の押下・離しが無ければ、今と同じく 1 回だけ呼ぶ (押下中の流れの移動、和音のキーを離したときの終わり)。
  - それぞれの流れについて `handle_drag_zoom` を呼ぶ (押下・押下中・離しの値は、その流れのものを渡す。開始の基点は
    その押下の位置)。最後の流れだけが pass の終わりに押されたままになり得る。
  - 1 つでも和音に使った流れがあれば、今と同じくこの pass は早期 return し、止めは `arm_fs_primary_suppression`
    (§13 の単一の入口) で 1 回立てる。入口は pass の終わりの押下を読むので、最後の流れが押されたままなら
    `PointerStream(Other)`、離し済みなら `ReleasedThisPass(Other)`。
  - 開始の可否の止めの判定 (`!primary_suppression.suppresses_current_frame()`) は今のまま、この pass の決定を使う。
  - 帰結: 同じ pass の押す・離すは、始めて同じ呼び出しで終える (動かしていないので倍率は変わらない)。押す・離すが
    別の pass のときと同じ結果 (送らない・次のクリックは止めない)。pass の初めに流れが無いときに押す・離す・押すが同じ pass に
    入っても、最後の押下で始めたドラッグが残り、次の pass の移動で拡大できる (今は始めた直後に `released` で終わり、
    止めだけが残る。独立設計レビュー r1 P2)。
  - **範囲外 (今の結果のまま)**: 前の pass から続く和音のドラッグ (止めは `PointerStream(Other)`) に、同じ pass で離す・押すが
    入ったとき。advance はその流れの離しで状態を `Idle` に戻すが、この pass の決定は `Suppress(Other)` なので、新しい押下は
    開始を拒まれ、pass の終わりの押下により `PointerStream(Other)` が立ち、新しい流れは離しまで止まる (今と同じ結果)。
    これを直すには、終わった流れの止めと、新しい流れへの保護 (F1・F2・タッチ・前面 UI) を pass の中で分ける規則が要り、
    1 フレームの中で離して押し直す操作のために止めの意味を増やすことになるので、採らない (独立設計レビュー r2 P2、
    CLAUDE.md の状態の組み合わせを減らす方針)。前のドラッグは今どおり終える。
- native presenter の popup の 4 か所はボタンを問わない版へ替える。`press_origin()` を直接読む箇所は、15.1 の対象外の
  箇所だけにする。
- 位置の意味は今と同じ (押した位置)。押下中の流れでは今と同じ値を返すので、別の pass の操作の結果は変わらない。

### 15.3 採らなかった案

- vendor の egui の `press_origin` を離しで消さないようにする: egui の多くの部品が「押下中なら `Some`」の意味で使っており、
  影響が広い。mIV 側の入口 1 つで足りる。
- 和音の開始だけを直す: Depth の除外と食い違う (§13.10 r1 P2)。

### 15.4 テスト (handler-level、旧コードで落ちるもの)

- viewer、和音を押したまま、押す・離すが同じ pass のクリック → ページを送らない (**旧コードで落ちる**)。拡大の倍率は
  変わらない。入力の無い描画 pass の後の普通のクリック (和音なし) で送る (止めが残らない)。
- 同じ操作の押す・離すが別の pass → 今と同じ (送らない) (対照)。
- Depth パネルの上で、和音を押したまま押す・離すが同じ pass → 拡大を始めない (パネルの除外)。パネルの外では始める。
  開始と除外が同じ位置で決まることを、パネルの境目をまたぐ押下と離し (押下は内、離しは外、またはその逆) で確かめる。
- 左ドラッグの開始の Depth 除外 (`can_start_drag`): 押下がパネルの中、同じ pass で閾値を超えて外へ動いた → ドラッグを始めない
  (今の別 pass の結果と同じ)。
- native presenter の popup: 外側の押す・離すが同じ pass → 閉じる (**旧コードで落ちる**、関数の単位でよい)。
- 押下位置の関数の単体: この pass の押下あり (離しあり・なし)、押下なしで押下中、押下も押下中もなし、同じ pass の押す・離す・押す
  (最後の押下)、ほかのボタンの押下 (左ボタン版は無視、ボタンを問わない版は返す)、位置なしの離し。
- 押す・離す・押すが同じ pass (和音を押したまま): 最後の押下で始めたドラッグが残り、次の pass の移動で倍率が変わる。
  止めは `PointerStream(Other)` (**旧コードで落ちる**)。位置なしの離し → 押すも同じ。
- 範囲外の固定: 前の pass から続く和音のドラッグに、同じ pass で離す・押すが入った場合は、前のドラッグを終え、新しい流れは
  始めず離しまで止める (今と同じ結果、§15.2)。この結果をテストで固定する。
- 中ボタン: 同じ pass で Depth パネル内の左クリック → パネル外で中ボタンを押す → 中ボタンのドラッグが始まる (今の結果を保つ)。
  逆に、中の押下がパネル内なら左の押下がパネル外でも中は始めない。
- 既存テストの改め方: `suppression_906_tests.rs` の和音の対照 (同じ pass のクリックでは scrub が始まらず `Idle` のまま、を
  確かめている部分) は、この修正で「始めて同じ pass で終わり、`ReleasedThisPass(Other)`、ページは送らない」に改める。
  その後の普通のクリックで送ることは、今の形どおり、和音の早期 return の後に入力の無い描画 pass を挟んで egui の当たり判定を
  準備してから確かめる (その描画 pass で `Idle` に戻ること、旧の残った止めならこの pass の後も失敗することを保つ)。
- F12 の別ウィンドウの viewer context で、和音の同じ pass のクリック → 送らない。兄弟の context を変えない。

## 16. 同じ pass の通常キャンバスのクリック回数 (§1.917 の境界試験)

従来の PageTurn の `accept_backing_click` は Response ごとに一度だけ加算していたため、1 pass に2組の押下/離しが届くと2打目をダブルクリックとして受け付けなかった。通常のクリックでも所有情報・前面 layer・focus・egui の認定・canvas の位置を離しごとに照合し、従来どおり3で飽和する受け付け数へ加算する。frame の初めの境界から再演し、同じ入力を再参照しても二重に足さない。DoubleClickClose 固有の2回ごとの区切りは従来の専用処理に残す。

これは §4.3/§5 の従来経路維持のうち、同じ pass の複数の離しを取りこぼす点だけの訂正。従来の3打目のページ送り、一覧から持ち越した raw count だけではダブルクリックにしない規則、前面の所有・focus の境界を保つ。detached の述語・viewport 経路・入力配送は変更しない。魚眼の入場/終了と同一 pass のクリック/ダブルクリックと、通常キャンバスの受付の回帰を共有 runner へ引き継ぐ。実装担当による cargo の検証・製品起動・コミットは未実施。
