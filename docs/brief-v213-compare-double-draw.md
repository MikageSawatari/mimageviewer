# ブリーフ: 比較の合成と、通常ページが同じフレームに二重描画されている

対象: v2.13.0 出荷ブロッカー。実装 = Codex Sol / レビュー・検収 = ClaudeCode /
実機確認 = 利用者。

前提: master (`8b9098bd` 以降)。着手前に `git log --oneline -3` で HEAD を確認すること。

---

## 1. 直前の修正で分かったこと

`8b9098bd` で「ピンド側の余白を不透明な黒で初期化」した。**余白自体は黒になった** (利用者確認)。
しかし症状は残っており、**残っていたのは別の層**だった。

利用者の実機スクリーンショット 3 枚 (2026-08-10) で確定:

- **合成の矩形の外側に、現在ページが全画面で描かれている**。合成は中央の狭い矩形で、
  その左右に現在ページ (猫) の背景が見えている
- `PinnedNormal` でも、ピンド画像の黒帯の**さらに外側**に現在ページの一部が覗く
- 利用者の言葉:「サイズが合ってないときは黒帯で埋めている形でしょうか？ それにしても、
  **画像を変えたときは黒帯部分が描画されず裏の画像が見えます**」

つまり **1 フレームに 2 つ描かれている**:

1. 通常表示の現在ページ (フィット、画面いっぱい)
2. その上に比較の合成 (合成キャンバスの矩形、多くの場合より狭い)

## 2. やること

**合成を描くフレームでは、通常ページを描かないこと。** 逆に、準備中で合成を描かないフレームでは
通常ページだけを描く。**どちらか一方**が常に成り立つようにする。

### 2.1 まず二重描画の経路を特定すること

`draw_compare_prepared_mode` の呼び出し元は `src/ui_fullscreen.rs` に **3 か所**ある
(11691 / 11850 / 31584 付近)。少なくとも 1 か所は `if compare … { … } else if … ` の形で
排他になっているので、**排他になっていない経路か、比較とは別に通常ページを描く経路**が
あるはず。holdover、enter-holdover、背景 blit も候補に入れて洗うこと。

**どの経路が 2 つ目の描画をしていたかをソースで特定してから直す。** 前回・前々回と推測で
2 回外している (4×4 説、余白透過説はどちらも症状の一部でしかなかった) ので、
**特定できなければ計測を足して報告**すること。

### 2.2 準備中の見え方

準備中 (`Ready` でない) は**通常ページだけ**。合成の切れ端を出さない。
準備完了後は**合成だけ**。通常ページを下に敷かない。

## 3. やらないこと

- 合成キャンバスの決め方、余白の黒 (`8b9098bd`)、`ComparePreparationState` を戻すこと
- 合成の矩形の外側を毎フレーム黒で塗って隠すこと。**それは二重描画を隠すだけで、
  下に何が描かれているかの問題は残る** (症状パッチ)

- 準備中は逆に通常ページだけになること
