# §1.298 一覧の余白ダブルクリック — 決定仕様と実装記録

2026-10-07、ライン B。**Q1〜Q4は利用者決定（2026-10-08）で確定済み。2026-10-08 実装。**
要件は [next-release-backlog.md §1.298](next-release-backlog.md) の同日決定と実装依頼。
現行仕様は実機確認後の追加決定に従い、既定OFFのチェックボックスでセル内letterboxも対象にする。
親へ戻る操作は既存の `GridParentFolder` の経路を使う。2026-10-06 の見送り記述より2026-10-07/08の決定を優先する。

## コードで確認した境界（初回調査）

- `App::grid_click_pairing` / `GridClickPairingState` が同じセル・items generation・時間に
  よるクリック対を所有する。`begin_primary_click_frame` は一次クリック時に状態を取り出し、
  セルが受理しなければ対を切る。egui の double/triple click の回数を起動判定に使わない。
- `ui_main::handle_grid_background_primary_click` は一覧入力可、セル hit なし、pointer 抑止なし、
  ダイアログなし、選択情報バー外を判定する。Explorer 選択モードで余白をクリックすると
  カーソル・範囲選択 anchor・チェックを解除する。Check モードでは解除しない。
- キーの `GridParentFolder` とリングの同名操作は現在、別の入口に実装されている。
  キー側には tag view / rating view の分岐もあり、リング側の `handle_gamepad_grid_back` を
  そのまま呼べば全一覧で等価、とは断定できない。実装前に共通入口を照合し、キー側の
  親へ戻る意味を保った共有処理に接続する。単なる `Path::parent()` には置き換えない。
- `resolve_grid_parent_nav` は実パスの親がない場合に `DriveList(Some(cur))` を返す。
  ドライブルートは no-op ではなくドライブ一覧へ戻る。スマートフォルダは
  `smart_folder_parent_nav_target`、横断ブックマークは `bookmark_view_back_nav` と
  一覧ルート／読込中の履歴戻り判定を先に使い、仮想ルートを物理パスの親へ置き換えない。

## クリック対の所有案

既存の一つの pairing owner を拡張し、pending target を `Cell(index)` / `Background` の
排他的な型で持つ。新しい背景用 bool、時刻、pending を App に並べて二重管理しない。
pending には一覧 generation、表示面、入力種別、受理時刻を含める。背景pairだけで入力種別を照合し、セルpairの既存条件は変更しない。

押下から解放まで一覧の背景が所有した一次クリックだけを `Background` として登録する。
セルで押して背景で離した場合、背景で押してセルで離した場合、スクロールやドラッグへ
移行した場合は登録しない。セル→背景、背景→セルは一致しないため対にならない。
背景→背景だけが時間条件内で対になり、発火時には pending を消す。
速い3クリックも「1対＋次の1打目」とし、操作を二重実行しない。

時間は既存の `ctx.input(time)` と OS 由来の `max_double_click_delay` を使い、独自の待ち時間は
作らない。クリック自体の距離・時間・drag 判定は既存の egui／touch owner に委ねる。
背景2打は既存 `max_click_dist` の範囲内だけを対にする（決定 Q4）。セル対の既存条件は変更しない。
一覧 generation 更新、一覧表示形式変更、表示面切替、ダイアログ／popup 開始、入力取消、
タッチスクロール／pinch 開始で対を終了する。リストを閉じて開いた後へ対を持ち越さない。

## 余白の範囲と入力優先順位（最新決定を適用）

サムネイルは設定ON時、一覧clip内の描いた画像矩形・ファイル名・アイコン・バッジ以外を
背景として扱う。セル内letterbox・4ptの外周余白、セル間、最終行より下も含める。
設定OFF時は従来のセル全体の項目判定を維持する。詳細一覧は最終行より下の空白が対象で、
行内の空列は行のまま。2026-10-08実機確認後の追加決定を優先する（下記）。
詳細ヘッダ、ソート欄、縦横スクロールバー（track・thumb・周囲の操作領域）、選択情報バー、
ツリー、フォルダバー、facet、メニュー、ダイアログ、popup は対象外で、クリック対も切る。
下側に重なる情報バーは一覧 rect 内でも先に除外する。バーの drag／double click を奪わない。
セルと背景で別々に同じ解放イベントを受理しないよう、描画後の共通 hit 判定に集約する。

最初の背景クリックは既存の選択解除をそのまま実行する。割り当てなしでも同じ。
2打目で親へ戻るときは対の消費→選択解除→既存の親ナビ要求の順とし、選択を復元する状態は
追加しない。検索最上位やスマートフォルダ仮想ルートなどで親操作が no-op でも、
Explorer モードの選択解除という既存の結果は維持する。ドライブルートはドライブ一覧へ戻る。
Check モードではチェックを解除しない。設定は既定OFFのチェックボックス1つとする（最新決定）。

タッチ／ペンの余白double tapにも同じ割り当てを適用する（決定 Q2）。touch owner が scroll／pinch／cancel と
相関済みの pointer mirror を先に処理し、受理された tap を一度だけ共通 pairing owner へ渡す。
マウスとtouchを混ぜた2打を対にせず、scroll終了直後の単発tapを2打目として扱わない。
既存セルのdouble tapとスクロールを変更しない。

## 一覧の種類と親操作

| 一覧 | 接続する意味／レビュー条件 |
| --- | --- |
| 通常の実フォルダ、展開表示、ファイル名スタック | 既存 GridParentFolder。ドライブルートではドライブ一覧へ戻り、元ドライブを選択する |
| ZIP 内ディレクトリ、PDF、変換書庫・EPUBのページ一覧 | 既存の仮想階層／元コンテナへの戻り方を維持。変換cacheの物理親へ移動しない |
| ローカル検索、全体検索、コンテナ検索 | 既存の検索内戻り／根で停止を維持。検索を勝手に終了しない |
| スマートフォルダ | 仮想ルートでは既存 no-op。配下の実フォルダは scope 内の親へ戻り、entry root／本からはスマートフォルダ仮想ルートへ戻る。ZIP 内などの階層戻りは既存キーの順序を維持し、scope 外の物理親へ抜けない |
| 横断ブックマーク一覧 | 仮想一覧ルート／読込中は履歴 Back があれば戻り、なければ no-op。一覧から開いた対象の配下では、コンテナ内の階層戻りと対象一致判定を保ち、専用経路で一覧へ復帰する。対象を離れた後の通常の親操作との違いも照合 |
| タグ、★一覧、コレクション、閲覧履歴、本棚、ドライブ一覧 | キー側の既存親操作と等価な戻り／no-op。実装前に各分岐をhandlerで照合 |
| ★固定の一覧・子一覧 | snapshotの既存戻りと範囲制約を維持 |
| フルスクリーン、detached viewer、Remote Web一覧 | 本件の背景判定対象外。メインの一覧は複数窓設定中でも一覧として扱う |

一覧種類ごとに新しい親探索を作らず、サムネイル／詳細の見せ方だけで意味を変えない。

## 状態の組み合わせを減らすための検討

既存 pairing owner に target identity を統合し、別の背景ダブルクリック認識器を作らない。
親ナビゲーションは既存処理へ一度だけ渡し、完了待ち・復元・再試行の新しい状態を持たない。
既存のmodal／入力禁止中はそもそもpairを開始せず、裏側で保留して閉じた後に実行しない。
新たに一覧全体をmodal化する案は、短いクリック対のために通常閲覧を止める必要がないので不採用。

## 初回の実装記録（2026-10-08、後段の追加決定で更新）

`grid_background_double_click_action` は serde default 付きで追加し、`none` / `parent_folder`
の保存IDを使う。未知IDは無操作へ正規化する。設定移行と環境設定のクリック選択欄へ追加した。
キー側の親処理を `handle_grid_parent_folder_action` に移し、背景からも同じ入口へ渡す。
既存の detached 保存／close の順序・判定はそのまま共有し、別の親探索や完了待ち状態は作らない。

`GridClickPairingState` に `Cell` / `Background` の target と背景押下の所属を統合する。
背景の一覧世代・表示形式・viewport・入力種別を照合し、egui frame の欠落で閉じた面への
持越しを切る。raw touch owner の tap 判定を読取専用で照合し、相関した pointer mirror の
解放だけを受理する。egui の複数passでは背景入力を一度だけ消費する。
popup の入力所有はUI描画前に既存ctxの一つのframe markerへ保持し、閉じるクリックを
次の背景クリックと対にしない。情報バーの除外は同一frame内の押下位置にも適用する。

Q3 の境界は既存のセル／行矩形を使う。現行サムネイルの矩形は隙間なく並び、4ptの描画余白は
セル内部であるため対象外。セルが占有しない下部・端部や隙間は背景として扱う。
新しいレイアウト隙間やセルの hit rect 縮小は追加せず、既存の選択・open・drag を維持する。
背景用に App の別 bool／時刻／pending、親操作の復元・再試行状態は追加しない。

### 入力・描画順序の回帰修正（2026-10-08）

ホイールは `App::process_scroll` が一覧描画より先に受理・消費するため、その owner で
`grid_click_pairing.end_activation()` を呼ぶ。背景判定まで raw delta が残ることには依存しない。
Ctrl+ホイールや列数上限・スクロール端で結果が変わらない場合も、受理した操作で対を終了する。

サムネイル・詳細一覧とも、描画した旧一覧の `ScrollArea` オフセット読戻しを完了してから
背景操作を実行する。★固定の復帰など、親 handler が `None` を返しながら一覧を差し替える
経路でも、旧オフセットが戻り先の初期位置を上書きしない。generation guard や別の保留要求を
追加する案より、書込みと一覧変更の順序を揃えて状態の組合せを減らす方法を採用した。
決定 Q1〜Q4 と既存親操作の意味は変えない。

回帰テストは `process_scroll` → `render_grid` の実順序で両一覧を描画する。
背景1打→消費済みホイール（通常／Ctrl）→背景1打が起動せず、次の1打で起動すること、
スクロール済みの★固定子一覧から長い固定一覧へ戻る当該frameと後続frameの
`scroll_offset_y` が復帰先の0を保つことを検査する。

## 実機確認後の追加決定（利用者 2026-10-08、8cb4d57de）

セルは隙間なく並び、初回実装では実質的に最終行より下しか背景にならなかった。
利用者は次を決定した。上の初回Q1／Q3、初回のセル内余白除外・enum保存形式より本節を優先する。

1. ON時は描いたサムネイル画像に覆われていないセル内余白（縦長／横長画像のletterbox、外周余白）、
   セル間・最終行より下を背景とする。単クリックは既存背景と同じ選択解除、double-clickは既存親操作。
   画像・ファイル名・アイコン・各バッジは項目領域。OFF時は既存のセル全体の入力を変えない。
2. 設定を「サムネイルの余白部分のダブルクリックで親フォルダへ移動」のチェックボックス1つにする。
   既定OFF。同じ設定で詳細一覧の最終行より下とtouch／ペンのdouble tapも扱う。
   未公開機能なので旧enumは移行せず、serde default付きbool `grid_background_double_click_parent` に置換する。
3. 同じセルでも画像1打→letterbox1打は背景の対ではない。押下／解放も同じ所属でなければ受理しない。
   OS時間・既存`max_click_dist`、入力種別の照合、バー／dialog／popup除外、親操作の意味は維持する。

### 描画領域とセル種類

描画owner `grid_paint` が、実際のtextureのfit矩形と実際に配置したlabel／overlay矩形を返す。
入力側はそのframeの結果を使い、独自の寸法cacheや二つ目のfit計算を持たない。
回転90°／270°による幅高さ交換、補正textureへの置換、SearchContainerの上部62%枠、
resume帯によるcaption移動・省略と物理pixelへの丸めも、描画と同じ計算結果を使う。
矩形はegui logical point、clipはセルと一覧の交差。DPIを入力側で再換算しない。
透明画像は黒背景を含む画像矩形全体が項目。glyph／vectorアイコンは描いたboundsを項目とする。
filename、形式・評価・タグ・編集・bookmark時刻・stack数・動画時間・filter件数・check・再生／切取マーク、
描いたresume meterとbookmarkのtitle plateも保護する。選択背景・枠・見開きcursorは装飾であり余白を項目にしない。

### 入力所有と状態の簡素化

ON時はセル描画（bookmark titleを含む）→矩形による一次入力→一覧全体の背景入力の順とする。
選択／checkが変わったセルだけ再描画して同frameの表示を保つ。OFF時は従来の入力→描画の順。
右クリック／右ドラッグは従来どおりセル全体が所有する。native D&DはON時、項目で押し始めた入力だけが開始できる。
項目の同期openで一覧世代が変わった場合は旧世代のセル描画を終了する。
ホイールの受理ownerでpairを終了し、背景親操作は旧ScrollAreaの読戻し後に実行する既存順序を維持する。

既存の押下所属を `Cell(index)`／`Background` の型へ統合し、click-pairの単一ownerを保つ。
別のcell press bool、背景recognizer、永続hit cache、親操作のpending／再試行状態は追加しない。
全セルのinteraction矩形を縮める案は、filename／badgeと右ドラッグを失うため採用しない。
描画を先に済ませ、その結果だけで一次入力の所属を選ぶことでDPI・回転・媒体種類ごとの状態の組合せを減らす。
短いクリックのために一覧をmodal化する必要はない。

### 押下中の描画変更とcaption外周の回帰修正（2026-10-08）

native D&Dの開始可否は、押下時に保存した`GridPressTarget::Cell(index)`と一覧contextを照合する。
ドラッグ開始frameの画像矩形で`press_origin`を再判定しない。Pending plateで押した後に
縦長画像が届いても項目の所有を保ち、逆に背景で押した後にplateへ変わっても項目へ移さない。
世代・表示面変更や入力取消は既存ownerで終了する。読込みを止める／遅らせる案は採用せず、
既存の押下所属だけを使うことで、新しい保留状態やhit cacheを追加しない。

CollectionPlaceholderは、描いたmarker・ファイル名・理由の実際のglyph矩形も登録する。
resume帯OFF・小さいセルでは内側plateから文字がはみ出しても、セル／一覧clip内の可視部分は項目とする。
読込中・失敗文字、書庫plateのアイコン、音声アイコン、共通badgeの文字も同じ境界で確認する。
省略されたcaptionは登録せず、描画位置・clip・OFF時の操作は変えない。

回帰検証は`process_scroll`→`render_grid`で、押下→読込み完了→ドラッグ開始のnative要求を検査する
（shell実行はしない）。逆方向の描画変更と、小さいセル・resume帯OFFで実際に描いたcaption／理由／
plate文字の外周クリックも検査する。利用者決定・保存形式への変更や新しい利用者質問はない。
