## 0. 一行で

隠蔽加工モードに「自動検出」を足す。画像から領域を検出し、**隠蔽加工のマスク** (図形またはビットマップ) として
追加する。**顔検出 (YuNet、MIT) は同梱**し、それ以外の検出器 (例: 成人向けイラストの局部の検出) は
**利用者が自分で入手した ONNX を決まったフォルダに置く (BYO)**。結果は通常のマスクと同じなので、
そのあと既存のツールで直せる。

## 1. 目的と範囲

### 1.1 やること

- **写真の顔を隠す** (匿名化)。同梱の顔検出で、ダウンロードなしに使える。
- **利用者が置いた検出器で任意の分類を隠す**。Ultralytics 形式で書き出された ONNX (箱の検出・輪郭の
  セグメンテーション) を読む。成人向けイラストの修正を補助する用途を含むが、mIV はそのモデルを配布しない。
- 検出結果は **提案**。利用者が確かめ、足りない所を足し、要らない所を消してから保存する。

### 1.2 やらないこと

- **検出器を消しゴム・補正レイヤーへつなぐこと**。検出は隠蔽加工 (隠す方向) にだけ渡す。局部の検出結果を
  消しゴム (MI-GAN の補完) に渡せると、モザイク除去の下ごしらえになるため
  (モザイク除去は実装しない方針、利用者決定)。顔の消去など正当な用途もあるが、v1 では分けない。
- **自動ダウンロード**。モデルの取得は利用者が配布元から行う。mIV は取得もしないし、取得先のページも開かない (§8)。
- **「これで投稿できる」等の判定**。基準への適合は利用者が判断する ([public-wording-policies.md](public-wording-policies.md))。
- **開いたときに自動でかけること**。毎回、利用者の操作から始める。
- **領域ごとに隠し方 (モザイク / ぼかし) を変えること**。隠し方は今までどおり隠蔽加工の全体設定で 1 つ。
- **複数の画像への一括適用** は §11 の段 3 で別に設計する。

### 1.3 永続データの判断 (リリース済み / 未リリース)

- マスクは既存の `conceal.db` と `mimageviewer.dat` (リリース済み) に、**今の形式のまま**入る。
  自動で作ったマスクも手で描いたマスクと同じ表現 (ビットマップ + `Shape`) なので、**スキーマ変更・移行はない**。
- 新しい設定 (前回選んだ検出器・余白・形など) は `settings_kv` の新しいキーで、未リリース。移行は要らない。
- 検出器フォルダ (`<data_dir>\detectors\`) も新規。

## 2. 公開モデルの調査結果 (2026-11-26)

再配布できるかを決めるための記録。**HF のライセンス表記は当てにならない**ので、学習の仕組みまでたどった。

| モデル | HF の表記 | 学習の仕組み | ONNX | 種類 |
|---|---|---|---|---|
| YuNet (OpenCV の公式モデル集) | — | 独自 (libfacedetection.train) | あり | 顔の箱 + 目鼻口の 5 点 |
| 01miku/anime-nsfw-segm-yolo26 | MIT | Ultralytics YOLO26 (`.pt` 同梱。ONNX に Ultralytics の AGPL-3.0 表記があるという報告) | あり (nano 640 / medium・xl 1280) | 輪郭 |
| deepghs/anime_censor_detection | MIT | Ultralytics YOLOv8 | あり | 箱 |
| notAI-tech/NudeNet v3 | GitHub は AGPL-3.0 | Ultralytics YOLOv8 | あり (320n / 640m) | 箱 |
| deepghs/nudenet_onnx | Apache-2.0 | 上の NudeNet の変換 (上流は AGPL) | あり | 箱 |
| erax-ai/EraX-NSFW-V1.0 | Apache-2.0 | Ultralytics YOLO11 の追加学習 | なし (`.pt` のみ) | 箱 |
| NSFW-API/NSFW_Segmentation | 表記なし | Ultralytics YOLO11 | なし (`.pt` のみ) | 輪郭 |

- 局部の検出器で、Ultralytics 以外 (RT-DETR・RF-DETR・D-FINE・YOLOX など Apache 系) で学習したものは
  HF・GitHub とも見つからなかった。旧 NudeNet v2 (RetinaNet) は当時 GPL-3.0。
  → **局部の検出器は同梱しない (BYO)** という旧案の結論は変わらない。
- 顔検出は YuNet が MIT で同梱できる (opencv_zoo の `models/face_detection_yunet/LICENSE`、©2020 Shiqi Yu)。
  2026-05 版 `face_detection_yunet_2026may.onnx` は入力の縦横が可変。README によると
  **検出できる顔はおよそ 10〜300px**。InsightFace の SCRFD / RetinaFace は重みが非商用研究のみで使えない。
- ある国内の AI 画像投稿サイトが 2026-11-26 に、投稿時の自動モザイクを公開した。ソース (MIT) を読むと、
  上の 01miku の nano を ブラウザの ONNX Runtime で動かしている。後処理 (重なりの除去 → 32 係数と元マスクから
  輪郭マスク → 入力 640 で約 8px 太らせる) は §5.3 の参考になる。閾値は局部の分類で 0.15〜0.22。

## 3. 全体像

```
隠蔽加工モード (Ctrl+M)
  └ パネルの [自動検出…] → 設定ダイアログ (検出器・分類・形・余白)
        └ [検出] → モーダルの進行表示 (キャンセル可)
              │  入力: current_conceal_source_pixels(target) の Arc (隠蔽の直前の画素)
              ▼
        検出 worker (1 回ごとに 1 本)
          ├ 顔: YuNet (同梱、<data_dir>\models\ へ展開済み)
          └ BYO: <data_dir>\detectors\*.onnx
              │  AiRuntime の「外部モデル」セッション (§6.2)
              ▼
          検出結果 → 画像座標の Detection 列 (箱 / 輪郭パッチ)
              ▼
        UI スレッド: 持ち主の照合 → Undo を 1 つ積む → 図形 / ビットマップへ追加
              ▼
        既存の経路: clear_conceal_caches(idx) → conceal-materialize → 表示
```

- 検出の結果は **既存のマスク表現**に入るだけ。保存・Undo・マスクスロット・サイドカー・Ctrl+E・一括エクスポートは
  新しい処理なしで動く。
- 新しく足すのは、検出 (前処理・推論・出力の読み取り)、検出器の一覧、ダイアログ、結果の追加の 4 つ。

## 4. 操作の流れと UI

### 4.1 流れ

1. 隠蔽加工モードに入る (既存)。
2. パネルの「処理タイプ」の下に **[自動検出…]** ボタンを置く。押すと設定ダイアログを開く。
3. ダイアログで検出器と分類を選び、[検出] を押す。
4. **検出中はモーダル** (進行表示と [キャンセル] だけ)。ページ移動・ツール操作・モード終了は受け付けない (§7.1)。
5. 終わると、見つかった領域をマスクに足し、「N か所を追加しました」(0 件なら「見つかりませんでした」) を出す。
6. 足された図形は選択ツール (S) で動かす・消すことができる。輪郭のマスクは筆・消去で直す。
7. 1 回の検出は **Undo 1 回**で取り消せる。

### 4.2 設定ダイアログ

`default_pos()` の通常ダイアログ (モーダル)。1093×614 でも [検出] と [閉じる] が見えること (見出しと操作行は ScrollArea の外)。

| 項目 | 内容 | 既定 |
|---|---|---|
| 検出器 | 「顔 (内蔵)」+ フォルダにある検出器を 1 行ずつ。チェックで選ぶ (複数可) | 顔のみ |
| 分類 | 選んだ検出器の分類名をチェックで選ぶ (顔は分類 1 つなので出さない) | 検出器ごとに前回値、初回は全部 |
| 形 (箱の検出器) | 楕円 / 矩形 | 顔 = 楕円、BYO = 矩形 |
| 形 (輪郭の検出器) | 輪郭に沿う / 楕円 / 矩形 | 輪郭に沿う |
| 余白 | 箱は大きさの % で広げる。輪郭は px で太らせる | 箱 15%、輪郭 = 長辺の 0.6% (最小 2px) |
| 閾値 (詳細を開いたときだけ) | 確からしさの下限 | 検出器の既定 (§5.4) |
| 検出器フォルダ | [フォルダを開く] [一覧を読み直す] | — |

- 各検出器の行には、ファイル名・分類の数・種類 (箱 / 輪郭)・ONNX に書かれたライセンス文字列 (あれば) を出す。
- 文言は処理内容だけを書く (例:「顔を検出して楕円のマスクを追加します」)。「投稿用」などの用途判定の語は使わない。
- 読めなかったファイルは灰色の行で理由を出す (例:「出力の形式を読めません」)。黙って隠さない。

### 4.3 置き場所

- ボタンは隠蔽加工のパネルだけに置く。**消しゴム・補正レイヤーには置かない** (§1.2)。
- キー割り当ては v1 では付けない (ダイアログを開くだけの操作のため)。付けるなら `KeyAction` 経由 (keymap 規則)。

## 5. 検出

### 5.1 入力

- 入力は `current_conceal_source_pixels(target_idx)` の `Arc<ColorImage>` (隠蔽の直前、元の解像度)。
  マスクも同じ解像度 (`conceal_mask_size`) なので、座標の変換は検出の前処理の逆変換だけで済む。
- 着手時に `conceal_mask_size` とソースの大きさが一致することを確かめ、違えば検出を始めない (エラー表示)。
- 透過画像は RGB に変換して検出する (マスクは座標だけなので透過は保たれる)。

### 5.2 出力の形式 (`DetectorFormat`)

| 形式 | 出力 | 読み方 |
|---|---|---|
| `YuNet` | stride 8/16/32 ごとの cls・obj・bbox・kps | OpenCV の `FaceDetectorYN` と同じ式。5 点は v1 では使わない |
| `UltralyticsDetect` | `[1, 4+C, N]` (xywh + 分類ごとの確からしさ) | 転置 → 閾値 → 分類ごとの重なり除去 (IoU 0.5) |
| `UltralyticsSegment` | `[1, 4+C+32, N]` と元マスク `[1, 32, H/4, W/4]` | 上と同じ + 32 係数 × 元マスク → 0 以上を内側 → 箱で切り抜く |
| `UltralyticsEnd2End` | YOLO26 など重なり除去済み `[1, K, 6(+32)]` | 閾値のみ (除去は不要) |

- 形式は ONNX の入出力の形と、Ultralytics が書き出すメタデータ (`task`・`names`・`imgsz`・`stride`・`end2end` 等) から
  決める。**どれにも当てはまらなければ読めない検出器として表示する** (推測で読まない)。
- YOLO26 が `End2End` で書き出されるか、従来形式かは **段 0 で実物を確かめる** (§11)。調べた投稿サイトの実装は
  01miku の YOLO26 nano に重なり除去をかけているので、従来形式の可能性がある。

### 5.3 前処理と後処理

- **Ultralytics 系**: 長辺を `imgsz` に合わせて縮め、余りを灰色 (114) で埋める (letterbox)。RGB、0..1、NCHW。
  出力の座標から余白を引き、縮めた倍率で割って元の画像座標へ戻す。
- **輪郭**: 元マスクの解像度で 0/1 を作り、箱の外と letterbox の余白を捨て、元の画像の解像度へ拡大してから、
  §4.2 の余白 (**元の画像の px**) ぶん太らせる。結果は **検出ごとの小さなパッチ** (画像座標の矩形 + その範囲の
  ビット列) にする (§7.4 の UI スレッドの負荷のため)。
- **YuNet**: 顔の大きさが 10〜300px の範囲に入るよう、**長辺 640 と 1920 (元が小さければ元の大きさ) の 2 段**で検出し、
  合わせて重なりを除く。段の数と大きさは段 0 の測定で決める (大きな集合写真の小さな顔と、近い顔の両方を拾うため)。
  入力は OpenCV の `FaceDetectorYN` に合わせる見込み (BGR、0..255 のまま、縦横を 32 の倍数へ右下に埋める。
  出力の stride の計算は埋めた後の大きさを使う)。**段 0 で OpenCV の実装と、非正方形・端数の大きさの画像で
  同じ箱になることを確かめてから確定する** (Sol レビュー P3、2026-11-26)。

### 5.4 閾値

- 既定は検出器ごとに決める。顔 = 0.6 (段 0 で調整)。BYO = 0.25。ONNX と同じ場所に `<名前>.json` (§6.1) があれば
  その分類ごとの値を使う。deepghs 形式の `threshold.json` も読む。
- 隠す用途では **見落としより誤検出のほうが直しやすい**ので、既定は低めに置く。

## 6. 検出器の管理

### 6.1 BYO フォルダ

- 置き場は **`<data_dir>\detectors\`** に固定する (ポータブル版・`--data-dir` でも data_dir に従う)。
  フォルダを変える設定は v1 では作らない (状態を増やさない)。
- 1 つの検出器 = `<名前>.onnx` + 任意の `<名前>.json`。json は分類名・既定の閾値・既定の形を上書きするためのもの:

  ```json
  { "names": ["anus", "penis", "vagina"], "thresholds": {"anus": 0.15}, "shape": "rect" }
  ```

- 分類名は、json → ONNX のメタデータ `names` → deepghs 形式の `labels.json` (同名フォルダ内) の順で探す。
  どこにも無ければ「分類 0」「分類 1」… と出す (使えるが、利用者には分かりにくいことを表示する)。
- フォルダの読み込み (read_dir・ONNX のメタデータの読み取り) は **worker** で行う。ダイアログを開いたときと
  [一覧を読み直す] で走らせ、結果が来るまでは「読み込み中」と出す。UI スレッドで ONNX を開かない。
- ファイルを選んで取り込むボタン (コピーで登録) は v1 では作らない。[フォルダを開く] で足りるかを使ってから決める。

### 6.2 推論セッション (`AiRuntime` の外部モデル)

- 今の `AiRuntime` は `ModelKind` (固定の列挙) ごとにセッションを持ち、`load_model` は同じ種類なら読み直さない。
  BYO の検出器は数も中身も決まらないので、`ModelKind` には入れない。
- **`AiRuntime` に「外部モデル」の表を足す**: 鍵は `(パス, ファイルの大きさ, 更新時刻)`。持ち主は今と同じ `AiRuntime`
  1 つで、別のキャッシュを作らない。TensorRT には回さない (DirectML か CPU)。同時に保持するのは 2 つまで
  (古いものから閉じる)。
- **同梱の YuNet も同じ外部モデルの経路で読む** (展開先のパスを渡す)。`ModelKind` を足さず、TensorRT の経路・
  前回実行の診断・`as_str` の表に触れない。経路を 1 つにするため。
- 既存の `with_session` は全推論を 1 つのロックで直列にしている。外部モデルの表は **別のロック**にして、
  先読みのアップスケールが走っていても検出 (利用者が待っている操作) がその後ろに並ばないようにする。
  GPU 自体は共有するので、遅くなることはある。
- DirectML で読めないモデルがあった場合の扱いは、段 0 で実物を試してから決める。決めるまでは
  **黙って CPU に切り替えない** (読めなければエラーとして表示する)。

### 6.3 同梱する YuNet

- `face_detection_yunet_2026may.onnx` (約 0.23MB、入力が可変) を `vendor/models/` に置く。取得は
  `scripts/bootstrap-vendor.sh` に足す (`raw.githubusercontent.com` は LFS のポインタを返すので
  `media.githubusercontent.com/media/...` から取る)。`vendor/models/` は再取得できない扱いの場所なので、
  置いたらバックアップへも実ファイルでコピーする。
- 今の `EmbeddedModel` は `kind: ModelKind` が必須で、パスの取得も `ModelKind` の表に依存している
  (`src/ai/model_manager.rs`)。**同梱物の識別と推論用の `ModelKind` を分ける小さな変更を範囲に入れる**:
  同梱物を `ModelKind` ではなく同梱物の識別子 (例: 既存モデル = `ModelKind` を包む、YuNet = 専用の値) で
  持ち、通常版 (`<data_dir>\models\` へ展開) とポータブル版 (exe 隣の `models\` から直接読む) の両方で
  パスを返す。あわせて `scripts/build-portable.ps1` の同梱一覧と `build.rs` の依存物の検査に YuNet を足す
  (Sol レビュー P2、2026-11-26)。推論は §6.2 の外部モデルの経路で、このパスを渡して読む。
- ライセンス表記: 環境設定のソフトウェア情報・`installer/readme.txt`・同梱の第三者ライセンス一覧に
  「YuNet face detector — MIT License, Copyright (c) 2020 Shiqi Yu」を足す。

## 7. 非同期と状態

### 7.1 検出中はモーダル (状態の組み合わせを減らす)

検出の途中にページ移動・ツール操作・Undo・モード終了・別の検出が入ると、結果を足す先が変わる。これを全部
扱う仕組みは作らず、**検出中はモーダル**にする (CLAUDE.md「設計の簡素化」)。

- 設定ダイアログと進行表示は `common_modal_dialog_open` に「今表示されているか」を返す helper で登録する。
  これで止まるのは**キー入力と、共通のモーダル判定を見ている画面だけ**。隠蔽加工のキャンバス
  (`handle_conceal_paint` は `canvas_pointer_inputs` に常に有効を渡している) とパネル (無効化は
  `book_structural_op` のときだけ) は止まらない (Sol レビュー P1、2026-11-26)。
- そこで **隠蔽加工の入力を止める述語を 1 つ作る**: `conceal_input_blocked()` =
  本の構造操作中 || 自動検出のダイアログが開いている || 検出の待ちがある。パネルの `ui.disable()`、
  キャンバスの `canvas_pointer_inputs` の有効フラグ、隠蔽加工のキー処理 (ツール切替・Undo・スロット・
  プリセット・モード終了) の 3 か所が、この述語だけを見る。今の `book_structural_op` の個別判定もこの述語へ
  寄せる。止まっている間も描画は続ける (進行表示とプレビューは出す)。[自動検出…] ボタン自体もこの述語で無効になり、
  検出の二重受付はここで起きない。
- **目のプレビューの先読みも同じ述語で止める** (Sol レビュー R2 P2)。`sync_conceal_preview_before_pipeline` は
  パネルを描く前に、目のボタンの矩形と生の `primary_down` から `conceal_preview_active` を更新するので、
  パネルの `ui.disable()` では止まらない (ダイアログのドラッグが背面の目の矩形を通っても反応し得る)。
  述語が真の間は **新しく押したことによるプレビューの開始を受け付けない**。表示の継続と、離したときの
  保持状態の後始末はそのまま残す。Tab での保持は既に `KeyboardOwner::Modal` を除いている。
- ホイール (筆の半径・拡大)、右クリック・ジェスチャー、全画面のキー・閲覧用スロットは、既存の共通モーダル判定で
  止まることを R2 で確認済み。止まらないのは、別の viewer の操作・閉じる・非同期の対象切替の完了などの
  lifecycle で、これは止めずに §7.2 の破棄と照合で扱う (`reset_conceal_mode` と対象切替の完了でも待ちを捨てる)。
- 検出は短い (顔は数十 ms、Ultralytics の nano は数百 ms の見込み。xl の 1280 や初回のセッション作成は数秒)。
  待つ時間がモーダルで困るほど長くならない見込みだが、段 0 で測る。
- それでも外から来る変化 (フォルダの監視による一覧の読み直し、裏で終わった消しゴムの補完や補正レイヤーの
  再計算、別ウィンドウ、リモート操作) は止まらないので、結果を足す前に **開始時の条件と照合する** (§7.2)。
  合わなければ捨てて「画像が変わったため中止しました」と出す。

### 7.2 待ちの状態

```rust
/// 開始時に確定し、あとから書き換えない (表示位置の付け直しの対象にしない)。
pub(crate) struct ConcealDetectRequest {
    context: ViewerContextId,
    page_key: String,
    items_generation: u64,
    conceal_session: u64,              // 隠蔽加工モードに入るたびに進める番号 (新規)
    source: Arc<egui::ColorImage>,     // 検出に渡した画素 (current_conceal_source_pixels の結果)
    source_kind: &'static str,         // "fs" / "erase_result" / "local_adjust"
    mask_size: [usize; 2],
}
pub(crate) struct ConcealDetectPending {
    request: ConcealDetectRequest,
    cancel: Arc<AtomicBool>,
    rx: mpsc::Receiver<Result<ConcealDetectOutput, String>>,
}
impl Drop for ConcealDetectPending { fn drop(&mut self) { self.cancel.store(true, Release); } }
```

- 置き場は **viewer context の bundle** (既存の `local_adjust_segmentation_pending` と同じ扱い)。
  複数ウィンドウでは各 context が自分の 1 つだけを持つ。
- 先例 `local_adjust_segmentation_pending` の出現箇所を全部たどり、同じ箇所に入れる: bundle の保存・復元、
  各 lifecycle での破棄 (フォルダ切替・context を閉じる・モード終了)、`book_append_undo` の待ち判定、
  `prepared_edit`、全 context の poll、`update_phases` の再描画要求、idle・停止の判定 (一部だけ入れると、
  閉じた context の結果が別の context に入る)。
- **ただし `page_edit_owner.rs` の付け直し (`reproject_page_edit_owners`) には入れない**。先例の付け直しは
  `owner.items_generation` を今の値へ書き換えるので、入れると開始時の条件が失われる (Sol レビュー P1)。
  一覧が読み直されたら (`items_generation` が変わったら) 結果は捨てる。待つのは短いので、追いかける価値が無い。
- 受け取り (`poll_conceal_detect`、毎フレーム `try_recv`) では、次が**全部**今と一致するときだけ結果を足す:
  context、隠蔽加工モード中で `conceal_session` が同じ、`items_generation` が同じ、編集対象の page_key が同じ、
  `conceal_mask_size` が `mask_size` と同じ、**今の `current_conceal_source_pixels` が開始時と同じ `Arc`
  (`Arc::ptr_eq`) で `source_kind` も同じ**。一致しなければ捨てる。
- 画素の照合を `input_generation` にしないのは、**`input_generation` だけでは消しゴムの補完や補正レイヤーの
  結果の更新を網羅できない**ため。本番で進むのは元画像の読み直し (`bump_input_generation_for_fs_cache_reload`) と
  全ページ一括の `bump_all_input_generations()` (全画面の終了・補完の設定変更) で、ページ単位の
  `bump_input_generation` は本番から呼ばれていない (2026-11-26 のコード)。`Arc` の同一性なら
  raw / erase / local-adjust のどれが差し替わっても捨てられる。中身が同じで `Arc` だけ替わった場合も捨てるが、
  利用者がもう一度押せば済むので、それで良い。**変化が無ければ `Arc` が保たれる** (毎フレーム作り直されない)
  ことは R2 でコードを確認済み (fs は `fs_cache` の画素、erase_result と local_adjust は今の鍵の cache の画素を
  `Arc::clone` で返す)。実装時にもテストで確かめる。動く画像の fs は現在のフレームの `Arc` を返すが、隠蔽加工モードの
  入口が動く画像を除いているので対象外。
- マスクの版の照合は持たない。検出中は `conceal_input_blocked()` で同じ context のマスクを変える入力が全部
  止まるため (§7.1)。

### 7.3 worker

- `std::thread::Builder` で 1 回ごとに 1 本 (先例と同じ)。`ai_runtime_init.wait_terminal_while(!cancel)` で
  ランタイムの準備を待つ。キャンセルは検出器ごと・YuNet の段ごとの区切りで見る。
- **worker は `local_ai_activity_lease()` を取り、ランタイム待ちから終わるまで持つ** (先例と同じ。Sol レビュー P2)。
  推論の途中ではキャンセルが効かないので、待ちの状態を捨てた後も worker は少し残る。リモートへの引き渡しは
  この活動数を見て停止の完了を判断しているので、lease が無いと引き渡しが推論中に進む。新しい待ち合わせの
  仕組みは作らず、既存の lease を使う。
- worker の中で完結させるもの: セッションの用意、前処理、推論、出力の読み取り、座標の変換、輪郭パッチの作成。
- 結果: `ConcealDetectOutput { shapes: Vec<Shape>, patches: Vec<MaskPatch>, counts: Vec<(String, usize)> }`。

### 7.4 結果を足す (UI スレッド)

1. `admit_book_append_followup_mutation()` と `remote_session_blocks_local_control()` を通す (先例と同じ)。
2. `push_conceal_undo()` で今のマスクと図形を 1 つ積む (既存の Undo はマスク全体のスナップショットなので、
   何個足しても 1 回で戻る)。
3. 箱 → `Shape::Rect` / `Shape::Ellipse` (`ShapeOp::Add`) を `conceal_shapes` の**末尾**に足す。
4. 輪郭 → 各パッチの範囲だけ `conceal_mask` に OR する (全体を舐めない)。
5. マスクの表示用テクスチャを更新し、`clear_conceal_caches(idx)` で再合成させる。図形を足したときは、既存の
   図形の確定 (`commit_conceal_shape`) と同じく `conceal_mask_texture = None` にする。輪郭だけのときは
   パッチごとの範囲で部分更新する (離れたパッチを 1 つの大きな範囲にまとめない)。
6. 選択中の図形は外す (`conceal_selected_shape = None`)。

- 合成の順序 (ビットマップを下地に図形を作成順に適用) は変えない。そのため **輪郭で足した部分に、前からある
  消去 (`Subtract`) の図形が重なると、そこは抜けたまま**になる。バケツと同じ既存の規則なので、変えずに
  マニュアルに書く。箱から作る図形は末尾に足すので、前の消去の図形より後で効く。
- **UI スレッドの費用 (Sol レビュー P2 で見積もりを直した)**: 結果の追加そのものは図形の push とパッチの範囲の
  OR だけだが、手順 2 の Undo はマスク全体を複製し、図形を足したときの表示用テクスチャは全体を作り直す。
  どちらも **既存の 1 回の筆・図形の確定と同じ費用で、1 回の検出につき 1 回**。手描きの操作で既に払っている
  費用なので、検出のために worker 側で状態を準備する仕組みは作らない。大きな画像 (例 8000×6000) で
  この 1 回が目立つかは段 0 と実装時の perf ログで測り、目立つなら既存の手描きの操作と一緒に直す
  (検出だけの別経路は作らない)。

### 7.5 まれな失敗

モデルが壊れている・読めない・推論に失敗した・GPU のメモリが足りない、はログとエラー表示で終わる
(既定の割り切り)。再試行・自動で別の検出器に切り替える・途中の結果を残すことはしない。

## 8. 配布・ライセンス・公開文書

- **mIV が配布するのは YuNet だけ**。BYO の検出器は利用者が配布元から取得する。mIV は検出器のダウンロードも、
  配布元のページを開くこともしない (配布元のページに成人向けの見本画像が載っていることがあり、
  アプリから直接開かせない)。
- ダイアログとマニュアルに書くこと:「mIV は追加の検出器を配布していません。入手した検出器は配布元の
  ライセンスに従って使ってください」。ONNX にライセンス文字列があれば、そのまま表示する (Ultralytics 製なら
  AGPL-3.0 と出る)。HF の表記を mIV が言い換えない。
- **製品ページ・Store の説明・スクリーンショット**では、顔を隠す機能として紹介する。局部の検出は書かない
  (Store Policies 11.1 の説明文の年齢基準と、11.7 を避けるため。v7.20、2026-09-15 公開)。
  Store の年齢区分 (IARC) の回答に影響しないかを、公開時に確かめる。
- マニュアルの扱い (追加の検出器の具体名・入手先を書くか) は §13 の判断待ち。
- 表記: 投稿サイト名・基準名・適合の判定は書かない ([public-wording-policies.md](public-wording-policies.md))。
  処理の説明は「検出した領域をマスクに追加する」「余白 N% で広げる」のように機構で書く。
- 法的な整理 (2026-11-26、法律相談ではない): モザイクを**かける**機能はわいせつ性を下げる方向なので、提供で
  責任を問われる構図は考えにくい。注意点は見落としで、mIV は「これで十分」と表示しない。モザイクで違法な
  画像が合法になるわけではないことも、UI では何も示唆しない。

## 9. 既存の仕組みとの整合

- **表示順**: raw → erase → local-adjust → conceal → edit result → final pipeline は変えない。検出はその conceal の入力で行う。
- **キャッシュ**: マスクの変更は `clear_conceal_caches(idx)` (該当ページだけ)。全体設定の変更ではないので
  `bump_conceal_generation` は呼ばない。
- **ZIP・PDF・見開き**: 隠蔽加工は対象ページ 1 枚 (`target_idx`) で動いている。検出も同じ 1 枚に行う。分岐は足さない。
- **アップスケール後の解像度**: 隠蔽はアップスケールより前段 (元の解像度) なので、検出も元の解像度で行う。
- **リモート操作中**: 先例と同じく `remote_session_blocks_local_control()` で止める。worker は
  `local_ai_activity_lease()` を終わるまで持ち、リモートへの引き渡しは推論が終わるまで完了しない (§7.3)。
- **detached viewer**: 待ちの状態は context の bundle に置き、持ち主の context でだけ受け取る。detached の
  述語・viewport の経路には触れない予定。触れる必要が出たら、detached リワークの規則 (双方のレビューで構造的な
  修正であることに合意し、[detached-rework-plan.md](detached-rework-plan.md) に記録) に従う。

## 10. UI スレッドの応答性 ([ui-responsiveness.md](ui-responsiveness.md) §4)

| 処理 | 置き場 |
|---|---|
| 検出器フォルダの read_dir・ONNX のメタデータ | worker (ダイアログを開いたとき・読み直し) |
| セッションの作成・推論・後処理 | 検出 worker |
| ソース画素 | `Arc` の clone だけ (複製しない) |
| 結果の追加 | 図形の push とパッチ範囲の OR。Undo の複製と表示用テクスチャの作り直しは既存の 1 操作と同じ費用で 1 回 (§7.4) |
| 再合成 | 既存の `conceal-materialize` worker |

`perf::event` を「検出の開始」「セッション準備」「推論」「後処理」「結果の追加」に入れる。

## 11. 段階

### 段 0 — 実物の確認 (設計を確定させるための調査、コードは本体に入れない)

- YuNet 2026may を ort + DirectML / CPU で読み、出力の形と式を確かめる。段 (640 / 1920 など) と閾値を
  人物写真で決める。写真は権利のはっきりしたものを使い、リポジトリには入れない。
- Ultralytics の汎用モデル (yolo11n・yolo11n-seg・yolo26n・yolo26n-seg、COCO の分類) を ONNX に書き出し、
  出力の形とメタデータ (`names`・`imgsz`・`task`・`end2end`) を記録する。これらは開発機での確認だけに使い、
  配布物にもリポジトリにも入れない (AGPL)。
- §2 の局部の検出器 (01miku nano・deepghs・NudeNet 320n) は、**灰色の画像などを入れて出力の形とメタデータだけ**
  確かめる。成人向けの画像は集めない・使わない。実際の検出の様子は利用者の確認に回す。
- 検出にかかる時間 (初回のセッション作成を含む) を測り、§7.1 のモーダルで困らないかを判断する。
- **前処理の約束を確定する**: YuNet は入力の色の順・値の範囲・32 の倍数への埋め方を、OpenCV の
  `FaceDetectorYN` と非正方形・端数の大きさの画像で比べて同じ箱になること。Ultralytics 系は letterbox の
  余白の除き方と、輪郭の余白 (元の画像の px) の座標系を、汎用モデルの書き出しで確かめること。
- 大きな画像 (例 8000×6000) で、結果の追加の 1 回 (Undo の複製 + 表示用テクスチャ) にかかる時間を測る (§7.4)。
- DirectML で読めないものがあるかを確かめ、§6.2 の扱いを決める。

### 段 1 — 顔の自動検出 (同梱)

YuNet の同梱、外部モデルのセッション、検出 worker とモーダル、設定ダイアログ (顔だけ)、図形の追加と Undo、
ライセンス表記、マニュアルと製品ページ。これだけで「写真の顔に楕円のぼかしを足して直す」が使える。

### 段 2 — 追加の検出器 (BYO)

検出器フォルダと一覧の worker、Ultralytics の 3 形式の読み取り、分類の選択、輪郭パッチ、json による上書き、
読めないファイルの表示。

### 段 3 — 複数の画像への一括適用 (別に設計する)

一覧で選んだ画像に検出をかけ、各ページの `conceal.db` にマスクを書き、既存の一括エクスポートで書き出す。
スナップ写真の顔をまとめて隠す用途の本命。決めることが多いので (既にマスクがあるページの扱い、確認の流れ、
進行とキャンセル、書き込みの失敗の割り切り)、段 1・2 の後に別の設計書にする。

## 12. テスト

- **単体** (検出のモジュール):
  - 各形式の出力の読み取りを、作った小さなテンソルで確かめる (既知の入力 → 既知の箱・輪郭)。
  - letterbox の行きと戻りで、画像座標が元に戻る (縦長・横長・元より大きい入力)。
  - 重なりの除去、閾値、分類の選択。
  - 輪郭パッチ: 箱での切り抜き、太らせ、元の解像度への拡大、画像の端での切り詰め。
  - メタデータ・json・`labels.json` からの分類名の決定と優先順位。どれにも当てはまらない形を「読めない」にすること。
- **App レベル** (`page_edit_owner_tests` などの先例に倣う):
  - 結果を足すと図形とビットマップが増え、Undo 1 回で両方とも戻る。`conceal_cache` の該当ページが無効になる。
  - 持ち主 (context・page_key・items_generation)・`conceal_session` のどれかが違う結果は捨てる。
  - 検出中 (とダイアログ表示中) は `conceal_input_blocked()` が真になり、**キーだけでなく、キャンバスの生の
    ポインター入力 (筆・バケツ・図形・選択の操作) とパネルの操作 (スロット・プリセット・閉じる) も効かない**。
    [自動検出…] を続けて押しても 2 本目が始まらない。キャンセルで待ちが消える。
  - 述語が真の間、目のボタンの矩形を押しても、ドラッグで通過してもプレビューが始まらない。押していた保持は離すと
    後始末される。
  - 開始後に同じページの画素が差し替わる (消しゴムの補完の完了・補正レイヤーの再計算・元画像の読み直し) と、
    `Arc` の照合で結果を捨てる。差し替わらなければ (`Arc` が保たれ) 結果を足す。一覧の読み直し
    (`items_generation` の変化) でも捨てる。
  - キャンセルで待ちが消えた後も、worker が終わるまでは活動の lease が残り、リモートへの引き渡しの停止判定が
    完了しない。
  - context を閉じる・フォルダを替える・モードを出ると待ちが消え、worker のキャンセルが立つ。
    **別の context の隠蔽マスクは変わらない** (複数ウィンドウ)。
  - リモート操作中・本の追加の後続待ち中は始まらない。
  - 消しゴムと補正レイヤーのパネルに自動検出のボタンが無い。
- **UI**: ダイアログの 1093×614 の検査 (`tests/support/scroll_layout.rs` の先例)。スナップショットは足すなら
  [ui-snapshot-policy.md](ui-snapshot-policy.md) に従う。
- **利用者の実機確認**: 人物写真での顔の検出とぼかし、BYO の検出器を置いたときの一覧・検出・モザイク、
  大きな画像・ZIP・PDF・見開きのページ、検出中に別ウィンドウを操作したとき。

## 13. 利用者の判断が要る点

1. **マニュアルに追加の検出器の具体名・入手先を書くか**。書けば使い始めやすいが、mIV が成人向けの検出器を
   案内する形になる。案: マニュアルには形式の条件 (Ultralytics 形式の ONNX、置く場所、json の書き方) だけを書き、
   モデル名は書かない。製品ページ・Store には顔の機能だけを書く。
2. **段 3 (一括適用) の優先度**。スナップ写真の用途は一括のほうが価値が大きい。
3. **消しゴムに顔の検出だけは許すか** (顔を補完で消す用途)。v1 では許さない案。

## 15. 判断の記録

- **顔は同梱、局部は BYO**: 同梱できる顔検出が実在し (YuNet、MIT)、局部の検出器は調べた範囲ですべて
  Ultralytics 製で AGPL の主張がある。顔を隠す機能は機微性が低く、製品として紹介しやすい。
- **結果を既存のマスクにする**: 検出は完全ではない前提なので、焼き込まずに直せる形で渡す。保存・Undo などを
  新しく作らずに済む。
- **箱は図形、輪郭はビットマップ**: 箱は図形にすると動かせる。輪郭は図形で表せないので、筆やバケツと同じ
  ビットマップに入れる。
- **検出中はモーダル**: 検出は短く、途中の操作を受け付ける利点が小さい。割り込みを扱う仕組みを作るより、
  組み合わせそのものを消すほうが単純で見落としが少ない。外からの変化だけを持ち主の照合で捨てる。
- **検出器フォルダは固定、取り込みボタンなし**: 設定と状態を増やさない。使ってから要否を決める。
- **外部モデルを `AiRuntime` に置く**: セッションの持ち主を 1 つにし、`ModelKind` の固定の表 (TensorRT・診断) に
  手を入れない。同梱の YuNet も同じ経路にして、読み方を 1 つにする。
- **隠蔽加工だけ**: 局部の検出結果を補完につなげない。v1 では顔も含めて分けない (用途が薄く、経路を 1 つにできる)。
