## 1. 現状 (コード読み)

- ページ単位表示の左ドラッグ (`src/ui_fullscreen.rs` の「通常モード: ドラッグ操作」の `else if !continuous_active` 分岐) は、
  ドラッグ開始時の pan に `total_drag_delta` を足した絶対値の候補を `set_fs_pan_from_input(self.fs_zoom, 候補)` へ渡す。
  タッチの 1 本指ドラッグも egui の主ボタンのドラッグとしてここへ来る。
- `set_fs_pan_from_input` は初期配置要求 (§1.726) を消し、Z 以外では `clamp_fullscreen_pan_from_layout` (前 frame の layout から、
  画像が画面から完全に消えないための最小の重なり `FS_PAN_MIN_VISIBLE_PX` を残す緩い制限) を通して `fs_pan` に書く。
  この書き込み口はキー・ホイール・各種ズーム・ピンチの 2 本指移動・ゲームパッド・ナビゲータ・分析モードの切り替えなど 20 か所以上が共有する。
- 描画時にも `pan_bounds::draw_pan_correction` が同じ緩い制限で範囲外の pan を戻す (§1.810)。
- ページ内スクロール (§1.474、`src/ui_fullscreen/in_page_scroll.rs`) は、描いた表示単位の印 (`FsDrawnUnitStamp`) と入力時の照合
  (`fs_scroll_layout_matches`) が通るときだけ、`scroll_geometry` (表示単位 = 描いた各ページの pan 0 での矩形と白紙の相方の和) の
  「画面からはみ出す軸だけの範囲」で動く。範囲の外にある位置からは、内側へは進み、外側へは動かない (`AxisRange::step`)。

## 2. 決めること

### 2.1 設定

- `Settings::fullscreen_bound_drag_pan: bool`、`#[serde(default)]` で既定 **false**。未設定・旧版の設定ファイルでも従来の自由な移動。
- **未リリースの新しい設定キー**なので migration は不要 (v5.5.0 以前に無い。追加するだけで旧データの意味は変わらない)。
- 設定の転送 (`settings_transfer.rs`) は既存の bool 設定 (`fullscreen_smooth_page_scroll`) と同じ扱い。表示名は UI の文言と同じ。
- 環境設定: 「見開き・閲覧」ページ (`SpreadMode`) の「ページ内のスクロールを滑らかに動かす」の次に 1 行、anchor `spread/bound-drag-pan`。
  - チェックボックス: 「閲覧時のドラッグ移動を画像の端までに制限する」
  - 補足 (`ui.small`): 「ページ単位の静止画表示で、画面からはみ出す方向は画像の端で止まり、画面に収まる方向は動きません。
    補正パネルを開いているときや編集中、ズームモード・連結読み・360 度・3D 表示には適用しません。キー・ホイール・ズームの動きは変わりません。」
  - 検索の索引 (`search_index.rs`) に entry を足す (語: ドラッグ・パン・移動・端・制限・余白)。
- 「…」の小パネルや上部バーには足さない (設定を変える場所を増やさない)。

### 2.2 適用する入力 (ここだけ)

- **ページ単位表示のキャンバスの左ドラッグ 1 か所** (マウスと、egui が主ボタンのドラッグとして渡すタッチの 1 本指ドラッグ)。
- 適用しない (今のまま): キー (↑↓・4 方向・K / J はもともと端で止まる)、ホイール、Ctrl+ホイール・キーボード・中ボタン・
  Ctrl+Space のズーム、ピンチと 2 本指の移動 (ズームの操作の一部)、ゲームパッドの移動とズーム、ナビゲータのドラッグ・ダブルクリック・
  範囲ズーム (位置を明示的に指定する道具)、分析モードとの切り替え、Ctrl+ドラッグの回転、Space+ドラッグ (編集中)、初期配置、
  描画時の位置補正 (§1.810)、ダブルクリックのリセット。
- 共有の書き込み口 `set_fs_pan_from_input` には手を入れない (入力の種類の引数も足さない)。

### 2.3 適用する画面 (面の述語)

- ページ内スクロールと同じ面 `fs_in_page_scroll_surface()` の上だけ: ページを持つ静止画、ページ単位、ズームの持ち主が通常の画像
  (Z ズーム・360 度・3D・分析を除く)、比較なし、表示トリムの編集なし、編集モード (消しゴム・隠蔽加工・切り取り・注釈・補正レイヤー等) なし、
  範囲キャプチャなし。連結読みはドラッグの分岐の手前で別経路に分かれるので対象外 (専用の制約のまま)。
- さらに、**左パネルの補正・表示トリムのタブを開いている間**も対象外 (r1 P2-3)。`is_overlay_edit_mode_active()` は
  通常の画像補正パネルを含まないので、ドラッグ専用の述語で `adjustment_mode.is_open()` かつ
  `fullscreen_left_panel_tab != Bookmarks` を除く。ブックマークのタブは閲覧として扱い、制限する。
  共有のページ内スクロールの述語 `fs_in_page_scroll_surface()` は変えない。
- **自由回転で傾けて描いている間も対象外** (r5 P2-3 を受けた設計担当の判断)。判定は、照合が通った前 frame の layout の transform に
  自由回転が適用されているか (描画と同じしきい値。`free_rotation_rad` の絶対値が描画側の「回転なし」のしきい値を超える) で行う (r6 P3)。
  `fs_free_rotation` の生の値は使わない: 見開きの 2 ページ描画は自由回転を適用しないので、単ページで傾けた値が残ったまま見開きへ切り替えても、
  見開きは制限する。単ページへ戻れば、傾いて描くので対象外に戻る。斜めに置いた画像には画面の辺に合う「端」がなく、
  外接矩形で制限しても角に余白が残り、細長い画像では外接矩形が画面を覆ったまま画像が見えなくなる。実際の四角形との交差で制限する形は
  許容領域が箱でなくなり、組み合わせが増える。自由回転は Ctrl+ドラッグで一時的に傾ける操作なので、その間は今の自由な移動のままにする。
  90° 単位の回転 (保存される回転) は対象 (描いた矩形が画面の辺に平行)。
- 面の外・設定 OFF のときは今のコードをそのまま通る (候補を `set_fs_pan_from_input` へ渡す)。

### 2.4 範囲 (端) と、ドラッグ 1 frame の処理

設定 ON かつ面の上のドラッグの frame では:

1. 従来どおり、ドラッグ開始時の pan + `total_drag_delta` を候補にする (絶対値。frame ごとの差分を積まない)。
2. `fs_scroll_layout_matches(ctx)` が通らなければ (描いた表示単位と今の構成・幾何・倍率が合わない frame)、`fs_pan` を書かない。
   初期配置要求は従来のドラッグと同じく消す。次に照合が通る frame で、同じ絶対値の候補から追いつく。
3. 照合が通れば、前 frame に描いた layout から、描いた要素の矩形 (実ページと白紙の相方。`scroll_geometry` と同じ作り方)、表示領域 `V`、
   描いた pan `p_d` (各 transform が持つ pan) を読む。今の `fs_pan` を `cur` とする。**以後の矩形はすべて `cur` へ換算して使う**
   (描いた矩形 + (`cur` − `p_d`)。ふつうは `cur = p_d` で換算は 0。滑らかな移動の補間中だけ違う)。`U` = 要素の和の外接矩形 (表示単位)。
   **端はすべて `cur` から測った移動量を物理ピクセルの整数倍に丸めて `cur` に足す** (pan を動かすのは物理ピクセルの整数倍だけ)。
   表示単位の端 (この 3) は `trunc_px` (0 の向きへ丸める。測った辺を越えない)、要素の可視性の箱 (3b) は**箱の内側へ**丸める
   (下限は `ceil_px`、上限は `floor_px`)。どちらも、丸める前に範囲の中にある `cur` は丸めた後も必ず中にある (r8 P2)。
   **表示単位の端の `trunc_px` だけ**は、整数との差が 0.001 物理 px 以下なら演算誤差とみなして整数へ寄せてから丸める。その帯の外の端数の丸め方向は変えない。
   **可視性の箱の `ceil_px` / `floor_px` は整数へ寄せず、素の内向きの丸めを使う**。演算誤差で 1 物理 px 内側へ縮む場合は丸めの残りとして許容する。既に水準を満たす軸の原点の保持は維持する。
   軸ごとに:
   - **画面に収まる軸** (`U` の長さ ≤ `V` の長さ): 位置は `cur` のまま (動かさない。中央へ寄せ直さない。先頭・末尾単ページの左右配置、
     ピボットのズームでずれた位置もそのまま残す)。
   - **画面からはみ出す軸**: 端を、描いた矩形を画面の辺に合わせるための移動量から求める。
     `min = cur + trunc_px(V.max − U.max)`、`max = cur + trunc_px(V.min − U.min)`。位置は `clamp(候補, min(min, cur), max(max, cur))`。
     範囲内なら端で止まる。範囲の外にある位置 (設定を ON にした直後、窓の大きさの変更、ピボットのズームの後など) からは、内側へは動き、
     さらに外側へは動かない。内側へ入った後は外へ戻れない。**ドラッグの開始で位置が跳ばない**。
   - こうして軸ごとに clamp した位置を**候補 c** とする (各軸で `cur` と 1 の候補の間にある)。
3b. **見え方の水準を下げない** (r4 P2 / r5 / r6 / r7): 外接矩形が画面を覆っていても、実際に描く要素が見えるとは限らない
   (非対称な見開きの L 字の空き。`asymmetric_spread(true, false)` で pan 0 から `(-510, 1000)` へ動かすと、左ページは左へ、右ページは下へ
   完全に外れ、全画面が背景になる)。**描いた要素** = 各実ページの描いた矩形と、白紙の相方の矩形 (傾けて描く表示は対象外なので、どれも画面の辺に
   平行)。規則は 1 つで、場合分けをしない:
   - **見え方 `v(p)`**: 要素 e と軸ごとに、基準の長さ `m` = min(`FS_PAN_MIN_VISIBLE_PX`, e の長さ, 画面の長さ) (共有の緩い制限と同じ) と、
     e と画面の重なりの長さ (離れていれば負の距離) をとり、`重なり / m` の 2 軸の小さい方を e の見え方とする。`v(p)` は全要素の見え方の最大
     (1 以上なら、どれかの要素が共有の緩い制限と同じだけ見えている。0 以下なら何も見えていない)。
   - **水準 `t` = min(1, v(cur))**。要素ごとに「e の見え方が `t` 以上」になる pan の箱 `B_e(t)` を作る (軸ごとに `重なり ≥ t·m` の範囲。
     `t = 1` なら共有の緩い制限の min / max と同じ式。端は箱の内側へ丸める: 下限 `cur + ceil_px(移動量)`、上限 `cur + floor_px(移動量)`。
     `cur` が箱の外にある要素で `cur` の側へ丸めると箱が広がり、必要な重なりが 1 物理ピクセル未満の要素 (短くトリムしたページ) では、画面と接するだけの
     位置まで許してしまう — r9 P2)。
   - `K` = `cur` と c を対角とする箱 (c は各軸で `cur` と 1 の候補の間にあるので、`K` の中は「要求と逆へ動かない・行き過ぎない」位置)。
     位置は、`B_e(t) ∩ K` が空でない要素ごとの `clamp(c, B_e(t) ∩ K)` のうち、c に最も近いもの。
   - `v(cur) ≥ t` なので、`cur` は見え方が最大の要素の `B_e(t)` に入っていて、端を `cur` の側へ丸めるので丸めた後も入っている (r8 P2:
     補間中に `p_d` 起点で丸めると、0.25 px の差で `cur` が箱から外れ、合法な縦 100 px の移動が止まる。内側への丸めでも、`cur` を含む箱は
     `cur` を含んだまま)。候補は必ずある
     (浮動小数の誤差で 1 つも無ければ `cur`)。
   - 意味: ふつうの位置 (`v(cur) ≥ 1`) からは、どれかの要素が `FS_PAN_MIN_VISIBLE_PX` だけ見える位置にしか動かない。新しく見える要素も、
     見えていた要素も同じ基準 (r7 P2)。見開きの片方からもう片方へは、移った先が基準を満たせば同じ frame で移る (r6 P2)。
     基準に足りない位置 (`v(cur) < 1`。窓の大きさの変更などで、25 px だけ見えている・何も見えていない) からは、**今の水準より悪くならない**位置に
     動く: 外側へは進まず、内側と、水準を保てる別の軸へは少しずつ動ける (r5 P2-1・P2-2)。何も見えていない位置 (`v < 0`) からも同じ規則で、
     いちばん近い要素からそれ以上離れない。水準は動いた後の位置から毎 frame 測り直すので、良くなった分は戻せない (3 の範囲と同じ性質)。
4. 位置が `cur` と違うときだけ書く。書き込みは **ON 専用の書き込み** (`fs_zoom` を描いた倍率 `drawn_zoom` に揃え — ページ内スクロールの
   `write_fs_page_scroll_pan` と同じく near-fit の正規化の境で倍率が変わらないようにする —、初期配置要求を消し、`fs_pan` に位置をそのまま書く)。
   共有の `set_fs_pan_from_input` は通さない (r1 P2-1 / r2 P2-1 / r3 P2-3)。`cur` と同じなら書かない (初期配置要求は 2 と同じく消す)。
   - 共有の緩い制限 (`clamp_fullscreen_pan_from_layout`) は「どれかの**実ページ**が `FS_PAN_MIN_VISIBLE_PX` だけ画面に残る」ことを要求し、
     白紙の相方を含まない。一方、初期配置 (§1.726) と描画時の補正 (§1.810) は白紙を含む表示単位を基準にしており、白紙の側の初期配置では
     実ページが画面の外にある位置が通常に存在する。この位置から緩い制限を通すと、小さなドラッグで位置が大きく跳ぶ。実ページごとの可視性の箱と
     交わりを取る形 (r2 の修正) も、その位置から内側へ徐々に戻れない (r3 P2-3)。
   - そこで ON のドラッグは、**表示単位の範囲 (3) と、白紙の相方を含む描いた要素の可視性 (3b)** を基準にする。初期配置・描画時の補正と同じく
     白紙の相方を表示の一部として扱う。描画時の補正は表示単位を許容するので、書いた位置を戻さない。
   - 拡大した白紙付きの単ページでは、ドラッグで白紙の側の端 (白紙の相方が画面を覆う位置) まで動かせる。キーのページ内スクロールは共有の緩い制限を
     通すので、その手前 (実ページが少し残る位置) で止まる。この差は残す (ページ内スクロールは変えない)。
- 3・3b は純関数 `bounded_drag_pan(layout, cur, proposed) -> Vec2` 1 つにまとめる (倍率・DPI・`p_d` は layout の transform から読む)。
  ページ内スクロールの `scroll_geometry` / `scroll_pan` は変えない。

**端の精度と丸め (割り切り)**:

- 描画は layout の原点・sampler の原点・見開きのページ間隔を物理ピクセルへ丸める。端は「いま描いた矩形」から測るので、端に着いた後に描き直した
  矩形が、丸めのせいで予測と最大 1〜2 物理ピクセル違うことがある (端数の倍率、見開きで幅が奇数のときの `round()` の境など)。
- 3 の規則は**外側へしか自分から動かない**: 端より手前 (画像が画面の外に 1 物理ピクセル以上残る) なら、その整数部分だけ外へ動く。1 物理ピクセル未満なら
  動かない。丸めのせいで端を越えた (余白が出た) 場合は、`cur` が範囲の外にある場合と同じ扱いでそのまま残し、自分から内側へ戻さない。
  したがって端で往復 (振動) しない。数 frame で必ず止まる。
- 結果: 回転のない単ページ・通常の見開きでは端にちょうど止まる (はみ出しが 1 物理ピクセルだけの画像でも端から端まで動く。不動帯はない)。
  端数の倍率などで辺が物理ピクセルに乗らないときは、画像が最大 1 物理ピクセル未満だけ画面の外に残る。見開きの丸めの境では端に最大 1〜2 物理ピクセルの余白が残ることがある。
  これは §1.810 の描画時の補正が許容している丸めの残り (`2 * physical_pixel_scale`) と同じ大きさで、同じく許容する。
- 止まる位置は**描いた位置として**同じになる。論理の pan の値は、途中で描いた pan の端数によって 1 物理ピクセル未満だけ違うことがある
  (例: 0 から直接動かすと 500、0.75 を描いた後だと 499.75。描いた位置は同じ)。
- **「跳ばない」「最大 1〜2 物理ピクセル」は、実効の幾何が変わらない間の、今回足す端の処理についての性質** (r4 P3)。次の既存の動作はそのまま受け継ぐ:
  補間中にドラッグが pan を書くと補間が捨てられ、描画が補間の途中の位置から最終位置の側へ移る。near-fit の正規化 (`fs_zoom_pan_for`) を
  またぐと実効の倍率が変わり、描く大きさが変わる (大きな画像では 2 物理ピクセルを超える)。論理の pan の端数の差は `fs_view_has_moved` の
  完全一致の判定には現れる (描いた位置の一致とは別)。
- 滑らかな移動の補間中は `p_d` (補間の途中の pan) と `cur` (最終位置) が違う。矩形を `cur` へ換算してから測るので式はそのまま使える
  (換算した矩形は、`cur` で描いた場合と丸めの分だけ違い得る)。
  書けば補間は捨てられ (`fs_pan != to`)、次の frame は `cur` で描いた矩形から測り直す。
- **採らない: 任意の pan に対する描画の幾何を解き直す純関数 `G(p)` を作り、余白を作らない最外の pan を厳密に求める** (r3 P2-1 / P2-2 の提案)。
  通常描画の幾何 (単ページの fit・見開きの joint layout・間隔の揃え・白紙の相方・sampler の丸め) を描画経路から切り出す大きな変更になり、
  設定 OFF の描画にも触れる。得られるのは最大 1〜2 物理ピクセルの差で、今回の設定の範囲に見合わない。必要が分かれば別項目にする。

- 表示単位は `scroll_geometry` と同じ作り方: 見開きは左右と白紙の相方とページ間隔を合わせた外接矩形、回転 (90° 単位と自由回転) は描いた
  矩形 (自由回転は対象外)、表示トリムは描いた範囲。

### 2.5 設定の切り替え・窓の大きさ・解像度の確定

- **位置を補正する処理を足さない**。設定を ON にしたとき・窓の大きさや DPI の変更・回転・トリム・素材の解像度の確定で、今の位置が
  端の範囲の外になっても、そのまま残る。次のドラッグは 2.4 の 3 のとおり内側へだけ動く (自分から内側へ戻す処理はない)。ページを送れば初期配置で範囲内から始まる。
- 素材の解像度が確定しても、表示単位の大きさは fit と倍率で決まるので、ふつうは範囲が変わらない。変わった場合も上と同じ。

## 3. 状態の組み合わせを減らす検討 (CLAUDE.md「設計の簡素化」)

- **採用**: 新しい実行時状態を持たない (設定 1 つだけ)。端は毎 frame、描いた表示単位から求める (ページ内スクロールの既存の幾何と照合を再利用)。
  適用はドラッグの 1 か所に限り、共有の書き込み口・描画時の補正は変えない。設定 OFF の経路は今のコードそのもの。
- **採らない: 描画時の補正を ON のとき厳しくする (常に端の範囲内に保つ)**。ズームのピボット・初期配置・キー・ナビゲータなど全入力の結果が
  変わり (要望の範囲外、「他の操作を変えない」に反する)、画面に収まる軸を常に中央へ戻すことになる。
- **採らない: `set_fs_pan_from_input` に入力の種類を渡して分岐する**。20 か所以上の呼び出し元すべてに種類が要り、組み合わせが増える。
- **採らない: 端の範囲へ単純に clamp する**。範囲の外にある位置からドラッグを始めた瞬間に位置が跳ぶ。
- **採らない: 設定の切り替え・リサイズで位置を補正する**。新しい書き手と発火条件が増える。内側へだけ動く規則で足りる。
- **採らない: ON のドラッグでも実ページごとの可視性 (共有の緩い制限) を守る**。白紙の相方を含む表示単位を基準にする初期配置・描画時の補正と基準が違い、跳び・手前での停止・内側へ戻れない位置が出る (設計レビュー r1〜r3)。表示単位 1 つを基準にする。
- **採らない: 端を厳密に解く幾何の純関数 `G(p)`**。2.4 の「端の精度と丸め」。
- **採らない: ナビゲータのドラッグにも適用する**。ナビゲータは位置を明示的に指定する道具で、要望は画像そのもののドラッグ。
- まれな失敗: 保存データを持たない。既定の割り切り。

## 5. 検証 (テスト)

純関数:
- はみ出す軸で範囲内から外へ → 端で止まる。各辺 (左右上下) と斜め。
- 収まる軸 → 動かない (`cur` のまま、0 でない `cur` でも中央へ戻らない)。
- 範囲の外の `cur` から: 内側へは動く、外側へは動かない、内側へ入った後に外へ戻れない。
- 見開き (左右で高さが違う・白紙の相方つき)・90° 回転・表示トリム済みの layout で、端が `scroll_geometry` の端と一致する。

App (handler-level):
- 設定 OFF: 今のドラッグと同じ (収まる画像も動く、はみ出す画像は今の緩い制限の範囲まで動く)。既存のドラッグのテストが変わらないこと。
- 設定 ON: 拡大画像のドラッグで各辺の端で止まる。収まる画像はドラッグで動かない。単ページの左右配置 (白紙の相方) が中央へ寄らない。
- 設定 ON でも面の外 (編集モード・Z・表示トリムの編集・連結読み) は今のドラッグのまま。
- 設定 ON でも、キー・ホイール・Ctrl+ホイールのズーム・ゲームパッドの移動の結果が OFF と同じ。
- 照合が通らない frame (ページ送り待ちなど) では `fs_pan` を書かず、初期配置要求は消える。
- ドラッグの開始で位置が跳ばない (範囲の外の `cur` から、移動 0 の frame で `fs_pan` が変わらない)。
- 設定の転送・既定値・serde default (旧設定ファイルに key が無い → false)。

- 白紙の相方つきの拡大単ページ: 白紙の側の初期配置 (実ページが画面の外) から小さくドラッグして、位置が跳ばずに内側へ少しずつ動く。
  白紙の側の端 (表示単位の端) まで動き、そこで止まる。描画時の補正が書いた位置を戻さない。
- 非対称な見開き (`asymmetric_spread(true, false)`): `cur = (-450, -500)` (右ページが十分見え、左ページは幅 40 px) からの縦のドラッグは、
  表示単位の端までは進まず、右ページが基準だけ残る位置で止まり (pan の y を増やす向きは `(-450, 755)`、減らす向きは `(-450, -957)`。
  設計レビュー r2・r8 の導出)、横は動かない。
- 短くトリムしたページ (r9 P2): DPI 1.0、画面 `(30,50)–(1030,1050)`、左ページ `(-480,-950)–(520,2050)`、右ページ `(540,538)–(1540,562)` (pan 0)、
  `cur = p_d = (-489, 1000)` (左ページが幅 1 px) から `(-510, 512)` を要求しても、全画面が背景になる位置へは動かない。
- 滑らかな移動の補間中: 非対称な見開き、DPI 1.0、`p_d = (-200.75, 1000)`、`cur = (-442, 1000)` (換算した左ページの重なり 47.75 px) から
  c = `(-442, 900)` へ、1 回の入力で 100 px 動く (その frame のあとすぐ離しても同じ)。
- 入力の分け方 (r6 P2 / r7 P2): 同じ直線のドラッグを「大きな 1 回の入力 → すぐ離す」と「小さな入力の連続」で与え、**最後の候補 c が許される位置
  (どれかの要素が基準を満たす) のとき**、描いた位置が同じ (論理の pan は 1 物理ピクセル未満の差まで)。`asymmetric_spread(true, false)`、DPI 1.0、
  `cur = (-442, 1000)` から: c = `(-510, 700)` (右ページが縦 103 px) は 1 回でも分割でも描画位置として c (論理の pan は 1 物理 px 未満の差を許容)。c = `(-510, 762)` (右ページが縦 41 px で基準に
  足りない) は、1 回でも `(-502, 790)` を経る分割でも `(-442, 762)`。c が許されない位置のときは、途中の位置によって止まる所が変わり得る
  (壁に沿って滑る動きの性質。逆へは戻らない)。
- 端数の倍率・DPI 1.0 / 1.25 / 1.5 で「端を越える同じ候補 → 実描画 → 再照合」を 10 frame 繰り返し、数 frame 以内に `fs_pan` が
  変わらなくなり、その後は描いた辺も変わらない (往復しない)。止まった位置の余白は 2 物理ピクセル以下。
- 見開きで幅が奇数 (例: 表示域 1000、左右 1000 / 1001、間隔 0、DPI 1.0) の端で、往復せずに止まり、余白は 2 物理ピクセル以下。
- はみ出しが 1 / 2 / 3 物理ピクセルだけの画像 (回転なし) で、端から反対の端まで動く (不動帯がない)。端の直前から端を越える入力で端に着く。
  DPI 1.0 / 1.25 / 1.5 の実描画でも、端で同じ候補を繰り返した後に反対の端へ動かし、元の端へ戻して固定点と可動幅を検査する。
- 滑らかな移動の補間中 (`p_d` ≠ `cur`) のドラッグで、補間が捨てられ (既存の動作)、端の処理が逆向きの移動を足さず、次の frame で測り直した端に止まる。
- 非対称な見開き (`asymmetric_spread(true, false)`) で pan 0 から `(-510, 1000)` を要求しても、どちらかのページが `FS_PAN_MIN_VISIBLE_PX` だけ
  残る位置で止まり、全画面が背景にならない。白紙の側の初期配置からは小さなドラッグで少しずつ動く (白紙も要素)。
- どの要素も画面と重ならない位置 (窓の大きさの変更の後を想定) からのドラッグは、跳ばず、いちばん近い要素からそれ以上離れず、近づく向きと
  距離を保つ別の軸へは動き、要素が見える位置まで動かせる。
- `asymmetric_spread(true, false)` で、左ページの見えている幅が 0 / 1 / 25 / 45 / 48 px の位置 (右ページは画面の外) から、外側・内側・別の軸へ
  ドラッグする: 外側へは見えている幅を減らさない、内側へは少しずつ動く、別の軸へは水準を保てる範囲で動く
  (例: `cur = (-443, 1000)` から `(-443, 900)` へ 100 px 動く。`cur = (-465, 1000)` から `(-510, 1000)` へは動かない)。
- 自由回転で傾けて描いている単ページは、設定 ON でも今のドラッグのまま (OFF と同じ結果)。90° 回転では制限する。
  単ページで傾ける → 見開きへ切り替える (値は残るが傾けて描かない) → 制限する → 単ページへ戻る → 対象外、の順の回帰。
- 補正パネル・表示トリムのタブを開いている間は制限しない。ブックマークのタブでは制限する。各編集モード (消しゴム・隠蔽・切り取り・注釈・
  補正レイヤー・SNS 分割) で今のドラッグのまま。
- 動かなかったドラッグの解放でページを送らず、その後の単クリックは送る (自動配置の判定を保つ)。動いた場合は今のとおりクリックで送らない。
- 滑らかな移動中 (§1.823) に、制限されたドラッグが論理の pan を変える場合は補間が捨てられ、変えない場合は補間が続く。
- 照合が通らない frame からドラッグを続けて復帰する場合 (同じ絶対値の候補から追いつく) と、復帰前に離す場合。near-fit、DPI・窓の大きさの
  変更、暫定素材から完成素材への交換の後のドラッグ。
- 1 本指のタッチ (`ViewerPointerPassthrough` 経由) で ON / OFF の差が出る。ナビゲータのドラッグと 2 本指の移動は ON / OFF で同じ。
- F12 / 独立 context でドラッグした後、兄弟 context の pan・倍率・描いた印・初期配置要求・補間・ドラッグ開始点が変わらない。

実機 (利用者・サブ PC): OFF の既存動作、ON の各辺での停止、収まる画像・拡大画像・見開き・回転・表示トリム済み、編集への出入り、
別ウィンドウ、設定の切り替え・窓の大きさの変更の後のドラッグ。

### 8.1 NG-1: 端の外へ引いてから戻すと、押した位置へ戻るまで動かない

- 観測 (サブ PC): ON、`3-grid.png` 100% で右下の端に着けた状態から押し、端の外へ引いてから戻すと、押し始めの位置を越えるまで画像が動かない。
- 原因 (コード): 候補は「ドラッグ開始時の pan + `total_drag_delta`」(2.4 の 1、絶対値)。端で止めた分が `total_drag_delta` に残り、戻す向きの移動が
  まずその分を打ち消すのに使われる。OFF でも共有の緩い制限の外へ引けば同じ動きになる (§1.834 で生まれたものではない)。
  確認依頼文の期待「戻す向きに変えたところですぐ動き出す」は、設計担当がコードを確かめずに書いたもので、r10 の設計とは食い違っていた。
- 変更: 照合が通り `bounded_drag_pan` が位置 `r` を出した frame で、**`r` が候補 `c0` (= 開始時の pan + `total_drag_delta`) と違う軸だけ**、
  ドラッグの起点の pan (`fs_pan_drag_start` の pan) を `r − total_drag_delta` に置き直す。次の frame の候補は `r` + (その frame までの指の移動) になり、
  戻す向きに変えた瞬間から動く。
  - `r` と `c0` が同じ軸 (端に当たっていない軸) は起点を書き換えない (浮動小数の積み残しを作らない)。
  - 照合が通らない frame (2.4 の 2) は起点を変えない。次に照合が通る frame で、同じ絶対値の候補から追いつく性質を保つ。
  - 3b の見え方の制限で止まった軸も同じ扱い (`r` ≠ `c0` なら置き直す)。止まった理由で場合分けしない。
  - 書き換えるのは既存のドラッグの起点 1 つで、新しい実行時状態は足さない。解放で起点を消すのは今のまま。
  - 対象の入力は 2.2 と同じ (マウスの左ドラッグと、同じ経路を通る 1 本指のタッチのドラッグ)。2 本指の移動・ピンチ・ゲームパッド・キー・ホイール・
    ナビゲータ・Ctrl のドラッグ回転・連結読みのドラッグには広げない。1 本指のタッチを外すと、制限は効くのに NG-1 だけ残るので、制限と同じ入力にそろえる。
- **経路に依存する (仕様)**: 起点を置き直すと、止められた分 (端の外・3b で止まった分) は捨てられ、行き先は「押した位置からの移動量」ではなく
  「止まった位置からの移動量」になる。端に当たってから向きを変えたときにすぐ動くのは、この性質による (求める挙動)。
  その代わり、**途中の frame で起点が置き直されると、同じ直線上の単調な入力でも、入力の分け方で終点が変わる** (r11 P2)。
  例: `asymmetric_spread(true, false)`、DPI 1.0、開始 pan `(-442, 1000)`。累積移動 `(-68, -300)` を一度に渡すと `(-510, 700)`。
  先に `(-51, -225)` を渡すと 3b で x が止まり `(-442, 775)` (起点の x が −391 になる)、続いて `(-68, -300)` で `(-459, 700)`。
  さらに同じ向きへ動かせば `(-510, …)` へは届く (止めた分を後から取り返さないだけ)。止めた分を覚えておく状態は足さない。
- 5 の「同じ直線を大きな 1 回の入力と小さな入力の連続で与えて、描いた位置が同じ」は、**途中で起点が置き直されない場合** (止まるのが最後の frame だけ、
  または端で止まる軸の結果が同じになる場合) に限る。純関数のテスト (`bounded_drag_pan` だけを呼ぶもの) は起点を扱わないので今のまま通る。

### 8.2 気-1: 縮小して画面に収まった画像が、画面の外にはみ出したまま戻せない

- 観測 (サブ PC): ON、拡大して左上の端へ寄せてから、画面中央で Ctrl+ホイールで縮小すると、縦横とも画面より小さくなっても下の段が画面の外に
  約 66 px 出たまま残り、ドラッグで戻せない。
- 原因 (設計): 2.4 の 3 で「画面に収まる軸は `cur` のまま (ピボットのズームでずれた位置もそのまま残す)」とした。はみ出す軸には
  「範囲の外の位置からは内側へだけ動く」戻り道を作ったが、収まる軸には作っていなかった。
- 変更: 画面に収まる軸 (`U` の長さ ≤ `V` の長さ) の候補を次にする。内側にある移動量の範囲 `I = [V.min − U.min, V.max − U.max]` (収まるので空でない)。
  - `0 ∈ I` (表示単位が画面の中に収まっている): 今のまま `cur` (動かない。原則「画面に収まる方向は動かない」を保つ)。
  - `U.min < V.min` (低い側にはみ出している): 範囲 `[cur, cur + trunc_px(V.min − U.min)]` に clamp。
  - `U.max > V.max` (高い側にはみ出している): 範囲 `[cur + trunc_px(V.max − U.max), cur]` に clamp。
  - つまり、はみ出している分を戻す向きにだけ動き、全体が画面に入ったところで止まる。外側へは動かない。入った後は今と同じく動かない。
    中央へは寄せない。端の丸めははみ出す軸と同じ `trunc_px` (整数への寄せを含む) で、止まる位置は最大 1 物理ピクセル手前になり得る (2.4 の丸めの残りと同じ)。
  - この候補に 3b の見え方の制限をそのままかける (内側へ動くと重なりは減らない)。8.1 の起点の置き直しもこの軸に同じく効く。
- 環境設定の補足文「画面に収まる方向は動きません」は変えない (戻す向きの動きは、はみ出した状態から元に戻すための例外で、収まっている画像は動かない)。
  マニュアルの行に「画面からはみ出している分を戻す向きには動きます」を足す。

### 8.3 採らなかった案

- **起点を毎 frame 置き直す (frame ごとの差分で動かす)**: 照合が通らない frame の追いつき (2.4 の 2) が成り立たなくなり、OFF と同じ経路の性質も変わる。
  端で止まった軸だけ置き直せば NG-1 は消える。
- **OFF の経路でも置き直す**: OFF は今のコードそのまま、という前提 (2.3・3) を崩す。要望の範囲外。
- **縮小 (ピボットのズーム) の後に、収まった軸を画面の中へ寄せ直す**: ズームの結果を変える (2.6・3 の「他の操作を変えない」に反する)。
- **収まる軸を画面の中なら自由に動かす**: 「画面に収まる方向は動かない」(要望・2.1 の文言) に反する。

  - 上の 3b の例を、ドラッグの分岐を通る handler-level のテストで与え、分けた入力の終点が `(-459, 700)` になる (経路依存を仕様として固定する)。
