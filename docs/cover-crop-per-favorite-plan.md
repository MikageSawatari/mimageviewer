## 1. コードで確かめた今の作り (master `361411c72`)

- 自動切り出しは環境設定の全体設定 3 つ (`thumb_cover_auto_crop` / `_binding` / `_folders`、settings.rs) で決まる。
  `configured_thumbnail_auto_crop(settings) -> Option<AutoCropIdentity>` (app.rs) が識別子を作り、
  `App::thumbnail_auto_crop_identity()` はドライブ一覧だけ `None` にする。
- 識別子は**一覧ごとには持たず、サムネイルの要求を作るたびに全体設定から求める** (`enqueue_priority_thumbnail`・
  `update_keep_range_and_requests`・`enqueue_idle_upgrades`・`seed_auto_aspect_from_cache`)。
  `make_load_request_with_auto_crop` → `LoadRequest::set_auto_cover_crop` が、キャッシュのキー (`|autocrop:v3…`)・
  catalog の親行・worker への指示を同時に書く (cover-crop-plan §5.3 の単一の所有者)。
  要求 1 件ごとに識別子を渡す形なので、アイテムごとに違う識別子を渡すこと自体は今の型で表せる。
- 存続集合 (`folder_thumb_existing_keys_for_with_auto_crop` / `representative_existing_keys_in_archive`) は
  「印なしのキー + 現在の識別子のキー」を残し、物理フォルダの一覧で `delete_missing` が他を消す。
  呼び出し元 7 か所 (物理フォルダ・タグ表示・お気に入り検索・閲覧履歴・★一覧の install と prepare worker・ZIP 内一覧) は、
  アイテムごとに呼ぶが同じ値を渡している。
- 一覧単位で識別子を持つのは、コレクション一覧の digest / 再利用キー (`CollectionGridThumbnailSources` /
  `CollectionGridPrepareReuseKey`)、`BookCoverEnv` (範囲画面・AI 説明文・メタデータ欄が使う)、★一覧 prepare の設定の写し。
  色フィルタ (`color_identity_for_idx` / `color_work_identity_for_idx`) はアイテムごとに全体設定から求める。
- 全体設定を環境設定で変えると、`apply_file_type_visibility_change` が表示中の一覧を読み直す
  (検索・タグ表示などは閉じて元の場所へ戻る。フルスクリーン中は戻ったときに読み直す)。キーの名前空間が分かれているので、
  作り済みの行を消す処理は無い。
- mIV Remote・MCP の `get_thumbnail`・AI 説明文の一括作成 (`caption_job_worker`) は自動切り出しを使わない (Remote は印なしのキー)。
- お気に入り (`FavoriteEntry`) は settings.db の `favorites` 表に列を明示して保存する (リリース済み)。列の追加は
  `migrate_favorites_table` の `ALTER TABLE ADD COLUMN` (`auto_index_similar` が前例)。JSON は手書きの
  Deserialize/Serialize で、未知の項目は無視する。設定の書き出し・読み込み (settings_transfer) はお気に入りを運ばない。
- 「お気に入り > 編集」は OK/キャンセルの無い即時反映のダイアログで、行ごとの列 (索引の入/切など) を変えたフレームで
  `settings.save()` と副作用を走らせる (favorites_editor.rs)。
- 似た規則の前例: 補正の「標準設定を分ける」は `final_composite::active_favorite_default_id_for_path` で、
  **値を持つお気に入りのうち最も深いもの**を選ぶ (値の無いお気に入りは素通し)。

## 2. 状態を減らす検討 (CLAUDE.md「設計の簡素化」)

- **表示状態の記憶 (`FavoriteViewState`) には入れない**。あれは一覧やフルスクリーンでその場で変えた値を、
  利用者が有効にしたとき (`remember_favorite_view_state`、既定 OFF) だけ覚える仕組みで、全体設定へ overlay を
  かぶせて戻す。自動切り出しは環境設定でしか切り替えない値なので、入れると「overlay 中の環境設定の表示」
  「記憶 OFF のとき効かない」「その場の入口が無い」の組み合わせが増える。**お気に入りそのものの設定** (索引の入/切と同じ扱い)
  にする。
- **一覧ではなくアイテムの場所で決める**。一覧の場所で決めると、検索結果・閲覧履歴・★一覧・コレクションのような
  場所を持たない一覧で決められず、同じ本が一覧によって違うキー・違う見た目になる。アイテムの場所で決めれば、
  同じ本はどの一覧でも同じキーになり、キャッシュも共有される。要求ごとに識別子を渡す今の作りにそのまま乗る。
- **綴じ方向・画像フォルダの本は全体設定のまま**。お気に入りが持つのは入/切だけ。
- **切り替えの効果は既存の経路に乗せる**。値を変えたら、環境設定で全体を変えたときと同じ読み直し
  (`apply_file_type_visibility_change`) を呼ぶ。作り済みのサムネイルを消す処理は足さない (キーが変わるだけ)。
- **入口は 1 か所** (「お気に入り > 編集」の表)。一覧の表示メニューに入/切を置く案 (§1.787 の案 a) は、
  「今いる場所のお気に入りがどれか」「場所を持たない一覧でどれを変えるか」の組み合わせを生むので採らない。
- まれな失敗 (設定の保存失敗など) は既定の割り切り (ログ + 通知。既存の `settings.save()` の扱いのまま)。

## 3. データと永続化

- `FavoriteEntry` に `cover_auto_crop: FavoriteCoverAutoCrop` を足す。値は 3 つ:
  `FollowGlobal` (既定、全体の設定どおり) / `On` (切り出す) / `Off` (切り出さない)。§9 Q1 で 2 値に減らす案も示す。
- settings.db: `favorites` 表に `cover_auto_crop INTEGER NOT NULL DEFAULT 0` (0=全体どおり, 1=切る, 2=切らない) を
  `migrate_favorites_table` で足す。**リリース済みのストアなので移行が要る**。既存の行は 0 になり、今の挙動のまま。
  未知の数値は 0 として読む。`write_favorites` / `read_favorites` / `favorite_entries_equal` / テスト用の CREATE TABLE の写しを揃える。
- JSON (手書きの serde): 項目が無ければ `FollowGlobal`。Serialize の項目数を更新する。
- 旧版は新しい版で保存した settings.db を `reject_newer_app_version` で開かないので、下位互換の追加対応は要らない。
- 設定の書き出し・読み込みはお気に入りを運ばないので、この値も運ばない (全体の 3 設定は今どおり運ぶ)。
- お気に入りのパスを書き換える経路 (画像フォルダの ZIP 化で登録先を差し替えるなど) は、値を引き継ぐ。
  `FavoriteEntry` の構造体リテラルをすべて直す (`Default` derive が無い)。

## 4. 解決の規則

- 入力: アイテムの**論理的な場所** (利用者が見ている元のファイル・フォルダ)。
  - 本のタイル (ZIP / PDF / 変換アーカイブ / 画像フォルダの本): その本のパス。変換アーカイブは変換キャッシュの ZIP ではなく元の書庫。
  - ZIP 内一覧の ZipDir: 外側の ZIP のパス (ZIP 内一覧は一覧全体が同じ答えになるので、一覧ごとに 1 回求めてよい)。
  - フォルダの自動代表 (`folderthumb:auto-v3`): そのフォルダのパス。
- 規則: 場所を含むお気に入りのうち、**`FollowGlobal` 以外の値を持つ最も深いもの**の値を使う。無ければ全体設定。
  補正の標準設定の解決と同じ形 (値の無いお気に入りは素通し)。パスの比較は既存の `search_index_db::is_under`
  (小文字化・区切りの統一・区切り境界での一致) と同じ規則にする。
- 結果の識別子: `On` → `Some(AutoCropIdentity { binding: 全体, folders: 全体 })`、`Off` → `None`、
  全体どおり → 今の `configured_thumbnail_auto_crop`。ドライブ一覧は今どおり常に `None`。
- 所有者: 純粋な値 `CoverAutoCropScope` を `Settings` から作る関数 1 つと、
  `scope.identity_for(path) -> Option<AutoCropIdentity>` を 1 つ置く。scope の中身は
  「全体の入/切」「綴じ方向と画像フォルダの本の設定から作る識別子 (全体 OFF でも保持する。`On` のお気に入りが使う)」
  「値を持つお気に入りの正規化済みルートと値の一覧」。比較 (`PartialEq`) は実効の意味で行い、全体 OFF かつ `On` の
  お気に入りが無いときは識別子を比較に含めない (使われない綴じ方向の変更で読み直さない)。
  環境設定の差分判定 (`cover_auto_crop_changed`、今は `Option<AutoCropIdentity>` 同士の比較) もこの scope の比較に置き換える。
  これで「全体 OFF・お気に入り `On` のまま綴じ方向を変える」と読み直す (レビュー指摘 2)。
  App の中に派生状態として**保持しない** (保持すると更新漏れの経路が増える)。呼び出し側は関数の入口で 1 回作り、
  アイテムごとに `identity_for` を呼ぶ。値を持つお気に入りが 1 つも無いとき (既定の状態) は、パスを見ずに全体の値を返す。
  Send + Clone にして worker (★一覧 prepare・コレクション prepare) へ写しを渡す。
- 費用: 要求の経路は毎フレーム見える範囲のアイテムを回るので、値を持つお気に入りがあるときだけ、アイテムのパスを
  1 回正規化して数件 (上限 100) のルートと比べる。I/O は無い。**scope はアイテムごとの関数の中で作らず、
  一括処理 (要求の 1 回の走査・存続集合の 1 回の構築・色フィルタの全件の候補作り) の外側で 1 回作って借用で渡す**
  (色フィルタは一覧の全件を回るため。レビュー指摘 4)。App に派生のキャッシュは持たない。
  毎フレームの割り当てが目立つなら、正規化済みの文字列を借用で比べる形 (`similar_db::key_is_under_any` と同型) にする。

## 5. 置き換える箇所

`configured_thumbnail_auto_crop` / `thumbnail_auto_crop_identity` を直接呼ぶ所を、アイテム (または本) の場所を渡す
解決に置き換える。全体の値を見てよいのは `CoverAutoCropScope` を作る関数と、環境設定の差分判定だけにする。

- サムネイルの要求 4 か所 (priority / 可視と先読み / idle upgrade / 自動アスペクトの cache probe)。
- 存続集合 7 か所。**要求と同じアイテムごとの識別子にしないと、物理フォルダの読み込みの `delete_missing` が
  もう片方の行を消して作り直しが繰り返される**ので、要求と存続集合は同じ関数で求める。
- 色フィルタ 2 か所 (palette のキーと色の走査の要求)。
- `BookCoverEnv`: 一覧単位の `auto_cover_crop` をやめ、本のパスで解決する (範囲画面・AI 説明文・メタデータ欄)。
- ★一覧 prepare worker: 設定の写し (`thumbnail_source_discovery_snapshot`) はお気に入りを含まないので、
  `CoverAutoCropScope` の写しを options に入れる。
- コレクション一覧: digest と再利用キーに、一覧単位の識別子ではなく `CoverAutoCropScope` を入れる
  (値を変えたら再利用しない)。
- `cover_rotation_cache` の `CoverCacheInputs::grid` は ON/OFF を見ずに常に識別子を作る無効化の手がかりなので変えない
  (実装時に確認し、変える必要があれば設計担当へ返す)。
- 変換アーカイブ・直接読む RAR・ZipDir は、**お気に入りの解決には論理パス (元の書庫)** を、キーの `v4r` 判定には
  今どおり実際に読む書庫を使う。staged の準備で `current_folder` がまだ公開されていない経路は、既存の
  `logical_pin_source` (app.rs `prepare_zip_grid_with_nav` 付近) を論理パスとして使う。
- **フォルダの自動代表 (K2、レビュー指摘 1)**: worker の代表選び (`resolve_folder_thumb_image_inner`) は、今は
  文脈の識別子 1 つで子の本の行のキーを作り、行が無ければその候補を飛ばす。親と子で値が違う入れ子のお気に入りでは、
  子の本自身が書いた行 (子の場所の識別子のキー) と親が探すキーが食い違い、代表が出なくなる。そこで:
  1. 代表選びの文脈に識別子ではなく `CoverAutoCropScope` の写しを持たせ、**子の本の行は子の場所で解決した識別子のキーで読む**
     (cover-crop-plan §5.1 K3 の「子の writer と同じ key」に合わせる)。
  2. 親のフォルダ行のキーは、今どおり親の場所の識別子の印 (`|autocrop:…`、`v4f` を含む) を付けたうえで、
     **親のフォルダより下に値を持つお気に入りがあるときだけ**、その一覧 (親からの相対の正規化パスと値を並べたもの) の
     短いハッシュを 1 つの印として足す (例 `|favcrop:{16桁hex}`。親の識別子が無いときも付ける)。
     入れ子が無い通常の場合はキーが今と同じなので、更新後に作り直しは起きない。入れ子のお気に入りの値を変えると
     親のキーが変わり、親の代表は選び直される (選定証明は変えない)。
  3. 印の付け外しは cover-crop-plan §5.2 と同じく、キーを作る 1 つの関数 (`representative_cache_key_for_policy_with_auto…`) だけが
     行い、存続集合も同じ関数で作る。印の正確な位置と冪等性 (付け直しで二重にならない) をテストで固定する。

## 6. 切り替えたときの扱い

- 「お気に入り > 編集」の表に列「表紙の自動切り出し」を足し、行ごとにコンボ (全体の設定どおり / 切り出す / 切り出さない) を置く。
  ヒントに「綴じ方向などは環境設定の値を使います」と書く。
- 値を変えたフレームで、他の列と同じく `settings.save()` する。続けて、**お気に入りの変更前後で
  `CoverAutoCropScope` が変わったら**、環境設定の全体の切り替えと同じ `apply_file_type_visibility_change` を呼ぶ。
  削除・並べ替え・パスの書き換えも同じ比較で拾う (削除で値を持つお気に入りが消えれば読み直す)。
  お気に入りを書き換えるほかの経路 (レビューで照合済み):
  - 追加ダイアログ・MCP の追加 (`commit_favorite_add`): `FollowGlobal` で足すので解決は変わらない。
  - MCP の索引フラグの更新 (`commit_favorite_index_flags`): 影響しない。
  - 画像フォルダの ZIP 化: 元のお気に入りを残し、ZIP のパスのお気に入りを**複製**する (image_folder_zip_operation.rs)。
    値は複製元から引き継ぐので scope は変わる。ZIP 化の終わりにある既存の一覧の更新で足りるかを実装で確かめ、
    足りなければ同じ比較で読み直す (二重の読み直しはしない)。
  - 起動時の読み込み・sanitize、環境設定の OK (お気に入りは実行中の値を引き継ぐ): 読み直しの対象外 (起動時は一覧がまだ無い)。
- **保持中の一覧 (レビュー指摘 3)**: 別の viewer context に保持された一覧は、読み込み済みのサムネイルを持ったまま
  要求を出さないので、要求の時点の解決だけでは古い表示が残る (全体設定の切り替えにも同じ制限が今ある)。
  読み込み済みのサムネイル (`ThumbnailState::Loaded`) に**要求で実際に使った識別子** (無ければ `None`) を記録し、
  保持した一覧が再び表示される境界の既存の照合 (`reconcile_restored_cover_thumbnails`、cover_rotation.rs。回転の
  変更と同じ述語・同じ再読込の経路) に「今の scope で求めた識別子と違う」を 1 つの条件として足す。違うものだけ読み直す。
  全体設定の切り替えも同じ条件で拾えるようになる。viewport・HWND・detached の述語は変えない。復元境界の照合に
  条件を足すので、触れた範囲と理由を [detached-rework-plan.md](detached-rework-plan.md) に記録する
  (CLAUDE.md「Detached viewer リワーク中のルール」。症状パッチではなく、記録した識別子と現在の解決を比べる構造的な照合)。
- 作り済みのサムネイルは消さない。`Off` にすると印なしのキーの行 (存続集合に常に残っている) がそのまま使われる。
  `On` に戻すと自動の識別子付きの行が要る (物理フォルダの読み込みで消えていれば作り直す)。全体設定を切り替えたときと同じ。

## 7. 波及

- mIV Remote・MCP・AI 説明文の一括作成: 自動切り出しを使わないので変更なし。Remote が読むお気に入りの等価判定
  (`favorite_entries_equal`) は新しい項目を含める。
- 設定の書き出し・読み込み: お気に入りを運ばないので変更なし (§3)。
- 公開文書: マニュアルの「お気に入りの編集」と「表紙の自動切り出し」の説明に、お気に入りごとに切り替えられること、
  綴じ方向などは全体の設定を使うこと、同じ本はどの一覧に出ても同じ設定になることを書く。環境設定の自動切り出しの
  欄のヒントにも「お気に入りごとに変えられる」と一言足す。製品ページのカードは変えない。
- 設計書: cover-crop-plan.md に本書への節を足す。display-pipeline.md の表紙の切り出しの記述に 1 行足す。

## 8. テスト

- 解決: 入れ子 (値を持つ最も深いものが勝つ、全体どおりは素通し)、大文字小文字・区切りの違い、名前が前方一致するだけの
  兄弟は含まない、値を持つお気に入りが無いときは全体の値、`On` と全体 OFF、ドライブ一覧は常に `None`。
- 永続化: 旧い `favorites` 表からの移行で 0 になる、往復、未知の数値は全体どおり、JSON の項目なし・往復。
- **通しのテスト (編集 → 保存 → 効果)**: 全体 ON の状態で、ダイアログのコンボを「切り出さない」にする操作を
  egui のハーネスで流し、(1) `settings.favorites` の値が変わる、(2) settings.db から読み直しても値が残る、
  (3) 読み直しが走り、そのお気に入りの下の本の要求に `|autocrop:` が付かず、外の本には付く、までを 1 本で確かめる
  (§1.471 の「OK で値が捨てられる」型の漏れを防ぐ)。
- 存続集合: 値を持つお気に入りの下と外の本が混ざる物理フォルダで、`delete_missing` が要求と同じキーを残す
  (作り直しが繰り返されない)。
- 場所を持たない一覧: 閲覧履歴・★一覧・コレクションに出た本が、その本の場所のお気に入りの値で要求される。
  コレクションの再利用キーが値の変更で変わる。
- 変換アーカイブ・ZIP 内一覧の ZipDir が論理パスで解決される。通常 ZIP・直接読む RAR・変換 ZIP の、固定あり/なしで
  要求のキーと存続集合のキーが一致する。
- 全体 OFF・お気に入り `On`: 識別子が作られ、綴じ方向・画像フォルダの本の設定を変えると scope の比較が変わって読み直す。
  全体 OFF で `On` が無いときは綴じ方向の変更で読み直さない。
- K2: 親 ON・子のお気に入り OFF とその逆で、子の本の行を子のキーで読み、親の代表が出る。入れ子の値を変えると親のキーの
  `|favcrop:` が変わる。入れ子が無いときは親のキーが今と同じ。印の付け直しが冪等。物理フォルダの読み込みの
  `delete_missing` まで通す。
- 保持中の一覧: 一覧を別の context に保持したまま値を変え、復元したときに識別子の違うサムネイルだけ読み直される
  (同じものは読み直さない)。全体設定の切り替えでも同じ。
- 通しのテストは、変更前に対象の本を `Loaded` にしておき、実際のイベント処理の後で古い表示が再利用されず、
  新しい要求がキューに入ることまで確かめる。
- 編集ダイアログの小画面 (1093×614) の検査と、既存のスナップショット (`favorites_*_snapshot_dark`) の更新
  (列が増える意図的な見た目の変更)。

## 9. 利用者に確かめること (推奨を先に)

1. 値の種類: **3 値 (全体の設定どおり[既定] / 切り出す / 切り出さない)** を推奨。全体 OFF のまま漫画のお気に入りだけ
   切る使い方もできる。2 値 (「このお気に入りでは切り出さない」だけ) にすると組み合わせは減るが、その使い方ができない。
2. 入れ子のお気に入り: **値を持つ最も深いお気に入りが決め、「全体の設定どおり」は素通し**を推奨 (補正の標準設定と同じ規則)。
3. 決め方: **アイテムの場所で決める** (検索結果・履歴・★一覧・コレクションに出ても、その本の場所のお気に入りの値)。
   一覧の場所で決める案は採らない (§2)。
4. 入口: **「お気に入り > 編集」の表の列だけ**を推奨。一覧の表示メニューやお気に入りの追加ダイアログには置かない。
5. 値を変えたときの読み直し: 環境設定で全体を切り替えたときと同じく、表示中の一覧を読み直す
   (検索結果・タグ表示は閉じて元の場所に戻る)。これを推奨 (専用の読み直しを作らない)。

## 10. 範囲外

- 綴じ方向・画像フォルダの本のお気に入りごとの切り替え。
- 一覧・フルスクリーンからのその場の切り替え。
- 手動の範囲指定 (お気に入りの値に関係なく今どおり効く)。
- mIV Remote での自動切り出し。
