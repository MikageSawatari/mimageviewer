# 補正スコープ再設計 — 標準設定の分離モデル

対象バージョン: v2.9.0 想定
状態: **実装済み**（§9 の 1〜6 を実施。実装との差分は §4.2 / §4.3 / §4.4 / §10 に反映済み）

## 1. 何を変えるか（要約）

補正の解決を **2 段**にする。

```
この画像の個別設定  >  その場所の標準設定
```

「場所」は 2 種類しかない。

- **標準（共通）** — 既定の場所
- **標準（お気に入り「xxx」）** — そのお気に入りが「お気に入り用標準設定を使う」を
  **ON** にしているときだけ生まれる

お気に入りごとに `□ お気に入り用標準設定を使う` を持ち、**既定は OFF**。
OFF のお気に入りは場所を作らず、配下も「標準（共通）」を見る（＝現行と同じ）。

ユーザーへの見せ方は「お気に入りが独自の設定を持つ」ではなく、
**「標準設定が場所ごとに分かれている」**とする。

```
標準（共通）
標準（お気に入り「scan」）
```

### 1.1 データモデルは現状のまま

| 対象 | 変更 |
| --- | --- |
| `settings.global_preset` | **変更なし**（＝「標準（共通）」の実体） |
| `adjustment.db` の `favorite_params` | **変更なし**（＝「標準（お気に入り「xxx」）」の実体） |
| `page_params` / サイドカーのページ個別 | **変更なし** |
| `settings.preset_slots` | **変更なし**。従来どおり値のコピー元であり、参照ではない |

**`ON / OFF` は `favorite_params` に行があるかどうかそのもの**。
チェックボックスは「行を作る / 消す」の UI でしかないので、新しい永続データは要らない。

⚠️ この対応が成り立つ前提として、**無補正の内容を持つ `favorite_params` の行を
「無駄だから」と間引いてはならない**。行の存在自体が ON を意味するため、
間引くと ON が黙って OFF に変わる。現在このような掃除は無い
（`prune_favorite_params` は削除済みお気に入りの orphan 行だけを消す）。
`adjustment_db` と `apply_favorite_change` にこの旨のコメントを置き、
「無補正の行が生き残る」ことを固定する回帰テストを入れる。

明示的な `bool` を `FavoriteEntry` へ足す案もあるが、①永続フィールド追加で移行が要る
②フラグと行の有無が食い違う状態（ON なのに行が無い等）の整合ルールが要る、
という 2 つのコストが増えるため採らない。

## 2. なぜこの形か

| 解けること | 内容 |
| --- | --- |
| キー挙動の内外差が消える | `Ctrl+Alt+数字` は「この場所の標準へ複製」。OFF のお気に入りの中では対象が「共通」なので、内外で意味が変わらない |
| 「効いていない層」が消える | 場所は常に 1 つしか無い。値があるのに隠れている層が存在しない |
| ラジオが 2 行で済む | 「その場所の標準 / この画像」だけ |
| お気に入りを作っても挙動が変わらない | 既定 OFF なので、登録しただけでは何も起きない |
| 移行が要らない | ON/OFF は既存データの形から導出できる（§6） |
| トリムと同型になる | 表示トリムの「本全体 / このページ」とそのまま同じ構造 |
| 新しい概念を増やさない | スロット参照・画像ごとのピン・フォルダスコープをいずれも導入しない |

### 2.1 引き受けるコスト

- **スロットを後から調整しても、複製済みの場所は追従しない**。再度 `Ctrl+Alt+数字` を押す
- ただし「場所」の数は ON にしたお気に入りの数（実測 2 件）であって、
  ページ単位（実測 1085 件）ではない。再適用の負担もデータ量も小さい

## 3. 解決規則

```
effective_params(idx) =
    page_params[idx]              // この画像の個別設定があればそれ
 ?? nearest_on_favorite_params(idx)  // 最近祖先の「ON のお気に入り」の標準
 ?? global_preset                 // 標準（共通）
```

現行との差は 1 点だけ。**「最も近いお気に入り」ではなく「最も近い ON のお気に入り」を探す**。

現行は、内側のお気に入りが独自標準を持たない場合、外側のお気に入りが標準を持っていても
無視して `global_preset` に落ちていた。新モデルでは OFF のお気に入りは透過するので、
外側の ON が効く。§7 に非互換として記載する。

## 4. UI

### 4.1 ラジオ（2 行）

```
ON のお気に入り配下:                 それ以外:
◉ 標準（お気に入り「scan」）          ◉ 標準（共通）
◯ このページ                        ◯ このページ
```

- 上段の名前は書き込む対象によって変わる。「今いる場所」ではなく「どの標準か」を指すので、
  OFF のお気に入りの中にいるときも「標準（共通）」で嘘にならない
- 下段は表示トリムと語彙を揃えて「このページ」にする（§4.4）
- お気に入り名は `ui_helpers::truncate_name` で切り詰める。桁数はパネル幅 258px で
  実測して決める（§10）
- 初期選択は、その画像に個別設定があれば「この画像」、無ければ上段
- **個別設定があるページで上段を選ぶと、その場でこのページの個別設定を解除する**。
  残したまま標準を編集すると個別設定が優先されて表示が動かず、§2 が消したかった
  「効いていない層」が再発するため。`Ctrl+Alt+数字` と同じ挙動で、`Ctrl+Z` で戻せる
- 実装上は「個別設定がある ⟹ 選択は『このページ』」を不変条件として張る。
  `Ctrl+数字` や Undo で後から個別設定が生まれたときもラジオが自動的に追従する
- 選んだスコープがスライダー編集と `Ctrl+Alt+数字` の書き込み先になる
- トーストも同じ名前で出す（「標準（お気に入り「scan」）を更新」）

### 4.2 お気に入りごとのチェックボックス

**補正パネルのラジオ上段の真下に置く**（お気に入り配下でのみ表示）。
お気に入り編集ダイアログ（[favorites_editor.rs](../src/ui_dialogs/favorites_editor.rs)）にも
同じものを置くが、正本はパネル側。

```
お気に入り配下・OFF:                    お気に入り配下・ON:
◉ 標準（共通）                          ◉ 標準（お気に入り「scan」）
   □ このお気に入り用に標準を分ける          ☑ このお気に入り用に標準を分ける
◯ このページ                            ◯ このページ
```

上段の真下にあることで「なぜ今『共通』なのか」「チェックすればこのお気に入り用になる」が
一目で分かる。**ON と OFF を同じ場所で切り替えられることが要件**
（片方だけ別画面にすると「押したら戻せない」と受け取られる）。

| 操作 | 動作 |
| --- | --- |
| OFF → ON | その時点で**そのページに効いている標準**の内容を種にして `favorite_params` の行を作る。**見た目は変わらない** |
| ON → OFF | 行を削除する。確認は**条件付き**（下記） |

> 種を「標準（共通）」ではなく `effective_default_for_idx` にしているのは、入れ子で
> 外側のお気に入りが ON のときに共通を種にすると見た目が変わってしまうため。
> 非入れ子では両者は一致するので、本節の意図（見た目は変わらない）と矛盾しない。
> お気に入り編集ダイアログ側は「現在のページ」を持たないので共通の標準を種にする。

OFF にするときの確認は、失うものがある場合だけ出す。

- 内容が「標準（共通）」と**同一**（＝ ON にした直後など）→ 失うものが無いので**無確認**
- 内容が**異なる** → 「このお気に入りの標準設定が削除されます」と確認

どちらも `set_favorite_default` / `clear_favorite_default` を通すので `Ctrl+Z` で戻せる
（`capture_adjust_full` がお気に入りの差分を記録している）。

OFF のお気に入り配下で `Ctrl+Alt+数字` を押した場合は「標準（共通）」へ書く
（＝ OFF の意味どおり）。トーストに「標準（共通）を更新」と出るので、
どちらを書き換えたかはその場で分かる。

### 4.3 ボタン

選択中スコープに応じて入れ替わる。実装後の最終ラベルは次のとおり。

```
[ 共通の標準からコピー ]              ← 書き込み先がお気に入り標準のときだけ表示
[ 現在の設定値を標準に反映 ]          ← 「このページ」選択時だけ表示
[ このフォルダの全画像を標準に揃える ]     ／ [ フォルダ全画像をこのページに揃える ]
（標準側はボタンなし）                   ／ [ 個別設定を解除 [Q] ]
```

最後の行は標準側に空行やダミーを置かないため、実際の UI ではスライダー以降の上下位置が
スコープによってずれる。この差はユーザー了承済み。

- **共通の標準からコピー**: 「標準（共通）」の内容をこの場所の標準へ複製。
  お気に入りツリーを移ったときに共通の見た目を持ち込む導線。書き込み先が
  お気に入り標準のときだけ表示する（共通のときは自分自身へのコピーになるため）
- **現在の設定値を標準に反映**: 今のページに効いている実効値を、その場所の標準として
  保存する。書き込み後はそのページの個別設定が `prune_page_params_matching_default` で
  自動的に畳まれるので**見た目は変わらず**、ラジオは「標準」へ移る。
  初版の設計では §4.3 を 3 ボタンにして旧「標準にする」を落としていたが、
  「1 枚作り込んでから標準へ上げる」導線がスロット経由の 2 手順になってしまうため、
  ユーザー判断で復活させた（2026-07-28）
- **一括**: 選択スコープに従う

  | 選択中 | 実行内容 |
  | --- | --- |
  | その場所の標準 | 一覧の全画像から個別設定を削除 → 全画像が場所の標準に従う |
  | このページ | 現在の実効値を全画像へ個別設定として複製（現行の「全画像の個別設定に適用」） |

  ラベルにはお気に入り名を入れない（258px に収まらない）。正確な対象は tooltip に置く。
  「このページ」側は 258px 実測で溢れたため
  `フォルダ全画像をこのページに揃える` へ短縮した

- **個別設定を解除 [Q]**: 「このページ」選択時に出る。個別設定が無ければ disabled
- **すべてリセット**: スライダー下の共通ボタン。選択中スコープ（その場所の標準／
  このページ）の全補正値へ `AdjustParams::default()` を書く。標準は常に存在するため
  「解除」とは呼ばない。「このページ」では個別設定を標準へ戻す操作ではなく、
  無補正の個別値を設定する操作であり、上の「個別設定を解除」と結果が異なり得る
- **保存スロットのクリック（読み込み）**: **選択中スコープに従う**（2026-08-08 追記）。
  「このページ」なら現在ページの個別設定へ、「その場所の標準」ならその場所の標準へ
  複製してページ個別を解除する（= `Ctrl+Alt+数字` と同じ書き込み）。
  §5 のキーボードをスコープ非連動で固定したのは、読みながら `Ctrl+1` / `Ctrl+2` を
  打ち分ける速さを守るためであって、**ラジオが目の前に出ているパネル側まで
  固定する理由はない**。加えて、これがキーボードの無い環境（タブレット）から
  標準へ読み込む唯一の導線になる

### 4.4 表示トリムとの統一

**適用範囲も補正パネルと同じ導出規則にする。** 手動設定ではページ個別行があれば
「このページ」、無ければ「本全体」とし、セレクタの選択状態自体は保存しない。

当初は「トリムの挙動は変えず、語彙と構造だけ揃える」としていた。しかし実機確認で、
ページ個別値を作ったページへ戻っても「このページ」を再選択しない限り値が効かないことが
判明した。**これは仕様ではなく、表示トリム実装時の見落とし (バグ) と判断した**
(2026-07-28、ユーザー判断)。自動で全体設定へ戻ってしまうなら、ページごとに個別設定を
持つ意味が無いため。旧バージョンから同じ挙動だったが、更新履歴にも仕様変更ではなく
バグ修正として載せる。保存済み個別値は一時的な編集値ではなく、そのページを表示するたびに
優先される永続設定として扱う。

初版は「トリムのチェックボックスを補正と同じ 2 行ラジオにする」としていたが、
実装時のレビューで **モード（何をするか）と適用範囲（どこへ保存するか）という別の軸を
1 つのラジオ列に混ぜていること自体**が分かりにくさの原因だと判明したため、
次の形へ変更した（2026-07-28、ユーザー決定）。

```
◯ トリムなし
◯ 自動余白カット（本全体）
◉ 手動設定
     適用範囲：［本全体］［このページ］
     [余白スライダー …]
```

| 項目 | 対応 |
| --- | --- |
| モード | `トリムなし` / `自動余白カット（本全体）` / `手動設定` の 3 択 |
| 適用範囲 | `手動設定` のときだけ、スライダーの直上に `［本全体］［このページ］` を出す |
| 選択状態 | 編集対象に enabled なページ個別行があれば `このページ`。見開きは左右どちらかにあれば `このページ` |
| `このページ` を選ぶ | 保存済み値 → 自動検出 seed → 本全体値の優先順位でページ個別行を作る |
| `本全体` を選ぶ | 編集対象ページの個別行を DB から削除し、本全体設定へ戻す |
| `（本全体）` | 自動余白カットのモード自体が本単位で保存されることを示す。余白量はページごとに自動検出するので、その旨は tooltip に置く |
| 下段の語 | 補正パネルの「この画像」を「**このページ**」へ寄せた。ZIP 画像・PDF ページも含む語なので包括的 |
| 「個別設定」 | 既に両方で使っているのでそのまま |

旧 UI では `本全体の設定を適用` のラジオとスライダーの間に別のコントロール
（このページの個別設定を適用チェックボックス）が挟まり、続くスライダーの
書き込み先が読み取れなかった。適用範囲セレクタをスライダーの直上へ置くことで解消する。

本側へ保存する基本モード (`ViewTrimApplyMode`) は変更しないが、表示時の実効モードは
`idx` ごとに解決する。

| UI / 表示状態 | `base_apply_mode` | `idx` の enabled 個別行 | 実効モード |
| --- | --- | --- | --- |
| トリムなし | `None` | 参照しない | `None` |
| 自動余白カット（本全体） | `Auto` | 参照しない | `Auto` |
| 手動設定 + 本全体 | `Book` | なし | `Book` |
| 手動設定 + このページ | `Book` | あり | `Page` |

見開きと連結読みでも各 `idx` を独立して解決するため、個別設定のあるページと無いページが
同時に表示されても、それぞれ Page / Book になる。旧一時状態
`view_trim_page_apply_root_idx` は適用判定から廃止し、enabled なページ個別行を唯一の正本にする。

対象は [ui_view_trim.rs](../src/ui_view_trim.rs) の 700 行付近。

## 5. キーボード

内外で意味が変わらない。

| キー | 意味 | 変更 |
| --- | --- | --- |
| `Ctrl+1`〜`9` / `Ctrl+0`（フルスクリーン） | スロットを**この画像**へ複製 | 据え置き |
| `Ctrl+1`〜`9` / `Ctrl+0`（グリッド） | チェック済み（なければ選択 1 件）へ複製 | 据え置き |
| `Ctrl+Alt+1`〜`0` | スロットを**この場所の標準**へ複製し、この画像の個別設定を解除 | 書き込み先の決め方を統一（v2.8.0 は「お気に入りがあれば必ずお気に入り」だった） |
| `Ctrl+Alt+-` | **共通の標準をこのお気に入りへ複製**。共通の標準を選んでいるときは no-op + トースト | **新規**。スロット 10 の右隣 |
| `Q` / `Ctrl+Backspace` | ページ個別の解除 | 据え置き |

`Ctrl+数字` をページ固定にするのは、1 冊の中でカラーページ = スロット 1、
モノクロ = スロット 2 と打ち分ける用途を守るため。ここをスコープ連動にすると、
ラジオの状態で行き先が変わり、読みながらの高速適用ができなくなる。

## 6. 移行

**不要**。`ON / OFF` は `favorite_params` に行があるかどうかで決まるため、
既存データがそのまま新モデルの状態になる。

| 現状 | 新モデルでの状態 |
| --- | --- |
| `favorite_params` に行があるお気に入り（実測 2 件） | ON。従来どおりその値が効く |
| 行が無いお気に入り（実測 22 件） | OFF。従来どおり共通の標準が効く |

値のコピーも、標準が無補正かどうかの判定も要らない。
v2.8.0 へ戻しても同じデータを同じ意味で読む（§7 の入れ子の例外を除く）。

### 6.1 実測（開発機、2026-07-28）

| 項目 | 値 |
| --- | --- |
| お気に入り | 24 件 |
| `favorite_params` に行があるお気に入り | 2 件 |
| `global_preset` | 無補正 |
| 使用中スロット | 4 / 10 |
| ページ個別設定 | 1085 件 |

## 7. 副作用と非互換

| 項目 | 内容 |
| --- | --- |
| 入れ子のお気に入りの解決 | 内側が OFF・外側が ON のとき、**外側の標準が効く**（現行は共通の標準に落ちていた）。該当する構成は稀だが更新履歴に書く |
| 標準フォールバックの廃止 | ON のお気に入り配下では共通の標準に落ちない。OFF なら従来どおり |
| v2.8.0 へのロールバック | データ形式が同じなので動く。入れ子の例外だけ解決が変わる |
| メタ情報のインポート・エクスポート | **影響なし**（`FORMAT_VERSION` 据え置き） |
| グリッドの「補」バッジ | **影響なし** |
| Undo / キャッシュ無効化 | 既存経路のまま。新しい層が無い |
| お気に入りの削除 | 配下は共通の標準に戻る。orphan 掃除は現行どおり |

## 8. 見送るもの

| 用途 | 判断 |
| --- | --- |
| スロット参照（調整の追従・データ量） | 場所の数が少ないので複製で足りる。概念を増やさない方を採る |
| 画像ごとの参照ピン | 1 枚ずつ判断する操作が実運用に無い |
| フォルダスコープ | 階層化されたお気に入りの末端から全体に届かなくなる |
| お気に入り配下から共通の標準を直接編集 | 用途が薄く混乱のもと。「共通の標準からコピー」で足りる |
| お気に入り配下の一部フォルダだけ別設定 | 個別複製のまま。現状から悪化しない |
| すべてのお気に入りに一括適用 | 必要になったら足す。初版には入れない |
| スロット枠の可変長化 | 保存形式とパネル UI の作り替えになる。将来まとめて |

## 9. 実装順序

1. 解決規則を「最近祖先の ON のお気に入り」へ変更（§3）+ 既存データでの回帰テスト
   （ON/OFF の導出、入れ子の新旧差、お気に入り外）
2. パネル: 2 行ラジオ、上段の動的ラベル、編集先の振り分け
3. チェックボックス（§4.2）をパネルとお気に入り編集ダイアログの両方に。ON 時の種入れ、OFF 時の条件付き確認
4. ボタン整理（§4.3）と、表示トリムの見た目・語彙の統一（§4.4）
5. キー: `Ctrl+Alt+数字` の書き込み先を「この場所の標準」に統一、`Ctrl+Alt+-` 追加
   （`KeyAction` / `ini_name` / `context` / `default_chords` / `ALL_ACTIONS` /
   `docs/keymap.ini.default`）
6. ドキュメント: [preset-and-adjustment.md](preset-and-adjustment.md) §1・§4、
   [keymap-spec.md](keymap-spec.md)、マニュアル `adjustment.html`、
   README 更新履歴（標準設定の分離・入れ子の解決変更）
