## 1. 何を作るか

一覧で選んだ画像 (1 枚以上) を、配置・隙間・角丸・枠線・画像ごとのラベルを選んで 1 枚の画像に結合し、
ファイルへ書き出す。書き出した画像の構成 (元の画像・並び・ラベル・設定) を mIV が覚えておき、
後から「結合をやり直す」で読み込み直して、直して書き直せる。

## 2. 範囲

### 2.1 最初の版に入れるもの

他ソフトの分析で「ほぼ全製品にある」もの (横一列・縦一列・隙間と色・並べ替え・形式) はすべて入れ、
「差が出る」もののうち静止画の結合に当たるもの (グリッド・揃え位置・透明の背景・角丸・枠線・
ライブプレビュー・プリセット・番号/説明) も入れる。

調べた製品に無く、mIV の差になる点: 右から左の並び (右綴じの見開き)、行ごとに詰める並べ方、
全体の比率に合わせた最小の切り取り、画像ごとの説明のラベル、保存済み編集 (補正・消しゴム・切り取り等) の
反映、ZIP・PDF の中のページの結合、構成を覚えての書き直し、元の情報 (EXIF 等) を残さないことの明記。

### 2.2 入れないもの

| もの | 理由 |
| --- | --- |
| 影 | 利用者の判断 |
| クリップボードへのコピー | 利用者の判断 (ファイルから既存の方法でコピーできる) |
| 自由な位置の文字・全体のタイトル・透かし | 結合の後に注釈ツール・一括エクスポートで入れる |
| テンプレート (1 枚大 + 小など)・自由配置 | コラージュ専用の編集画面になり規模が大きい。詰める並べ方で多くを代えられる |
| スクリーンショットの重なりの自動検出・長尺の分割書き出し | 写真・イラストの結合とは別系統 |
| 顔に合わせた切り取り | 顔検出が無い。9 か所の基準点と、事前の切り取り編集で代える |
| 引き伸ばし (縦横比を変える) | 絵が歪む |
| 元の情報 (EXIF・AI プロンプト・ICC) の転記 | どの画像の情報か決まらない。隠した部分が縮小画像に残る問題 (batch-export-plan §3.7) も起きない |
| 動画・音声・フォルダ・本 | 対象外として数える (一括エクスポートと同じ) |

## 5. 選択肢 (`CombineOptions`)

ダイアログの値はすべて 1 つの構造体に入る。書き出しの開始時に clone を 1 回 worker へ渡し、実行中に変えない。
プリセットもこの構造体をそのまま保存する (画像ごとのラベルの文字は入れない、§5.5)。

### 5.1 並べ方

```rust
enum CombineLayout {
    Row,              // 横一列
    Column,           // 縦一列
    Grid,             // グリッド
    JustifiedRows,    // 行ごとに詰める
    JustifiedColumns, // 列ごとに詰める
}
enum CombineDirection { LeftToRight, RightToLeft } // 縦の並びは常に上から下
```

| 並べ方 | 中身 | 関係する欄 |
| --- | --- | --- |
| 横一列 | 左右に並べる | そろえ方 (§5.2) |
| 縦一列 | 上下に並べる (4 コマ・縦長の漫画) | そろえ方 |
| グリッド | 列数 × 必要な行数、行優先で埋める。最後の行の空きセルは背景 | 列数 (自動 / 1〜20)、セルの比率、セルへの入れ方 (§5.2) |
| 行ごとに詰める | 各行の中で高さをそろえ、行の幅を全体の幅に合わせる。縦横比を保ち、切り取らず、空きが出ない (全体の比率を固定したときだけ切り取る、§5.3) | 行の分け方: 自動 / 1 行の枚数を指定 (例 `2-2`・`1-3`) |
| 列ごとに詰める | 上の縦版 (各列の中で幅をそろえ、列の高さを全体の高さに合わせる) | 列の分け方: 自動 / 1 列の枚数を指定 |

- **右から左**: 横の並び (横一列・グリッドの各行・行ごとに詰めるの各行・列ごとに詰めるの列の並び) を右から始める。
  縦一列では欄を押せなくする。
- 1 行の枚数の指定は `-` 区切りの数の並び (各 1〜100)。合計が枚数と違うときは欄の下にエラーを出し、
  「書き出す」を押せなくする (足りない・余る分を自動で補わない)。

### 5.2 大きさのそろえ方

**横一列・縦一列** (`LineSize`):

- **そろえる** (既定): 並べる向きと直交する辺 (横一列なら高さ) を、「いちばん大きい画像」(既定) /
  「いちばん小さい画像」に合わせる。縦横比を保つ。
- **そろえない**: 元の大きさのまま並べ、短い画像を揃え位置 (上・中央・下 / 左・中央・右、既定 中央) に置き、
  空きは背景色。全体の比率の固定は使えない (欄を押せなくする)。

**グリッド**:

- セルの比率: 「先頭の画像に合わせる」(既定) / 1:1 / 4:5 / 3:4 / 4:3 / 2:3 / 3:2 / 9:16 / 16:9。
  全体の比率を固定したときは、セルの比率は全体から決まる (欄は「全体の比率に合わせる」を表示して押せなくする)。
- セルへの入れ方: **収める** (既定。縦横比を保ってセルの内側、空きは背景色) / **埋める** (縦横比を保ってセルを覆い、
  はみ出しを切る)。

**位置の基準点** (`anchor`、9 か所、既定 中央、全画像共通): 収めるときのセル内の位置、埋める・全体の比率の固定で
切るときの残す側。

### 5.3 全体の比率の固定

`canvas_ratio: Option<(u32, u32)>`。「固定しない」(既定) / 1:1 / 4:5 / 3:4 / 4:3 / 2:3 / 3:2 / 16:9 / 9:16 / 指定 (W:H、各 1〜100)。

- 横一列・縦一列 (そろえる)・行ごとに詰める・列ごとに詰める: 配置の太さ (§6.3 の `k`) を全画像共通の倍率で変え、
  各画像を同じ割合で切り取って合わせる。切る基準は §5.2 の基準点。
- グリッド: セルの比率を全体から決める (切り取りはセルへの入れ方による)。
- ダイアログに「切り取り: 最大 N%」(各画像の切り取られる辺の割合の最大) を出す。
- 余白・隙間・帯だけで全体の比率を満たせない (画像の高さが 0 以下になる) ときは、エラーを出し「書き出す」を押せなくする。

### 5.4 隙間・余白・背景・角丸・枠線

| 欄 | 範囲 | 既定 |
| --- | --- | --- |
| 隙間 (横・縦) | 0〜500 px。「縦横を同じにする」(既定 ON) | 0 |
| 外周の余白 | 0〜500 px | 0 |
| 背景 | 色 / 透明 (PNG・WebP のときだけ選べる。JPEG を選ぶと色に戻し、欄の下に理由を出す) | 白 |
| 角丸の半径 | 0〜500 px (カードの短辺の半分で頭打ち) | 0 |
| 枠線 | 太さ 0〜100 px、色 | 0、白 |

- すべて**出力の px**。出力の大きさを変えても指定どおり (§6.1)。
- **カード** = 画像 + (ラベルが帯のとき) その下の帯。角丸と枠線はカードの外形に掛ける。枠線はカードの内側に描き、角丸に沿う。
- 角丸の外側は背景 (透明の背景なら透明)。縁はなめらかにする (§7.2)。

### 5.5 画像ごとのラベル

```rust
struct LabelOptions {
    placement: LabelPlacement,  // None (既定) / Overlay / Band
    number_format: NumberFormat, // Arabic (1,2,3、既定) / ZeroPadded (01,02) / UpperAlpha (A,B,C) / LowerAlpha (a,b,c)
    number_start: u32,          // 0..=999、既定 1 (英字は 1 = A)
    style: BadgeStyle,          // Plain (縁取り文字、既定) / Box (角丸の箱) / Pill (丸いバッジ)
    text_size_px: u32,          // 8..=500、既定 48
    text_color: [u8; 3],        // 既定 白
    outline: bool,              // Plain のとき。既定 true (黒)
    fill_color: [u8; 3],        // Box / Pill の下地。既定 黒
    fill_opacity: u8,           // 0..=100、既定 70
    overlay_anchor: Anchor9,    // 既定 左上
    overlay_margin_px: u32,     // 0..=500、既定 16
    band_color: BandColor,      // Background (背景と同じ、既定) / Color([u8; 3])
    band_align: HAlign,         // Left / Center (既定) / Right
}
// 画像ごと (プリセットには入れない)
struct CombineItemSpec { source: CombineSourceRef, label_override: Option<String> }
```

- **中身**: `label_override` が `Some(s)` ならその文字 (空文字はその画像だけラベルなし)、`None` なら自動の番号。
  番号は**今の並びの位置**から振る (`number_start` + 位置)。英字は 26 を超えたら `AA, AB, ...`。
- **並べ替え**: `label_override` は画像に付いて動く。番号は並びから振り直す。
- **入力**: プレビューで画像を選び、下の欄で文字を入れる (1 行、最大 200 文字)。「番号に戻す」でその画像を `None` へ。
  一括の操作として「ファイル名を入れる」(全画像を拡張子なしのファイル名に。ZIP はエントリ名、PDF は `<PDF 名> p<N>`)、
  「すべて番号に戻す」。
- **重ねる** (`Overlay`): カードの内側の基準点から `overlay_margin_px` (枠線の内側から測る) に置く。
  - Plain: 文字だけ。`outline` で黒の縁取り。
  - Box: 文字の外接矩形に余白 (`text_size × 0.35`) を足した角丸 (半径 `text_size × 0.3`) の下地。
  - Pill: 高さの半分を半径にした丸い下地。短い文字 (番号) は円に近く、長い文字は横長の丸になる。幅の最小は高さ。
- **下の帯** (`Band`): カードの画像の下に帯 (高さ `t`: Plain は `ceil(text_size × 1.6)`、Box・Pill は下地の余白のぶん
  `ceil(text_size × 2.0)`) を足し、帯の中に `band_align` で 1 行書く。
  バッジの種類は帯でも効く (帯の中に Box / Pill を置ける。Plain は帯に直接書く)。帯は全画像で同じ高さで、配置の計算に含める (§6)。
- **はみ出し**: 判定は**装飾を含めたラベルの外接矩形の幅と高さ** (文字の行の高さ + 縁取り + Box / Pill の余白、Pill の最小幅) で行う。
  置ける領域 (重ねるならカードの内側 (枠線の内側) から余白を引いた矩形、帯なら帯の矩形から左右の余白を引いた矩形) に
  幅か高さが収まらないときは、文字の大きさを 60% まで縮める。60% でも高さが収まらない、または幅が収まらず末尾を `…` にしても
  収まらない、または置ける領域が 0 以下なら、そのラベルは描かず、ダイアログに「収まらないラベルがあります (N 件)」を出す
  (書き出しは止めない)。
  この判定は**出力の座標**で 1 回だけ行い (§7.3 のラベルの配置)、プレビューはその結果を縮小して描く。
- **切り抜き**: ラベルはカード形 (角丸) の被覆率で切り抜き、帯のラベルはさらに帯の矩形で切り抜く。角丸の外や
  隣のカードへははみ出さない。
- 文字はすべて 1 行。フォントの選択は作らない (透かしと同じ、注釈の既定フォント)。

### 5.6 出力

```rust
enum OutputSize { Original, Width(u32), Height(u32), LongEdge(u32) } // px は 16..=65500
struct CombineOutput {
    size: OutputSize,           // 既定 Original
    format: CombineFormat,      // Png (既定) / Jpeg { quality } / Webp { quality, lossless }
    destination: Destination,   // FirstImageFolder (既定) / Folder(PathBuf)
    name: String,               // ダイアログで毎回作る (保存しない)。既定 `<先頭の画像の名前>_結合`
}
```

- **大きさ**: `Original` は §6.2 の基準の大きさ。ほかは全体の幅・高さ・長辺を指定 px にする (画像だけが伸び縮みし、
  隙間などは §5.4 のとおり)。拡大は許す (配置の都合で元より大きくなる画像は、元の解像度を超えて拡大される。
  ダイアログに「拡大される画像があります」を出す、§9)。
- **上限**: 全体の画素数 1.5 億 (RGBA で約 600MB)、WebP 各辺 16383、JPEG 各辺 65500。超える設定はダイアログで
  寸法と一緒に知らせ、「書き出す」を押せなくする (縮小か形式の変更を案内)。
- **場所**: 先頭の画像のフォルダ (ZIP・PDF は書庫のあるフォルダ) か指定のフォルダ。
- **名前**: 文字欄 (置換子なし)。拡張子は形式から付ける。同名があれば `_1`〜`_9999` の連番 (上書きしない)。
  やり直しの置き換えだけ例外 (§10.3)。名前は `basename_from_text` で正規化する。
- **形式**: PNG / JPEG / WebP。品質の欄と既定は一括エクスポートと同じ (JPEG 95、WebP 90)。
- **元の情報は書かない** (§2.2)。出力のメタデータは空。

## 6. 配置の計算 (純粋な関数)

`image_combine::layout(options, dims: &[(u32, u32)], label_band: Option<u32>) -> Result<Layout, LayoutError>`。
入力は各画像の合成後の寸法 (§8.1 の下見で決まる) と設定だけ。ファイル・フォントを読まない。
UI (並べ替えの当たり判定・寸法の表示・エラー) と worker (下見の描画・書き出し) が**同じ関数**を呼ぶ。

`Layout` = 全体の寸法 `(W, H)` と、画像ごとの カード矩形・画像矩形・元画像の切り取り矩形 (合成後の画像の座標、
小数) ・帯の矩形。座標は出力の px (小数)。描画のときに丸める (§7.1)。

### 6.1 1 つの変数の 1 次式

どの並べ方も、画像の大きさは 1 つの倍率 `s` に比例し、隙間・余白・枠線・帯は固定の px なので、
全体の幅と高さは `W = a·s + b`、`H = c·s + d` の形になる。出力の大きさの指定 (§5.6) は、この式を `s` について
解くだけで決まる (反復しない)。`Original` は §6.2 の `s₀`。

### 6.2 並べ方ごとの式と基準の大きさ (`Original`)

記号: 行数 `Q`、列数 `C`、画像 `i` の縦横比 `aᵢ = wᵢ / hᵢ`、隙間 `gx, gy`、余白 `m`、帯の高さ `t` (帯が無ければ 0)。
**帯は常に画像の下に付く**ので、縦の並びでは帯が枚数ぶん高さに加わり、横の並びの式の単純な縦横の入れ替えにはならない。

| 並べ方 | 画像の大きさ | 全体 | 基準 `s₀` |
| --- | --- | --- | --- |
| 横一列 (そろえる) | 高さ `s`、幅 `aᵢ·s` | `W = s·Σaᵢ + (n−1)gx + 2m`、`H = s + t + 2m` | いちばん大きい / 小さい画像の高さ |
| 横一列 (そろえない) | 元の大きさ × `s` | `W = s·Σwᵢ + (n−1)gx + 2m`、`H = s·max hᵢ + t + 2m` | `s₀ = 1` |
| 縦一列 (そろえる) | 幅 `s`、高さ `s/aᵢ` | `W = s + 2m`、`H = s·Σ(1/aᵢ) + n·t + (n−1)gy + 2m` | いちばん大きい / 小さい画像の幅 |
| 縦一列 (そろえない) | 元の大きさ × `s` | `W = s·max wᵢ + 2m`、`H = s·Σhᵢ + n·t + (n−1)gy + 2m` | `s₀ = 1` |
| グリッド (c 列 × q 行) | セル幅 `s`、セルの画像部の高さ `s/r` (`r` = セルの比率) | `W = c·s + (c−1)gx + 2m`、`H = q·(s/r + t) + (q−1)gy + 2m` | セルの画像部が中央値の画像を収める (収める) / 覆う (埋める) 大きさ。中央値は面積の中央値の画像 (偶数のときは小さいほう) |
| 行ごとに詰める | 行 `j` (枚数 `nⱼ`) の画像の高さ `hⱼ = (s − (nⱼ−1)gx) / Aⱼ` (`Aⱼ` = 行の `aᵢ` の和、`s` = 内側の幅) | `W = s + 2m`、`H = Σⱼ(hⱼ + t) + (Q−1)gy + 2m` | 行の画像の高さの平均が、画像の高さの中央値に等しくなる `s` |
| 列ごとに詰める | 列 `j` (枚数 `nⱼ`) の画像の幅 `wⱼ = (s − (nⱼ−1)gy − nⱼ·t) / Bⱼ` (`Bⱼ` = 列の `1/aᵢ` の和、`s` = 内側の高さ) | `H = s + 2m`、`W = Σⱼwⱼ + (C−1)gx + 2m` | 列の画像の幅の平均が、画像の幅の中央値に等しくなる `s` |

どれも `s` の 1 次式 (または 1 次式の和) なので、出力の大きさの指定から `s` が閉じた形で決まる。

**検査** (`LayoutError`、ダイアログは理由を出して「書き出す」を押せなくする): 全体の寸法だけでなく、**各画像の矩形が
幅・高さとも 1 px 以上**、各行・列の画像部 (`hⱼ`、`wⱼ`) が正、すべての値が有限であること。例: 正方形 3 枚を `2-1`、
`gx = 500`、`s = 400` にすると 1 行目の `h = −50` で、全体の高さが正でもエラーにする。

- 拡大の扱い: `Original` でも、詰める並べ方や「いちばん大きい画像に合わせる」では、元より拡大される画像があり得る。
  拡大は許し (§5.6)、ダイアログで知らせる。
- 結果の寸法は四捨五入した整数。0 以下・上限超えは `LayoutError`。

### 6.3 全体の比率の固定

比率 `R = W/H` を指定したとき、並べ方の太さの倍率 `k` を全画像共通で、**画像の部分だけ**に掛ける (帯・隙間・余白・
枠線には掛けない)。横の並び (横一列・行ごとに詰める) は幅を §6.2 のまま (`s` で決まる) にして、各行の画像の高さを
`k` 倍し、`H(k) = k·Σⱼhⱼ + (Q−1)gy + Q·t + 2m` を `W / R` に合わせる。縦の並び (縦一列・列ごとに詰める) は高さを
§6.2 のままにして、各列の画像の幅を `k` 倍し、`W(k) = k·Σⱼwⱼ + (C−1)gx + 2m` を `H·R` に合わせる (帯の高さは
`s` の側に入っているので `k` に掛からない)。どれも 1 次式で `k` が決まる。

**出力の大きさの指定と一緒のとき**は、先に最終のキャンバスの寸法を決め、それから `s` と `k` を解く (§6.2 の自然な配置から
`s` を決めて後で `k` を掛けると、指定した寸法が崩れるため):

1. キャンバスの寸法: `Width(w)` → `W = w, H = w / R`。`Height(h)` → `H = h, W = h·R`。`LongEdge(e)` → 長いほうの辺を `e`、
   もう一方を `R` から。`Original` → 横の並びとグリッドは §6.2 の `s₀` の `W` を、縦の並びは `s₀` の `H` を保ち、もう一方を `R` から。
2. 保つ軸 (横の並び・グリッドは `W`、縦の並びは `H`) から `s` を解く (§6.2 の式)。
3. もう一方の軸から `k` (グリッドはセルの画像部の比率 `r`) を解く。

例: 正方形 1 枚・横一列・高さ 100 px・比率 2:1 → `H = 100, W = 200` → `s = 200` (画像の幅) → `k = 0.5` (画像の高さ 100、上下を切る)。

- `k < 1`: 画像を縦に切る (表示の高さ `k·h`、幅はそのまま)。`k > 1`: 表示の高さを `k·h` に広げ、幅はそのままなので
  横に切る (縦横比を保って覆い、はみ出しを切る)。切る位置は基準点 (§5.2)。
- 全画像が同じ割合だけ切られるので、切り取りが特定の画像に偏らない。「切り取り: 最大 N%」は `|1 − k|` と `|1 − 1/k|` から出す。
- `k ≤ 0` (固定分だけで高さが足りない)、または `k` を掛けた後の画像の矩形が 1 px 未満は `LayoutError`。
- グリッドはセルの画像部の比率 `r` を `R` と行数・列数・固定分から決める (`H = W/R` を §6.2 のグリッドの式で `r` について解く)。

### 6.4 自動の分け方

候補 (行数・列数) ごとに、出力の大きさの指定と全体の比率の固定まで**最後まで解いた配置** (§6.2・§6.3) を作り、
`LayoutError` になる候補は外して、残りを次の値で比べる。全部の候補がエラーなら、ダイアログにエラーを出す。

- **行ごとに詰める (自動)**: 行数 `Q` を 1〜n で試す。各行の枚数は均等 (`n / Q` の切り捨てと切り上げ、**多い行を下に**)。
  固定が無いときは全体の比率 `W/H` と 1:1 の対数の差、固定があるときは切り取りの量 `|ln k|` が最小の `Q` を選ぶ
  (帯・余白・隙間があると、自然な配置の比率の差と `|ln k|` は一致しないので、固定があるときは `k` そのものを比べる)。
  同点は行数の少ないほう。例: 見本の 4 枚 (3:4・4:3・3:4・3:4 程度、固定なし) は 2-2 になる (1 行では約 3.6:1、2 行で約 0.89:1)。
  例: 正方形 4 枚・帯 180 px・隙間と余白 0・固定 3:5 では、2-2 は `k ≈ −0.13` で外れ、1 行 (`k ≈ 4.87`) が選ばれる。
- **列ごとに詰める (自動)**: 列数で同じ (多い列を右に。右から左のときは左に)。
- **グリッドの列数 (自動)**: 列数 `c` を 1〜n で試す。固定が無いときは全体の比率と 1:1 の対数の差、固定があるときは
  解いたセルの画像部の比率 `r(c)` と画像の縦横比の中央値の対数の差 (セルへの入れ方で生じる余白・切り取りが最小になる) が
  最小の `c`。同点は列数の少ないほう。
- 決まった分け方 (例 `2-2`) はダイアログに表示し、「指定」に切り替えたときの初期値にする。

### 6.5 右から左

各行 (縦の並びでは列の並び) の中で x を鏡に写す: `x' = W − x − 幅`。グリッドの最後の行の空きは左側に来る。

## 7. 描画

### 7.1 1 つの描画関数を 2 つの大きさで使う

`image_combine::render(layout, sources, options, labels, scale, fonts) -> RgbaImage` (straight RGBA)。
下見のプレビューは `scale < 1` で、縮小済みの小さな絵を元にする。書き出しは `scale = 1` で元の解像度の絵を元にする。
**配置・角丸・枠線・ラベルの描き方は 1 か所だけ**にし、プレビューと出力の食い違いを作らない。
矩形は `scale` を掛けてから丸める (左上と右下をそれぞれ `round`、隣り合う矩形の継ぎ目が隙間と一致する)。

書き出しは 1 枚ずつ描く必要がある (全部の絵をメモリに持たない) ので、関数は「キャンバスを用意する」
「カード 1 枚を描く」「ラベル 1 つを描く」に分け、下見と書き出しが同じ部品を順に呼ぶ。

### 7.2 カード 1 枚の順番

1. 背景で塗ったキャンバス (透明なら (0,0,0,0)) を用意する (最初に 1 回)。
2. 帯があれば、カード形 (角丸) の帯の部分を帯の色で塗る。
3. 元画像の切り取り矩形を画像矩形の大きさへ縮小・拡大する (Lanczos3、`fast_resize`)。
4. カード形の被覆率 (角丸の縁は画素の中心から円弧までの距離で 0〜1 のなめらかな値) を掛けて、キャンバスへ src-over
   (straight alpha、透かしの合成と同じ式 batch-export-plan §7.2)。
5. 枠線: カード形の内側 `border` px の帯の被覆率で、枠線の色を src-over。
6. ラベル (重ねる・帯): §7.3 で決めた配置で、comic-core で文字を描いた RGBA (Box / Pill は下地を先に描く) を、
   カード形 (帯のラベルはさらに帯の矩形) の被覆率で切り抜いて src-over。

- 元画像のアルファ (透過 PNG) はそのまま合成する。JPEG は背景が不透明なので、透明の部分は背景色になる。
- 角丸・枠線・Pill の円弧は同じ被覆率の関数を使う。

### 7.3 ラベルの配置 (出力の座標で 1 回)

`label_layout(layout, labels, options, fonts) -> Vec<Option<PlacedLabel>>`。各ラベルの文字 (番号の展開後)・使う文字の
大きさ (60% までの縮小)・`…` の省略・装飾込みの外接矩形・置く位置を、**出力の座標**で決める (§5.5 のはみ出しの規則)。
フォントの計測 (comic-core の `layout_text`) が要るので worker で行い、描画の要求ごとに 1 回計算して、
プレビュー (`scale < 1`) と書き出し (`scale = 1`) は同じ結果を縮小して使う。これでプレビューと出力で
「縮めた / 省略した」の判断が食い違わない。

## 8. worker

結合の操作 1 回 (§9.1 の `CombineSession`) につき、専用スレッド `image-combine` を **1 本だけ**起こし、
下見から書き出しまで同じスレッドが続けて受け持つ。編集の snapshot (`BakedEditSnapshot`) は clone できず、
AI・消しゴムの runner も持つので、**下見で受け取った snapshot をそのまま書き出しに使う** (書き出し用に作り直さない、
別のスレッドへ渡し直さない)。worker は次を寿命の間持つ:

- 対象ごとの `BatchExportItem` (snapshot を含む) と、合成後の寸法・小さな絵。
- 一括エクスポートと同じ `raw: Option<RawDecodeContext>` と `LocalAiActivityLease` (worker の寿命で持つ。
  ダイアログを開いている間も保存済みの AI 編集の合成が走るため)。
- フォント (comic-core、最初の描画の前に 1 回読む)。

メモリ: snapshot (マスク等) を全件持つのは一括エクスポートと同じ (一括もダイアログの間 `items` に全件を持つ)。
それに小さな絵の合計 (100 枚 × 256² × 4 ≈ 26MB、16 枚以下では 1 枚 512² 程度) とプレビュー 1 枚が加わる。

### 8.1 下見 (ダイアログを開いている間)

1. **準備 (UI)**: 対象ごとに `batch_export_item_for_target` を呼び (§3、1 フレームの予算 6ms・1 件は必ず進める)、
   できた順に worker へ送る。**失敗はその対象の失敗として残す** (一括のループのように対象外へ数えない)。
   対象は ID (並びの初期位置) で持ち、失敗しても数が減らない。
2. **読み込み (worker)**: 各画像を `decode_composite_source_for_materialization` (長辺 4096、取消付き) →
   `compose_book_page_for_materialization` で合成し、**合成後の寸法**と、小さな絵 (長辺
   `clamp(2048 / ceil(√n), 256, 1024)` px、Lanczos3) を持つ。元の解像度の絵はすぐ捨てる。
   1 件ごとに `Loaded { id, dims }` / `Failed { id, message }` を UI へ送る。ダイアログは「読み込み中 12/40」を出す。
3. **描画の要求**: 全件の寸法がそろった後、UI は設定・並び・ラベルを変えるたびに
   `Render { generation, spec }` を送る。worker は受け取ったら channel を空になるまで読み、**最後の要求だけ**を描く
   (配置 §6 → ラベルの配置 §7.3 → 描画 §7)。プレビューは長辺 1600 px 以内 (`scale = min(1, 1600 / max(W, H))`)。
   結果 `Rendered { generation, rgba, layout }` を返し、UI は今の generation と一致するものだけを texture にする
   (1 回の結果で 1 枚のアップロード)。
4. フォントを読めなければラベルなしの描画はでき、ラベルを使う設定では「ラベルのフォントを読めません」を出して
   「書き出す」を押せなくする。

- 準備・読み込みに失敗した対象はダイアログの一覧に出す。「読めない画像を外す」を押すまで「書き出す」は押せない
  (一部が空の出力を作らない)。外すと worker へ `Remove { ids }` を送り、worker はその snapshot・絵を捨てる。
- 寸法がそろう前 (読み込み中) は設定を変えられるが、描画の要求は送らない (配置に全件の寸法が要る)。

### 8.2 書き出し

「書き出す」で UI は `Write { spec }` (設定・並び・ラベル・出力先、置き換えなら元の出力のパス) を同じ worker へ送り、
ダイアログを閉じて進捗ダイアログに替える。worker は描画の要求を受け付けなくなり、書き出しを始める。

**進捗の接続**: 今の `ExportPending` / `ExportEvent` / `poll_export_pending` を使う。`total` は**枚数 + 1** (画像の処理 + 保存)。

- `ExportEvent::Step { label }` を足す: 完了数だけを 1 進め、成功・失敗には数えない (一括・単ページは送らない)。
  画像 1 枚を描き終えるたびに送る。
- 保存と構成の保存が終わったら `Completed(ExportSuccess)` (出力ファイル 1 件の成功) → `AllDone`。
  失敗は `Failed(ExportFailure)` → `AllDone`。取消は `Cancelled`。今の `poll_export_pending` の終わりの扱い
  (`end`、`AllDone` の無い切断は中断) はそのまま。
- `ExportPending` に `origin: ExportOrigin` (`Single` / `Batch` / `Combine`) を足す。終わり (`end` が決まったフレーム) の通知は
  `Combine` のとき結合の処理 (`finish_combine_write`) に渡す: `combine_session` を `None` に戻す、成功なら §8.4 の通知と一覧の選択、
  索引の読み直しを要求する (§10.5)。失敗の一覧の表示 (進捗ダイアログを残す) は今の共通の処理のまま。
  **終わりの通知の無い切断** (`end == None` のまま channel が切れ、今の処理が「worker が中断されました」を出して
  `export_pending` を消す分岐) でも、`Combine` なら同じ分岐で `finish_combine_write` を中断として呼び、`combine_session` を
  `None` に戻す (ログ + 通知だけ。書きかけの回復はしない、まれな失敗の割り切り)。結合の終わりの処理は「`export_pending` を
  手放すすべての分岐」から 1 回だけ呼ぶ。
- 構成の保存 (`combine.db`) だけが失敗したら、出力は残し、`Completed` の後に `Failed { label: "構成の保存", message }` を送る
  (進捗ダイアログに「構成を保存できませんでした。やり直しは使えません」が残る。まれな失敗の割り切り)。

1. 開始時: 配置とラベルの配置を計算し (§6・§7.3、下見と同じ入力なので同じ結果)、キャンバスを確保する。
   置き換え (§10.3) なら元ファイルの保護の集合を作る。
2. 画像ごと (並びの順): 取消の確認 → **持っている snapshot で**読み込み・合成 (取消付き) → **寸法が下見と同じか確かめる**
   (違えば「元の画像が変わりました。開き直してください」で全体を失敗) → 切り取り・縮小 → カードを描く →
   元の絵を捨てる (snapshot は書き出しが終わるまで持つ)。
3. 保存: エンコード (メタデータなし) → 書き込み (`create_new` の連番。置き換えは一時ファイル → 置き換え)。
4. 構成を保存する (§10.1): worker が `combine.db` を開いて (busy_timeout 付き) 1 行を upsert する。
5. `Completed` → `AllDone` を送って worker は終わる (上の「進捗の接続」)。

- 取消の確かめ: 各画像の前、読み込み・合成の中 (取消トークン)、**エンコードの前**、**書き込みの前** (一時ファイル・
  `create_new` の直前)。書き込みを始めた後は取消を見ず、最後まで書いて `Completed` → `AllDone` を送る (取消の要求が
  届いていても、結果は書けたものとして扱う)。取消・失敗では何も書かない (一時ファイルはエンコードが終わるまで作らない)。
- メモリの山は snapshot 全件 + キャンバス + 合成中の 1 枚 + その縮小。
- 区間の計測: `perf::event("image_combine/item", …)` に decode / compose / resize / draw の ms、
  `image_combine/encode` に出力寸法・形式・ms。下見は `image_combine/preview_load` と `image_combine/preview_render`。

### 8.3 取消

書き出し中の取消トークンを読み込み・合成へ渡す (AI・消しゴム等の合成も 1 件の途中で止まる)。取消で止まったら
`Cancelled` を送って何も書かない。確かめる点は §8.2 のとおりで、書き込みを始めた後は止めない。

### 8.4 書いた後

- 通知: 「結合しました: <名前>」。押すと mIV でその画像を開く (今の一覧にあればその項目を全画面で開く。
  別のフォルダなら、そのフォルダへ移ってその項目を全画面で開く。既存の「パスを指定して開く」経路を使い、
  新しい開き方を作らない。どの関数かは実装時に確かめる)。今の保存通知 (`show_capture_saved_toast`) の
  「Explorer で表示」とは別の動き (`FeedbackAction` に「mIV で開く」を足す)。
- 一覧: 出力先が今の表示中のフォルダなら、`post_operation_selection` (`Known`) で書いた画像にカーソルを移す (共有の規則で、
  出力が 1 件のときはチェックを付けない)。一覧の更新は既存の操作の再走査 (`Operation`) を結合の完了の処理から要求する
  (本の置き場の下のフォルダでも更新と選択が効くように。一括エクスポートの今の経路は本の置き場の下で更新されない既存の漏れがある
  (実装担当の報告、2026-11-26、未修正・別件))。
- 失敗・取消は今の進捗ダイアログ・通知の文 (一括エクスポートと同じ形)。

### 9.1 操作の持ち主 (`CombineSession`)

受付から書き出しの終わりまでを、App の 1 つの欄 `combine_session: Option<CombineSession>` が持つ。

```rust
enum CombineSession {
    /// やり直し: 構成の読み込みと元の画像の有無の確認を worker が行っている (§10.2 の 1)。
    ReopenLoading { request: u64, cancel: Arc<AtomicBool>, rx: Receiver<ReopenLoaded> },
    /// やり直し: 見つからない元の画像の確認 (§10.2 の 2)。
    ReopenMissing { request: u64, loaded: ReopenLoaded },
    /// ダイアログ (準備・下見・設定)。worker (§8) と channel を持つ。
    Dialog(Box<CombineDialogState>),
    /// 書き出し中。進捗は今の `export_pending` に出すが、終わるまでこの状態を持つ。
    Writing { request: u64 },
}
```

- 状態は 1 つだけ。`Some` の間は「画像を結合...」「結合をやり直す...」を受け付けない (押せない項目にし、キーでは
  「結合の操作中です」を出す)。一括エクスポート中 (`export_pending.is_some()`) も同じ。
- `ReopenLoading` / `ReopenMissing` / `Dialog` は `modal_dialog_block_reason` (= `common_modal_dialog_open`) と
  `document_open_modal_admission_blocked` の**両方**で `true` を返す (外からの「開く」・お気に入りの直接の開き方を止める)。
  `Writing` は一括エクスポートと同じく進捗ダイアログの扱い (止めない)。
- `ReopenLoading` / `ReopenMissing` / `Dialog` での Esc・×・「キャンセル」は、取消トークンを立てて `None` に戻す。
  worker と channel は捨て、待たない。遅れて届いた結果は `request` 番号が合わないので捨てる (`None` に戻った後は
  受け取る channel が無い)。
- `Writing` での取消 (進捗ダイアログのキャンセル) は**取消の要求だけ**を立て、session と受信口は終わりの通知
  (`AllDone` / `Cancelled`、§8.2) が届くまで持つ (今の `draw_export_progress_dialog` が取消の要求の後も `ExportPending` を
  持つのと同じ)。終わりの通知を受けて `None` に戻る。

## 10. 構成の保存と読み込み直し

### 10.1 中央 DB (`combine.db`)

data_dir に新しい SQLite `combine.db`。**保存先はここだけ** (利用者決定 2026-11-26「中央の DB だけ」)。
フォルダの `mimageviewer.dat` には入れない。

```sql
CREATE TABLE combine_recipes (
  output_key TEXT PRIMARY KEY,   -- adjustment_db::normalize_path と同じ正規化
  recipe     TEXT NOT NULL,      -- JSON (下)
  updated_at INTEGER NOT NULL    -- UTC ms
);
```

構成 (`CombineRecipe`、JSON、`"v": 1`):

```rust
struct CombineRecipe {
    v: u32,
    options: CombineOptions,          // 出力の名前を除く全部
    format: CombineFormat,            // 書いた形式 (置き換えで固定に使う、§10.3)
    items: Vec<CombineItemSpec>,      // 並びの順。source + label_override + annotation_space
}
// CombineItemSpec に annotation_space: Option<[u32; 2]> を持つ (下の「注釈の基準の寸法」)
enum CombineSourceRef {
    File { path: PathBuf },
    ZipEntry { zip_path: PathBuf, entry_name: String },
    PdfPage { pdf_path: PathBuf, page_num: u32 }, // パスワードは入れない (§10.2)
}
```

- 画像には何も書かない (利用者の判断。パスが外へ出ない)。パスはすべて絶対パス。
- 書き出しが成功した後に upsert する (置き換えでも同じ行を上書き)。新しい名前で書いたときは新しい行。
- 未リリースの新しいストアなので、移行は不要 (形式は `v` で区別する)。
- エクスプローラーなど mIV の外でフォルダ・出力を移す・改名すると構成は失われる (結合した画像は残る)。
  `mimageviewer.dat` へのバックアップは後の版で足せる (今は作らない)。

### 10.2 やり直し (読み込み直し)

「結合をやり直す...」(`CombineSession` の流れ):

1. `ReopenLoading`: UI は対象の出力のキーを worker へ渡す。worker が `combine.db` から構成を読み、各元の画像の有無を
   確かめる (ファイル・ZIP・PDF の `metadata`。ZIP のエントリ・PDF のページ数までは確かめない)。
   行が無ければ「この画像には結合の構成がありません」で `None` に戻り、索引の読み直しを要求する (§10.5)。
2. `ReopenMissing`: 見つからない元の画像があれば一覧を出し「見つからない画像を外して開く」/「キャンセル」。
   全部見つからなければ開かずに理由を出す。全部あればこの状態を飛ばす。
3. `Dialog`: 見つかった元の画像から、§3 の resolver で `BatchExportItem` を作る (一覧の項目と同じ規則で補正・回転・
   編集を解く。1 フレームの予算で 1 件ずつ、§8.1 の 1 と同じループ)。PDF のページは `App::pdf_open_password` で
   パスワードを得る。パスワードが要るのに無ければ、その対象は「パスワードが必要です (一度 PDF を開いて入力してください)」の
   失敗になる (§8.1 の失敗の扱い)。ZIP のエントリ・PDF のページが実際に無い場合も下見の読み込みの失敗になる。
4. 構成の設定・並び・ラベルでダイアログを開く (プリセットの選択は空)。出力の名前・場所は元の出力のもの。

- 元の画像の今の保存済み編集で合成する (最初の書き出しの後に元の画像の補正を変えていれば、変えた後の絵になる)。
- **注釈の基準の寸法** (段 C の実装中に実装担当が報告、設計担当の決定 2026-11-26): テキスト注釈の座標は元の画像の基準の寸法
  (`comic_source_dims`) に対して持つが、一覧の項目はこの寸法を表示用に読み込んだ画像やメモリ上の寸法の記録から得ていて、
  `comic.db` にもベクターの PDF の解析にも残っていない。一覧に無い元の画像では同じ値を得られない。そこで、書き出しのときに
  各元の画像の snapshot の `comic_source_dims` を構成の `annotation_space` に記録し、やり直しの resolver はその値を使う。
  記録が無く注釈がある元の画像 (ラスター画像は合成した絵の寸法と同じなので、実際に問題になるのはベクターの PDF のページ) は、
  ずれた合成をせず、その対象を「注釈の位置を再現できません。一覧から結合し直してください」の失敗にする (§8.1 の失敗の扱い)。
- 構成の JSON が読めない (`v` が未知・壊れている) ときは開かずに理由を出し、ログに残す (行は消さない)。

### 10.3 置き換え

やり直しで開いたダイアログだけ、出力の欄に「元の結合画像を置き換える」(既定 ON) を出す。

- ON: 元の出力のパスへ、一括エクスポートの `Replace` と同じ方法で書く (同じフォルダの一時ファイル → 置き換え、
  置き換えたファイルの更新日時は「書き出した時刻」と「前のファイルの秒 + 1 秒」の遅いほう、batch-export-plan §4.4)。
  **名前・場所・形式の欄は押せなくし、形式は構成の `format` (元の出力の形式) に固定する** (品質は変えられる)。
  戻せないことを欄の下に書く。
- 元の出力が今回の元の画像に含まれる (結合した画像をさらに結合に使った) ときは置き換えを押せなくする。
- OFF: 通常の書き出し (形式・名前・場所を選べる、連番)。
- **出力に付いている編集**: 結合した画像に注釈などの編集 (補正・消しゴム・隠蔽・補正レイヤー・切り取り・注釈) が
  保存されていると、置き換えた後の画像に同じ座標で掛かり、配置を変えていればずれる。編集は消さず (利用者が作った
  データ)、置き換えが ON で出力に編集があるときはダイアログに「この画像の注釈などの編集は残ります。配置を変えると
  位置がずれます」を出す。判定は受付の時点で、対象の出力 (今の一覧の項目) の idx の編集の有無 (App が持つ表) から
  取り、`CombineSession` に持つ (I/O なし。モーダルの間に一覧は変わらない)。

### 10.4 改名・削除

- `rename_key_migration::STORES` に `combine.db` の `combine_recipes.output_key` を 1 行足す。改名・移動では
  出力のキーを引き継ぎ (exact と配下の prefix、新キー優先は他のストアと同じ)、mIV の中での削除では
  `purge_removed_scopes_impl` が同じ表で行を消す (他の編集と同じ。削除した出力の構成は残さない)。
  本の構造操作の方針 (`book_policy`)・コピーの扱い (`copies_with_book_page`) は注釈 (comic) と同じにする。
- 構成の中の**元の画像のパスは引き継がない** (利用者の条件「もとのファイルが同じパスに残っている限り」)。
  元の画像を改名・移動したら、やり直しでは見つからない画像になる (§10.2 の 2)。
- メタ情報の持ち運び (`mimageviewer.meta.miv`) と設定の持ち運びには入れない (最初の版の範囲外)。

### 10.5 索引 (メニューを出すかどうか)

「結合をやり直す...」を出すかを UI スレッドで I/O なしに決めるため、App は構成のある出力のキーの集合を持つ。

```rust
struct CombineIndex { keys: HashSet<String>, loaded: bool, generation: u64 }
```

- **変化のたびに全部読み直し、最後の世代だけを採用する**。読み直しの要求は `combine.db` の書き込みが確定した**後**に出す:
  書き出しの終わり (§8.2)、やり直しで行が無かったとき、そして `STORES` を通るすべての変更 (改名・削除の purge・本の
  コピー (`copy_stores_impl`)・内容の同一性からの復元 (`content_identity/restore.rs`))。後者は `StoreMutationEffects` に
  `combine_index_stale` を足し (combine の descriptor の行が変わったら立つ。キャプション・文字起こしの表示の失効と同じ仕組み)、
  App がその効果を受けたところで読み直しを要求する。要求ごとに `generation` を 1 増やし、
  worker が `output_key` を全部読んで `(generation, keys)` を返す。届いた結果は `generation` が最新のときだけ採用する。
  どの要求も確定した DB を読むので、最新の世代の結果には、それまでの変化が全部入っている。増分の更新・prefix の付け替えは持たない。
- 起動後に 1 回読む。読み終わるまで (`loaded == false`) は、対象が 1 件の画像なら「結合をやり直す...」を出す
  (押して構成が無ければ §10.2 の 1 で知らせる)。
- 索引に古いキーが残っても害は無い (押したときに DB で確かめる)。
- キーだけを持つ (1 行数十〜数百バイト。1 万件で数 MB)。読み直しは数十 ms 未満の見込み (worker)。

## 11. 簡素化と、まれな失敗の割り切り

CLAUDE.md「設計の簡素化」に沿って検討した結果:

- **採用: 受付から書き出しの終わりまでを 1 つの持ち主 (`CombineSession`、§9.1) にし、ダイアログとやり直しの準備を
  モーダルにする**。開いている間に一覧・選択が変わる、外から別のものが開かれる、別の書き出しが始まる、やり直しの対象が
  消える、の組み合わせを消す。
- **採用: 下見から書き出しまで 1 本の worker が snapshot を持ち続ける** (§8)。書き出し用に snapshot を作り直したり、
  スレッドの間で渡し直したりしない。
- **採用: 下見の読み込みは開いたときに 1 回だけ**。並べ替え・設定の変更で読み直さない (配置と描画だけ)。
- **採用: 描画の要求は最後の 1 件だけ**。途中の要求を順に描かない。
- **採用: 設定は書き出しの開始時に 1 回だけ worker へ渡す**。書き出し中はダイアログが無い。
- **採用: 置き換えでは形式を元の出力に固定する** (拡張子と中身の食い違い・別名で残す扱いを作らない)。
- **採用: Enter で書き出さない**。Enter の持ち主の判定 (一括エクスポートで 1 節を要した) を作らない。
- **採用: 上書きはやり直しの置き換えだけ**。通常の書き出しは連番。
- **採用: 元の情報を書かない**。どの情報を残すかの選択と縮小画像の警告の組み合わせが消える。
- **採用: 読めない画像があれば外すまで書き出せない**。一部が空の出力・失敗の種類分けを作らない。
- **採用: 構成は画像に書かず、中央の DB だけに置く** (利用者の判断)。サイドカーの復元・編集の貼り付けとの関係を作らない。
- **採用: 索引は変化のたびに全部読み直し、最後の世代だけを採用する** (§10.5)。増分の更新の順序を扱わない。
- **採用: 元の画像のパスは改名で引き継がない** (利用者の条件)。
- **採用しない: 書き出し後にダイアログを残す**。やり直しで同じことができる。

まれな失敗は割り切り (ログ + 通知): 書き込み・置き換え・`combine.db` の書き込み (画像は書けたが構成を覚えられない →
「構成を保存できませんでした。やり直しは使えません」を通知) の失敗、下見の後に元の画像が変わった (§8.2 の 2)、
索引の読み込みの失敗 (メニューの出方が古いままになるだけ。押せば DB で確かめる)。再試行はしない。

## 14. テスト

- **配置 (純粋)**: 5 つの並べ方 × 向き × 隙間・余白・帯の有無で、全体の寸法とカード矩形が式どおり。
  帯付きの縦一列・列ごとに詰める (列ごとに枚数が違う) の数値。正方形 3 枚 `2-1`・`gx = 500` の行がエラーになる例、
  過大な余白・帯、極端な縦横比 (1:50)。全体の比率を固定しても自動で複数行・複数列が選ばれる例。
  `Width` / `Height` / `LongEdge` / `Original` と全体の比率の固定の組み合わせで、指定した寸法と比率を両方満たす
  (正方形 1 枚・横一列・高さ 100・2:1 → 200×100)。比率がいちばん近い候補がエラーで別の候補が選ばれる例 (§6.4 の正方形 4 枚・帯 180・3:5)。
  見本の 4 枚 (3:4・4:3・3:4・3:4) が自動で 2-2 になる。右から左の鏡写し。出力の大きさの指定で隙間・枠線が変わらない。
  全体の比率の固定で `k < 1` / `k > 1` の切り取り矩形と「最大 N%」。`k ≤ 0`・上限超え・行の枚数の不一致のエラー。
  1 枚のとき。
- **描画**: 角丸の縁の被覆率 (なめらか)、透明の背景で角丸の外が透明、枠線が角丸に沿う、帯・Box・Pill の位置、
  はみ出しの縮小と `…` (装飾込みの幅と高さで判定)、幅の広いカードの帯に Box・Pill と下に伸びる字 (g, y) を含む文字が
  収まる、収まらないラベルは描かず件数が出る、置ける幅が 0 以下でラベルを描かない、小さいカード・大きい角丸でラベルが
  角丸の外へ出ない、JPEG で背景が不透明。**プレビュー (scale < 1) と出力 (scale = 1) が同じ関数で、
  縮小した出力とプレビューの配置が 1px 以内で一致**。
- **worker と進捗**: 下見の最後の要求だけを描く (generation)、取消でファイルができない (画像の処理中・エンコードの前・
  書き込みの前)、書き込みを始めた後の取消でも完了が 1 回だけ採用される、`AllDone` を送らずに送信側を閉じると
  `export_pending` と `combine_session` の両方が解放される、実際の `poll_export_pending` を通して進捗
  (`Step` が成功に数えられない)・正常終了・通知・一覧の選択・索引の読み直しの要求、構成の保存だけの失敗、寸法が下見と違えば全体の失敗、
  読めない画像があると書き出せない、メモリ (キャンバス + 1 枚) を超えて絵を持たない (注入した読み込み関数で数える)。
- **構成の保存**: 書き出しで `combine.db` に行ができ、JSON の往復が一致。改名で出力のキーが移る、フォルダの改名で
  配下の出力のキーが移る、mIV の中での削除 (出力単体・親フォルダ) で行が消える (`rename_key_migration` の既存テストの形)。
- **索引**: 読み直しの結果を遅らせて届けても、古い世代の結果が新しい結果を上書きしない。読み込み済みの状態から、
  本のコピー・内容の同一性からの復元で増えた行が、`combine_index_stale` を通じて索引に入る。起動直後 (未読み込み) の
  メニューの出方。行が無い画像で「やり直す」を押すと知らせて読み直す。
- **やり直し**: 見つからない画像の一覧と外して開く、置き換えで元の出力が新しい内容になり更新日時の規則を満たす、
  置き換えでは形式を変えられない、元の出力が元の画像に含まれると置き換えを押せない、出力に編集があると注意が出る。
  **一覧に無い元の画像の snapshot が、一覧で開いたときと同じ** (書庫に標準の補正があるZIP・PDF、製本ページ、
  パスワードを保存済みの PDF。パスワードが無い PDF は対象ごとの失敗)。
- **操作の持ち主**: `ReopenLoading` 中の再実行・外からの「開く」が受け付けられない、Esc の後に届いた結果が捨てられる、
  書き出し中に結合を開けない。
- **準備の失敗**: snapshot の読み出しの失敗 (フォントが読めない等) でも対象の数が減らず、外すまで書き出せない。
- **snapshot の受け渡し**: 書き出しが下見と同じ snapshot を使う (注入した合成関数で、同じ snapshot の同一性を確かめる)。
- **ダイアログ**: 1093×614 と 1366×728、UI 倍率 100% / 200% で見出し・操作行・× が押せ、設定が最後まで届く
  (`scroll_layout`)。UI スナップショット (既定・ラベル帯・やり直し)。Enter で書き出さない、Esc で閉じる、
  ラベルの欄が `ime_focus` の helper を通る (既存の allowlist テスト)。
- **入口**: 右クリック・ツールメニューの 2 項目の出す条件 (1 枚・101 枚・対象外だけ・索引に有る/無い)、
  `KeyAction` 2 つが既定のキーなしで keymap の一覧・ini に載る。
- 破壊的な経路 (置き換え) のテストは一時フォルダだけで行い、実ドライブのルートを使わない。
