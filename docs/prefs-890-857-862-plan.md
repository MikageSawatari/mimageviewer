## A. §1.890 フォルダ背景色の低コントラストを、確認後に許可する

### A.1 今の作り (コード参照、master 206768a81)

- `FolderCellBackground { enabled, light: [u8;3], dark: [u8;3] }` (`src/folder_cell_background.rs`)。
  `valid()` は両テーマで、背景に直接載る文字の色 (検索結果のフォルダの階層パス・件数) すべてに 4.5:1 以上を要求する。
  OFF でも検査する。
- `valid()` を使う入口は 3 つ:
  1. 環境設定の OK の可否 (`src/ui_dialogs/preferences.rs` の OK ボタンの `add_enabled` 条件と、横の赤い説明)。
     編集欄の下にも赤い説明 (`src/ui_dialogs/preferences/folder_background.rs`)。
  2. 設定の書き出し・取り込み (`src/settings_transfer.rs` の `preferences_policy!` の検査 `|v, _raw| v.valid()`)。
     書き出しでは低コントラストの色が「issue」で落ち、取り込みでは拒否されて今の値が残る。
     取り込みは環境設定の下書き (`state.settings`) へ入る (`src/ui_dialogs/preferences/transfer.rs:190`)。
  3. AI からの設定変更 (MCP `set_settings`)。`stage1_validate` が同じ検査表 (`parse_items`) を通るので拒否される。
     通れば `install_headless_preferences_state` → `apply_preferences_dialog` で直接適用する (UI の OK ボタンの条件は通らない)。
- 形の検査は別にある: RGB の各値は `u8` なので serde が 0〜255 以外・型違いを拒否する。HEX の入力途中・6 桁でない値は
  `name_colors::hex_input_ready` が OK を止める (「色: HEX は6桁で指定してください」)。どちらもコントラストとは独立。
- 設定は v5.7.0 で出荷済み (`94076e6a9`、タグ v5.7.0 に含まれる)。

### A.2 方針 (要約)

- **コントラストは「不正」ではなく「注意」にする。** `valid()` をやめ、読みやすさの判定 (比の計算) だけを残す。
  形の検査 (serde の `u8`・HEX 6 桁) は今のまま拒否する。
- **確認を出すのは、環境設定の OK を利用者が押したときだけ。** 条件は「この OK で、低コントラストの色が新しく塗られ始める」こと
  (A.3)。確認の窓で「色を選び直す / この色で設定」を選ぶ。
- **承認の印は保存しない。** 今の設定 (live) にある色は、環境設定の確認・取り込み・AI の変更のどれかで利用者が決めた色なので、
  それ自体を「承認済み」とみなす。下書きと live の比較だけで「変えていなければ聞き直さない」が成り立つ。
  これで保存形は変わらず、移行も要らない (A.6)。
- 取り込み・書き出し・AI の変更は、コントラストで拒否しない。取り込みは下書きに入るので、OK の時点で A.3 の規則どおり確認が出る。
  AI の変更は確認なしで受け付ける (A.5)。

### A.3 確認を出す条件 (1 か所の関数)

`folder_cell_background.rs` に置く (名前は実装で調整してよい):

```text
readable(colors, theme)         = 直接載る文字の色すべてに対して contrast >= 4.5   (今の valid() の中身をテーマごとに)
min_text_contrast(colors, theme) = 直接載る文字の色との比の最小値 (説明文の数値用)
newly_painted_low_contrast(live, draft) -> テーマの集合 (Light / Dark の 0〜2 個)
    テーマ t が入るのは、次をすべて満たすとき:
      draft.enabled
      かつ !readable(draft, t)
      かつ !(live.enabled かつ live.color(t) == draft.color(t))
```

- 「変更していない保存済みの色」は聞き直さない: live で ON・同じ色なら、そのテーマは入らない。ほかの設定だけを変えて OK を押しても出ない。
- OFF の下書きでは確認しない (色は塗られないため)。後で ON にした OK のときに、その時点の色で確認する
  (live が OFF なので「新しく塗られ始める」に当たる)。
- 片方のテーマだけを変えたときは、変えたテーマだけが対象。もう片方の承認済みの色を聞き直さない。
- 直接載る文字の色の一覧は今の 1 か所 (`valid()` の中の配列) のまま、描画と共有する (§1.880 の不変条件を保つ)。
- 文字コントラストの設定 (標準 / 強い) はこれらの文字色を変えないので、判定は 1 通り (今と同じ)。

### A.4 環境設定の UI

- **編集欄の下の説明** (`folder_background.rs`): 低コントラストのテーマがあれば、赤 (error) ではなく注意の色
  (`ui.visuals().warn_fg_color`) で出す。例:
  「Light の色は文字とのコントラスト比が 4.2:1 で、4.5:1 未満です。検索結果のフォルダの場所や件数が読みにくくなることがあります。」
  (両テーマなら 2 行)。OFF でも出す (見本は今も OFF で描いている)。数値は小数 1 桁で**切り捨て**る
  (例: 4.49:1 は「4.4:1」。四捨五入すると境界の色が「4.5:1 で 4.5:1 未満」と読めてしまうため、独立レビュー r1 P3)。
  判定は丸める前の比で行い、表示用の整形は判定と別の 1 つの関数に置く (説明と確認の窓で共用)。
- **OK ボタン**: `folder_cell_background.valid()` を OK の条件と横の赤い説明から外す。ほかの条件 (HEX 6 桁など) は今のまま。
- **OK を押したとき**: ほかの条件をすべて満たして OK が押され、`newly_painted_low_contrast(live, draft)` が空でなければ、
  適用せずに確認の窓を開く。空なら今までどおり適用する。
- **確認の窓** (`egui::Modal`、既存の `draw_discard_changes_confirm` と同じ形の小さな関数):
  - 見出し「フォルダの背景色の確認」、本文「Light の色は文字とのコントラスト比が 4.2:1 (4.5:1 未満) です。検索結果のフォルダの
    場所や件数が読みにくくなることがあります。この色で設定しますか？」(対象テーマごと)。
  - ボタン「色を選び直す」「この色で設定」。Esc と窓の外のクリックは「色を選び直す」と同じ。
  - 「この色で設定」: 適用する (`apply_preferences_dialog`)。ほかの変更も同時に適用される (OK と同じ)。
  - 「色を選び直す」: 窓を閉じ、下書き (色・ほかの変更すべて) をそのまま残す。環境設定の表示を
    「表示 → サムネイル」のフォルダ背景の場所へ移す (既存の検索結果からの移動 `select_preference_search_result` と
    検索の項目 `thumbnail/folder-background` を使う。新しい移動の仕組みは作らない)。
- **確認の窓の状態**: `PreferencesState` (下書き) に `Option<…>` を 1 つ持つ (環境設定を閉じれば一緒に消える)。開いている間は:
  - 環境設定の窓を `.enabled(false)` にする (設定の転送の窓が開いているときと同じ)。
  - 環境設定の Enter / Esc の処理 (`enter_pressed` / `escape_pressed`) を止め、Esc は確認の窓だけが受ける
    (今の破棄確認のように、同じ Esc で環境設定のキャンセルへ進まないこと)。
  - 下書きは変えられないので、窓を開いた時点の判定のまま「この色で設定」で適用してよい。
- AI の適用 (`agent_set_settings`) は `apply_preferences_dialog` を直接呼ぶので、確認の窓を通らない (A.5 の決定どおり)。
  実装時に、**UI から適用へ進む経路がほかに無いか** (`apply = true` を立てる箇所、`apply_preferences_dialog` の呼び出し元) を列挙し、
  利用者の操作で適用するものはすべて確認を通ることを確かめる。

### A.5 入口ごとの扱い (決定)

| 入口 | 形の不正 (型・範囲・HEX) | 低コントラスト |
| --- | --- | --- |
| 環境設定の編集欄 | HEX 6 桁でなければ OK 不可 (今のまま) | 注意の色で説明 (拒否しない) |
| 環境設定の OK | 同上 | A.3 の条件で確認の窓 |
| 設定の書き出し | 型は Settings が保証 | 拒否しない (issue にしない) |
| 設定の取り込み (下書きへ) | serde が拒否 (今のまま、issue 1 件) | 拒否しない。下書きに入り、OK で A.3 の確認 |
| AI の設定変更 (MCP `set_settings`) | serde が拒否 (今のまま) | 拒否しない・確認しない |
| 設定 DB の読み込み | serde (今のまま) | 検査しない (今のまま) |

AI の変更を確認なしで受ける理由: 利用者が AI に頼んだ変更で、適用の通知 (既存の `poll_agent_changes` の通知) と一覧の表示ですぐ分かる。
変更の結果に注意を返す仕組み (応答の形の変更) は MCP の契約を変えるので今回入れない (MCP 側を触る mcp-keys-843 と範囲を分ける)。
AI 向けの文書 (`docs/mcp-guide-settings-plan.md` の `folder_cell_background` の行) は「4.5:1 未満も受け付ける。読みやすさの判定は
環境設定の確認だけ」に直す。AI に渡す設定の説明文がコード内にあれば、同じ趣旨に直す (実装担当が確かめる)。

### A.6 保存形・移行・旧版

  そのまま読めて、確認も出ない。

### A.8 状態の組み合わせを減らす検討

- 「承認済み」の印を保存する案 (色ごとの承認フラグ・承認した色の記録) は採らない。印と色の食い違い (色だけ変わった・取り込みで印だけ来た・
  AI が色だけ変えた) の組み合わせが増え、保存形の変更と移行も要る。live との比較で同じ効果が出る。
- 確認の窓は OK のときだけ。編集のたびに聞く案は採らない (色を選んでいる途中に何度も出る)。
- 確認中は環境設定の窓を操作できなくする (下書きが確認後に変わる組み合わせを消す)。
- まれな失敗 (保存の失敗など) は既定の割り切り (既存の設定保存の経路のまま)。

## B. §1.857 環境設定を狭くすると右端の文字が切れる / ラベル付きのコンボが縦に伸びる

### B.1 今の作り

- 環境設定の窓 (`preferences.rs` の `egui::Window::new("環境設定")`) は `.resizable(true)`・`.default_size([720, 520])` で最小幅が無い。
  左のツリーは 180px 固定、右のページはその残り。
- 「ページジャンプ量」の行 (`src/ui_dialogs/preferences/pages.rs` の該当行) が `ui.horizontal` で折り返さず、約 267px あってページの幅を右へ広げる。
  右のページの `ScrollArea` は縦だけなので、はみ出した分は切れる (観測: 454px で切れ、495px 以上では切れない)。
- `ComboBox::from_label` はラベルが長いと、狭い幅でラベルが折り返してボタンが縦に伸びる。

### B.2 方針

1. **折り返さない行を直す**: 「ページジャンプ量」の行を `horizontal_wrapped` にする。ほかに同じ形の行が見つかれば同じく直す。
2. **窓に最小幅を付ける**: 操作カスタマイズの窓 (`min_size(egui::vec2(560, 420).min(safe_size))`) と同じ形で、画面に収まる範囲に
   クランプした最小幅を付ける。値は B.3 の検査がすべてのページで通る最小の幅に余裕を足して決め、**640px 以下**に収める
   (今の既定 720px より狭くでき、利用者が普段使う幅を奪わない)。640px で収まらないページがあれば、そのページの行を直す
   (最小幅を上げない)。固定列の再設計が必要な右クリックメニュー表は、ラウンド4の利用者指示により B.4 の明示除外とする。
3. 最小幅で、ラベル付きのコンボが縦に伸びないことも検査で確かめる。伸びるものはラベルの短縮ではなく、ラベルとコンボを別の部品に
   分ける (`ui.label` + `ComboBox::from_id_salt`) か、`horizontal_wrapped` の行にする。

### B.3 検査 (狭い幅のレイアウト検査)

- 環境設定の全ページ (`PreferencesPage` の全値) を、窓を最小幅にして描き、B.4 の明示除外以外は右のページの `ScrollArea` の出力で
  `content_size.x <= inner_rect.width() + 1 物理ピクセル` を確かめる (`tests/support/scroll_layout.rs` の許容と同じ考え方。
  必要なら幅の検査関数を `ScrollLayout` に足す)。
- 同じ描画で、AccessKit の `Role::ComboBox` の部品の高さが 1 行分を超えないこと。ラウンド4で `interact_size.y` だけでは足りないと判明したため、同じ harness・フォント・style で参照用の単一行 ComboBox を描き、その実測高 + 1 物理ピクセルを上限にする。参照は右ペイン外・非操作の Background Area に置き、他のテストでは描かない。
- 1093×614 の小さい画面でも、最小幅の窓の OK / キャンセルが画面内に見えること (CLAUDE.md の起動時ダイアログの規則に合わせる。
  既存の `container_icon_kinds_preferences_small_dialog_controls_reachable` と同じ形)。
- 窓の最小幅は画面より大きくしない (クランプ)。
- はみ出し部品と行高の診断は、右ペインの左端以右、上端以降で viewport に縦に交差する部品に限る。タイトルバーの ×、固定の操作行、参照 ComboBox を含めない。ComboBox の無いページは `query_all_by_role` で扱う (設計担当の修正を維持)。

## C. §1.862 取り込み系の場所▼で、保存先がまだ無いときの表示

### C.1 今の作り

- 場所▼の「クリップボード取り込み」「ブラウザ閲覧」の行は `known_folders::main_capture_locations` が作り、
  `ui_main.rs` の `draw_capture_location_button` が押されたら `start_folder_pane_open(path)` を呼ぶ
  (`FolderOpenScanPurpose::PaneNavigation`)。
- 走査は worker で行い、失敗すると `resolve_main_folder_open_ready` が共通の警告「フォルダを読み取れませんでした」を出す
  (`app.rs` の `Err(error)` の分岐。`scan` は `std::io::Result<ScannedDir>`)。保存先は最初の保存まで作らないので、まだ無いとこれが出る。
- ブラウザ閲覧の環境設定の「保存先を開く」は、`browser_integration/backend.rs` で「保存先はまだありません。最初の保存時に作成します。」を返す。

### C.2 方針

- **取り込み系の 2 行から開いた走査が `NotFound` で失敗したときだけ**、警告を「保存先はまだありません。最初の保存時に作成します。」にする。
  ほかの失敗 (アクセス拒否・ネットワークなど) と、ほかの場所の行・ツリー・アドレス入力は今のまま。
- 「取り込み系の行から開いた」ことは**要求 (`FolderOpenScanPurpose`) に載せて運ぶ**。App の別のフラグに覚えない
  (後の別の走査に漏れないように。§1.853 の同じ形の所有の考え方)。今の `PaneNavigation` と同じ動作の印を足す形
  (例: `PaneNavigation` に「見つからないときの文言」を持たせる、または同じ動作の変種) にし、`PaneNavigation` を見ている箇所
  (`matches!(…, PaneNavigation)` など) の挙動を変えない。形は実装担当がコードを見て決め、選んだ理由を本書へ 1 行残す。
- UI スレッドで `is_dir()` などを呼んで先に調べる案は採らない (UI スレッドの同期 I/O の規則。ネットワーク上の保存先もあり得る)。
- 登録のときにフォルダを作る案は採らない (何も保存していないのにフォルダができるため。バックログの理由)。
- 文言は 1 か所の定数にし、`browser_integration/backend.rs` と共有する。
- 実装の形: `CaptureDestinationNavigation` を `FolderOpenScanPurpose` の変種に追加し、既存 `PaneNavigation` の各処理 arm と同じ扱いにした。既存の要求の構築形を変えず、要求自身が保存先の意図を所有して `NotFound` の文言だけを選べるため。

### C.3 テスト

- 取り込み系の行から、無いパスを開く → 警告が新しい文言、現在の一覧は変わらない。
- 同じ無いパスを通常の場所・アドレス入力の経路 (`PaneNavigation`) で開く → 今までどおり「フォルダを読み取れませんでした」。
- 取り込み系の行から、在るパスを開く → 今までどおり開ける。

  B の最小幅が 640px を超えそうなら止めて統括へ相談する。

### 実装の引き継ぎ (2026-11-25、コンパイル・Rust テスト未実施)
