# ブリーフ: ページ送りのトレース不変条件を機械判定にする

## 前提 (必ず守ること)

- **アプリを起動しない**。
- **git 操作をしない**。master の作業ツリーに未コミットのまま残す。統合はこちらで行う。
- **製品コード (`src/`) を変更しない**。触るのは `scripts/analyze_perf.py` と、
  必要ならそのテストだけ。ページ送りの不具合そのものは別途こちらで直している。

## 背景

フルスクリーンのページ送り (キー押しっぱなし) の表示は、これまで何度も壊れている。
壊れ方が毎回違うのに、**どれも実機で気づきにくく、気づいても言葉での再現手順が曖昧**になる。

- 間のページが表示されず飛ぶ
- カラー化されていないフレームが混ざる
- サムネイルで素早く通過すべきところで高画質を待ってしまう
- 同じページがサムネイルと完成画像で往復する

2026-08-11 の 1 日だけで、この領域で 3 回退行を出した。**3 回とも perf ログの
`fs.page_turn_ready` と `fs.page_turn_decision` を時系列に並べれば一目で分かる形**だった。
つまり人の目視ではなく、**トレースの不変条件**で機械的に落とせる。

`scripts/analyze_perf.py` には既に `page-turn` サブコマンドがあるが、集計を出すだけで
合否を返さない。ここに判定を足す。

## やること

`python scripts/analyze_perf.py <jsonl> page-turn` に **`--check` オプション**を足す。
指定時は下の不変条件を検査し、違反があれば内容を出力して **exit 1**、無ければ exit 0。
`--check` を付けない従来の呼び出しは**出力も終了コードも変えない** (既存の手順を壊さない)。

### バースト (押しっぱなし区間) の切り出し

`fs.page_turn_ready` を時系列に並べ、**連続するイベントの間隔が 300ms 以内**のものを 1 つの
バーストとして扱う。バースト内で `idx` が単調増加なら送り方向、単調減少なら戻り方向。
どちらでもない (往復している) バーストは方向不明として扱い、I3 の連続性検査だけ外す。

`items_generation` が変わったらバーストを切る (別の一覧になったら別物)。

### 検査する不変条件

| ID | 内容 | 根拠 |
| --- | --- | --- |
| **I1** | 1 つのバースト内で、**同じ idx** の `source` が `final_composite` → `thumbnail` へ戻らない | 同一ページがサムネイルと完成画像で往復する退行 |
| **I2** | 1 つのバースト内で、`source` が**ページをまたいで混ざらない** (全ページ thumbnail か、全ページ final_composite か)。混在は違反 | 隣り合うページでカラー / モノクロが交互になる退行 |
| **I3** | バーストの最初と最後の idx の間の**すべての idx が 1 回以上**出現する | 「間のページが飛ぶ」退行。§1.58 の利用者要件「ページ表示自体は飛ばさない」 |
| **I4** | バーストの**最後の idx** は `mode=materialized` で終わる | 「キーを離してもサムネイル画質のまま残る」退行 |
| **I5** | `fs.page_turn_decision` で `catalog_thumbnail_ready=true` かつページ送り入力が残っている (`reason != "pending_zero"`) フレームは、`defer_ui_uploads=true` である | UI スレッドのアップロードを保留し続けるという §1.58 の中核。ここが崩れると戻り方向だけ引っかかる |

**既知の例外を 1 つだけ許す**: フォルダ末尾でキーを押し続けると、最後のページがサムネイル画質の
まま留まる (利用者判断 2026-08-10「支障なし」)。**バーストの末尾 idx が前後端 (先頭 0 または
最終ページ) で、かつ同じ idx が連続している場合だけ I4 を免除**する。それ以外では免除しない。

### 出力

違反ごとに、**バーストの開始時刻・方向・該当 idx・実際の source 列**を出す。人がログを
grep し直さずに原因へ辿り着ける粒度にすること。例:

```
I2 violation: burst t=6.47..7.42 forward idx=2..31
  mixed sources: final_composite x27, thumbnail x4 (thumbnail at idx=8,13,22,25)
```

最後に `checked bursts=N violations=M` のサマリを出す。

### テスト

`scripts/` 配下に既存の Python テストの置き方があればそれに合わせる。無ければ
`scripts/test_analyze_perf_page_turn.py` を新設し、**合成した JSONL** (実ログ不要) で
次を固定する:

- I1〜I5 それぞれについて、違反する列で exit 1、違反しない列で exit 0
- バースト分割 (300ms 超で切れる / `items_generation` 変化で切れる)
- 末尾ページの I4 免除が効くこと、および**免除条件を満たさないときは免除されない**こと
- `--check` なしでは終了コードが 0 のまま変わらないこと

## 参考にできる実ログ

`target/idle-health/v2.13.0-idle-health-session.jsonl` にセッションログがある。
また `%APPDATA%\mimageviewer\logs\perf_events.jsonl` に、この不変条件を**実際に破っている**
セッション (I2 違反: 送り方向で idx=8,13,22,25 だけ thumbnail、戻り方向で idx=21 以降が
すべて thumbnail) がある。**開発中の確認にはこれを使い、テストには合成 JSONL を使うこと**
(実ログはいずれ消えるため)。

## 完了条件

- `python scripts/analyze_perf.py <上記の実ログ> page-turn --check` が **exit 1** を返し、
  I2 違反を具体的な idx 付きで報告する。
- `--check` なしの既存呼び出しの出力と終了コードが変わらない。
- 追加した Python テストが通る。

## 報告してほしいこと

- バースト分割で判断に迷った点があれば、その扱い。
