# §1.118 コレクション仕様案

2026-09-14 に始めた検討記録。後日の確定事項と出荷前修正は
[実装計画 §23](collection-implementation-plan.md#23-v400-出荷前レビュー後の修正計画2026-09-16) に記録した。
以下の初期案と当時の未決事項は検討時点の記録として残し、現在の操作仕様は
[マニュアル](../htdocs/mimageviewer/manual/collections.html) と実装計画を参照する。

## 目的と確定要件

離れた場所の実ファイル・フォルダ・本を、元の場所を変えず一つの一覧として管理する。
スマートフォルダの条件検索や、ページをコピーする製本とは別機能。
同じ参照は一つのコレクション内で重複登録しない。名前を付けて複数のコレクションを保存し、アプリを閉じても残る。BGM音楽用、静止画スライドショー用など用途別に独立して管理する。同じファイルを別々のコレクションへ登録することはできる。
順序付き集合と順序なしを選択可能にし、スライドショー・連続再生の順序もコレクションに従う。
テキストのインポート・エクスポートを初回に含める。フォルダの内容をimport時に再帰展開しない。
元ファイルを変更せず参照だけを外す操作と、元ファイルをごみ箱へ移す操作を明確に分ける。

## 操作案

- 本棚ツールバーと同様の独立した「コレクション」ツールバーを設ける。追加先コンボと `追加` / `開く` を常設し、コンボは対象選択だけを行う。追加先はstable IDで保存し、管理画面の行と現在表示中の一覧から独立させる。作成・名前変更・削除・追加先指定・固定は管理画面で行い、既存本棚のデータ所有やコピー型の製本処理は混同しない。
- `展開` と展開中の `折りたたみ` では、管理画面で固定したコレクションだけをショートカットとして並べる。左クリックで開き、右クリックでそのコレクションへ参照を追加する。チェック済み項目があればカーソル位置より優先する。旧版の保存値`プルダウン`は読み込めるが、本棚と同じ`展開`へ正規化する。管理画面にentry一覧は置かず、内容はメイン一覧で表示する。
- 上部の同格な`コレクション`メニューを管理と内容操作の入口にする。`追加` / `開く`は保存した追加先を対象とし、import / export、手動順 / 通常ソート、専用並べ替え画面は現在表示中のexact Collection rootを対象とする。参照外しはrootの通常Delete / context commandで行う。管理画面を開く、行を名前変更・固定する操作や、追加先ではない行を削除する操作は、追加先や表示中一覧を勝手に切り替えない。追加先そのものを削除した場合だけ、authoritative Ready catalogから残る先頭のコレクションへfallbackし、空なら追加先なしにする。
- コレクションを開くと既存のサムネイル/詳細一覧を使い、ヘッダにコレクション名と並びを表示する。
- コレクションrootから登録Folder / ZIP / PDFを開いた場合は、そのentryを戻り先ownerとして保持する。
  配下の子フォルダ移動、同一フォルダの並べ替え・外部更新reloadはこのownerを引き継ぎ、途中で
  collection revisionが進んでも現在の物理表示を置き換えない。アドレス入力、履歴、お気に入り等の
  独立した物理移動は、読込成功時にcollection ownerを退役させる。読込失敗・取消・stale非同期結果では
  surfaceだけを切り替えず、元の一覧をそのまま保つ。
- コレクションrootの画像・本・動画サムネイルは通常一覧と同じproducerを新しいitems generationへ
  起動する。複数フォルダを横断するためcacheと動画sidecarは正規化full pathで識別し、別フォルダの
  同名ファイルを混同しない。動画はpin、同名画像、Shellの既存優先順位を維持する。
- 「手動順」では登録順を初期順とし、本棚のページ並べ替えと同じ専用サムネイル画面で単一 / 複数選択、ドラッグ、左右移動を提供する。保存はactorのlatest full manual entry列へstable entry ID順を送る。競合時は編集中の順を保持し、明示的な再読込または破棄でだけ手放す。
- 「通常ソート」は名前・日付・サイズ等、一覧で対応する並びを選ぶ。手動順を上書きしない。手動の並べ替え操作は手動順のときだけ提供する。
- 新規追加は保存された手動順の末尾へ追加する。通常ソート中の表示位置はソート結果に従う。
- 参照を外すメニュー名は「コレクションから外す」。コレクション全体の削除も定義と参照だけを削除する。
- 「元の場所を開く」は明示的に実フォルダへ移る操作として分離する。
- 見つからない参照は一覧に残し「見つかりません」と表示する。UIから自動 / 推測再リンクは行わず、登録解除して正しい参照を再追加する。既存保存参照やactorの移行用stable IDを変更しない。

## 閲覧・再生（通常フォルダのコード照合）

Sol/xhigh独立担当が2026-09-14に現コードを読んで確認した。実機での観測とは区別する。
通常の混在フォルダでも、画像・動画とZIP/PDFの全ページが一続きの列になるわけではない。

| 操作 | 現在の通常フォルダ | コレクションの仕様案 |
| --- | --- | --- |
| 画像の次/前 | Image/Video/Audioだけを現在の表示順から選び、未openのFolder/ZIP/PDFは飛ばす | 同じ抽出をコレクションの有効順で行う。元フォルダの隣接項目へ逸れない |
| 本を開く | 選択した本を別のページ一覧として開く | 同じloaderと本のページ順を使い、戻り先をコレクションentryにする |
| 本の最後 | 通常のページ送りでは次の本へ自動進入せず境界案内 | 同じ。親entryを自動展開して全ページを一列にしない |
| 本を閉じる | auto fullscreen設定で親一覧/本の一覧への戻り先が変わる。BSは本の一覧 | 同じ設定・キーの意味を維持し、親一覧へ戻る場合はコレクションの選択と位置を復元 |
| スライドショー | 静止画だけ。動画/音声と未open本は飛ばす。末尾はStop/Loop/NextFolder設定 | 静止画の抽出は同じ。有効順はコレクション。NextFolderは登録されたフォルダ/本の現在の有効順で次へ進む（利用者承認済み） |
| 動画/音声の連続再生 | 動画は次動画、音声は次音声。通常Continuousは末尾停止、ContinuousLoopは同一覧先頭 | 同じ媒体別抽出と終端規則をコレクション内で適用 |
| Ctrl+上下 | 一覧順ではなく物理folder treeのDFS。画像入りフォルダ/本を別nodeとして横断 | 登録されたフォルダ/本を最新の有効順で横断する（利用者承認済み）。登録外の物理的な隣接フォルダへ逸れない |

根拠: `ui_helpers.rs::adjacent_navigable_idx` とslideshow helper、`app.rs`のcontainer open/closeとmedia EOF、`fullscreen-navigation-consistency.md`。一覧のカテゴリ別配置と詳細表示orderは既存の正本を参照する。コレクションの手動順ではカテゴリ別に再配置して手動順を壊さないことを別途設計する。

### 横断範囲と再生中の編集

通常の操作対象は上表のように揃えられるが、Ctrl+上下やスライドショーの「次のフォルダ」は、通常一覧でも表示順とは異なる物理DFSを使っている。コレクションにはこのDFSがそのまま対応しない。
**コレクションに登録されたフォルダ/本を登録の有効順で横断する**方針は、Ctrl+上下とスライドショーのNextFolderとも利用者承認済み。登録フォルダの子を自動で外側の横断リストへ再帰追加する意味にはしない。通常のページ送りで本の終端から次の本へ自動進入する動作は追加せず、スライドショーでは明示されたNextFolder設定に従う。

再生中の一覧編集は**次の項目を選ぶ時点で最新の一覧を使う**。現在再生中のファイル参照を最新の有効順で探し、そこから次の再生対象を選ぶ。現在の参照が削除されていれば一覧先頭の再生対象から始める。動画は動画、音声は音声、スライドショーは静止画という対象抽出は既存どおり。現在の参照が末尾に残っている場合は従来の停止/ループ設定に従い、「参照が無い」場合の先頭開始と区別する。対象が0件なら停止する。

例: 音声Aを再生中に[A,B,C]を[A,C,B]へ変えたら次はC。Aを外して[C,B]にした場合も先頭のC。現在の再生を一覧編集だけで中断しない。別コレクションを編集しても再生中のコレクションには影響しない。参照の同定と一覧revisionの公開・次項目選択の境界は実装前に独立設計レビューする。旧indexだけで次を選ばず、一覧更新のためにUIを同期I/Oで待たせない。

参照を外しても元ファイルは消えない。実ファイルの削除・失踪は既存の失敗表示/スキップ規則に従う。大量のページを初期化時に全decode/全展開しない。

## テキスト入出力（初回必須）

- UTF-8（BOMあり/なし）、CRLF/LF、1行1パス。絶対パスとテキストの置き場所からの相対パス。
- 空行を無視し、行全体を囲む引用符はWindowsのパスのコピーに対応する。`#` はコメントにしない。
- 環境変数・ワイルドカード・コマンドを展開せず、URL/デバイスパスは拒否する。
- 最初のpreviewは文字列の解析のみ。対象パスの存在確認・リンク解決・サムネイル生成は行わない。
- 件数、追加先、解決したパス、無効行、重複行、ネットワーク参照を示して確認後に登録・アクセスする。件数はparser workerがpreviewと同時に確定し、確認画面の残り枠は説明値だけとする。候補を残り枠で先に切り詰めず、重複・検証・容量の最終判定はactorが行う。UNC、割当ドライブ、reparse経由の境界は既存のパス実装と照合して設計する。
- 同一パスの重複は最初の位置を保持。missingも保持。外部テキストの変更に自動追従しない。
- 解析/登録/存在確認はworkerで処理し、進捗と取消を提供する。
- exportはUTF-8 BOM付きの絶対パス1行1件。提案は現在のコレクション表示順（全件、ローカル絞り込みは除外条件にしない）を出力し、missingと日本語pathも含める。clipboardは変更しない。タグや補正設定、元ファイルのバックアップではない。

## 実装前に固定する境界

- 初回対象は実ファイル・実フォルダ・アーカイブ本体。コレクション入れ子、ZIP/PDF内の任意ページ単独登録は対象外。
- 専用DBとworkerに定義・stable entry ID・source path・手動orderを所有させ、設定配列やUI threadの同期I/Oへ置かない。
- `TopLevelGridSurface` に明示的surfaceを設け、一覧の戻り先・閲覧順・非同期結果の世代を同じcontextで所有する。
- 当初の Remote には集約結果を指す Collection という名称だけがあり、手動保存コレクションは別の型・保存元として実装した。既存の集約 payload を永続定義と見なさない。
- mIV内rename/moveは既存path migrationへ統合。失敗時に参照だけ進むことがないようtransaction境界を検討する。外部移動は推測追跡しない。
- 元ファイル削除は既存の確認/ごみ箱経路を維持し、コレクションから外す操作とは混同しない。
- コレクション直下で通常の <kbd>Delete</kbd> または「コレクションから外す」を使うと、checked 優先、
  なければ selected の参照登録だけを解除する。読み込み中など参照 binding を確定できない時は何も削除せず通知する。
  物理 child 一覧の <kbd>Delete</kbd> は従来どおり元ファイル操作である。直下から元ファイルを明示操作する場合は
  「元ファイルをゴミ箱へ移動…」または「元ファイルのWindowsメニュー」を選ぶ。Windowsメニュー内の操作対象は
  リンク先の元ファイルであり、関連付け、プロパティ、Shell拡張を含む既存機能を維持する。
- 別窓、比較、見開き、AI/補正、検索への移動、Remoteの閲覧権限と戻り先を維持する。

### 朝回答の独立設計照合

Sol/xhigh独立担当と親が以下の境界を照合した。製品実装はまだ行っていない。

- ツールバーは`ToolbarSectionId`、表示順、展開/折りたたみ等の共通機構だけを利用する。新しいCollections専用sectionと設定を持ち、本棚の`active_book_name`、製本キャッシュやコピー処理を流用しない。既存の保存済みtoolbar orderへの新section補完は既存のfallback契約を維持する。
- DB/workerがcollection ID、entry ID、参照key、有効順、revisionを含むimmutableな一覧を公開する。再生中のcollection IDと現在の参照はviewer/Remote sessionごとに所有し、PC側で別のコレクションを開いても切り替えない。
- 次の対象は最新一覧でentry IDを探し、無ければ登録の重複判定と同じ正規化済みsource keyで現在のファイル参照を探す。同じファイルを削除して再登録した場合も、そこに参照があればその次。両方無いときだけ先頭にする。mIV内rename/moveはstable IDで追従する。keyはsourceの種類も含め、DB/workerで生成・保持し、UIでstatやcanonicalizeをしない。
- 既存のindexだけによるmedia navigationに特例を継ぎ足さず、次項目要求のsourceをGrid/Collectionで型として区別する。collection ID・entry ID・revisionを非同期結果へ持ち運び、結果適用時に古い一覧/別contextの結果を採用しない。
- 登録folder/bookを開いた後の内部ページ・ファイル一覧は別の子contextとして維持する。子ファイルがコレクション直下に登録されていないことを削除扱いしない。Ctrl+上下は開いた登録entryのoriginから外側の最新順を解決する。

再生中の並べ替え・削除・同参照再追加・rename、次項目解決中の一覧更新、別collectionの編集、複数窓/Remoteの独立、直接登録した媒体とfolder/book内の媒体、末尾Stop/Loop、空一覧を回帰対象にする。

## 利用者の判断（2026-09-16、v4.0.0 出荷前レビュー後）

[出荷前レビュー](review-v4.0.0/README.md) の判断待ち項目への利用者回答と、ClaudeCode の提案。2026-09-17 に提案 2・3・5 を利用者が承認し、確定した。
修正は Codex の制限回復後に行い、実装単位は [実装計画 §23](collection-implementation-plan.md#23-v400-出荷前レビュー後の修正計画2026-09-16) を正本とする。

1. **確定: 手動順をソート UI の一級項目にする。** ツールバーのソートボタン列 / プルダウンと表示メニューの
   「ソート順」に「手動順」を追加し、コレクション直下では定義の `order_mode` / `standard_sort` から選択表示を
   導く。選択時は global の `settings.sort_order` を書き換えず actor の `SetOrder` だけを送る。上部
   「コレクション」メニューの「並び順」は残し、同じ 1 つの述語から表示を導く。手動順のときは列ヘッダソートを
   ページ順固定として無効化し、通常ソートのときはコレクションを開く時点で列ヘッダソートをツールバー所有へ戻す
   （レビュー A-1 / A-2、案 C）。
2. **確定: シャッフルを追加する。設計は下記「シャッフル順の設計」（2026-09-17 確定）。** 動画側の
   連続再生トグルに第 4 状態を足すのではなく、コレクションの並び順として「シャッフル」を持つ。手動順は保存
   したまま、シャッフル順は定義が持つ seed から決定的に導くため、次の曲が一覧に見え、前後移動は通常の隣接移動に
   なり、選び直すと seed が変わって並び直る。ループは既存の「連続再生 + ループ」設定に従う。静止画の
   スライドショーも同じ有効順を使うため追加費用なくシャッフルできるが、画像向けの専用 UI は設けない。
   通常フォルダ向けのセッション限定シャッフルは v4.x の候補。
3. **確定（2026-09-17）: 1 コレクションあたり 10,000 件を上限にする。** 本棚の 1 冊 9,999 ページ（`books.rs` の
   `MAX_BOOK_PAGES`）と同じ桁。追加 / 取り込みで超える分は理由付きで拒否し、取り込み確認画面は上限超過を
   全行描画せずに示す。Remote の永続 root entry prefix は同じ 10,000 件定数から導き、
   catalog の 100,000 件と既存 aggregate の 100,000 件は別上限に保つ。
   上限を設けても、ページ送りごとの全件再 stat（レビュー T3）は対象 1 件の確認へ縮める。
4. **確定（仕様）: 専用並べ替え画面はキャンセルを持たず、閉じる時に保存する。** 本棚の並べ替えモードが
   「閉じる時は保存」（[compile-book-plan.md §2.2](compile-book-plan.md)）であるのと同型。Conflict 時だけ

### シャッフル順の設計（2026-09-16 提案、2026-09-17 確定）

- `CollectionOrderMode` に `Shuffle` を加え、定義に `shuffle_seed: u64` を持つ。手動 position は変更しない。
  **2026-09-19 設計補正**: 未リリースでも試用中の DB があるため、移行前バックアップと既存データを保持する
  原子的な schema migration を行う。seed は u64 全域を往復できる保存形式を固定する。
- 有効順は prepare worker が `SHA-256(shuffle_seed の little-endian 8 bytes || entry ID の UUID raw 16 bytes)`
  のdigest辞書順、同値時にはUUID raw bytes昇順で作る。seed はDBに16桁hex TEXTとして保存し、u64全域を
  往復する。entry ID は stable UUID なので、
  登録・解除・名前変更・再生中の編集があっても残る entry の相対順は変わらず、新規 entry は seed で決まる位置へ
  入る。旧 index に依存しない。
- 次 / 前 / EOF / Ctrl+↑↓ / スライドショーは既存の latest-next reducer をそのまま使う（有効順が変わるだけ）。
  末尾の折り返しは `VideoContinuousMode::ContinuousLoop` に従い、`Continuous` は末尾で停止、`Off` は 1 件だけ。
- UI: ソート選択肢「シャッフル」を選ぶと `SetOrder { mode: Shuffle, sort }` を送り、collection actor の
  DB更新境界で新規seedを生成・永続化する。既に Shuffle のときに再選択すると seed を引き直す
  （「並び直す」）。手動順 / 通常ソートへ戻すと seed は保持したまま無視する。
- 一覧はシャッフル順で表示するので次の曲が見える。専用並べ替え画面は手動順のときだけ（現行どおり）。
- Remote は prepared snapshot の有効順を読むだけで追従する。wire に order mode を載せる箇所は Shuffle を通す。
  Web の表示分岐と IPC の版も更新する。hash の方式と同値時の entry ID tie-break を明示し、実行間で順序を保つ。
- Manual / Shuffle は詳細表示の列ヘッダによる一時並べ替えを無効にするが、ツールバー / メニューでの
  並び順選択は有効に保つ。Standard の列ヘッダソートは表示限定で、再生・書き出し・Remote の有効順は変えない。
  Collection root の見開き・seek・Home / End・slideshow は installed items の有効順（local filter の可視投影）を
  使い、列ヘッダ順は一覧の描画と選択に限定する。PhysicalSource 子と通常一覧の読み順は従来の表示順を使う。
  表示と選択 target は同じ採用 revision に束ね、読み込み中・更新待ちは理由付きで無効化する。
  同一 root の order 切替でも列ソートを戻し、新 order と items の採用後に詳細表示順を整合させる。
- 将来候補: ループ折り返し時に seed を引き直す設定（毎周違う順にしたい場合）。
- 回帰: seed 固定で順序が決定的、entry 追加 / 削除後も残りの相対順が不変、再選択で seed が変わる、
  Remote と PC の順序一致、Off / Continuous / ContinuousLoop の終端規則。
