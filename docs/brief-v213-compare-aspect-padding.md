# ブリーフ: 縦横比が違う 2 枚を比較すると、余白に現在ページが透ける

対象: v2.13.0 出荷ブロッカー (最後の 1 件)。実装 = Codex Sol /
レビュー・検収 = ClaudeCode / 実機確認 = 利用者。

前提: master (`2094e469` 以降)。着手前に `git log --oneline -3` で HEAD を確認すること。

---

## 1. 原因は確定した (実機ログ + 利用者の切り分け)

**⚠ 前回の「4×4 の縮退ペア」という見立ては誤りだった。** そこを直しても症状は消えていない
(利用者確認 2026-08-10)。実際はこうである。

`[compare-geometry]` ログ (利用者実機):

```
key=13 cur=34 pin=32 target=3584x4608   ← ページ 34 は縦長
key=19 cur=35 pin=32 target=4096x4096   ← ページ 35 は正方形
```

**合成キャンバス (`target_size`) は current ページ自身の寸法**になっている。したがって
current が正方形のページに来ると合成も正方形へ広がり、縦長のピンド画像はその中に収まるよう
縮小される。**その余った左右に current 側が見えている。**

利用者の切り分け (2026-08-10):

- **縦横比が違うページのときだけ起きる**
- **同じ縦横比のページどうしなら起きない**

利用者の言葉では「揃える前後の両方が表示され、揃える前のはみ出した部分が見えている」。
見え方は `[current | pinned | current]`。

## 2. 直すこと

**ピンド側の余白に current を透けさせない。** 余白は単色 (背景色) で埋める。
結果は `[黒 | pinned | current]` になり、「ピンド画像はこの範囲」という意味が読める。

- `target_size` の決め方 (current ページの寸法) は**変えなくてよい**。変えると同じ縦横比の
  ペアの見た目まで動く
- 余白の色は**既存のフルスクリーン背景と同じもの**を使う。新しい色定数を作らない
- **`Wipe` / `Diff` / `PinnedNormal` の 3 モードすべて**で同じにすること。
  差分表示で余白が「差なし」に見えるか「差あり」に見えるかも確認して報告する

### 2.1 なぜ余白が current になっているのかを先に確認すること

ピンド側の RGBA を組む所で、**current のバッファを土台にしてピンドを上書きしている**か、
**未書き込み領域が透明で下の current が透ける**かのどちらかのはず。**どちらかを確定してから
直す**こと。両方に当てはまる直し方 (「余白を明示的に塗る」) でよいが、根拠は報告する。

## 3. やらないこと

- `target_size` を union へ変える等、合成キャンバスの決め方を変えること
  (同じ縦横比のペアの見た目が動く。今回の症状には不要)
- 縦横比が違うペアで比較自体を禁止・警告すること
- 前回入れた `ComparePreparationState` を戻すこと (あれ自体は害がないので残す)

  画素を直接見る単体テストで固定する)
- 同じ縦横比のペアでは合成バッファが従来と 1 画素も変わらないこと
