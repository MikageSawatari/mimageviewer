## 2. 仕様

### 2.1 設定 (2 項目、独立)

| 設定 | 値 | 既定 |
| --- | --- | --- |
| 上下キー (修飾なし ↑↓) | ページ送り / ページ内スクロール | ページ送り |
| 通常のホイール (修飾なし) | ページ送り / ページ内スクロール | ページ送り |

- 既定は現行と完全に同じ。既定のままでは新しい経路を一切通らない。
- 共通設定のみ (`Settings`)。お気に入り別の表示状態・本ごとの設定には入れない。設定の転送は
  `fullscreen_horizontal_cursor_direction` と同じ分類。**未リリースの新設定**なので migration 不要 (serde default)。
- 環境設定「見開き / 連結」の「カーソルキー左右の方向」の直後に 2 行。説明 1 行:
  「ページ単位の表示で、画像が画面からはみ出す分だけ動かします。ページの端で止まり、次のページへは送りません。」
- 移動量は既存の「連結読みのスクロール量」(ホイール 1 ノッチ 20% / 矢印キー 1 回 16%、表示領域の大きさ基準) を共用し、
  見出しを「スクロール量 (連結読み・ページ内スクロール)」へ改める。新しい量の設定は作らない (判断事項 Q3)。

### 2.2 ページ内スクロールが働く面 (1 つの述語)

`App::fs_in_page_scroll_surface()` を 1 か所に置き、↑↓・ホイール・新しい `KeyAction` の全部がこれを使う。
成立条件 (既存の `plan_fs_canvas_click` の `ordinary_still` と同じ領域):

- フルスクリーンの現在項目がページを持つ静止画 (画像・ZIP 内画像・PDF ページ等。`GridItem::has_page_data`)。動画・音声・音楽ビューは除く
- `reading_flow.is_paged()` (連結読みでない)
- `fs_zoom_owner() == FsZoomOwner::Image` (Z ズーム・360 度・3D 写真・分析モードを除く)
- 比較表示 Off、表示トリム編集中でない、オーバーレイ編集 (消しゴム・隠蔽・補正レイヤー・切り取り・テキスト・SNS 分割) でない
- ページ一覧 (O) や modal・TextInput・IME が先に入力を持つ場合は、既存どおりそちらが先に消費するのでここへ来ない

成立しないとき、設定がページ内スクロールでも ↑↓・ホイールは**現行の経路のまま** (ページ送り・連結のスクロール・ズーム等)。
「設定で選んだ文脈以外の固定矢印を変更しない」(backlog) をこの述語 1 つで守る。

### 2.3 スクロール範囲と 1 回の移動 (純関数)

前 frame の `FullscreenPageLayout` から、現在の表示単位 (単ページ / 見開き全体 / 分割の片側) の矩形 `unit` と viewport を得る。
`unit` は §1.726 と同じく描いたページの paint rect の和 (見開きで描く白 companion を含む。Vacant 枠は含めない)。
同じ helper を共用し、表示単位矩形の計算を 2 か所に書かない。

軸ごとのスクロール範囲 (pan 空間、zoom は変えない):

- `unit` がその軸ではみ出す (`unit.height() > viewport.height()`) ときだけ範囲を持つ。
  縦: `pan.y ∈ [viewport.bottom − (unit.bottom − pan₀.y), viewport.top − (unit.top − pan₀.y)]`
  (`pan₀` はその layout を描いたときの pan。横も同様)。
- はみ出さない軸は動かさない (その方向の入力は何もしない)。

1 回の移動 (`step` 画素、向き `±`):

- 目標 = `pan + step` を範囲へ寄せる。ただし**範囲の外側へは押し出さない**:
  すでにその向きの端以上 (手動ドラッグで端の外へ出している場合を含む) なら何もしない。
  範囲の内側から端を越える移動は端で止める。範囲の外から内側へ向かう移動は、その向きへ step だけ進み、端を越えない。
- 書き込みは `set_fs_pan_from_input` を通す (§1.726 の要求を消す・既存の緩い clamp を通す)。
  端に揃えた位置は 48px 制約の内側なので、clamp で値は変わらない。
- 移動は即時 (連結読みのキー・ホイールと同じ。アニメーションしない)。

使う geometry が今の表示単位のものでない frame では、入力を消費して何もしない:
layout の種類が `Single` / `Spread` でない、layout のページに現在の表示単位のページが無い (holdover・読み込み待ちを描いている)、
ページ送りの navigation sequence・紙めくり演出が進行中 (`page_turn_barrier_active()` 等の既存の判定)。
キー入力は 1 frame で寿命が尽きるので、取りこぼした分を後から適用しない (既存のページ送りと同じ方針)。

### 2.4 上下キー = ページ内スクロール

- 修飾なし ↓ = 下を見る (画像が上へ動く)、↑ = 上を見る。1 回 = 表示領域の高さ × 矢印キーのスクロール量 (既定 16%)。
- 長押しは OS のキーリピートのまま 1 リピート 1 回 (`SinglePerFrame`、連結読みの ↑↓ と同じ)。
- 縦の端で止まる。次のページへは送らない。縦にはみ出していないページでは何もしない (判断事項 Q1)。
- **Shift+↑↓ は現行どおりページ送り** (スタックのフラット読書中はスタックジャンプ)。ページ内スクロールを選んだ人の
  キーでのページ送りは ←→・Shift+↑↓・PageUp/PageDown が残る。
- ←→ は変えない (常にページ送り。「カーソルキー左右の方向」も従来どおり)。

### 2.5 通常のホイール = ページ内スクロール

- 修飾なしのホイールの縦成分で縦にスクロール。1 ノッチ = 表示領域の高さ × ホイールのスクロール量 (既定 20%)。
  量の換算は連結読みの `continuous_reading_wheel_delta_px` と同じ式 (高精度ホイール・タッチパッドの端数もそのまま比例)。
- Ctrl+ホイール (ズーム)、Shift+ホイール・Alt+ホイール (現行どおりページ送り)、パネル・ナビゲータ・シークバー上のホイールは変えない。
  Shift+ホイールはホイールでのページ送りの逃げ道として残す。
- 端で止まる。はみ出していないページでは何もしない (Q1)。
- 同じ frame にホイールのページ送りとクリックが混ざる既存の調停 (`FsWheelFrameProposal`) では、
  ページ内スクロールは「ナビゲーションを作らない wheel action」として扱い、`fs_wheel_action_requests_navigation` の
  答えを 1 か所で変える (ズームと同じ分類)。

### 2.6 新しい KeyAction (既定キーなし)

| Action | 説明 (description) | 既定 |
| --- | --- | --- |
| `FsPageNScrollNext` | ページ内を N 字の順に次へスクロールする | なし |
| `FsPageNScrollPrev` | ページ内を N 字の順に前へスクロールする | なし |
| `FsPageScrollUp` / `Down` / `Left` / `Right` | ページ内を上 / 下 / 左 / 右へスクロールする | なし (判断事項 Q4) |

- context `FsImage`、trigger `Press` (リピート可)、`SinglePerFrame`。`ini_name` / `description` / `context` / `trigger` /
  `default_chords` (空) / `ALL_ACTIONS` / `docs/keymap.ini.default` (`# Action = none`) を揃える。
- 面 (§2.2) が成立しないときは**キーを消費しない** (§1.470 の `FsZoomIn` と同じ。同じキーを編集モード等が使える)。
- 4 方向の移動量は上下キーと同じ (矢印キーのスクロール量)。左右も端で止まり、綴じ方向で反転しない (画面の左右)。
- 上下キーの設定がページ送りでも、これらの Action は使える (キーを割り当てた人だけが使う)。
- リング・ジェスチャ・マウスボタン・ゲームパッドには今回足さない (キーボード専用。`ring-keyaction-parity.md` は KeyAction → Ring の
  方向を要求しないことを確認する)。

### 2.7 N 字スクロール

縦を優先して読み、縦の端で綴じ方向へ 1 列進み、反対側の縦端から読む (NeeView の N 字と同じ順序)。

- 次 (`FsPageNScrollNext`):
  1. 縦にはみ出していて下端でない → 下へ 1 画面分 (表示領域の高さ × 85%) 進む。下端で止める。
  2. 縦の下端 (または縦にはみ出していない) で、横にはみ出していて読み終わりの横端でない → 読む方向へ 1 画面分 (幅 × 85%) 進み、縦は上端へ。
     右→左の本は左へ、左→右は右へ進む。
  3. どちらも端 → 何もしない (ページは送らない)。
- 前 (`FsPageNScrollPrev`): 逆順。上へ戻り、上端なら読み始め側へ 1 列戻って縦は下端へ。
- 85% は連結読みの PageUp/PageDown と同じ定数 (`VERTICAL_READING_PAGE_SCROLL_FRAC`)。15% を前の画面と重ねる (判断事項 Q3)。
- 読書方向は §1.726 と同じ源 (`spread_mode.reading_direction().unwrap_or(self.reading_direction)`)。
- 新しい状態を持たない。毎回、今の pan と範囲から次の位置を決める純関数 (`n_scroll_target(pan, ranges, dir, steps, forward)`)。
  途中でドラッグ・ホイールで動かしても、その位置から続く。
- 「読み始め」(§1.726) と組み合わせると、ページを開いた位置 = N 字の始点になる。既定の「中央」では中央の列から始まる。
  マニュアルに組み合わせを 1 行書く。

### 2.9 状態の組み合わせを減らす検討 (CLAUDE.md「設計の簡素化」)

- **新しい実行時状態を持たない。** 足すのは保存する設定 2 つと、状態を持たない純関数だけ。N 字の「今どの列か」も持たず、
  今の pan から毎回求める。context 固有の新しいフィールドが無いので、detached / swap / 駐車中の reset に新しい経路が要らない。
- **面の判定を 1 つの述語にする。** ↑↓・ホイール・新 Action が同じ述語を使い、モードごとの除外を書き分けない。
- **端でページを送らない。** 「端ならページ送り」を足すと、端の判定・送った直後の初期位置・長押しで端を越える連続送りの組み合わせが増える。
  利用者決定どおり送らない。
- **アニメーションしない。** 連結読みと同じ即時移動にし、スクロール中の割り込み (ページ送り・ズーム・別入力) の組み合わせを作らない。
- **使える geometry が無い frame は捨てる。** 読み込み待ち・演出中に入力を溜めて後で適用する仕組みを作らない (既存のページ送りの方針と同じ)。
- **移動量の設定を増やさない。** 連結読みの量を共用し、N 字は既存の 85% 定数。
- 採らなかった案: 「端に着いたらページを送る」(ZipPla・SumatraPDF・NeeView のホイール Type A 方式) は利用者決定により採らない。
  「スクロール中だけ別の表示状態に入る」案は、終了条件と他モードとの排他が増えるので採らない。
- まれな失敗は既定の割り切り (このページ内スクロールは保存データを持たないので該当なし)。

## 3. 判断事項 (利用者に決めてもらう。推奨を先頭に)

- **Q1 画面に収まる画像での ↑↓・ホイール**: (推奨) 何もしない。端で止める方針と同じで、設定を選んだ人の操作が予測どおりになる。
  代案: その軸がはみ出していないときだけページを送る (ZipPla・SumatraPDF に近い)。ページ全体フィットで使う人には便利だが、
  同じキーがページによって意味を変える。
- **Q2 スクロール後のクリック送り (§1.745)**: (推奨) 現行の規則のまま「動かした」扱いにし、単クリックでは送らない
  (2026-11-15 の利用者決定「パン後は単クリックを止める」と同じ扱いで、ダブルクリックで中央へ戻せる)。
  代案: キー・ホイールのページ内スクロールで動かした位置は自動配置と同じ扱いにし、クリックで送れるようにする
  (その場合、スクロール後のダブルクリックは 2 ページ送りになる)。
- **Q3 移動量**: (推奨) 連結読みのスクロール量 (ホイール 20%・キー 16%) を共用し、N 字は 1 画面の 85% (15% 重ね)。
  代案: ページ内スクロール専用の量・N 字の重なり幅を設定に足す。
- **Q4 含める操作の範囲**: (推奨) N 字の前後 2 つと 4 方向の個別スクロール 4 つを、どれも既定キーなしで足す。
  端・中央への位置合わせ (NeeView の「上端へ」等) は今回入れない (Home/End はページ移動のまま)。
  代案: N 字だけにする / 位置合わせも入れる / N 字に既定キーを割り当てる (空いている候補は少なく、既存の割り当てと競合しやすい)。
- **Q5 ゲームパッドの方向キー上下**: (推奨) 今回は変えない。代案: 上下キーの設定に合わせる。

## 5. 検証

- 純関数: 縦だけ / 横だけ / 両方はみ出す、収まる軸は不動、端で止まる、端の外 (手動ドラッグ後) から外へは動かない・内へは動く、
  見開き (白 companion 込み)、回転 90 度、viewport 原点が 0 でない (HUD 予約)。
- N 字: LTR・RTL での列の進み方、下端→次の列の上端、最後の列の下端で何もしない、前方向の逆順、縦だけ・横だけはみ出す場合。
- App の handler レベル: 設定 = ページ送りでは現行どおり `spread_page_nav` (回帰)、ページ内スクロールでは pan だけ変わり
