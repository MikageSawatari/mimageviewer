# ページ内スクロールと N 字スクロール (§1.474)

- 状態: **設計 r2・独立設計レビュー r1 (REVISE、P2×7・P3×2) を反映、再レビュー前・利用者判断待ち** (2026-11-18)。ブランチ `feat-474-page-scroll`。
- 要望: 5ch >>642・>>767。通常のページ単位表示で、次のページを見せずに今のページ内を矢印キーやホイールで動かしたい。
  NeeView のような N 字スクロールもほしい。
- 方針 (2026-11-12 利用者決定、backlog §1.474): 修飾なし ↑↓ と通常のホイールを、それぞれ独立に
  「ページ送り (既定) / ページ内スクロール」から選べる。N 字の前方向・次方向を `KeyAction` で割り当て可能にする。
  ページ内で完結し、自動でページは送らない。
- 観測の出どころ: 本書の「現状」はすべてコード読み (worktree 96ed160a0) と独立レビューのコード照合。実画面での確認はしていない。

## 2. 仕様

### 2.1 設定 (2 項目、独立)

| 設定 | 値 | 既定 |
| --- | --- | --- |
| 上下キー (修飾なし ↑↓) | ページ送り / ページ内スクロール | ページ送り |
| 通常のホイール | ページ送り / ページ内スクロール | ページ送り |

- 既定は現行と完全に同じ。既定のままでは新しい経路を一切通らない。
- 共通設定のみ (`Settings`)。お気に入り別の表示状態・本ごとの設定には入れない。設定の転送は
  `fullscreen_horizontal_cursor_direction` と同じ分類。**未リリースの新設定**なので migration 不要 (serde default)。
- 環境設定「見開き / 連結」の「カーソルキー左右の方向」の直後に 2 行。説明 1 行:
  「ページ単位の表示で、画像が画面からはみ出す分だけ動かします。ページの端で止まり、次のページへは送りません。」
- 移動量は既存の「連結読みのスクロール量」(ホイール 1 ノッチ 20% / 矢印キー 1 回 16%、表示領域の大きさ基準) を共用し、
  見出しを「スクロール量 (連結読み・ページ内スクロール)」へ改める。新しい量の設定は作らない (判断事項 Q3)。

### 2.2 どこで置き換えるか: 入力の所有 → 置き換え点 → 面の述語

r1 では「面の述語 1 つ」で分岐する案だったが、前面 UI の入力所有と、モード外のための従来経路への戻しが混ざっていた (レビュー r1 P2-7)。
次の 3 段に分ける。

1. **入力の所有 (変更しない)**: modal・TextInput・IME・ポップアップ・context menu (native の OS ループと egui fallback の両方)・
   ナビゲータ・情報パネル・ページ一覧 (O)・編集ツールのパネルなど、前面 UI が入力を持つ判定は既存のまま。
   そこで消費・遮断される入力は置き換え点に来ない。新しい経路は前面 UI の入力を背面へ渡さない。
2. **置き換え点 (2 か所だけ)**: 既存コードが「その入力でページ送りをする」と決めた地点で、送る代わりにスクロールする。
   - 上下キー: `consume_arrow` の結果のうち **plain の ↑↓ に一致した結果だけ**。`nav_next` / `nav_prev` を作る前に振り分ける。
     Shift+↑↓ に一致した結果・スタックジャンプ・動画/音声の `VideoNextFile` 等は対象外。
   - ホイール: `fs_wheel_action_requests_navigation` が「送る」と答える、**修飾なしの** wheel action。
     ただし**シークバー上 (ドラッグ中でない hover) のホイールは置き換えず、現行どおりページ送り**。Alt+ホイールも送りのまま。
3. **面の述語** `App::fs_in_page_scroll_surface()` (1 か所、置き換え点の両方とスクロール用 `KeyAction` が使う):
   - 現在項目がページを持つ静止画 (`GridItem::has_page_data`)。動画・音声・音楽ビューは除く
   - `reading_flow.is_paged()`
   - `fs_zoom_owner() == FsZoomOwner::Image` (Z の照準・確定、360 度、3D 写真、分析を除く)
   - 比較表示 Off、表示トリム編集中でない、オーバーレイ編集でない、範囲キャプチャ選択中でない
   - fullscreen の context menu が開いていない (`fs_context_menu_idx.is_none()`)
   述語は `plan_fs_canvas_click` の `ordinary_still`・§1.726 の退役条件と同じ領域を表す。3 つを 1 つの helper に寄せられるかを
   実装時に確かめ、寄せられない差分があれば理由をコメントに残す。

述語が成立しないとき、または設定がページ送りのときは、置き換え点で何もせず**現行の経路のまま**送る。

### 2.3 スクロールの解き方: 同じ frame の幾何で 1 回 (レビュー r1 P2-1)

入力の時点では今の表示単位の幾何が分からない (キー処理は描画より先で、前 frame の layout は holdover・別 slice・
別の見開きの組・別 viewport のものかもしれない)。そこで §1.726 と同じく、**描画準備でその frame の表示単位を確定した消費箇所**で解く。

- **要求**: 置き換え点・スクロール用 `KeyAction` は、移動の意図だけを記録する。
  `FsInPageScrollIntent { viewport, frame_nr, kind }`、`kind` は `Lines { dx, dy }` (キー・4 方向: 表示領域比の段数、ホイール: 画素) または
  `NScroll { forward }`。同じ frame に複数あれば `Lines` は加算、`NScroll` は最後の 1 つ (`SinglePerFrame` なので通常 1 つ)。
- **寿命は 1 pass**: 作った viewport・frame 番号と一致する、同じ pass の描画準備でだけ解く。一致しない・その pass で解かれなかった要求は捨てる。
  後の frame へ持ち越さない (既存のページ送りの「入力を溜めない」方針)。置き場所は pass 内の値渡しを優先し、
  描画経路まで値を渡せない場合は context 所有の 1 フィールドに `viewport` / `frame_nr` を付けて照合する (どちらにしたかと理由を本書に記録)。
- **解く場所**: `resolve_fs_initial_placement` / `fs_initial_placement_pan` と同じ各消費箇所 (単ページ・見開きの通常経路と仮素材の経路)。
  条件は §1.726 と同じ: その frame で選んだ表示単位が current (holdover を描いていない)、素材と今の fit / view から幾何を解決できた。
  条件がそろわなければ要求を捨てる (pan 不変)。紙めくり演出・ページ送りの navigation sequence 中も捨てる。
- **§1.726 との順序**: スクロールの意図を記録する時点で利用者入力として `clear_fs_initial_placement_request()` を呼ぶ
  (既存の `set_fs_pan_from_input` と同じ扱い)。したがって同じ frame に初期配置要求とスクロール要求が並ぶことはない。
- **同じ frame のズーム**: Ctrl+ホイールなどで同じ frame に倍率が変わった場合も、解く時点の `fs_zoom` で幾何を解くので整合する。

### 2.4 スクロール範囲と 1 回の移動 (純関数)

解く箇所で、その frame の pan 0 の表示単位から次を求める (§1.726 の `zero_pan_unit` と viewport を共有する)。

- **外接矩形 `unit`**: 描くページの `paint_quad()` (clip 前) の四隅の外接矩形の和。自由回転 0 なら `paint_rect` と同じ。
  見開きで描く白 companion を含み、描かない Vacant 枠は含めない (レビュー r1 P2-4。§1.726 と同じ helper を、四隅の外接に直して共用する。
  自由回転は open で 0 に戻るかを実装時に確かめ、戻らない経路があれば §1.726 の読み始めも外接で解くことになるので本書に記録する)。
- **可視性の区間**: 実ページ (白 companion を除く) を 48px 以上見せる、既存の `clamp_fullscreen_pan_from_layout` と同じ制約を
  pan の区間として表す (`pan_correction_for_minimum_overlap` と同じ式)。
- **移動可能範囲 (軸ごと)**: `unit` がその軸ではみ出すときの端揃えの範囲
  (縦: `pan.y ∈ [viewport.bottom − unit.bottom, viewport.top − unit.top]`、横も同様) と可視性の区間の**共通部分**。
  共通部分が空なら可視性の区間を使う。はみ出さない軸は範囲なし (動かさない) (レビュー r1 P2-3)。
  共通部分を使うことで、白 companion 側の端へ揃えると実ページが画面外へ出る場合でも、setter に戻されて N 字が同じ列を繰り返すことがない。
- **1 回の移動**: 目標 = `pan + step`。範囲の外側へは押し出さない:
  その向きの端以上 (手動ドラッグで端の外にある場合を含む) なら何もしない。内側から端を越える移動は端で止める。
  外側から内側へ向かう移動は step だけ進み、端を越えない。
- **書き込み**: 既存の clamp を通しても値が変わらない位置 (上の共通部分の内側) を `fs_pan` に入れる。`fs_automatic_initial_view` は書き換えない。
- 移動は即時 (連結読みのキー・ホイールと同じ。アニメーションしない)。

### 2.5 上下キー = ページ内スクロール

- 修飾なし ↓ = 下を見る (画像が上へ動く)、↑ = 上を見る。1 回 = 表示領域の高さ × 矢印キーのスクロール量 (既定 16%)。
- 固定矢印の consume 契約を変えない: `consume_arrow` が返す 1 つの結果 (matched chord・first keydown / repeat・held・release 済み repeat) を
  **一度だけ消費して振り分ける**。first keydown は短い tap でも 1 回、release 済み repeat は動かさない、同 frame の複数 edge は 1 回
  (`SinglePerFrame`)。native / egui で二重に消費しない。長押しは OS のキーリピートで 1 リピート 1 回。
- 縦の端で止まる。次のページへは送らない。縦にはみ出していないページでは何もしない (§3 の既決事項 D1)。
- **Shift+↑↓ は現行どおりページ送り** (スタックのフラット読書中はスタックジャンプ)。ページ内スクロールを選んだ人の
  キーでのページ送りは ←→・Shift+↑↓・PageUp/PageDown が残る。
- ←→ は変えない (常にページ送り。「カーソルキー左右の方向」も従来どおり)。

### 2.6 通常のホイール = ページ内スクロール

- 修飾なしのホイールのデルタの向きに画像を動かす (egui の ScrollArea と同じ向き。ホイール下 = 下を見る)。
  縦 1 ノッチ = 表示領域の高さ × ホイールのスクロール量 (既定 20%)。換算は連結読みの `continuous_reading_wheel_delta_px` と同じ式で、
  高精度ホイール・タッチパッドの端数もそのまま比例させる。
- **横成分**: 横のチルト・タッチパッドの横・Shift+ホイール (egui が縦を横へ移す) の横成分は、横のページ内スクロールに使う
  (同じ量の換算を幅で行う。Shift+ホイール下 = 右側を見る)。現行では全画面でこの横成分は何もしないので、
  既定の設定のままでは挙動は変わらない (レビュー r1 P2-5 で現状を訂正)。
- **受付の閾値**: ページ送りの `wheel_y.abs() > 0.5` は変えない。ページ内スクロールの置き換え点では、
  有限で 0 でないデルタ (縦・横) を受け付ける (`TouchPhase::Move` 以外は既存の変換で 0 になる。消費済み segment は既存どおり除く)
  (レビュー r1 P2-6)。
- **変えないもの**: Ctrl+ホイール (ズーム)、Alt+ホイール (ページ送り。ホイールでのページ送りの逃げ道)、
  シークバー上のホイール (ページ送り)、パネル・ナビゲータ・ポップアップ上のホイール。
- 端で止まる。はみ出していないページでは何もしない (D1)。
- `fs_wheel_action_requests_navigation` はページ内スクロールの wheel action に「送らない」と答える (分類は 1 か所)。
- **同じ frame のクリック** (レビュー r1 P2-2): ページ内スクロールの wheel action を受け付けた frame では、
  キャンバスのクリック・ダブルクリックを `FsCanvasClickAction::None` にする (送りもリセットもしない)。
  クリックの計画は wheel の適用前で、スクロール後の位置を予測するには §2.3 の幾何が要るため、予測ではなく同 frame の組み合わせを捨てる。
  ホイールでズームした frame の既存の予測 (`propose_fs_wheel_click_transform`) は変えない。

### 2.7 新しい KeyAction (既定キーなし)

| Action | 説明 (description) | 既定 |
| --- | --- | --- |
| `FsPageNScrollNext` | ページ内を N 字の順に次へスクロールする | なし |
| `FsPageNScrollPrev` | ページ内を N 字の順に前へスクロールする | なし |
| `FsPageScrollUp` / `Down` / `Left` / `Right` | ページ内を上 / 下 / 左 / 右へスクロールする | なし (判断事項 Q4) |

- context `FsImage`、trigger `Press` (リピート可)、`SinglePerFrame`。`ini_name` / `description` / `context` / `trigger` /
  `default_chords` (空) / `ALL_ACTIONS` / `docs/keymap.ini.default` (`# Action = none`) を揃える。
- 面 (§2.2 の 3) が成立しないとき、または入力の所有が前面 UI にあるときは**キーを消費しない** (§1.470 の `FsZoomIn` と同じ)。
- 4 方向の移動量は上下キーと同じ。左右も端で止まり、綴じ方向で反転しない (画面の左右)。
- 上下キーの設定がページ送りでも、これらの Action は使える (キーを割り当てた人だけが使う)。
- リング・ジェスチャ・マウスボタン・ゲームパッドには今回足さない (キーボード専用。`ring-keyaction-parity.md` が
  KeyAction → Ring の方向を要求しないことを実装時に確認する)。

### 2.8 N 字スクロール

縦を優先して読み、縦の端で綴じ方向へ 1 列進み、反対側の縦端から読む (NeeView の N 字と同じ順序)。

- 次 (`FsPageNScrollNext`):
  1. 縦に範囲があって下端でない → 下へ 1 画面分 (表示領域の高さ × 85%) 進む。下端で止める。
  2. 縦の下端 (または縦に範囲が無い) で、横に範囲があって読み終わりの横端でない → 読む方向へ 1 画面分 (幅 × 85%) 進み、縦は上端へ。
     右→左の本は左側へ、左→右は右側へ進む。
  3. どちらも端 → 何もしない (ページは送らない)。
- 前 (`FsPageNScrollPrev`): 逆順。上へ戻り、上端なら読み始め側へ 1 列戻って縦は下端へ。
- 端の判定・移動は §2.4 の移動可能範囲 (共通部分) で行う。
- 85% は連結読みの PageUp/PageDown と同じ定数 (`VERTICAL_READING_PAGE_SCROLL_FRAC`)。15% を前の画面と重ねる (判断事項 Q3)。
- 読書方向は §1.726 と同じ源 (`spread_mode.reading_direction().unwrap_or(self.reading_direction)`)。
- 列の位置を状態に持たない。毎回、今の pan と範囲から次の位置を決める純関数。途中でドラッグ・ホイールで動かしても、その位置から続く。
- 「読み始め」(§1.726) と組み合わせると、ページを開いた位置 = N 字の始点になる。既定の「中央」では中央の列から始まる。
  マニュアルに組み合わせを 1 行書く。

### 2.9 他の機能との関係

| 機能 | 扱い |
| --- | --- |
| 見開き | 見開き全体を 1 つの範囲として動かす。片側に置いた単ページの既存配置は、はみ出さない軸では動かさない |
| 回転 | 保存回転は layout が回転後の表示空間なのでそのまま。自由回転は四隅の外接で範囲を決める (§2.4) |
| 画面に収まる画像 | その軸は何もしない (D1) |
| 分割 (横長の片側表示) | 表示中の片側が範囲 (その frame で確定した slice の幾何を使う) |
| 綴じ方向 | ↑↓・4 方向・ホイールは画面基準。N 字の横の進み方だけ読書方向に従う |
| 連結読み | 面の外。↑↓・ホイールは現行の連結スクロールのまま。新 Action は消費しない |
| Z ズーム・360・3D・分析・比較・編集モード・表示トリム編集・範囲キャプチャ | 面の外。現行のまま |
| シークバー | その上のホイールはページ送りのまま |
| §1.726 読み始め | スクロールは利用者入力なので初期配置要求を消す |
| §1.745 クリック送り | スクロール後は「動かした」扱い (`fs_automatic_initial_view` を書き換えない)。単クリックでは送らず、ダブルクリックで中央へ戻す。手で元の自動位置・中央へ戻せば現行どおり送る (D2)。同 frame のホイール + クリックは §2.6 |
| 紙めくり演出 | pan が 0 でないと演出しない既存規則のまま。スクロール後のページ送りは演出なし (§1.726 と同じ制限) |
| ナビゲータ・ルーペ・キー拡大 | 確定した `fs_pan` をそのまま使う。変更なし |
| スライドショー | ページ内スクロールでは止めない・影響しない |
| F12 別ウィンドウ / 独立 viewer | 新しい永続状態が無く、各 context の `fs_pan` だけを読み書きする。要求は作った viewport の pass でだけ解く。入力は既存の viewport ごとの配送。兄弟 context は変えない |
| ゲームパッド・タッチ | 変更しない (Q5) |
| mIV Remote | 変更しない (本体の `fs_pan` を使わない別表示) |
| `?` ヘルプ | 固定キー欄の ↑↓・ホイールの説明は「ページ内スクロール (ページ単位の通常表示のとき。連結・Z・比較などでは従来どおり)」のように、適用される面を書いて出し分ける (レビュー r1 P3-8)。新 Action は割り当て後に一覧に出る (既存の仕組み) とマニュアルに書く |

### 2.10 状態の組み合わせを減らす検討 (CLAUDE.md「設計の簡素化」)

- **永続する実行時状態を持たない。** 足すのは保存する設定 2 つと、1 pass でだけ生きるスクロール要求、状態を持たない純関数。
  N 字の「今どの列か」も持たず、今の pan から毎回求める。要求は後の frame へ持ち越さないので、detached の swap・駐車中の reset・
  close の各経路に、持ち越した要求の扱いを足す必要がない (context 所有のフィールドにする場合も frame 照合で自動的に無効になる)。
- **前 frame の幾何を当てにしない。** §1.726 と同じ消費箇所で、その frame の確定した幾何から解く。前 frame の layout が今の表示単位と
  同じかを照合する仕組み (世代・slice・holdover の証明) を新しく作らない。
- **同 frame のホイール + クリックは予測しない。** スクロール後の位置を予測して判定する代わりに、その組み合わせのクリックを捨てる。
- **端でページを送らない。** 端の判定・送った直後の初期位置・長押しで端を越える連続送りの組み合わせを作らない (利用者決定どおり)。
- **アニメーションしない。** スクロール中の割り込み (ページ送り・ズーム・別入力) の組み合わせを作らない。
- **移動量の設定を増やさない。** 連結読みの量を共用し、N 字は既存の 85% 定数。
- 採らなかった案: 「端に着いたらページを送る」(ZipPla・SumatraPDF・NeeView のホイール Type A 方式) は利用者決定により採らない。
  「スクロール中だけ別の表示状態に入る」案は、終了条件と他モードとの排他が増えるので採らない。
  前 frame の layout へ照合情報を足す案 (レビュー r1 P2-1 の代案) は、照合の項目 (世代・slice・組・回転・viewport・HUD 予約) が多く、
  §1.726 の消費箇所を使えば不要なので採らない。
- まれな失敗は既定の割り切り (このページ内スクロールは保存データを持たないので該当なし)。

## 5. 検証

- 純関数: 縦だけ / 横だけ / 両方はみ出す、収まる軸は不動、端で止まる、端の外 (手動ドラッグ後) から外へは動かない・内へは動く、
  見開き (白 companion 込み、companion 側の端で実ページの可視性の区間が効く)、回転 90 度、自由回転 45 度・負の角度・トリム併用、
  viewport 原点が 0 でない (HUD 予約)。
- N 字: LTR・RTL での列の進み方、下端→次の列の上端、最後の列の下端で何もしない、前方向の逆順、縦だけ・横だけはみ出す場合、
  白 companion のある見開きで同じ列を繰り返さず終端に着く (`set_fs_pan_from_input` 相当の clamp を通した最終 pan で確かめる)。
- 要求の寿命: 同じ pass の current な表示単位でだけ解く。holdover・紙めくり演出・navigation sequence 中・幾何未解決では捨てて pan 不変、
  次の frame へ持ち越さない。分割の片側切替・見開きの組の変更・resize・HUD 予約の変更と同じ frame のスクロールは、新しい幾何で解く。
  同じ frame の Ctrl+ホイールの倍率変更後の幾何で解く。§1.726 の要求がスクロールで消える。
- 上下キーの handler: 設定 2 つの全 4 組。ページ送りでは現行どおり `spread_page_nav` (回帰)、ページ内スクロールでは pan だけ変わり
  `fullscreen_idx` が変わらない。Shift+↑↓・←→ は送る。スタックのフラット読書の Shift+↑↓ はスタックジャンプ。
  同 frame の短い down/up は 1 回、release 済み repeat は動かない、複数 edge は 1 回、native / egui で二重に動かない、
  配送時の修飾と現在の修飾が違う場合、TextInput / IME / modal / context menu 中は背面へ渡らない。
  面の外 (連結・Z・比較・編集・動画・音声・音楽・範囲キャプチャ) では現行の結果と同じ。
- ホイール: 通常は縦スクロール、Shift・チルトは横スクロール (既定設定では現行どおり何もしない)、Ctrl はズーム、Alt は送り、
  シークバー上 (hover) は送り、ドラッグ中のシークバー・パネル・ナビゲータ上は現行どおり。0.1 / 0.5 の Point デルタ・正負が比例して動く。
  ページ送り側の 0.5 の閾値は不変。同 frame の通常ホイール + 単クリック / ダブルクリックで送らない・リセットしない。
  Ctrl・通常・Alt のホイールが混ざる frame と遅延適用 (`merge_at_frame_tail`) の結果。
- クリック (D2): スクロール後は単クリックで送らず `fs_automatic_initial_view` が不変。ダブルクリックで中央へ戻る。
  手で元の自動位置・中央へ戻せば送る。
- 新 Action: 面の外・前面 UI 所有では消費しない、既定キーなし、ini 往復、`bundled_keymap_default_matches_generated_reference`、
  割り当て後に `?` に出る。
- 設定: 編集 → OK → 効果まで通し (環境設定 UI で値を変えて保存し、fullscreen の handler が新しい値で分岐する)。serde 欠落・転送。
- context: F12 別ウィンドウ・独立 viewer の入力が自分の `fs_pan` だけを変え、main の pan と要求を変えない。逆も同じ。
- UI スナップショット (環境設定の該当ページ)。
