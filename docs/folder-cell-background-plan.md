# サムネイル一覧のフォルダの背景色 (§1.880) — 設計

状態: **設計 (2026-11-23)。独立設計レビュー r1 (P2 1 件・P3 2 件)・r2 (P3 1 件) を反映済み。§8 は利用者が 2026-11-23 に決定済み。実装へ進む**。収録は v5.7.0 の予定。
発端: 5ch >>886 の「フォルダは背景を一般的なフォルダの黄色で着色すれば見やすい」。バックログ §1.880 の方針
(画像には色を重ねずセルの背景を着色する・選択とチェックの色を優先する・専用の選択色などを増やさない・既定は今の表示)
を前提にする。

## 1. 今の作り (コード参照)

- サムネイル一覧のセルは `src/app/grid_paint.rs` の `paint_cell` が描く。背景は選択またはチェックなら共通の青
  (Dark `40,70,110` / Light `180,210,255`)、それ以外は通常色 (Dark `gray 28` / Light 白) で、セル全体 (`rect`、
  角丸 2) を塗る (`grid_paint.rs:1064` 付近)。サムネイル画像はその内側 4px (`inner = rect.shrink(4)`) に描く。
- 同じ `paint_cell` を、メインの一覧 (サブ展開・スタック・コレクション・本棚・検索結果を含む) と外部ドロップの
  スナップショット用セル (`draw_drop_hover_snapshot_cells`) が通る。F12 のページ一覧は専用の描画
  (`src/ui_fullscreen/page_overview.rs` → `src/ui_page_overview.rs`) で、フォルダのセルを並べる一覧ではないので
  対象外。詳細一覧 (表形式) は別の描画で、名前の色は `details_name_colors` が持つ。
- 「フォルダ」の判定は `details_name_colors::category(item) == Some(Folder)` に 1 つある: 実フォルダ
  (`GridItem::Folder`)・書庫内のフォルダ (`ZipDir { is_archive: false }`)・検索結果のフォルダ
  (`SearchContainer { kind: Folder }`)。ドライブ一覧は `GridItem::Folder` + `is_drive_list` で表す。
- フォルダのセルの上に載る物: 代表画像 (またはアイコンのみのときの 📁 の字形、色 `220,170,30`)・種類アイコンの板
  (`os_theme::thumbnail_type_background`、フォルダは teal の不透明な板)・ファイル名の板 (`draw_cell_filename`、
  Light は白 α220 / Dark は黒 α160 の板の上に文字)・各種バッジ (自前の板)。
- **背景に直接載る物** (独立レビュー r1 P2 で訂正。初版は「📁 の字形だけ」と誤っていた):
  - アイコンのみのフォルダの 📁 の字形 (`220,170,30`、`grid_paint.rs:1100` 付近)。
  - 検索結果のフォルダで代表画像が無い・未ロードのとき (種類のアイコンで表示するときも通る) の、📁・階層パス
    (Light `gray 60` / Dark `gray 220`、`grid_paint.rs:1313`・`:1433`) と件数「N 枚」
    (Light `180,80,0` / Dark `240,200,100`、`grid_paint.rs:1443`)。
- 「代表画像の代わりに種類のアイコンで表示する」(環境設定 → サムネイル、`thumbnail/container-type-icon`) を使うと、
  フォルダは画像を出さずアイコンだけになる。

## 2. やること

設定が ON のとき、**選択もチェックもされていないフォルダのセル**の背景 (今の通常色で塗っている `rect` 全体) を、
設定の色 (Light / Dark で別) で塗る。それ以外は何も変えない。

- 優先順: 選択・チェック (共通の青) > フォルダの色 > 通常色。カーソルの太い枠・チェック印・切り取りの半透明
  (`is_cut` は中身の painter だけを薄くし、背景は今も不透明) は今のまま。
- サムネイル画像・アイコン・板・バッジ・代表画像の選定・サムネイルキャッシュには触れない (再生成なし)。
- 画像がセルいっぱいのとき、色が見えるのは周りの 4px と、縦横比が合わずに空いた部分だけになる。色帯や画像を縮める
  対応は入れない (§8 の Q3)。アイコンのみのフォルダ・縦横比の違う代表画像・「種類のアイコンで表示する」では
  セルの大部分に色が見える。

## 3. 対象の範囲

| 対象 | 着色 | 理由 |
| --- | --- | --- |
| 実フォルダ (`GridItem::Folder`、ドライブ一覧でない) | する | 提案の対象 |
| 書庫内のフォルダ (`ZipDir { is_archive: false }`) | する | 利用者から見て同じ「フォルダ」。分類の持ち主 (`details_name_colors::category`) と揃える |
| 検索結果のフォルダ (`SearchContainer { kind: Folder }`) | する | 同上 |
| ドライブ一覧のドライブ | しない | 一覧の全部がドライブなので色分けの意味が無い。分類を「フォルダ かつ ドライブ一覧でない」とする |
| 本 (ZIP・PDF・変換対象の書庫・書庫内の書庫) | しない | §1.882 (ZIP と通常画像の識別性) で別に扱う。今回は範囲を広げない |
| 詳細一覧 (表形式) | しない | 名前の色 (`details_name_colors`) が既にある。適用先を混同しない |
| mIV Remote の Web UI | しない | 別の UI。必要なら別項目 |

「何がフォルダか」は `details_name_colors::category` を呼んで決め、条件を書き写さない
(ドライブ一覧の除外だけ `paint_cell` が持つ `is_drive_list` で足す)。

## 4. 設定

- 新しい設定 `folder_cell_background` (1 つの struct、`settings_kv` に JSON で保存。`details_name_colors` と同じ形):
  `{ enabled: bool, light: [u8; 3], dark: [u8; 3] }`。既定は `enabled: false` と既定の色 (§8 の Q1・Q2)。
- **未リリースの新しい設定なので移行は不要**。値が無いときは serde の既定。壊れた JSON・型の違いは既存の読み込み処理
  (`settings_db.rs` の `Corrupted` などのエラー) に任せ、この設定のための回復処理は足さない (独立レビュー r1 P3)。
- 書き出し・取り込み: `settings_transfer.rs` の `preferences_policy!` の export 側に 1 行
  (表示名「サムネイルのフォルダ背景」、検査は §5 と同じ)。`details_name_colors` の行と同じ形。
- §1.843 (AI 連携の設定の確認・変更) では、環境設定の下書きが持つ値だけの項目なので **第 1 段**
  (export 側の鍵が自動で第 1 段に入る。`docs/mcp-guide-settings-plan.md` §6.4.3 の件数と §17 の一覧に 1 鍵足す)。
- 環境設定 → 表示 → サムネイルに置く:
  - チェック「フォルダのセルの背景に色を付ける」
  - Light / Dark の色ボタン (2 つ。既存の名前の色の色選び・16 進入力の部品を使う) と「既定の色に戻す」
  - 見本: Light / Dark それぞれで、フォルダ (代表画像あり)・フォルダ (アイコンのみ)・検索結果のフォルダ
    (代表画像なし、階層パスと件数)・選択中のフォルダ・画像 の 5 セルを並べて描く。見本は本物の `paint_cell` と同じ色の関数を使う (見本専用の色の決め方を作らない)。
  - 環境設定の検索の項目 (`search_index.rs`) に 1 行 (「フォルダ」「背景」「色」「黄色」)。
- OFF にしても色は保持する (名前の色と同じ)。

## 5. 読みやすさと色の検査

- 背景に直接載る文字は、検索結果のフォルダの階層パスと件数だけ (§1)。ほかの文字は既存の板 (不透明または半透明) の上にあり、板は今のまま維持する。
- 検査 (保存・取り込み・AI からの変更・見本で共通の 1 つの関数):
  - その テーマで**背景に直接載る文字の色すべて** (今は階層パスと件数の 2 色) に対して 4.5:1 以上。
  - 文字の色は `grid_paint.rs` の直書きの値を定数 (テーマを受けて色を返す関数) に出し、描画と検査が同じ定数を使う
    (`docs/mcp-guide-settings-plan.md` §6.4.3 の「画面と検査が同じ定数」と同じ考え)。背景に直接文字を描く
    新しい経路を足したら、その色をこの一覧に足す (コメントで書く)。
  - これらの文字の色は文字コントラストの設定 (Standard / Strong) で変わらない固定の色なので、検査も 1 通り。
  - 参考 (計算): 既定の候補 Light `#FFF4CC` は件数の色に 4.66:1、階層パスに 10.0:1 で通る。少し濃い `#FFF0B3` は
    件数の色に 4.49:1 で通らない。Dark `#3A3420` は件数に 7.77:1、階層パスに 9.05:1。
  - 📁 の字形は文字ではなく、今の白の背景でも 2.14:1 (既定候補の `#FFF4CC` で 1.94:1) なので、検査の対象にしない。
    見本で見え方を示す。
- 文字コントラスト「強い」でも色は使う (背景に載る文字の色は強いでも変わらず、検査で読みやすさを保つ)。
- 選択・チェックの青との区別: 青系の色を選ぶと、チェックだけされたセル (枠なし) と見分けにくくなる。
  検査で拒まず、見本に選択中のセルを並べて利用者に見せる (自由な配色まで管理しない、バックログの方針)。

## 6. 描く場所

- `paint_cell` の背景の分岐に「選択でもチェックでもなく、フォルダで、ドライブ一覧でなく、設定が ON」を 1 つ足す。
  色は `folder_cell_background` の関数 (テーマを受けて色を返す) から取る。設定は `paint_cell` の呼び出し元から
  引数で渡す (今の `is_drive_list` などと同じ)。
- 外部ドロップのスナップショット用セルにも同じ引数を渡す (既定 OFF なので今のスナップショットは変わらない)。
- 毎フレームの経路に足すのは、分類 1 回 (`match`) と bool の判定だけ。I/O・割り当てなし。

## 9. 状態の組み合わせを減らすための検討

- 選択色・チェック色・ホバー色・種類ごとの色は増やさない (バックログの方針)。設定は ON / OFF と 2 色だけ。
- 表示中の一覧は、設定の変更を次のフレームの描画で読むだけ (キャッシュも状態も持たない) ので、作り直しの処理は要らない。
- 色の検査は 1 つの関数で、画面・取り込み・AI からの変更が共有する (§1.843 の「画面と検査が同じ定数」)。
- まれな失敗 (設定の保存の失敗など) は既定の割り切り (既存の設定保存の経路のまま、新しい回復処理は足さない)。

  「既定の色に戻す」は ON / OFF を保ち、両テーマの色だけを戻す。

  代表画像は context が保持するメモリ内の単色テクスチャで、ファイル・worker を使わない。
- `settings_transfer` の export 側に1鍵を追加し、§1.843 の第1段にも入る (export 170・除外側の印57・合計227)。
