# 本のサムネイルは表紙だけ保存する設定 (§1.452)

- 状態: 実装・独立レビュー済み (2026-11-08)。v5.1.0 向け。設計 = ClaudeCode、実装 = Codex Sol / high、独立レビュー = Sol / xhigh。
- 発端: 5ch >>623・627。Leeyes の「先頭の画像のみ保存する」に当たる設定。
  目的は、少ない容量でなるべく多くの本の表紙サムネイルを残すこと。
- 関連: [サムネイルカタログ設計](catalog-design.md)、[仮想フォルダ](virtual-folders.md) §3.1・§3.1.1・§3.4、
  [サムネイル要求のライフサイクル](thumbnail-request-lifecycle-plan.md)。

## 1. 仕様

環境設定 → パフォーマンス → キャッシュに、チェックボックスを 1 つ足す。**既定 OFF** (今の動きのまま)。

- ON のとき、**本の中のページ一覧のサムネイル** (ZIP・CBZ・直読み RAR・変換書庫・入れ子書庫の中の
  画像、PDF・EPUB のページ) を、サムネイルキャッシュに**新しく保存しない**。
- **本棚に並ぶ表紙** (親フォルダの一覧に出る本のタイル) は今までどおり保存する。表紙は本の先頭ページ、
  または利用者が代表に固定した画像で、これが「先頭ページと代表画像だけを残す」に当たる。
- 保存しないページも、表示に必要なときは今までどおり作ってメモリに持つ。ページ一覧・
  フルスクリーンのシーク用サムネイル・ページ概観・先読みは今のまま使える。
- 保存済みのキャッシュは今までどおり読む。設定を変えただけでは、保存済みのキャッシュも
  代表の固定も消さない。
- 代償: 本の中のページは、一度メモリから外れたあと・開き直したとき・再起動後に作り直すので、
  ページ一覧の表示が遅くなることがある。これを設定画面とマニュアルに書く。

### 1.1 「先頭」と「代表」の扱い

表紙の行は、親フォルダの catalog に本ごとに 1 行ある (`zipthumb:` / `pdfthumb:` / `archivethumb:`、
固定があれば `#pin:` 付き)。この行の画像は、固定が無ければ本の自動表紙 (ZIP は書庫内の格納順で最初の
画像、PDF は 1 ページ目)、固定があれば代表の画像そのものである。**したがって「先頭ページと代表画像だけ
保存する」は、表紙の行だけ保存して本の中のページの行を保存しないことで満たせる。**

本の中の一覧で「先頭のページ」「代表のページ」を見分けて、その行だけ保存する案は採らない
(§5 の比較)。

既存の「親の表紙 → 本の catalog への seed」(`src/app.rs` の `setup_virtual_folder_seed_and_writeback`) は、
PDF と ZIP / CBZ について、本の catalog に先頭ページの行が無いとき、親の表紙の画像を先頭ページの行として
写す。**ON のときはこの seed を行わない** (OFF では今までどおり)。理由:

- ON は「本の中のページの WebP の行を作らない」設定で、seed はその行を作る。
- seed は親の表紙の stamp を照合せずに写すので、親の表紙が古いと古い画像と寸法を先頭ページの行に入れる。
  OFF では先頭ページの行が作られていれば seed は入らないが、ON では行が無いので本を開くたびに入り得る。
  §2.2 の寸法の行も、WebP の保存で消えるので古い寸法に戻る (実装担当の指摘、2026-11-08)。
- ZIP では seed の写し先 (一覧の最初の `ZipImage`) と親の表紙 (書庫内の格納順で最初の画像) が同じとは限らず、
  写した行の stamp (親の書庫の mtime・サイズ) とページ要求の stamp (エントリの mtime・非圧縮サイズ) も一般に
  一致しない。OFF の既存の挙動で今回は扱わないが、ON で使い続ける理由は無い。

代償として、ON では本を開いた直後の先頭ページも作り直す (1 ページ分)。EPUB と RAR はもともと seed の対象外。

### 1.1.1 書庫内の RAW ページは対象外

ZIP 内の RAW 画像のうち、埋め込みプレビューが使えないものは、mIV Remote では生成せず catalog の行だけを
読む (`remote_raw_thumbnail_requirement` → `CatalogOnly`、[RAW 計画](raw-libraw-plan.md) の「PC で作った
catalog を使う」契約)。ON でこの行を保存しないと、Remote ではそのページのサムネイルが出なくなる。
本の中の RAW ページは数が少ないので、**RAW のページの行は ON でも今までどおり保存する**
(判定は `zip_entry` の拡張子で `raw_format::is_raw_path`)。

### 1.2 代表を変えたとき

代表を付け替えると、親の表紙タイルのキーが `#pin:{新しい source_id}` に変わる。親の一覧で新しい
キーの要求が出て、表紙として普通に保存される。古い代表の行は既存の `delete_missing` が今までどおり
整理する。新しい仕組みは要らない。本の中で代表に固定したページ自身の行 (エントリ名・ページキー) は、
ON のとき保存しない。親の表紙行が代表の画像を持っているので、本棚の表示には影響しない。

### 1.3 既存の保存設定との優先関係

保存の判定は次のようにまとめる。

```text
保存の条件 = 保存先が使える && (force_cache || CachePolicy の判定)      … 今までと同じ
抑える行   = ON && 本の中のページの行 (override なし + zip_entry / pdf_page) && RAW ではない
WebP の行を保存する = 保存の条件 && !抑える行
寸法の行だけ保存する = 保存の条件 && 抑える行                            … §2.2
```

- **Off**: もともと新しく保存しないので、この設定は効果が無い (チェックは押せるままにし、説明で触れない)。
- **Auto**: 「PDF ページは常に」「ZIP 内画像は常に」は、表紙には今までどおり効き、本の中のページには
  効かない (ON が絞る)。
- **Always**: 表紙は保存し、本の中のページは保存しない。
- **force_cache**: ドライブ直下の固定代表など、表紙タイル側の要求だけが使う。本の中のページの要求には
  付かないので、式の順序で差は出ないが、行の種類の判定を先に置いて意味を固定する。
- **一括キャッシュ作成**の「ZIP ファイルの中身もキャッシュ」「PDF ファイルの中身もキャッシュ」は、
  その場で利用者が明示して選ぶ操作なので、**一括作成の選択を優先する** (中身も保存する)。一括作成の
  ダイアログで、ON のときに「この設定より、ここでの選択が優先されます」と一行添える。
  一括作成の保存経路 (`src/app/cache_ops.rs`) は変えない。
- 別物で変えないもの: ZIP / PDF 変換キャッシュ、EPUB 変換キャッシュ、編集プレビューキャッシュ、
  フルサイズ・AI の先読み、`pdf_meta` / `container_page_meta` (ページ数)、動画・音声のサムネイル。

### 1.4 対象範囲

| 対象 | ON のとき |
| --- | --- |
| ZIP / CBZ / 直読み RAR / 変換書庫 (RAR・7z・LZH → ZIP) の中の画像 (`ZipImage`) | 保存しない (寸法だけ残す) |
| 上のうち RAW 画像のページ | 保存する (§1.1.1) |
| 入れ子書庫・書庫内フォルダの中の画像 (外側書庫の catalog にエントリ名で入る行) | 保存しない |
| 書庫内フォルダ・入れ子書庫のタイル (`ZipDir`、`zipdir:`) | 保存する (その中の本の表紙) |
| PDF / EPUB のページ (`PdfPage`) | 保存しない (寸法だけ残す) |
| 親一覧の本タイル (`ZipFile` / `PdfFile` / `ConvertibleArchive`)、固定代表 | 保存する |
| 検索・コレクション等の合成一覧の本タイル (代表の override 付き) | 保存する |
| 検索・コレクション等の合成一覧に出る本のページ (`ZipImage` / `PdfPage`) | 保存しない |
| フォルダの代表 (`folderthumb:`)、通常の画像ファイル | 変わらない |
| 本として扱う画像フォルダの中の画像 | **対象外 (変わらない)** |

本として扱う画像フォルダは対象にしない。中の画像は通常の画像ファイル (`GridItem::Image`) で、
保存先もそのフォルダ自身の catalog であり、通常のフォルダと区別する材料が要求に無い。Auto では
速く読める画像はもともと保存されないことが多く、容量の問題は書庫・PDF より小さい。対象にするには
本扱いの判定を要求生成側へ持ち込む必要があり、状態が増えるので見送る。マニュアルには
「ZIP・PDF などの書庫と文書が対象」と書く。

## 2. 判定の置き場所

**worker の保存直前の 1 か所** (`thumb_loader::load_one_cached` の保存判定と、PDF の取消時回収の
判定) に置く。設定は `CacheDecision` に持たせる。

- `CacheDecision` に `cache_book_cover_only: bool` を足し、`from_settings` で `Settings` から写す。
  `without_thumbnail()` では false。
- 行の種類は、`load_one_cached` が catalog のキーを決める規則と同じ入力で決める。
  `cache_key_override` が無く、`pdf_page` か `zip_entry` がある要求は、キーがページキー
  (`pdf_page_cache_key`) かエントリ名になる「本の中のページの行」である。override がある要求
  (表紙・代表・`zipdir:`・検索の代表) は対象外。この分類を 1 つの関数にまとめ、キーの導出と
  保存判定の両方から呼ぶ (同じ意味を 2 か所に書かない)。
- 保存判定: `save_target.open_if(force_cache, policy_should_save)` で保存先を開いた後、行の種類を見て、
  許す行なら今までどおり WebP の行を保存し、ON が抑える行なら WebP を作らず寸法の行だけを保存する
  (§2.2)。どちらの場合も `cache_map` には WebP の行だけを入れる (寸法の行は入れない)。
- 保存しないページの行の代わりに、**ページの寸法だけ**を残す (§2.2)。PDF の取消時回収
  (`HarvestOnCancel`) は、寸法を残すためにも今までどおり選んでよい (回収した描画から寸法を得る)。
  回収の判定は、行の種類ではなく「保存先が使えて、保存条件が成り立ち得るか」のまま変えない。

この置き場所なら、本体の通常一覧・idle 高画質化 (`SourceOnly`)・RAW の非同期現像の続き・
シーク用サムネイル・ページ概観・mIV Remote (`remote_ipc/container.rs` の preloaded 直呼びを含む)
が、全部同じ判定を通る。要求を作る側 (`make_load_request`、Remote の要求生成) は変えない。

### 2.1 設定の反映の時点

- 本体: thumbnail worker は `spawn_thumbnail_workers` で作られるときに `CacheDecision::from_settings` を
  取る。新しい設定は、OK の後に **worker が新しく作られる読み込み** (フォルダ・本を開く、本から出る等)
  から効く。ZIP の中のフォルダ間の移動は同じ worker を使い続ける (`src/app.rs` の ZIP 内移動) ので、
  本を開いたまま設定を変えた場合は、その本を開き直すまで前の設定のまま。Off / Auto / Always の変更と
  同じ時点で、専用の作り直し処理は足さない。
- mIV Remote: 本体の起動時に作る IPC サーバの設定 snapshot から `CacheDecision::from_settings` を作る。
  既存の `cache_policy` と同じく、本体を次に起動したときから効く。

### 2.2 ページの寸法だけを残す

mIV Remote は、本のページの横長判定 (見開きの単独表示・横長分割) に catalog の行の寸法
(`CatalogDb::load_source_dims` / `load_source_dims_matching`) を使う。行が無い ZIP のページはヘッダだけ
読んで補うが、RAR と入れ子書庫は補えず、ヘッダの補完は EXIF の向きを適用しない。PDF は worker へ問い合わせる
(既にサムネイルを作った PDF には追加費用を出さない、という既存の条件がある)。ON で行を保存しないだけだと、
これらの判定が ON の利用者で変わる。

そこで、ON で**ページの行を保存しなかったときは、同じ catalog に寸法だけの行を保存する**。

- 新しい表 `page_dims` (filename TEXT PRIMARY KEY, mtime, file_size, source_width, source_height,
  layout_width, layout_height)。既存の `pdf_meta` / `video_meta` と同じく、catalog を開くときの
  `CREATE TABLE IF NOT EXISTS` に足す追加表で、既存の表・行・schema version は変えない (リリース済みの
  catalog だが、既存行の移行は要らない。旧版はこの表を読まない)。
- 書く条件: 保存条件 (`force_cache || CachePolicy の判定`) が成り立ち、保存先が使え、ON が本の中のページの
  行を抑えたとき。つまり、OFF なら WebP の行が入っていた場合にだけ、その代わりに寸法の行が入る。Off の
  ポリシーでは何も書かない。キー・mtime・file_size は WebP の行と同じ値を使う。寸法は WebP の行に入れる
  `source_dims` / `layout_dims` と同じもの (EXIF 適用後・RAW は現像寸法・PDF はラスタと page box)。
- 読む側: `load_source_dims` / `load_source_dims_matching` が `thumbnails` の寸法と `page_dims` を合わせて
  返す (同じキーは `page_dims` を優先、下の「1 キー 1 行」)。`_matching` は `page_dims` にも同じ mtime / file_size の条件を
  付ける。Remote の呼び出し側は変えない。表が無い古い catalog では `thumbnails` だけを返す。
- 1 キー 1 行の寸法: 同じキーの寸法は、最後に記録したほうが読まれるようにする。
  - 寸法の行を保存するときは、同じキーの WebP の行には触らない (stamp が違っても消さない)。
    WebP の行は画像の保存先、寸法の行は最新の寸法の記録と役割を分ける。stamp を見ないで古い行を読む
    既存経路 (ドライブ一覧の固定代表の seed が `ZipEntry` / `PdfPage` のページ行を読む等) も今までどおり残る。
  - WebP の行を保存するとき (OFF、RAW、表紙、一括作成、OFF の seed を含む全部の WebP 保存入口)、同じキーの
    寸法の行を同じ transaction で消す (catalog の `thumbnails` への INSERT の trigger で一か所にまとめてよい)。
    ON では本の中のページへ写す seed を行わない (§1.1) ので、ON で記録した寸法を写しが消すことは無い。
  - したがって、寸法の行がある = 最後の WebP 保存より後に寸法を記録した、なので、読む側は同じキーで
    **`page_dims` を優先**する。寸法列が NULL の古い WebP の行に、高画質化等で寸法を記録した場合も新しい
    寸法が返る。
- 消す側: `delete_missing` は `page_dims` からも存続集合に無いキーを消す。全件・期限の削除は DB ファイル
  単位なので変更不要。**指定フォルダの削除は SQL で行を消す経路がある** (別ドライブの音声の行を残すとき、
  `catalog.rs` の指定フォルダ削除が `pdf_meta` / `container_page_meta` / `video_meta` を列挙して消す) ので、
  そこに `page_dims` を加える。
- 読み取り専用で開く経路 (通常の read-only、Collection 専用の read-only) では表を作らず、表が無いことを
  許す。
- 本体の一覧・見開きは今までどおりメモリ上のサムネイルの寸法を使い、`page_dims` は読まない。
- 容量: 1 ページあたり数十バイトで、WebP (数十 KB) に比べて無視できる。

### 2.3 本 → 親の表紙の書き戻しは、今の stamp に合う行だけ写す

既存の書き戻し (`fire_virtual_folder_writeback_if_ready`) は、本の先頭ページが表示された後、その本の
`cache_map` にある先頭ページの行を、本の現在の mtime・サイズを付けて親の表紙行へ写す。`cache_map` は
起動時に `load_all` で読んだ写しで、stamp の合わない古い行も入っている。今は先頭ページを作り直すと
保存が成功して `cache_map` の行も新しくなるので古い行は写らないが、ON (や Auto で保存しなかった場合)
では古い行が残ったまま、**今の本の stamp を付けて親へ写される**。

書き戻しは、`cache_map` の行の mtime・file_size が、先頭ページの要求に使った stamp と一致するときだけ
写すように直す。一致しなければ何もしない (親の表紙は、親の一覧を表示したときに通常どおり作られる)。
これは ON に限らない既存の欠陥の修正で、OFF の挙動も変わる (古い行を写さなくなる) が、正しい表紙を
写す場合の挙動は変わらない。

この結果、ON では「親の一覧を経ずに本を直接開いたときに、親の表紙を先回りして作る」ことは起きなくなる
(書き戻す新しい行が無いため)。表紙は親の一覧を表示したときに作られて保存されるので、本棚に表紙が残る
ことは変わらない。先回りのためだけに先頭ページの識別と保存の受付を足すと §5 の状態が戻るので、ON の
代償として受け入れる。

## 3. 影響と代償

- **本体の見開き・横長判定**: メモリ上のサムネイルとフルサイズの寸法を使う (`ui_fullscreen.rs` の
  `known_page_dims`)。保存しなくても、表示したページの寸法は今までどおり分かる。
- **mIV Remote の横長判定**: §2.2 の寸法の行で、OFF と同じ材料が残る。寸法の行が書かれるのは、OFF なら
  WebP の行が書かれていた場合と同じなので、判定の結果は OFF と変わらない。
- **mIV Remote の書庫内 RAW**: §1.1.1 のとおり保存を続けるので変わらない。
- **再生成**: 同じ一覧を見ている間は、表示中のページは Loaded のまま保たれ、保存しないことを理由に
  作り直す経路は無い (通常の再要求は Pending / Evicted のとき、idle 高画質化は origin と解像度で判断)。
  メモリから外れたページへ戻る、開き直す、再起動する場合は作り直しが増える。これは要望どおりの交換。
- **既存の行**: 本の catalog の `delete_missing` は、今の一覧ではなく本に存在する全エントリ・全ページの
  キーを存続集合にする。保存を絞ってもキーの体系は変えないので、保存済みのページの行は消えない。
  ON の間に元のページが更新された場合、古い WebP の行は上書きされず残る (通常のサムネイル要求は
  mtime / サイズが合わないので読まない)。寸法は寸法の行が新しい値を返す。古い行は本を消す・キャッシュ
  管理で消すときに今までどおり整理される。
  OFF のときに保存したページを ON で開き直すと、保存済みの WebP の行から表示した後、idle 高画質化
  (`SourceOnly`) が元のページを読み直し、同じキーの寸法の行だけを足す。WebP の行は上書きも削除もされず
  残り、寸法の値は同じになる (2026-11-08 にサブ PC 担当が rows-D で観測: 本の中の DB に T 10 行 + D 10 行)。
- **親表紙からの seed と、本 → 親への書き戻し**: seed は ON のとき行わない (§1.1)。
  書き戻しは §2.3 のとおり今の stamp に合う行だけを写すよう直す。ON では、親の一覧を経ずに開いた本の
  表紙の先回り保存は起きない (親の一覧を表示したときに作る)。
- **通常の使い方の変化**: 既定 OFF なので無い。

## 4. 変える場所

1. `Settings`: `cache_book_cover_only: bool` (`#[serde(default)]`、既定 false)。
   `overwrite_non_preferences_from` には足さない (環境設定で編集する項目のため)。
   `settings_transfer.rs` の分類で、既存のキャッシュ設定と同じ「移行しない」群に入れる。
2. `CacheDecision`: フィールド、`from_settings`、`without_thumbnail`、直接リテラル (テスト・
   `bench_scroll`) の追従。
3. `thumb_loader`: 行の種類の関数 (RAW の除外を含む)、`load_one_cached` の保存判定と寸法の行の保存。
   `HarvestOnCancel` の判定は変えない。
3a. `catalog`: `page_dims` 表の作成、寸法の行の保存 API、`load_source_dims` / `load_source_dims_matching`
   の合成、`delete_missing` の追従。
3b. `app.rs` の本 → 親の書き戻し: stamp の一致を条件にする (§2.3)。
4. 環境設定 → キャッシュ (`ui_dialogs/preferences/pages.rs` の `page_cache`): モードの直後、Auto の
   しきい値群の外に置く。環境設定の検索 (`search_index.rs`) に項目を足す。
   - 文言 (案): 「本 (ZIP・PDF など) は表紙のサムネイルだけ保存する」
   - 説明 (案): 「本棚に並ぶ表紙 (先頭ページ、または代表に固定した画像) だけを保存し、本の中のページの
     サムネイルは保存しません (ページの縦横の大きさだけは記録します)。容量を抑えられますが、本を開き直した
     ときにページ一覧の表示が遅くなることがあります。RAW 画像のページは保存します。保存済みのキャッシュは
     消えません。」
5. 一括キャッシュ作成のダイアログ (`ui_dialogs/cache_creator.rs`): ON のとき、中身のチェックの下に
   「ここでの選択が優先されます」の一行。
6. マニュアル `htdocs/mimageviewer/manual/settings.html` の「キャッシュ生成設定」の表に 1 行。
   必要なら `tut-cache.html` にも短く。製品ページは変えない (通信・保存先・権限は変わらない)。
7. `docs/catalog-design.md` §9 と `docs/virtual-folders.md` §3.1 に、この判定を 1 段落ずつ。

## 5. 採らなかった案

- **本の中の先頭ページ・代表ページの行も保存する**: 先頭の定義が二つある (自動表紙は書庫内の格納順、
  中の一覧は読書順・本の構成の後)。同期 I/O 無しで一致させるには、列挙 worker で表紙の identity を
  確定して結果に持たせ、要求に型付きの保存指示を載せる必要がある。さらに、ZIP の中で代表を付け替えても
  一覧は作り直されず、表示済みのページは再要求されないので、新しい代表を保存させる専用の受付が要る。
  得られるのは、親の表紙行と同じ画像の複製 1〜2 行だけである。状態と経路が増える割に利点が小さいので
  採らない。ON では、開いた直後の最初のページも作り直す (§1.1)。容量と速度の交換として受け入れる。
- **設定で一括作成の「中身も」を抑える**: 利用者がその場で明示した選択を、離れた場所の設定で
  黙って無効にすることになる。一括作成の選択を優先し、ダイアログに一行添える。
- **要求を作る側 (UI) で保存可否を決めて要求に載せる**: Remote・合成一覧・派生要求のすべての作り手が
  漏れなく載せる必要があり、漏れると黙って効かない。worker の保存直前なら作り手を問わない。

## 6. テスト

設定の追加は、編集 → OK → 効果まで通しで確かめる。

1. `CacheDecision` / 行の種類の関数: (override 有無) × (`zip_entry` / `pdf_page` / なし) × ON / OFF の表。
2. worker (`load_one_cached` / `process_load_request`、偽の PDF レンダを使う既存の型に倣う):
   ON で `ZipImage`・`PdfPage` の行が作られず、表示 (SourcePixels → Finalized) は届く。`ZipFile`・
   `PdfFile`・`ConvertibleArchive`・`ZipDir`・固定代表 (`#pin:`) の行は作られる。OFF では今までどおり
   ページの行も作られる (Always と Auto + 常にキャッシュ)。ON でも保存済みのページの行は読まれる
   (cache hit)。idle 高画質化 (`SourceOnly`) と RAW の続きでも ON が効く。PDF の取消時回収の後も
   寸法の行が残る。書庫内の RAW ページは ON でも WebP の行が保存される。
3. 寸法の行: ON で抑えたページに `page_dims` 行ができ、`load_source_dims` / `_matching` が返す
   (`_matching` の stamp 条件、表が無い catalog、読み取り専用で開いた catalog)。Off のポリシーでは書かれない。
   保存順の両方向: 古い WebP の行 (縦長) → 原本を横長に更新 → ON で作り直し、で横長が返り古い WebP の行は
   バイト列ごと残る。寸法の行 → OFF で WebP を保存、で寸法の行が消え WebP の寸法が返る。同じ stamp で寸法列が
   NULL の WebP の行 → 寸法を記録、で新しい寸法が返り WebP のバイト列は残る。EPUB で古い世代の WebP と新しい世代の寸法が混在しても `_matching` が正しい世代を
   返す。`delete_missing` で存続集合に無いキーが消える。指定フォルダの削除で、別ドライブの音声の行を残しつつ
   寸法の行が消える (`catalog.rs` の既存の音声 scope 保持の fixture に足す)。
4. Remote: container の ZIP エントリ・PDF ページの要求 (preloaded 直呼びを含む) で ON が効き、
   本の表紙要求は保存される。ON で一度見た本 (RAR・入れ子・EXIF で縦横が入れ替わる JPEG を含む) で、
   横長判定の結果が OFF と同じになる。プレビューの無い書庫内 RAW のページサムネイルが Remote で取れる。
5. 本体の通し: 環境設定のダイアログで ON にして OK → 設定が保存される → 本を開く (worker が作られる)
   → 本の catalog にページの WebP 行が増えず寸法の行があり、親の catalog に表紙の行がある。既存の
   `make_load_request` → worker → catalog の検査 (`src/app/tests.rs` 52226 行付近) に倣う。
   ZIP を開いたまま ON にした場合、その ZIP の中のフォルダ移動では前の設定のまま、開き直すと効く。
6. 既存の行を消さない: ページの行がある本を ON で開き直しても、`delete_missing` の後に行が残る。
7. 代表の変更: ON で本に代表を固定し直すと、親の表紙の新しい `#pin:` 行が保存される。
8. 書き戻し: ページの行がある PDF を更新し (mtime・サイズを変える)、ON で開いて先頭ページを作り直しても、
   親の表紙行に古い画像が写らない (行が無いか、内容が新しい)。OFF で先頭ページを作り直して保存した
   場合は、今までどおり新しい画像が親へ写る。ZIP の正常な書き戻しも確かめる (比較する stamp は、
   ZIP はエントリの stamp、PDF は文書の stamp で、親に付ける `parent_entry_*` と混同しない。値は同じ
   items 世代の `image_metas[target_idx]` から取り、同期 I/O を足さない)。親の catalog が空の状態から
   ON で直接開いた場合は、親の表紙行が作られない (仕様)。
9. seed: ON では本を開いても親の表紙を先頭ページの行へ写さない (本の catalog に WebP の行が増えず、
   寸法の行が消えない)。OFF では今までどおり写す。
10. 設定: serde の既定 false、旧設定からの読み込み、環境移行の分類テスト、環境設定の検索項目。

## 7. 簡素化の検討 (CLAUDE.md「状態の組み合わせを減らす」)

- 採用: 判定を worker の保存直前 1 か所に置き、作り手ごとの印を作らない。
- 採用: 「先頭・代表」を表紙の行そのものと見なし、中の一覧での先頭・代表の識別と、代表変更時の
  保存受付をなくした (§5)。
- 採用: 反映の時点を既存のキャッシュ設定と同じ (worker が新しく作られる読み込みから) にし、表示中の
  一覧を追従させる処理を足さない。
- 採用: Remote の寸法は、Remote 側に補完を足すのではなく、OFF なら WebP の行が入る条件で寸法の行を残し、
  読む関数 2 つの中で合成する。呼び出し側と判定の材料は OFF と同じになる。
- 検討して採らなかった: ON の代償として Remote の横長判定・RAW のサムネイルの劣化を受け入れる案。
  通常の Remote の使い方で起こり得る劣化で、寸法の行は容量をほとんど使わないため。
- まれな失敗は割り切り (ログ + 通知 [+ 作り直し])。この設定は保存を減らすだけで、新しい失敗の経路を作らない。
