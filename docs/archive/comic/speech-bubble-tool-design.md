# 吹き出しツール設計メモ

Status: Codex 案 / Draft
Date: 2026-06-03

## 1. 結論

吹き出しツールは、補正レイヤーの一種ではなく、独立した「レタリング / 注釈オブジェクト」機能として
扱うのがよい。

推奨する処理順序は次の通り。

```text
元画像
  -> AI denoise / upscale
  -> 全体画像補正
  -> ポストフィルタ
  -> 消しゴム / 補完
  -> 補正レイヤー x N
  -> 隠蔽加工 (モザイク / 塗りつぶし / ぼかし)
  -> 吹き出し / キャプション / レタリング
  -> crop (任意、最後段)
  -> 表示 / 書き出し
```

ユーザーの直感としても、吹き出しは「画像を補正する」ものではなく「完成画像の上に載せる
可編集の文字オブジェクト」である。モザイクより後、crop より前に置くと、テキストは
ポストフィルタやぼかしで潰れず、crop では最終投稿範囲として自然に切り抜かれる。

ただし、既存の隠蔽加工は公開前の安全処理として重要なので、設計上は「隠蔽加工済みの
ラスター画像の上に、ユーザーが新規作成したレタリングを載せる」と明確に分ける。
吹き出し内の文字を隠したい場合は、その吹き出しを編集 / 削除する。既存の隠蔽加工で
吹き出しまで後段マスクする設計は v1 では入れない。

## 2. 調査サマリ

漫画向けツールやレタリング解説を確認すると、必要機能は大きく 5 群に分かれる。

| 観点 | 調査で見えた要件 | mIV での解釈 |
| --- | --- | --- |
| 作成 | 楕円 / 曲線 / ペン描き / 尾付き吹き出し / 素材から追加 | 最初からテンプレート追加 + ハンドル編集にする |
| 編集 | バウンディングボックス、回転、制御点、尾の曲げ、線幅/塗り変更 | 既存マスクオブジェクトの選択 / ハンドル編集感に寄せる |
| 文字 | フォント、サイズ、太字/斜体、揃え、縦書き、字間/行間、ルビ | 日本語縦書きと IME を初期設計の中核にする |
| レイアウト | 複数オブジェクトの整列、均等配置、複製、スタイル適用 | 画像投稿用途でも整列 / 複製 / スタイル保存は重要 |
| 漫画記号 | 通常会話、思考、叫び、ささやき、通信、ナレーション、オフ画面 | テンプレートとして用意し、後から詳細調整できるようにする |

Clip Studio Paint は、吹き出しを専用の balloon layer として作成し、線幅、線色、塗り、
尾の曲げ、制御点編集、変形、同一レイヤー内での結合、素材からの追加を持つ。テキスト側も
フォント、サイズ、スタイル、揃え、横/縦書き、字間 / 行間、ルビ、縦中横を扱う。
Comic Life 系のアプリは、吹き出し、キャプション、レタリングを画像上の配置オブジェクトとして
追加し、ドラッグ、リサイズ、即時テキスト入力、Undo、スタイル、複数尾、グループ / ロックを
重視している。レタリング解説では、尾が話者の口へ向くこと、叫び / 思考 / ささやき / 通信 /
ナレーションを形や線で区別すること、接線や読み順を避けることが繰り返し強調されている。

## 3. 補正レイヤーに入れない理由

補正レイヤーに `Text` / `Balloon` 効果を追加する案は、実装上は一見近道に見えるが避けたい。

- 補正レイヤーは「入力画像を変換する効果」で、吹き出しは「入力画像に依存しない編集可能な
  ベクター / テキストオブジェクト」である。
- テキストはフォント、IME、縦書き、ルビ、字間、行間、禁則処理、フォントフォールバックなど、
  画像フィルタとは別の複雑さを持つ。
- 補正レイヤー内に入れると、ポストフィルタ、ぼかし、モザイク、色補正の影響を受けて
  文字が潰れやすい。
- ユーザーは吹き出しを「選択して文章を直す」「尾を話者へ向ける」「順番を入れ替える」
  ものとして期待する。効果レイヤーのパラメータ UI だけでは操作感が合わない。
- 書き出し前の最終レイアウトとして扱う方が、SNS 投稿用のセリフ入れに自然である。

共有すべきものはある。キャンバス座標変換、選択ハンドル、Undo、矩形 / 楕円 / 多角形の
オブジェクト編集、サイドカー保存のキー規則は、消しゴム / 隠蔽加工 / 補正レイヤーの
既存資産に寄せる。

## 4. ユーザー向け機能要件

### 4.1 オブジェクト種別

初期から欲しいもの:

| 種別 | 用途 | 備考 |
| --- | --- | --- |
| 通常吹き出し | 会話 | 楕円、角丸、丸角矩形、自由曲線 |
| 思考吹き出し | 心の声 | 雲形 + 小円の尾 |
| 叫び / 驚き | 大声、衝撃 | ギザギザ / バースト形、太めの枠線 |
| ささやき | 小声 | 破線枠、薄い線色、グレー文字プリセット |
| 通信 / 機械音声 | 電話、無線、ロボット | 角張った枠、波線 / ジグザグ尾 |
| ナレーション枠 | 場所、時間、内心、説明 | 矩形 / 角丸、尾なし |
| 文字のみ | 画像上の短いセリフ / 注釈 | 枠なし、文字縁取りあり |
| SFX / 効果文字 | 擬音、強調文字 | v1 では文字のみの強化として扱い、変形文字は後続 |

後続候補:

- 複数吹き出しをつなぐコネクタ。
- 1 つの吹き出しから複数の尾を出す群衆会話。
- コマ端へ接する flat-side / butting balloon。
- 花、音符、汗、疑問符などの小さな漫画記号。
- 手描き風のランダムゆらぎ、筆圧風の線。
- 輪郭や内側に沿う手続き生成装飾。きらきら、花、泡、ふわふわ、レース風などを
  画像素材ではなく計算で生成し、自由なサイズ / 形状変更へ追従させる。

### 4.2 吹き出し形状

必要な調整項目:

- 位置、幅、高さ、回転。
- 角丸半径、楕円率、ギザギザ数、雲の丸み、線の揺れ。
- 塗り色、塗り不透明度、枠線色、枠線幅、枠線不透明度。
- 破線 / 点線 / 二重線 / 影 / 外側グロー。
- 内側余白。テキストと枠線が近すぎる事故を避ける。
- 前面 / 背面の z-order。
- オブジェクト単位のロック、表示 ON/OFF。

吹き出し本体は、最低限はパラメトリック形状で十分。自由曲線の制御点編集は便利だが、
初期実装では「標準形状 + 尾 + サイズ / 回転 / スタイル」で実用に届く。

### 4.3 尾

尾は吹き出しツールの価値を決める。

初期から欲しいもの:

- 尾なし / 三角尾 / 曲線尾 / 折れ線尾。
- 尾の付け根、先端、曲げ点をキャンバス上でドラッグ。
- 尾の幅、先端幅、丸み。
- 思考用の小円尾。
- オフ画面話者向けの端点マーク。
- 吹き出し移動時に尾も一緒に移動するか、先端を固定するかの切替。

レタリングの実用上、尾は話者の口元へ向く必要がある。ツール側では「尾の先端ハンドル」
を常に見つけやすくし、Shift で水平 / 垂直 / 45 度制約、Ctrl で細かい移動など、
既存キャンバス操作に近い補助を用意する。

#### 4.3.1 ツノの管理方式

参考実装として Studio Genesis C.A. の「吹き出しメーカー」を見ると、ツノは独立した
子オブジェクトではなく、吹き出し本体の形状から毎回再計算されるジオメトリとして扱われている。
通常ツノは本体輪郭に開口部を作り、付け根 2 点から先端へつなげた連続パスにする。
丸ツノ / 思考ツノは、輪郭上の付け根円と先端までの小円列として生成する。

mIV でもこの考え方を採る。

- 保存するのは `tail.tip`、`tail.kind`、`tail.width`、`tail.follow_mode` などのパラメータだけ。
- 本体の移動 / リサイズ / 回転 / shape 変更時に、付け根位置とパスを再計算する。
- `Triangle` / `Curve` は本体輪郭へ開口部を作る連続パスとして描く。
- `RoundBump` は輪郭上の丸 + 先端へ向かう 1〜3 個の小円列として描く。
- `ThoughtTrail` は思考吹き出し専用に見えるが、丸ツノとして楕円 / 角丸にも使えるようにする。
- surprise / text-only のようにツノが不自然な shape では UI 側でツノを disabled にする。
- 先端ハンドルは常に source image coordinate。表示時だけページ回転 / ズーム / pan を掛ける。

この方式なら、ツノの数式は `BubbleShape` の輪郭サンプラ / 法線計算と共通化できる。
装飾や合体も同じ輪郭情報を使えるため、`comic-core` に `outline_sampler(shape, transform)` を
置く価値が高い。

### 4.4 テキスト

吹き出し内テキストは、画像編集よりも文書編集に近い。

初期から欲しいもの:

- 複数行テキスト編集。
- 日本語 IME の変換を壊さない Enter / Escape 処理。
- 横書き / 縦書き。
- 縦書き内のインライン向き指定。短い欧数字 / `!?` / `!!!!` などを縦中横にする、
  英単語を 90 度横倒しにする、または 1 文字ずつ正立させる。
- フォント、サイズ、文字色。
- 太字、斜体、下線、取り消し線。
- 左 / 中央 / 右揃え。縦書きでは上 / 中央 / 下相当の揃え。
- 字間、行間。
- 枠内折り返し。
- 自動リサイズ: テキストに合わせて吹き出しを広げる。
- 自動フィット: 吹き出し内に収まるまで文字サイズを下げる。
- 文字の縁取り / 影。枠なしテキストで必須。
- プレビュー時の実ピクセルサイズ警告。投稿サイズで読めない文字を避ける。

#### 4.4.1 縦書き内の欧文 / 記号 / 感嘆符列

縦書きでは、欧文や半角記号の扱いを 1 種類に固定しない。日本語組版ではおおむね次の
3 表現を使い分ける。

| 表現 | 内容 | 主な用途 |
| --- | --- | --- |
| 正立 | 1 文字ずつ日本語文字のように立てて並べる | 単独の英字、頭字語、記号を強く見せたい場合 |
| 横倒し | 単語 / 文を 90 度回転して縦行内に置く | `LOVE`、`STOP`、英語の短文、長めの欧文 |
| 縦中横 | 短い横書きの塊を縦行の中央に収める | 2 桁数字、`!?`、`!!`、`!!!!`、短い英字略語 |

吹き出しでは、文末の `!!`、`!?`、`!!!!`、`?!` などは縦中横の対象にしたい。
「びっくり!!!!」なら、`びっくり` は縦書き、`!!!!` は横一列の塊として中央揃えする。
ただし横幅が行幅を大きく超える場合は、ユーザーに「文字サイズを下げる / 横倒しにする /
分割する」を選ばせる。

初期実装の自動ルール:

- 縦書き中、半角の数字 / 英字 / `!` / `?` / `.` / `,` / `:` / `;` が 1〜4 文字連続したら
  `AutoTateChuYoko` 候補にする。
- `!!`、`!!!`、`!!!!`、`!?`、`?!`、`??` は既定で縦中横にする。
- 5 文字以上の英単語は既定で横倒しにする。
- 全角英数字は既定で 1 文字ずつ正立にする。
- どの自動判定も、ユーザーが選択範囲へ手動指定した属性を上書きしない。

UI は入力記号ではなく、選択範囲に属性を付ける方式を主にする。

- 選択範囲ツール: `縦中横` / `横倒し` / `正立` / `自動` / `解除`。
- コンテキストメニュー: 選択中テキストを縦中横、横倒し、正立へ変更。
- テキストパネル: `短い半角列を自動で縦中横`、`自動文字数 1〜4`。

`びっくり[!!!!]` のような文字記法は v1 の主操作にしない。角括弧はセリフ内の実文字として
普通に使われ、IME 変換中の編集やコピー / 貼り付けでも壊れやすい。将来、キーボードだけで
大量入力したいユーザー向けに軽量マークアップを入れる場合も、保存データはマークアップ文字列ではなく
`TextRun` の属性へ展開して保持する。

日本語漫画用途で重要な後続候補:

- ルビ。
- 禁則処理。行頭に句読点や閉じ括弧が来ないようにする。
- 句読点ぶら下げ。
- 約物の詰め。
- 英文の単語単位折り返しと、日本語の文字単位折り返しを混在させる。
- 文字列全体を円形 / パス上へ配置する SFX 向けレタリング。

### 4.5 配置と編集操作

必要な操作:

- クリックで追加、ドラッグで配置、ダブルクリックでテキスト編集。
- 選択、複数選択、移動、リサイズ、回転。
- コピー / ペースト / 複製。
- 削除、Undo / Redo。
- 矢印キー 1 px 移動、Ctrl+矢印 10 px 移動。
- 前面へ / 背面へ / 最前面 / 最背面。
- 整列: 左 / 中央 / 右 / 上 / 中央 / 下。
- 均等配置。
- グループ化、ロック。
- オブジェクト一覧。
- スタイルコピー / ペースト。
- よく使う吹き出しスタイルの保存。

吹き出し作成直後はテキスト編集に入るのがよい。Comic Life のように、追加した瞬間に
入力できる方が投稿用の短いセリフ入れでは速い。

### 4.6 テンプレート / プリセット

初期プリセット:

- 白塗り + 黒枠 + 中央揃え。
- 白塗り + 黒太枠 + 叫び。
- 破線 + グレー文字 + ささやき。
- 雲形 + 小円尾 + 思考。
- 角丸矩形 + 色付き塗り + ナレーション。
- ぽってり長円 + 丸ツノ。
- 角丸 + 丸ツノ。
- 枠なし白文字 + 黒縁取り。
- 枠なし黒文字 + 白縁取り。
- SNS 向け大字幕。
- きらふわ: 白塗り / 薄い枠 / 輪郭外側の星きらめき。
- 花ふわ: 白塗り / 薄い枠 / 輪郭上の小花散布。
- 丸ふわ: 白塗り / ぼかし気味の多重丸 / 泡状ドット。

ユーザー定義スタイルは `settings.db` 側にグローバル保存し、ページ内オブジェクトには
スタイルを展開した値を保存する。スタイル削除後も既存ページの見た目が変わらない方が安全。

### 4.7 手続き生成装飾

CLIP STUDIO ASSETS には、少女漫画風モノローグ向けの「ふわ系」フキダシツールがあり、
丸ふわ / 花ふわ / きらふわのような装飾付き吹き出しが素材ツールとして利用されている。
mIV では画像素材を貼るのではなく、吹き出し形状に追従する手続き生成装飾として扱う。

生成単位:

| 種類 | 生成方法 | 用途 |
| --- | --- | --- |
| きらきら | 4 点 / 8 点星、十字光、短い光条を輪郭外側や内側へ散布 | 少女漫画、夢、かわいいモノローグ |
| 花 | 5 枚花びら、丸花、桜風花びらを輪郭に沿って配置 | 花ふわ、春、かわいい強調 |
| 泡 / 丸 | 半透明の小円、外側グロー、大小ランダム円 | 丸ふわ、やわらかい思考 |
| ハート / 音符 | 小さなシンボルを一定密度で配置 | 恋愛、楽しい声 |
| レース / フリル | 輪郭に沿う小半円や波線の連続 | 上品、手紙風 |
| 粒子 / 砂 | 小粒ドットを薄く散らす | 夢、回想、淡い発話 |

配置モード:

- `Outline`: 吹き出し輪郭上に装飾を置く。
- `Outside`: 輪郭法線の外側へ散らす。
- `Inside`: 塗り内側に薄く散らす。
- `Tail`: 尾の周辺だけに置く。
- `TextSafe`: テキスト矩形を避けて内側へ散らす。

実装方針:

- 各 `BalloonShape` は輪郭をサンプリングする `outline_sampler` を持つ。装飾はこの輪郭点、
  接線、法線、曲率を入力にして配置する。
- ランダム性は `object_id + decoration.seed` から作る決定論的 PRNG にする。リサイズしても
  同じ雰囲気を保ち、保存 / 再読込 / 書き出しで結果が揺れない。
- 装飾サイズは、画像 px 固定ではなく、吹き出し短辺に対する比率と最小 / 最大 px を併用する。
- 密度は「輪郭長あたり N 個」「面積あたり N 個」で指定する。大きい吹き出しほど自然に増える。
- 生成結果は保存せず、パラメータだけ保存する。表示 / 書き出し時に同じ seed で再生成する。
- 素材画像の複製にならないよう、花や星は単純なベジェ / 多角形 / SDF で生成する。
- 透明感、線の太さ、塗り、グロー、回転ゆらぎ、サイズゆらぎをパラメータ化する。

初期プリセットとしては、`きらふわ`、`花ふわ`、`丸ふわ` の 3 種を用意すると実用感が高い。
これらは既存素材を取り込むのではなく、同じ「ふわっとした装飾吹き出し」というカテゴリを
パラメータで再現する。

### 4.8 同色吹き出しの合体

Studio Genesis C.A. の「吹き出しメーカー」は、レイヤーの重なり方として「上に乗せる」と
「1つ下の同色レイヤーと合体」を持つ。実装上は、連続する同色・同不透明度の吹き出しを
描画グループにまとめ、白フチ / 枠線 / 塗りをグループ単位で合成して、後段レイヤーの形で
重なり部分を抜く。厳密なベクター Boolean union ではないが、UI としては「同色の吹き出しが
つながって見える」効果を軽く実現している。

mIV の設計では、次の 2 段で扱う。

| 段階 | 方式 | 用途 |
| --- | --- | --- |
| Phase 2 | 軽量グループ合体 | 連続する同スタイル吹き出しを `MergeGroup` として描画し、塗り / 枠 / 白フチを一体化して見せる |
| 後続 | 幾何 union | `kurbo` / `lyon` 等で輪郭 union を取り、編集済みの単一複合パスへ変換する |

軽量グループ合体の仕様:

- 各 `BalloonObject` に `merge_mode: Normal | MergeWithPreviousSameStyle` を持たせる。
- 合体条件は、前の描画オブジェクトと fill / opacity / outline / white_outline / decoration が同じこと。
- 合体中でも、各吹き出しのテキスト、ツノ、選択、移動、削除は独立したままにする。
- レイヤー一覧では合体中の行に `合体` バッジを出す。
- 後段の別レイヤーが上に乗る場合は、その形状で下の合体グループを隠す。これにより前後関係が分かりやすい。

この機能は、漫画で複数の丸い吹き出しを重ねて 1 つの発話に見せる用途に効く。
最初から完全な Boolean union を狙うより、編集可能性を保つ軽量合体を先に入れる方がよい。

### 4.9 再生成 seed とランダム形状

びっくり / 思考 / ふわ系装飾は、毎回同じ完全な形ではなく、少し揺らぎがある方が自然に見える。
ただし、保存や書き出しのたびに形が変わると困る。そこで `shape_seed` と `decoration.seed` を
保存し、ユーザーが `再生成` を押した時だけ seed を変える。

- `Burst`、`Cloud`、`Wavy` は `shape_seed` で輪郭ゆらぎを決める。
- `DecorationLayer` は layer ごとの `seed` で配置を決める。
- UI には `再生成` ボタンを出す。対象は shape / 装飾のどちらか、または両方を選べる。
- Undo / Redo では seed 変更も通常操作として扱う。

### 4.10 透明背景書き出し

参考ツールは、背景画像なしでも保存でき、その場合は背景透過素材になる。mIV でも
吹き出し単体素材の作成需要がありそうなので、通常のページ注釈とは別に後続候補として残す。

- 現在ページ上の選択吹き出しだけを透明 PNG として書き出す。
- 複数選択時は bbox で切り出す。
- 背景画像を含める / 含めないを export で選べる。
- これは元画像編集パイプラインとは別の「注釈素材書き出し」なので、通常 Ctrl+E の既定にはしない。

## 5. mIV への統合案

### 5.1 UI 入口

フルスクリーン上部バー / 画像補正パネルの処理順アイコンは、次の順にする。

```text
消しゴム -> 補正レイヤー -> 隠蔽加工 -> 吹き出し -> エクスポート / crop
```

吹き出しパネルは補正レイヤーとは別パネルにする。

左パネル:

- オブジェクト一覧。
- 追加ボタン。
- 選択オブジェクトの種類。
- テキスト入力。
- フォント / サイズ / 方向 / 揃え。
- スタイルプリセット。

右ツールパネル:

- 形状、尾、線 / 塗り。
- 手続き生成装飾。星 / 花 / 泡 / ハート / レース、密度、サイズ、seed、配置モード。
- 配置、整列、z-order。
- テンプレート保存。

キャンバス上:

- 選択枠、リサイズハンドル、回転ハンドル。
- 尾の付け根 / 曲げ点 / 先端ハンドル。
- テキスト編集時の caret / IME preedit 表示。

### 5.3 永続化

新規 DB:

| ファイル | 内容 |
| --- | --- |
| `balloon.db` | ページ単位の `BalloonDocument` JSON |

キー規則は `adjustment.db` / `local_adjust.db` / `export_crop.db` と揃える。

- `Image`: 正規化済み絶対パス。
- `ZipImage`: ZIP 本体パス + エントリ名。
- `PdfPage`: PDF 本体パス + page index。

サイドカー `mimageviewer.dat` には `balloons` としてミラーする。フォルダ移動時の復元価値が高く、
補正レイヤーや crop と同じく「中央 DB が authoritative、サイドカーはバックアップ」にする。

フォントファイルそのものは保存しない。`font_family` とフォールバック候補だけを保存し、未導入
フォントの場合は起動時に代替フォントで表示し、パネル上で警告する。将来、投稿再現性を強めるなら
ユーザー指定フォントの埋め込みやコピーも検討するが、ライセンス面の確認が必要になる。

### 5.4 表示 / 書き出しパイプライン

表示用の通常テクスチャ選択は既存の `resolve_fs_processed_texture` を維持する。
その結果に、吹き出しレイヤーをオーバーレイとして重ねる。

```text
resolve_fs_processed_texture()
  -> conceal_cache or lower layer texture
  -> balloon overlay
  -> crop preview overlay
  -> rotation / zoom / pan / fit
```

実装上は 2 段を分ける。

- 編集中表示: egui shapes / galley でベクター風に描く。ハンドル操作と IME の追従を優先する。
- 書き出し / キャプチャ: worker でラスター合成する。表示と同じ line break / font fallback /
  shape tessellation を使い、WYSIWYG の差を最小にする。

重い処理は UI スレッドに載せない。

- フォント一覧の初回列挙は worker または起動時キャッシュ。
- 大きいページへの高解像度テキストラスタライズは worker。
- `.ttf` / `.otf` をユーザーが指定する場合、読み込みと検証は worker。
- `ctx.load_texture` は 1 フレームに 1 枚程度へペーシングする。

キャッシュ:

| キャッシュ | キー |
| --- | --- |
| `balloon_overlay_cache` | page idx + image size + balloon_generation + font_generation |
| `balloon_composite_cache` | lower input generation + overlay generation |

編集操作中は古い合成結果を最終出力に使わない。表示は下位画像 + 編集中ベクター overlay で即応し、
キャプチャ / Ctrl+E は worker 合成完了後だけ許可する。

### 5.5 サムネイル

v1 ではサムネイル画像へ吹き出しを焼き込まない方がよい。

理由:

- 小さなサムネでは文字が読めず、ノイズになりやすい。
- 補正レイヤーもサムネイル非反映の方針で、重い仕上げ系を一覧へ持ち込まない設計と合う。
- テキストレンダリングとフォント fallback をサムネ worker へ持ち込むと負荷と依存が増える。

代わりに、ページに吹き出しがある場合はサムネ左上に `吹` バッジを出す。将来、希望が強ければ
設定で「サムネに注釈を表示」を追加する。

### 5.6 右 Ctrl 元画像プレビュー

右 Ctrl の元画像プレビューでは、吹き出しも一時的に非表示にする。

理由:

- 既存の右 Ctrl は raw decode を見るための機能であり、ユーザー作成の注釈も比較対象から外す方が直感的。
- 吹き出しを確認したい場合は通常表示に戻せばよい。

### 5.7 見開き

初期実装はページ単位の吹き出しに限定する。見開き表示時は左右ページそれぞれの
`BalloonDocument` をページ矩形内に描く。

後続候補:

- 見開き全体にまたがる吹き出し。
- 見開き中央をまたぐ SFX。
- 左右ページ間のオブジェクト移動。

これらは保存キーと crop / export の扱いが複雑になるため、v1 では避ける。

## 6. IME / ショートカット

吹き出しツールは multiline TextEdit を使うため、既存の IME ルールを最重要にする。

- `Enter` は通常は改行。`Ctrl+Enter` または明示ボタンで編集確定。
- `Escape` は IME 変換中なら変換キャンセルを優先し、ツール終了や編集確定を発火しない。
- `dialog_enter_pressed(ctx)` / `dialog_escape_pressed(ctx)` と同じ考え方を、フルスクリーン内の
  吹き出し編集にも適用する。
- テキスト編集中は、ページ送り、削除、コピー、貼り付け、Undo などのグローバルショートカットを
  TextEdit 側へ優先させる。
- `Ctrl+V/C/X/A/Z/Y` は、TextEdit にフォーカスがある間はテキスト編集として扱う。
- IME candidate window が caret 位置に追従するよう、フルスクリーンビューポート入口で
  既存の `update_ime_state(ctx)` 経路を使う。

動画 native presenter overlay の TextEdit で整えた IME / clipboard の知見も参考にする。
吹き出し編集を動画には当面適用しないが、独立 HWND / viewport で TextEdit を扱う場合の落とし穴は同じ。

## 8. 検証項目

- Image / ZipImage / PdfPage で保存キー、表示、書き出しが一致する。
- フォルダ移動後、sidecar から吹き出しが復元される。
- 隠蔽加工済み画像の上に吹き出しが乗る。
- crop 変更で吹き出しが最終出力範囲に合わせて切り抜かれる。
- 右 Ctrl 元画像プレビューで吹き出しが非表示になる。
- テキスト編集中、IME の Enter / Escape がツール操作に奪われない。
- TextEdit フォーカス中にページ送り / 削除 / Undo がグローバル操作へ漏れない。
- 4K / 8K 画像で吹き出し操作中に UI が固まらない。
- フォント未導入環境でも代替表示され、JSON 読み込みで panic しない。
- Ctrl+E / キャプチャ保存で表示結果と同じ文字位置 / 行分割になる。
- きらふわ / 花ふわ / 丸ふわ装飾が、吹き出しのリサイズ / 回転 / shape 変更に追従し、
  同じ seed なら保存 / 再読込 / 書き出しで同じ配置になる。
- `MergeWithPreviousSameStyle` の吹き出しが、個別編集可能なまま同色グループとして一体表示される。
- `再生成` で shape / 装飾の seed が変わり、Undo / Redo で元の形へ戻る。
- サムネイルには `吹` バッジだけが出て、サムネ生成 worker がフォント処理を始めない。

## 9. 実装時の注意

- UI スレッドでフォントファイル読み込み、フォント一覧走査、高解像度ラスタライズをしない。
- `try_lock` + `sleep` の待ち合わせを入れない。合成完了は generation 付き channel で受ける。
- JSON は `schema_version` と `#[serde(default)]` 前提で後方互換にする。
- 文字列は任意 Unicode を許容する。保存は UTF-8。PowerShell で読むときは
  `Get-Content -Encoding UTF8` を使う。
- フォント名や外部フォントパスを扱う場合は、存在確認、拡張子、サイズ上限、読み込み失敗時の
  フォールバックを必ず用意する。
- エクスポートは既存の `create_new` 方針を守り、元画像を直接上書きしない。
