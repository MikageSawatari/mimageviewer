# 検収所見 #7: ON モード + ZIP/PDF 直開き OFF で、ページ一覧からの open が連動窓になる

正本プラン: [../../detached-rework-plan.md](../../detached-rework-plan.md) /
CUT 仕様: [stage-cut §1.1](detached-rework-stage-cut.md)

ゲート C smoke (2026-07-07) でユーザーが発見。

## 症状 (再現確定)

- 設定: 複数ウィンドウ **ON** (画像/動画を別ウィンドウで開く) + **ZIP/PDF 直開き OFF**
  (開いたらページ一覧を表示)
- ZIP/PDF を開いてメインにページ一覧を表示 → 一覧から画像 (ページ) を開く
- → 開いた画像ウィンドウが**メインと連動**している (メインの選択で中身が変わる)

## 仕様違反

CUT §1.1: **ON モードでは全ての detached 窓は生まれつき独立** (自前 bundle、メイン
連動なし)。連動窓は OFF モード専用。

直開き ON の経路 (ZIP/PDF → 直接ページ表示) は独立になるのに、直開き OFF の
「ページ一覧 → ページ open」経路がモード判定を通っておらず、連動窓を作っている。

## 修正要件

1. ページ一覧 (ZIP/PDF を仮想フォルダとして開いた状態) からのページ open 経路に
   ON モード判定を通し、独立窓 (自前 bundle) で開く。直開き ON/OFF で最終状態が
   同じ (独立窓) になること。
2. 通常フォルダ内の画像 open (既に独立) との経路差を確認し、モード判定の分岐が
   1 箇所に集約できるならそうする (open 経路ごとの重複判定はこのバグの温床)。
3. OFF モード + 直開き OFF の従来挙動 (連動窓 1 枚) は不変。
4. テスト:
   - ON + 直開き OFF: ページ一覧から open → runtime.linked=false + 独立 bundle +
     メイン選択に追従しない
   - ON + 直開き ON / OFF + 直開き各設定の 4 象限を遷移テストで固定
5. コミットに `(detached-rework findings-7)` を含める。
