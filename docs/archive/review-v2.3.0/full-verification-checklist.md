## 4. 複数ウィンドウモード

    再activate → 正常継続。※合格済み、軽く。
24. **削除×別窓再生** (旧#5,6): 別窓再生中にグリッドで無関係ファイル削除 → 再生継続・
    サムネ/選択正常。視聴中ファイル削除 → 窓が閉じて削除される。
    2026-07-10 実機: 視聴中削除は「窓 close → ハンドル解放が非同期」の競合で初回が
    共有違反で失敗することあり (2 回目で成功)。ユーザー許容済み = 既知動作。
    改善案 (削除 worker の短時間リトライ) は backlog §1.11。
24a. **detached 切替中のメイングリッド削除**: `A.jpg, B.mp4, C.mp4` の順で B を
     detached 再生 → A の削除開始 → 完了前に C へ移動して「準備中」→ A の削除完了後も
     C への切替が消えず、そのまま再生を継続する。
24b. **次曲削除後の EOF skip** (追補第 6 弾): A/B/C を連続再生対象にして A を別窓再生 →
     A の snapshot を park/promote した後、メイン一覧で次曲 B を削除または rename → A の EOF で
     欠損した旧 B をスキップして C の再生が継続する。全候補を消した場合は従来の末尾動作になる。
24c. **NAS/切断ドライブ相当でも EOF/次送りで UI が固まらず thread が増えない (可能なら)**
     (追補第 7・11 弾):
     UNC/NAS または切断可能な外付け媒体上の A/B/C を一覧化して A を再生 → B/C を到達不能にする →
     手動の前後送りを 20 回ほど連打し、連続再生 EOF も発火。存在確認中もメイン UI が操作・
     再描画でき、タスクマネージャーの mIV thread 数が入力回数に応じて単調増加しない
     (media-nav resolver は最大 1 thread)。ParkedLive の EOF 解決中にメイン一覧を操作しても
     自動次送りが永久停止せず、復帰後に次候補へ進むか、全候補失敗後に従来の境界動作へ着地する。
25. **parked 音楽×画像閲覧** (旧#7): 音楽を別窓再生 → メイン窓で画像を次々開く →
    別窓のタイムライン/スペクトラムがリセットされない・CPU 正常。
    (park 中のタイムラインは入力無効の「クリックで操作に戻る」表示 + スペクトラム

25a. **tile mode の ParkedLive close**: 動画 A を S で tile mode → 画像を開いて A を

    右ドラッグ → グリッド用候補が出てグリッド対象に効く。
    (既知動作 2026-07-10 ユーザー合意: 窓が非アクティブのときは右クリックでリングが
    出ない = 最初のクリックは活性化に使われる。仕様として許容)
31. **スタック×複数ウィンドウ**: 集約ビューでスタックをクリック → 別窓で画像が開き
    Shift+↓↑ でスタック間ジャンプ。(メイン一覧はフラット読書ビューに切り替わる = 現仕様)
31b. **parked 画像窓の復帰フォールバック** (旧#25、§2 から移動 — parked 窓は本モードのみ):
    画像を別窓表示 → メイン窓の操作で窓が parked still 化 (別の画像をグリッドから開く /
    フォルダ移動の legacy park) → **さらに別フォルダへ移動してから** parked 窓をクリック →
    親フォルダが窓内に読み込まれ同じ画像で復帰。復帰後の窓内で ←→ ページ送り可。
31c. **★固定×parked 復帰** (旧#37、§2 から移動。2026-07-10 に条件を正確化):
    **通常の parked 窓は ★固定中でもそのまま復帰できるのが正しい** (窓は自分の文脈を
    持ち、メイン一覧のロックと無関係。実機確認済み 2026-07-10)。
    「復帰できません (★固定を解除してください)」トーストが出るのは**縮退ケース限定**:

    フォールバック」しか残っていない窓を、★固定中にクリックしたときだけ。このとき
    load_folder が★固定で早期 return するため、進めると窓が無言で消える → 事前に弾いて
    **窓を parked のまま残す**のがガードの目的。(任意) この組み合わせを作って
    トースト + 窓残存 + ★固定解除後の復帰を確認。

## 7. ファイル操作 × 複数ウィンドウ (2026-07-10 角度④修正の確認)

40. **再生中ファイルの削除**: 動画/音声をメディア窓 (または parked) で再生したまま、
    メイングリッドからそのファイルを削除 → 窓が閉じて削除が成功する
    (以前は decoder が掴んでいて削除失敗が繰り返された)。

    修正済み (Sol 実装: 窓 close 後の decoder teardown が非同期で IFileOperation が
    ロック中 abort する競合 → 削除 worker 内で abort/共有違反系のみ 200ms×5 回
    リトライ、失敗分のみ再投入・キャンセル 20ms 応答)。**再確認**: 同じ手順で
    1 回の削除操作で成功すること。
41. **別窓表示中のファイルのリネーム**: 画像を別窓 (parked) で表示したまま

42. **メイン fullscreen の削除スライド退行なし**: メイン fullscreen で画像を

## 8. 終了処理

49. **大量削除直後の有界終了 (追補第12弾)**: お気に入り監視対象で数千ファイルを
    まとめて削除し、削除完了直後 (indexerの差分追従 / overflow再scan中) にmIVを終了 →
    数秒以内にプロセスが終了し「応答なし」で残らない。再起動後にCtrl+Gで削除済み項目が
    残らず、残存ファイルは従来どおり検索できることも確認する。
50. **全メタ hard purge / missing 非破壊 (追補第13弾・改)**:
    - ★・補正・タグ・回転を付けたファイルを mIV で削除 → ★件数が即減り、各メタも消える。
    - 同じファイルをごみ箱から同じ path へ復元 → 以前のメタは戻らない (仕様)。
    - 外付けドライブを切断中にタグ検索 → 結果からは隠れるが、再接続後もタグは残る。
51. **削除確認の固定キー (追補第15弾)**: 削除確認で Y = 削除、N / Esc = キャンセル、
    Enter は無反応。Y / N に背面グリッド操作を割り当てた設定でも、確認を閉じた同 frame に
    背面へ反応が漏れない。日本語 IME 変換中の Y / N / Esc は確認操作として発火しない。
52. **本棚追加の未焼き込み編集警告 (追補第15弾)**: 隠蔽 / 消しゴム / 補正レイヤー /
    テキスト注釈のある通常ページを 1 枚・複数・スタックから本へ追加 → 追加完了後に
    「本棚のファイルには反映されない」警告が 1 回だけ出る。補正のみ・回転のみ・無編集では
    警告が出ず、従来どおりの追加結果になる。
53. **孤児メタデータ整理 (追補第16弾)**:
    - 削除済みファイルの孤児 rating を含む状態で「設定 → サムネイルキャッシュ管理 →
      メタデータを整理…」→ スキャン → 件数確認 → 整理を実行し、★件数が正しく減る。
    - 外付けドライブを切断した状態でスキャン / 整理 → そのドライブの行が
      「オフライン保護」として残り、再接続後に★・タグ等が維持されている。
54. **削除中に DB ロックが起きても再起動で旧メタが消える (journal 再試行、追補第17弾)**:
    ★・タグ・補正を付けたファイルを削除中に
    `rating.db` 等を別プロセスで排他ロックし、初回 + 3 回の purge を失敗させる → ファイル削除自体は
    成功する → ロックを解除して mIV を再起動 → 同じ path の旧メタが消え、同名ファイルを作り直しても
    旧★・タグ・補正が復活しない。ログに `[delete-purge] retry done` と `remaining=0` が残ること。
55. **大量ファイル削除の速度 (追補第20弾)**: メタを付けたものを含む 1400 件以上をまとめて削除し、
    ごみ箱移動の進捗が従来どおりチャンク単位で進み、完了までの体感速度が第13b弾以前と同等で
    あること。途中キャンセルした場合も、すでにごみ箱へ移った分だけが一覧から消え、その分の
    ★・タグ・補正等だけが消えること。
56. **大量メタ環境の末尾 purge (追補第21弾)**: rating / tag等が数万行ある環境で
    1000～1400件以上をまとめて削除し、ごみ箱移動後の末尾purgeが数秒以内に完了して
    「削除中」ダイアログが閉じること。exact file、削除フォルダ配下、ZIP / PDF container配下の
    ★・タグ・補正・回転等が消え、名前が隣接する別pathのメタは残ること。
