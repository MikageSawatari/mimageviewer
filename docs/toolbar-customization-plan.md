# ツールバー カスタマイズ / セクション統一モデル 実装計画

ステータス: **設計のみ・未実装** (2026-06-19 起案)。
**UI を大きく変えるため、段階的 MVP ではなく一度に完成形を目指す** (ユーザー方針)。
本リファクタは**整理系機能 ①ファイル名スタック / ②製本クイック追加 より先**に入れる
(本棚ピン留め等が、このモデルの上に乗るため。§7)。

## 0. 背景と目的

機能追加に伴いツールバーが肥大化し、セクションの UI も不揃いになっている:
- **タグ**だけ「設定 / 検索」ボタンを持つ。**本棚**だけ「ComboBox + 開く + 追加」の独自構成。
  **お気に入り**は設定 affordance なし。
- 表示/非表示・表示形式の調整が**環境設定ページに埋もれて**いて発見しにくい。
- セクションの**順序はハードコード**で並べ替えられない。

目標 = **全セクションを 1 つの統一コンポーネントに揃え**、操作・カスタマイズ・並べ替えを
一貫させ、環境設定のツールバーページを撤去する。

## 1. 統一セクションモデル

各セクション = `[ドラッグハンドル] [ラベル / ⚙] [ 項目を表示形式で描画 ]`。

### 1.1 ジェスチャマップ: 左=副作用なし / 右=副作用あり (確定)

項目の操作を全セクションで統一する。**左クリック = 安全 (開く・ビュー) / 右クリック = 変更
(追加・付与)**。

| セクション | 項目 左クリック (安全) | 項目 右クリック (変更) | 項目管理の置き場所 |
| --- | --- | --- | --- |
| 本棚 | その本を**開く** | 選択/カーソル/FS ページを**コピー追加** (重複 skip + トースト) | ⚙: 固定解除 / 改名 / 本の管理 |
| タグ | そのタグの**タグビューを開く** (`open_tag_view_for_tag`) | **タグ付与** (トグル、`request_tag_toggle_for_selection`)。**Shift+右 = 今いるコンテナへ付与** | ⚙: タグ設定 |
| お気に入り | フォルダへ**移動** | (なし = 読み取り専用) | ⚙: お気に入り編集 |
| 列 / 比率 / ソート | 値を選ぶ (= 適用) | — | ⚙: 表示形式 / 出す項目 |
| ★ レーティング | その評価で**絞り込み** (フィルタ) | その評価を**選択へ付与** (`apply_rating_to_selection`)。**Shift+右 = 今いるコンテナへ付与** (`set_current_folder_rating`) | ⚙: 表示形式 |
| スマートフィルタ等 | フィルタ適用 | — | ⚙ |

- **帰結**: 項目の右クリックは「変更操作の直接実行」なので**項目右クリックに管理メニューを
  出さない**。固定解除/改名等の項目管理は **⚙ / セクションラベル右クリック / 管理画面**へ。
- **お気に入り**は変更操作が無いので左クリック (移動) のみ。
- **★ レーティング (2026-06-19 確定)**: ★0〜5 の各ボタンは「その評価値」を表し、左=その値で絞り込み
  (安全)、右=その値を**選択へ付与** (変更)、**Shift+右=今いるコンテナ (親フォルダ/ZIP/PDF) へ付与**。
  「なし」ボタンの右クリック = 評価 0 (クリア)。付与操作 (`apply_rating_to_selection` /
  `set_current_folder_rating` / `current_folder_rating`) は既存なので配線のみ。右クリックの対象解決は
  タグと同じ `selection_target_indices` (フルスクリーンページ > チェック集合 > カーソル) に揃える。
- **コンテナ対象の修飾 (Shift+右) = 一般規則 (確定 2026-06-19、(B) 採用)**: 「**右 = 選択へ /
  Shift+右 = 今いるコンテナへ**」を **★ レーティングとタグの共通ルール**にする (学習を一度で済ませる)。
  - 「今いるコンテナ」= `current_folder` (= 実フォルダ / ZIP / PDF)。**PDF/ZIP のページ一覧を
    閲覧中は、その PDF/ZIP 自体がコンテナ**になり、Shift+右でその本 (PDF/ZIP) に付与できる
    (ユーザー要望)。
  - 実装: ★は `set_current_folder_rating` (既存) を流用。**タグは「現在のコンテナへ付与」の
    helper を新設** (rating と対称。`current_folder` → tag target を**アーカイブパス remap 付き**で
    解決し、`request_tag_toggle_for_selection` と同じ書き込み経路に流す)。
  - 注意: `current_folder` が ZIP/PDF のときも container 付与が効くことを確認する (実フォルダ前提の
    コードが無いか)。`GridItem` の `container_ratable` 相当 (タグは container 対象の許可) に揃える。
- **既存タグからの変更**: 現状タグは「左=トグル(変更) / 右=このタグで探す(安全)」で、本モデルは
  **左右を入れ替える** (左=タグビュー / 右=付与)。意図的に安全側へ倒す。大きな UI 変更の一部
  として一括切替する。

### 1.2 右クリックの 2 つの対象 (混同しない)
- **項目** (ピン本ボタン / ピンタグボタン等) の右クリック = §1.1 の変更操作を**直接実行**
  (メニューを出さない)。
- **セクションのラベル / ⚙** の右クリック (またはクリック) = **そのセクションの設定メニュー**
  (表示/非表示・表示形式・出す項目・編集・検索/開く)。詳細ビューのヘッダー右クリック
  (`draw_details_column_context_menu` + `response.context_menu`、[src/ui_main.rs](../src/ui_main.rs))
  の idiom を流用。
- **ツールバーの空き領域**の右クリック = **全セクションの表示/非表示チェックリスト** +
  「既定に戻す」。現在の `show_toolbar_*` チェック (環境設定) を置換。

## 2. データ駆動セクションモデルと行 (順序・並べ替え・改行の土台)

### 2.0 現状の作り (2026-06-19 実機コード確認)
- ツールバー周辺は**複数の独立した `TopBottomPanel::top` が縦に積まれた構造**で、順序は
  `App::update` の呼び出し順で固定 ([src/app.rs](../src/app.rs) 36151〜): メニュー (`menubar`) →
  ツールバー (`toolbar`) → アドレスバー (`address_bar`) → 検索/タグ等の文脈バー →
  ファセットバー (`facet_filter_bar`) → 詳細遅延ステータスバー。
- **メインツールバー (`toolbar`) は `horizontal_wrapped`** ([src/ui_main.rs](../src/ui_main.rs) 3416〜)
  = 幅に収まらなければ**自動で次の行へ折り返す**。セクション順はコード内 `if show_* {}` 並びで
  固定、**手動の改行指定は無い** (折返しは幅まかせ)。
- **アドレスバー (フォルダバー) は別パネル (独立した行)** で、左端から path 入力 + フォルダ系
  ボタン (A/B クイック・履歴戻る進む・親・前後フォルダ・お気に入り・履歴メニュー・ピン) を出す。
  各表示/非表示は環境設定で個別 ON/OFF 済み。**ユーザーが見る「行頭から出る」挙動は、
  アドレスバーがツールバーと別の左寄せパネルだから**。

### 2.1 セクション順 (ドラッグ並べ替え)
- `ToolbarSectionId` enum + **永続順序 `toolbar_section_order: Vec<ToolbarSectionId>`**
  (詳細列の `details_column_order` と同型)。render はこの Vec をループして各セクションを描く。
- **ドラッグ並べ替え (最初から実装)**: 各セクション左端のハンドルをドラッグ → ドロップで Vec を
  更新・永続化。詳細列のドラッグ並べ替え (既存) を流用。
- 表示/非表示は既存 `show_toolbar_*` を流用 (空き領域右クリックから切替)。保存順に無い新セクションは
  末尾追記 fallback (`details_ordered_columns` と同じ)。

### 2.2 行の扱い: 自動折返し + 手動「行頭」フラグ (推奨方針、要確認)
- メインツールバーの**自動折返し (`horizontal_wrapped`) は維持** = ピンが増えても**絶対に
  はみ出さない/欠けない**安全網。
- 加えて、**セクションごとに「行頭に表示 (= ここで改行)」フラグ**を持たせる (順序 Vec に
  line-break マーカー、または各セクションの `new_row: bool`)。ユーザーが行の区切りを固定でき、
  幅まかせの折返しに頼らず**意図した行構成**にできる。
- UI = **セクション右クリック / ⚙ メニューに「□ 行頭に表示」チェック** (ユーザー提案)。
  手動指定が無いセクションは従来どおり幅で自動折返し → 両立。
- §3 の折りたたみ/プルダウンとも両立 (多項目セクションは「畳む」か「別行へ送る」かを選べる)。

### 2.3 アドレスバー (フォルダバー) のスコープ (2026-06-19 実機確認の上で確定)
- **path 入力をツールバーに統合しない (別パネル維持)**。理由: path 入力は
  `egui::TextEdit::singleline(&mut self.address).desired_width(f32::INFINITY)`
  ([src/ui_main.rs](../src/ui_main.rs) 5281〜) で**残り幅を貪欲に埋める**設計。`horizontal_wrapped`
  の中に「無限幅」ウィジェットを置くと、**path 入力の幅が手前の折返し状況に依存して不安定**になり
  (前に他セクションが並ぶと入力欄が潰れる)、実用に耐えない。描画自体は可能だが UX が壊れる。
- **将来オプション (後続・今回やらない)**: フォルダ系**ボタン** (←/→・親・前後フォルダ・A/B・
  お気に入り・履歴メニュー・ピン) は単なるボタンなので、ツールバーのセクションとして reorder
  対象にできる (幅問題なし)。path 入力だけ専用行に残す分割。
- **アドレスバーの位置のカスタマイズは §2.4 のバー縦順 (軽い形) で実現**する (path 入力の幅問題に
  触れずに済む)。

### 2.4 バーの縦順入れ替え (軽い形、採用)
- パネルは独立した `TopBottomPanel::top` を `App::update` の**呼び出し順**で縦積みしているだけ
  ([src/app.rs](../src/app.rs) 36151〜)。egui は呼び出し順で上から積むので、**縦順 = 呼び出し順**。
- **採用する軽い形**: 並べ替え対象を **{ツールバー / アドレスバー / ファセットバー} の少数に限定**し、
  永続した順序 (または「アドレスバーをツールバーの上/下」トグル) で呼び出し順を決める。
  実装は `match bar_id` で dispatch するループ + 戻り値をローカルに集約するだけ。
- **固定するもの**: メニューバーは最上部固定。検索 / タグ / favsearch 等の**文脈バー**と
  詳細遅延ステータスバーは固定 (モード依存で出入りするため並べ替え対象にしない)。
- **非採用 (重い形)**: どのバーも自由にドラッグで縦移動。render 戻り値の取り回し + 対象選別が増え
  割に合わない。

## 3. 表示形式の一般化

- 既存 `ToolbarSectionDisplay` ([src/settings.rs](../src/settings.rs)、現 `Buttons`/`Dropdown`) に
  **`Collapsible`="折りたたみ"** を追加 → **展開 / 折りたたみ / プルダウン**。
- **本棚 = 折りたたみ / プルダウンの 2 択**。お気に入り / タグも表示形式を選べる
  (既定は展開 or 折りたたみ)。**列 / 比率 / ソートは従来どおり 展開 / プルダウン**
  (`Collapsible` は付けない)。
- **折りたたみ**: ▶/▽ トグル。展開時は横並びボタン (1 クリック)、畳むと隠す。
  **畳み状態を永続化** (`toolbar_<section>_collapsed: bool`)。
- **プルダウン (お気に入り/タグ/本棚)**: 単一値 ComboBox ではなく**ポップアップの行リスト**。
  各行 左=安全 / 右=変更。行に登録/付与状態 (`On`/`Mixed`/`Off`、[src/ui_metadata_panel.rs](../src/ui_metadata_panel.rs)
  の `TagButtonState` を流用) を表示。

## 4. 発見性 (左右の意味を覚えてもらう)

- **各項目ホバーのツールチップ**: 「左:開く ／ 右:追加」(本) / 「左:タグビュー ／ 右:付与」(タグ)。
  展開・折りたたみ・プルダウンの**全モード**で出す。最も確実な学習手段。
- **プルダウンを開いた先頭にヒント行**: 「左クリック:開く ／ 右クリック:追加」。
- 右クリックは非発見的なので、ツールバー端の小さな ⚙ の常設や初回ヒントで補う。

### 4.1 技術リスク: ポップアップ内右クリック (実装初手で要検証)
- **egui 0.33 でプルダウン (ComboBox/Popup) の行に対する右クリックが安定動作するか未確認**
  (ポップアップが click で閉じる / 右クリックを食う可能性)。
- **フォールバック**: プルダウンの各行を「項目名 + 小さな副アクションボタン (例 `＋`=追加)」に
  して右クリックに依存せず 2 動作を出す (プルダウン時だけ左右対称を崩す)。展開 / 折りたたみは
  通常ボタンなので右クリックは確実。
- 着手時にまずこの 1 点を確かめ、不可なら全プルダウンをフォールバック方式で設計する。

## 5. 環境設定ツールバーページの撤去

- §1.2 (右クリック) + §2 (順序) + §3 (表示形式) が揃えば、環境設定の
  ツールバーページ ([src/ui_dialogs/preferences/pages.rs](../src/ui_dialogs/preferences/pages.rs))
  は不要 → **撤去**する。
- **後方互換**: `show_toolbar_*` / `toolbar_*_display` / `toolbar_*_items` 等の設定値は**保持**
  (UI だけ移す)。リリース済み設定の値は壊さない。
- **残す最小機能**: 「既定に戻す (順序・表示・表示形式)」を ⚙ / 空き領域右クリックに置く。

## 7. 他計画との関係

- **本棚ピン留め / 登録バッジ** ([compile-book-plan.md](compile-book-plan.md) §11): 本セクションが
  このモデルに乗る。§11.1 のジェスチャは **左=開く / 右=追加** に更新。§11.4 (本棚の
  折りたたみ/プルダウン) は本ドキュメントへ統合 (compile-book 側は pointer)。
- **ファイル名スタック** ([filename-stack-plan.md](filename-stack-plan.md)): スタックトグルは
  ツールバーの**モードトグル** (ピン項目セクションではない) として置く。「スタック選択 →
  ピン本へ追加」は**ピン本ボタンの右クリック**。
- **左右クリック規約の変更告知** ([version-highlights-plan.md](version-highlights-plan.md)):
  既存タグの左右入替など標準動作の変更は、更新後初回起動の「重要な変更点」画面で
  **display-only** に伝える (個別の移行ダイアログは設けない)。強制変更なので「新しい規約の説明 +
  カスタマイズは右クリック/⚙ から」を出すだけ。
- **着手順**: 本リファクタ (セクションモデル + 左右ジェスチャ + 右クリックカスタマイズ +
  ドラッグ並べ替え + 環境設定ページ撤去) を**一度に完成形**で入れ、その上に ②本棚ピン/バッジ・
  ①スタックを載せる。変更告知の仕組み (version-highlights) はこの refactor リリースで初使用。

## 8. 永続データへの影響

| 対象 | 状況 | 対応 |
| --- | --- | --- |
| `toolbar_section_order: Vec<ToolbarSectionId>` | 新規 | `#[serde(default)]` (空 = 既定順)。後方互換 |
| `toolbar_favorites_display` / `toolbar_tags_display` / `toolbar_bookshelf_display` | 新規 | `#[serde(default)]`、既定 展開 or 折りたたみ |
| `toolbar_<section>_collapsed` | 新規 | `#[serde(default)]` |
| 既存 `show_toolbar_*` / `toolbar_*_items` / `toolbar_*_display` | 保持 | 値は維持、UI のみ移動 |

新機能 (未リリース) のため**マイグレーション不要**。enum 変種追加
(`Collapsible` / `ToolbarSectionId`) は forward-only に留意 (旧バイナリへのダウングレード時のみ、
settings_db の quarantine 経路で吸収)。

## 9. テスト
- セクション順の永続 / ドラッグ並べ替え / 「既定に戻す」。
- **左=安全 / 右=変更**が全セクション・全表示形式で一致。タグの左右入替の回帰。
- プルダウン内の 2 動作 (右クリック、または §4.1 フォールバックの副ボタン)。
- 空き領域右クリックの表示 ON/OFF が `show_toolbar_*` と整合。
- 環境設定ページ撤去後も、全カスタマイズが右クリック / ⚙ から到達できる。
