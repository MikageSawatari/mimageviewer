# mimageviewer 仕様書

## 1. アプリケーション概要

Windows 11向けネイティブ画像ビューワー。
ViX（32bit旧来アプリ）の使い勝手を継承しつつ、Rustによるメモリ安全性とGPUアクセラレーションを実現する。

---

## 2. ウィンドウ構成

通常操作の中心はメインウィンドウ 1 つ。画像 / 動画の表示時は、設定と操作に応じて
フルスクリーン用のボーダーレスウィンドウ、またはメイン一覧とは独立した別ウィンドウビューアを生成する。

```
┌─────────────────────────────────────────────────────────┐
│ メニューバー: ファイル | お気に入り | 動画 | タグ | 製本 | 設定 │
├─────────────────────────────────────────────────────────┤
│ フォルダバー: [←][→] [A][B] [⬆][▲][▼] [フォルダパス...] [サブ展開][♡][履歴▼][📌] │
├─────────────────────────────────────────────────────────┤
│ ツールバー: [ツリー] [本棚] [列数/詳細] [縦横比] [ソート] [お気に入り] │
├─────────────────────────────────────────────────────────┤
│ 任意: 左フォルダツリー │                                 │
│                                                         │
│   サムネイルグリッド (仮想スクロール)                   │
│                                                         │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 2.1 メニューバー

| メニュー | 項目 |
|---------|------|
| ファイル | フォルダを開く… (Ctrl+O) / 読書履歴を開く / レーティング一覧 / 現在地フィルタ (Ctrl+F) / キャプチャ保存フォルダを開く / ゴミ箱を開く / 終了 |
| お気に入り | このフォルダを追加… / 編集 / コンテナ検索 (Ctrl+S) / アイテム検索 (Ctrl+G) / [登録済みフォルダ一覧] |
| タグ | ピン留めタグの管理… / タグビュー (Ctrl+T) / タグを付ける/外す… / 選択中の項目からタグをクリア / 旧XMPタグを取り込む… / [ピン留めタグ一覧] |
| 製本 | 追加先の本に追加 / クリップボードの画像を本に追加 / 本棚フォルダを開く / 追加先の本を開く / この本を並べ替え / 製本の管理… / 追加先の本を選ぶ |
| 設定 | サムネイル列数 / 比率 / ソート順 / キャッシュ管理… / サムネイル画質… / 統計… / 回転情報をリセット… / 環境設定… |

- トップレベルメニューのいずれかをクリックして開いている間は、`ファイル` /
  `お気に入り` / `動画` / `タグ` / `製本` / `設定` / `ヘルプ` の別項目へマウスを
  横移動して hover するだけで、開いているメニューが切り替わる。未オープン状態の
  hover だけではメニューを開かない。
- 製本の「この本を並べ替え」は常にメニューへ表示し、本フォルダ以外では disabled にする。
  本フォルダでは専用の並べ替えダイアログを開く。小サムネイルの
  サイズをその場で調整でき、ドラッグ中は挿入先に I 字型インジケータを表示する。左右ボタンで
  選択ページを移動できる。Ctrl/Shift クリックで複数ページを選択し、まとめてドラッグ移動できる。
  PageUp/PageDown/Home/End はサムネイル一覧のスクロール専用で、カーソル表示や Space 選択は
  しない。
  上部の本一覧から別の本を選び、選択ページをコピー/移動できる。閉じる時は未保存の並び替えを
  連番ファイル名へ反映し、編集破棄ボタンは置かない。
- 本フォルダ閲覧中はページ順を番号順に固定するため、メニュー/ツールバー/詳細ヘッダの
  ソート操作は無効化される。手動で混入した ZIP/PDF/フォルダ/動画など、画像以外の項目は
  本ページとして表示しない。
- 本ページは追加時に焼き込んだ画像ファイルを正本にするが、タグ/★/補正/消しゴム/
  補正レイヤー/隠蔽加工/テキスト注釈/切り取りは mIV 内部 DB の後段編集として許可する。
  本ページはグローバル補正やお気に入り標準を継承せず、個別設定だけを焼き込み済み画像の上へ
  重ねる。並べ替え・本名変更・別の本へのコピー/移動では編集情報の DB キーも追従する。
  回転はページ順と見開きの意味がぶれやすいため引き続き無効。
- 「読書履歴」は、フルスクリーンで読んだ画像フォルダ / ZIP / PDF /
  対応アーカイブを最近読んだ順に並べる専用ビュー。製本機能とは独立した導線として、
  ファイルメニューの「読書履歴を開く」と、アドレスバー「場所▼」の「読書履歴」
  (ドライブ一覧の下、本棚フォルダの上) から開く。動画は対象外。右クリックで 1 件ずつ「履歴から削除」できる。
- 「サブ展開」は、現在の実フォルダ配下の実ファイル画像 / 動画を、その時点のスナップショットとして
  フラット一覧化する一時ビュー。通常フォルダでフォルダを Space / Ctrl+クリックでチェックしている場合は、
  現在フォルダ全体ではなくチェックしたフォルダ群だけを 1 つのフラットビューにまとめる。
  内部的には `__subfolder_expansion__` の synthetic path を使い、
  実 root は `subfolder_expansion_root`、実際の走査起点は `subfolder_expansion_roots` に保持する。`last_folder`、通常フォルダ履歴、
  コンテナ★、catalog `delete_missing` など実フォルダ前提の処理には載せない。
  既存の★フィルタ、タグ、詳細表示、場所 facet、画像色フィルタ、Ctrl+F 現在地フィルタは実パス item に対して使える。
  画像色フィルタは画像だけを対象にし、大量件数では通常フォルダと同じ確認ゲートを挟む。表示順は現在のソート設定に従い、
  同値は root 相対の親フォルダとフルパスで安定化する。ソート変更時は保持中の
  スナップショットをメモリ内で再ソートし、ファイルシステムは再走査しない。サブ展開ビュー上でも
  `スタック` トグルを使える。この場合は親フォルダ単位で分類し、別フォルダの同名 prefix や
  先頭連番が 1 つのスタックに混ざらないようにする。

### 2.2 フォルダバー

- テキストボックスにフォルダのフルパスを入力
- **Enter** キーでそのフォルダを開く
- フォルダ移動時に自動更新される
- **← / → 履歴ボタン**: フォルダ移動履歴を戻る / 進む。履歴操作中は通常の
  フォルダ履歴に重複して積まない
- **A / B クイックフォルダボタン**: コピー元・コピー先など 2 つの作業場所を
  フォルダバー上で素早く切り替えるためのスロット。2 ペイン表示ではなく、
  サムネイルグリッドは常に 1 つだけ表示する。
  - 通常は A がアクティブ。A/B を左クリックするとその作業場所へ切り替える。
    記憶済みの場所があればそこへ移動し、未訪問ならドライブ一覧を表示する。
  - 作業場所を開いた後のフォルダ / ZIP / PDF / 変換済みアーカイブ移動は、
    アクティブな A/B の「最後に見た場所」として自動保存する。
  - A/B 間の切り替え自体はフォルダ履歴に積まない。← / → 履歴ボタンは
    アクティブなスロットごとの戻る / 進む履歴を操作し、A で進んだ履歴と B で
    進んだ履歴は混ざらない。
  - 記憶対象は実フォルダ、ZIP / PDF / 変換済みアーカイブのコンテナパスまでとし、
    ZIP 内エントリや PDF ページ単位の仮想パスは保存しない。
  - 検索中、タグ / ★固定など一時ビューでは誤って検索前フォルダを記憶しないよう
    disabled にする。ただし検索結果の「フォルダに移動」で実フォルダへ着地した後は
    通常どおり記憶できる。
- **⬆ 親フォルダボタン**: `Backspace` と同じく親フォルダへ移動し、元フォルダを選択状態にする。Ctrl+F フィルタが現在フォルダに効いている間は disabled になり、Esc / × で検索を閉じるまで親へ抜けない
- **▲ / ▼ ツリー順ボタン**: `Ctrl+↑/↓` と同じく、深さ優先のツリー順で前 / 次の
  画像・動画を含むフォルダや ZIP・PDF・変換アーカイブへ移動する
- **サブ展開**: 現在の実フォルダ以下にある画像 / 動画を worker で再帰走査し、その時点の
  スナップショットをフラット一覧として表示する。通常フォルダ表示中だけ有効で、ZIP / PDF /
  変換アーカイブの内部やコンテナ自体は初期版では含めない。フォルダを Space / Ctrl+クリックで
  チェックしてから押すと、チェックした複数フォルダだけをまとめて展開する。走査中はフォルダバーに
  `サブ展開中 N件 / Mフォルダ` の進捗と `中止` ボタンを表示し、キャンセルできる。
  走査完了後、結果が大きく表示反映に時間がかかる可能性が高い場合は、中央に
  `サブ展開の表示を準備中...` を表示してから一覧を差し替える。
  サブ展開中にボタンを押す、
  `Backspace` / ⬆ で戻る、または親へ戻る遷移が発生した場合は root の通常フォルダ表示へ戻る。
  `Ctrl+↑/↓` と `Ctrl+PageUp/PageDown` は実フォルダ DFS へ落とさず no-op にする。
  展開後は `スタック` トグルでフォルダをまたいだ一覧を親フォルダ単位のスタック集約にできる
- **場所▼ メニュー**: ドライブ一覧 / 読書履歴 / レーティング / 本棚フォルダ / デスクトップ /
  ピクチャ / ダウンロード / 利用可能なドライブ (`C:\` など) へ移動する。
  既知フォルダは Windows Known Folder API を優先し、
  OneDrive やリダイレクトされた Desktop に追従する。検索中と ★固定中は disabled。
  場所▼ボタンまたはフォルダバー左端の `フォルダ:` ラベルを右クリックすると、
  場所▼に表示する項目 (ドライブ一覧 / 読書履歴 / 本棚フォルダ / レーティング /
  デスクトップ / ピクチャ / ダウンロード / 各ドライブ) を切り替えられる
- **♡ / ♥ お気に入りボタン**: 未登録の現在フォルダではお気に入り追加ダイアログを開く。
  登録済みの現在フォルダではお気に入り編集ダイアログを開く。検索・索引の
  ルートになるため、追加対象は実フォルダのみで、ZIP / PDF / 変換済みアーカイブ
  閲覧中は追加できない。本棚ルートおよび本棚配下の本フォルダも、Ctrl+S/Ctrl+G の
  通常検索へ混ざらないようお気に入り追加対象外にする
- **履歴▼ メニュー**: 最近開いたフォルダをフルパスで最大 20 件表示し、選択したフォルダへ移動する。最近開いたフォルダ履歴は再起動後も保持され、フォルダバー左端の `フォルダ:` ラベルの右クリックメニューからクリアできる
- **検索中の挙動** (Ctrl+S お気に入り検索 / Ctrl+G 全文検索 アクティブ時):
  検索は透明な一時オーバーレイ扱い。検索中のフォルダ移動は ←/→ の戻る・進む履歴にも
  履歴▼ の最近開いたフォルダにも一切記録されず、検索を抜けると検索前の履歴状態が
  そのまま復元される。
  - **←/→/履歴▼**: disabled (検索中はフォルダ履歴の概念が適用されない)
  - **⬆ 親フォルダボタン**: 検索結果の仮想階層を 1 段ドリルアップする動作に転用
    (BS と同じ)。最上位 (Ctrl+G の集約ビュー / Ctrl+S の結果一覧) では disabled
  - **▲ / ▼ ツリー順ボタン**: 前 / 次のヒットフォルダへ移動 (キーボード Ctrl+↑/↓ と一致)。
    最上位では disabled
  - **検索の終了**: ←/BS では検索状態から抜けない。閉じるには <kbd>Esc</kbd>、検索バーの
    × ボタン、または <kbd>Ctrl</kbd>+<kbd>G</kbd> / <kbd>Ctrl</kbd>+<kbd>S</kbd> 再押下 (toggle)
  - **例外**: 右クリックメニューの「フォルダに移動」は検索を明示終了して実フォルダへ
    着地する正当なナビゲーションなので、その遷移 (検索前フォルダ C → 着地フォルダ X)
    だけは履歴に残し、X で ← を押すと C に戻れる
- **📌 代表サムネ固定ボタン** (フォルダバー右側): 選択中のアイテムを現在のフォルダ /
  ZIP / PDF / 変換済み RAR・7z・LZH の代表サムネに固定 / 解除する。左クリックでトグル (既に同じアイテムが
  ピン留め済みなら解除、そうでなければ設定)、右クリックで常に解除。表示は
  フォルダバー左端の `フォルダ:` ラベル右クリック → `代表サムネ固定 (📌)` でオフ可能
- フォルダバー右側に現在のサムネイル表示数を `(表示中/全体)` 形式で表示する。
  例: ★フィルタで 100 件中 20 件が表示されている場合は `( 20/100)`。
  分子は分母と同じ桁数に右寄せし、検索結果表示中は非表示

### 2.3 ツールバー

- 左フォルダツリーペインの表示切替、本棚の追加先切替/追加/開く、列数（1〜10 + 詳細）、
  縦横比（7種）、ソート順（4種）、レーティングフィルタ、スマートフィルタ、お気に入りフォルダのボタン、
  タグの付与/解除ボタンとピン留めタグのボタンを配置
- 詳細モードへの切り替えは列セクションの `詳細` または <kbd>Alt</kbd>+<kbd>-</kbd> で行う
- 列セクションの `詳細` はセクションのラベル右クリック → 設定で表示/非表示を切り替え可能。
  非表示でも <kbd>Alt</kbd>+<kbd>-</kbd> のショートカットは使える
- 詳細モードでは縦横比セクションを非表示にする。列セクションは `詳細` 選択状態として残す
- **ツールバーのカスタマイズはすべて右クリックで行う** (v2.0.0、`toolbar-customization-plan.md`):
  - **空き領域を右クリック** = 表示するセクションの ON/OFF チェックリスト。全セクションを隠した
    場合の入口として、`設定` メニュー → `ツールバー` からも同じメニューを開ける。
  - **セクションのラベルを右クリック** = そのセクションの設定 (表示形式 = 展開/折りたたみ/プルダウン、
    出す項目 = 列1〜10/比率/ソート、行頭に表示、このセクションを隠す、本/お気に入り/タグの管理)。
    フォルダバーでは `フォルダ:` ラベルまたは `場所▼` を右クリックして、場所▼の表示項目も設定できる。
    スマートフィルタバーでは `絞り込み:` ラベルを右クリックして、表示するフィルタボタンを設定できる。
    右クリック設定ポップアップはチェック操作では閉じず、複数項目を続けて変更できる。閉じるには
    右上の `×` または外側クリックを使う。履歴クリア、管理画面を開く、バー/セクションを隠すなどの
    実行操作は閉じる。
  - **「ツールバーを既定に戻す」** は影響が大きく取り消せないため、右クリックには出さず
    `設定` メニュー → `ツールバー` にのみ置き、確認ダイアログを経て実行する。
  - **セクションのラベルをドラッグ** = セクションの並べ替え (既定 OFF。右クリックメニューの
    `ドラッグで並べ替えを許可` を ON にしたときだけ有効。OFF のときはカーソル形状も変わらない)。
  - 各項目の操作は「左クリック = 安全 (開く/ビュー)、右クリック = 変更 (付与/追加)」で統一
    (★ レーティングのみ、左右がフィルタに使われているため付与は右クリックメニューの項目)。
- ウィンドウ幅が不足する場合、ツールバー項目はボタン単位で次の行へ折り返す。`行頭に表示` を
  指定したセクションはその手前で必ず改行する。ボタン内の日本語ラベルが縦に潰れるような内部折り返しは行わない
- セクション設定の値 (表示/並び順/表示形式/出す項目) は永続化される。フォルダバー (アドレス行) も
  「並べ替えできないだけのセクション」として扱い、出すボタンの詳細設定は他セクションと同様
  **ツールバー上の操作 = アドレスバー左端の `フォルダ:` ラベル右クリック**に統一する
  (`設定` メニュー → `ツールバー` には表示 ON/OFF チェックのみ。専用の環境設定ページは廃止)

### 2.4 フォルダツリーペイン

- ツールバー先頭の `ツリー` ボタン、またはグリッド表示中の <kbd>F</kbd> で、ウィンドウ内を左右ペインに分割する。右側は従来のサムネイルグリッド / 詳細一覧のまま、左側に実ファイルシステムのフォルダツリーを表示する
- ツリーは `C:\` などのドライブルートを起点に、**実ディレクトリのみ**を表示する。NTFS junction / ディレクトリシンボリックリンクは実ディレクトリ扱いで表示する。ZIP / CBZ / PDF / 変換対応アーカイブなど、右側ペインでは仮想フォルダとして開けるファイルは左ツリーには表示しない
- ZIP / PDF / 変換済みアーカイブ閲覧中の同期先は、ユーザー視点パス (`effective_folder`) の親フォルダとする。変換キャッシュ ZIP の実体パスはツリーに出さない
- 現在アクティブな実フォルダが見える最小範囲を自動展開する。右側ペインで別フォルダへ移動すると自動展開経路を置き換え、過ぎ去ったフォルダがユーザー手動展開でなければ閉じる
- ユーザーが手動で展開したフォルダは、現在フォルダの自動同期とは独立して維持する。ツリー側で `←` により自動展開された枝を閉じた場合は、次の現在フォルダ変更またはリロードまでその閉状態を優先する
- ツリー上部にはドライブ切替プルダウンと再読み込みボタンを表示する。再読み込みはツリーキャッシュと手動展開状態をクリアし、現在アクティブなフォルダが見える最小範囲で最新のファイルシステム状態を再列挙する
- ドライブ切替プルダウンを操作したときは、右側ペインの現在フォルダとは独立して選択ドライブを維持する。ツリー上でフォルダを開いた後は、その移動先に同期する
- 左右ペインの境界位置はウィンドウ幅に対する比率として保存し、再起動時に復元する
- 長いフォルダ名は左ペイン幅で省略表示し、フルパスはホバー表示する。文字列が右側グリッドへはみ出さないようにする
- フォルダ列挙はバックグラウンドスレッドで行い、UI スレッドでは `read_dir` を直接実行しない。展開中ノードと現在フォルダ経路だけを遅延列挙する
- ★固定 (Snapshot Lock) 中など、フォルダ間移動を禁止すべき状態ではツリーペイン全体を disabled 表示にし、クリック・キー操作によるフォルダ移動を受け付けない

### 2.5 サムネイルグリッド

- 設定で指定した **列数** の可変グリッド（行数は画面に応じて自動）
- 各セルはアスペクト比を維持してサムネイルを表示（余白はセル背景色で埋める）
- セルサイズ = ウィンドウの残余領域 ÷ 列数
- 選択中セルの下にはサムネイル情報ツールチップを表示する。既定はファイル名と画像解像度、動画ではファイル名と動画長さ。表示内容は環境設定 → 表示 → サムネイルで、種類 / サイズ / 更新日時 / 作成日時 / 動画解像度 / 動画コーデック / 親フォルダ名 / 場所 (フルパス) / 読書履歴の最終閲覧 / 読書履歴の既読位置を切り替えられる。読書履歴ビューでは、ホバー tooltip に場所 (フルパス) / 最終閲覧日時 / 既読位置を表示する (複数フォルダ・ドライブの同名本を場所で判別できるようにする)。ツールチップ幅はセル幅固定ではなく最大約 2.5 セル分を使い、画面右端ではセル右端に合わせて画面内に収める。動画長さなど未取得の値は選択中の 1 件だけバックグラウンドで遅延取得する
- **仮想スクロール実装**（下記詳細参照）

## 3. サムネイルグリッド詳細

### 3.1 仮想スクロール

```
総スクロール高さ = ceil(ファイル数 / 列数) × セル高さ

描画対象行 = 現在スクロール位置から見えている行 ± バッファ2行
それ以外の行 = 高さだけ確保、GPUテクスチャ未割り当て
```

- スクロールオフセットは App 自身で管理（egui の自動スクロールは使わない）
- オフセットは常に `cell_size` の整数倍にスナップ（行単位）
- 最大オフセットも行境界にスナップ → 最終行の下に余白が生じる
- マウスホイールは egui の MouseWheel イベントを消費して1行単位で移動

### 3.2 並列サムネイルロード手順

1. フォルダを開く → ファイル一覧を取得（瞬時）
2. グリッドレイアウト・スクロール高さを計算 → 空枠を即座に描画
3. **フォルダごとに専用 rayon スレッドプールを新規作成**（旧フォルダのタスクとプール競合しない）
4. キャンセルトークン（`Arc<AtomicBool>`）を旧タスクへ送信して中断
5. **フェーズ1**：可視範囲の画像を優先して並列ロード
6. **フェーズ2**：残りの画像を並列ロード（キャンセル確認しながら）
7. 完成したサムネイルを `mpsc::channel` でメインスレッドへ送信
8. メインスレッド: `Pending` なサムネイルがある間は毎フレーム `request_repaint()` を呼び、受け取り次第 GPU テクスチャ登録

### 3.3 サムネイル生成

- 表示用: セルの実ピクセルサイズにリサイズした ColorImage を直接 GPU へ送信（高画質）
- キャッシュ用: 長辺 512px にリサイズ → WebP (lossy, q=75) でエンコード → SQLite に保存
- アイドル時にキャッシュ由来のサムネイルを元画像から再デコードして高画質化（設定で ON/OFF）
- JPEG などの EXIF Orientation は通常画像と ZIP 内画像の両方でデコード時に適用する。既存の古い ZIP サムネイルキャッシュはそのまま使われ、削除すると現在の向きで再生成される。

### 3.4 ページ単位先読みと Eviction

- `thumb_prev_pages`（デフォルト 2）/ `thumb_next_pages`（デフォルト 4）ページ分のサムネイルを GPU メモリに保持
- 範囲外のサムネイルは `Evicted` 状態にして TextureHandle を drop → VRAM 解放
- `thumb_vram_cap_percent`（デフォルト 50%）で GPU メモリ使用量の安全ネット

### 3.5 詳細表示モード

- ツールバーの列セクションで `詳細` を選ぶか、<kbd>Alt</kbd>+<kbd>-</kbd> で
  `サムネ` / `詳細` を切り替える。<kbd>Alt</kbd>+<kbd>1</kbd>〜<kbd>0</kbd> は
  サムネ表示に戻して列数を切り替える
- 詳細モードは固定行高の一覧で、既定では左端にプレビューアイコン列を置き、続けて
  `名前` / `★` / `タグ` / `種類` / `サイズ` / `更新日時` / `状態` を表示する。
  状態列にはページ個別補正 (`補`) / 補正レイヤー (`レ`) / 消しゴム (`消`) /
  隠蔽 (`隠`) / 注釈 (`文`) / 回転 (`回`) を短縮表示する。
  読書履歴ビューでは、`更新日時` 列を `最終閲覧` 列に、`状態` 列を `既読位置` 列に
  読み替え、それぞれ最終閲覧日時と `12 / 120` のような既読位置を別々の列に表示する。
  プレビューアイコンにホバーすると、その 1 件だけサムネイルを読み込み、メインウィンドウ外の
  画面内に収まるツールチップで表示する
- 詳細一覧ヘッダの右クリックメニューから、`名前` 以外の既定列と追加列を表示/非表示にできる。
  同じメニューでサイズ列の表示単位を `最適` (既定) / `固定: バイト` / `固定: KB` /
  `固定: MB` から選べる。固定表示では整数部を 3 桁カンマ区切りにする。
  同じメニューの日時セクションで `秒まで表示` を切り替えられる。
  `作成日時`、`画像解像度`、`動画長さ`、`動画解像度`、`動画コーデック` は遅延ロード列で、
  `作成日時` は既定で非表示。
  画像は既存のフルスクリーンキャッシュ / サムネイルカタログ / 画像ヘッダ probe、
  動画は FFmpeg probe、作成日時はファイルシステム metadata を worker でバックグラウンド取得する
- 詳細一覧ヘッダの右端をドラッグすると列幅を変更できる。`名前` 以外の列幅を記憶する。
  `名前` 列は既定では余った幅を吸収する (自動調整) が、`名前` 列の右端をドラッグすると
  自動調整をやめて、その幅を固定幅として記憶する。ヘッダ右クリックメニューの
  `名前の幅を自動調整` で自動調整に戻せる (OFF にするとその時点の幅で固定)。記憶した列幅が
  画面に収まらない場合は横スクロールで表示する。縦スクロールバーが出るときは、その幅ぶんを
  右側に確保してヘッダと行の列を揃え、右端列の欠けや不要な横スクロールバーが出ないようにする
- 詳細一覧ヘッダを横ドラッグして別の列上で離すと、列順を入れ替えられる。
  非表示列の順序も内部的に保持し、再表示したときに前回の位置へ戻す
- 列ヘッダをクリックすると、その列で `昇順` → `降順` → `ソートなし` を切り替える。
  `ソートなし` ではツールバーのロード時ソート順を使う。列ヘッダソート中はツールバーの
  ソート操作を無効化する。遅延ロード列は読み込み完了 (Ready) まで列ヘッダでのソートを無効化する
- 行クリック、Ctrl/Shift 選択、右クリックメニュー、ダブルクリックで開く動作は
  サムネイルグリッドと同じセル操作を使う
- 詳細表示からフルスクリーンを開いた後の前後移動、Home/End、動画の前後移動、
  先読み、連結読み、スライドショーは、フィルタ後かつ列ヘッダソート後の表示順を使う。
  Ctrl+↑↓ / Ctrl+PageUp/PageDown のフォルダ横断は別経路で、詳細ソートや facet 条件は
  次フォルダ探索には持ち込まない
- 詳細モード中は通常の新規サムネイル要求を抑制し、既存サムネイルテクスチャも一度だけ解放する。
  ただしプレビューアイコンにホバーしている 1 件だけは一時的な保持範囲として worker に要求する。
  ただし動画サムネイルはフォルダロード時の専用 worker で取得するため、サムネモードへ戻った時に
  再表示できるよう保持する。列数・縦横比の設定はサムネモードへ戻った時のために保持する
- サムネ / 詳細の両モード共通で、ツールバー下のスマートフィルタバーから
  種類・拡張子・場所・★・タグ・日付・サイズ・状態・AI モデル・生成ツールを絞り込める。場所は元ファイル/元コンテナの親フォルダで、製本フォルダは `本棚 > 本名` と表示する。場所条件は現在の表示スコープだけに効く一時条件で、フォルダ / ZIP / PDF / 仮想ビューを移動すると解除され、設定にも保存しない。スマートフィルタバーは
  ツールバーの空き領域を右クリック (または `設定` メニュー → `ツールバー`) で表示/非表示を切り替え可能。
  `絞り込み:` ラベル右クリックで、バーに出すボタン (種類 / 拡張子 / 場所 / AI モデル / 生成ツール /
  ★ / タグ / 日付 / サイズ / 状態 / 画像色) を切り替えられる。
  アクティブ条件はチップ表示し、`全解除` でまとめて解除できる
- 状態フィルタの `補` / `レ` / `消` / `隠` / `文` / `回` は、画像ページ自身に加えて、
  そのページを含む ZIP / PDF / 変換アーカイブ / フォルダも表示する。フォルダは既定では
  直下の画像と直下の書庫だけを対象にし、`子フォルダも対象` を ON にすると DB 上の子孫ページも
  対象にする。判定は保存済み編集DBの page_path キーで行い、フィルタ時にフォルダや書庫を
  追加走査しない。`補` はページ個別補正だけを対象にし、グローバル標準・お気に入り標準は含めない。
  サムネイル左上の編集バッジ (`補` / `レ` / `消` / `隠` / `文`) と詳細表示の状態列は、
  保存済み編集を 1 つ上の見える親にだけ表示し、子フォルダや直下書庫内ページをさらに上位フォルダへは伝播しない。
- タグ条件では未読のタグ対象アイテムを候補に残し、バックグラウンド読み込み完了時に
  表示集合を再評価する。これによりタグ未読項目が永続的に取りこぼされるのを避ける
- 遅延ロード列の読み込み中は、スマートフィルタバー直下に
  `詳細情報を読み込み中 done/total` の進捗行を表示し、`停止` / `再開` で制御できる
- EXIF 撮影日時/カメラ、PDF ページ数などの追加遅延列は後続フェーズで同じ基盤へ追加する

## 4. フルスクリーン表示 ✅

### 4.1 ウィンドウ仕様

ビューア表示にはフルスクリーンモード、ウィンドウ内モード、別ウィンドウモードがある。
フルスクリーン / ウィンドウ内は環境設定 `video_in_window_mode`
（既定 false = フルスクリーン）で切り替える。動画 HUD のトグルボタンと静止画
ホバーバーの ⊞ トグルボタン（どちらも × ボタンの左）、および <kbd>F11</kbd>
ショートカット（消しゴムモード中は除く）でも切り替えられ、設定は動画・静止画で
共有する。別ウィンドウモードは `detached_viewer_enabled` と <kbd>F12</kbd> で切り替える。
F12 は F11 のフルスクリーン / ウィンドウ内選択を変更せず、別ウィンドウモードを OFF に
したときは直前の F11 状態へ戻る。

- **フルスクリーンモード**（既定）: ボーダーレスウィンドウ（タイトルバー・枠なし）、
  モニター解像度サイズ、メインウィンドウとは別ウィンドウとして生成
- **ウィンドウ内モード**: 動画も静止画もメインウィンドウのクライアント領域内に
  表示する。タイトルバー・ウィンドウ枠は残り、ウィンドウのリサイズ・移動に追従する。
  ウィンドウ内動画と静止画をホイールで往復しても表示モードが一貫する
- **別ウィンドウモード**: <kbd>F12</kbd> で ON/OFF を切り替える。ON 中に画像・動画を開くと、
  メイン一覧とは独立した通常ウィンドウで表示し、メイン一覧の選択カーソルとビューア表示を双方向同期する。
  別ウィンドウ中の <kbd>F11</kbd> は無効。別ウィンドウが閉じているだけならカーソル移動では再表示せず、
  Enter / ダブルクリックなどの明示 open で再表示する。既に同じ項目を表示中の場合、メイン一覧側の
  Enter は再オープンせず、必要に応じて別ウィンドウを前面化する。見開き表示中は、同時表示中の相方ページが
  メイン一覧の可視範囲内にある場合だけ破線のサブカーソルを描画する。

### 4.2 表示仕様

- 画像をモニター解像度に合わせて表示（バイキュービック縮小/拡大）
- 前後の画像をプリフェッチ（`prefetch_forward` / `prefetch_back` で枚数設定可能）
- 表示はページ構成 (1 ページ / 見開き 左→右・右→左、表紙単独あり) と連結方式
  (ページ単位 / 縦連結 / 横連結) を独立して選べる。<kbd>1</kbd>〜<kbd>5</kbd> はページ構成、
  <kbd>6</kbd> は連結方式 (ページ単位 → 縦連結 → 横連結)、<kbd>7</kbd> は横方向
  (左→右 / 右→左)、<kbd>0</kbd> はズーム/フィット
  (ページ全体 / 横幅 / 縦幅 / 100%原寸) を切り替える。
  旧ページ全体+余白カットは表示トリムの自動余白カットへ移行する。ホバーバーのズーム/フィットメニューでは
  フィットモードとは別に「拡大しない」「縮小しない」を切り替えられ、自動フィット倍率だけを
  100% で制限する。手動ズームは制限しない。ページ単位へ切り替えるとページ全体、
  縦連結へ切り替えると横幅フィット、横連結へ切り替えると縦幅フィットへ自動で戻る。
  左端 / 上端 / 右端ホバーで開く左パネルは「画像補正」「表示トリム」のタブ式で、
  選択中タブは次回起動後も保持する。表示トリムタブでは、保存 / エクスポートに影響しない
  表示専用の余白カットを調整できる。適用モードは「トリムなし」「自動余白カット」
  「本全体の設定を適用」のラジオ 3 つと、「このページの個別設定を適用」のチェックで構成する。
  ページ個別チェックは現在ページだけに効き、前後ページへ移動すると外れる。
  自動余白カットは表示中ページごとに自動検出し、本全体の自動検出としては扱わない。
  見開きでは左右ページの上下カット量を比較し、上 / 下は少ないカット幅を共通採用する。
  横方向のカット量はページごとの検出を維持する。
  本全体 / このページの手動設定では、
  単ページ / 見開き連動 / 見開き左右別に対応し、指定した矩形はページ全体 / 横幅 / 縦幅 /
  100%原寸の fit 基準として使う。矩形外は描画せず背景色に落とす。見開きの中央側をトリムした場合は、
  左右の見える端をページ間隔に合わせて再配置する。スライダー操作は対象の手動設定モードを適用する。
  自動余白カットからページ個別設定へ切り替える場合は、現在表示中の自動検出結果を初期値にする。
  見開き連動の自動検出は、上下 / 中央側 / 外側の共通値に左右の少ないカット幅を採用する。
  見開き連動 / 左右別の切替時は値を移行し、左右別から連動へ戻す場合は平均値を使う。
  ページ個別設定中の左右別切替は本全体設定を書き換えない。見開き連動 UI で作成したページ個別値は、
  ページの表示側が変わっても中央側 / 外側の意味を保つ。
  適用モード / 本全体設定は本ごと、ページ個別設定はページごとに `view_trim.db` へ保存する。
  自動余白カットはモードだけ保存し、検出結果はページ表示時に都度計算する。
  見開き中に横方向を変えた場合は、表紙単独あり/なしを
  保ったまま見開きの左開き / 右開きも連動する。ZIP の作品区切り表示上でも
  <kbd>0</kbd>〜<kbd>7</kbd> の表示操作キーは有効。連結方式は画像 /
  ZIP 内画像 / PDF ページを仮想配置し、縦連結はホイール・↑↓・PageUp/PageDown・ゲームパッド上下、
  横連結はホイール・←→・PageUp/PageDown・ゲームパッド左右でスクロールする。巨大キャンバスは
  作らず、GPU テクスチャは可視範囲 + 前後 2 ページ程度、最大 20 ページ程度に抑え、同時可視ページ数が
  16 ページを超えるような極端なズームアウトはズーム下限を引き上げて防ぐ。見開き内のページ間隔
  (既定 4px、0px で密着) と連結読みのページ/見開きユニット間隔 (既定 20px) は環境設定で変更できる。
  見開き構成の縦連結では、表紙・横長ページ・端数の単独ページも見開きページと同じ倍率で中央寄せする。
  ZIP の章区切りは、連結モードでも画像テクスチャ化せず、前後ページと同じサイズの区切りページとして表示する。
  連結読みのホイール・矢印/D-pad・左スティック速度も画面サイズ比 (%) で調整できる。
  連結モードでは比較、
  360度パノラマ、分析、編集系モードは起動せず、確定済みのページ単位補正・注釈・マスク結果だけを
  表示に反映する。
- マウスを画面上部に移動でファイル情報ヘッダーバーを表示（操作ボタン付き: ℹ / ↶ / ↷ / ▶ / 📷 / ✕）。
  静止画 / ZIP 内画像 / PDF ページのカメラアイコンは、クリックで現在表示の最終合成を
  クリップボードにコピーし、<kbd>Ctrl</kbd>+クリックで暗転オーバーレイを開いてドラッグ範囲だけを
  クリップボードにコピーする。範囲コピーは一回限りで、永続的な切り取り設定や本ページの実体は変更しない。
- 静止画フルスクリーンの左右半分クリックはページ送りに使う。LTR では右半分が次 / 左半分が前、RTL では左半分が次 / 右半分が前。
- 静止画フルスクリーンでは右下に `12 / 123` 形式のページ番号を常時表示する (環境設定で OFF 可能)。見開きは `12, 13 / 123`、右→左表示なら画面上の左ページから `13, 12 / 123` のように、カンマの後に 1 つスペースを入れて表示し、縦 / 横連結モードは画面中央に近い現在ページを表示する。下部ページシークバーを固定表示している間は同じ情報が重複するため右下のページ番号は表示しない。マウスを画面下部へ移動すると、フォルダ / ZIP / PDF / 変換アーカイブのフルスクリーンナビ対象がすべて画像の場合だけ画面下端フル幅のページシークバーを表示する。LTR は右端、RTL は左端にページ番号を表示し、表示内容は右下オーバーレイと同じ見開き対応ラベルにする。ドラッグ中はリアルタイムにページを移動する。縦 / 横連結モードではシーク先ページを中央に置く。ZIP の章区切り (`ZipSeparator`) は混在判定から除外する。動画など画像以外が混在する場合はシークバーを出さず、画像 / 動画 / その他の件数サマリーを表示する。シークバー端の鍵アイコンまたは環境設定で固定表示にすると、下端にシークバー領域を常時確保し、画像はその領域を除いた範囲へフィットする

- 動画メタ情報パネルは FFmpeg が読める埋め込み metadata の title / artist /

- 読書履歴は、フルスクリーンで読んだ画像フォルダ / ZIP / PDF / 対応アーカイブを

  履歴から開く時の続きから / 先頭からは
  既存の位置復元設定 (`book_open_resume` など) に従い、履歴専用設定は持たない。
  読書履歴ビューを表示した直後には、存在確認や自動整理で件数を変えない。項目を開こうとした
  1 件だけ確認し、親ドライブ / 共有が利用可能で対象ファイルやフォルダだけが見つからない場合は、
  移動せずトーストで通知してその行を読書履歴から削除する。外付けドライブ未接続や権限エラーなど
  存在しないと断定できない場合は、移動せずアクセス不能のトーストを出し、履歴行は残す。
  読書履歴から開いた本を「親へ戻る」操作 (Backspace / アドレスバーの親へ戻るボタン /
  自動フルスクリーン時の Esc 直帰) で閉じると、実ディレクトリではなく読書履歴ビューへ戻る。
  対象は本のルート階層にいる間だけで、本より深い階層 (サブフォルダやネスト ZIP の内側) では
  通常どおり 1 つ上の階層へ戻り、本のルートまで戻ったところで読書履歴へ抜ける。
  別の本 / フォルダへ明示的に移動 (アドレスバー / フォルダナビ等) すると戻り先予約は解除される。

  戻る操作で実体のない `__reading_history__` を開こうとする事故は起きない
  (読書履歴へ戻るのは上記「親へ戻る」専用経路)。
  読書履歴アイテムの右クリックには「この本のフォルダに移動」があり、本を含む実フォルダへ
  移動して前後の本を探せる。

  設定秒数 (既定 1.0 秒、0.1〜5.0 秒) 続いたらマウスカーソルを自動的に隠す。マウス操作で即時に
  再表示し、キー操作だけでは再表示しない。下部ページシークバーを固定表示していても、マウス操作がなければ同じ秒数で隠す。動画再生時は native presenter (D3D11 + 別 egui_ctx) 側でも同じ設定値を使う。

## 5. グリッド表示対象

サムネイルグリッドには以下を表示する。それ以外のファイルは無視する。

| 種別 | 表示内容 |
|------|---------|
| **フォルダ** | 代表画像サムネイル＋フォルダ名（画像がなければフォルダアイコン📁）。NTFS junction / ディレクトリシンボリックリンクも通常フォルダと同じセルとして表示する。代表画像はフォルダ内を再帰的に探索（最大3階層）し、最初に見つかった画像をソート順で選択。**ユーザーが📌で手動指定**したアイテムがあれば自動選定を上書きする |
| **ドライブ一覧** | `C:` / `D:` など接続済みドライブを並べる仮想ビュー。場所欄は空欄、ボリューム名は取得しない。未ピン時は painter 描画の固定ドライブアイコンを表示し、DB に代表サムネピンがあるドライブだけ既存カタログ / 動画ピン DB のサムネを cache-only で表示する。ドライブルート catalog はドライブ別に分け、ピン先がフォルダの場合は正しい root catalog に残っているフォルダタイルだけを使う。通常のドライブルート表示中にピン代表セルが生成された場合は、そのセルだけ `CachePolicy` に関わらず保存して後続の cache-only 表示に使う。キャッシュ未作成時や root catalog に正しいタイルが無い場合はアイコンへ戻し、ドライブ一覧表示だけでは `read_dir` / 代表画像探索 / metadata 確認 / ピン先デコードを行わない。D&D・チェック・レーティング・右クリックメニューは無効 |
| **画像ファイル** | サムネイル画像 |
| **動画ファイル** | サムネイル画像（Windows Shell API 経由）。フルスクリーン HUD でユーザーが指定したフレームがあればそれを優先 |
| **ZIP ファイル** | 1枚目の画像サムネイル＋ZIP バッジ（ダブルクリックで中を開く）。**ユーザーが📌で手動指定**したエントリがあれば自動選定を上書きする |
| **PDF ファイル** | 1ページ目のサムネイル＋PDF バッジ（ダブルクリックで中を開く）。**ユーザーが📌で手動指定**したページがあれば自動選定を上書きする |
| **RAR / 7z / LZH などの変換アーカイブ** | `archive_file_handling` が `Ignore` 以外なら表示する。未変換ならアーカイブアイコン＋形式バッジ。1 回開いて変換キャッシュ ZIP ができると、その ZIP の 1 枚目サムネイル＋形式バッジを表示する。変換後ビュー内で📌指定したエントリがあれば代表サムネに反映する |

#### 代表サムネの手動ピン (folder thumb pin)

ユーザーは親コンテナ (フォルダ / ZIP / PDF / 変換済み RAR・7z・LZH) の代表サムネを **その中の任意のアイテム**
(画像 / 動画 / サブフォルダ / 入れ子の ZIP/PDF / ZIP エントリ / PDF ページ) に手動で
固定できる。

- **設定経路**:
  - フォルダバーの **📌 ボタン**: 選択中のアイテムを現在のコンテナの代表サムネに
    する (左クリック: トグル、右クリック: 解除)
  - **P キー**: グリッドでは選択中アイテム、画像フルスクリーンでは現在表示中アイテムを
    現在のコンテナの代表サムネにする (トグル)
  - グリッドおよびフルスクリーンの **右クリックメニュー → 「📌 代表サムネに固定 /
    解除」**: 個別アイテムから設定
- **永続化先**: `%APPDATA%/mimageviewer/folder_thumb_pins.db` (コンテナ単位 1 行)
- **優先順位**: 手動ピン > 自動代表選定 > フォルダ/ZIP/PDF/アーカイブアイコン fallback
- **無効化条件**: pin 先のファイルが存在しない / mtime/size 変化で identity が変わった
  場合、自動的に新キャッシュキーで再生成 (古い WebP は `delete_missing` で掃除される)
- **対象外**: 検索アグリゲートビュー (Ctrl+G)、空フォルダ、`ConvertibleArchive`
  未変換アイテム (= disabled、変換完了後に設定可能)。RAR/7z/LZH の変換キャッシュ ZIP
  を内側から閲覧中は、元アーカイブの代表サムネとして設定できる
- **設定**: フォルダバー左端の `フォルダ:` ラベル右クリック → `代表サムネ固定 (📌)` でフォルダバー
  のボタンの表示有無を切替 (規定 ON)。右クリックメニューは常時表示

### 5.3 グリッド内のアイテム順

列ヘッダも同じ比較器を使う。数値順は漫画/連番ファイル向けの mIV 独自自然順で、
記号・空白をまたいで番号本体を比較する。

## 6. フォルダツリー走査（Ctrl+↑↓）

フォルダツリーを**深さ優先（前順）**でたどる。

```
例：
  c:\folder-1\a
  c:\folder-1\b
  c:\folder-1\b\test1
  c:\folder-1\b\test2
  c:\folder-1\c

c:\folder-1\b を表示中に Ctrl+↓ → c:\folder-1\b\test1 へ
c:\folder-1\b\test2 を表示中に Ctrl+↓ → c:\folder-1\c へ
c:\folder-1\a を表示中に Ctrl+↑ → c:\folder-1 へ（最初の子なので親）
```

- **Ctrl+↓（次）**：子フォルダがあれば最初の子へ、なければ次の兄弟へ、なければ祖先の次の兄弟を再帰検索
- **Ctrl+↑（前）**：前の兄弟の最後の子孫へ、最初の子なら親へ
- 画像/動画のないフォルダ・画像を含まない ZIP は `folder_skip_limit`（デフォルト 5、最大 30）回まで自動スキップ。
  PDF と RAR/7z/LZH などの変換アーカイブはコンテナ候補として停止対象にする（分割 RAR は先頭パートのみ）
- NTFS junction / ディレクトリシンボリックリンクはフォルダ候補に含める。循環参照は canonical path の既訪問追跡と深さ上限で停止する。

## 7. キーボード操作

一部のキーボード操作は上級者向け設定ファイル
`%APPDATA%\mimageviewer\keymap.ini` で変更できる。存在しない場合は起動時に
全キー定義行をコメントアウトした `keymap.ini` を生成してから読む。コメント解除した
行だけが上書きになり、コメントのままの操作はビルトイン既定キー (将来の変更を含む)
に追従する。現在バージョンの標準 Action 一覧は、起動時に更新生成される
`%APPDATA%\mimageviewer\keymap.ini.default` と `docs/keymap.ini.default` を参照する。
標準キーを持たないが割り当て可能な操作は `# Action = none` として表示され、
キー名に書き換えてコメント解除すると割り当てできる。`Action = none` のまま
コメント解除した場合は明示的な無効化として扱う。
同時に有効になり得る Action へ同じキーを割り当てた場合や、予約扱いの
Escape / Enter / 修飾なし矢印キーへ割り当てた場合は起動時に警告ログを出すが、
設定自体は読み込む。GUI での編集、競合解消 UI、OS クリップボード / D&D の
割り当て変更は対象外。
消しゴム / 隠蔽加工パネルの描画・消去ボタンとツールボタンは、修飾なし単独キーの
場合だけ `keymap.ini` の実割り当てを `[B]` のような compact 表示に反映する。
メニューバーの検索 / タグビュー項目など一部のメニュー表示と hover text は、先頭
chord を `(Ctrl+F)` のように反映する。
マウスとゲームパッドも原則 keymap 対象外だが、例外として、マウス右ドラッグの
フリック、マウス戻る / 進むボタン、ゲームパッド X リングは
`Settings.ring_shortcuts` で厳選アクションだけを差し替えられる。
画像・動画フルスクリーンでは、F11 相当のウィンドウ / 全画面切替と
F12 相当の別ウィンドウ ON/OFF もこの候補に含める。
これは `KeyAction` / `keymap.ini` の完全カスタマイズではなく、
マウス・ゲームパッド用の小さな固定メニューとして扱う。

### 7.2 フルスクリーン表示モード ✅

### 7.3 ゲームパッド操作

ゲームパッドは閲覧用の固定割り当てを中心に扱う。編集、削除、外部エクスポートなどの
破壊的操作や、完全な操作割り当て変更 UI は対象外。
例外として、マウス戻る / 進むボタンは「環境設定 > マウスボタン」、
X リングは「環境設定 > リングショートカット」で差し替えられる。

| 入力 | 動作 |
|------|------|
| 方向パッド / 左スティック | グリッドでは選択移動。詳細一覧では上下が 1 行移動、左右が表示行数ぶん前後にスキップする。画像フルスクリーンではページ送り。縦連結では上下がスクロール、左右がページ送り。横連結では左右がスクロール、上下がページ送り。左スティックは連結方向を連続スクロールする。動画フルスクリーンでは左右がシーク / タイルカーソル移動、上下が前後ファイル移動 |
| A / B | 決定・開く・再生 / 戻る・閉じる |
| LB / RB | Ctrl+↑ / Ctrl+↓ と同じツリー順の前 / 次フォルダ移動 |
| LT / RT | グリッドでは連続スクロール、画像ではズームアウト / ズームイン、動画では連続シーク |
| 右スティック上下 | 画像フルスクリーンのズーム。LT/RT より速めの連続ズームとして扱う |
| Select | グリッドでは場所リストを開き、ドライブ一覧 / 読書履歴 / 本棚フォルダ / 既知フォルダ / ドライブを上下で選んで A で移動する。画像フルスクリーンでは見開きモードを巡回切り替え (単ページ / 見開き 左→右 / 左→右(表紙あり) / 右→左 / 右→左(表紙あり))。動画フルスクリーンではブックマーク / チャプター / ピンの一覧を開き、上下で選んで A で移動する |

## 8. 設定項目

設定は SQLite データベース `%APPDATA%\mimageviewer\settings.db` に自動保存される
(2026-05 移行。旧 `settings.json` からは初回起動時に自動 migration し、旧ファイルは
`settings.json.migrated-<ts>` にリネームされる)。詳細は
[settings-sqlite-migration.md](settings-sqlite-migration.md) を参照。
キーボード割り当ての上級者向け上書きだけは DB に入れず、
`%APPDATA%\mimageviewer\keymap.ini` を起動時に存在しなければ生成し、1 回読む。
`keymap.ini.default` は現在の標準 Action 一覧として起動時に更新する。

### 永続化と復旧の仕組み

- **アトミック保存**: SQLite トランザクション内で全テーブルを DELETE+INSERT してから
  `commit()` する。VST3 chain など大型 row は hash で変更検出し、未変更ならスキップ。
  書き込み中の電源断・force kill で半端な状態が残らない (= WAL + commit 境界)。
- **世代バックアップ (10 世代)**: 起動 1 回につき最初の **user save** で 1 段ローテートし、
  `VACUUM INTO` で `settings.db.bak1`〜`settings.db.bak10` に過去 10 セッション分の
  consistent な snapshot を保持する。同セッション内の追加保存は in-place 更新のみで
  bak には伝播しない (= 1 起動 = 1 世代)。
- **自動復旧**: 起動時に main DB が壊れていたら (`PRAGMA integrity_check` 失敗 /
  `NotADatabase` / `DatabaseCorrupt`)、`settings.db` / `settings.db-wal` / `settings.db-shm`
  を 3 セットで `.corrupted-<ts>-<seq>` に quarantine 退避し、`bak1`→`bak10` を新→古の
  順に試行して最初に開けたものから復元する。全滅した場合のみビルトイン default に落ちる。
  `DatabaseBusy` / `CannotOpen` 等の transient I/O エラーは 50ms backoff で 3 回 retry し、
  それでも失敗すれば quarantine せず save 抑止のみ行う (= 一時的なアクセス不能で本物の
  DB を失わない)。
- **I/O エラー時の保存抑止**: 起動時に main DB が transient I/O エラーで開けなかった
  セッション、または全復旧経路が失敗したセッションでは、当該セッション中の
  `Settings::save()` をすべて no-op にする (`MAIN_UNREADABLE_THIS_SESSION` +
  `settings_db::SAVE_SUPPRESSED`)。永続化はそのセッション分諦め、次回起動でリトライする。
- **アップグレード前バックアップ**: 直近に保存したバイナリと現バイナリの
  バージョンが違うとき、初回 load で現状の `settings.db` を `VACUUM INTO` で
  `settings.db.preupgrade-v<old>` に複製する。スキーマ破壊が自動復旧で
  救えなかった場合の最終ライフライン。同じ前バージョン名の snapshot が既に
  存在するなら上書きしない。
- **診断ログ**: 復旧経路で起きたイベント (SQLite open エラーの primary/extended code /
  quarantine / bak recovery / preupgrade / save 抑止) は
  **`<data_dir>/logs/settings.log` に常に append** される。logger の初期化状態に
  依存しない独立 sink なので、起動ごく初期の設定復旧フェーズでも確実に残り、
  ユーザー報告時の調査に使える。

### 起動引数

`mimageviewer.exe <パス>` の最初の位置引数は起動時に開く対象として扱う。
通常フォルダはその場所を開き、ZIP / CBZ / PDF は本として開く。RAR / CBR / 7z /
CB7 / LZH / LHA は `archive_file_handling` が `Ignore` 以外なら本として開く。
通常の画像・動画ファイルが指定された場合は親フォルダを開き、
そのファイルをフルスクリーンで開く。ショートカットへのドラッグ＆ドロップや
SendTo は Windows が対象パスを位置引数として渡すため、この経路で処理する。

`auto_fullscreen_zip_pdf` が ON の場合、起動引数 / SendTo / 外部ファイラ経由で
ZIP / CBZ / PDF / 対応アーカイブを直接開いたときも、一覧で Enter / ダブルクリックした
場合と同じ明示オープンとして扱い、ページ一覧を経由せずフルスクリーン表示へ進む。
RAR / CBR / 7z / CB7 / LZH / LHA は `archive_file_handling` に従い、`Ask` なら
変換ダイアログ、`Convert` なら自動変換を挟んでから開く。`Ignore` では開かない。
パスワード付き PDF は既存のパスワード
ダイアログと保存済みパスワードを使い、入力成功後に明示オープン時のフルスクリーン
予約を継続する。

既存インスタンスが起動中の場合、2 個目のプロセスは Named Pipe
(`single_instance::OPEN_PATH_PIPE_NAME`) でパスを既存インスタンスへ送信し、
従来の activate event でウィンドウ復帰も要求してから終了する。既存インスタンスは
受信パスを UI スレッドの channel に積み、起動時と同じ明示オープン経路で開く。
これにより、変換アーカイブの確認ダイアログ、★固定中の移動ガード、
フォルダツリーペインの現在地同期は通常ナビゲーションと同じ規則に従う。

### エクスプローラ連携

環境設定 → 起動と連携 → エクスプローラ連携では、Windows の「送る」メニューへ
`mImageViewer.lnk` を登録 / 削除できる。登録先は per-user の SendTo Known Folder
(`FOLDERID_SendTo`) で、ショートカットの作成・読み取りには ShellLink COM
(`IShellLinkW` + `IPersistFile`) を使う。対象は通常のインストーラ/配布版では
launcher (`mimageviewer.exe`) とし、launcher から起動された core へ
`MIV_LAUNCHER_EXE_PATH` で渡されたパスを優先する。開発実行や portable 実行で
この環境変数が無い場合は現在の exe を登録する。

SendTo から渡されたファイル / フォルダは Windows により位置引数として渡されるため、
処理規則は上記の起動引数と同じ。既存インスタンスがある場合は launcher 側でも
runtime 展開や本体起動を行う前に、最初の位置引数を Named Pipe へ転送してから
activate event を送る。Pipe がまだ準備されていない起動直後だけ短く再試行し、
Explorer の SendTo 起動側が数秒単位で残らないようにする。

同じ設定ページで `use_native_shell_context_menu` を切り替えられる。既定 ON のとき、
実ファイル / 実フォルダの右クリックは Win32 `IContextMenu` による Windows 標準メニューを使う。
mIV 独自項目はメニュー先頭に追加し、名前変更は mIV の入力ダイアログから
`IFileOperation::RenameItem` で実行する。Delete キー / mIV 独自メニューの削除は
バックグラウンド worker から `IFileOperation::DeleteItem` をチャンク単位で使い、
通常はゴミ箱へ移動する。削除確認と進捗は mIV 側のダイアログを使い、ゴミ箱に
入れられず完全削除になる場合だけ Windows Shell の警告を残す。Shell 側のコピー / カット / ペースト /
プロパティ / 関連付けアプリ / 拡張メニューはそのまま表示する。背景右クリックでは現在表示中の
実フォルダだけ Shell 背景メニューを使う。背景メニューには mIV 先頭項目として「新しいフォルダ...」と「貼り付け」も出し、Shell の New サブメニューのインライン編集前提を避けつつ、Shell 側の Paste が表示されない環境でも同じ Shell `paste` verb を実行できる。ZIP/PDF 内ページ、ZIP 内ディレクトリ、検索コンテナ、仮想項目を含む
チェック選択では、ファイルコピー / カット / ペーストを含まない mIV 独自メニューを使う。
Ctrl+C / Ctrl+X / Ctrl+V は `use_native_shell_context_menu` の設定に関わらず同じ Shell verb
ヘルパーを使い、コピー / カット / ペースト時のフォルダ対応、衝突確認、進捗 UI は Windows 側に委ねる。Ctrl+C / Ctrl+X で ZIP/PDF 内ページなどファイルとして扱えない項目が選択に含まれる場合は、実ファイルだけを部分的に処理せずトーストで中止する。
現在表示中の実フォルダは notify-rs (`ReadDirectoryChangesW`) で常時監視し、外部 Explorer 操作や Shell メニュー操作による追加・削除・リネームを debounce 後に既存の外部変更チェックへ流して一覧を更新する。

#### 検索クエリ構文（Ctrl+F / Ctrl+G / Ctrl+S 共通）

パースは `src/search_query.rs` の `parse()` / `matches()`。

| 書き方 | 意味 |
|--------|------|
| `A B` | A と B の両方を含む (AND) |
| `-A` | A を含まない (NOT) |
| `"A B"` | スペース込みのフレーズ完全一致 |
| `-"A B"` | フレーズを含まない (NOT + フレーズ) |
| `#タグ名` | タグ検索（`#` 込みで一致） |

- 大文字小文字は区別しない
- 閉じクォート `"` がない場合は行末までを 1 トークンとして扱う（寛容パース）
- `-` 単体や末尾にある `-` はノイズとして無視する（`jean-claude` のような語内 `-` は通常の文字として扱う）

#### OR 検索モード (v0.7.2+、設計 [search-expansion-design.md §20](search-expansion-design.md))

各検索バー右端の **`□OR`** チェックを入れると include トークンを OR 結合する (既定は AND)。
**NOT (`-word`) は常に AND** のまま (チェック有無に関わらず除外は効く)。

| クエリ | AND モード (既定) | OR モード |
|---|---|---|
| `klee paimon` | 両方を含むものだけ | いずれかを含むもの |
| `klee #klee` | キーワード "klee" と タグ "#klee" の両方 | キーワードかタグのいずれかで "klee" を含むもの |
| `klee #klee -sleep -nsfw` | `klee AND #klee AND NOT sleep AND NOT nsfw` | `(klee OR #klee) AND NOT sleep AND NOT nsfw` |

状態は session-local (ウィンドウを閉じるとリセット)。Ctrl+S / Ctrl+F / Ctrl+G それぞれ独立に
保持される。

#### 最小クエリ長ポリシー (Ctrl+G のみ適用、v0.8.0)

Tantivy bigram インデックスで偽陽性を抑えるため、Ctrl+G は以下の最小長を要求する:

| クエリ種別 | 最小文字数 | 例 |
|---|---|---|
| 日本語 (CJK を 1 文字でも含む) | **2 文字** | `街並` OK / `街` NG |
| 英数字のみ | **3 文字** | `sdx` OK / `sd` NG |
| タグトークン (`#...` 始まり) | **制約なし (例外)** | `#a` OK / `#原` OK |

判定は各 include トークン単位。**タグトークン (`#name`) はこの最小長制約の対象外** —
`#` プレフィックス込みで最低 2 文字確保され、`tags` フィールドの bigram に直接当たるため
1 文字タグ名でも引ける ([global_search.rs::validate_query](../src/global_search.rs))。
また Ctrl+G では **NOT-only クエリは禁止**
(`-bad` のような除外だけの検索は Tantivy で候補を絞り込めず全件走査になるため)。
Ctrl+F (ローカル検索) はこれらの制約を受けない。

#### 検索の経路と索引

検索は「コンテナを探す」「アイテムを探す」「今いる場所を絞る」の 3 軸。
設計の正典は [search-container-item-redesign.md](search-container-item-redesign.md)。

| ショートカット | 呼称 | 対象 | 検索経路 | 備考 |
|---|---|---|---|---|
| Ctrl+S | コンテナ検索 | お気に入り全体のフォルダ / ZIP / PDF を名前で | コンテナ索引 `search_index.db` (SQLite LIKE) | 「種別」ドロップダウン (すべて / フォルダ / ZIP / PDF) で絞れる。動画は対象外 (動画はアイテム) |
| Ctrl+F | 現在地フィルタ | **現グリッドの表示中アイテムのみ** (非再帰・索引なし) | worker 上のオンデマンド判定 | 構造アイテム (フォルダ / ZIP / PDF) もファイル名で一貫して絞り込む。画像 / 動画は PNG tEXt / JPEG EXIF UserComment の AI 生成メタ + EXIF + XMP + 動画メタ + 外部メタデータサイドカー、PDF はファイル名 + document info。mIV タグは Ctrl+F の検索本文へ混ぜず、タグビューまたはスマートフィルタのタグ欄で探す。検索中は item 単位の処理済み数 / 総数を表示する。フィルタ元フォルダでは BS / Alt+↑ / ⬆ による親移動を止めるが、結果から子フォルダへ入った後の BS は通常どおり戻れる。PDF ページ表示中は無効、ZIP 表示中はファイル名フィルタに固定 |
| Ctrl+G | アイテム検索 | **お気に入り全体 (`auto_index_metadata=true`) の画像 / PDF / 動画** | アイテム索引 (Tantivy bigram) で候補絞り込み → STORED 原文を `matches()` で phrase/NOT/AND 正確判定 (streaming) | ZIP はコンテナなので対象外。動画は `video_meta_text`、PDF は `pdf_meta_text`、画像と同名 JSON/TXT は `sidecar_text` (値のみの自由語検索、mIV タグとは別系統) に分けて検索対象フィルタから選べる。mIV タグは Ctrl+G の検索本文へ混ぜず、タグ候補チップからタグビューへ誘導する。結果は一覧 / 集約の 2 ビューを切替でき、ヒットが多いと自動で集約に寄る。検索中はバー / アドレス欄 / 空グリッド中央に「検索中」を表示し、0 件確定と区別する。検索バーは狭い幅では折り返し、Ctrl+G のドロップダウン操作中は背後のグリッドをホイールスクロールしない |

#### AI メタデータ検索の Negative Prompt 除外

PNG の tEXt / iTXt / zTXt チャンク、または JPEG/JFIF の EXIF UserComment に
AI 生成メタデータが含まれる場合、**Negative Prompt は検索対象から除外される**。

- 実装: `png_metadata::build_searchable_from_chunks()` / `build_searchable_from_bytes_with_origin()`
  が、検出したフォーマットに応じて正プロンプト + サンプラ/モデル等のパラメータだけを
  連結した検索用テキストを生成する
- JSON 形式の生成メタデータは汎用 JSON より AI メタデータリーダーを優先する
- ComfyUI では KSampler ノードの `positive` / `negative` 入力先を辿って正側の
  CLIPTextEncode のテキストのみを採用
- フォーマット検出に成功した場合は、判別器が実際に消費したキー (`consumed_keys`) を
  生 tEXt の素通し追加から除外し、Negative を含む原文が再混入しないようにする
- フォーマット検出に失敗した場合は Unknown 扱いで非 AI tEXt チャンクの値を含める
  （取りこぼし回避）。未知の `parameters` JSON は生 JSON を prompt として扱わない

### 8.6 回転情報

回転データは `%APPDATA%\mimageviewer\rotation.db`（SQLite）に保存。通常画像は実ファイルの正規化パス、ZIP 内画像 / PDF ページは `page_path_key` と同じページ単位キーで保持する。元ファイルは変更しない（非破壊）。

### 8.7 レーティング

- 対象:
  - 単一ファイル単位 (`is_rating_leaf`): 通常画像 / 動画 / ZIP 内画像 / PDF ページ
  - コンテナ (`is_container_ratable`): フォルダ / ZIP ファイル / PDF ファイル本体 / RAR・7z・LZH 等の変換前アーカイブ / ネスト ZIP の本 (`ZipDir`)
  - ページとコンテナは独立に管理される (同じ `rating.db` だがキー形式が異なるので衝突しない)
  - ZipSeparator は対象外
- 付与:
  - F1〜F5（★1〜★5）、F6 で解除。グリッドでは選択/チェック済み (`ratable_targets` = `accepts_rating`) に、フルスクリーンでは表示中ページに適用
  - Shift+F1〜F5 / Shift+F6: 現在一覧表示中のコンテナ (フォルダ / ZIP / PDF / 変換済み RAR・7z・LZH / ネスト ZIP の本) にコンテナ★を付与 / 解除。グリッド・フルスクリーン両方で動作
  - チェック済みアイテムがある場合は一括適用（適用後チェックはクリア）
- キー (`rating_path_key`):
  - ページ単位: `App::page_path_key` と同じ形式 (`normalize_path(path)::entry` / `::page_N`)
  - コンテナ: `normalize_path(path)` のみ (`::` セパレータが付かないのでページキーと衝突しない)
  - 変換キャッシュ ZIP 閲覧中のコンテナ★は、cache ZIP ではなく元 RAR/7z/LZH パスを root にしたキーを使う
- 保存先: `%APPDATA%\mimageviewer\rating.db`（SQLite）
- 表示:
  - サムネイルセル左下に半透明の背景付きで★の数を描画
  - ページ★は金色 (255,215,50)
  - コンテナ★は銀青色 (180,220,255) + 先頭に 📁 アイコンを付加
  - フォルダバー（「フォルダ:」欄）の右端にも現在表示中のコンテナ★を 📁★★★ で表示
  - フォルダバー右端の件数表示は、レーティングフィルタ適用後の表示サムネイル数と
    フィルタ前の全サムネイル数を `(表示中/全体)` で示す
- フィルタ:
  - ツールバー「★: なし 1 2 3 4 5」の各バケットをトグル
  - ページ・コンテナ両方に同じフィルタが適用される (フォルダ一覧を★絞り込みできる)
  - 検索フィルタと AND 結合
- レーティング一覧:
  - ファイルメニューの「レーティング一覧」と、アドレスバー「場所▼」の「レーティング」から

### 8.8 テキスト注釈

- フルスクリーンのテキスト注釈モード (`Ctrl+T`、または画像補正パネル ヘッダーの吹き出しアイコン) で、
  ページ単位に非破壊の注釈オブジェクトを編集できる。元画像は書き換えない。分析 / 補正 / 消しゴム /
  隠蔽 / 動画再生中は入場できない。見開き表示中は左ページの単ページ編集に切り替わり、終了で復帰する。
- 種別は単体テキスト、吹き出し、メッセージウィンドウ、オノマトペ、スタンプ。
- セリフ / 単体テキスト / オノマトペは、フォント、サイズ、色、横書き / 縦書き、揃え、行間、字間、
  太字、斜体、袋文字、自動縦中横、記法による縦中横 / 横倒しを編集できる。
- 文字効果として、追加の外フチ、ドロップシャドウ、外側発光、背景プレート、Echo を
  テキストブロック単位で設定できる。組み込みプリセットには、字幕、中抜き、ネオン、
  Echo などの文字効果付きスタイルを含む。
- 吹き出しは、形状 (16 種)、塗り、輪郭、しっぽ (先端 / 付け根ハンドル)、装飾、すぐ下の吹き出しとの結合、
  文字に合わせた自動サイズを編集できる。メッセージウィンドウは、背景、枠、影、名前プレート、
  立ち絵枠、続き指標を編集できる。
- スタンプは同梱絵文字、またはユーザー画像。ユーザー画像は選択時に長辺 1024px へ縮小し、PNG/base64 を
  `StampSource::Embedded` として注釈へ埋め込むため、元ファイルの移動 / 削除や別マシンでも欠落しない。
  配置したユーザー画像は `comic_user_stamps.db` に MRU 履歴 (上限 48 / ピッカー表示 24、内容ハッシュで
  重複排除) として残り、ファイルを選び直さず再利用できる。履歴の削除 / prune は配置済みスタンプを壊さない。
- フォントは吹き出し / メッセージウィンドウは Yu Gothic 既定。オノマトペや装飾フォントは編集用追加パック
  から供給され、未導入時は追加自体をブロックする (システム既定へのフォールバックはしない = 後からフォント
  追加で保存済みの見た目が変わる事故を防ぐ)。
- 編集中のプレビュー解像度 (`text_preview_scale`: 原寸 / 1/2 / 1/4 / 1/8) を選べる。テキスト注釈モード中
  のみ下地を 1/N に縮小して合成 / GPU upload を軽くし、モード終了で原寸へ焼き直す。保存 / コピー / 比較 /
  `Ctrl+E` は常にフル解像度 (別経路)。設定は永続化される。
- 永続化は中央 `comic.db` (キーは `page_path_key` 系。ZIP / PDF・ネスト ZIP も対応) が正本。設定の
  バックアップ ON のときはフォルダ直下 `mimageviewer.dat` (サイドカー) にも dual-write し、フォルダ
  ごと移動しても保持される。注釈のあるページはサムネイル左上にピンクの「文」バッジを表示する。
- 注釈は最前面 (パイプライン最終段。ポストフィルタの後・切り取りの前) として、表示と
  保存 / コピー / 比較 / `Ctrl+E` 書き出しに焼き込まれる。サムネイルには焼き込まない。

### 8.9 開発者 / 診断

不具合報告時に、利用者がコマンドライン引数や `%APPDATA%` の手探りをせずに
ログを集められるようにするための機能群。

- **動作ログ (`mimageviewer.log`) は常時記録**: 旧仕様ではリリースビルドで
  `--log` 引数を付けないと記録されなかったが、「不具合が起きる前に有効化して
  いないと痕跡が残らない」問題があったため常時 ON にした。`--log` 引数は後方互換で
  受け付けるが現在は no-op。`logger.rs` が 16 MiB で `mimageviewer.log.bak` に
  ローテーションし、起動時に前回分を `mimageviewer.log.prev` に退避するため、
  長時間連続起動でもディスク使用量は上限固定。
- **`panic.log` のローテーション**: panic フックが書く `panic.log` は
  セッションを跨いで append し続けるため、同じ panic の連発で無制限に膨らみ得た。
  4 MiB 超で `panic.log.bak` に 1 世代退避してから作り直す (`main.rs`
  `append_panic_log_entry`)。
- **`perf_log_enabled`** (bool, デフォルト false): 性能ログ
  (`perf_events.jsonl`、構造化イベントログ) を記録するかの設定。フレーム単位の
  イベントを大量に吐くため常時 ON にはしない。起動時に 1 度だけ読まれ、ON なら
  `Settings::load()` 後に `perf::init_with_path` を呼んで有効化する
  (`perf::init` の START/FILE は `OnceLock` なので `--perf-log` 指定済みなら no-op)。
  変更は次回起動から反映。`--perf-log` 引数は従来どおり起動直後から全イベントを
  記録する開発者向け経路。サブ展開の表示反映は `subfolder.install_*`、
  場所 facet 初回件数計算は `ui.facet_place_counts_build`、場所メニュー描画は
  `ui.facet_place_menu_render`、フォルダ読込の rating / tag / visible index 構築は
  `nav.sli_prewarm_rating` /
  `nav.sli_prewarm_tags` / `nav.sli_rebuild_visible_indices` に分けて記録する。AI モデル facet
  の遅延メタデータ読込は `details_meta.load_start` / `load_done` / `ai_item_slow`、
  `ai_total_ms` / `ai_permit_wait_ms` / `ai_extract_ms`、
  メニュー件数集計は `ui.facet_ai_model_counts_build` / `ui.facet_ai_tool_counts_build`
  に記録する。AI facet 件数は表示集合と遅延メタキャッシュが変わるまでメモリキャッシュする。
- **環境設定「開発者」タブ** (`PreferencesPage::Developer`): 上記 `perf_log_enabled`
  のトグルと、「ログを zip にする」ボタンを置く。
- **診断 zip 書き出し** (`diagnostics.rs` `export_diagnostics_zip`): logs ディレクトリの
  ログ群 (動作ログ・`panic.log`・`settings.log`・worker ログ・現行 `perf_events.jsonl`)
  と `system_info.txt` (バージョン/OS/GPU) を 1 つの zip にまとめ、デスクトップ
  (`SHGetKnownFolderPath(FOLDERID_Desktop)` で解決) に
  `mImageViewer_diag_<日時>.zip` として保存する。rotate 済みの perf 世代
  (`perf_events.1.jsonl` 等) は巨大なので除外する。

### Ctrl+E エクスポート

- フルスクリーン静止画 (`Image` / `ZipImage` / `PdfPage`) で `Ctrl+E` を押すと、現在の表示結果をファイルに書き出す。見開き表示中は左右ページを現在の配置のまま 1 枚の見開き画像として書き出す。動画や区切りアイテムでは無効。
- `Ctrl+E` のほか、**画像補正パネルのヘッダー右側に並ぶ処理順アイコン列** (`消しゴム / 補正レイヤー / 隠蔽加工 / エクスポート`) のエクスポートアイコン (`draw_export_icon`) からも開ける。補正パネルはホバー表示のオーバーレイなので、クリック時は `adjustment_mode` を `false` にして閉じてから `open_export_dialog_for_current` に合流する (= ビューモードへ戻して合成結果を書き出す)。`open_export_dialog_for_current` は補正 / 消しゴム / 隠蔽 / 分析モード中は弾く (`is_overlay_edit_mode_active() || adjustment_mode || analysis_mode`) ため、`Ctrl+E` 直接押下はこれらのモード中は無効。アイコン経路は補正パネルを閉じることでこのガードを通過する。
- 保存先は前回保存先 (`Settings::export_last_directory`) が存在すればそれを既定表示し、なければ元の場所を使う。ダイアログの「元の場所」ボタンで、通常画像は画像ファイルの親フォルダ、ZIP 内画像は ZIP ファイルの親フォルダ、PDF ページは PDF ファイルの親フォルダ、見開き合成は左ページ側の元フォルダへ戻せる。
- 出力名は既定で `<元名>_edited`。バッチ出力では `_0` (現在の設定) / `_1`〜`_4` (隠蔽プリセット) を付ける。同じ名前が存在する場合はセッション単位で `_0001` などを挟み、上書きしない。
- 出力形式は JPEG 95 / PNG / WebP。元形式が書き出し非対応の場合は `Settings::export_fallback_format` に従う。形式変換、PDF、見開き合成ではメタデータ保持は無効。
- 出力サイズは「そのまま」「1/2 サイズ」「1/4 サイズ」から選ぶ。crop / 見開き / 隠蔽プリセット合成後の画像を基準に Lanczos3 で縮小し、既定値は `Settings::export_default_scale` に保存する。
- JPEG / PNG / WebP の同形式出力では、`Settings::export_embed_metadata` が有効なら元画像の EXIF / XMP / PNG text / WebP metadata を転記する。ZIP 内画像は worker がエントリバイトを読み、パスの無いメタデータ元として扱う。JPEG の Orientation は表示で回転済みの画素と一致するよう正規化する。
- 永続化設定は `Settings::export_embed_metadata` (メタデータ保持)、`Settings::export_last_directory` (前回保存先)、`Settings::export_batch_selection` (現在 / プリセット 1〜4 のチェック状態)、`Settings::export_fallback_format` (非対応元形式の JPEG / PNG 選択)、`Settings::export_default_scale` (出力サイズ)。
- 保存は `ctrl-e-export` worker で順次実行する。隠蔽プリセットの合成、画像エンコード、メタデータ転記、ファイル書き込みはいずれも worker 側で行い、UI は進捗モーダルを `try_recv` で更新する。キャンセルは次のエントリ開始前に反映され、処理中の 1 件は完了まで待つ。
- 現在表示中の実フォルダへ保存した場合は、フルスクリーンを抜けて一覧へ戻ったタイミングでフォルダを再読み込みし、新しい出力ファイルのサムネイルを反映する。ZIP / PDF / 検索結果などの仮想フォルダでは自動再読み込みしない。

### 10.1 AI モデル一覧

| realesrgan-x4plus-anime | アップスケール「イラスト・アニメ」 | Real-ESRGAN (6B 軽量版) | ~18MB | BSD-3-Clause |
| realcugan-x4-conservative | アップスケール「漫画 (トーン保持)」 | Real-CUGAN | ~5.4MB | MIT |

### 10.2 JPEG ノイズ除去

JPEG 圧縮で発生するブロックノイズ・モスキートノイズを AI で除去する機能。

- **対象**: フルスクリーン表示中の画像（補正パネルから選択）
- **選択肢**: なし / JPEG (RealPLKSR)
- **処理順序**: ノイズ除去 → 補正 → アップスケールの順に適用
- **設定**: `AdjustParams.denoise_model` フィールドに保存 (グローバルまたはページ個別)
- **UI**: 補正パネルの「AI ノイズ除去」チェックボックスで切替。`ai_feature_mode=high_quality`
  のときだけ実行され、`disabled` / `light` では保存済み設定を保持したまま実行しない

### 10.3 AI アップスケール

ONNX Runtime + DirectML EP でタイル分割 4x アップスケールを実行。
環境設定「全体設定」の `ai_feature_mode` で利用範囲を選ぶ:

- `disabled`: 低スペック環境向け。AI アップスケール / AI ノイズ除去を実行しない。
  表示が重い環境ではこの設定を推奨する
- `light`: 軽め。自動判別は漫画を `Real-CUGAN 4x conservative`、
  それ以外を `Real-ESR General V3` に振り分ける。手動選択もこの 2 モデルに制限し、
  ノイズ除去は実行しない
- `high_quality`: GPU 負荷高め。全アップスケールモデルとノイズ除去を許可する。
  GPU によっては表示や処理に時間がかかるモデルが含まれる

`high_quality` では、画像タイプ自動判別（イラスト/漫画/3D/写真）に基づき、以下の
3 モデルに自動振り分け:

- イラスト・アニメ → `Real-ESRGAN Anime 6B`
- 漫画 → `Real-CUGAN 4x conservative`（スクリーントーン保持）
- 写真 / 3D → `Real-ESRGAN x4plus`（ノイズ除去強）

補正パネルから手動で次の補助モデルも選択可能（自動選択の対象外）:

- `4x-NMKD-Siax-200k`: 写真向け、フィルム粒子や布目など質感を残す
- `Real-ESR General V3`: 高速軽量、補正量控えめで破綻しにくい

モデル範囲の制限は実行時に適用される。ページ個別 / お気に入り標準 / グローバル
プリセットに保存済みの重いモデル設定は削除せず、モードを `high_quality` に戻すと再び有効になる。

### 10.4 非破壊 AI 修復（消しゴムモード）

フルスクリーンで E キーを押すと消しゴムモードに入り、画像の任意領域をマスクして MI-GAN で補完する。
元画像ファイルは一切変更しない（非破壊）。修復情報はマスクとして DB に保存され、表示時にリアルタイム適用。
タイル分割方式（512×512、64px オーバーラップ、線形ブレンド）で元解像度を維持。

- **ツール**: 筆、囲み、直線、縦線、横線、矩形、楕円、選択
- **描画/消去モード**: 筆/囲みはビットマップ下地を直接追加・削除。直線/矩形/楕円などのオブジェクトは
  作成順に `add` / `subtract` として重なり、消去モードでも既存オブジェクトは丸ごと削除しない
- **画像端の編集**: 筆と囲みはドラッグ点が画像外にはみ出しても保持し、画像範囲に重なる部分だけを
  クリップしてマスクへ反映する。同じマスク編集 UI を使う隠蔽加工でも同じ挙動にする
- **共通ビュー操作**: 消しゴム / 隠蔽加工 / 切り取り / テキスト注釈 / 補正レイヤー中の
  画像上ホイールは、修飾キーなしでも `Ctrl+ホイール` でもズーム専用。
  パネル上の修飾なしホイールはパネルスクロールに使い、`Ctrl+ホイール` はズームを優先する。
  `Space+左ドラッグ` は一時パン、中ボタンドラッグはズームとして扱う
- **選択表示**: 選択ツール中は全ベクタをアウトライン表示し、合成マスクでは透明になる `subtract`
  オブジェクトもクリック対象として視認できるようにする
- **マスク永続化**: SQLite (`mask.db`) に deflate 圧縮した 1bit/pixel マスクと Shape JSON を保存。次回表示時に自動適用
- **マスクスロット**: 消しゴムは `F7` / `F8`、隠蔽加工は `F9` / `F10` でスロット 1 / 2 を適用。
  `Shift` を付けると現在ページまたはグリッドの対象ページから適用済みマスクを削除する
- **PDF 対応**: ズーム再レンダリングでサイズが変わった場合、マスクを最近傍法でリスケール
- **復元**: マスク全削除でいつでも元画像に戻せる

### 10.5 補正レイヤー

フルスクリーンの画像補正パネル右上に並ぶ処理順アイコンから「補正レイヤー」を開き、
マスク付きの非破壊フィルタを画像ごとに重ねられる。サムネイル画像には補正レイヤー結果を反映せず、
設定があるページにはバッジで示す。

- **UI**: `local_adjust_lab` と同じ左パネル + 右ツールパネル構成。左パネルはレイヤー一覧、
  効果選択、手描きツール選択を持ち、右上の `×` または `Esc` で閉じる。右パネルは
  ツール設定 / マスク設定 / 効果パラメータを表示する
- **レイヤー**: 1 レイヤーにつき 1 効果。全体 / 手動 / 線形・円形グラデーション /
  輝度・カラー範囲 / 被写体 / 領域分割のマスクを選べる。追加後も `マスク種類変更` で
  効果を残したままベースマスクを差し替えられる
- **効果**: `local-adjust-core` の全 `LocalEffect` を効果ピッカーから検索して選択できる。
  効果パラメータはコピー / ペースト / リセットに対応し、スポイトや位置ハンドル付き効果は
  画像上クリック / ドラッグで操作できる
- **プレビュー**: 変更直後は補正レイヤー抜きの下位画像を即時表示し、CPU worker の非同期合成が
  完了した時点で補正レイヤー込みの表示へ差し替える
- **書き出し**: Ctrl+E / キャプチャ保存では補正レイヤー結果を含める。補正レイヤーが有効な場合は
  最新の `local_adjust_cache` が揃ってから書き出す

## 11. セキュリティ方針

- 画像デコードは `image` クレート（純粋Rust・メモリ安全）を基本とする
- HEIC / AVIF / JXL / TIFF / RAW は Windows の WIC (Windows Imaging Component) 経由でデコード。
  WIC 呼び出しは `unsafe` ブロックに局所化（`src/wic_decoder.rs`）
- NVIDIA NGX 呼び出し部分も `unsafe` ブロックに局所化（Phase 2、未実装）
