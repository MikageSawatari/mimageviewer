# ブリーフ: 一覧スナップの移動量が大きいときはアニメーションする

対象: v2.13.0。実装 = Codex Sol / レビュー・検収 = ClaudeCode。
正本: [docs/touch-support-plan.md](touch-support-plan.md) §5.4。

前提 (完了・コミット済み・実機確認済み): Phase 1 一式 (`bb9574b2` 〜 `961bb47f`)、
一覧指スクロール `266948f4`、方向スナップ + ピンチ列数 `a6eeb386`。

---

## 1. 症状

実機報告 (2026-08-07):

> 逆走は良いのですが、**順方向にスナップする場合で、距離が多いときに、
> 瞬間的すぎて画面がジャンプしたように感じる**ことがあります。
> スナップでの移動量が大きい場合は、もう少し時間をかけてアニメーションした上で
> スナップできるようにできますか？

## 2. なぜ大きく動くか (設計どおりの帰結)

`a6eeb386` の方向スナップでは、逆走を許容値 (行高の 15%) に抑えるため、
**それ以上進んでいたら前方の行まで進める**。したがって:

- **逆方向のスナップ: 最大 15% 行** — 小さいので気にならない
- **順方向のスナップ: 最大 85% 行** — **ここが瞬間移動に見える**

## 3. 直し方 — 端数をアニメーションさせる

**`scroll_offset_y` (anchor) は行境界のまま維持する不変条件を絶対に壊さないこと**
(CLAUDE.md「Row snapping」/ plan §5.4)。したがって:

> **アニメーションさせるのは `remainder_y` だけ。**
> `anchor_y` はアニメーション完了時に 1 度だけ更新する。

- 順方向スナップ: `remainder_y` を現在値から `row_h` まで動かし、
  **完了時に `anchor_y += row_h`、`remainder_y = 0`** にする
- 逆方向スナップ: `remainder_y` を `0` まで動かして完了
- 描画位置は従来どおり `anchor_y + remainder_y` なので、**描画側の変更は不要なはず**

### 3.1 いつアニメーションするか

- **移動量が小さいときは従来どおり即時**にする。数 px の移動をアニメーションすると
  かえって鈍く感じる
- 目安: 移動量が **行高の 20% 未満なら即時**、それ以上ならアニメーション
- **しきい値と時間は 1 か所の定数**にして、doc comment に根拠を書く (実機で調整する)

### 3.2 時間とイージング

- **130ms 程度**、**ease-out** (最初に速く、最後に減速)。指を離した勢いの続きに見える
- 時間は移動量に比例させてもよいが、**上限を設ける**こと。
  比例させる場合も「最大 160ms」程度に収める

### 3.3 途中で触られたら中断する

- アニメーション中に新しいタッチが始まったら、**その時点の位置を引き継いで**中断する。
  完了を待たない・元に戻さない
- 中断時も `anchor_y` は行境界のままであること (端数側で引き継ぐ)

## 4. ⚠ アイドル時に repaint を出し続けないこと

mIV は静止時に意図的に就寝する。アニメーション中は `ctx.request_repaint()` が要るが、
**完了したら必ず要求を止めること**。

止め忘れると `scripts/check-idle-health.ps1` (リリース前の必須ゲート、
CLAUDE.md「idle health smoke」) が落ちる。**「アニメーション状態が無ければ repaint を
要求しない」ことをコード上で明確にする**こと。

## 5. スクロール通知との関係

`266948f4` で入れた「touch move ごとにスクロール中を通知する」処理
(`last_prefetch_scroll_at` / `last_scroll_event_at` / idle-upgrade) は、
**アニメーション中もスクロール中として扱う**こと。

指を離した瞬間に settle を発火させると、まだ動いている最中に
「停止した」と判断され、prefetch 抑制が早く解除される。
**settle はアニメーション完了時**にする。

## 6. マウス無影響 (plan §5.15)

- **ホイールスクロールにアニメーションを入れないこと。** 1 ノッチ 1 行の即時移動のまま
- スクロールバーのドラッグも従来どおり
- `MIV_DISABLE_TOUCH_GESTURES=1` で現行挙動へ戻る

## 7. テスト

アニメーションの進行計算は**純関数**にして unit test する:

- 経過時間 0 → 開始位置、経過時間 >= duration → 目標位置ちょうど
- ease-out になっている (中間時点で線形より進んでいる)
- **移動量がしきい値未満なら即時完了** (アニメーション状態を作らない)
- **アニメーション完了後の `anchor_y` が `row_h` の整数倍**であること (既存の不変条件)
- 中断したときに `anchor_y` が行境界のままで、端数が引き継がれること
- 上下端のクランプ後もこれらが成り立つこと

## 9. 制約

- **アプリを起動しないこと。** 検証ビルドは ClaudeCode が用意する
- ブランチ操作・コミットは不要。master の作業ツリーで作業する
- **診断ログは残すこと**
- detached-rework 凍結ルールは有効
- **範囲を広げないこと。** 慣性スクロールは入れない (plan §5.4)。
  これは「スナップ先までの短い補間」であって、速度から到達点を決める慣性ではない

完了したら、変更内容・**しきい値と時間の値**・**repaint を止める仕組み**・
テスト結果を報告すること。
