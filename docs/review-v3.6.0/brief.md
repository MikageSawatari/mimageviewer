## 特に見てほしい観点

### 1. 状態の所有と寿命

このセッションで 2 度、**同じ状態を 2 か所が終わらせていた**ことが原因の不具合が出た。

- `StillSeekGesture` (Idle / Track / Strip / StripCommitted) の生成・破棄が
  本当に 1 か所か。**フレームを跨いで生き残るべき状態が、途中の別処理で
  消える経路が他に無いか。**
- `BottomBarLock` (None / BarOnly / BarAndStrip) の遷移に、到達できない状態や
  戻れない状態が無いか
- 列の可視状態 `still_seek_strip_visible` を触る入口は 4 つある
  (フィルム状ボタン / 上下ドラッグ / Shift+S / 環境設定)。**食い違う組み合わせが無いか**

### 2. 次元の掛け合わせ

以下の組み合わせで、**破綻する組が無いか**を機械的に洗ってほしい。
実機での確認は依頼者が行うので、**コードから到達可能な破綻を挙げてくれればよい**。

- 読み方向: LTR / RTL
- シークバー方向設定: 読み方向に合わせる / 常に左→右 (**列とバーで別軸になった**)
- ページ構成: 単ページ / 見開き / 連結読み / 分割表示
- 固定: None / BarOnly / BarAndStrip
- 列: 表示 / 非表示、高さ 4 段階
- プレビュー: 3 択
- コンテナ: 通常フォルダ / ZIP / PDF / 変換済みアーカイブ
- 端: 先頭ページ / 末尾ページ / 総数 1 / 総数 0
- ページの向き: 回転あり / なし、縦長 / 横長混在

### 3. 動画との一致

「動画に合わせる」という要求で作った部分が、**本当に一致しているか**。
ずれているなら、それが意図的か事故かを判断してほしい。

- ドラッグの向き・量・確定タイミング
- 下方向ドラッグでの close
- ロックの 3 状態
- 高さの予約 (静止画 38pt / 動画はシーク行 24 + コントロール行 40)

### 4. 性能

列は**毎フレーム**レイアウトを組む。`--perf-log` の計測は未実施。

- UI スレッドで I/O・デコード・DB アクセスに到達する経路が無いか
- 数万ページで有界か (要求数・テクスチャ数・レイアウトのループ回数)
- 直前のリリースで入れた**先読み抑制 gate** と競合していないか
  (ドラッグ中は投機的先読みを止め、列とプレビューは priority 経路に載せる設計)
- `keep_range` を広げていないか (worker のキャンセル判定を鈍らせる)

### 5. テストが実態を見ているか

**この領域のテストは全部通ったまま 4 件の実機不具合を通した。**

- ハンドラ単体テストが、**production が通るフレームの並び**を再現しているか
- 「純関数だけを見て、統合を見ていない」テストが他に無いか
- 追加すべき回帰テストがあれば、**何を固定すべきか**を挙げてほしい
