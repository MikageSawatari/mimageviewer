## 3. 選択肢 (`BatchExportOptions`)

ダイアログの値はすべてこの 1 つの構造体に入る。worker へは開始時に clone を 1 回渡すだけで、
実行中に UI から変えない。プリセット (§8) もこの構造体をそのまま保存する。

### 3.1 形式

```rust
enum BatchFormatKind { Png, Jpeg, Webp, SameAsSource }
struct BatchFormat {
    kind: BatchFormatKind,
    jpeg_quality: u8,        // 1..=100、既定 95
    webp_quality: u8,        // 1..=100、既定 90 (単ページの WebP と同じ)
    webp_lossless: bool,     // 既定 false
    same_fallback: SameFallback, // Jpeg / Png。既定 Jpeg
}
```

- 品質はダイアログの数値欄 (DragValue) で任意に指定する。各形式の品質は独立に覚える
  (形式を切り替えても他方の値を失わない)。
- **元と同じ形式**: 元の拡張子で決める (I/O なし)。`jpg`/`jpeg`/`jfif` → JPEG、`png` → PNG、
  `webp` → WebP。それ以外 (GIF・BMP・TIFF・HEIC・AVIF・JXL・RAW・PSD など) と PDF ページは
  `same_fallback` (JPEG か PNG) にする。ZIP 内画像はエントリ名の拡張子で決める。
  品質は上の `jpeg_quality` / `webp_quality` を使う。
- JPEG のサブサンプリング・progressive、PNG の圧縮レベル、AVIF/JXL/TIFF は範囲外 (§1.362)。
- 透過: JPEG は今と同じく `edits.jpeg_matte` で背景を合成する。PNG・WebP はアルファを保つ。
- **形式ごとの寸法の上限**: リサイズの目標寸法を計算した直後 (リサイズ用のバッファを確保する前) に確かめ、
  WebP は各辺 16383px、JPEG は各辺 65500px (使用中の `turbojpeg-sys` の `JPEG_MAX_DIMENSION`) を
  超えたらその項目を「この形式で書ける大きさを超えています (W×H)」の失敗にして次へ進む
  (リサイズの指定と保存済みの AI 拡大の組み合わせで、通常の操作でも起こり得るため)。
  WebP のエンコードは `Result` を返す `encode_simple(false, quality)` / `encode_simple(true, 75.0)` へ替える
  (`encode` / `encode_lossless` はこれを `unwrap()` しているだけなので、同じ入力では同じバイト列になり、
  単ページの出力は変わらない)。
- 形式の決定は **worker の書き出しだけが持つ**。`BakedEditSnapshot.format` は製本・外部ツール用に
  残すが、一括の新しい書き出し関数は読まない (同じ意味を 2 か所に持たない)。
- `CaptureFormat` と `ExportFormat` は変えない (キャプチャ設定・単ページと共有のため)。

### 3.2 リサイズ

```rust
enum BatchResizeMode {
    None,                 // そのまま
    Percent(u32),         // 1..=400
    LongEdge(u32),        // 長辺
    ShortEdge(u32),       // 短辺
    Width(u32),           // 幅 (高さは比率から)
    Height(u32),          // 高さ (幅は比率から)
    Fit { width: u32, height: u32 }, // 枠に収める (縦横比を保って枠の内側)
}
struct BatchResize { mode: BatchResizeMode, allow_upscale: bool, filter: ResizeFilter }
enum ResizeFilter { Lanczos3, CatmullRom, Bilinear, Nearest } // 既定 Lanczos3
```

- px 指定の範囲は今の長辺指定と同じ 256〜16384 (`ExportScale::LONG_EDGE_MIN/MAX`)。Fit の各辺も同じ。
- **拡大の可否は 1 つの規則で決める**: 目標寸法を出し、元より大きくなる (幅か高さのどちらかが元を超える)
  かつ `allow_upscale == false` なら**リサイズしない** (元の寸法のまま)。`Percent(200)` も
  `allow_upscale` が OFF なら変わらない。既定は OFF (今の長辺指定と同じ縮小のみ)。
- 1/2・1/4 は `Percent(50)` / `Percent(25)` で表す。今の `ExportScale::scaled_by_factor` と
  **同じ式** (`(w as f32 * factor).round().max(1)`、factor = p / 100) で寸法を出すので、
  1/2・1/4・長辺指定の出力寸法は今と同じになる (§10 のテストで固定する)。
- フィルタは `fast_image_resize` の `FilterType::{Lanczos3, CatmullRom, Bilinear}` と
  `ResizeAlg::Nearest`。`crate::fast_resize::Quality` に `CatmullRom` / `Nearest` を足し、
  既存の `Bilinear` / `Lanczos3` の意味は変えない。UI の表示名は「Lanczos (既定)」「バイキュービック」
  「バイリニア」「最近傍 (ドット絵向け)」。
- リサイズは**保存済み編集の合成の後** (AI 拡大・切り取り・回転の後) の絵に掛ける。今と同じ位置。
- 埋める (Fill = はみ出しを切る)、メガピクセル指定は範囲外。
- PDF ページは今と同じく長辺 4096px で描画してから合成する。拡大を許可して 4096px を超える目標を
  指定すると、描画済みの絵を拡大する (PDF を目標寸法で描き直さない)。ダイアログには書かない
  既知の制限として本書に残す。

### 3.3 出力先

```rust
enum BatchDestination {
    Folder { path: PathBuf, keep_structure: bool },
    SameAsSource { subfolder: String }, // 空なら元のフォルダの直下
}
```

各項目の**元の場所** (`source_dir`) を次のように決める (I/O なし、パス演算だけ):

| 元 | `source_dir` |
| --- | --- |
| 画像ファイル・スタックのメンバー | ファイルの親フォルダ |
| ZIP 内画像 | ZIP ファイルの親フォルダ |
| PDF ページ | PDF ファイルの親フォルダ |

ZIP/PDF は書庫を 1 段のフォルダとして再現しない。`<filename>` が既に書庫名を含む
(`<zip名>_<entry名>`) ので、元と同じフォルダに並べても名前で区別できる。書庫内のフォルダ階層も
再現しない。これは単ページの「元の場所」と同じ定義である。

- **元と同じフォルダ**: `source_dir` (+ `subfolder`)。`subfolder` は 1 段の名前として
  `basename_from_text` で正規化する (区切り文字を含めて別の場所へ出さない)。
- **構造の維持** (`Folder` + `keep_structure`): 全項目の `source_dir` の**共通の祖先**を基点とし、
  `path / (source_dir から基点を除いた相対パス)` へ出す。共通の祖先は大小文字を区別しない
  コンポーネント比較で求める (Windows のパス規則)。ドライブ・UNC 共有が違う項目が混ざり共通の祖先が
  無いときは、相対パスの先頭にドライブ名 (`C`) / `サーバ名_共有名` を 1 段置く。
  基点は開始時に worker が全項目から 1 回だけ決める (項目の順序に依存しない)。
- 通常フォルダの一覧で開いた場合は基点がそのフォルダになるので、構造の維持は「選んだ項目が
  サブフォルダを含む場合だけ」効く。検索結果・コレクション・スマートフォルダでは基点が自動で
  共通の祖先になる。基点の手動指定は作らない。
- フォルダ作成は worker が項目の名前を決めるときに `create_dir_all` する (§3.5 の予約キーのため。
  今は書き始める前に出力フォルダを 1 回作っている)。

### 3.4 ファイル名と置換子

今の `<filename>` `<dirname>` `<num>` に次を足す。未知の `<...>` は今と同じくそのまま残す。

| 置換子 | 意味 | 決める場所 |
| --- | --- | --- |
| `<ext>` | 元の拡張子 (小文字、ZIP はエントリ名の拡張子、PDF ページは `pdf`) | 準備時 (I/O なし) |
| `<num:N>` | 連番を N 桁 (1〜9) で。`<num>` は今どおり 4 桁 | 準備時 |
| `<date>` | 元の更新日 `YYYYMMDD` (ローカル時刻) | worker |
| `<time>` | 元の更新時刻 `HHMMSS` (ローカル時刻) | worker |

- テンプレートは拡張子を除いた名前。出力の拡張子は常に付ける。`<ext>` は元の拡張子。
  ただし、末尾が文字どおり `.<ext>` のときは書き出す形式の拡張子として扱い、二重に付けない (末尾以外の `<ext>` は元の拡張子のまま)。
- 元の更新日時は、画像ファイルはそのファイル、ZIP・PDF は**書庫ファイル**の更新日時 (§6.4 と同じ)。
- 出力寸法の置換子 (`<width>` など) は入れない。名前が合成の前に決まらないと、§4.2 の
  「スキップは読み込みより前に判定する」が成り立たないため。
- ダイアログの例 (先頭 1 件) では `<date>` `<time>` を展開せず、そのまま表示して
  「書き出し時に決まります」と添える (UI で stat しない)。
- 正規化は今と同じ `basename_from_text` (区切り文字は `_`)。

### 3.5 上書きの扱い

```rust
enum OverwritePolicy { Rename, Skip, Replace } // 既定 Rename (今の挙動)
```

- `Rename`: 今と同じ。既存ファイルと同一実行内の名前を避けて `_1`〜`_9999`。
- `Skip`: 既存のファイルがあれば、その項目を**読み込む前に**飛ばし、「スキップ」として数える。
- `Replace`: 既存のファイルを置き換える。同じフォルダの一時ファイルへ書いてから
  `MoveFileExW(MOVEFILE_REPLACE_EXISTING)` 相当で置き換える (書きかけの絵を残さない)。
  置き換えたファイルはごみ箱へ送らない (戻せないことをダイアログに書く)。
- **同一実行内の衝突は方針に関係なく常に連番**にする。2 つの項目が同じ名前へ落ちたとき、
  後の項目が前の項目の出力を上書き・スキップしない。
- **予約キー**: 同一実行内の名前の予約 (今の `claimed: HashSet<PathBuf>`) は、パスそのものではなく
  `OutputKey` で比較する。worker は出力フォルダを `create_dir_all` した**後**に `canonicalize` し
  (フォルダ文字列ごとに 1 回だけ、結果を覚える)、`OutputKey` = 「正規化したフォルダ + `\` + ファイル名」を
  小文字化した文字列にする (Windows のファイル名は大小文字を区別しないため)。フォルダを先に作るので
  未作成のフォルダの扱いは要らず、junction・シンボリックリンク・8.3 形式名・`.` / `..`・大小文字の違いで
  同じ実体を指す出力先は同じキーになる。`canonicalize` が失敗したらその項目は失敗 (まれな失敗の割り切り)。
  書き終えたファイルは、そのファイル自身を `canonicalize` したパス (8.3 形式の短い名前は長い名前になる) の
  キーも予約に足す。
  判定の順 (候補の名前ごと):
  1. 「正規化したフォルダ + 名前」のキーが予約済み → 次の連番へ。
  2. 候補が存在しない (`exists()` が false) → この候補で予約して進む。
  3. 候補が存在する → その候補のファイル自身を `canonicalize` し、そのキーが予約済みなら今回の出力なので
     次の連番へ (候補の名前が今回書いたファイルの 8.3 形式の別名だった場合もここで分かる)。
     予約済みでなければ、今回より前からあるファイルとして方針 (`Rename` は次の連番、`Skip` はスキップ、
     `Replace` は §3.5 の元ファイルの保護を確かめて置き換え) に従う。
  `Skip` でも出力フォルダは判定のために先に作る (その項目が飛ばされても空のフォルダは残り得る)。
- **今回の入力は上書きしない**: `Replace` でも、今回の対象の元ファイル (画像ファイル・ZIP・PDF) と、
  **画像の透かしが有効なときのロゴの画像** (§7) と同じ実体へは書かない。worker は開始時にこれらを
  `canonicalize` した集合を作り、
  既存の出力先を置き換える前にそれも `canonicalize` して照合する。一致したら置き換えず、
  その項目を「元ファイルは上書きしません」の失敗にする (8.3 形式名・シンボリックリンク経由の
  同一実体も、正規化で同じになる)。`Rename` / `Skip` は既存ファイルに書かないので照合しない。
- 「確認する」(1 件ごとに尋ねる) は作らない (§9 簡素化)。

### 3.6 元の情報と更新日時

```rust
keep_metadata: bool,   // 既定 false (今の挙動)
keep_file_time: bool,  // 既定 false
```

- `keep_metadata`: **出力の形式が元と同じ (JPEG→JPEG / PNG→PNG / WebP→WebP) の項目だけ**、
  元の情報を残す。形式が変わる項目・PDF ページは残さない (単ページの規則と同じ)。ダイアログの説明文に書く。
  形式ごとの転記対象:

  | 形式 | 残すもの |
  | --- | --- |
  | JPEG | APP1 (EXIF・XMP)、APP2 の ICC (`ICC_PROFILE`、複数セグメントを順に) |
  | PNG | tEXt / iTXt / zTXt (AI プロンプト、Raw profile の EXIF・XMP を含む)、`eXIf`、`iCCP` |
  | WebP | `EXIF`、`XMP `、`ICCP` |

  - **EXIF の共通処理**: 3 形式とも、EXIF は TIFF 本体 (JPEG は APP1 の `Exif\0\0` の後、PNG の `eXIf` は
    本体そのもの、WebP の `EXIF` は先頭に `Exif\0\0` があればその後) に対して同じ関数で処理する。
    処理は 2 つだけ: Orientation を 1 にする、IFD1 (埋め込みの縮小画像) を外す (IFD0 の「次の IFD」を 0 にし、
    IFD1 が指す縮小画像のバイト範囲を 0 で埋める。長さとオフセットは変えない)。TIFF として読めない EXIF は
    転記しない (その項目は EXIF なしで書き、失敗にはしない)。
  - **ICC は出力の画素形式に合うものだけ**: 出力は常に RGB(A) なので、ICC ヘッダの色空間
    (先頭から 16〜19 バイト) が `RGB ` のものだけ転記する。グレースケール (`GRAY`)・CMYK などの ICC は
    付けない (付けると出力に合わないプロファイルになる)。それらの元画像は ICC なしの出力になり、
    他のソフトでは sRGB として表示される。
  - **単ページとの共通処理**: `SaveOptions::metadata_profile` は `Single` (既定) / `Batch`。
    単ページも IFD1 を外し、縮小画像を検出するが、転記対象と Orientation の扱いは従来どおり。
    読めない EXIF は単ページでは残して「EXIF (外せませんでした)」と警告し、一括では転記しない。
    PNG のテキスト内の `Raw profile type exif` / `APP1` も両方で処理する。ImageMagick の長さと16進の桁数を
    厳密に照合し、変わった数字だけ元の位置で書き換え、圧縮の有無・iTXt の言語と訳語を保つ。
    詳細は [単ページの設計 §3.1〜3.3](single-export-thumbnail-plan.md)。
  - XMP は解釈せずそのまま残す。XMP の `xmp:Thumbnails`、EXIF の MakerNote (メーカー独自の領域) に
    含まれ得る縮小画像は消さない (利用者決定、§13 Q3)。代わりに §3.7 の警告を出す。
  - EXIF の画素数タグは書き換えない (単ページと同じ)。
  - ZIP 内画像の転記元はデコードに使ったエントリのバイト列 (同じ読み込みを使い、2 回読まない)。
- `keep_file_time`: 書き出した後、出力ファイルの更新日時を元の更新日時 (§3.4 と同じ値) にする。
  `std::fs::File::set_modified` を使い、依存を足さない。作成日時は変えない。
  **上書きの扱いが `Replace` のときは効かない** (ダイアログでは押せなくし、「上書きのときは使えません」と書く。
  保存する値はそのまま残し、`Rename` / `Skip` に戻すと元の選択が効く。worker は
  `overwrite != Replace && keep_file_time` だけを見る)。理由は §4.4 の「置き換えた出力のサムネイル」。

### 3.7 元の縮小画像が残る出力の警告 (利用者決定 2026-11-25、§13 Q3)

「元の情報を残す」で書いた出力に、元の絵の縮小画像が残っている可能性があれば、書き出しの後に目立つ形で
知らせる。隠したつもりの部分が縮小画像から漏れることを避けるため。縮小画像そのものは書き直さない。

**検出 (worker、エンコードの中で)**: 転記するメタデータは worker が既にメモリに持っている (§3.6) ので、
そのバイト列を調べるだけにする。ファイルを読み直さず、UI スレッドでは何もしない。

| 種類 | 条件 | 調べ方 |
| --- | --- | --- |
| EXIF (外せませんでした) | **単ページだけ** | 読めない EXIF を従来どおり残す場合。一括は読めない EXIF を転記せず、この種類は立てない ([単ページの設計 §3.2](single-export-thumbnail-plan.md)) |
| XMP の縮小画像 | **常に** (項目の編集に関係なく) | 転記する XMP に、縮小画像の構造を書くための名前空間 `http://ns.adobe.com/xap/1.0/g/img/` (`xmpGImg`、`xmp:Thumbnails` の中身はこの名前空間で書かれる) のバイト列があるか。調べる範囲は下の「調べる XMP」 |
| メーカー独自の領域 (MakerNote) | **限定した 5 種類の保存済み編集がある項目だけ** | EXIF の共通処理 (§3.6) で TIFF を読むときに、Exif IFD (タグ 0x8769 が指す IFD) に MakerNote (タグ 0x927C、長さ 1 以上) があるか |

調べる XMP (**実際に転記するものだけ**を、形式ごとに):

- **JPEG 標準 XMP**: 転記する APP1 のうち、`http://ns.adobe.com/xap/1.0/\0` で始まるものの本体。複数あればそれぞれ。
- **JPEG 拡張 XMP**: 転記する APP1 のうち `http://ns.adobe.com/xmp/extension/\0` で始まるもの。各断片の
  見出し (GUID 32 バイト・全体長 4 バイト・offset 4 バイト) を読み、**GUID ごとに分け**、各グループの中を
  offset 順に並べ、**実際に持っている断片の本体だけ**をつないで調べる (見出しの全体長は確保サイズに使わない。
  断片の欠け・重なりがあっても、持っている分を順につないだもので判定する)。見出しが読めない断片は、その断片の
  本体を単独で調べる。今の転記は全 APP1 を残すので、別の GUID の断片も出力に残り、それぞれ調べる。
- **PNG**: 転記するテキストチャンク (tEXt / zTXt / iTXt、§3.6) のうち、キーワードが `XML:com.adobe.xmp` のもの
  すべて (位置・数に関係なく)。tEXt はそのまま、zTXt と圧縮フラグの立った iTXt は worker の中で `flate2` で
  展開してから調べる。展開は **1 チャンクあたり 16 MiB**、**1 ファイルの合計 32 MiB** (既存の
  `png_metadata::read_png_text_chunks` の累積上限と同じ値) で打ち切る。チャンクの上限で打ち切った・
  展開できなかったチャンクは「調べられない」、合計の上限に達したらそれ以降の XMP チャンクは調べずに
  「調べられない」として、**警告側に倒す** (縮小画像ありと同じ扱い)。名前空間が見つかった時点でその項目の
  XMP の検査は終える。ただし Raw profile の EXIF の処理はこの省略と独立して続ける。
  `Raw profile type exif` / `APP1` / `xmp` (キーワードは大文字小文字を問わない) も同じ展開・合計上限を共有する。
  Raw profile の XMP と、XMP の見出しを持つ APP1 は16進を戻してから名前空間を調べる。
  戻せない・宣言長と桁数が合わない・上限超過の Raw XMP は転記したまま「調べられない」と警告する。
  Raw EXIF は読めなければ一括ではチャンクを転記しない (単ページは残して警告)。
  詳細は [単ページの設計 §3.2・§3.4](single-export-thumbnail-plan.md)。
- **WebP**: 転記する `XMP ` チャンク。

- 「隠す編集」は、その項目の編集 snapshot に消しゴム・隠蔽・切り取り・注釈・補正レイヤーのどれかがあること
  (`BakedEditSnapshot` の `erase` / `conceal` / `export_crop` / `comic` / `local_adjust` が `Some`)。
  これは**警告の対象を絞るための限定的な判定**で、対象外の項目なら安全という意味ではない
  (たとえば補正の明るさ (`params`) で見えなくした部分も、元の縮小画像には写っている)。
- **MakerNote を常に警告にしない理由**: カメラで撮った JPEG のほとんどが MakerNote を持ち、中身は
  メーカーごとの形式で、縮小画像があるかは解釈しないと分からない。常に警告すると、写真を「元の情報を残す」で
  書き出すたびに警告が出て、XMP の警告まで読まれなくなる。そこで、部分を隠す目的で使われる 5 種類の
  保存済み編集がある項目に限る。
- **XMP は常に警告する**: 利用者の指示どおり。XMP の縮小画像は撮影機器より、編集ソフトが書き込むことが
  多く、通常の写真では出にくい。
- 名前空間の有無だけを見る軽い判定なので、縮小画像が無いのに名前空間だけ宣言された XMP でも警告になり得る
  (警告側に倒す)。
- 形式が変わる項目・「元の情報を残す」が OFF の項目は、元の情報を転記しないので検出しない。

**時点**: 書き出しの**後** (その項目を書き終えたとき)。書き出しの前に調べるには、開始前に全件の元ファイルを
読む工程と、「書き出すかどうか」を尋ねる途中の確認が要り、§9 で外した組み合わせが戻るため。
書き出しの前には、ダイアログの説明文で知らせる (§6.3)。

**対象と見せ方**:
- worker は該当する項目を書き終えた直後に `ExportEvent::ThumbnailNotice { label, path, kinds }` を送る
  (`kinds` は XMP / メーカー独自の領域の組。単ページでは読めない EXIF の種類もある)。`ExportPending` に一覧として持つ。
  単ページの worker も [単ページの設計 §3.4](single-export-thumbnail-plan.md) に従い、`Completed` の直後に同じイベントを送る。
  ログ (mimageviewer.log) にも出力のパスと種類を 1 行ずつ残す。
- 完了 (`AllDone`) でも取消 (`Cancelled`) でも、警告が 1 件でもあれば**進捗ダイアログを自動で閉じず**
  (通知のトーストに置き換えない)、警告の枠を出す。利用者が「閉じる」か × で閉じるまで残る。
- **終了状態**: `ExportPending` の `finished: bool` を `end: Option<ExportEnd>` (`Done` / `Cancelled`) に
  置き換える (`finished` と同じ意味の値を 2 つ持たない)。`AllDone` を受けたら `Done`、`Cancelled` を受けたら
  `Cancelled` にし、警告があれば pending を**破棄せず**保持する (警告が無い取消は今と同じく破棄してトースト)。
  - 終了後の channel 切断 (worker の正常終了) は、今の `finished` と同じく `end.is_some()` なら無視する
    (「worker が中断されました」を出さない)。`end` が `None` のままの切断だけが中断。
  - 「閉じる」と × は、今の失敗ありの完了と同じく `end.is_some()` のときだけ pending を破棄する。
  - 取消で残った画面には「キャンセルしました」と、そこまでの成功・スキップ・失敗の件数を出す。
  - 一覧の更新 (§4.4) は終了を受けたフレームで今と同じく 1 回だけ要求する (画面を残しても繰り返さない)。
- **画面の構成と高さ** (警告と失敗一覧が両方ある小画面でも操作行を押し出さない):
  - 固定の見出し (ScrollArea の外): 警告色 `warn_fg_color`・太字の「元の縮小画像が残っている可能性があります
    (N 件)」と、件数の行 (「完了: 成功 N / スキップ M / 失敗 K」または「キャンセルしました: …」)。
  - 固定の操作行 (ScrollArea の外): 「閉じる」。
  - 本文 (縦 ScrollArea 1 つ、`auto_shrink([false, true])`): 説明、警告の一覧、失敗の一覧 (今の失敗一覧の
    120pt の別 ScrollArea はこの画面では使わず、本文に入れる)。本文の最大高は `ctx.content_rect()` から
    枠・固定の見出し・操作行の**実測の高さ**と画面余白を引いて決める (起動時ダイアログの規則と同じ考え方)。
    幅は今の進捗ダイアログと同じ固定幅で、長いファイル名は折り返す (floating scrollbar の幅を確保する)。
  - 説明: 「元の情報を残して書き出した次のファイルに、元の絵の縮小画像が含まれている可能性があります。
    消しゴムや隠蔽で隠した部分が、縮小画像に残っていることがあります。公開する前に確認するか、
    元の情報を残さない設定 (一括では『元の情報を残す』、1 枚の書き出しでは『AI プロンプト / EXIF を保持』をオフ) で書き出し直してください。」
  - 警告の一覧: 出力のファイル名と種類 (「EXIF (外せませんでした)」(単ページのみ)「XMP の縮小画像」「XMP (調べられませんでした)」「メーカー独自の情報」)。
    行を押すとそのファイルを Explorer で示す (`reveal_path_async`、既存)。
    Shell へ渡す直前に、verbatim のドライブ・UNC パスと相対パスを通常の絶対パスに変換し、区切りを正規化する (絶対化に失敗した相対パスと、それ以外の verbatim 名前空間は元の表記を保つ)。
    `reveal_path_async` は `SHOpenFolderAndSelectItems` でファイルを選択して開く。以前の `explorer.exe /select,<パス>` では、
    2026-11-25 にサブ PC エージェントが「フォルダは開くがファイルが選択されない」ことを観測した (空白のないパス)。
    起動方法が原因かは推定で、修正後の実機での確認は未確認。失敗時は HRESULT をログに残して親フォルダを開く。
  - **表示の条件**: 警告の画面は `end.is_some()` かつ警告が 1 件以上のときだけ。書き出し中 (`end == None`) に
    `ThumbnailNotice` が届いても一覧に記録するだけで、画面は今の進捗ダイアログ (キャンセルの操作を含む) のまま。
    書き出し中の進捗ダイアログには件数の行に「縮小画像の警告 N 件 (終了後に一覧を出します)」を足す。
  - 警告が無いときの進捗ダイアログ (書き出し中・失敗ありの完了) は今の構成のまま。
- 警告が無ければ §4.4 の通知の表のとおり (今と同じ)。

## 4. worker と取消

### 4.1 準備 (UI スレッド)

準備の流れ (`advance_export_batch_preparation`) は変えない。新しい選択肢のために準備で増えるのは
文字列とパスの演算だけ (`source_dir`、`<ext>`、元の拡張子) で、ファイル I/O・DB・デコードを足さない。
`BatchExportItem` に `source_dir: PathBuf` と `source_ext: String` を足す。

§1.177 (重い 1 件の間 UI が止まる) はこの設計では直さず、悪化もさせない (§13 Q5)。

### 4.2 1 件の処理 (worker)

開始時に 1 回:

1. 出力の基点 (§3.3 構造の維持) を決める。
2. `Replace` なら元ファイルの正規化集合 (§3.5) を作る。
3. 透かしの素材 (文字のフォント・ロゴの画像) を読む (段 B、§7.3)。読めなければ、どの項目も書かずに
   全件を同じ理由で失敗にして終える。

項目ごと (今の順序を保ち、増える段を太字にする):

1. 取消の確認。
2. 構成の確認 (`composition_check`、今と同じ)。
3. **元の更新日時を取得** (`<date>` `<time>` か `keep_file_time` を使うときだけ `metadata`)。
4. **出力フォルダと名前を決める** (§3.3、§3.4)。出力フォルダを作って正規化し、`OutputKey` で予約する (§3.5)。
5. **`Skip` で既存のファイルがあれば `Skipped` を送って次へ** (デコードしない)。
6. デコード (**取消トークン付き** `decode_composite_source_for_materialization`、PDF の長辺 4096 は今と同じ)。
7. 保存済み編集の合成 (**取消トークン付き** `compose_book_page_for_materialization` 相当。
   diffusion fallback の戻り値は今と同じく使わない)。
8. **リサイズ** (§3.2)。
9. **透かし** (段 B)。
10. **エンコード** (`keep_metadata` なら転記元を渡す)。形式ごとの寸法の上限は 8 の目標寸法の計算直後に確かめる (§3.1)。
11. 書き込み: `Rename` / `Skip` は `create_new`、`Replace` は一時ファイル→置き換え (フォルダは 4 で作成済み)。
12. **`keep_file_time` なら更新日時を設定**。失敗しても出力は残し、その項目を失敗として報告する
    (まれな失敗の割り切り、§9)。
13. `Completed`。10 のエンコードで §3.7 の縮小画像を検出していれば、続けて `ThumbnailNotice` を送る。

- 一括の書き出し関数は `export_batch` に新しく置き (`write_batch_item` など)、一括はそちらだけを通る。
  `books::write_composited_page` は**製本 (`write_source`) のために残し、変えない**。製本の合成
  (`compose_book_page*`) も共有のまま変えない。
- 縮小は `scale_export_pixels` から「目標寸法へリサイズする」部分を切り出して共有し、
  単ページは今の `ExportScale` のまま同じ部分を呼ぶ (単ページの挙動は変えない)。

### 4.3 取消

- 一括の取消トークン (`ExportPending.cancel`) を 6・7 のデコードと合成へ渡す。消しゴム・AI・
  補正レイヤー・隠蔽・注釈は既に取消トークンを見るので、1 件の途中でも止まる。
- 取消で止まった項目は書き込まない (書き込みは 11 で、そこまでに取消を確認する)。`Replace` の
  一時ファイルは書く前に作らないので残らない。止まった後の扱いは今と同じ (`Cancelled` を送って終える)。
- 1 件の書き込み・置き換え・日時設定の途中では止めない (短いため)。

### 4.4 進捗と結果

- 失敗と縮小画像の警告は `crate::logger::log` で `mimageviewer.log` に残す。製品ターゲットの
  `log` facade は通常ログへ転送されない。2026-11-25 にサブ PC エージェントが、画面には失敗 9 件と
  縮小画像の警告が出た一方、通常ログの `batch export` 行が 0 件だったことを観測した。
- `ExportEvent` に `Skipped { label, path }` を足し、`ExportPending` に `skipped: Vec<…>` を持つ。
  単ページの worker は送らない (単ページの完了処理は今と同じ結果になる)。
- 進捗: 分母は今と同じ対象件数、完了数は「成功 + スキップ + 失敗」。進捗ダイアログに
  「成功 N / スキップ M / 失敗 K」を出す。
- 完了 (`AllDone`) の通知:

  | 結果 | 通知 |
  | --- | --- |
  | 失敗あり | 今と同じく進捗ダイアログを残し「完了: 成功 N / スキップ M / 失敗 K」 |
  | 失敗なし・スキップなし・成功 1 件 | 今と同じく保存通知 (クリックで Explorer に表示) |
  | 失敗なし・スキップなし・成功 2 件以上 | 今と同じく「N 件をエクスポートしました」 |
  | 失敗なし・スキップあり・成功 1 件以上 | 「N 件をエクスポートしました (既にある M 件はスキップ)」 |
  | 失敗なし・全件スキップ | 「既にある M 件をスキップしました (書き出した画像はありません)」 |

  取消 (`Cancelled`) の通知は今と同じ文で、スキップ件数は足さない。
  ただし、§3.7 の警告が 1 件でもあれば、完了でも取消でも上の表より優先して進捗ダイアログを残し、警告の枠を出す。
- **一覧の更新**: `AllDone` / `Cancelled` のどちらでも、成功パスのうち**親フォルダが今の表示先と一致する
  ものを探し**、1 つでもあればそのパスで `note_exported_file_for_folder_refresh` を 1 回だけ呼ぶ
  (今は最初の成功パスだけを渡しており、「元と同じフォルダ」で出力先が複数になると、
  先頭が別のフォルダのとき今の表示先が更新されない)。判定は今の関数と同じ `path_eq`。
  単ページは出力先が 1 つなので結果は今と同じ。
- **置き換えた出力のサムネイル** (実装レビューの指摘で決定、2026-11-25): `Replace` で既存のファイルを
  置き換えるときに「元の更新日時にする」も効かせると、更新日時が前と同じで、ファイルサイズも同じになり得る
  (単色に近い画像を補正だけ変えて PNG で書き直すと同じ長さになる。通常の操作で起こる)。すると、フォルダの
  再走査・catalog・編集済みプレビューのキャッシュ・スタックの代表など、更新日時とサイズで照合する
  すべてのキャッシュが変化に気付かず、古いサムネイルが残る。
  - 検討した案: 置き換えた出力の各キャッシュを個別に失効させる案は、実装レビューで失効の取りこぼしが
    層ごとに見つかり (catalog → 編集済みプレビュー → スタックの代表 → パスの表記違い・junction)、扱う組み合わせが
    増え続けたので採らない。
  - **採用: 組み合わせを無くす** (CLAUDE.md「設計の簡素化」)。`Replace` のときは「元の更新日時にする」を効かせない
    (§3.6)。置き換えたファイルの更新日時は書き出した時刻になる。失効の仕組みは足さない。
  - **秒単位の照合**: catalog と編集済みプレビューのキャッシュは更新日時を秒単位で照合する
    (`ui_helpers::mtime_secs`、`catalog::file_stamp`、`EditPreviewCacheDb::load_validated`)。同じ秒の中で置き換えると
    気付かない。そこで worker は、置き換える前のファイルの更新日時 (秒) を書き込みの前に読み、置き換えた出力の
    更新日時を「書き出した時刻」と「前のファイルの秒 + 1 秒」の遅いほうにする (照合値を区別するため、
    更新日時が未来へずれることがある。短時間に続けて置き換えると、ずれは積み重なる)。
    これで、フォルダ表示の再走査 (§4.4 の一覧の更新) と、秒単位で照合するキャッシュが変化に気付く。
  - 検索結果・タグ結果に表示中の置き換えた出力は、再検索までサムネイルが古いまま残る。他のソフトが上書きしたときの
    検索結果と同じ今の制限として許容し、表示中の一覧を差し替える仕組みは足さない (§13、利用者の判断)。
  - 失うもの: 「同じ名前のファイルを置き換え、かつ元の更新日時を付ける」使い方だけ。元の更新日時が要るときは
    「連番」か「スキップ」で書き出す。
- 区間の計測: `perf::event("export_batch/item", …)` に decode / compose / resize / watermark /
  encode / write の ms、出力寸法、形式、方針の結果 (written / skipped / replaced / failed) を入れる。
  開始時の準備 (基点・正規化・透かし読み込み) も 1 つの event にする。

### 4.5 ローカル AI の借用

`local_ai_activity` (v3.5.0 F09) は今と同じく worker の寿命で持つ。並列化はしない (範囲外)。

## 5. 永続化と移行

### 5.1 欄

`Settings` に次を足す。どちらも**未リリース**の欄なので、この 2 つに移行は要らない。

```rust
#[serde(default)]
pub export_batch_options: Option<BatchExportOptions>, // 前回の設定
#[serde(default)]
pub export_batch_presets: Vec<BatchExportPreset>,     // 段 C
```

`BatchExportOptions` の各欄は `#[serde(default)]` 付きにし、段 B・C の欄追加や今後の欄追加で
前の段の保存値が読めなくならないようにする。

### 5.2 リリース済みの欄からの移行

`export_batch_directory` / `export_batch_template` / `export_batch_format` / `export_batch_scale`
はリリース済み。次のように読み替える。

- ダイアログを開くとき、`export_batch_options` が `None` なら旧 4 欄から `BatchExportOptions` を作る
  (`BatchExportOptions::from_legacy`)。`Some` ならそれだけを使い、旧 4 欄は読まない。
- 書き出しを始めると `export_batch_options = Some(...)` を保存する。**旧 4 欄の値はもう更新しない**
  (前回の設定の持ち主は新しい欄 1 つ。`write_settings_kv` は全欄を書き直すので、旧 4 欄の行は
  最後の値のまま書かれ続ける)。
- 旧 4 欄を型に残す理由は「`export_batch_options` が無い設定 (今のリリースで保存した設定) から読み替えるため」
  だけ。`build_settings_from_db` は未知の欄を無視するので、欄を消しても読み込みは壊れない。ただし読み替えの
  元が無くなるので残す。
- 読み替え表:

| 旧 | 新 |
| --- | --- |
| `CaptureFormat::Png` | `kind: Png` |
| `Jpeg95` / `Jpeg85` / `Jpeg75` | `kind: Jpeg`, `jpeg_quality: 95 / 85 / 75` |
| `ExportScale::Full` | `None` |
| `Half` / `Quarter` | `Percent(50)` / `Percent(25)` |
| `LongEdge(n)` | `LongEdge(n)`、`allow_upscale: false` |
| `export_batch_directory` (と今の初期値の決め方) | `Folder { path, keep_structure: false }` |
| `export_batch_template` | そのまま |
| — | `filter: Lanczos3`、`overwrite: Rename`、`keep_metadata: false`、`keep_file_time: false`、透かしなし |

- 今の保存先の初期値の決め方 (`export_batch_directory` が存在すればそれ、無ければ単ページの直前、
  無ければ今のフォルダ) は `Folder` の初期値にだけ使う。`export_batch_options` の `Folder` の path が
  空のときも同じ決め方で埋める。
- 旧版へ戻した場合: (1) 新しい 2 欄は旧版にとって未知の欄で、旧版は未知の欄を無視して読める
  (既存の enum への値の追加ではないので、`unknown variant` の非互換にはならない)。(2) それとは別に、
  v2.6.0 以降は新しい版が保存した設定を `app_version` で検出して保存を止め、復元を案内する
  ([settings-sqlite-migration.md §6.4](settings-sqlite-migration.md))。(3) 旧版で設定を保存し直すと
  未知の 2 欄 (前回の設定・プリセット) は保持されない。これは既存の新欄と同じ扱いで、
  新しい版へ戻すと旧 4 欄から読み替え直す (プリセットは失われる)。
- 設定の持ち運び (§1.317): `export_batch_options` は既存の `export_batch_*` と同じく
  「環境設定外で管理する状態」として**除く**。`export_batch_presets` も、保存先・透かし画像の
  PC 固有のパスを含むので**除く** (`settings_transfer.rs` の分類表に足す)。

## 6. ダイアログ

### 6.1 構成

```
┌ 一括エクスポート ─────────────────────────── × ┐
│ 12 件を書き出します (対象外 2 件)                 │  ← 固定 (見出し)
│ プリセット [ (選ぶ) ▼ ] [保存...] [削除]          │  ← 固定 (段 C)
├──────────────────────────────────┤
│ ▼ 出力先とファイル名                            │  ↑
│   ◉ フォルダ [............] [変更...]           │  │
│      ☐ 元のフォルダ構造を保つ                   │  │
│   ○ 元と同じフォルダ  サブフォルダ [....]      │  │
│   ファイル名 [<filename>      ]                 │  │  ScrollArea
│   <filename> <dirname> <num> <num:N> <ext> …   │  │  (縦)
│   例: IMG_0001.jpg                              │  │
│   同じ名前があるとき ◉連番 ○スキップ ○上書き   │  │
│ ▼ 形式                                          │  │
│   [JPEG ▼] 品質 [95]  …                         │  │
│   ☐ 元の情報 (EXIF・XMP・AI プロンプト・色) を残す │  │
│   ☐ 元の更新日時にする                          │  │
│ ▼ サイズ                                        │  │
│   [長辺 ▼] [2048] px  ☐ 拡大する  方式 [Lanczos ▼] │  │
│ ▼ 透かし (段 B)                                 │  ↓
├──────────────────────────────────┤
│ [書き出す] [キャンセル]          エラー文        │  ← 固定 (操作行)
└──────────────────────────────────┘
```

- 見出し 2 行と操作行は ScrollArea の外。本文だけを縦 ScrollArea
  (`auto_shrink([false, true])`) に入れる。
- 本文の最大高は `ctx.content_rect()` から、枠・見出し・操作行の**実測の高さ**と画面余白を引いて
  決める (固定の本文高・一律の大きな控除を使わない)。`resizable(false)` のままにし、幅は約 520pt。
- 節は `CollapsingHeader` にしない (閉じた節の設定が効いていることに気付けないため)。見出しラベルだけ置く。
- `default_pos()` を使い `anchor()` を使わない。ドラッグ移動・× は今と同じ。
- テキスト欄 (保存先・サブフォルダ・ファイル名・透かしの文字・ロゴのパス・プリセット名) はすべて
  `crate::ime_focus` の helper を通す。Esc は今と同じく閉じる。
- **Enter の持ち主は 1 つ**: Enter は描画の前に `dialog_enter_pressed` で 1 回だけ取り、**候補**として持つ。
  描画の前の状態 (フォーカスのある部品、popup が開いているか) も覚える。描画の後、描画中に起きたこと
  (クリック・値の変更・フォーカスの移動・popup の開閉) と突き合わせ、そのフレームで実行する操作を
  次の順で**1 つだけ**決める。
  - 用語: **テキスト欄の確定** = 描画の前にその単一行テキスト欄にフォーカスがあり、描画中にその欄の
    `lost_focus()` が立ち、Enter の候補があり、描画中に**他の部品がフォーカスを得ていない**こと
    (egui の単一行 TextEdit は Enter でフォーカスを手放すので、描画の後のフォーカスは無くなる。
    クリックで別の欄へ移った場合は、その別の欄がフォーカスを得るので確定にならない)。
  1. 描画中に部品が操作された (ボタン・チェック・ラジオ・ComboBox の項目がクリックされた、または
     Enter / Space で押された。「書き出す」「保存」ボタン自身もここに入り、そのボタンの操作として実行する)、
     描画の前か後に popup が開いている、または他の部品がフォーカスを得た → **その部品の操作だけ**。
     汎用の Enter (書き出し・プリセットの保存) は実行しない。
  2. プリセット名の欄の確定 → **プリセットの保存だけ** (§8)。ロゴのパスの欄の確定 → **ロゴの確認だけ**
     (§7.4。入力したパスの結果を見てから書き出してもらうため、書き出しは始めない)。
  3. 保存先・サブフォルダ・ファイル名・透かしの文字のいずれかの欄の確定、または描画の前も後も
     フォーカスが無い → 今と同じく「書き出す」(開始できる状態のときだけ)。
  4. 上のどれにも当たらない (ボタン等にフォーカスがあるだけで操作は起きていない、など) → 何もしない。
  今は Enter を無条件で開始に使っており、「変更...」ボタンにフォーカスがあるとフォルダ選択と書き出しが
  両方動き得る。これも 1 の規則で直る。
- ComboBox は `dark_popup_style` 等の既存 helper の配色に従い、popup 内に ScrollArea を置く場合は
  wheel を消費する (coding-conventions の規則)。文字色は `ui.visuals()` の値を使う。今の
  エラー表示の固定色 `Color32::from_rgb(255, 140, 140)` は `error_fg_color` に直す (触るついで)。
- 表示されるかどうかの登録は今の `export_batch_dialog.is_some()` のまま (準備中も描画する)。
- 選択に応じて出す欄を変える (品質は JPEG/WebP のときだけ、代わりの形式は「元と同じ形式」のときだけ、
  サブフォルダは「元と同じフォルダ」のときだけ、構造の維持は「フォルダ」のときだけ)。

## 7. 透かし (段 B)

### 7.1 選択肢

```rust
struct BatchWatermark {
    enabled: bool,                // 既定 false
    kind: WatermarkKind,          // Text / Image
    text: String,
    text_color: [u8; 3],          // 既定 白
    text_outline: bool,           // 既定 true (黒の縁取り)
    text_size_percent: u32,       // 1..=50、既定 4 (文字の高さ = 出力の短辺に対する %)
    image_path: Option<PathBuf>,
    image_size: ImageWatermarkSize, // 既定 PercentOfWidth(20)
    anchor: WatermarkAnchor,      // 9 か所 (左上〜右下)。既定 右下
    margin_percent: u32,          // 0..=20、既定 2
    opacity_percent: u32,         // 0..=100、既定 60 (文字・画像で共通)
}
enum ImageWatermarkSize {
    PercentOfWidth(u32),          // 1..=100。ロゴの幅 = 出力の幅 × %
    Original,                     // ロゴの実寸 (画素数のまま)
}
```

- 文字と画像は 1 つだけ (両方同時には付けない)。
- **文字の大きさ**: 文字の高さ (`size_px`) を出力画像の短辺に対する %。
- **画像 (ロゴ) の大きさ** (利用者要望 2026-11-25、作者のロゴを画像で入れる用途): 2 つから選ぶ。
  - 「出力の幅に対する割合」(既定 20%): ロゴの幅 = 出力の幅 × %、高さは縦横比から。出力のサイズが
    ばらばらでも、見た目の割合がそろう。
  - 「実寸」: ロゴの画素数のまま重ねる (拡大・縮小しない)。決まったサイズで書き出すときに、ロゴを
    くっきり出したい用途。
  - どちらでも、ロゴが出力から余白を引いた内側に収まらないときは、収まるまで縦横比を保って縮める (拡大はしない)。
- **余白**: 出力画像の短辺に対する % (0〜20、既定 2)。位置は 9 か所の基準点から、余白だけ内側。
  中央の列・行の基準点では、その方向の余白は使わない (真ん中に置く)。
- タイル (敷き詰め)・回転・影・フォントの選択は入れない (§13 Q4)。

**ロゴの画像の形式** (ファイル選択のフィルタと、worker のデコード):

| 形式 | 透過 |
| --- | --- |
| PNG | アルファをそのまま使う (透過のあるロゴの推奨形式) |
| WebP | アルファをそのまま使う |
| JPEG | 透過なし (四角い不透明の画像として重なる)。EXIF の向きは反映する |
| BMP | 32bit のアルファがあれば使う、無ければ不透明 |
| GIF | 透過色を使う。アニメーションは 1 枚目だけ |

- デコードは `image` crate (今の依存で、この 5 形式を読める) で `RgbaImage` (straight alpha) にする。
  表示用の `egui::ColorImage` (premultiplied) を通さない (往復の丸めで縁の半透明が変わるため)。
- SVG・PSD・HEIC などは選べない (ファイル選択のフィルタに出さない。手で入れたパスの拡張子が表に無ければ
  §7.4 の確認で「この形式は透かしに使えません」)。

**ロゴの画像のパスとプリセット**: `image_path` は `BatchExportOptions` の一部なので、前回の設定と
プリセット (§8) に入る。パスは書いたとおりに保存する (相対パスにしない)。見つからないときの知らせ方は §7.4。

### 7.2 合成の順番

```
デコード → 保存済み編集 (補正・消しゴム・補正レイヤー・隠蔽・AI・表示用補正・注釈・回転・切り取り)
        → リサイズ → 透かし → エンコード (JPEG はここで背景合成)
```

- 透かしは**全件に同じもの**を、各画像の保存済み編集とリサイズの**後**に重ねる (§1.362 の決定)。
- リサイズの後にする理由: 透かしの大きさを出力寸法に対して決めるので、どのサイズで書き出しても
  文字が同じ割合・同じ鮮明さになる。リサイズの前に焼くと縮小で文字がつぶれる。
- 焼き込みの段 (`bake_stage_export_batch`) に関係なく掛ける (透かしは書き出しの段であり、編集ではない)。
- 合成は straight alpha の src-over (`comic_overlay::composite_overlay_over` と同じ流儀) で、
  **不透明度はロゴ・文字の元のアルファに掛ける**。透過のある出力 (PNG・WebP) でも同じ式。
  画素ごとに (値は 0〜1 に正規化、`o` = 不透明度 / 100):

  ```
  a_w   = a_logo × o                      // ロゴの透明な所 (a_logo = 0) は 0 のまま、半透明の縁も比率を保つ
  a_out = a_w + a_base × (1 − a_w)
  C_out = (C_w × a_w + C_base × a_base × (1 − a_w)) / a_out   (a_out = 0 なら C_out = 0)
  ```

  出力の下地が不透明 (`a_base = 1`) なら `C_out = C_w × a_w + C_base × (1 − a_w)`。透過のあるロゴは、
  透明な部分は下地がそのまま見え、不透明な部分だけが不透明度の割合で重なる。不透明度 100% はロゴの
  アルファどおり、0% は透かし無しと同じ出力になる。文字も、縁取りを含めて描いた RGBA に同じ式を使う。
- **画素の持ち方 (透かしの段から保存まで straight RGBA)**: 表示用の `egui::ColorImage` は premultiplied
  (`Color32`) なので、透かしを重ねた後に `ColorImage` へ戻すと、透明に近い画素の色が丸めで変わる
  (例: 透明な下地にロゴの画素 `(100, 0, 0, 16)` を重ねると赤が約 96 になる)。そこで:
  - 保存の入口を straight RGBA (`&[u8]` + 幅・高さ) を受ける関数 (`encode_rgba_with_metadata` など) に
    一本化し、今の `ColorImage` を受ける入口は「今と同じ `color_image_to_rgba` で変換してから呼ぶラッパー」にする。
    今の JPEG / PNG / WebP のエンコードはどれも先頭で `color_image_to_rgba` しているので、透かしが無い経路
    (単ページ・一括とも) の出力バイトは変わらない。メタデータの転記 (§3.6) と縮小画像の検出 (§3.7) は
    straight RGBA の入口の側に置き、両方の入口で共有する。
  - 一括で透かしが有効な項目は、リサイズ後の `ColorImage` を `color_image_to_rgba` で 1 回 straight RGBA にし、
    その上で透かしを合成して、straight RGBA の入口へ渡す。透かしが無い項目は今と同じく `ColorImage` の入口へ渡す。
  - `comic_overlay::composite_overlay_over` は `ColorImage` を返すので、透かしの合成には使わない
    (同じ式を straight RGBA に対して書いた関数を使う)。

### 7.3 描画

- 文字: 注釈の文字描画 (comic-core の `TextBlock`、縁取りは `outline`) を使う。フォントは注釈の既定
  フォント (`comic_overlay::load_comic_fonts`、Yu Gothic 等) を **worker が開始時に 1 回**読む。
  読めなければ全件を「透かしのフォントを読めません」の失敗にして終える。
  文字の外接矩形を測り、基準点へ置く。複数行は入れない (1 行)。
- 画像: worker が開始時に 1 回デコードして `RgbaImage` (straight alpha) にし、項目ごとに目標寸法へ縮小する
  (同じ寸法の出力が続くときは前の縮小結果を使う)。縮小は**アルファで重み付けして** (fast_image_resize の
  `mul_div_alpha` を有効にして) 行い、透明な部分の色が縁へにじんで暗い/明るい輪郭が出ないようにする
  (本体のリサイズ `resize_rgba8_exact` の設定は変えない。ロゴ用に設定を明示した関数を使う)。
  リサンプル方式は Lanczos3 固定。「実寸」で収まる場合は縮小しない。
  ファイルを読めない・デコードできないときは、どの項目も書かずに全件を同じ理由で失敗にして終える
  (§4.2 の開始時の 3)。

### 7.4 ロゴの画像が見つからないときの知らせ方 (書き出しの前)

プリセットや前回の設定に入ったパスは、ファイルを移動・削除すると見つからなくなる。書き出しの前に
ダイアログで知らせる。UI スレッドではファイルを確かめない。

- **確認**: 透かしが ON・種類が画像で `image_path` が決まったとき (ダイアログを開いたとき、ファイルを選んだとき、
  パスを入力し終えたとき、プリセットを呼び出したとき) に、短命のスレッドで `std::fs::metadata(path)` を
  1 回呼び、「ある (ファイル)」「見つからない」「形式が使えない (拡張子が §7.1 の表に無い)」を channel で返す。
  拡張子の判定はスレッドを待たずに UI でしてよい (文字列だけ)。
- **状態**: ダイアログの状態 (`ExportBatchDialogState`) に `logo_check: { path, result }` を 1 つだけ持つ。
  `result` は `Pending(Receiver)` / `Found` / `Missing` / `Unsupported`。**確認のたびに専用の channel を作り、
  その receiver を `Pending` が持つ**。新しい確認を始める (パスが同じでも、選び直し・プリセットの呼び出しなど)
  ときは `logo_check` ごと置き換え、前の receiver を捨てる。前の確認のスレッドは送り先が無くなるので、
  `A → B → A` と選び直しても、最初の A の遅い結果が今の確認に混ざらない。
  ダイアログを閉じたら破棄し、スレッドは待たない。
- **表示**: `Missing` / `Unsupported` のときは、パスの欄の下にエラー色 (`error_fg_color`) で
  「透かしの画像が見つかりません: <パス>」/「この形式は透かしに使えません」を出し、**「書き出す」を押せなくする**
  (透かしを OFF にするか、画像を選び直せば押せる)。`Pending` の間は押せる (確認の完了を待たせない)。
- **最後の確認は worker**: ダイアログで `Found` でも、書き出しを始めたときに worker が実際に読む (§4.2 の開始時の 3)。
  その間に消された場合は、どの項目も書かずに「透かしの画像を読めません: <パス>」の失敗で終える
  (まれな失敗の割り切り)。
- これは書き出しの前の案内で、§3.7 の警告 (書き出しの後) とは別の表示。

## 8. プリセット (段 C)

```rust
struct BatchExportPreset { name: String, options: BatchExportOptions }
```

- 保存: 「保存...」でダイアログ上部の行が名前の入力欄に変わる。Enter か「保存」で今のダイアログの値
  (`BatchExportOptions` 全部: 形式・品質・リサイズ・出力先・名前・上書き・元の情報・日時・透かし) を保存する。
  名前は前後の空白を除き 1〜40 文字。同じ名前があれば置き換える (ボタンの表示を「上書き保存」に変える)。
  一覧の上限は 50 件。
- 呼び出し: ComboBox で選ぶと、その値でダイアログの値を**置き換える**。プリセットとダイアログの値の
  結び付き (変更済みの印・自動保存) は持たない。書き出すと、その時点の値が「前回の設定」になる。
- 削除: 選んでいるプリセットを「削除」で消す。確認は出さない (プリセットは設定の組であり、
  画像や編集は失われない)。
- 保存は、利用者が保存・削除を押した時点で `Settings::save_checked()` を呼ぶ (UI スレッドで同期)。
  これは今の一括エクスポートの開始時の保存、環境設定の OK など、利用者の明示操作で設定を保存する
  既存の経路 (`settings.save()` の呼び出しは約 230 か所) と同じ扱いで、新しい種類の I/O ではない。
  プリセット専用の書き込み worker を作ると、同じ `settings.db` を書く経路が 2 本になり、
  順序の食い違いが生まれるので作らない。`save_checked()` が失敗を返したら
  「プリセットを保存できませんでした」を通知し、ログに残す (メモリ上の一覧はそのまま。次に設定が
  保存されたときに一緒に書かれる)。保存は `SETTINGS_WRITE_GATE` で直列化される。
- プリセットの並びは保存した順。並べ替え・名前の変更・書き出し/読み込み・メニューからの直接実行は範囲外。

## 9. 簡素化と、まれな失敗の割り切り

CLAUDE.md「設計の簡素化」に沿って検討した結果:

- **採用: 選択肢は開始時に 1 回だけ worker へ渡す**。実行中にダイアログは無く (今と同じく進捗ダイアログ
  だけ)、選択肢が途中で変わる組み合わせが無い。
- **採用: 上書きの「確認する」を作らない**。worker から UI へ 1 件ごとに尋ねると、待機中の取消・閉じる・
  別の書き出しとの組み合わせが生まれる。方針は開始前に 1 つ選ぶ。
- **採用: 同一実行内の衝突は常に連番**。方針ごとに同一実行内の扱いを変えない。
- **採用: 元の情報は形式が同じときだけ**。形式をまたぐ転記 (EXIF を PNG へ等) を作らない。
- **採用: プリセットは値の置き換えだけ**。変更済みの追跡・プリセットとの同期を持たない。
- **採用: 構造の維持の基点は自動 (共通の祖先) だけ**。手動の基点の欄を作らない。
- **採用: ロゴの確認はダイアログの状態 1 つ (今のパスの結果だけ)**。パスが変わったら前の結果を捨てる。
  確認中は書き出しを止めない (待たせる状態を作らない)。最後の確認は worker が実際に読むことで行う。
- **採用: 透かしの素材 (フォント・画像) は開始時に 1 回読む**。項目ごとに読み直さない。読めなければ
  全体を失敗にする (一部だけ透かしの無い出力を作らない)。
- **採用しない: 1 件ごとのモーダル化の追加**。一括エクスポートのダイアログは既に modal 相当
  (`common_modal_dialog_open`)、書き出し中は今の進捗ダイアログのままで足りる。

まれな失敗は割り切り (ログ + 通知): 書き込み・置き換え・更新日時の設定・フォルダ作成の失敗は、
その項目のエラーとして進捗ダイアログの一覧と mimageviewer.log に出し、次の項目へ進む (今と同じ)。
再試行・失敗の種類分けはしない。置き換えの途中で mIV が強制終了した場合に残る一時ファイル
(`.miv-tmp-*`) は掃除しない (次回の同じ書き出しでは別名の一時ファイルを使う)。

## 10. テスト

- **既定の挙動が変わらないこと**: `from_legacy` で作った選択肢 (旧 4 欄の全組み合わせ: PNG/JPEG95/85/75 ×
  そのまま/1/2/1/4/長辺) で書いた出力が、今の `write_composited_page` の出力と**バイト一致**し、
  名前も一致する (同じ入力画像・同じ編集 snapshot)。一括の呼び出し先を新しい関数へ切り替える前に
  このテストを書き、比較の基準 (期待バイト列のハッシュ) を固定する。
- 選択肢の単体: 寸法の計算 (各モード × 拡大の可否 × 縦長/横長/正方形、Percent(50/25) が今の
  Half/Quarter と同値)、形式の決定 (拡張子の表、PDF → 代わりの形式)、置換子 (`<num:N>`・`<ext>`・
  未知の置換子が残る)、出力先 (元と同じフォルダ、サブフォルダの正規化、共通の祖先、ドライブ違い)。
- worker:
  - `Skip` は既存ファイルの項目をデコードしない (デコード回数の計測で確かめる)。
  - `Replace` は既存ファイルを置き換え、今回の元ファイル (別名・大小文字違いのパスを含む) は置き換えない。
  - 同一実行内の衝突は `Replace` / `Skip` でも連番。別フォルダの `A.jpg` と `a.jpg`、出力先の表記違い
    (`C:\out` と `c:\OUT\`)、junction 経由の別名 (`C:\real\a.png` と、`C:\real` を指す `C:\alias` の
    `C:\alias\b.png` を「元と同じフォルダ + サブフォルダ」・固定名で出す) でも、先の出力を置き換え・スキップしない。
    8.3 形式の短い名前を持つボリュームで、先の出力の短い名前と同じ名前に後の項目が落ちても、先の出力を
    置き換え・スキップしない (短い名前が作られない環境ではテストを飛ばす)。
  - WebP で 16383px を超える項目はその項目だけ失敗し、worker は止まらず次へ進む (panic しない)。
  - 完了処理: §4.4 の通知の表の各行、成功パスの先頭が別フォルダでも今の表示先の更新が 1 回だけ要求される。
  - 取消が合成の途中で効く (遅い消しゴム runner を注入し、取消後に書き込みが無いこと)。
  - `keep_metadata`: 3 形式それぞれで §3.6 の表のものが残り、EXIF の Orientation が 1、IFD1 の縮小画像が
    消える (IFD0 の次 IFD が 0、元の縮小画像のバイトが残らない)。`GRAY` / CMYK の ICC は付かない。
    形式違いでは何も残らない。読めない EXIF は落とし、その項目は成功する。
  - 単ページの出力が変わらない: `SaveOptions` の新しい欄が既定 OFF のとき、JPEG / PNG / WebP の
    転記結果が今と同じバイト列 (WebP の `encode_simple` への置き換えを含む)。
  - `keep_file_time`: 出力の更新日時が元と一致する (ZIP/PDF は書庫の日時)。
  - 縮小画像の警告 (§3.7): `xmpGImg` の名前空間を持つ XMP で `ThumbnailNotice` が出て、XMP は書き直されて
    いない。対象: JPEG 標準 XMP、JPEG 拡張 XMP で名前空間が断片の境目をまたぐもの、別の GUID の断片が
    offset の間に混ざるもの、PNG の tEXt / zTXt / 圧縮 iTXt / 非圧縮 iTXt、複数のテキストチャンクの後ろの
    ほうにだけ XMP があるもの、WebP。展開が 16 MiB を超える・壊れた圧縮の XMP チャンクは「調べられない」で
    警告になる。複数の圧縮 XMP チャンクで合計 32 MiB に達したら、残りを展開せずに「調べられない」で警告になる。
    書き出し中に警告が届いても、終了までは今の進捗ダイアログ (キャンセルできる) のまま。
    名前空間の無い XMP では出ない。MakerNote は 5 種類の保存済み編集がある項目だけ出て、
    無い項目では出ない。「元の情報を残す」が OFF・形式違いの項目では出ない。
  - 完了処理: 警告があると `AllDone` でも `Cancelled` でも進捗ダイアログが残り、警告の枠と一覧が出る。
    `Cancelled` を受けたフレームだけでなく、**次の poll (worker 終了による channel 切断) の後も**画面と警告が
    残り、「worker が中断されました」が出ない。「閉じる」・× で pending が破棄される。一覧の更新の要求は 1 回だけ。
    警告が無い取消は今と同じくトーストで閉じる。
  - 警告の画面の配置を 1093×614 と UI 倍率 200% で検査する: 警告多数 + 失敗多数 + 長いファイル名が同時にあっても、
    固定の見出しと「閉じる」が見えて押せ、本文が最後の行まで届く。
  - 透かし (段 B): 9 か所の位置・余白、文字の大きさの割合、ロゴの「出力の幅に対する割合」と「実寸」、
    出力より大きいロゴが内側に収まるまで縮むこと、不透明度 0 で出力が透かし無しと一致、
    透かし画像を読めないと全件失敗で何も書かない。
  - ロゴの透過 (§7.2 の式): アルファのある PNG ロゴで、`a_logo = 0` の画素は下地のまま、`a_logo = 1` の画素は
    `C_w × o + C_base × (1 − o)`、半透明の画素は式どおり (許容誤差 ±1)。透過のある出力 (PNG) の下地が
    半透明・透明のときも式どおり。WebP・GIF (透過色)・BMP (32bit) のロゴでアルファが使われ、JPEG のロゴは不透明。
  - ロゴの縮小で、透明の縁に囲まれた不透明の色が縮小後に暗く/明るくにじまない (アルファで重み付けした縮小)。
  - ロゴの確認 (§7.4): 見つからないパス・使えない拡張子で「書き出す」が押せず、エラー文が出る。
    プリセットの呼び出しで確認が走る。古いパスの結果が新しいパスに使われない。`A → B → A` と選び直したとき、
    最初の A の遅い結果 (送り先の無い channel) が採用されない。確認中は押せる。ロゴのパスの欄で Enter を
    押すと確認だけが走り、書き出しは始まらない。
  - ロゴの上書き保護: `Replace` で、ロゴの画像と同じ実体 (別名・大小文字違いを含む) に落ちる出力は
    「元ファイルは上書きしません」の失敗になり、ロゴは変わらない。
  - straight RGBA の保存経路: 透明な下地 (PNG) にロゴの画素 `(100, 0, 0, 16)` を実寸・不透明度 100% で重ねた出力を
    **書いた PNG を読み直して**確かめ、赤が 100 のまま (±1)。透かしの無い経路は単ページ・一括とも、
    入口の一本化の前後で出力バイトが同じ。
- 設定: `export_batch_options` が無い設定から旧 4 欄を読み替える、ある設定では旧 4 欄を無視する、
  書き出し開始で旧 4 欄の値を更新しない、`settings_transfer` の分類漏れ検査が通る。
- UI: §6.2 の配置検査とスナップショット、Enter の振り分け (§6.1 の 1〜4 がそれぞれ 1 つだけ実行される。
  ボタン・ComboBox にフォーカスがあるときは書き出さない、実際の単一行 TextEdit のプリセット名の欄に
  Enter を送ると保存 1 回・書き出し 0 回、ファイル名の欄に Enter を送ると書き出し 1 回、
  同じフレームに「プリセット名の欄のクリック」と Enter が届いたときは書き出さない、
  「書き出す」ボタンにフォーカスがあって Enter なら書き出しが 1 回だけ)、
  プリセットの保存・置き換え・呼び出し・削除と、保存失敗時の通知 (段 C)。
