# ブリーフ: 初回オーバーレイヘルプ (中央タップの発見可能性)

対象: v2.13.0 Step 3d。実装 = Codex Sol / レビュー・検収 = ClaudeCode。
正本: [docs/touch-support-plan.md](touch-support-plan.md) §5.5「発見可能性をどう担保するか」/ §5.14-8。

前提 (完了・コミット済み・実機確認済み): Phase 1 一式、Phase 2 の一覧スクロールと
ピンチ列数変更、Step 3b の左右パネルハンドル (`2bcd4204` まで)。

**範囲は静止画 / 本のフルスクリーンのみ**。動画・音楽は Phase 3。

---

## 1. なぜ要るか

中央タップは**不可視の領域**なので、それ単独では気づけない。
タブレットには **Esc キーが無い**ので、気づけない利用者は
「フルスクリーンに入ったら出られない」状態になる。これが今回の安全網。

---

## 2. 表示条件 — 「1 回だけ」ではなく「中央タップを一度使うまで」

§5.5 のとおり:

> **中央タップでクロームを一度表示できたら「学習済み」**として、以後は出さない。
> それまでは開くたびに出す。

- 大多数の利用者にとっては**文字どおり 1 回**で終わる
- 見逃した人にだけもう一度出るので、「閉じられない」への安全網が残る
- **3 ジェスチャ全部の実行は要求しない**。安全上必要なのは中央タップだけ
- **マウス・キーで開いた場合は出さない**。既存挙動を一切変えないこと

### 2.1 「学習済み」の永続化

必要なのは**真偽値 1 個**だけ (「中央タップでクロームを一度出したか」)。
利用者向け設定ではないので、環境設定 UI には出さないこと (§5.1-6 の無設定方針)。

⚠ **設定 DB はリリース済み**なので、フィールド追加は既存の後方互換パターンに従うこと
(CLAUDE.md「永続データ・スキーマ変更時の判断」)。既存フィールド追加の実装例に倣い、
**旧 DB から読んだときに既定値へフォールバックし、DB family を変えない**こと。
2026-07-19 に unknown variant を `Corrupted` と誤分類して main / bak1〜bak10 を
quarantine した事故があるので、ここは慎重に。

### 2.2 「タッチで開いた」をどう判定するか

マウス・キーで開いたときに出さないための判定が要る。次のどちらかを選び、
**選んだ理由を報告すること**:

- (a) フルスクリーンを開いた要求がタッチ由来かを記録して伝える
- (b) フルスクリーン中に**最初のタッチ接点が発生した時点**で出す
  (マウス利用者はタッチしないので原理的に出ない)

(b) は「タッチで開いた」判定が不要で誤検出しない代わりに、最初の 1 タップが
ヘルプ表示に消費される。(a) は素直だが provenance の配線が要る。
**どちらでも構わないので、実装が単純で誤検出しない方を選ぶこと。**

## 3. 内容

単なるテキスト箇条書きではなく、**中央領域の輪郭・左右領域を半透明で図示**する。
「クロームがある」ではなく「**どこを叩けば何が起きるか**」を伝える。

| 領域 | 説明 |
| --- | --- |
| 中央 | メニュー (上下バーと左右のパネルハンドル) を表示 |
| 左右 | ページ送り |

⚠ **エッジスワイプは書かないこと。** plan §5.5 の内容表にはまだ
「端からスワイプ = 操作パネル」が残っているが、**Windows 11 では四辺すべて OS 予約**
だったため `2bcd4204` で実装ごと削除済み。**plan の内容表もこのステップで修正すること**
(左右パネルへは「中央タップ → ハンドル」で到達する)。

### 3.1 消し方

**オーバーレイをタップすること自体が中央タップになる**ので、
消し方を別途覚える必要がない。

- オーバーレイ表示中は、**画面のどこをタップしてもクローム表示 + 学習済み**にする。
  左右をタップしてもページ送りにしないこと (最初の 1 タップでページが飛ぶと驚く)
- 表示中はページ送り・ピンチなど他のジェスチャを走らせないこと

### 3.2 スケーリングへの導線 (§5.14-8)

オーバーレイの隅に、**従属的な 1 行**を添える:

> UI が小さい場合はメニューの「スケーリング」から変更できます

- **強制しない**。「タッチには 150% 以上が必須」とは書かない
- ジェスチャの図示より**視覚的に従属させる** (小さく、下部に置く)
- **UI 倍率が 100% のときだけ出す**。既に 150% 以上で使っている利用者には不要。
  これは永続設定の静的な参照であって実行時状態による分岐ではないので、決定性方針に反しない

## 4. 出さない場面

- マウス / キーボードだけで操作しているとき
- 学習済みのとき
- **`MIV_DISABLE_TOUCH_GESTURES=1` のとき**
- 編集モード / 解析モード / 範囲選択キャプチャなど、
  タッチのタップ処理自体が無効化されている場面 (既存の `touch_input_enabled` と揃える)
- 動画・音楽 (Phase 3)

---

## 5. 忘れた人の再表示手段

既存のコンテキストヘルプ **`HelpShowContextShortcuts`** ([src/keymap.rs:1365](../src/keymap.rs))
に **「タッチ操作」欄を追加**する。現在の画面で有効な操作だけを出せるので、
通常のヘルプページより見つけやすい。**新しい機構は作らないこと。**

キーボードのないタブレットでは押せないが、これは
「一度覚えた人が思い出す」ための経路なので問題ない (安全網は §2 の再表示が担う)。

---

## 6. マウス無影響 (§5.15)

- マウス / キーボードだけの操作で**オーバーレイが出ないこと**
- 既存のフルスクリーン描画・入力に変化がないこと
- `MIV_DISABLE_TOUCH_GESTURES=1` で現行挙動へ戻ること

---

## 7. テスト

**純関数 unit** で:

- 表示判定 (学習済み / 未学習 × タッチ有無 × キルスイッチ × 各種モード)
- オーバーレイ表示中のタップが**クローム表示 + 学習済みマーク**になり、
  **ページ送りにならない**こと
- 学習済みフラグが立った後は開き直しても出ないこと
- スケーリング 1 行が **UI 倍率 100% のときだけ**出ること
- 図示矩形が中央タップ領域の定義 (`classify_tap` の中央矩形) と**一致**すること。
  図と実際の当たり判定がずれていると、教えた内容が嘘になる

**永続化のテスト**:

- 旧 DB (このフィールドが無い) から読んだとき既定値になり、**quarantine されないこと**
- 保存して読み直すと維持されること

**kittest snapshot**:

- オーバーレイ表示 (UI 倍率 100% = スケーリング 1 行あり)
- 学習済みで非表示

スナップショット更新時は PNG を目視確認してからコミットすること。
