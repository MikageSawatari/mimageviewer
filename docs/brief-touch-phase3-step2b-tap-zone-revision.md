## 1. 実機フィードバックと、仕様を変える理由

利用者報告 (2026-08-08、Step 2 の実機確認):

> シングルタップでもシークしているように見えます。シングルタップでシークのほうが
> 動作が揃って自然でしょうか。**中央タップで HUD 切り替え、左右タップでシーク、
> 領域は静止画と同等**とするのが使いやすそうです。
>
> HUD をだした状態でダブルタップしたら、**HUD が見えたままのほうが自然**だと思います
> (いま どこを見ているか分かるので)。

「シングルタップでシークしている」のは**バグではなく、Step 2 で入れた累積の副作用**である。
同じ側を連打すると 1 回目だけ HUD トグル、2 回目以降は毎回シークするため、
**タップの意味が「どこを叩いたか」ではなく「いつ叩いたか」で決まる**状態になっていた。

これは §5.10 の規則 (見えない cross-frame state で意味を変えない) に照らしても筋が悪い。
**タップの意味は位置だけで決まるべき**である。

### 撤回する旧仕様

plan §5「動画・音楽のタップ割り当て」の次の 2 行を**撤回**する
(2026-08-06 の机上判断を、2026-08-08 の実機判断で更新する。**削除せず、撤回として記録する**):

- 「単一タップは画面全体で HUD 表示」
- 「左右の『ダブル』タップで相対シーク。単一タップにシークを載せると誤操作しやすい」

撤回の理由: 中央 / 左右にゾーンが分かれていれば、静止画のページ送りと同じ確実さで狙える。
時間窓に依存する意味の切り替えのほうが、実機では誤操作に感じられた。

## 2. 新しい仕様

### 2.1 タップ割り当て — 静止画と同じ領域、同じ考え方

| 領域 | 単発タップ |
| --- | --- |
| **中央** (`center_tap_rect`、静止画と同一) | **HUD 表示 / 非表示のトグル** |
| **左** | **5 秒戻る** |
| **右** | **5 秒進む** |
| HUD の当たり判定内 | 従来どおりボタン操作 (Step 1 の widget passthrough) |

- **領域は静止画と完全に同一**。`center_tap_rect` / `classify_tap` をそのまま使い、
  動画専用の矩形を作らない
- **左右は物理的な画面の側**。読み方向 (RTL / LTR) で反転しない (時間軸は反転しないため)
- シーク量は **±5 秒** (plan §5.14-9)。既存の
  `App::native_video_seek_relative_with_hint` を通す (Step 2 で配線済み)

### 2.2 ダブルタップ機構を削除する

`DoubleTapRun`、時間窓 (`VIDEO_DOUBLE_TAP_MAX_INTERVAL_MS`)、距離しきい値
(`VIDEO_DOUBLE_TAP_MAX_DISTANCE_POINTS`)、および関連テストを**削除する**。

**無効化して残すのではなく消すこと。** 位置だけで意味が決まる設計になれば、
この state はもう存在理由が無い。残すと次の読者が「いつ使われるのか」を調べることになる。

### 2.3 シークはクロームの状態を変えない

**左右タップはクローム latch に一切触れない。**

- HUD が出ていれば**出たまま**シークする (利用者の指摘に直接対応)
- HUD が隠れていれば**隠れたまま**シークする。**シークのために HUD を強制表示しない**

強制表示しない理由: 静止画の左右タップ (ページ送り) もクロームを出さない。
mIV の「閲覧中はクロームを隠す」方針と揃える。位置を確認したいときは中央タップで出せる。

## 3. 初回オーバーレイヘルプを静止画と分ける

利用者判断 (2026-08-08):

> 静止画と動画では表示される内容が違うので、初回表示の判定は別々にすべきではないでしょうか。

**Step 2 の「学習フラグを共有する」判断を撤回する。**

左右タップの意味が静止画 (ページ送り) と動画 (シーク) で**違う**以上、
片方で学習した人はもう片方を教わっていない。§2 の変更でこの差はさらに大きくなった。

### 3.1 フラグを 2 つに分ける

- 静止画 / 本用と、動画用の **2 つの独立した bool** にする
- **どちらも v2.13.0 で追加され、まだ出荷していない**
  (CLAUDE.md「永続データ・スキーマ変更時の判断」)。したがって
  **マイグレーション不要**で、既存の `touch_center_chrome_learned` を
  対称な名前へ改名してよい (例: 静止画用 / 動画用が一目で分かる命名)。
  改名した場合は**未リリースにつき移行コード不要である旨をコミットメッセージに残すこと**
- `settings_kv` の加法フィールド + `#[serde(default)]` で、DB schema family は変えない
- 旧 DB の boot が `LoadedExistingDb` のままで quarantine しないことをテストする
  (Step 3d と同じ)

### 3.2 動画ヘルプの内容を新仕様へ更新する

| 行 | 内容 |
| --- | --- |
| 中央 | **中央をタップ = HUD を表示 / 非表示** |
| 左 | **左をタップ = 5 秒戻る** |
| 右 | **右をタップ = 5 秒進む** |
| 隅の 1 行 | 「UI が小さい場合はメニューの『スケーリング』から変更できます」(従属的に小さく) |

**中央矩形の輪郭と左右領域を図示すること** (静止画版と同じ考え方)。
Step 2 の動画ヘルプは「画面全体タップ」を前提にしていたので、
**中央と左右の境界が見える図に描き直す**。

表示条件・畳み方 (表示中はどこを叩いても「学習 + HUD 表示」、シークしない) は
Step 2 のままでよい。

### 3.3 コンテキストヘルプとマニュアル

- `HelpShowContextShortcuts` の動画「タッチ操作」欄を新仕様の 3 行に更新する
- `htdocs/mimageviewer/manual/video.html` の記述を更新する
  (バージョン表記を書かない / 内部用語を書かない)

## 4. 音声モードは変更しない

利用者確認 (2026-08-08):

> 音声モードにした場合、グラフ表示部分をタップでシークします。
> HUD は常時表示なのでこれはこの動作で良さそうです。

- 音楽ビューは egui 側 (`fs_music_view_active`) の既存動作で、**現状のままでよい**
- native overlay 側の `audio_only` 経路も従来どおり (`PageSide` はクローム toggle へ落ちる)
- **音楽ビューのファイルに触れないこと**

## 5. マウス無影響 (§5.15)

- presenter 上のマウス左クリック (再生 / 一時停止)、ダブルクリック、右クリック (リング) は不変
- キーボードの ← → (±5 秒) も不変
- `MIV_DISABLE_TOUCH_GESTURES=1` で現行挙動へ戻ること

## 6. テスト

Step 2 のダブルタップ系テストは**削除**し、次を固定する。

- 中央タップ → クロームトグルのみ。シークしない
- 左タップ → **−5 秒**。クローム latch が変わらないこと (出ていれば出たまま / 隠れたままなら隠れたまま)
- 右タップ → **+5 秒**。同上
- 連続タップしても、**1 回のタップにつきシークがちょうど 1 回**であること
  (累積の削除で「1 タップ 2 回シーク」が起きないことの回帰テスト)
- 読み方向を変えても左が負、右が正であること
- HUD source のタップではシークしないこと
- `audio_only` ではシークせずクロームトグルになること
- 初回ヘルプ表示中はシークしないこと
- **静止画で学習済みでも動画のヘルプが出ること**、およびその逆 (フラグ独立の回帰テスト)
- 旧 DB (両フラグ欠落) の boot が `LoadedExistingDb` で、quarantine しないこと
