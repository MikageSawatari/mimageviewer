## 1. §1.54 フォルダツリーペインの幅が読み込み中に伸び続ける

正本: バックログ §1.54 (原因は 3 段の合成として特定済み)。

**起点**: [src/ui_folder_pane.rs:301](../src/ui_folder_pane.rs) の行レイアウトで、末尾
ウィジェット用の予約幅が `trailing_width = 18.0` の固定値。実際に消費するのは
`item_spacing.x (2.0) + Spinner 幅 (= spacing.interact_size.y = 既定 18.0) = 20.0` なので、
`row.loading` の行だけ毎フレーム 2pt はみ出す。それが `ScrollArea` の
`(false, false) => inner_size.max(content_size)` と `SidePanel` の「content rect を
`PanelState` に保存する」挙動と合成されて**毎フレーム 2pt 積算するフィードバックループ**になる。
増えた幅は `settings.folder_tree_pane_width_ratio` に書き戻されるので**再起動しても太いまま**。

**直し方** (バックログの方針どおり):

1. 予約幅を実測から作る (`ui.spacing().item_spacing.x + ui.spacing().interact_size.y`)、
   または末尾を `Layout::right_to_left` の子 Ui で先に確保する。
   **マジックナンバー 18.0 をやめる**。
2. 「幅が内容から決まる」構造への保険として、ペイン本体は available_width を超えて
   確保しないことを不変条件にする。
3. 同型の「予約幅を持つ行に `ui.spinner()` を置く」箇所が他にないか確認する
   (現状は本件のみのはず。あれば報告)。

**テスト**: **loading 行を出したまま複数フレーム回してもペイン幅が変わらない**ことを
egui_kittest の状態遷移テストで固定する (1 フレームだけの検証では積算バグを捕まえられない)。

**注意**: 幅が既に太くなってしまっている利用者の設定は、この修正では戻らない。
**設定を勝手に書き換えないこと** (利用者が自分で戻せる)。この点は報告に書くこと。

## 2. §1.56 ルーペが画像の端で像を引き延ばす

正本: バックログ §1.56。**方針は (c) に決定済み** (利用者判断 2026-08-07)。

**原因**: [src/ui_fullscreen.rs:21538 付近](../src/ui_fullscreen.rs) で、サンプルする uv 矩形の
min / max を**それぞれ独立に `clamp(0.0, 1.0)`** している一方、描画先の `loupe_rect` は
`LOUPE_SIZE` の正方形で固定。端では uv 側だけが小さく / 非正方形になり、それを正方形へ
引き伸ばすので像が歪む。

**直し方 (c)**: **倍率を一定に保ったままルーペの中身がパンし、画像の外側にあたる部分は
背景色で埋める**。位置も倍率も正しく、何が起きているかが読み取れる形にする。

- 採らない案: (a) uv 窓をクランプせずスライド = 端でルーペ中心とカーソル位置がずれ、
  画素検分で嘘になる。(b) 描画先をレターボックスに縮める = 端でルーペの大きさが変わる。
  **どちらも実装してはいけない**。
- 背景色は既存のルーペ枠 / フルスクリーン背景と整合する色を使う (新しい色定数を作らない)。

**テスト**: uv → 描画先の写像を純関数へ切り出し、中央 / 左端 / 右上隅 / 画像より小さい
表示など複数条件で、**倍率 (= source px あたりの描画 px) が一定**であることと、
外側領域が背景として塗られる範囲を固定する。

## 3. §1.57 テキスト注釈の色ピッカーが、パネル外を最初にクリックすると閉じる

正本: バックログ §1.57。開発側でも再現確認済み。

**原因**: [src/ui_text.rs:2383](../src/ui_text.rs) で、キャンバス入力を無視するかどうかを
`panel_rect.contains(p) || detail_rect.contains(p)` という**手で列挙したパネル矩形との
包含判定**で決めている。egui の色ピッカーは独立した浮動 Area で、パネル外へはみ出して
開くため、はみ出した部分のクリックが「キャンバスのクリック」と判定されてキャンバス側処理が走る。

**直し方**: 矩形の列挙をやめ、**ポインタ直下に `Order::Middle` / `Foreground` の浮動レイヤが
あるかを egui に問い合わせる**判定へ寄せる。同型の前例が既にあり、CLAUDE.md「ダイアログ」節の
`App::process_scroll` が同じ考え方で背面グリッドの wheel を止めている。**矩形の列挙のままだと、
次にポップアップを増やしたときに同じバグが再発する**ので、列挙を残した上で色ピッカーの矩形を
足すだけの修正にはしないこと。

**テスト**: パネル矩形の外に浮動レイヤがある状態で、その上のクリックがキャンバスへ
渡らないこと。浮動レイヤが無いときは従来どおりキャンバスへ渡ること。
