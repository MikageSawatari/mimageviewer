## 1. 切り分け: 仕様どおりの動きか、不具合か

### 1.1 報告の条件

縦横比が約 1:1.4 の画像を見開きで表示し、指定倍率 150% では移動量 20% は問題なく 15% で「N 字 1 回ではなく繰り返しての移動」になる。
200% では 20% でも起きる (>>857 の報告。座標の逆戻りや無限ループは報告されていない)。

### 1.2 今の計算 (コード読み)

`ordered_scroll_pan_with_steps` (`src/ui_fullscreen/in_page_scroll.rs`) は、

1. 主軸 (N 字 = 縦、Z 字 = 横) を読む向きへ `表示領域[主軸] × 量` 進める。clamp 後に主軸が進み、副軸が動かなければ採る。
2. 進めなければ (主軸の端)、副軸を `表示領域[副軸] × 量` 進め、主軸を読み始めの端へ戻した 1 つの候補を作る。clamp 後に副軸が読む向きへ
   進んだときだけ採る。どちらも進まなければ動かない (端で止まる / スクロール＋ページ送りなら送る)。

「量」は、K / J とスクロール＋ページ送りのキーでは主軸・副軸とも `fullscreen_n_scroll_step_percent`。ホイールのスクロール＋ページ送りでは
主軸がホイールの量 (`continuous_reading_wheel_scroll_percent`)、副軸が `fullscreen_n_scroll_step_percent`。
**列 / 段を替える移動 (副軸) は、いつも N 字 / Z 字の移動量と同じ割合**である。

副軸の端までの残り (はみ出し) を `O`、1 回の副軸の移動を `S = 表示領域[副軸] × 量` とすると、端は clamp で止まるので、
列 (段) の数は **`1 + ceil(O / S)`** になる。最後の折り返しは残りの分だけ動く (小さいこともある)。

### 1.3 報告の条件の計算

1920×1080 の表示領域で、縦長の 2 ページを高さに合わせて見開きにし (倍率 100% で高さ 1080)、指定倍率で拡大した場合:

| 縦横比 | 倍率 | 横のはみ出し `O` | 20% (`S` = 384) | 15% (`S` = 288) |
| --- | --- | --- | --- | --- |
| 1:√2 (A 判・B 判) | 150% | 371 px (19.3%) | 列 2 = **N 字 1 回** | 列 3 (2 回折り返す) |
| 1:√2 | 200% | 1135 px (59.1%) | 列 4 | 列 5 |
| 1:1.4 | 150% | 394 px (20.5%) | 列 3 (最後の折り返しは約 10 px) | 列 3 |
| 1:1.4 | 200% | 1166 px (60.7%) | 列 5 | 列 6 |

1:√2 の行は、報告の 3 つの観測 (150%/20% は 1 回、150%/15% は繰り返し、200%/20% は繰り返し) にそのまま合う。
「繰り返しての移動」は、列替えの横移動も 15% / 20% と小さいため、前の列と 80〜85% 重なった列を何度も上から読み直す動きと読める。

### 1.4 単体テストでの確認 (座標列)

`n_scroll_report_850_tests.rs` は、上の見開き (縦横比 1:1.4 / 1:√2、ページ間 0 / 20 px、倍率 150% / 200%、量 15% / 20% / 85%、
右→左 / 左→右、キー (主軸も同じ量) / ホイール (主軸 20%)、次へ / 前へ) を読み始め (前へは読み終わり) から端まで進め、座標列を記録する。
各組み合わせで次を検査する。

- 同じ座標に二度来ない (逆戻り・ループがない)。
- 読み進める 1 回は主軸だけが読む向きへ進み、折り返しは副軸が読む向きへ進む (副軸が戻らない)。
- 折り返しは主軸の読み終わりの端からだけ起き、新しい列 / 段は主軸の読み始めの端から始まる。
- 1000 回以内に止まり、止まる位置は読み終わり (前へは読み始め) の角だけ (途中で止まらない)。
- 折り返しの回数が §1.2 の `ceil(O / S)` と一致する。

この診断の範囲: 対称な見開き・固定のページ間で、純関数 `ordered_scroll_pan_with_steps` と通常の書き込み口
(`set_fs_pan_from_input` が clamp 後の値を保つこと) を通す。実際の描画から layout を作る経路、ホイールの frame 予測・遅延適用は
通さない (いずれも同じ純関数を呼ぶことはコード読みで確認。独立設計レビュー r1 も同じ判断)。

結論 (§1.5 の結果を前提): 報告の 3 つの観測は、「列替えも読み進める量と同じ割合」という §1.826 の仕様で**説明できる**。
上の範囲では座標の逆戻り・ループ・途中停止は起きない。**報告者の画面で実際に起きている原因は未確認** (寸法も仮定)。
§1.826 の設計 (「小さい量でも同じ列を繰り返さない」) が言う「繰り返さない」は同じ座標の列のことで、大きく重なった別の列を読むことは
防いでいない。

### 1.5 テスト結果の記録

`cargo nextest run -p mimageviewer --lib -E 'test(/report_850|ordered_|asymmetric_original/)'` を実行 (run-heavy 経由):
**38 件すべて成功** (新しい 3 件 + 既存の N 字 / Z 字・非対称見開きのテスト)。§1.4 の検査は全組み合わせで満たした。

記録した座標列の要約 (次へ・キー、右→左。左→右も同じ列数。列替えの移動は表示幅に対する割合):

| 縦横比 | ページ間 | 倍率 | 15% | 20% | 85% |
| --- | --- | --- | --- | --- | --- |
| 1:√2 | 0 | 150% | 列 3 (0.15, 0.043) | **列 2** (0.193) | 列 2 (0.193) |
| 1:√2 | 0 | 200% | 列 5 | 列 4 (0.2, 0.2, 0.191) | 列 2 (0.591) |
| 1:√2 | 20 px | 150% | 列 3 | 列 3 (0.2, **0.004**) | 列 2 |
| 1:1.4 | 0 | 150% | 列 3 (0.15, 0.055) | 列 3 (0.2, **0.005**) | 列 2 (0.205) |
| 1:1.4 | 0 | 200% | 列 6 | 列 5 | 列 2 (0.607) |

- 1:√2・ページ間 0 の行が報告の 3 つの観測に合う。ページ間 20 px や 1:1.4 では、150%・20% で最後の列替えが 7〜10 px だけになり、
  ほぼ同じ列をもう一度読む (§1.6 の端数の列)。報告の「20% は問題ない」は、はみ出しが 1 回の列替え以下に収まる条件で起きる。
- どの組み合わせでも 85% なら列 2。列替えの量だけを大きくすれば、読み進める量が 15% でも列 2 になる (§5 の 2 で固定する)。

### 1.6 端数の列について (変えない)

はみ出しが `S` の整数倍をわずかに超えると、最後の折り返しは数 px しか動かない (上表 1:1.4・150%・20% で約 10 px)。
これは clamp で端に止める既存の規則の結果で、主軸の最後の 1 回にも同じことが起きる。列を均等に割り直しても列の数 (`1 + ceil(O / S)`)
は減らず、見えない範囲を作らずに列を減らす手は `S` を大きくすることだけなので、本件では割り直しを足さない。
列替えの量を 100% にすると、clamp により「隙間を作らない範囲で最も遠い列」へ移り、列の数は最小 (`1 + ceil(O / 表示幅)`) になる。

## 2. 足すもの

### 2.1 設定

| 項目 | 内容 |
| --- | --- |
| 名前 | `fullscreen_n_scroll_wrap_step_percent: Option<u32>` |
| 意味 | N 字 / Z 字で、列 (N 字) / 段 (Z 字) を替えるときの副軸の移動量。表示領域の幅 (N 字) / 高さ (Z 字) に対する %。 |
| 未設定 (`None`) | **読み進める量 (`fullscreen_n_scroll_step_percent`) と同じ**。今の動きのまま。 |
| 範囲 | 10〜100 (`Some` の値)。読み込み時に clamp (既存の `fullscreen_n_scroll_step_percent` と同じ扱い)。 |
| 既定 | `None` (serde default)。既存の設定ファイルには項目が無いので `None` になり、動作は変わらない。 |

- **リリース済みか**: `fullscreen_n_scroll_step_percent` は v5.5.0 で出荷済み (CHANGELOG v5.5.0)。本件はその意味を変えず、
  新しい項目を足すだけ。新しい項目は未リリースで、無ければ `None` = 今と同じになるので **migration は不要**。
- 旧版へ戻したとき: 通常の設定は SQLite の設定 DB にあり、保存した版がその exe より新しければ、旧版は DB を開く段階で
  `Incompatible` として止める (`settings_db.rs` の `reject_newer_app_version`、v5.5.0 にもある既存の保護)。本件はこの扱いを変えない。
  JSON として読む経路 (旧形式の取り込みなど) では、`Settings` の Deserialize が未知の項目を無視する (`deny_unknown_fields` 無し)。
  どちらでも本件のための追加処理は要らない。
- 解決は 1 か所: `Settings::fullscreen_n_scroll_fractions()` のような helper が `(読み進める量, 列 / 段を替える量)` を 0.1〜1.0 で返す。
  今 3 か所に書かれている `.clamp(10, 100) as f32 / 100.0` をこの helper へ寄せる。
- 表し方は**移動量 (%)** にする (重なり率にしない)。隣の「順に読む操作 1 回」が移動量で、片方だけ重なり率にすると、同じ画面で
  20 と 80 が同じ意味になる (反転) ため。説明文では「100% は表示領域 1 つ分。端に近いときは残りの分だけ動きます」と書き、
  「100% なら重ならない」とは書かない (端で clamp されるので、例えば §1.3 の 1:√2・150% では 100% でも横の移動は 371 px で、
  前の列と約 81% 重なる)。重なりとの対応は「端でなければ、85% なら前の列と 15% 重なる」と留保付きで書く。

### 2.2 計算への適用

`ordered_scroll_pan_with_steps` の引数を、意味の違う 2 つの `f32` + `Option<f32>` から、型付きの 1 つにまとめる。

```rust
struct OrderedScrollSteps {
    /// 主軸 1 回 (表示領域[主軸] に対する割合)
    primary: f32,
    /// 列 / 段を替える 1 回 (表示領域[副軸] に対する割合)
    wrap: f32,
}
```

| 入口 | primary | wrap |
| --- | --- | --- |
| K / J (`apply_fs_page_scroll_key`) | 読み進める量 | 列 / 段を替える量 |
| スクロール＋ページ送りのキー (`fs_page_scroll_or_turn_key`) | 読み進める量 | 列 / 段を替える量 |
| スクロール＋ページ送りのホイール (`fs_page_scroll_or_turn_wheel`。frame の予測も同じ関数) | ホイールの量 × ノッチ | 列 / 段を替える量 |

- 変えるのは「折り返しの副軸の移動量」の値だけ。主軸の移動、折り返しを採る条件 (副軸が clamp 後に読む向きへ進んだときだけ)、
  主軸を読み始めの端へ戻すこと、端で止まる / 送る判定、着地 (次 = 読み始め、前 = 読み終わり)、滑らかな移動は今のまま。
- 未設定のとき `wrap == primary` (キー) / `wrap == 今の N 字の量` (ホイール) なので、全入口で今と同じ候補になる。
- 前へ (J・逆順) も同じ量を逆向きに使う。

### 2.3 適用範囲の整理

| 場面 | 扱い |
| --- | --- |
| N 字 (縦優先) | 列を替える横移動 = 表示幅 × 列 / 段を替える量 |
| Z 字 (横優先) | 段を替える縦移動 = 表示高さ × 列 / 段を替える量 |
| 主軸がはみ出さないページ (例: N 字で縦が収まる横長) | 今と同じく、主軸は進めず折り返しだけになる。このとき副軸の 1 回は**列 / 段を替える量**で進む (§2.4) |
| 副軸がはみ出さないページ | 折り返しは起きない。今と同じ |
| 見開き・横長分割・白紙の相方・回転 (保存・自由) | 描いた表示単位の外接矩形 (`scroll_geometry`) の画面の縦横で決まる。今と同じ。量は画面の軸に対する割合 |
| 倍率 | 量は表示領域に対する割合なので、倍率で変わらない (今と同じ)。はみ出しが倍率で増えるだけ |
| 縦横の端での停止と折り返し | 今と同じ規則。端数の列は §1.6 |
| 上下キー・ホイールのページ内スクロール・4 方向 | 関係しない (N 字 / Z 字の順を使わない) |
| 連結読み (PageUp / PageDown) | 関係しない |

### 2.4 主軸がはみ出さないときの量 (決めること)

N 字で縦が画面に収まり、横だけはみ出すページでは、K は主軸 (縦) を進めず、毎回「折り返し」として横へ進む
(`ordered_scroll_without_primary_overflow_uses_only_secondary_axis`)。この 1 回は計算上は折り返しなので、別の量を設定すると
**列 / 段を替える量**で進む。

- 採る案: そのまま列 / 段を替える量を使う。この場面の横移動は「次の列へ移る」動きそのもので、列替えの量を大きくした人は
  この場面でも重なりを少なくしたいはず。特別扱いの分岐を足さない (状態と分岐を増やさない)。
- 採らない案: 主軸がはみ出さないときだけ読み進める量を使う。分岐が 1 つ増え、同じ横移動がページの縦の大きさで量を変える。

### 2.5 環境設定

「閲覧表示」の「スクロール量」の欄、「順に読む操作 (N 字 / Z 字) 1 回」の直下に置く。

```

[ ] 列 / 段を替えるときは別の移動量にする   [ 85 %]   (チェックが無い間は数値を無効表示)

```

- チェックを入れると `Some(今の読み進める量)` で始める (入れただけでは動きが変わらない)。外すと `None` に戻す

- 数値は `DragValue`、10〜100、`%`。無効表示中も今の解決値 (= 読み進める量) を表示する。
- 検索 anchor `spread/n-scroll-wrap-step` を足し、検索語に「列」「段」「折り返し」「重なり」「N 字」「Z 字」を入れる。
- 「…」(その他の機能) の読み順の小パネルには足さない (§1.826 と同じく、設定を変える場所を増やさない)。

### 2.6 キー操作

**足さない**。量を切り替える操作 (例: 列替えの量を一時的に変えるキー) の要望は無く、量は設定で決まる値として扱う
(読み進める量 §1.826 にもキーは無い)。`KeyAction`・keymap・`docs/keymap.ini.default` は変えない。

### 2.7 設定の書き出し / 読み込み (`settings_transfer`)

- 書き出しの対象に足す (同じ分類、表示名「N 字 / Z 字の列・段替えの移動量」)。値は `null` (= 未設定) か 10〜100 の整数。
  範囲外・型違いは既存の項目と同じく問題として報告し、取り込まない。
- **`null` を受け取る唯一の項目になる**。今の転送は全項目で `null` を拒否し、テスト `null_is_rejected_for_every_logical_item` が
  それを固定している。この項目だけを明示的な例外にし (一覧で名前を挙げる。型から自動で例外にしない)、他の項目の `null` 拒否は保つ。
- 読み込みで項目が無い (旧版の書き出しファイル) ときは、既存の項目と同じく今の値を変えない。`null` があれば `None` にする
  (項目の欠落と `null` を区別する)。
- テスト: `Some(85)` の設定へ `null` を取り込むと `None`、項目の欠落では `Some(85)` のまま、`Some(10)` / `Some(100)` の往復、

  (`all_settings_fields_are_classified` の件数) と、往復テストの「既定と違う値」(`nondefault_source` 系、`fullscreen_n_scroll_step_percent`
  の隣) を更新する。

## 3. 状態の組み合わせを減らす検討 (CLAUDE.md「設計の簡素化」)

- **設定は `Option<u32>` 1 つ**: 「別にするか」の bool と量の u32 を分けると、「別にしない + 量あり」の意味のない組み合わせができる。
  `None` = 読み進める量と同じ、で既定と既存値の引き継ぎも 1 つの規則で済む (migration も不要)。
- **実行時状態を足さない**: 量は入力のたびに設定から解決する。列・段の位置や「何列目か」を記憶しない (§1.474 の「端を記憶しない」を保つ)。
- **計算の入口を 1 つに保つ**: 3 つの入口は今も同じ純関数を通る。量の解決を 1 つの helper にまとめ、入口ごとに書かない。
- 採らなかった案:
  - 既存の `fullscreen_n_scroll_step_percent` を「読み進める量」と「列替えの量」の 2 つへ移し替える (migration で複製):
    出荷済みの項目の意味を変え、旧版へ戻したときの扱いも増える。
  - 列替えの既定を固定値 (例 85%) にする: 読み進める量を変えている既存の利用者の動きが変わる (CLAUDE.md「通常の使い方が不便になる変更」)。
  - 重なり率で表す: §2.1 の反転の理由。
  - 列を均等に割る: §1.6 の理由。
- まれな失敗 (設定の保存失敗など) は既存の設定保存の割り切り (ログ + 通知) のままで、本件で足すものは無い。

## 5. 検証 (追加テストの観点)

1. 純関数: 列 / 段を替える量が読み進める量と違うとき、N 字 / Z 字 × 右→左 / 左→右 × 次へ / 前へで、主軸の 1 回は読み進める量、
   折り返しの副軸は列 / 段を替える量で進む (`ordered_primary_and_wrap_moves_share_n_and_z_rules_in_both_directions` の別量版)。
2. 報告の条件 (`n_scroll_report_850_tests.rs`): 1:√2・150%・読み進める 15% / 列替え 100% で列 2 (N 字 1 回)、200% でも列 2。
   列替えの量にかかわらず、同じ座標に戻らず端で止まる (今の検査を別量の組み合わせにも広げる)。
3. 既定の不変: `None` のとき、全入口 (K / J、スクロール＋ページ送りのキー、ホイール) の候補が今と同じ (既存テストがそのまま通る +
   `Some(読み進める量)` と `None` が同じ座標列になる)。
4. 主軸がはみ出さないページ (§2.4) は列 / 段を替える量で進む。
5. 非対称の見開き (`asymmetric_original_spread_never_repeats_a_column_or_row_after_clamp`) を、別量 (小さい列替え / 大きい列替え) でも回す。
6. 入口: K / J とスクロール＋ページ送りのキー、ホイール (予測と適用の両方) が設定の列替えの量を使う (handler-level)。
7. 設定: 読み込み時の clamp (`Some(5)` → 10、`Some(150)` → 100、無い → `None`)、環境設定の行 (チェックで `Some(読み進める量)`、
   外すと `None`、OK で保存・キャンセルで戻る)、転送の往復と範囲外の拒否。
8. UI の見た目: 環境設定の該当 snapshot を更新する (`fullscreen_in_page_scroll_setting_tests`)。`python scripts/check_ui_glyphs.py`。

ブランチで流すのは上の関連テストと `in_page_scroll` 配下・設定転送・環境設定の該当テストだけ (全件は統括が master 取り込み後)。

## 6. 利用者に相談すること

   何度も読むことになる」という読み取りが合うか。§1 のとおり今の動きは仕様どおりで、座標の逆戻りやループは単体テストで起きていない。

   (1:√2・150% / 200%)。既定を 100% や 85% に変える案は、既存の動きを変えるので採らない前提。
3. 主軸がはみ出さないページで、K の横移動が列替えの量になる (§2.4)。
