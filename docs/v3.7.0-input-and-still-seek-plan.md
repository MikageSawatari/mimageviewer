## 共通機構の設計確認

動画入力は native presenter / egui / App の所有と消費順を確認する。
端パネル、モーダル、シーク列、360 度、拡大表示、タイルが既に消費した入力を通常割り当てで再処理しない。
main / F12 / 複数窓の対象解決を既存 owner に従わせ、別窓や背面一覧を変更しない。

実装前調査では通常 wheel が `render_core` で `NavigateItem` へ先に変換されるため、
App の残余入力だけに設定を足しても主経路へ効かないと確認した。producer は通常操作の
wheel を量付きの typed command として一度だけ渡し、App が現在の Settings から Navigate と
相対 VolumeStep を一度解決して、既存 source / epoch gate と実行に同じ結果を渡す。設定を任意の metadata へ複製せず、
source 切り替え時に metadata が空でも既定値へ戻らない。App の残余経路も同じ純粋 resolver を使う。
ただし既存 `NavigateItem` は、切り替え中の連続送りを落とさないため epoch 不一致を許可している。
通常 wheel の実効操作を App で一度解決し、Navigate はこの例外を維持、Volume は古い source を
拒否する。同じ実効操作を gate と実行が共有し、全操作へ一律の epoch 拒否を加えない。
native wheel event は現在 Alt を保持しないため、presenter / HUD の入力取得境界から運ぶ。
新設定は修飾なしだけに適用し、Shift / Alt の既存挙動を変更する一般 wheel 設計へは広げない。

通常 wheel は `ring_shortcuts` 内の専用 enum とし、旧 Shift / Alt 互換 field を再公開しない。
同じ編集UIを環境設定「動画」と操作カスタマイズ「マウスボタン」で共有し、同じSettings fieldを編集する。
環境設定検索はVideoページの実anchorへ結び付ける。別Windowへの検索destination拡張や偽anchorは追加しない。
共有fieldは両ダイアログの編集セッションで、開いた時点の値・編集値・現在のlive値を照合する。
その画面で値を変更していればOK時に編集値を反映し、未変更または初期値へ戻していればlive値を保つ。
環境設定の既存non-preferences移送と、操作カスタマイズのring全体保存の両方向へ同じ解決を適用する。
未保存判定も同じ規則とし、キャンセルはliveへ書かない。ほかのring項目の編集所有は変更しない。
片側だけの保存対策では逆順で巻き戻るため、独立レビューで双方向の共有field境界として確認した。
既存 mouse button の back / forward / middle 保存値・既定を保ち、6種類の段階別 seek を候補に加える。
Small / Large の既存 KeyAction ID と既定 chord は維持し、Medium 前後を既定割り当てなしで追加する。
秒数は Settings の整数 1～600、独立値として解決時に範囲制限する。既存の音楽・音声 seek 経路も
同じ設定に従い、固定の左右とタップは Medium、ゲームパッドの既存 VK 経路もこれに追従する。
音量の実計算は既存 dB フェーダーの処理へ合流し、UI / worker に別の音量 state を持たせない。

### native wheel のイベント単位の配送

独立レビューで、即時 command 化した wheel も egui へ再投入され、batch 最終ポインターの
別領域で消費され得ることを確認した。逆順では領域 wheel が最終 canvas 位置で消失する。
frame 全体の `consumed_wheel` だけでは区別できないため、§4.2 の同じ入力境界で是正する。
これは backlog §1.199 の mixed-batch 所有問題とも同じ境界であり、通常 wheel の設定追加と
別の回避策を積まずに統合する。§1.199 の完了扱いは実 handler の両順序回帰が通ってから判断する。

各 raw wheel に `Command / OverlayRegion / AppRemainder` の処理先を一つ与え、batch の
event index に対応する結果を outcome が所有する。恒久的な新しい入力 ID や pending bool は不要。
Command は egui / App へ raw を渡さず、OverlayRegion は元座標で実際の handler へ一度渡して
App 転送を止め、AppRemainder はその event だけ転送する。領域判定は Ctrl+tile より先に行う。

wheel を末尾にした入力 segment ごとに egui の論理処理を通し、後続 move を同じ pass に混ぜない。
既存 `render_once` の UI 処理・状態確定と GPU 出力を分離し、`FullOutput::append` で texture /
platform output を順に合わせ、最後の shapes だけを従来どおり一回 submit / present する。
各 pass の時刻は実時間を使い、固定 dt の水増し・イベント再投入・空の疑似 frame を作らない。
pointer-only prefix の空処理を先行させず、button / key で modal が変わる prefix は
古い gate で後続 wheel を確定しない。非 wheel の text / modal 前後保護も維持する。

契約は raw 入力の配送所有であり、egui が Context 内に持つ平滑スクロールの残量は
通常の別 frame と同じ内部アニメーションとして維持する。全平滑量を元 panel に固定する保証や、
ScrollArea の offset / smoothing の独自再実装には広げない。
回帰は canvas と strip / panel の両順序・同方向/逆方向 wheel、Navigate / Volume、
Ctrl+tile と領域の重なりを実 handler で確認し、raw 配送回数・直後の領域効果・通常 command の
回数を区別する。単に pure resolver が合うことを end-to-end 成功と扱わない。

この境界は親と独立 Astra が構造的修正として合意した。Sol の前提検証後に実装する。

静止画列は `StillSeekGeometry` を画像予約領域、描画、当たり判定、パネルの余白で共有している。
高さ設定を表示箇所だけ置き換えず、ドラッグ距離・狭い表示領域への収まりも同じ寸法から解決する。
`SeekStripHeight` は動画と共用のため、静止画専用設定型への分離と既存 serde 値の互換を検討する。
静止画専用の5段階を用意し、旧 `large / medium / small / smallest` の保存値と `Large` 既定を維持する。
新しい「最大」の初期値は 144、各段階の範囲は整数 36～320 とする。
値は独立して設定でき、段階名はプリセットの識別子とする。他段階の値を自動移動・ソートしない。
数値の範囲制限は解決時に適用し、起動しただけで保存値を書き換えない。未知 enum の保護も維持する。

実効寸法は実際の viewport から解決する。ROOT の最小高さ 580pt は detached には存在せず、
それを下限として仮定しない。窓の新しい最小サイズ制限を加える代わりに、極小の窓では bar / strip /
鍵ボタン / inset も共通の fit 結果に従う。描画だけ intersect して予約量が要求値のまま残る状態をなくす。
通常の画面では既存 4 段の寸法を保ち、動画の geometry は変更しない。

外枠の正本は active fullscreen の CentralPanel 内の `ui.max_rect()` とする。
予約済み `image_rect` から外枠を逆算せず、解決した frame 内の geometry を single / spread の
zoom、holdover 表示にも渡す。holdover が捕捉した古いページではなく、現在の表示面の
chrome 設定を使う。単独 holdover の入口も外枠と画像矩形を区別する。
画像の最低高さは `min(1, viewport_height)` とし、上部固定バーと下部バー・列を優先して収め、
その余りへ上下の有効 gap を割り当てる。任意余白を先取りして操作領域を0へ押し出さない。
十分な領域では要求された上下gapを保ち、固定・非固定の画像予約とoverlayの区別も維持する。
下部予約が 0 の場合は下部 gap も 0 とする。
鍵ボタン、inset、content も解決後の矩形に従い、極小画面で外枠の外に最小 1px を作らない。
静止画用の予算解決を動画の固定バー処理へ暗黙に適用しない。
この極小領域の最低高は media / seek の矩形が外枠内で非反転になる契約であり、
既存の上部バー自身も収まらない高さで、画像が上部バーに覆われず見える保証ではない。
上部バー全体の描画・入力レイアウトの再設計は今回へ追加しない。

bar が38pt、stripが36pt未満なら一律に非表示にする下限は追加しない。正の実効領域では
ボタン・鍵・余白も連続的にfitし、0領域だけ矩形を返さない。共有 `draw_icons.rs` には
rect指定のbar button helperを加え、既存32×32 APIはその矩形を渡すwrapperとして維持する。
静止画だけがfitted rect版を呼び、paint clip / hit / touch correlation記録を同じ矩形に揃える。
既存呼出元の32pt動作、動画の固定bar helperは維持する。親と独立Astraがこの追加境界を確認した。
mixedメディア要約や見開き準備中の早期描画も同じfitとclipを使い、総高さ0では描画・操作を作らない。

静止画セルの実幅は各ページの縦横比で変わるため、ドラッグ換算幅を `drag_step_width` と区別する。
既存幅は `round((height - 10) * 148 / 94) + 4` で 45 / 64 / 102 / 152 を再現できる。
この幅は押下開始時に既存 `StillSeekGesture::Strip` の座標と一緒に保持し、release まで維持する。
別窓での高さ設定変更や viewport fit の変化で、進行中のドラッグの着地点を飛ばさない。

上記は親 Astra と独立 Astra のコード照合で合意した構造的変更である。
Solの実装前提確認と独立レビューで、geometry消費経路、極小画面、gapの優先順位、
通常hover previewとpanelのclip分離を確認した。統合・実テストの状態は作業台帳へ記録する。

要求、keep、完了反映、寸法キャッシュ、cancel は同じ viewer context の所有に従う。
未確認の寸法を UI スレッドの同期 I/O で埋めず、既存 worker と完了通知の経路を調べる。
設定永続化は通常の Settings / SettingsDb を使い、未知値の保護や保存抑止を弱めない。

## 実装と検証の進め方

### §1.200 実装前の根因照合

Sol の source 調査では、通常フォルダと ZIP / PDF は `image_metas` を準備しており、
寸法・メタデータ未準備を一律の根因とする仮説は採用しない。
静止画 overlay が限定ページを `keep_set` へ加えた後、ROOT の詳細表示の tooltip 終了処理
`clear_details_hover_keep` が同じ集合を全消去する経路がある。
次 frame の `poll_thumbnails` は keep 外の結果を捨てるため、シーク側の要求が残っていても表示へ届かない。
hover の対象変更も集合の全消去を行い、旧 hover 解放では同じ idx をシーク側が使っていても
要求・texture を破棄し得る。独立レビューでは、generation が一致した `fs_holdover` の
navigation target も保持を要求する第三の owner と確認した。通常の grid 保持範囲も含め、
既存 owner の要求集合を共有の保持集合へ投影し、
片方の終了で他方の要求・queue・Loaded を破棄しない所有境界へ修正する。
worker の限定ページ集合、通常グリッドの抑制、items 世代と context の契約は保つ。
bounding range は grid / navigation / hover / 表示中の bookmark の範囲であり、遠方の still seek ページは exact set に残す。
Details 分岐の queue retain も保持集合と整合させ、hover 終了だけに局所的な例外を加えない。

追加レビューで、しおりパネルも `ensure_bookmark_panel_thumbnails` から同じ保持集合へ要求を
加える owner と確認した。詳細表示の投影でこれを落とすと、Loaded や待機キューを破棄した後に
パネルが再要求するため、後段の再追加だけでは保持にならない。表示中のしおりパネルが使う
既存のページ解決結果も投影へ参加させる。新しい同期 DB 読み出しや永続 pending state を
加えず、パネルの表示条件と現在の context の正本から必要なページを得る。
具体的には既存 keep 候補だけを、現在の loaded bookmark 集合・container・各 item の
PageIdentity と照合して保持する。全 items を追加走査せず、新しいページの導入は従来の
`ensure_bookmark_panel_thumbnails` が保持集合へ追加してから要求する経路に任せる。
これは過去の要求元の来歴ではなく、現在の bookmark membership を独立した失効条件にする。
タブの閉鎖・行の削除・別本への切り替えで失効し、他 owner が使うページは残す。
bookmark は worker の bounded range にも参加し、同 ensure の range 上書きも union へ合流する。
navigation の ensure も同じく既存 bounded range へ合流させる。直後の投影で再計算される場合も、
その前に worker 向け atomic range を移動先だけへ狭めて、他 owner の要求を棄却させない。
世代更新だけで keep が全消去されるとは仮定せず、現在 item の照合と既存 ThumbMsg の世代拒否を保つ。
なお本の適格性を調べる既存 helper 自体にも `items.iter().all(Image)` があるため、
保持候補を絞るだけでは毎 frame の全件走査は消えない。materialized `items` のこの厳密な結果は
既存 context 所有の `ViewerNavigationCaches` 内で source / generation ごとに memo 化し、
同 owner の `invalidate` で失効させる。filtered nav の `FsSeekInfo` は母集合が異なるので代用しない。
新しい要求状態や独立 owner を追加せず、本の種類・synthetic 除外・設定・空一覧・container の
既存条件を維持する。別 context で同じ世代番号の場合も cache 自体の交換に従わせる。
通常の bookmark draft helper も synthetic / 製本 / 自動フォルダ本の無効設定などの短絡順を保ち、
Image 全件分類が不要な本で新たな全件走査を増やさない。

画質ダイアログは詳細表示が記録した `last_cell_size = content_w`、`last_cell_h = 28` を
A/B それぞれの preview 寸法へ流用している。さらに固定2列・slider・footerが狭幅へ収まらない。
viewport と実際の利用可能幅から preview 寸法を決め、狭いときは A/B を縦に配置する。
Window の外枠制約と内部スクロールを併用し、プレビュー拡大、スライダー、適用、閉じる操作を維持する。

### 担当とゲート

親 Astra が設計と編集所有を調整し、Sol / xhigh が主要前提を検証して実装する。
独立 Astra は指示への適合と設計自体をレビューする。矛盾が出た場合は実装を進めず根拠を親へ戻す。
2026-09-08の利用者追加指定により、次の作業区切りから親が変更範囲・不変条件・完了条件を
まとめて渡し、担当は範囲内の通常判断を進める。途中相談は前提矛盾・範囲拡大・阻害要因を中心とする。
独立レビューは重要設計とまとまった実装の検収へ集中し、再レビューは既知指摘と修正影響を確認する。
重大な指摘は回数で打ち切らない。検証担当を一人に定め、有効な成功済み結果を再利用する。
再実行時は対象変更または失敗と、確かめる条件を記録する。連絡は判断が必要な発見・引き渡し・完了を
中心とし、利用者への進捗報告、必須検証、実機検証の事前了承とデータ保護は維持する。
旧 ClaudeCode 指定の今回の移行は [作業台帳の移行表](v3.7.0-priority-work.md#旧担当指定との衝突と今回の移行範囲) のとおり。
detached の構造制約と §11 への変更記録は維持する。

`settings.rs`、環境設定ページ、`ui_fullscreen.rs`、`app/tests.rs` 等は複数項目にまたがるため、
同時に編集しない。先に必要ファイルを一覧化し、親の引き渡し後に編集する。
既存の native wheel 修正と他系統の未コミット変更を保持し、独立した変更単位で検証・保存する。

回帰は設定の旧値読込と往復、実 handler の消費、context 間の非干渉、要求から完了までの経路、
通常・狭幅の headless UI を使う。焦点テスト後に全体 gate と確認用 build を実施する。
実アプリ起動・入力・前面操作は行わず、[明示了承を得るリリース前検証](interactive-release-verification.md) へ残す。

### 実アプリ確認へ引き渡すシナリオ

- 動画・音声の通常ホイールを音量へ変更し、ファイル送りとの切り替えと保存後の再読込を確認する。
  パネル、シーク列、拡大表示、360度、Ctrl+タイルの既存操作も確認する。
- 小シークを2秒などの非既定値へ変更し、進む・戻るボタンに割り当てる。
  小・中・大のキー／リング、通常左右、タッチとゲームパッドも設定した段階の量で動くことを確認する。
- 通常ホイールの設定を環境設定と操作カスタマイズの両方から変更する。
  両画面を開いた状態で、未編集の画面の保存が他方の変更を戻さないことを確認する。
- 詳細表示から実フォルダ、ZIP、PDFを直接開き、シーク列・ホバープレビュー・しおりの画像が読み込まれることを確認する。
  メイン、F12、複数窓で別contextの表示を壊さないことも確認する。
- 静止画・本の5段階の高さ、個別値、固定／非固定、左右読み、見開き、狭い窓と表示倍率を確認する。
  列のドラッグ中に別窓で高さを変更しても、着地点が急変しないことを確認する。
- 動画の「最大」と5段階の個別高さを変更し、保存後の再読込と静止画・本側の設定が独立していることを確認する。
  動画サムネイル・音声波形、固定／非固定、メイン／F12、狭い窓と表示倍率の変更でも、
  列と下部操作が重ならず操作できることを確認する。列のドラッグ中のリサイズ・高さ変更、
  別マウスボタンの解放ではシークが急変・確定せず、操作中のボタンを離すと正常に完了することも確認する。
- サムネイル表示と詳細表示から画質ダイアログを開き、狭い幅でプレビュー、適用、閉じる、リサイズを確認する。
- 長い日本語の動画タイトルを、通常表示・拡大表示・F12で確認する。狭い窓や表示倍率変更でも
  上部のボタン群と文字が重ならず、倍率表示・リセットを含む操作が残ることを確認する。
- AI・カラー化の先読みを前方3／後方2に設定し、左右開き・表紙ありで前後の見開きの両ページを確認する。
  保存済み後方値は自動変更しない。旧前方2の一度限りの移行と重要な変更点の表示は、
  Cargo版更新後のv3.7.0成果物を使った隔離データで確認する。現在の3.6.0確認用buildでは発火しない。

これらは未実施の確認項目であり、headless回帰の成功から実HWND・GPU・入力機器の成功を推定しない。
既存のidle-health、実アプリsmoke、データ保護のゲートへ追加し、実行枠の了承を得てから実施する。
動画操作自動化やidle測定runnerの改良の完成を待つ必要はなく、未自動化部分は了承済み枠で
手動操作とログ確認を組み合わせる。自動化の延期を製品検証の免除とは扱わない。
