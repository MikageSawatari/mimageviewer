## 2. 目標

1. 3D のままスライドショーを開始・継続できる。3D に入ってもスライドショーを止めない。
2. 自動送りで次のページへ移った最初のフレームから、そのページを 3D で描く (平面 → 立体の切り替わりを見せない)。
3. 次のページの深度が間に合わなければ自動送りを待たせ、今のページの 3D を表示し続ける。待ちには上限を置く (§5.4)。
4. 手動のページ送り・360°・書き出し・別ウィンドウ・紙めくりの既存の挙動を変えない。

## 3. 状態の組み合わせを減らす検討 (CLAUDE.md の規則)

| 案 | 採否 | 理由 |
| --- | --- | --- |
| 先読みの持ち主を 1 つにする (3D の context 所有の `DepthViewState` に「次」の枠を 1 つだけ足す) | **採用** | 先読みの寿命・取消・VRAM の会計が 3D の状態と同じ所有者に入り、3D を終えれば枠ごと消える。別の queue・map・ready フラグを作らない |
| 「準備できた」を別の状態にせず、既存の深度 LRU に入っているかで判定する | **採用** | 結果の置き場所は LRU だけ。枠は「計算中」だけを持ち、完了したら LRU に入れて枠を空にする。ready の二重表現を作らない |
| 送ると準備の確定点を 1 つにする (タイマーが送ると決める `advance_slideshow` の中で、送り先を決めた直後に 1 回だけ深度の準備を照合する) | **採用** | 「送る予定」の pending 状態を作らない。待つときは何も変えず、期限切れのタイマーが次のフレームでもう一度同じ照合をする (既存の未 anchor 時の 50 ms 再描画と同じ形)。新しいタイマーや待ち行列は作らない |
| 次のページを決める関数を 1 つにする (自動送りと先読みが同じ関数で送り先を決める) | **採用** | 2 か所に書くと、先読みしたページと実際に送るページがずれる |
| 推論の順番: 今のページを先に、次のページは今のページの深度が終わってから | **採用** | worker は同じ context の新しい要求で実行中の要求を取り消す (`depth_estimation.rs:249`)。優先度の仕組みを足さず、「今のページが終端 (Ready / Failed) のときだけ先読みを出す」で順番を作る。今のページが新しい要求を出せば、既存の取消で先読みは消える |
| 先読みの入力は、紙めくりと同じ「表示前の resident 素材」を使う | **採用** | `resident_final_prepare_material` (`app/final_prepare.rs:147`) は、通常の表示が採用するのと同じテクスチャを、アップロードや I/O なしで返す。3D 側で表示の優先順位を書き直さない (正本 §4.1 の原則) |
| 表示用の final が無いページの素材は、紙めくり用の次ユニット準備 (D3) を 3D のスライドショー中にも動かして作る | **採用** (§5.6、前提の確認あり) | 既存の生産者を使い、3D 専用の final 生成を書かない |
| 先読みは 3D のスライドショー中だけ。手動のページ送りでは先読みしない | **採用** | 正本 §1 の判断 (dGPU では不要) を変えない。「次」が一意に決まるのはスライドショーだけで、手動では前後どちらに行くか分からない |
| 間に合わないページで、前のページの 3D を表示したまま新しいページへ移る (表示とページ番号をずらす) | 不採用 | 表示中のページと位置の所有者が食い違う状態を作る。待つ側 (送らない) で解決する |
| 待ち中をモーダルにする | 不採用 | 待ちはスライドショーの進行を遅らせるだけで、利用者の操作と食い違う状態は無い。手動操作はスライドショーを止める既存の規則で済む |
| 次のフォルダ・コレクションの次 (一覧の外) も先読みする | 不採用 (§5.8) | 次の一覧はまだ読み込まれていない。読み込みを先にすると、フォルダ移動・コレクションの非同期要求の所有と組み合わせが増える |

## 4. 変える入口 (3D とスライドショーの共存)

1. **3D の入場でスライドショーを止めない。** `close_fs_exclusive_conflicts` のスライドショー停止を、360° の入場だけで行う形に分ける
   (360° の挙動は変えない)。3D の入場時の他の後始末 (補正パネル等を閉じる) はそのまま。
2. **3D 中もスライドショーの操作を受け付ける。** 次の 3 か所の抑止を「表示占有」から「360° 固有」に分類し直す (360° の挙動は変えない):
   S キー、topbar の再生 / 一時停止ボタン、リングの `ImageSlideshow`。
   - topbar の「…」(スライドショーの設定の小パネルを含む) は、3D 中は今までどおり出さない。間隔などの設定は 3D に入る前に行う。
     「…」には 3D と両立しない項目もあり、項目ごとの分類は今回の範囲外にする。
3. **開始の条件は今までどおり** (`toggle_fullscreen_slideshow`: 静止画のページで開始)。

## 5. 先読みと送りの照合

### 5.1 次のページを決める関数 (1 つ)

`advance_slideshow` から、送り先を決める部分を純粋な関数に切り出す。自動送りと先読みが同じ答えを使う。

```rust
pub(crate) enum SlideshowNextTarget {
    /// 今の一覧の中の別のページ。先読みと照合の対象
    InItems { idx: usize },
    /// 同じページの反対側 (分割表示)、コレクションの要求、次のフォルダ、停止。先読みしない
    Other,
}
fn slideshow_next_target(&mut self, cur: usize) -> SlideshowNextTarget
```

- 3D 中は 1 ページ表示・ページ表示 (連結読みでない) なので、送り先は `adjacent_idx_in_order(still, cur, 1)`。
  末尾で `LoopFolder` のときは先頭の静止画 (`first_slideshow_still_idx`) も `InItems`。
- コレクションの直接登録画像 (`start_collection_slideshow_navigation` が要求を出す場合)、`NextFolder`、`Stop`、
  分割表示の同じページの反対側は `Other`。
- **3D 中のアニメーション画像** (§10 の判断 2、推奨案): 3D 中は、`fs_cache` に読み込み済みでアニメーションと分かっているページを
  送り先から飛ばす。まだ読み込まれていないページは候補のまま (素材待ちの間に読み込まれ、アニメーションと分かれば次のフレームで
  送り先が先へ進む)。上限の待ちで先に送った結果アニメーションに着地した場合は、既存の継続条件で 3D を終える (トースト)。
- `advance_slideshow` は、3D でないときは今までとまったく同じ送り先を選ぶ (アニメーションを飛ばすのは 3D 中だけ)。

### 5.2 先読みの持ち主

`DepthViewState` (context 所有) に枠を 1 つ足す。

```rust
pub(crate) struct DepthNextSlot {
    pub target: DepthNextTarget,          // idx・item の識別子・items_generation
    pub key: DepthSourceKey,              // 送り先の表示テクスチャの id
    pub phase: DepthNextPhase,
}
pub(crate) enum DepthNextPhase {
    ReadingBack { readback: DepthReadback },
    Estimating { pending: DepthPending }, // Drop で取消 (既存)
    Failed { reason: String },            // 同じ key は再試行しない (今のページの Failed と同じ規則)
}
pub next: Option<DepthNextSlot>,
```

- 完了した深度は LRU (既存、4 件) に入れ、枠を `None` に戻す。「準備できた」は **LRU に `key` があること**だけで表す。
- 枠を持つのは `FsExclusiveView::Depth` の間だけ。3D を終えれば `DepthViewState` の Drop で消える (取消は既存の Drop)。
- VRAM の会計: 読み戻し中の buffer は `readback_bytes` に、完了した深度は既存の `depth_bytes` (LRU) に入る。

### 5.3 毎フレームの進め方 (`advance_depth_source` の中、今のページの処理の後)

1. **望む送り先を求める**: 次をすべて満たすときだけ `Some(idx)`。それ以外は `None`。
   - `slideshow_playing`、かつ今のページの深度が終端 (`Ready` または `Failed`)
   - `slideshow_next_target(cur)` が `InItems { idx }`
   - 書き出しの操作中でない (`depth_export_operation.is_none()`)、窓が見えている (既存の hidden / minimized の早期 return と同じ)
2. **送り先の素材**: `resident_final_prepare_material(ctx, idx)` の元テクスチャ。無ければ待つ (枠は作らない)。
   renderer に backing が無ければ待つ。
3. **照合と進行**:
   - LRU に `key` があれば何もしない (準備済み)。
   - 枠が同じ `target` と `key` なら枠を進める: `ReadingBack` は既存と同じ非ブロッキング poll と repaint、完了したら同じ worker へ
     `submit` (今のページは終端なので何も取り消さない)、`Estimating` は `try_result` で受け取り、R16 を上げて LRU へ入れ、枠を空にする。
     R16 のアップロードは今のページと共有の「1 フレーム 1 枚」(`last_depth_upload_frame`) に従う。
   - 枠が別の送り先・別の `key` なら枠を捨てて (Drop で取消) 作り直す。作るときは今のページと同じ経路で、一時的な色テクスチャ
     (`copy_color`) を作って `readback` を出し、色テクスチャはすぐ捨てる (GPU の命令が参照を持つので submit 後に捨ててよい)。
     同じ経路を通すので、先読みした深度は送った後に計算した場合と同じ結果になる。
4. 望む送り先が `None` なら枠を捨てる。
5. perf: 先読みの開始・読み戻し完了・推論完了・LRU 投入に `perf::event("depth", "next_prefetch", ...)` を置く (idx・key・所要時間)。

### 5.4 送るときの照合 (確定点は 1 つ)

`advance_slideshow` の中で、送り先が `InItems { idx }` に決まり `accept_book_slideshow_target` を呼ぶ直前に、
3D 中だけ次の 1 つの関数で照合する。

```rust
enum DepthSlideshowGate { Go, Wait }
fn depth_slideshow_gate(&mut self, ctx, idx, now) -> DepthSlideshowGate
```

- `Go`: 3D でない / 送り先の素材のテクスチャの `key` が LRU にある / 枠がその `key` で `Failed` /
  待ちが上限を超えた (`now >= slideshow_next_at + 上限`、§10 の判断 1)。
- `Wait`: 上記以外 (素材がまだ無い、読み戻し中、推論中)。`advance_slideshow` は何も変えずに戻る。
  `slideshow_next_at` は過ぎたままなので、次のフレームで同じ照合をする。タイマーの既存の
  `request_repaint_after(remaining.min(100ms))` (remaining = 0) で再描画が続く。先読みの完了も worker が repaint する。
- 待ち中は今のページの 3D を描き続ける。画面上の表示は足さない (§10 の判断 1 の推奨)。
- 上限は「1 回の待ちの開始時刻」を新しく覚えず、既存の期限 `slideshow_next_at` からの経過で決める (新しい状態を作らない)。
- 上限を超えて送ったページは、今の 3D の経路 (2D と計算中の箱 → 3D) で表示する。先読みが途中なら §5.5 で引き継ぐ。

### 5.5 送った後の引き継ぎ (先読みの途中を捨てない)

送り先へ移ったフレームで、今のページの `select_source(key)` が LRU に無い `key` を選んだとき、枠が同じ `key` を持っていれば、
新しく読み戻しを出さずに枠の段階 (`ReadingBack` / `Estimating` / `Failed`) を今のページの段階へ移す。
色テクスチャは描画用に今までどおり `copy_color` で作る。手動で送り先へ移った場合も同じ。
これで上限で送った場合も、推論のやり直し (同じ context の新しい要求による取消) が起きない。

### 5.6 送り先の素材を表示前に作る (D3 の次ユニット準備を使う)

`resident_final_prepare_material` が返すのは、表示が採用するテクスチャがすでにあるときだけ。ページの種類ごと:

| ページ | 表示前のテクスチャ | 作る者 |
| --- | --- | --- |
| 補正なし (色調・シャープ・ポストフィルタ・AI・編集なし) | `fs_cache` の先読みテクスチャを final が共有する (同じ TextureId、`app.rs:88165`) | 既存の元画像の先読み (`prefetch_forward`) |
| 補正・ポストフィルタ・局所補正・隠蔽・注釈あり | 紙めくり ON のときだけ D3 の次ユニット準備 (`prefetch_next_final_unit`) が作る。OFF だと移った後に UI スレッドで作る | **D3 を 3D のスライドショー中にも動かす** (下記) |
| カラー化・LUT | 既存の `prefetch_final_effects` | 既存 |
| AI 拡大あり | 既存の AI 先読み (`prefetch_final_ai`) で CPU 結果ができた後、D3 の after-AI 計画で final を作る | 既存 + D3 |

- D3 の有効条件 (`d3_final_prepare_unit_at`、`app/final_prepare.rs:495` の `page_turn_animation_enabled`) を、
  1 つの述語 `next_unit_final_prepare_enabled()` = 「紙めくり ON または 3D のスライドショー中」に置き換える。
  Next 以外の位置 (Current / Previous) と、紙めくりの受付・source 先読みの範囲 (`page_turn_prefetch_policy_enabled`) は変えない。
- **実装担当が着手前に確かめる前提** (違えば止めて設計担当へ返す):
  1. D3 の開始条件 `page_turn_current_unit_presented()` (`final_prepare.rs:447`) は、紙めくりの提示状態
     (`PresentationState::Flat` の受理済みの証拠) を見る。3D の描画は submission を `LegacyRendered` にする
     (`ui_fullscreen.rs:45337`) ので、3D 中はこの証拠が作られず、D3 が始まらない可能性がある。その場合は、3D のスライドショー中の
     「今のユニットを提示した」証拠を「今のページの深度が Ready」とし、同じ述語の中で選ぶ (別の開始経路を作らない)。
  2. D3 が作った final が、送った後に `ensure_final_composite_texture_impl` の cached exact-complete (`app.rs:91333`) として
     そのまま採用され、`resident_final_prepare_material` が返した TextureId と同じになること。テストで固定する (§8)。
  3. 紙めくり OFF で D3 を動かしても、D3 の投機の予算・登録枠・取消 (`speculative_final_unit_is_needed`) が紙めくりの状態に
     依存せず閉じること。
- 元画像の先読み数 (`prefetch_forward`) が 0、VRAM 予算外、AI 先読み 0 で AI が要るページなど、表示前の素材が作られない設定では、
  §5.4 の上限まで待ってから送る (毎ページ待つ)。設定の組み合わせとして受け入れ、マニュアルに書く。

### 5.7 間隔の数え方 (3D 中)

3D 中は `current_slideshow_frame_ready` を「今のページの深度が `Ready` または `Failed`」とする (既存の条件に加える)。
間隔は「3D で見えている時間」になる。先読みが当たったページは移った最初のフレームで Ready なので、今までどおりすぐ数え始める。
上限で送ったページは 3D になってから数える。

### 5.8 一覧の外へ送る場合

- **次のフォルダ (`NextFolder`)**: 全画面を閉じて開き直すので、今は 3D が黙って終わる (§1)。§10 の判断 3。
- **コレクションの直接登録画像**: 送り先は送る時点の最新一覧から非同期に決まる (先に推測しない設計、collection-playback-plan §5.3)。
  先読みも照合もせず、今の 3D の経路 (2D と計算中の箱 → 3D) で表示する。間隔は §5.7 で 3D になってから数える。§10 の判断 4。

### 5.9 他の機能との関係

- **手動のページ送り**: 既存の規則でスライドショーを止める。次のフレームで枠は捨てられる (§5.3 の 4)。
  移ったページが枠と同じ `key` なら §5.5 で引き継ぐ。
- **書き出し**: 書き出しの modal 中はスライドショーのタイマーが止まる (既存)。先読みも出さない (§5.3)。
- **360°**: 変更なし。360° の入場は今までどおりスライドショーを止め、360° 中の抑止も残す。
- **紙めくり**: 3D 中は紙めくりの対象外 (既存)。紙めくり ON でも 3D 中の自動送りは通常の切り替えになる。
- **別ウィンドウ・複数ウィンドウ**: 新しい状態はすべて 3D の context 所有の `DepthViewState` と、context ごとのスライドショーの状態の中。
  App 全体の状態を足さない。3D を持てるのはプロセスで 1 context (既存) なので、先読みも 1 context だけ。
  detached の述語・viewport の経路には触れない予定。実装で触れる必要が出たら、CLAUDE.md のリワーク中のルールに従う。
- **非表示・最小化**: 先読みも今のページと同じく進めない。スライドショーは §5.4 の上限まで待つ。
- **Remote**: 3D は Remote に出さない (既存)。変更なし。

## 6. UI スレッドと GPU (ui-responsiveness §4)

- 同期 I/O なし。素材は resident のものだけを使い、読み込みは既存の先読み・D3 の worker が行う。
- 先読み 1 回あたりの UI スレッドの GPU 仕事は、今のページの深度と同じ (blit + mip 生成 + 504² と長辺 1536 の blit・読み戻しの
  命令の発行)。読み戻しの完了は非ブロッキング poll。R16 のアップロードは今のページと共有の 1 フレーム 1 枚。
- 先読みの一時的な色テクスチャ (8K で約 340 MB) は命令の発行後すぐ捨てる。今のページの色テクスチャと同時に持つのは
  その 1 フレームだけ。
- 区間に `perf::event` を置く (§5.3 の 5)。

## 7. まれな失敗

既定の割り切り (ログ + 通知)。先読みの読み戻し・推論の失敗は枠の `Failed` に記録してログに出し、送った後に今のページの失敗として
既存の通知を出す (§5.5)。先読みの段階では通知しない (まだ見ていないページの失敗を出さない)。再試行の仕組みは足さない。

## 8. テスト

状態遷移・handler レベルで次を固定する (GPU を使うものは既存の depth のテスト helper と test-group gpu)。

1. 3D に入ってもスライドショーが止まらない。360° に入ると今までどおり止まる。
2. 3D 中に S キー・topbar の再生ボタン・リングで開始 / 停止できる。360° 中は今までどおり抑止。「…」は 3D 中も出ない。
3. 先読みは今のページの深度が終端になるまで出ない。今のページの新しい要求で先読みが取り消される (同じ context の supersession)。
4. 先読みした深度が LRU に入り、送った最初のフレームで `Ready` (読み戻し・submit が起きない) — 補正なしのページ
   (fs_cache 共有) と、補正ありのページ (D3 の final) の両方。TextureId の一致を確かめる。
5. 素材がまだ無い・推論中は送らない (`Wait`)。期限 + 上限を過ぎたら送る (`Go`)。上限で送ったページで、推論中の先読みが
   今のページへ引き継がれ、取り消されない。
6. 3D 中は既知のアニメーション画像を送り先から飛ばす。3D でないときの送り先は変わらない。
7. 手動送り・スライドショー停止・3D 終了・context の終了・フォルダ移動で枠が捨てられ、取消が届く。兄弟 context に作用しない。
8. 間隔は 3D が Ready になってから数える。
9. 書き出し中は先読みを出さない。
10. 既存回帰: `test(/depth|slideshow|page_turn|final_prepare|panorama|export|admission/)`。

## 10. 利用者に決めてもらうこと (推奨案つき)

1. **次のページの深度が間に合わないとき**
   - (推奨) 待つ。ただし上限を「スライドショーの間隔 1 回分」(既定 3 秒なら最大 3 秒余分に表示) とし、超えたら送る
     (そのページは平面 → 計算中の表示 → 立体になる)。待ち中の表示は出さない。
   - 上限なしで待つ (表示前の素材が作られない設定では止まったように見える)。
   - 待たない (送る時点で間に合わなければ平面 → 立体が見える)。
   - 補足: dGPU では推論 30〜50 ms、内蔵 GPU で約 1 秒なので、間隔 3 秒なら通常は待たない。CPU だけ (約 3.6 秒) や間隔を短くした
     場合に待ちが出る。
2. **アニメーション画像 (GIF / APNG / WebP アニメ) のページ**
   - (推奨) 3D 中のスライドショーでは飛ばす (3D のまま次の静止画へ)。
   - そのページへ送り、3D を終えて 2D でスライドショーを続ける (今のページ送りと同じ。もう一度 D で 3D)。
   - そのページの手前でスライドショーを止める (3D は続く)。
   - 動画・音声は今もスライドショーが飛ばすので、判断は不要。
3. **終わりの動作が「次のフォルダへ」のとき (フォルダの境目)**
   - (推奨) 今と同じく 3D を終えて 2D でスライドショーを続ける。ただし黙って終わらないよう、トーストで知らせる。
   - フォルダの最後でスライドショーを止める (3D は続く)。
   - 3D を続けたまま次のフォルダへ進む (次のフォルダの最初のページだけ平面 → 立体が見える)。全画面を閉じる経路で 3D を残す
     作り直しが要り、作業が大きい。今回の版の方針 (大きな新機能なし) から外れる。
4. **コレクションの直接登録画像のスライドショー**: 送り先が送る時点で決まる仕組みのため、先読みできない。毎ページ「平面 → 立体」が
   見えることを、今回は制限として受け入れてよいか。(推奨: 受け入れる。マニュアルに書く)
5. **先読みは 3D のスライドショー中だけ** (手動のページ送りでは先読みしない)。正本の判断 (dGPU では不要) のまま。(推奨: このまま)
