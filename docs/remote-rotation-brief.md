# 実装ブリーフ: リモート閲覧のビューアに保存回転を反映する

対象: v3.1.0。利用者の実機確認で発覚 (2026-08-16)。

## 1. 何が壊れているか

**リモートのビューアは、保存済みの回転 (`rotation_db`) を無視して表示している。**

- 一覧のサムネイルには回転が適用されている
  (`src/remote_ipc/thumbnail.rs` の `generate_catalog_resolved` が `image.rotate90()` 等を呼ぶ)。
- しかし**ビューアのページ画像を作る `load_image_timed`
  (`src/remote_ipc/container.rs`) には回転が無い。**
- そのため、本体では横向きに見えるページが、リモートでは縦向きのまま出る。
  一覧のサムネイルと本文の向きも食い違う。

さらに直前のコミット `618cf369` で**ペア判定だけ**回転後に統一したため、現状のリモートは
「回転前の向きで表示しながら、回転後の向きでペアを組む」状態になっている。
**ペアだけ直しても意味がない**ので、表示側を正す。

## 2. やること

`load_image_timed` が返すページ画像に、保存回転を適用する。

### 2.1 適用順序 — トリムの後、最後に回す

本体の正本は [`docs/display-pipeline.md`](display-pipeline.md) §2.4:

```
2. 表示トリムの実効 content bbox
3. 回転 (rotation_db, 0/90/180/270)
```

**トリムが先、回転が後。** リモートも同じ順にする。つまり合成 (補正・トリム・auto-trim) が
終わった最後に回す。こうするとトリム座標は回転前空間のままで、**本体と共有している
トリム状態がそのまま通じる**。順序を入れ替えると、本体で設定したトリムがリモートで
ずれて適用される。

回転キーは既存のページキー (`crate::edit_source::page_key_for_grid_item` 相当) を使い、
サムネイル側・ペア判定側と同じキー体系にすること。

### 2.2 クライアントから来る座標を戻す — ここが要点

配信画像が回転すると、**クライアントが返してくる座標は回転後の空間になる**。
一方サーバ側の状態 (トリム等) は回転前空間で持っている。

**クライアント → サーバ方向の座標をすべて洗い出し、境界で逆回転して受けること。**
少なくとも表示トリムの矩形が該当する (リモートからトリムを操作できる)。
補正・カラー化・AI などに座標を伴うものが他にもないか、**送信側の型を列挙して確認する**。

変換はサーバ側の入口 1 箇所に集約する。クライアントへ回転を伝えて向こうで直す形にしない
(クライアントが 2 つの座標系を持つことになり、後から必ずずれる)。

### 2.3 寸法を返す経路

ページの寸法をクライアントへ返している経路があれば、**回転後の値**にする。
`api_image_info` (`crates/remote-web/src/http.rs`) など、寸法を運ぶ応答を洗い出すこと。
画像自体は回転済みで届くので、寸法だけ回転前のままだとレイアウトが崩れる。

### 2.4 キャッシュキー

ページ画像をキャッシュしている場合、**回転をキーに含める**こと。含めないと、回転を
変えたあとに古い向きの画像が出る。サーバ側・クライアント側の双方を確認する。

### 2.5 ペア判定はそのまま

`618cf369` で入れた `cached_landscape_flags` / コレクション側の回転反映は**正しいので残す**。
表示が回転すれば、ペアと表示が一致する。

## 3. 通信

**IPC プロトコルと `PageGroup` ペイロードの形は変えない。** 座標の逆変換はサーバ側で
閉じるので、クライアントの要求方法は変わらないはず。変える必要が出たら**手を止めて報告**する。

## 4. テスト

- 回転ありのページで、配信画像の寸法が回転後になること (0/90/180/270)。
- **トリムを設定したページに回転を掛けたとき、本体と同じ領域が出ること。**
  順序を間違えると通るテストにならないよう、非対称なトリム矩形で確認する。
- クライアントから来る座標の逆変換 (2.2 で洗い出した各経路)。
- 回転を変えたらキャッシュが効かず新しい向きが出ること。
- 実行: `cargo test -p mimageviewer --lib remote_ipc::`、
  `cargo test -p mimageviewer-remote`、web 側は `node --test`
  (`crates/remote-web/web`)、`cargo fmt --all`。

- 本体側の回転・トリムの仕様。
- 動画の回転 (既に別経路で扱っている)。
