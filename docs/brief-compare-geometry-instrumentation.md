# ブリーフ: 比較表示の幾何がまだ合っていない — まず計測できるようにする

対象: v2.13.0。実装 = Codex Sol / レビュー・検収 = ClaudeCode / 実機確認 = 利用者。

正本: [docs/next-release-backlog.md](next-release-backlog.md) §1.60 / §1.55-2。

前提: master の作業ツリー。着手前に `git log --oneline -3` で HEAD を確認すること。
`096a4bad` (uv 窓によるクリップ) まで入っているが、**実機では症状が変わっていない**。

---

## 1. 実機で観測されている症状 (2026-08-09、スクリーンショット 3 枚)

1. `Shift+C` のワイプでズームすると**縦横比が崩れる**。継ぎ目が白線と一致しない
2. `Alt+C` でパンすると合成画像が**画面上部の帯に潰れる**
3. **ズームしているのに、メイン表示には合成画像の全体が写っている**。
   同じフレームのナビゲータでは黄色い枠が小さい範囲を指しており、**メイン表示の内容が
   その枠の中身と対応していない**
4. **ワイプの境界を左右へ動かすと、ナビゲータの黄色い枠が左右に動く**。
   本来動くべきなのは枠ではなく、**ナビゲータ内で分割されている画像の割合**

## 2. ⚠ 推測で直さないこと

`096a4bad` は ClaudeCode の推測 (「callback rect が画面外へ出てクランプされる」) に基づいて
入れたが、**実機では効いていない**。同じことを繰り返さないこと。

症状 3 と 4 は、**メイン表示・ナビゲータの枠・ワイプ割合が別々の座標系から導かれている**
ことを示唆する。特に 4 は、ナビゲータの枠が「可視範囲」ではなく別のものから計算されている
か、ワイプのドラッグが同時にパンを動かしている可能性を示す。**どちらかは未確定**。

## 3. やること (この順で)

### 3.1 まず計測できるようにする (必須)

比較表示が有効なフレームで、次を 1 行のログに出す。値が前フレームと変わったときだけ出力し、
変化が無ければ出さない (押しっぱなしで溢れさせない)。`crate::logger::log` を使う。

- 呼び出し元の区別: メイン表示 / ナビゲータ
- `compare_view_mode` とワイプの `fraction`
- `draw_compare_prepared_mode` に渡っている `image_rect` と `zoom_pan` (zoom 値とパン量)
- `pair.target_size`
- `compare_image_draw_rect` が返した `draw_rect`
- `compare_shader_visible_region` の `visible` と `uv_window`
- callback rect として実際に渡した矩形
- 白線を描いた画面 x (`compare_wipe_screen_x` の結果)
- ナビゲータ側: `content_rect` と黄色い枠の矩形、およびその枠を導いた入力
  (どのページ / どの uv から計算したか分かる形にする)

**この計測は一時的なもの**である。原因が確定して修正が入ったら、回帰テストへ置き換えて
撤去する。ログ行にその旨のコメントを残すこと。

### 3.2 並行してソースを読み、症状 3 と 4 の原因を確定させる

読むべき箇所の当たり:

- `draw_compare_prepared_mode` ([src/ui_fullscreen.rs:22773](../src/ui_fullscreen.rs)) に
  渡っている `zoom_pan` が、実際にユーザーのズーム / パン状態を反映しているか。
  **反映されていなければ、メイン表示はフィットのまま全体を描くので症状 3 の説明になる**
- ナビゲータの黄色い枠 (`build_flat_navigator_layout` の `visible_rect`) が、
  **合成画像ではなく背後のページ (`fullscreen_page_layout`) の可視 uv から**計算されて
  いないか。比較中は描いている絵が合成画像なので、枠だけ別座標系だと 3 / 4 の両方を説明できる
- ワイプのドラッグが通常のパン処理を止めているか。`compare_wipe_grab_hit` が
  `draw_rect.contains(pointer)` を要求するようになったため、掴み損ねたドラッグが
  パンへ流れていないか

**原因がソースで確定したなら、そのまま直してよい**。ただし:

- 確定していないものを「たぶんこれ」で直さないこと。確定できなければ**計測だけ入れて報告**する
- 直した場合も **3.1 の計測は残す** (実機で確認するため)。撤去は次のラウンドで行う

### 3.3 症状 4 の「あるべき姿」

ワイプの割合を変えたとき、**ナビゲータの中で分割位置 (継ぎ目) が動く**のが正しい。
可視範囲を示す黄色い枠は動かない。ナビゲータは `zoom_pan = None` で全体を描いているので、
継ぎ目はナビゲータの `content_rect` 上の同じ割合の位置に来る。
